Motivation

Choose a feasible student using task-specific quality, memory and retained supervision rather than model size alone.

Prerequisites

  • Autoregressive conditional likelihood
  • SFT response masking
  • Data validation and held-out evaluation

Notation and units

  • x prompt; y=(y1…ym) retained teacher response
  • L=-sum log Pstudent(yt|x, y<t)/m
  • N samples; k candidates/prompt; p candidate acceptance

Assumptions

  • Synthetic data is explicitly distinguished from ground truth
  • Reported DeepSeek experiments are historical source results, not reruns
  • IID acceptance only for binomial toy calculations

Step-by-step derivation

  1. Specify task, held-out metric, quality threshold, context length, throughput/latency and hardware budget.
  2. Estimate rawweight bytes=N bits/8; addcache, activations, adapter/runtime and serving overhead separately.
  3. Eliminate memory-infeasible candidates, then measure candidates on the same target evaluation; choose a quality/cost Pareto point.
  4. Capacitygap is task-dependent; no theorem says student benchmark accuracy≤teacher accuracy when labels, pretraining or regularization differ.
  5. Length filtering discards complete long examples; truncation removes tokens within examples. These produce different datasets and risks of missing final answers.
  6. Quadratic attention arithmetic ratios do not equal end-to-end runtime or memory ratio under optimized attention kernels.
  7. Teacher curation quality, verifiers and distribution coverage determine which behavior is transferred; compare held-out correctness androbustness, not only synthetic validation NLL.

Step 4.9 — Limits of Distillation and How to Choose the Student

Plan node: I5 · chat order #41

We now have the complete mechanism, pipeline, and empirical evidence.

The last major part of this distillation chapter is understanding the limits:

\boxed{ \text{When does distillation work extremely well?} }

and:

\boxed{ \text{When does the student fail to absorb the teacher?} }

The supplied material identifies several interacting factors: student capacity, quality of the teacher-generated data, choice of base model, sequence length, and the distinction between transferring existing capability and creating genuinely new capability. (Source: Build a DeepSeek Model (From Scratch))

1. The first limit — capacity gap

The most fundamental limitation is:

\boxed{\text{student capacity}}

A teacher may contain vastly more learned structure than the student can represent.

Suppose:

T=671B

and:

S=1.5B.

The student is approximately:

\frac{671}{1.5}\approx447\times

smaller by parameter count.

The student therefore cannot be expected to preserve every capability of the teacher.

The source calls this the capacity gap. (Source: Build a DeepSeek Model (From Scratch))

2. What exactly is being lost?

Think of the teacher as having learned many things simultaneously:

\text{mathematics}
\text{coding}
\text{language}
\text{world knowledge}
\text{reasoning strategies}
\text{formatting}
\text{instruction following}.

A tiny student has to compress all of those into a much smaller parameter space.

So:

\boxed{ \text{some capabilities survive better than others} }

rather than:

\boxed{ \text{all capabilities shrink equally} }.

The benchmark table demonstrates exactly this unevenness. (Source: Build a DeepSeek Model (From Scratch))

3. 1.5B is the clearest example

For the reported 1.5B student:

\text{MATH-500}=83.9\%

but:

\text{LiveCodeBench}=16.9\%.

Therefore:

83.9-16.9 = \boxed{67.0}

percentage points.

So the model is very strong in one reported domain and much weaker in another.

That is a classic capacity-gap signature. (Source: Build a DeepSeek Model (From Scratch))

4. Why coding suffers more

The source's explanation is that coding requires a much broader representational space:

\text{syntax} + \text{APIs} + \text{libraries} + \text{architectural patterns} + \text{program behavior}.

A very small model may simply not have enough capacity to retain all of these patterns while also maintaining general language capability.

The chapter explicitly interprets the 1.5B coding weakness this way. (Source: Build a DeepSeek Model (From Scratch))

5. This gives us an important design rule

Do not ask only:

“How many parameters does my student have?”

Also ask:

\boxed{ \text{What capability am I trying to compress?} }

For a narrow task:

\text{small student}

may work surprisingly well.

For broad general-purpose behavior:

\text{larger student}

may be necessary.

Correction: Teacher capability limits demonstrations it can provide, but does not establish student accuracy≤teacher accuracy. The transfer intuition is not a mathematical ceiling.

Complete grounded review

6. Second limit — teacher quality

Distillation cannot transfer what the teacher does not know.

Let:

f_T(x)

be teacher behavior.

Student tries to approximate:

f_S(x)\approx f_T(x).

If:

f_T

contains an error, then a naive student-training pipeline may learn that error.

Therefore:

\boxed{ \text{teacher quality sets the quality ceiling of transferable behavior} }

The source repeatedly emphasizes that distillation transfers existing capabilities rather than creating entirely new ones. (Source: Build a DeepSeek Model (From Scratch))

7. Why rejection sampling matters here

Suppose the teacher produces:

100

candidate responses.

Imagine:

70

are good and:

30

are poor.

If we train on all 100:

\boxed{ 30\%\text{ noisy supervision} }

enters the student.

But if verification/filtering retains only:

65

high-quality examples, then the student sees a much cleaner target distribution.

So rejection sampling changes:

\boxed{ \text{raw teacher behavior} \rightarrow \text{selected teacher behavior} }

before the student learns it.

8. The student learns style as well as content

This is an especially important insight from the source.

Suppose the dataset contains many responses with:

  • chaotic formatting,
  • language mixing,
  • excessive code blocks,
  • incoherent explanations.

The student can learn those patterns because they are present in its training targets.

Therefore:

\boxed{ \text{data quality controls learned behavior quality} }

not merely benchmark correctness.

The chapter explicitly says the student learns to mimic the style of the training data as well as its content. (Source: Build a DeepSeek Model (From Scratch))

9. Therefore, rejection sampling is not just “remove wrong answers”

The actual filtering objective is closer to:

\boxed{ \text{correct} \cap \text{well-formatted} \cap \text{useful} }

Only the intersection should ideally enter the student dataset.

This is why:

\boxed{\text{data curation}}

is effectively part of the model-training algorithm.

10. Third limit — base model matters

The student does not start from zero.

Let:

S_0

be the pretrained base.

Distillation gives:

S_0 \rightarrow S_1.

So:

\boxed{ S_0\text{'s prior capability affects what can be learned} }

The source explicitly notes that distillation is not “one size fits all.” The base model's pretrained knowledge interacts with teacher-generated data. (Source: Build a DeepSeek Model (From Scratch))

11. Think of distillation as adding on top of a foundation

Imagine two students receive exactly the same teacher lessons.

Student A:

\text{strong algebra foundation}

Student B:

\text{weak algebra foundation}.

The same teacher explanation can produce different results.

Likewise:

\boxed{ \text{same teacher data} + \text{different base model} \Rightarrow \text{different final student} }

That is why base-model selection is strategically important. (Source: Build a DeepSeek Model (From Scratch))

12. Qwen vs Llama evidence

The reported AIME results include:

\text{Qwen-7B}=55.5\%

and:

\text{Llama-8B}=50.4\%.

So:

55.5-50.4 = \boxed{5.1}

percentage points.

The Llama model is actually slightly larger but performs worse on this reported benchmark.

Thus:

\boxed{ \text{parameter count alone is insufficient} }

The source attributes this to differences in the base model and pretrained capabilities. (Source: Build a DeepSeek Model (From Scratch))

13. Strategic student-selection rule

For math-heavy applications, the chapter points toward a math-capable base.

For broader applications, a general-purpose base may be preferable.

Conceptually:

\boxed{ \text{choose the base whose prior capabilities match the target domain} }

rather than blindly choosing the largest available model. (Source: Build a DeepSeek Model (From Scratch))

14. Fourth limit — sequence length

Reasoning traces can be very long.

The source reports an average sample length of:

\boxed{5,355\text{ tokens}}

for its large DeepSeek-R1 distillation dataset. (Source: Build a DeepSeek Model (From Scratch))

Long reasoning traces are valuable because they carry more intermediate reasoning.

But they also increase compute cost.

15. Why long context is expensive

For standard self-attention:

\boxed{ \text{attention matrix}\in\mathbb{R}^{N\times N} }

so attention work grows approximately as:

O(N^2).

If:

N\rightarrow2N,

then approximately:

N^2\rightarrow4N^2.

Therefore:

\boxed{ \text{doubling sequence length}\approx4\times\text{ quadratic attention work} }

for the attention component.

16. Source's practical sequence-length filtering

In the smaller hands-on experiment, the raw examples had:

\text{average}=2946

tokens,

while the longest reached:

42005.

The chapter filters to:

\boxed{2048}

maximum sequence length for the demonstration. (Source: Build a Reasoning Model (From Scratch))

17. Why filtering can make distillation feasible

Suppose an example has:

42,005

tokens.

Compared with:

2,048,

the approximate quadratic attention-work ratio is:

\left(\frac{42005}{2048}\right)^2
\approx (20.51)^2
\approx \boxed{421}.

So the quadratic attention component for the extremely long sequence can be hundreds of times larger.

That illustrates why long-sequence filtering can dramatically reduce cost.

This is a derived numerical interpretation of the source's lengths, not a runtime measurement reported by the source.

18. Fifth limit — the student may memorize style without understanding

This is a conceptual subtlety.

Suppose the dataset contains:

Step 1...
Step 2...
Step 3...
Answer...

The student learns the token patterns.

But successful sequence prediction does not necessarily mean the student has internally reproduced exactly the teacher's reasoning mechanism.

What we can safely say from the source is that the student learns to reproduce teacher behavior/reasoning traces through supervised next-token prediction. (Source: Build a Reasoning Model (From Scratch))

So:

\boxed{ \text{behavioral imitation} \neq \text{literal internal mechanism copying} }

This distinction is important when discussing what “knowledge transfer” really means.

19. Sixth limit — distillation does not automatically create new reasoning

Suppose teacher capability is:

C_T.

Student learns:

C_S\approx\text{compressed subset of }C_T.

Pure imitation does not normally create:

C_{\text{new}}>C_T.

The source explicitly says advancing beyond the teacher's frontier may require stronger base models and larger-scale reinforcement learning. (Source: Build a DeepSeek Model (From Scratch))

Therefore:

\boxed{ \text{distillation = transfer} }

while:

\boxed{ \text{RL = potential capability discovery/improvement} }

20. This explains why RL and distillation are complementary

The full picture is:

\boxed{ \text{RL} \rightarrow \text{improve teacher} }

then:

\boxed{ \text{distillation} \rightarrow \text{compress/distribute teacher} }

So the two-stage strategy is:

\boxed{ \text{discover first} \rightarrow \text{compress second} }

This is one of the deepest conclusions of the chapter. (Source: Build a DeepSeek Model (From Scratch))

21. Why small-model RL can fail

The source reports that smaller models such as 7B dense and 16B MoE models showed little meaningful AIME improvement under direct RL in the described experiments.

It notes that increasing response lengths led these smaller models toward repetition and that they could not effectively exploit long chains of thought. (Source: Build a DeepSeek Model (From Scratch))

So the problem can be expressed as:

\boxed{ \text{RL exploration requirement} > \text{small model's effective capacity} }

at least in the described setup.

22. Distillation changes the problem

Direct RL asks:

Discover a useful reasoning strategy.

Distillation asks:

Reproduce this strategy that already exists in the dataset.

Thus:

\boxed{ \text{exploration} \rightarrow \text{imitation} }

The source describes this as the fundamental advantage of distillation for smaller models. (Source: Build a DeepSeek Model (From Scratch))

23. Numerical comparison of training effort

The reported same-architecture experiment used:

RL
>10,000

policy-gradient steps.

Distillation
2\text{–}3

SFT epochs.

(Source: Build a DeepSeek Model (From Scratch))

Do not directly conclude that:

10,000\text{ steps} > 3\text{ epochs}

in a precise computational sense, because a step and an epoch are different quantities.

What the source is demonstrating is the qualitative training-effort contrast:

\boxed{ \text{large repeated RL exploration} }

versus:

\boxed{ \text{a few passes over curated supervised data} }.

24. Training economics

The chapter reports these estimated figures:

\boxed{\$202K}

for DeepSeek-R1-Zero's RL training,

\boxed{\$82K}

for the full R1 pipeline,

and:

\boxed{\$10K}

for generating the distillation dataset.

It notes that the $10K figure corresponds to approximately:

\boxed{5,000\text{ H800 GPU hours}}

and that these cost values are estimates derived from disclosed GPU-hour counts and public cloud pricing; exact internal costs may differ. (Source: Build a DeepSeek Model (From Scratch))

25. Numerical — cost ratio

Using the chapter estimates:

\frac{202}{10} = \boxed{20.2}.

So the R1-Zero RL estimate is about 20.2 times the estimated distillation-data-generation cost.

Again:

\boxed{ \text{this is a chapter-specific estimate, not a universal cost ratio} }

26. The one-time investment property

This is one of the strongest systems ideas.

Suppose teacher-generated data costs:

\$10K.

Once the dataset exists, you can train:

S_1

then:

S_2

then:

S_3.

The expensive teacher-generation stage does not have to be repeated for each student.

The source explicitly emphasizes this reuse and notes that DeepSeek trained six students from the same data. (Source: Build a DeepSeek Model (From Scratch))

27. Numerical — amortizing teacher data

Suppose the data-generation cost is:

\$10,000

and six student models use it.

Ignoring student-training costs, average teacher-data-generation cost per student is:

\frac{10000}{6} = \boxed{\$1666.67}.

For:

20

students:

\frac{10000}{20} = \boxed{\$500}.

So the more students reuse the dataset, the lower the amortized teacher-data cost per student becomes.

28. But the data itself is large

The source's dataset is approximately:

804,745

samples.

Average length:

5,355

tokens.

Therefore:

804745\times5355 \approx \boxed{4.31\times10^9}

tokens.

So the dataset is enormous even though the student training procedure is comparatively simple.

This reminds us:

\boxed{ \text{simple training objective} \neq \text{small data/computation problem} }

33. Another important trade-off: context length

Suppose the student supports:

N=2048.

A long reasoning trace may be truncated.

Then the student may lose:

\boxed{\text{later reasoning steps}}

or:

\boxed{\text{final verification/answer}}.

So maximum sequence length is not merely a memory setting.

It can affect:

\boxed{\text{what portion of the teacher behavior is actually supervised}}

because the student cannot learn tokens that are removed from the training sequence.

This follows directly from the chapter's length filtering and answer-sequence training procedure. (Source: Build a Reasoning Model (From Scratch))

34. Numerical — truncation effect

Suppose a teacher trace has:

5,000

tokens.

Student maximum:

2,048.

Tokens discarded:

5000-2048 = \boxed{2952}.

Percentage discarded:

\frac{2952}{5000}\times100 = \boxed{59.04\%}.

So over half the teacher sequence would be unavailable to the student in that simple truncation scenario.

This is why length filtering is a substantive design decision.

36. Full limitation map

We can now summarize the limits:

\boxed{ \text{Teacher limitation} }

→ cannot transfer knowledge that is not present.

\boxed{ \text{Student capacity limitation} }

→ cannot absorb everything.

\boxed{ \text{Data quality limitation} }

→ noisy teacher outputs become noisy supervision.

\boxed{ \text{Base-model limitation} }

→ pretrained capabilities affect absorption.

\boxed{ \text{Sequence-length limitation} }

→ long reasoning traces increase cost or may be truncated.

\boxed{ \text{Frontier limitation} }

→ distillation mainly transfers existing behavior rather than discovering beyond the teacher.

39. Final exam framework for the entire chapter

For any distillation question, identify these five things:

1. Teacher
\boxed{\text{Who generates the knowledge?}}
2. Transfer signal
\boxed{ \text{logits/probabilities or text?} }
3. Objective
\boxed{ KL+CE \quad\text{or}\quad \text{next-token CE} }
4. Student
\boxed{ \text{How much capacity does it have?} }
5. Data quality
\boxed{ \text{Were teacher outputs verified and filtered?} }

Once these five are clear, most distillation questions become straightforward.
