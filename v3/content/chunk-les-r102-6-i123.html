Motivation

Translate classical teacher/student loss into correct log-probability arguments, temperature scaling, gradients and parameter accounting.

Prerequisites

  • Stable softmax/logsumexp
  • KL direction
  • Matrix/embedding parameter counts

Notation and units

  • p_T=softmax(z_T/T)
  • q_T=softmax(z_S/T)
  • alpha: hard-loss weight
  • L=alpha CE+(1-alpha)T² KL(p_T||q_T)

Assumptions

  • Teacher outputs are detached
  • True class index0 in inherited numerical
  • Same four classes in exact example
  • Batch/position reduction explicitly declared

Step-by-step derivation

  1. Calculate stable teacher probabilities p_T and student log probabilities log q_T from logits divided by positive T.
  2. Evaluate KL=sum_c p_T,c(log p_T,c-log q_T,c). PyTorch input log q_T with target p_T realizes teacher-to-student KL despite the argument order.
  3. Calculate hard CE from unscaled student logits against the actual class label.
  4. Multiply KL by T² and combine using alpha. Do not call T²KL both L_soft and KL then multiply T² twice.
  5. Differentiate with respect to student logits: alpha(q_1-onehot)+(1-alpha)*T*(q_T-p_T). This exact gradient is independently checked by finite differences.
  6. The high-temperature difference q_T-p_T is order1/T, explaining the familiar approximately1/T² unscaled gradient; that scaling is asymptotic rather than a universal exact statement.
  7. Freeze teacher and optimize only student; eval disables teacher dropout, while no_grad disables teacher graph tracking.
  8. Count each embedding, every matrix and every bias. For the provided toy teacher the layers total40,138 parameters, not about26k; the student totals8,810.
  9. For[B,S,V] logits, batchmean KL divides by B, not B*S; tokenmean requires flattening valid positions or masked explicit normalization.

Mastery answers and retained exercise context

  1. no_grad prevents teacher graph tracking; eval separately controls dropout/module behavior.
  2. Temperature exposes more relative nonwinning probabilities.
  3. T² compensates high-temperature gradient scaling rather than guaranteeing a constant gradient for allT.
  4. R1 text distillation uses CE over curated generated responses instead of this logit objective.
  5. Capacity and teacher/data quality still constrain results.

Edge cases and remaining gaps

  • Loss minimization does not guarantee the distilled student outperforms an equally trained baseline.
  • A teacher that is random or poorly trained supplies poor supervision.
  • The supplied classification toy is not a faithful reproduction of language-model R1 distillation.

Now that we understand why DeepSeek's reasoning distillation differs from classical KD, the source takes us back to implementation.

This step is important because we should be able to look at the mathematics and translate it directly into:

\boxed{\text{PyTorch computation} \rightarrow \text{loss} \rightarrow \text{backpropagation}}

The source deliberately uses toy-sized models so that the entire process can be traced by hand. (Source: Build a DeepSeek Model (From Scratch))

1. First, be clear about which distillation we are implementing

There are two things in the chapter:

Classical KD
\boxed{ \text{Teacher logits} \rightarrow \text{soft targets} \rightarrow KL }

This is what Section 8.6 implements.

DeepSeek-R1 reasoning distillation
\boxed{ \text{R1-generated text} \rightarrow \text{filtered dataset} \rightarrow \text{SFT} }

That was the subject of R102.5.

So when we now write code containing:

teacher_logits
student_logits
temperature
KL divergence

we are implementing classical KD, not the actual R1 reasoning-distillation recipe.

That distinction must remain explicit. (Source: Build a DeepSeek Model (From Scratch))

3. The training step

The entire classical KD training step is:

                Input batch
               /           \
              /             \
             ▼               ▼
        Frozen Teacher    Trainable Student
             │               │
             ▼               ▼
       teacher logits    student logits
             │               │
             │          ┌────┴─────┐
             │          │          │
             │          ▼          ▼
             │       Hard CE     Soft logits
             │                       │
             │                       ▼
             │                      KL
             │                       │
             └───────────────────────┘
                         │
                         ▼
                       Total loss
                         │
                         ▼
                    Backpropagation
                         │
                         ▼
                  Student parameters

Only the student is updated. (Source: Build a DeepSeek Model (From Scratch))

4. Step 1 — Teacher forward pass

We send the input through the teacher:

x\rightarrow T(x)=z_T

where:

z_T\in\mathbb{R}^{C}

contains the teacher logits.

But the teacher is frozen.

Therefore the source uses:

with torch.no_grad():
    t_logits = teacher(x)

Why?

Because we don't need gradients through the teacher.

Computing them would waste memory and computation. (Source: Build a DeepSeek Model (From Scratch))

5. Step 2 — Student forward pass

The same input goes through the student:

x\rightarrow S_\theta(x)=z_S

Here gradients are required because:

\theta

must be updated.

So:

s_logits = student(x)

6. Step 3 — Hard-label loss

The first branch is ordinary language/classification learning.

We use the ground-truth label y:

\boxed{ L_{\text{hard}} = CE(z_S,y) }

This branch answers:

Is the student's actual prediction correct?

In PyTorch:

hard_loss = F.cross_entropy(
    student_logits,
    labels
)

(Source: Build a DeepSeek Model (From Scratch))

7. Step 4 — Make the teacher's distribution soft

Now we use temperature:

p_T^{(T)} = \operatorname{softmax} \left( \frac{z_T}{T} \right).

Similarly:

p_S^{(T)} = \operatorname{softmax} \left( \frac{z_S}{T} \right).

In code:

soft_teacher = F.softmax(
    teacher_logits / temperature,
    dim=-1
)

soft_student = F.log_softmax(
    student_logits / temperature,
    dim=-1
)

The student uses log_softmax because PyTorch's KL implementation expects the input in log-probability form. (Source: Build a DeepSeek Model (From Scratch))

8. Step 5 — KL divergence

Now compare:

p_T^{(T)}

with:

p_S^{(T)}.

The source uses:

\boxed{ KL(p_T^{(T)}\|p_S^{(T)}) }

implemented as:

kl_loss = F.kl_div(
    soft_student,
    soft_teacher,
    reduction='batchmean'
)

(Source: Build a DeepSeek Model (From Scratch))

The interpretation is:

“Make the student's probability distribution look like the teacher's probability distribution.”

9. Step 6 — Apply T^2

Remember:

L_{\text{soft}} = T^2 KL(p_T^{(T)}\|p_S^{(T)}).

Why?

Because increasing T reduces gradient magnitude approximately as:

\frac{1}{T^2}.

Thus:

\boxed{ T^2 }

compensates for that scaling effect. (Source: Build a DeepSeek Model (From Scratch))

Correction: Notation correction: define L_soft=KL, then L=alpha L_hard+(1-alpha)T² L_soft; or define L_soft=T²KL and omit anotherT². The numerical example uses the scaling once.

10. Step 7 — Combine the two objectives

The final loss is:

\boxed{ L = \alpha L_{\text{hard}} + (1-\alpha)T^2L_{\text{soft}} }

in the implementation used by the source.

So there are two teachers influencing the student, conceptually:

Ground truth
     │
     ▼
"Be correct."

Teacher
     │
     ▼
"Behave like me."

        ↓

      Student

The ground truth provides correctness.

The teacher provides richer distributional information.

The source gives:

14. Complete classical KD code

The source's complete toy training setup is essentially:

import torch
import torch.nn as nn
import torch.nn.functional as F


class TeacherModel(nn.Module):
    def __init__(self, vocab=100, d=64, classes=10):
        super().__init__()

        self.embed = nn.Embedding(vocab, d)

        self.net = nn.Sequential(
            nn.Linear(d, 128),
            nn.ReLU(),

            nn.Linear(128, 128),
            nn.ReLU(),

            nn.Linear(128, 64),
            nn.ReLU(),

            nn.Linear(64, classes)
        )

    def forward(self, x):
        return self.net(
            self.embed(x).mean(dim=1)
        )


class StudentModel(nn.Module):
    def __init__(self, vocab=100, d=64, classes=10):
        super().__init__()

        self.embed = nn.Embedding(vocab, d)

        self.net = nn.Sequential(
            nn.Linear(d, 32),
            nn.ReLU(),

            nn.Linear(32, classes)
        )

    def forward(self, x):
        return self.net(
            self.embed(x).mean(dim=1)
        )


def distillation_loss(
    student_logits,
    teacher_logits,
    labels,
    temperature=3.0,
    alpha=0.3
):
    soft_teacher = F.softmax(
        teacher_logits / temperature,
        dim=-1
    )

    soft_student = F.log_softmax(
        student_logits / temperature,
        dim=-1
    )

    kl_loss = F.kl_div(
        soft_student,
        soft_teacher,
        reduction='batchmean'
    )

    hard_loss = F.cross_entropy(
        student_logits,
        labels
    )

    return (
        alpha * hard_loss
        + (1 - alpha)
        * temperature**2
        * kl_loss
    )


def train_distill(
    teacher,
    student,
    loader,
    epochs=10,
    T=3.0,
    alpha=0.3,
    lr=1e-3
):
    teacher.eval()

    optimizer = torch.optim.Adam(
        student.parameters(),
        lr=lr
    )

    for epoch in range(epochs):

        total = 0.0

        for x, y in loader:

            optimizer.zero_grad()

            with torch.no_grad():
                teacher_logits = teacher(x)

            student_logits = student(x)

            loss = distillation_loss(
                student_logits,
                teacher_logits,
                y,
                temperature=T,
                alpha=alpha
            )

            loss.backward()
            optimizer.step()

            total += loss.item()

        print(
            f"Epoch {epoch + 1}: "
            f"{total / len(loader):.4f}"
        )

This follows the training-loop structure in the source. (Source: Build a DeepSeek Model (From Scratch))

15. Notice where the gradient flows

This deserves special attention.

The graph is:

\text{Teacher} \rightarrow z_T

but:

\boxed{\nabla_{\theta_T}=0}

because the teacher is frozen.

The student produces:

z_S

and:

\boxed{\nabla_{\theta_S}\neq0}.

So after:

loss.backward()

the optimizer performs:

optimizer.step()

on:

\boxed{\theta_S}

only.

This is the defining teacher-student asymmetry in classical KD. (Source: Build a DeepSeek Model (From Scratch))

\boxed{CE}

Experiment 2 — Distillation

\boxed{ \alpha CE+(1-\alpha)T^2KL }

This gives:

\boxed{ \text{Student baseline} < \text{Distilled student} < \text{Teacher} }

17. Why distillation helps particularly on ambiguous examples

Suppose the correct class is A.

Hard-label training says:

A=1,\qquad B=C=D=0.

The teacher might instead say:

A=.60,\quad B=.30,\quad C=.08,\quad D=.02.

The student learns not just:

“A is correct.”

but also:

“B is considerably closer to A than C or D.”

That additional relational structure is what the source means by:

\boxed{\text{dark knowledge}}.

The source notes that the benefit is particularly visible on ambiguous or closely related examples. (Source: Build a DeepSeek Model (From Scratch))

18. Now connect this back to DeepSeek-R1

This is where many students accidentally mix up the methods.

Classical KD:

\boxed{ R1\text{-style teacher} \rightarrow \text{logits} \rightarrow KL }

would require us to have access to the teacher's internal output distribution during training.

But DeepSeek's R1 distillation does:

\boxed{ R1 \rightarrow \text{generate response} \rightarrow \text{filter} \rightarrow \text{text dataset} \rightarrow SFT }

No teacher logits are needed during student training. (Source: Build a DeepSeek Model (From Scratch))

19. Why this matters enormously at R1 scale

Imagine attempting classical KD using a 671B teacher.

The teacher and student have to participate in the training computation.

That's extremely expensive.

DeepSeek's approach instead performs:

Expensive operation once
\text{R1 teacher} \rightarrow \text{800K curated examples}

Then:

Cheap/reusable operation
\text{800K static examples} \rightarrow \text{many students}.

The source explicitly emphasizes this decoupling as a major practical advantage. (Source: Build a DeepSeek Model (From Scratch))

21. The deeper idea: exploration vs imitation

The source makes a particularly interesting argument later in the chapter.

During RL, a huge model can:

\boxed{ \text{explore} \rightarrow \text{fail} \rightarrow \text{recover} \rightarrow \text{discover} }

A tiny student may not have enough capacity to discover those strategies independently.

But after the teacher has discovered them, the student only needs to:

\boxed{\text{imitate}}

through supervised learning. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{Exploration is harder than imitation} }

and distillation transforms the former into the latter.

That is a deep reason why an RL-trained teacher can be used to create surprisingly capable smaller models.

22. But compression is not lossless

The source's empirical section shows that the teacher remains ahead.

It reports:

\text{DeepSeek-R1}: 79.8\%\ \text{AIME}

versus:

\text{best distilled}:72.6\%.

So:

\boxed{ \text{student} < \text{teacher} }

in ultimate capability.

Distillation is therefore not magic compression of every capability into an arbitrarily tiny model. (Source: Build a DeepSeek Model (From Scratch))

23. The capacity gap explains why

The source reports for the 1.5B model:

83.9\%\quad\text{MATH-500}

but only:

16.9\%\quad\text{LiveCodeBench}.

(Source: Build a DeepSeek Model (From Scratch))

The source's explanation is that mathematical reasoning has relatively structured and repeatable solution patterns, whereas coding spans a much larger space of syntax, APIs, design patterns, error handling, and implementation choices.

Therefore:

\boxed{ \text{different capabilities have different compressibility} }

24. The student-size intuition from the source

The chapter gives these practical bands:

\boxed{1.5B-3B}

for narrow, well-defined reasoning domains.

\boxed{7B-14B}

as a suggested sweet spot for more general reasoning.

\boxed{32B-70B}

for getting much closer to teacher-level quality across domains. (Source: Build a DeepSeek Model (From Scratch))

These are source-specific practical guidelines, not universal laws.

You should now be able to answer these without calculation:

Why is the teacher run under torch.no_grad()?

Because its weights are frozen; only the student receives gradients. (Source: Build a DeepSeek Model (From Scratch))

Why divide logits by T?

To soften the probability distribution and expose more relative information among alternatives. (Source: Build a DeepSeek Model (From Scratch))

Why multiply the KL term by T^2?

To compensate for the reduction in gradient magnitude caused by temperature scaling. (Source: Build a DeepSeek Model (From Scratch))

Why doesn't DeepSeek-R1 reasoning distillation use this classical KD loss?

Because the source treats the valuable teacher signal as the generated reasoning trajectory, so the student is trained on curated teacher-generated text using ordinary SFT rather than teacher-logit KL matching. (Source: Build a DeepSeek Model (From Scratch))

What is the biggest practical limitation?

The capacity gap: a student that is too small cannot absorb every capability of the teacher equally well. (Source: Build a DeepSeek Model (From Scratch))
