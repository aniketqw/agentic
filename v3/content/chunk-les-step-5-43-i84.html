Complete lesson review: derivation, checked numericals, answers and source boundaries

Read this review alongside the preserved lesson below. Corrections qualify inherited claims. Sources support named mechanisms; teaching fixtures are independent reconstructions. Earlier progress reports remain historical snapshots.

Motivation

Integrate attention-history reuse and expert conditional computation without mixing their bottlenecks.

Prerequisites

  • Causal attention, stable row softmax andmatrix shapes
  • Row-versuscolumn convention; matrix associativity andtranspose identities
  • Bytes per element, batch, layer/head dimensions; RoPErotations
  • Two-layer FFN matrix shapes and parameter counts
  • Stable softmax, top-k, integer indices and gather/scatter accumulation
  • Expert parallelism, load/importance distinction and non-gradient feedback

Notation and units

  • B=batch, L=layers, T=cached tokens, Hkv=KV heads, dh=head width, bc=bytes per cache element
  • Row convention: X[T, D], Wdown[D, dc], WUK[dc, dh], WUV[dc, dv]
  • MLA cache stores cKV[T, dc] and decoupled position key[T, dR]
  • T=B×S flattened tokens, D model width, N routed experts, k selected per token
  • Row score matrix[T, N]; selected indices and gates[T, k]; final stream[T, D]
  • Book bias is a persistent nontrainable buffer; gate weights come from softmax selected biased logits
  • V3: si=sigmoid(x·ei); select by si+bi; normalize original si within selected set

Assumptions

  • Decoder-only causal inference with fixed weights, deterministic evaluation and consistent positions
  • No quantization, padding overhead, cache fragmentation, beam duplication orallocatorcost unless specified
  • Each attentionhead has its own softmax; equal absorption uses the same factorized weights
  • Bias-free educational two-matrix GELU experts use2DHparameters; gated/SwiGLUuses3DH
  • Per-tokenk/N is routed expert activation fraction, notcomplete-model storage or latency ratio
  • The Transformer owns the residual unless a standalone MoE explicitly returns x+transform; neveraddit twice
  • Tie behavior and normalization must be explicit; expert choices are learned, not manual domain labels

Step-by-step derivation

  1. The pre-norm block first forms u=Norm(X), then H=X+MLA(u). The attention return must have[B, S, D]to fit the residual. Its per-layerlatent/position cache persists across generation steps.
  2. Secondforms v=Norm(H), then Y=H+F_MoE(v), where F_MoE=shared+routed transformations without another internal residual. Router input is the post-attention normalized representation.
  3. RMSNorm uses x/sqrt(mean(x²)+epsilon)times learned scale; LayerNorm subtracts mean and scales variance. The book MiniDeepSeek LayerNorm simplification is not production RMSNorm.
  4. Attention selects history positions; MoE selects expert functions for current representations. Neither mechanism replaces the other: latent cache concerns activation history; experts concern weight capacity/conditional compute.
  5. For B2, S512, D2048, N64, k8, H1024:1024tokens, router[1024,64], indices[1024,8],8192assignments and128idealload. Routedpool268,435,456weights versus33,554,432activeper-token before shared/router/dense components.
  6. Training can compute causal positions in parallel while decoding uses prefix caches; position offset, mask, weight version and residual ownership must stay consistent. A full network training benchmark is a separate claim from these tensor/numeric checks.

Mastery answers and retained exercise context

  1. What does MLA solve? Persistent attention-history cache cost.
  2. What does MoE solve? Scaling expert capacity with sparse per-token FFN work.
  3. Does MoE erase unused weights? No; expert pool remains accessible.
  4. Where should residual be added? Once around each sublayer transformation.
  5. WhyisbookLayerNormnot exact production? RMSNormdoes not center by mean; thebookusesLayerNormfor simplicity.

  • All expert weights must remain available, possibly sharded/offloaded; unselected does not mean not stored
  • Dispatch, all-to-all communication, kernel batching and load imbalance can reduce ideal compute advantages
  • No real DeepSeek training, pretrained quality evaluation or distributed hardware benchmark was run

Step 5.43 — How MLA and MoE Fit Together in the DeepSeek Transformer

Plan node: A2 · chat order #84

↩ Back to main text: Step 1.10 — Position-Wise Feed-Forward Network (FFN / MLP)

We now move from understanding MoE internally to understanding where MoE sits inside the entire DeepSeek Transformer.

This is important because MLA and MoE are sometimes mentally mixed together as “two efficiency tricks.” They are not solving the same problem.

The source explicitly frames DeepSeek's architecture as a Transformer in which the conventional multi-head attention is replaced by Multi-Head Latent Attention (MLA) and the conventional feed-forward network is replaced by DeepSeek-Mixture-of-Experts (MoE). (Source: Build a DeepSeek Model (From Scratch))

So the first thing to lock in is:

\boxed{ \text{MLA and MoE occupy different parts of the Transformer block} }

5.43.1 Start from the standard Transformer block

A conventional decoder-only Transformer block is conceptually:

\boxed{ X \rightarrow \text{Attention} \rightarrow \text{Residual} \rightarrow \text{FFN} \rightarrow \text{Residual} }

With pre-normalization:

\boxed{ H_1=X+\operatorname{Attention}(\operatorname{Norm}(X)) }

then:

\boxed{ Y=H_1+\operatorname{FFN}(\operatorname{Norm}(H_1)) }

This is the basic structure we have already used when studying Transformer blocks.

The DeepSeek source's MiniDeepSeek implementation follows this same pattern: normalize → attention → residual, then normalize → MoE → residual. (Source: Build a DeepSeek Model (From Scratch))

5.43.2 DeepSeek changes the first sub-block

Instead of:

\boxed{\text{standard MHA}}

DeepSeek uses:

\boxed{\text{MLA + decoupled RoPE}}

Why?

Because the standard KV cache becomes very expensive for long contexts.

The source describes MLA as specifically targeting the KV-cache memory bottleneck by caching a compressed latent representation rather than the full K/V tensors. (Source: Build a DeepSeek Model (From Scratch))

So MLA is primarily an:

\boxed{\text{attention-memory optimization}}

in the source's framing.

5.43.3 DeepSeek changes the second sub-block

Instead of:

\boxed{\text{dense FFN}}

DeepSeek uses:

\boxed{\text{MoE}}

Why?

Because a dense FFN activates all of its expert-like capacity for every token.

MoE instead provides:

\boxed{ \text{many parameters} + \text{only a sparse subset active/token} }

The source describes MoE as addressing computationally expensive dense FFNs through sparse expert activation.

So MoE is primarily a:

\boxed{\text{conditional-computation / parameter-scaling mechanism}}

in the source's framing.

5.43.4 Therefore the DeepSeek block is

Conceptually:

\boxed{ X \rightarrow \operatorname{RMSNorm} \rightarrow \operatorname{MLA} \rightarrow + \rightarrow \operatorname{RMSNorm} \rightarrow \operatorname{MoE} \rightarrow + }

In the source's educational MiniDeepSeek implementation, LayerNorm is used for simplicity while the text explicitly notes that DeepSeek uses RMSNorm. (Source: Build a DeepSeek Model (From Scratch))

So distinguish:

\boxed{ \text{source implementation choice} }

from:

\boxed{ \text{DeepSeek architectural description} }.

5.43.6 The most important conceptual separation

Remember:

\boxed{\text{MLA decides how tokens attend to one another}}

while:

\boxed{\text{MoE decides which FFN experts process each token}}

That is the cleanest distinction.

5.43.7 MLA's question

MLA receives token representations:

X

and asks:

Which previous tokens should this token retrieve information from?

So it produces:

Q,K,V

or their latent/decoupled equivalents and performs attention.

The central problem is:

\boxed{\text{KV cache memory}}

The source describes MLA as compressing the information stored in K/V while reconstructing the required representations for attention. (Source: Build a DeepSeek Model (From Scratch))

5.43.8 MoE's question

MoE receives the output of the attention sub-block:

H.

It asks:

Which specialized feed-forward networks should process this token?

The router gives:

L=H W_R+b

then:

TopK(L)

then:

\sum_i g_iE_i(H).

The central problem is:

\boxed{\text{dense FFN computation / scaling}}

The source explicitly positions MoE as a replacement for the expensive dense FFN.

5.43.9 Very important: MLA does not route experts

MLA does not say:

T_1\rightarrow E_3.

That's MoE.

MLA says something like:

T_t \rightarrow \text{attend to }T_1,T_2,\ldots,T_{t-1}.

So:

\boxed{ \text{Attention routing across positions} }

and:

\boxed{ \text{MoE routing across experts} }

are two completely different routing processes.

5.43.10 Example

Suppose we have:

The cat sat on the mat

For the token:

\text{“mat”}
MLA/attention

It may attend strongly to:

\text{“cat”}

or:

\text{“sat”}

or:

\text{“the”}.

This determines what contextual information the token representation receives.

MoE

After attention, the representation of “mat” might be routed to:

E_4,E_17,E_{31}.

Those experts transform the representation.

Therefore:

\boxed{ \text{Attention = gather context} }
\boxed{ \text{MoE = transform context using specialized pathways} }

This is an interpretation built from the two source mechanisms.

5.43.11 Think of the Transformer block as two questions

Question A
\boxed{ \text{“What information from other tokens do I need?”} }

Answer:

\text{MLA}.
Question B
\boxed{ \text{“How should I transform the information I've gathered?”} }

Answer:

\text{MoE}.

That is why these mechanisms complement each other.

5.43.12 Why MLA solves memory, not parameter sparsity

Suppose standard MHA has huge K/V cache:

\boxed{\text{large cache}}

MLA compresses that cache.

Therefore:

\boxed{ \text{MLA} \rightarrow \text{lower KV-cache memory} }

It does not fundamentally make the FFN sparse.

That's MoE's job.

5.43.13 Why MoE does not solve the KV-cache problem

Suppose you have:

100{,}000

tokens.

Even if your FFN is perfectly sparse, attention still needs to deal with the history.

The KV cache still exists.

Thus:

\boxed{ \text{MoE does not replace MLA} }

and:

\boxed{ \text{MLA does not replace MoE}. }

They target different bottlenecks.

5.43.14 The architecture hierarchy

This is the hierarchy you should memorize:

\boxed{\text{Transformer}}

contains:

\boxed{\text{Attention sub-block}}

and:

\boxed{\text{FFN/MoE sub-block}}.

DeepSeek replaces them with:

\boxed{ \text{Attention} \rightarrow \text{MLA} }

and:

\boxed{ \text{FFN} \rightarrow \text{DeepSeek-MoE} }.

The source explicitly presents DeepSeek this way. (Source: Build a DeepSeek Model (From Scratch))

5.43.15 Now add RMSNorm

Before MLA:

X_N=\operatorname{Norm}(X).

Then:

H=X+\operatorname{MLA}(X_N).

Then:

H_N=\operatorname{Norm}(H).

Then:

Y=H+\operatorname{MoE}(H_N).

So the full mathematical skeleton is:

\boxed{ H=X+\operatorname{MLA}(\operatorname{Norm}(X)) }
\boxed{ Y=H+\operatorname{MoE}(\operatorname{Norm}(H)) }.

The source's TransformerBlock uses precisely this computational ordering, though its simplified code uses LayerNorm rather than an RMSNorm implementation. (Source: Build a DeepSeek Model (From Scratch))

5.43.16 DeepSeek's educational code

The source's block is essentially:

h, new_cache = self.attention(
    self.norm1(x),
    attn_mask,
    past_kv,
    position_offset
)

x = x + h

x = x + self.feed_forward(
    self.norm2(x)
)

return x, new_cache

(Source: Build a DeepSeek Model (From Scratch))

Here:

\texttt{self.attention} = \text{DeepSeekAttention}

and:

\texttt{self.feed\_forward} = \text{DeepSeekMoE}.

5.43.17 Trace one tensor through the block

Suppose:

Input:

X: \boxed{2\times16\times512}.

Normalization:

\boxed{2\times16\times512}.

MLA output:

\boxed{2\times16\times512}.

Residual addition:

\boxed{2\times16\times512}.

\boxed{2\times16\times512}.

\boxed{2\times16\times512}.

5.43.18 Why this matters

Attention temporarily creates internal tensors with dimensions based on:

\text{heads},\text{latent dimensions},\text{RoPE dimensions}.

MoE temporarily creates:

\text{expert-specific token groups}.

But the residual stream continues to be:

\boxed{B\times S\times D}.

This makes the whole architecture composable.

5.43.19 Now connect MLA's cache to MoE's parameters

This is where DeepSeek becomes interesting.

MLA

reduces the cost of storing the history used by attention.

MoE

increases the total parameter capacity without activating all expert parameters per token.

So conceptually:

\boxed{ \text{MLA} \rightarrow \text{memory efficiency} }

and:

\boxed{ \text{MoE} \rightarrow \text{parameter/computation efficiency} }.

The source's roadmap explicitly describes MLA as reducing memory requirements and MoE as scaling intelligence efficiently through sparse experts.

5.43.20 Important distinction: cache vs weights

This deserves special emphasis.

MLA stores

past compressed representations:

\boxed{\text{latent KV information}}

for inference.

MoE stores

expert weights:

\boxed{E_1,E_2,\ldots,E_N}.

So:

\boxed{ \text{MLA problem} = \text{activation/cache memory} }

while:

\boxed{ \text{MoE problem} = \text{model capacity and conditional computation} }.

The exact memory behavior involves more details, but this is the conceptual distinction established by the source.

5.43.21 DeepSeek generation path

Suppose a new token arrives.

The model:

\boxed{ \text{token} \rightarrow \text{embedding} \rightarrow \text{Transformer blocks} \rightarrow \text{logits} }.

Inside each block:

\boxed{ \text{Norm} \rightarrow \text{MLA} \rightarrow \text{residual} \rightarrow \text{Norm} \rightarrow \text{MoE} \rightarrow \text{residual} }

The MLA path updates/uses its KV cache.

The MoE path selects experts for the token.

So one generated token simultaneously interacts with:

\boxed{ \text{past-token memory} }

through MLA and:

\boxed{ \text{specialized computation} }

through MoE.

5.43.22 A one-token inference trace

Suppose a token representation is:

x_t\in\mathbb R^D.
First norm
q_t=\operatorname{Norm}(x_t).
MLA

The token attends to cached history:

h_t=\operatorname{MLA}(q_t,\text{KV-cache}).
Residual
z_t=x_t+h_t.
Second norm
u_t=\operatorname{Norm}(z_t).
MoE router
L_t=u_tW_R+b.
Top-K
I_t=TopK(L_t,k).
Expert mixture
r_t= \sum_{i\in I_t}g_{t,i}E_i(u_t).
Residual
\boxed{ y_t=z_t+r_t. }

That is one complete Transformer block for one token.

5.43.23 Notice how the two caches/selection systems differ

MLA:

\boxed{ \text{historical token information} }

is reused.

MoE:

\boxed{ \text{historical expert choices do not determine the next token} }

because the router evaluates the current representation.

Each token can choose different experts.

So:

\boxed{ \text{KV cache = reuse past activations} }

while:

\boxed{ \text{MoE router = choose current computation} }.

Very important distinction.

5.43.26 MLA side numerical intuition

From our earlier MLA work, suppose:

\frac{32768}{512} = \boxed{64\times}.

Imagine, conceptually:

5.43.28 What happens to training?

During training, the same Transformer block processes the whole sequence in parallel.

The source's MiniDeepSeek architecture passes the sequence through the block and supports the MoE routing path; the training pipeline later combines MLA, MoE, and MTP.

For MoE:

T

tokens are routed to selected experts.

For MLA:

all sequence positions can participate in parallel attention subject to the causal mask during training.

So:

\boxed{ \text{training parallelism} }

and:

\boxed{ \text{inference autoregressive decoding} }

have different execution characteristics.

5.43.29 What happens during inference?

At inference time, the model generates one new token at a time.

MLA benefits from its:

\boxed{\text{KV cache}}

so it doesn't recompute all historical K/V representations.

MoE processes the current token through only the selected routed experts plus shared experts.

The source's inference path explicitly threads the past KV cache and position offset through each TransformerBlock. (Source: Build a DeepSeek Model (From Scratch))

5.43.33 Exam question: “Why can't MLA alone produce a 671B sparse model?”

Because MLA and MoE solve different things.

MLA changes:

\boxed{\text{attention representation/cache}}

It does not create:

\boxed{\text{specialized expert networks}}.

MoE creates:

\boxed{\text{many experts + sparse activation}}.

Therefore the 671B/37B distinction comes from the MoE-style conditional parameter activation, not from MLA.

The source attributes DeepSeek-R1's 671B total / 37B active-per-token figure to its MoE design. (Source: Build a DeepSeek Model (From Scratch))

5.43.34 Exam question: “Does MoE eliminate memory cost?”

No.

MoE gives:

\boxed{ \text{sparse computation} }

but the full expert weights still exist.

Thus:

\boxed{ \text{MoE} \neq \text{delete unused weights} }.

The source makes this explicit when discussing the 671B R1 model: all 671B parameters must still be stored even though only approximately 37B are activated per token. (Source: Build a DeepSeek Model (From Scratch))
