Assumptions

  • Synthetic data is explicitly distinguished from ground truth
  • Reported DeepSeek experiments are historical source results, not reruns
  • IID acceptance only for binomial toy calculations

Step-by-step derivation

  1. Separate R1-Zero(RL without initial SFT), R1(two SFT/two RL stages), and distilled students(SFT of pretrained dense bases).
  2. Create teacher-curated data once and reuse for multiple students; teacher generation cost excludes subsequent student training cost.
  3. For IID candidate acceptance p, none accepted probability(1-p)^k, so at least one 1-(1-p)^k. Correlated outputs violate IID.
  4. Compute parameter compression and raw 16-bit storage independently of benchmark scores and MoE active parameter count.
  5. Read AIME pass@1 as a particular historical evaluation setting; cons@64 is a different metric.
  6. Base-family comparison is suggestive, not architecture-only causal proof: model pretraining and math specialization differ.

Step 4.6 — The Complete DeepSeek-R1 Distillation Pipeline, Model Choices, and Empirical Results

Plan node: I5 · chat order #38

We have now understood how one teacher-generated response becomes one student training example.

The next level is to understand the complete system:

\boxed{ \text{How does DeepSeek go from a huge reasoning teacher to several much smaller models?} }

The supplied material gives us the complete picture: DeepSeek-R1 is first built through a staged post-training pipeline; then R1 becomes the teacher that generates a large synthetic dataset; that dataset is filtered; and smaller dense Qwen/Llama models are fine-tuned on it. (Source: Build a DeepSeek Model (From Scratch))

1. Start with the three models: R1-Zero, R1, and R1-Distill

These names are easy to confuse.

DeepSeek-R1-Zero

The source describes it as the pure RL experiment.

It starts from a base model and applies reasoning-oriented RL with verifiable rewards, without first using supervised chain-of-thought data.

Conceptually:

\boxed{ \text{Base} \rightarrow \text{RLVR} \rightarrow \text{R1-Zero} }

The interesting result is that reasoning-like behavior can emerge through RL pressure on verifiable tasks. (Source: Build a DeepSeek Model (From Scratch))

DeepSeek-R1

R1 is the more engineered and usable system.

The source describes its pipeline as involving:

\boxed{ \text{cold-start SFT} \rightarrow \text{reasoning RL} \rightarrow \text{rejection sampling} \rightarrow \text{mixed-data SFT} \rightarrow \text{final RL} }

The purpose is not merely to maximize mathematical correctness.

It also improves:

\text{readability} + \text{format} + \text{language consistency} + \text{general usefulness}.

(Source: Build a DeepSeek Model (From Scratch))

DeepSeek-R1-Distill

This is the smaller-student family.

The basic flow is:

\boxed{ \text{R1 teacher} \rightarrow \text{teacher-generated data} \rightarrow \text{filter} \rightarrow \text{SFT smaller model} }

The source explicitly says these smaller models are not trained by repeating the complete large-scale RL pipeline. (Source: Build a DeepSeek Model (From Scratch))

2. The complete six-stage picture

The distillation chapter describes the overall DeepSeek pipeline as a six-stage process, with distillation as Stage 6. (Source: Build a DeepSeek Model (From Scratch))

At the level relevant to this course, think of it as:

\boxed{ 1.\ \text{Pretraining} }
\downarrow
\boxed{ 2.\ \text{Cold-start supervised fine-tuning} }
\downarrow
\boxed{ 3.\ \text{Reasoning-oriented RL} }
\downarrow
\boxed{ 4.\ \text{Rejection sampling + supervised refinement} }
\downarrow
\boxed{ 5.\ \text{Final RL} }
\downarrow
\boxed{ 6.\ \text{Distillation} }

The exact figure is the source's organization; the important conceptual point is that distillation comes after the strong reasoning teacher has already been developed. (Source: Build a DeepSeek Model (From Scratch))

3. Why distill at the end?

This is the key strategic insight.

Suppose you distill from a weak model:

T_{\text{weak}} \rightarrow S.

Then the student can only imitate weak behavior.

Instead, you first create a much stronger reasoning model:

\text{Base} \rightarrow \text{RL/SFT} \rightarrow \boxed{\text{R1}}

and only then:

\boxed{\text{R1}} \rightarrow \text{distillation dataset} \rightarrow \boxed{\text{smaller models}}.

So:

\boxed{ \text{first create intelligence, then compress it} }

That is the architectural idea behind the entire process.

4. Why not train a 1.5B model with the same RL pipeline?

This is an excellent question.

The source gives the practical reasoning:

RL requires the smaller model to discover useful reasoning behavior through exploration.

That can be:

\text{expensive}

and:

\text{unstable}.

A strong teacher can instead provide successful examples directly.

Therefore:

RL route
\text{try} \rightarrow \text{reward} \rightarrow \text{update} \rightarrow \text{try again}.
Distillation route
\text{teacher already solved it} \rightarrow \text{copy successful strategy}.

The source explicitly says that distillation packages the teacher's solution patterns into supervised data so that the student does not have to rediscover them through expensive exploration. (Source: Build a DeepSeek Model (From Scratch))

5. The teacher is a data generator

This is the most important systems-level mental model.

Do not visualize:

671B teacher
      ↓
copy weights
      ↓
1.5B student

Instead:

671B teacher
      ↓
generate responses
      ↓
verify
      ↓
filter
      ↓
804K curated examples
      ↓
1.5B student
      ↓
SFT

So the teacher is acting as:

\boxed{\text{synthetic-data generator}}

rather than:

\boxed{\text{weight source}}.

The source explicitly describes the transfer from R1 to the distilled models as a data flow, not a parameter flow. (Source: Build a DeepSeek Model (From Scratch))

6. Rejection sampling at scale

Now let's examine the data-generation stage in more detail.

For each prompt:

x

the teacher generates multiple responses:

R_1,R_2,\ldots,R_k.

Then each response enters the filtering system.

Conceptually:

                         Prompt
                           |
             +-------------+-------------+
             |             |             |
             v             v             v
            R1            R2            R3
             |             |             |
          verify         verify        verify
             |             |             |
            pass          fail          pass
             |                           |
             +-------------+-------------+
                           |
                           v
                     keep clean traces

The source defines rejection sampling in essentially these terms: generate multiple candidate responses, verify correctness, and retain correct, well-formatted responses. (Source: Build a DeepSeek Model (From Scratch))

7. Why multiple responses instead of one?

Suppose the probability that a teacher-generated answer is accepted is:

p=0.4.

If we generate only one response:

P(\text{at least one accepted})=0.4.

If we generate two independent candidates:

P(\text{at least one accepted}) = 1-(1-p)^2
= 1-(0.6)^2 = 0.64.

With four:

1-(0.6)^4 = 1-0.1296 = \boxed{0.8704}.

So approximately:

\boxed{87.0\%}

chance of obtaining at least one acceptable response.

This is the intuition behind generating multiple candidates before filtering.

8. Verification depends on the domain

This is important because there is no universal verifier.

Mathematics

Final answer can often be checked:

\boxed{ \text{candidate answer}=\text{ground truth?} }

Programming

Execute the generated code:

\boxed{ \text{code}\rightarrow\text{tests}\rightarrow\text{pass/fail} }

Less mechanically verifiable tasks

The source describes using DeepSeek-V3 as a generative reward model for some STEM/logic-style cases where correctness is not reducible to a simple deterministic check. (Source: Build a DeepSeek Model (From Scratch))

So the verifier depends on the task.

9. Correctness filtering is not enough

Suppose a response is:

x=83

blah blah blah

混合 languages!!!!

[500 lines of irrelevant code]

Maybe the final answer is correct.

But the training sample is poor.

The student does not only learn:

\text{answer correctness}

It also learns:

\text{response style}

and:

\text{format}.

Therefore DeepSeek filters for readability and coherent formatting as well. (Source: Build a DeepSeek Model (From Scratch))

10. Why this creates a self-improvement loop

Here is a beautiful connection to the earlier RL chapters.

R1 becomes stronger through RL:

\boxed{ \text{RL} \rightarrow \text{better reasoning behavior} }

Then R1 generates training examples:

\boxed{ \text{R1} \rightarrow \text{high-quality reasoning traces} }

Then smaller models learn from those traces:

\boxed{ \text{traces} \rightarrow \text{students} }

So the overall pattern is:

\boxed{ \text{RL discovers/strengthens} \rightarrow \text{distillation distributes} }

The source explicitly makes this complementarity point. (Source: Build a DeepSeek Model (From Scratch))

11. Why start the student from a pretrained model?

The source's implementation does not start the student from random weights.

It loads a pretrained base model.

For the practical example, the chapter starts from pretrained Qwen3 and then performs distillation. (Source: Build a Reasoning Model (From Scratch))

Why?

Because the student already has:

\boxed{ \text{language knowledge} + \text{tokenization knowledge} + \text{general representations} }

and distillation can focus on adding:

\boxed{ \text{teacher's reasoning behavior} }.

So we're not teaching language from zero.

We are adapting an existing language model.

12. This is analogous to knowledge transfer into a pretrained network

Think of:

S_0 = \text{pretrained student}.

Then distillation produces:

S_1 = \text{distilled student}.

So:

\boxed{ S_0 \xrightarrow{\text{teacher-generated SFT}} S_1 }

The teacher isn't replacing the student's base model.

It is shaping its behavior.

13. Why Qwen and Llama?

The source reports six distilled models across two architecture families:

Qwen
1.5B,\ 7B,\ 14B,\ 32B
Llama
8B,\ 70B

(Source: Build a DeepSeek Model (From Scratch))

So DeepSeek did not create one student size.

It created a family of deployment choices.

14. Think of the student family as a compression ladder

\boxed{ 671B \rightarrow 70B \rightarrow 32B \rightarrow 14B \rightarrow 8B \rightarrow 7B \rightarrow 1.5B }

The teacher is huge.

Students are progressively cheaper.

This lets different deployment environments choose different trade-offs:

\text{performance} \leftrightarrow \text{memory} \leftrightarrow \text{compute}.

15. Parameter-compression numerical

Teacher:

671B.

Student:

1.5B.

Compression ratio:

\frac{671}{1.5}
= \boxed{447.3}.

So the student has about:

\boxed{447\times}

fewer parameters.

The chapter rounds this to approximately a 450× parameter-count compression. (Source: Build a DeepSeek Model (From Scratch))

16. Very important: fewer parameters does not mean zero capability

The 1.5B student is not expected to reproduce every aspect of the 671B teacher.

Instead:

\boxed{ \text{retain useful behavior at much lower cost} }

The source emphasizes that the transfer is powerful but not lossless. (Source: Build a DeepSeek Model (From Scratch))

Correction: GPT-4o ~1.8T parameters is an unsupported book estimate. Benchmark comparisons cannot establish parameter compression from that estimate.

The biggest lesson is not:

“Small models become equal to the teacher.”

\boxed{ \text{small models recover a surprisingly large fraction of teacher capability} }

while using vastly fewer parameters.

20. Relative performance retention

A useful numerical:

32. Why can distillation outperform RL on the smaller architecture?

Distillation instead says:

\text{large teacher already discovered strategy} \rightarrow \text{small model imitates it}.

\boxed{ \text{reward signal} \rightarrow \text{potentially new behavior} }

\boxed{ \text{Distillation mainly transfers} }

45. Why quality control matters even more for distillation

This is a subtle but important training principle.

The student may learn both.

Distillation therefore creates a powerful amplification mechanism:

\boxed{ \text{teacher mistakes can become student training data} }

unless filtering intervenes.

That is why rejection sampling is not merely a data-cleaning convenience.

It is part of the actual learning architecture.

56. The deepest conceptual lesson

There are really three different ways of obtaining reasoning behavior.

1. Human demonstrations
\text{human reasoning} \rightarrow \text{SFT}
2. RL discovery
\text{model exploration} \rightarrow \text{reward} \rightarrow \text{better reasoning}
3. Teacher transfer
\text{strong model reasoning} \rightarrow \text{synthetic traces} \rightarrow \text{SFT}

DeepSeek combines these ideas rather than treating them as mutually exclusive. (Source: Build a DeepSeek Model (From Scratch))

57. Final mathematical summary

For classical KD:

\boxed{ L_{\text{classical}} = \alpha CE + (1-\alpha)T^2KL }

For DeepSeek-R1 hard distillation:

\boxed{ L_{\text{R1-distill}} = -\frac1N \sum_t \log P_S(y_t|x,y_{<t}) }

For the system pipeline:

\boxed{ \text{Teacher generation} \rightarrow \text{verification} \rightarrow \text{filtering} \rightarrow \text{SFT} }

For the strategic role:

\boxed{ \text{RL strengthens/discovers} \quad\Rightarrow\quad \text{distillation transfers/compresses} }
