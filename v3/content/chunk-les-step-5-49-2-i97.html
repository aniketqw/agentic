Complete lesson review: derivation, checked numericals, answers and source boundaries

Read this review alongside the preserved lesson below. Corrections qualify inherited claims. Sources support named mechanisms; teaching fixtures are independent reconstructions. Earlier progress reports remain historical snapshots.

Motivation

Prevent one outlier from setting the quantization scale for every token/channel.

Prerequisites

  • Linear algebra and chain rule
  • Binary floating-point normal/subnormal encodings
  • Quantization scale convention
  • Tensor shape and loss normalization

Notation and units

  • X:[N, K], W:[K, O], Y=XW:[N, O] row convention
  • s_q: fmax/amax quantization multiplier; s_d:1/s_q reconstruction multiplier
  • Nc:128 reduction/group channels in cited design
  • G: dL/dY; dX=GW^T; dW=X^TG

Assumptions

  • All toy numerical inputs and normalization conventions are stated explicitly.
  • The teaching companion requires NumPy and runs on CPU; it claims no production backend execution.
  • Finite saturating E4M3FN RTNE is simulated; tensor arithmetic uses NumPy higher precision.

Step-by-step derivation

  1. One activation tile covers one token and 128 input channels; each token has its own tile scales. Weight tiles span 128 input channels by 128 output channels.
  2. For shapes [N,K] and [K,O], scale counts are N*ceil(K/128) and ceil(K/128)*ceil(O/128); include padding and partial tiles.
  3. For each reduction group g, compute code product C_g and restore its scale before summing: Y_ij=sum_g C_gij/(sX_ig*sW_gj). A single output scale is invalid when K-group scales differ.
  4. Scale overhead is (number of scales*bytes per scale)/(FP8 payload bytes). Smaller blocks reduce outlier interactions but add metadata and may reduce kernel efficiency.

↩ Back to main text: Step 3.5 — Quantization → QLoRA · Step 3.6B — GGUF, K-Quants, QAT, BitNet, and 1.58-bit LLMs

We now reach the second pillar of DeepSeek's FP8 framework.

The first pillar answered:

\boxed{\text{Which precision should be used where?}}

The second asks:

\boxed{\text{When we use FP8, how do we preserve enough information?}}

The answer is:

\boxed{\text{Fine-Grained Quantization}}

The central problem is the presence of outliers. The source develops this using the concrete vector:

\boxed{[2.0,\;3.0,\;500.0]}

and then moves from one scale for the entire tensor to separate scales for smaller groups/blocks. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.1 First recall ordinary tensor-wise quantization

From the previous step, our basic scaling mechanism was:

\alpha=\max_i|x_i|

then:

s=\frac{q_{\max}}{\alpha}

then:

q_i=\operatorname{round}(x_i s)

and approximately:

\hat{x}_i=\frac{q_i}{s}.

The important assumption is:

\boxed{\text{one scaling factor for the entire tensor}.}

That assumption becomes problematic for LLM activations and weights because their values can have a large dynamic range. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.2 The outlier problem

Take the source's example:

x=[2.0,\;3.0,\;500.0].

Suppose we want to map this to signed INT8:

[-127,127].

The maximum absolute value is:

\alpha=\boxed{500}.

Therefore:

s=\frac{127}{500} = \boxed{0.254}.

Now quantize.

For 2.0:

2(0.254)=0.508

so:

\boxed{q_1=1}.

For 3.0:

3(0.254)=0.762

so:

\boxed{q_2=1}.

For 500:

500(0.254)=127

so:

\boxed{q_3=127}.

Therefore:

\boxed{ [2,3,500] \rightarrow [1,1,127]. }

This is exactly the numerical example used by the source. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.3 What went wrong?

The original values contained:

2\neq3.

But after quantization:

\boxed{1=1}.

So the distinction between them disappeared.

This is what the source calls the squashing problem: the outlier 500 determines the global scale, forcing ordinary values into a tiny region of the quantized range. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.4 Dequantization makes the problem visible

Recall:

\hat{x}=\frac{q}{s}.

For q=1:

\hat{x} = \frac1{0.254} \approx \boxed{3.94}.

So:

2.0 \rightarrow 3.94.

For the other value 3.0, it also became 1, therefore:

3.0 \rightarrow 3.94.

And:

500 \rightarrow \frac{127}{0.254} = 500.

So:

\boxed{ [2.0,3.0,500] \rightarrow [3.94,3.94,500]. }

The source reports approximately 97% relative error for 2.0 and 31% for 3.0, while the outlier is recovered almost perfectly. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.5 Calculate those relative errors

For a value x reconstructed as \hat{x}:

\boxed{ \text{relative error} = \frac{|x-\hat{x}|}{|x|} \times100\%. }

For 2.0:

\frac{|2-3.94|}{2}\times100
= \frac{1.94}{2}\times100 = \boxed{97\%}.

For 3.0:

\frac{|3-3.94|}{3}\times100
= \frac{0.94}{3}\times100 \approx \boxed{31.3\%}.

This reproduces the source's result. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.6 The insight

The problem is not necessarily FP8 itself.

The immediate problem is:

\boxed{ \text{using one scale for values with very different magnitudes}. }

So ask:

Why should the value 500 be allowed to determine how we represent the values 2 and 3?

It shouldn't.

Therefore:

\boxed{ \text{break the tensor into smaller regions}. }

And:

\boxed{ \text{give each region its own scaling factor}. }

That is the basic idea of fine-grained quantization. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.7 From tensor-wise scaling to group-wise scaling

Ordinary quantization
Entire tensor
┌─────────────────────────────┐
│ 2   3   500   ...           │
└─────────────────────────────┘
             │
             ▼
       one scale factor
Fine-grained quantization
Tensor
┌──────────┬──────────┬──────────┐
│ Group 1  │ Group 2  │ Group 3  │
└──────────┴──────────┴──────────┘
     │          │          │
     ▼          ▼          ▼
    s₁         s₂         s₃

Now an outlier in Group 1 does not automatically determine the scale for Groups 2 and 3.

The source describes exactly this divide-and-conquer strategy. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.8 The simplest toy version

Suppose instead of:

[2,3,500]

being one group, we split it into:

[2,3]

and:

[500].

For the first group:

\alpha_1=3.

For the second:

\alpha_2=500.

Therefore:

s_1=\frac{127}{3}

while:

s_2=\frac{127}{500}.

Now the small numbers are not affected by the 500 outlier.

5.49.2.9 Quantizing the first group

For:

[2,3]

we have:

s_1=\frac{127}{3}\approx42.333.

Quantize 2:

2(42.333) \approx84.667

so:

\boxed{85}.

Quantize 3:

3(42.333) = 127.

so:

\boxed{127}.

Therefore:

\boxed{ [2,3]\rightarrow[85,127]. }

Compare this with the global-scale result:

[2,3]\rightarrow[1,1].

Huge improvement in preserving the distinction.

5.49.2.10 Dequantize

For 85:

\hat{x} = \frac{85}{127/3}.

Thus:

\hat{x} = 85\frac3{127} \approx \boxed{2.008}.

For 127:

\hat{x} = 3.

So:

\boxed{ [2,3]\rightarrow[2.008,3.0] }

approximately.

The first value now has only about:

\frac{|2-2.008|}{2}\times100 \approx \boxed{0.4\%}

relative error, rather than the catastrophic error from global scaling.

This is our illustrative derivation of the principle.

5.49.2.11 The actual DeepSeek idea

The source applies this principle separately to:

\boxed{\text{activations}}

and:

\boxed{\text{weights}}.

But the geometry differs.

For activations, we have a long vector.

For weights, we have a 2D matrix.

The source therefore uses:

\boxed{ \text{groups for activations} }

and:

\boxed{ \text{2D blocks/tiles for weights}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.2.12 Activations: start with a vector

Suppose an activation vector is:

x\in\mathbb R^{7168}.

The source uses DeepSeek-V3's 7168-dimensional activation example. (Source: Build a DeepSeek Model (From Scratch))

Instead of:

\boxed{ \text{one scale for all 7168 values} }

the vector is divided into groups.

The source specifies:

\boxed{ N_C=128 }

elements per activation group. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.13 How many activation groups?

Suppose:

d=7168.

and:

N_C=128.

Then:

\frac{7168}{128} = \boxed{56}.

So one activation vector has:

\boxed{56\text{ groups}}

under the source's stated grouping.

Each group gets its own scaling factor:

s_1,s_2,\ldots,s_{56}.

5.49.2.14 Why 128?

The source identifies 128 as the group size used in its described implementation.

The conceptual benefit is that 128 values share a scale rather than thousands of values sharing one scale.

Therefore:

\boxed{ \text{local dynamic range} }

is handled independently.

The number 128 is source-specific; the broader idea of smaller groups with independent scaling is the general mechanism. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.15 The source's activation example

Imagine:

Group 1

maximum magnitude:

20.
Group 2

maximum magnitude:

0.1.

With a single tensor-wise scale, the 20 can force the 0.1-scale values into an extremely narrow quantized region.

With fine-grained scaling:

\boxed{s_1\text{ is based on Group 1}}

and:

\boxed{s_2\text{ is based on Group 2}}.

The source explains that an outlier in one group therefore no longer affects the other groups. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.16 Numerical comparison

Suppose the target range is:

[-127,127].

For Group 1:

\alpha_1=20.

Then:

s_1=\frac{127}{20}=6.35.

For Group 2:

\alpha_2=0.1.

Then:

s_2=\frac{127}{0.1}=1270.

Notice the difference:

\boxed{ s_1=6.35 }

versus:

\boxed{ s_2=1270. }

That is exactly what we want.

The small-valued group gets a much larger scale, so its values occupy more of the available quantized range.

5.49.2.17 This is “local dynamic-range adaptation”

That phrase is useful conceptually.

Tensor-wise:

\boxed{ \text{one global dynamic range} }

Fine-grained:

\boxed{ \text{many local dynamic ranges}. }

Therefore:

\boxed{ \text{outlier influence becomes local instead of global}. }

That is the essence of the second pillar.

5.49.2.18 Now weights are different

A weight matrix has two dimensions:

W\in\mathbb R^{m\times n}.

You cannot naturally treat it as one long activation vector if you want to preserve its 2D structure.

The source therefore partitions it into:

\boxed{\text{2D tiles / blocks}}.

(Source: Build a DeepSeek Model (From Scratch))

5.49.2.19 Source's weight block size

The source states:

\boxed{ 128\times128 }

as the block size used for weights in its FP8 framework. (Source: Build a DeepSeek Model (From Scratch))

Therefore every weight block has:

128\times128 = \boxed{16,384}

weight values.

Each such block receives its own scaling factor.

5.49.2.20 Example weight matrix

Suppose:

W\in\mathbb R^{512\times512}.

Using:

128\times128

blocks:

\frac{512}{128}=4

blocks along each dimension.

Therefore:

4\times4 = \boxed{16}

weight blocks.

Each has its own scale:

s_{11},s_{12},\ldots,s_{44}.

So instead of:

\boxed{1\text{ scale}}

we have:

\boxed{16\text{ scales}}.

5.49.2.21 Why does this help?

Suppose:

W_{11}

contains an outlier of:

500.

But:

W_{12}

contains values only around:

0.1.

Tensor-wise scaling would let the 500 influence the entire matrix.

Block-wise scaling gives:

s_{11}

based on the range of W_{11}, while:

s_{12}

is based on W_{12}.

Therefore:

\boxed{ W_{11}\text{ outliers don't determine }W_{12}\text{'s precision}. }

That is exactly the source's explanation. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.22 Number of scales: an exam formula

For an activation vector of length d and group size N_C:

\boxed{ N_{\text{activation groups}} = \left\lceil\frac{d}{N_C}\right\rceil }

assuming padding or handling of a remainder where needed.

For dimensions divisible by N_C:

N=d/N_C.

For a weight matrix:

W\in\mathbb R^{M\times N}

with block:

B_r\times B_c,

the number of blocks is approximately:

\boxed{ \left\lceil\frac{M}{B_r}\right\rceil \left\lceil\frac{N}{B_c}\right\rceil. }

For DeepSeek's stated:

B_r=B_c=128.

5.49.2.23 Numerical: activation scale count

Suppose:

d=4096

and:

N_C=128.

Then:

4096/128 = \boxed{32}

groups.

Therefore:

\boxed{32\text{ activation scaling factors}}

for that vector.

5.49.2.24 Numerical: weight scale count

Suppose:

W\in\mathbb R^{4096\times4096}.

With:

128\times128

blocks:

4096/128=32.

Therefore:

32\times32 = \boxed{1024}

blocks.

Hence:

\boxed{1024\text{ weight scaling factors}}.

This is a very good exam numerical.

5.49.2.25 Does using many scales cost extra memory?

Yes.

Every group/block requires scale metadata.

But the scale count is dramatically smaller than the number of values.

For:

4096\times4096 = 16,777,216

weights, we need only:

1024

scales.

So there is:

\boxed{ 16,777,216\text{ data values} \quad\text{vs}\quad 1,024\text{ scales}. }

The source emphasizes the precision benefit of the local scaling; it does not give a detailed memory-overhead calculation for the scale metadata in the cited passage. The numerical comparison above is a derived consequence of the stated 128×128 block size.

5.49.2.26 Scale overhead example

Suppose each scale is stored in 2 bytes.

For:

1024

weight blocks:

1024\times2 = 2048

bytes.

Therefore:

\boxed{2\text{ KB}}

of scale metadata.

Compare this with the FP8 weights:

16,777,216\times1 = 16,777,216

bytes:

\boxed{16\text{ MB}}.

So:

\boxed{ \text{scale metadata}\ll\text{weight data}. }

This is an illustrative calculation, not a storage-format specification from the source.

The source's complete fine-grained diagram contains two independently scaled inputs:

Activation groups                Weight blocks
      │                                │
      │ separate scales               │ separate scales
      ▼                                ▼
   FP8 Input  ───────────────►  FP8 Weight
                    │
                    ▼
             Tensor Core GEMM
                    │
                    ▼
             low-precision result
                    │
                    ▼

                    │
                    ▼

(Source: Build a DeepSeek Model (From Scratch))

This is the key bridge to Pillar 3.

5.49.2.28 Why do we need both activation and weight scaling?

Because the matrix multiplication is:

Y=XW.

Both:

X

and:

W

can have different local dynamic ranges.

Therefore:

\boxed{ \text{one global scale for }X }

is not ideal.

And:

\boxed{ \text{one global scale for }W }

is not ideal.

DeepSeek therefore independently partitions/scales both.

The source explicitly distinguishes activation groups from weight blocks. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.29 How do the scales affect the matrix multiplication?

Suppose:

X\approx s_X Q_X

and:

W\approx s_W Q_W

under a conceptual dequantization convention.

Then:

XW \approx (s_XQ_X)(s_WQ_W).

Because the scales are scalar for the corresponding local group/block:

= s_Xs_W(Q_XQ_W).

So:

\boxed{ \text{low-precision GEMM} + \text{appropriate scale restoration} }

can approximately reconstruct the original magnitude.

The source's diagram explicitly says the CUDA-core stage multiplies the low-precision Tensor Core output using the corresponding activation and weight scaling factors to restore magnitude. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.30 Why are there two scaling factors?

Because two things were scaled:

\boxed{X}

and:

\boxed{W}.

So:

\boxed{ s_{\text{output}} \sim s_Xs_W. }

This is an important exam concept.

5.49.2.31 Numerical example of scale restoration

Suppose a local activation group has:

s_X=2

and a weight block has:

s_W=3.

Suppose the low-precision GEMM produces:

Q_XQ_W=10.

Then approximate restored output:

Y = s_Xs_W(10).

Therefore:

Y=2\times3\times10 = \boxed{60}.

This is a simplified scalar demonstration of the source's scale-restoration principle.

5.49.2.32 The “divide and conquer” interpretation

The source's strategy can be summarized as:

Global scaling
\boxed{ 1\text{ region} \rightarrow 1\text{ scale} }
Fine-grained scaling
\boxed{ N\text{ local regions} \rightarrow N\text{ local scales}. }

The goal is:

\boxed{ \text{each local region uses the numerical range it actually needs}. }

5.49.2.33 Why this synergizes with E4M3

This becomes important later.

FP8 E4M3 has:

\boxed{ 3\text{ mantissa bits} }

so it gives better precision than E5M2 but less dynamic range.

The source later argues that fine-grained scaling handles dynamic-range problems locally, allowing DeepSeek to use E4M3 more uniformly. (Source: Build a DeepSeek Model (From Scratch))

So the relationship is:

\boxed{ \text{fine-grained scaling} \rightarrow \text{local range control} \rightarrow \text{less pressure for a huge global dynamic range} }

which eventually supports:

\boxed{ \text{E4M3 emphasis}. }

We'll derive that fully under Pillar 4.

5.49.2.34 Another exam numerical

Suppose:

W\in\mathbb R^{2048\times4096}

and block size is:

128\times128.

Number of blocks vertically:

2048/128 = 16.

Horizontally:

4096/128 = 32.

Therefore:

16\times32 = \boxed{512}

weight blocks.

Thus:

\boxed{512\text{ independent weight scales}}.

5.49.2.35 Activation example

Suppose:

d=7168

and:

N_C=128.

We found:

7168/128=56.

Now suppose each group has maximum magnitudes:

[20,\;0.1,\;\ldots].

Group 1 uses a scale based on:

20.

Group 2 uses a scale based on:

0.1.

The exact scale formula under our previous symmetric INT8 illustration would be:

s_i=\frac{127}{\alpha_i}.

Thus:

s_1=\frac{127}{20}=6.35

and:

s_2=\frac{127}{0.1}=1270.

So Group 2 can use almost the entire representable quantization range for its tiny values rather than being squashed by Group 1's large values.

This is precisely the numerical intuition behind the source's activation example. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.36 A subtle wording clarification

The source's explanatory text says:

“Group 1 are scaled by 20” and “Group 2 are scaled by 0.1.”

In context, those numbers are the groups' maximum magnitudes used to determine their independent scales. Under the explicit scaling convention introduced earlier in the source, the actual scale multiplier would be derived from the target range, for example:

\frac{127}{20}

or:

\frac{127}{0.1}.

So do not memorize “scale = 20” literally as a universal scaling formula. The source's underlying principle is:

\boxed{ \text{each group gets a scale derived from its own local maximum}. }

This preserves the source's framing without confusing the local maximum \alpha with the scale factor s. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.37 Why fine-grained quantization is especially useful for LLMs

The source describes LLM values as having potentially enormous dynamic ranges.

With one global scale:

\boxed{ \text{one outlier} \rightarrow \text{whole tensor's scale changes}. }

With local scaling:

\boxed{ \text{one outlier} \rightarrow \text{mainly affects its own local region}. }

This is the fundamental reason fine-grained quantization improves numerical fidelity. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.38 Full fine-grained pipeline

Let's now assemble the source's Figure 5.29 conceptually.

Step 1 — Input activation
X

is divided into:

\boxed{ N_C\text{-element groups}. }
Step 2 — Activation scales

Each group gets:

\boxed{s_1,s_2,\ldots}
Step 3 — Weight matrix
W

is divided into:

\boxed{ 128\times128\text{ blocks}. }
Step 4 — Weight scales

Each block gets its own:

\boxed{s_{ij}}.
Step 5 — FP8 Tensor Core GEMM

Quantized values enter the fast matrix multiplication.

Step 6 — CUDA-core restoration/accumulation

The source describes dequantizing the low-precision intermediate using the corresponding scales and producing a higher-precision output. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.39 The central formula

For a local group/block, conceptually:

\boxed{ q_X=\operatorname{Quantize}(X;s_X) }
\boxed{ q_W=\operatorname{Quantize}(W;s_W) }

then:

\boxed{ q_Y=q_Xq_W }

and approximately:

\boxed{ Y\approx s_Xs_Wq_Y. }

The precise hardware implementation can organize scaling/accumulation more intricately, but this is the correct mathematical intuition for why both scales appear in reconstruction; it matches the source's Figure 5.29 explanation. (Source: Build a DeepSeek Model (From Scratch))

5.49.2.41 Exam numerical — quantization error comparison

Consider:

x=[2,3,500]

with INT8 target range.

Global scale
s=\frac{127}{500}=0.254.

32\times32=1024

scales.

16\times16=256

With one global tensor scale
1

\boxed{\text{fewer scales}}

Step 5.49.2 checkpoint

Know these formulas:

\boxed{ \alpha_g=\max_{i\in g}|x_i| }

for the maximum of a local group g, and conceptually:

\boxed{ s_g=\frac{q_{\max}}{\alpha_g} }

then:

\boxed{ q_i=\operatorname{round}(x_i s_g). }

For an activation vector:

\boxed{ N_{\text{groups}} = \left\lceil\frac{d}{128}\right\rceil }

for the source's stated group size.

For a weight matrix:

\boxed{ N_{\text{blocks}} = \left\lceil\frac{M}{128}\right\rceil \left\lceil\frac{N}{128}\right\rceil. }

And conceptually:

\boxed{ Y\approx s_Xs_W(Q_XQ_W). }

Most importantly:

\boxed{ \text{Tensor-wise scaling: outlier affects everyone} }

versus:

\boxed{ \text{Fine-grained scaling: outlier mainly affects its own group/block}. }

The source presents this as one of the key enablers of stable FP8 training at scale. (Source: Build a DeepSeek Model (From Scratch))
