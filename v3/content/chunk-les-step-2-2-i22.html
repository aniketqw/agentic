Motivation

Change sampling concentration without changing positive-temperature logit order.

Prerequisites

  • Softmax
  • Logit differences
  • Entropy

Notation and units

  • p_i(T)=exp(z_i/T)/sum exp(z_j/T)
  • T positive; T=0 is a separate greedy policy

Assumptions

  • Finite allowed logits
  • Uniform high-temperature limit is over allowed support
  • Equal maxima retain ties in the mathematical low-temperature limit

Step-by-step derivation

  1. Divide logits by T before normalization; odds p_i/p_j=exp((z_i-z_j)/T). Lower T enlarges log-odds magnitude.
  2. For [2,1,0], T=1 yields [.6652409558,.2447284711,.0900305732]; T=2 yields [.5064803911,.3071958857,.1863237232].
  3. For [4,2,0], scaled logits at T=.5,1,2 are [8,4,0], [4,2,0], [2,1,0].
  4. For finite logits, T→infinity makes exp differences approach one, giving uniform support. T→0+ concentrates on maximum logits, uniform across tied maxima rather than arbitrarily selecting one.
  5. Let beta=1/T. H=ln Z-beta*E[z]; dH/dT=Var_p(z)/T³ >=0. Thus entropy is nondecreasing with T for a fixed finite logit vector.
  6. Stable softmax subtracts the maximum scaled logit. A greedy T=0 branch is not an evaluation of z/0.
  7. If probabilities p at T=1 are given, temperature can equivalently use normalized p_i^(1/T). Applying softmax(p/T) is not that equivalence.

    Step 2.2 — Temperature Scaling

    Plan node: I2 · chat order #22

    We now know that the Transformer produces logits:

    z=[z_1,z_2,\ldots,z_V]

    and normally converts them to probabilities using:

    \boxed{ p_i=\frac{e^{z_i}}{\sum_j e^{z_j}} }

    Then a decoder chooses or samples a token.

    Now we introduce one of the most important controls in LLM generation:

    \boxed{\text{Temperature }T}

    Your decoding slides define temperature as reshaping confidence before sampling: divide the logits by T before softmax. They explicitly show that T<1 sharpens the distribution and T>1 flattens it, while the ranking of tokens stays unchanged. (Source: decoding-sampling-slides)

    2.2.1 Why Do We Need Temperature?

    Suppose the model gives:

    P= [0.90,0.05,0.03,0.02].

    The model is extremely confident.

    Sampling from this distribution will almost always choose the first token.

    Now suppose we want more variety.

    We could alter the model itself, but that is unnecessary.

    Instead, we can change the shape of its output distribution at decoding time.

    Temperature gives us that control.

    So:

    \boxed{ \text{Temperature does not retrain the model.} }

    It changes how sharply we interpret its logits during generation.

    2.2.2 The Temperature Formula

    Given logits:

    z_i,

    temperature modifies them as:

    \boxed{ z_i'=\frac{z_i}{T} }

    and then:

    \boxed{ q_i(T)= \frac{e^{z_i/T}} {\sum_j e^{z_j/T}} }

    This is the core equation given in the master cheatsheet and the decoding slides. (Source: MASTER_Mathematical_Cheatsheet_All_Lecture_PDFs_v2; decoding-sampling-slides)

    2.2.3 Where Exactly Does Temperature Go?

    This order is critical:

    \boxed{ \text{logits} \rightarrow \frac{\text{logits}}{T} \rightarrow \text{softmax} \rightarrow \text{probabilities} }

    Not:

    \text{softmax} \rightarrow \frac{\text{probabilities}}{T}.

    Temperature acts on the logits.

    Your production source describes the same sequence: logits are generated, temperature rescales the logits, and softmax then produces probabilities. (Source: Building LLMs for Production)

    2.2.4 First Understand T=1

    If:

    T=1,

    then:

    \frac{z_i}{1}=z_i.

    So:

    \boxed{ q_i(1)=softmax(z_i). }

    Temperature 1 means ordinary softmax.

    2.2.5 What Happens When T<1?

    Suppose:

    T=0.5.

    Then:

    z_i'=\frac{z_i}{0.5}=2z_i.

    So the differences between logits become larger.

    That makes the softmax more extreme.

    Hence:

    \boxed{ T<1\Rightarrow\text{sharper distribution}. }

    The top token receives more probability.

    Lower-probability tokens receive less.

    2.2.6 What Happens When T>1?

    Suppose:

    T=2.

    Then:

    z_i'=\frac{z_i}{2}.

    So the differences between logits become smaller.

    Softmax becomes less confident.

    Hence:

    \boxed{ T>1\Rightarrow\text{flatter distribution}. }

    More probability mass is spread over alternative tokens.

    This is exactly the behavior illustrated in your decoding slides. (Source: decoding-sampling-slides)

    2.2.7 The Easiest Way to Remember It

    Think of the logits as a set of hills.

    Low temperature

    Divide by a number smaller than 1:

    \frac{z}{T}\quad(T<1)

    makes the hills taller.

    Softmax becomes sharper.

    High temperature

    Divide by a number larger than 1:

    \frac{z}{T}\quad(T>1)

    makes the hills shorter.

    Softmax becomes flatter.

    So:

    \boxed{ T\downarrow\Rightarrow\text{confidence concentration}\uparrow }
    \boxed{ T\uparrow\Rightarrow\text{distribution spread}\uparrow }

    2.2.8 Important Numerical Example From Your Slides

    The slide uses the logits:

    \boxed{ z=[3.0,\;0.5,\;0.3,\;0.0,\;-0.5,\;-1.5] }

    and compares:

    T=0.5,\quad T=1.0,\quad T=2.0.

    The resulting distributions are given in the slide. (Source: decoding-sampling-slides)

    Let's derive them ourselves.

    2.2.9 Case 1 — T=1

    Since:

    z/T=z,

    we calculate:

    softmax([3,0.5,0.3,0,-0.5,-1.5]).

    The probabilities are approximately:

    \boxed{ [0.8062,\;0.0662,\;0.0542,\;0.0401,\;0.0243,\;0.0090] }

    This matches the slide. (Source: decoding-sampling-slides)

    So the top token gets:

    80.62\%.

    2.2.10 Case 2 — T=0.5

    Now divide every logit by:

    0.5.

    Therefore:

    z'= [6,\;1,\;0.6,\;0,\;-1,\;-3].

    Now apply softmax.

    The result is approximately:

    \boxed{ [0.9854,\;0.0066,\;0.0045,\;0.0024,\;0.0009,\;0.0001] }

    Again this matches your slide. (Source: decoding-sampling-slides)

    The top token jumped from:

    0.8062

    to:

    0.9854.

    So lowering temperature dramatically concentrated the distribution.

    2.2.11 Case 3 — T=2

    Now:

    z'= [1.5,\;0.25,\;0.15,\;0,\;-0.25,\;-0.75].

    Softmax gives:

    \boxed{ [0.4883,\;0.1399,\;0.1266,\;0.1089,\;0.0848,\;0.0515] }

    This also matches the slide. (Source: decoding-sampling-slides)

    Now the top token has only:

    48.83\%.

    The distribution is much flatter.

    2.2.12 Put the Three Cases Together

    Temperature Probability of top token
    T=0.5 0.9854
    T=1.0 0.8062
    T=2.0 0.4883

    So:

    \boxed{ T\downarrow\Rightarrow p_{\max}\uparrow }

    and:

    \boxed{ T\uparrow\Rightarrow p_{\max}\downarrow. }

    2.2.13 But Does Temperature Change the Ranking?

    No.

    This is one of the most important facts.

    Suppose:

    z_1>z_2>z_3.

    For any:

    T>0,

    dividing by T preserves the ordering:

    \frac{z_1}{T} > \frac{z_2}{T} > \frac{z_3}{T}.

    Softmax is monotonic with respect to ranking.

    Therefore:

    \boxed{ \arg\max_i z_i = \arg\max_i q_i(T) }

    for positive T.

    Your decoding slides explicitly state that temperature changes the sharpness of the distribution but never changes token ranking. (Source: decoding-sampling-slides)

    2.2.14 This Gives Us a Powerful Exam Shortcut

    Suppose:

    z=[5,2,1,-3].

    Ask:

    Which token remains the greedy choice for T=0.5,1,2,10?

    Answer:

    Always token 1.

    Because:

    5>2>1>-3.

    Temperature changes the probabilities, but not the order.

    Therefore:

    \boxed{ \text{temperature alone cannot change the argmax token}. }

    2.2.15 Numerical Exam Question

    Given:

    z=[4,2,1].

    At:

    T=0.5,

    the scaled logits are:

    [8,4,2].

    At:

    T=2,

    they are:

    [2,1,0.5].

    In both cases the largest value is still the first component.

    Thus the greedy token remains:

    \boxed{1}.

    2.2.16 Then Why Does Temperature Affect Generation?

    Because most interesting generation is not purely greedy.

    Temperature is primarily useful before sampling.

    Suppose:

    q(T)= [0.5,0.3,0.2].

    Sampling means:

    y\sim q(T).

    Therefore the second and third tokens still have chances to be selected.

    At a lower T:

    q(T)\approx[0.8,0.15,0.05],

    so the top token dominates.

    At a higher T:

    q(T)\approx[0.4,0.35,0.25],

    so alternatives get more chance.

    Thus:

    \boxed{ \text{temperature controls randomness/diversity through the distribution shape}. }

    2.2.17 Temperature Does Not Randomly Change the Ranking

    This distinction matters.

    Temperature does not say:

    "Sometimes token 4 becomes more likely than token 1."

    Instead:

    \boxed{ \text{temperature changes how far apart the probabilities are}. }

    Sampling is what introduces the actual randomness.

    So:

    \boxed{ \text{Temperature = distribution reshaping} }
    \boxed{ \text{Sampling = stochastic token selection} }

    2.2.18 Temperature T\rightarrow0

    This is conceptually important.

    As:

    T\rightarrow0^+,

    the highest logit dominates more and more.

    Suppose:

    z_1>z_2,\ldots,z_V.

    Then:

    \frac{z_1}{T}

    becomes much larger relative to the others.

    Thus:

    q_1(T)\rightarrow1

    and:

    q_i(T)\rightarrow0,\quad i\neq1.

    So:

    \boxed{ T\to0^+ \Rightarrow \text{distribution approaches one-hot at the argmax}. }

    The reasoning-model source uses temperature 0.0 operationally as greedy decoding rather than literally performing division by zero. Its generation code explicitly branches:

    if temperature is None or temperature == 0.0:
    next_token = torch.argmax(...)

    and only divides by temperature for positive nonzero values. (Source: Build a Reasoning Model (From Scratch))

    This is an important implementation detail.

    2.2.19 Never Literally Divide by Zero

    The mathematical expression:

    z/T

    is undefined at:

    T=0.

    So in implementations:

    \boxed{ T=0 \rightarrow \text{greedy/argmax branch} }

    rather than:

    z/0.

    Your reasoning-model source explicitly implements this behavior. (Source: Build a Reasoning Model (From Scratch))

    2.2.20 Temperature T\rightarrow\infty

    Now the opposite extreme.

    As:

    T\rightarrow\infty,

    we have:

    \frac{z_i}{T}\rightarrow0

    for every token.

    So:

    e^{z_i/T}\rightarrow e^0=1.

    Therefore:

    q_i(T) \rightarrow \frac1V.

    Thus:

    \boxed{ T\to\infty \Rightarrow \text{uniform distribution}. }

    Every token becomes approximately equally likely.

    This is the mathematical extreme of "maximum randomness" under this transformation.

    2.2.21 Exam Numerical — Extreme Temperature

    Suppose vocabulary has:

    V=4

    and logits:

    [10,2,-3,0].

    As:

    T\to\infty,

    the distribution approaches:

    \boxed{ [0.25,0.25,0.25,0.25]. }

    As:

    T\to0^+,

    the distribution approaches:

    \boxed{ [1,0,0,0]. }

    This is an excellent conceptual numerical.

    2.2.22 Temperature and Entropy

    Now we connect temperature to a quantity we studied in the mathematical foundations:

    \boxed{\text{Entropy}}

    For a distribution:

    p,

    entropy is:

    \boxed{ H(p) = -\sum_i p_i\ln p_i. }

    Higher entropy means the probability mass is more spread out.

    Lower entropy means it is more concentrated.

    Your temperature example gives us a direct demonstration.

    2.2.23 Entropy for T=0.5

    For:

    p= [0.9854,0.0066,0.0045,\ldots],

    the entropy is approximately:

    \boxed{ H\approx0.0939\text{ nats}. }

    Very low.

    The model is highly concentrated.

    2.2.24 Entropy for T=1

    For:

    p= [0.8062,0.0662,0.0542,\ldots],

    we get:

    \boxed{ H\approx0.7731\text{ nats}. }

    Higher.

    2.2.25 Entropy for T=2

    For:

    p= [0.4883,0.1399,0.1266,\ldots],

    we get:

    \boxed{ H\approx1.4903\text{ nats}. }

    Much higher.

    So:

    \boxed{ T\uparrow \Rightarrow H(p)\uparrow }

    for this example.

    2.2.26 Maximum Entropy

    For a vocabulary of:

    V

    tokens, the uniform distribution:

    p_i=\frac1V

    has entropy:

    \boxed{ H_{\max}=\ln V. }

    Our example has:

    V=6.

    Therefore:

    H_{\max}=\ln6\approx1.7918.

    Our values:

    T=0.5\rightarrow0.0939
    T=1\rightarrow0.7731
    T=2\rightarrow1.4903.

    And:

    1.4903<1.7918.

    So the T=2 distribution is flatter, but it is not yet uniform.

    2.2.27 Why Does Dividing by T Do This?

    Let's take two logits:

    z_1=3

    and:

    z_2=1.

    Difference:

    \Delta=3-1=2.
    At T=0.5
    \Delta'=\frac{2}{0.5}=4.

    The gap doubles.

    At T=2
    \Delta'=\frac22=1.

    The gap halves.

    Thus temperature is simply rescaling the relative differences in logits.

    That's why softmax becomes sharper or flatter.

    2.2.28 Two-Token Case Gives an Especially Clear Formula

    Suppose we have two logits:

    z_1,z_2.

    The probability of token 1 is:

    q_1 = \frac{e^{z_1/T}} {e^{z_1/T}+e^{z_2/T}}.

    Divide numerator and denominator by e^{z_2/T}:

    q_1 = \frac{ e^{(z_1-z_2)/T} }{ 1+e^{(z_1-z_2)/T} }.

    So:

    \boxed{ q_1 = \sigma\left(\frac{z_1-z_2}{T}\right) }

    where \sigma is the logistic sigmoid.

    This reveals something profound:

    \boxed{ \text{Temperature acts on the relative logit gap}. }

    2.2.29 Numerical Two-Token Example

    Take:

    z_1=2,\quad z_2=1.

    Difference:

    1.
    T=1
    q_1 = \frac{e^1}{1+e^1}
    \approx0.7311.

    So:

    q=[0.7311,0.2689].
    T=0.5

    Difference becomes:

    \frac1{0.5}=2.

    So:

    q_1= \frac{e^2}{1+e^2} \approx0.8808.

    Thus:

    q=[0.8808,0.1192].
    T=2

    Difference becomes:

    \frac12=0.5.

    So:

    q_1= \frac{e^{0.5}}{1+e^{0.5}} \approx0.6225.

    Thus:

    q=[0.6225,0.3775].

    This is temperature in its simplest mathematical form.

    2.2.30 Why Softmax Ordering Is Preserved

    For:

    T>0,

    if:

    z_i>z_j,

    then:

    \frac{z_i}{T}>\frac{z_j}{T}.

    Exponentiation is increasing:

    e^{z_i/T}>e^{z_j/T}.

    And dividing by the common positive denominator preserves the ordering.

    Therefore:

    \boxed{ z_i>z_j \Rightarrow q_i(T)>q_j(T). }

    So temperature changes confidence, not ranking.

    2.2.31 Temperature and Greedy Decoding

    This leads to an important practical conclusion.

    If we use:

    \arg\max

    after temperature scaling, the selected token is unchanged for positive T.

    Therefore:

    \boxed{ \text{Greedy + temperature} \approx \text{same argmax token} }

    provided no other filtering changes the candidate set.

    Temperature is mainly useful when we sample.

    2.2.32 Temperature + Sampling

    The reasoning-model source gives the generation procedure:

    1. get logits,
    2. apply temperature,
    3. softmax,
    4. sample using the resulting probabilities.

    Its code uses:

    logits = scale_logits_by_temperature(out, temperature)
probas = torch.softmax(logits, dim=-1)
next_token = torch.multinomial(probas.cpu(), num_samples=1)

    (Source: Build a Reasoning Model (From Scratch))

    Mathematically:

    \boxed{ y_t \sim q_\theta(\cdot\mid y_{<t},x;T) }

    where:

    q_i(T) = \frac{e^{z_i/T}} {\sum_j e^{z_j/T}}.

    2.2.33 Numerical Sampling Probability

    Suppose after temperature:

    P=[0.6,0.3,0.1].

    Over many independent sampling trials under the same distribution, approximately:

    • 60% choose token 1
    • 30% choose token 2
    • 10% choose token 3.

    This does not mean each batch of 10 trials will necessarily contain exactly:

    6,3,1.

    Sampling is random.

    The probabilities define the long-run frequencies.

    2.2.34 A Critical Distinction: Temperature vs Top-k

    They do different things.

    Temperature

    Changes the probabilities of all candidates:

    z_i\rightarrow z_i/T.
    Top-k

    Changes the candidate set by removing all but the top k.

    Therefore:

    \boxed{ \text{Temperature = reshape} }
    \boxed{ \text{Top-k = filter} }

    They can also be combined.

    2.2.35 Numerical Combined Example

    Suppose logits are:

    z=[4,3,1,0,-2].

    First use:

    T=2.

    Then:

    z/T=[2,1,0.5,0,-1].

    Suppose we also use:

    k=3.

    Keep the top three original logits:

    4,3,1.

    Set:

    0,-2\rightarrow-\infty.

    Thus after temperature and filtering:

    [2,1,0.5,-\infty,-\infty].

    Softmax gives a probability distribution over only the top 3 tokens.

    This is the combined strategy we will formalize later.

    2.2.36 Order of Operations Matters

    For a combined temperature + top-k decoder, a common procedure is:

    \boxed{ z \rightarrow \text{top-k filtering} \rightarrow z/T \rightarrow softmax \rightarrow sample }

    Raschka's implementation filters logits using top-k first, then applies temperature, then softmax and samples. (Source: Build a Large Language Model (From Scratch))

    For this operation, top-k membership is unchanged by positive temperature anyway because temperature preserves ranking.

    So selecting the top k before or after positive temperature gives the same retained set.

    But you should still follow the source's specified order when reproducing its implementation.

    2.2.37 Why Does Temperature Not Solve Repetition By Itself?

    Suppose the model repeatedly gives:

    P(\text{same token})=0.95.

    A higher temperature can spread the distribution somewhat.

    But temperature does not explicitly know:

    "This token has already been repeated too often."

    So temperature is a general confidence/diversity control, not a dedicated repetition-control mechanism.

    Your decoding source notes that sampling can improve diversity and that maximization-based methods can exhibit repetition issues; the slide deck separately covers repetition penalties among other decoding controls. (Source: decoding-sampling-slides)

    We'll treat repetition penalties separately rather than mixing them into temperature.

    2.2.38 Practical Temperature Ranges — Source Framing

    Your reasoning-model source gives the following practical guidance:

    • T=0: greedy
    • approximately 0.3–0.8: modest diversity
    • much higher temperatures: broader exploration, potentially lower reliability

    This is source guidance, not a universal law. The right setting depends on the task and model. (Source: Build a Reasoning Model (From Scratch))

    Your decoding slides similarly emphasize that the choice depends on whether the task values one strong answer or diverse alternatives. (Source: decoding-sampling-slides)

    2.2.41 Exam Numerical — Compute Softmax After Temperature

    Given:

    z=[2,1,0]

    and:

    T=2.

    First:

    z'=[1,0.5,0].

    Thus:

    \boxed{ P\approx[0.5065,0.3072,0.1863]. }

    T\uparrow \Rightarrow \text{distribution flattens} \Rightarrow \text{entropy generally increases}.

    2.2.45 A Very Important Mathematical Property: Translation Invariance

    Softmax satisfies:

    softmax(z)=softmax(z+c)

    for the same constant c added to every logit.

    With temperature:

    softmax(z/T) = softmax((z-c)/T)

    up to the equivalent common-shift transformation.

    This is why implementations can safely subtract:

    \max(z)

    before exponentiating for numerical stability.

    For example:

    z=[100,99,98]

    can be shifted to:

    [2,1,0]

    before softmax without changing the resulting probabilities.

    This is useful in numerical implementation.

    2.2.46 Numerical Stability With Temperature

    Suppose:

    z=[1000,999,998]

    and:

    T=0.5.

    Then:

    z/T=[2000,1998,1996].

    Directly computing:

    e^{2000}

    will overflow in ordinary floating-point arithmetic.

    Instead subtract the maximum:

    [2000,1998,1996]-2000

    giving:

    [0,-2,-4].

    Then:

    softmax([0,-2,-4])

    is numerically safe and mathematically equivalent.

    This is a practical numerical detail that often appears in implementation questions.

    Temperature sampling is conceptually:

    logits = model(context)

scaled_logits = logits / temperature

probs = softmax(scaled_logits)

next_token = sample(probs)

    The reasoning-model source implements this exact logical flow. (Source: Build a Reasoning Model (From Scratch))

    For:

    T=0,

    the implementation takes:

    next_token = torch.argmax(logits)

    instead of dividing by zero. (Source: Build a Reasoning Model (From Scratch))

    2.2.48 Temperature in One Mathematical Picture

    Suppose:

    z_1>z_2>z_3.

    Then:

    Low T
    \frac{z_1-z_2}{T}

    is large.

    Therefore:

    p_1\gg p_2\gg p_3.
    T=1

    Normal confidence.

    High T
    \frac{z_1-z_2}{T}

    is smaller.

    Therefore:

    p_1,p_2,p_3

    become more similar.

    So:

    \boxed{ T\text{ is essentially a scale parameter for logit differences}. }

    2.2.49 Connection to Everything We Learned Earlier

    This topic is directly connected to our earlier softmax discussion.

    We learned:

    softmax(z)

    turns logits into probabilities.

    Now we modify it:

    \boxed{ softmax(z/T). }

    We learned that logits are produced after:

    H\rightarrow W_U\rightarrow Z.

    Now:

    Z \rightarrow Z/T \rightarrow softmax.

    We learned greedy decoding:

    \arg\max z.

    Now we know:

    T>0

    does not change that ranking.

    And we learned sampling:

    y_t\sim p.

    Now temperature gives us:

    \boxed{ y_t\sim softmax(z/T). }

    Everything fits together.

    2.2.50 Temperature vs Sampling — Final Distinction

    This is worth making completely explicit.

    Suppose:

    z=[3,2,1].

    Temperature produces a new probability distribution.

    It does not pick the token.

    Then sampling uses the distribution.

    So:

    \boxed{ z \overset{/T}{\longrightarrow} z' \overset{softmax}{\longrightarrow} p \overset{sample}{\longrightarrow} y_t. }

    Whereas greedy does:

    \boxed{ z\overset{\arg\max}{\longrightarrow}y_t. }

    That is the clean distinction.
