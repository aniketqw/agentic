Step-by-step derivation

  1. Exact forward KL is sum_a p(a)log[p(a)/q(a)] with p=current and q=reference, measured in nats. Reverse KL exchanges the weighting distribution and is generally different.
  2. A signed individual log ratio can be negative; nonnegativity belongs to the distribution-weighted expectation, not each sampled log-ratio.
  3. With delta=log q(a)-log p(a), k3=exp(delta)-delta-1 is nonnegative because exp(delta)>=1+delta.
  4. Under a~p its expectation is KL(p||q), provided the complete probability support is compatible. Under a~old it is a different expectation unless importance correction is included.
  5. Old-policy samples with detached sampling probabilities cannot be naively treated as fresh current-policy samples during repeated updates. Numerical unbiasedness of the value estimator also does not by itself prove an unbiased gradient estimator.
  6. Add positive beta times the KL penalty to a minimized loss; subtract it from a maximized reward objective. Record whether penalty is token mean, response sum, or global token mean.

Step 5.6 — KL Regularization: Why Do We Need a Reference Model?

Plan node: I6 · chat order #47

We have now built:

\text{reward} \rightarrow \text{advantage} \rightarrow \text{policy ratio} \rightarrow \text{clipping}.

But the GRPO pipeline still has another component:

\boxed{\text{KL regularization}}

The source introduces this as the mechanism that prevents the trained policy from drifting too far from a reference policy. (Source: Build a Reasoning Model (From Scratch))

The key distinction is:

\boxed{\text{clipping controls individual update size}}

while:

\boxed{\text{KL controls longer-term policy drift}}

(Source: Build a Reasoning Model (From Scratch))

1. Start with the problem

Suppose RL is rewarding mathematical correctness.

The model discovers:

“Great. I can get reward 1 by exploiting the verifier.”

It might begin producing:

correct answer
+
weird formatting
+
unnecessary repetition
+
strange token patterns
+
very long outputs

The reward may still be high.

So maximizing reward alone can cause the model to move too far from the original model's general behavior.

The source describes this concern explicitly: reward optimization can lead to undesirable drift, while a reference-policy constraint helps preserve the original behavior. (Source: rl-grpo-slides)

2. What is the reference policy?

We introduce:

\boxed{\pi_{\mathrm{ref}}}

This is a frozen reference model.

The source describes it as typically being the original model at the beginning of training, kept fixed or refreshed relatively rarely. In the DeepSeek-R1 discussion, the reference model is refreshed every 400 steps in the source's description. (Source: Build a Reasoning Model (From Scratch))

So now there are conceptually three model states:

1. Old / rollout policy
   → generated the current samples

2. Current policy
   → being trained

3. Reference policy
   → provides a longer-term anchor

Do not confuse them.

3. Old policy vs reference policy

This is one of the most important distinctions.

Old policy

Used for:

\boxed{\text{policy ratio}}

and answers:

How different is the current policy from the policy that generated this rollout?

Reference policy

Used for:

\boxed{\text{KL regularization}}

and answers:

How far has the current policy drifted from the chosen reference model?

So:

\boxed{ \text{old policy} \neq \text{reference policy} }

even though a particular implementation may temporarily use the same model snapshot for both purposes.

The source discusses these roles separately.

4. Why clipping is not enough

Suppose every training step changes the policy only a little.

For example:

1\rightarrow1.1\rightarrow1.2\rightarrow1.3\rightarrow\cdots

Each individual step may be acceptable.

But after hundreds of updates, the model can still move substantially away from the starting distribution.

This gives:

\boxed{ \text{small step changes} \not\Rightarrow \text{small total drift} }

That is why the reference-policy KL term complements clipping.

The source explicitly describes clipping as limiting changes between steps and KL as controlling change over the longer training trajectory. (Source: Build a Reasoning Model (From Scratch))

5. What does KL mean conceptually?

KL divergence measures how different one probability distribution is from another.

Conceptually:

\boxed{ D_{KL}(\pi_\theta\|\pi_{\mathrm{ref}}) }

asks:

How different is the current model's distribution from the reference distribution?

A larger KL means:

\boxed{\text{more divergence}}

A smaller KL means:

\boxed{\text{more similar}}

The source uses KL precisely as a regularizer to discourage drastic changes. (Source: Build a Reasoning Model (From Scratch))

6. Classical KL formula

For two discrete distributions P and Q:

\boxed{ D_{KL}(P\|Q) = \sum_x P(x) \log \frac{P(x)}{Q(x)} }

For an LLM, x could represent tokens or complete token distributions.

At the full token-distribution level:

D_{KL} = \sum_v P_\theta(v\mid s) \log \frac{P_\theta(v\mid s)} {P_{\mathrm{ref}}(v\mid s)}.

However, there is an important source-specific detail.

Correction: The mean logp_new-logp_ref over fixed old-policy rollouts is a signed surrogate, not automatically the forward KL. K3 expectation equals forward KL only under its stated current-policy sampling measure, with importance handling needed under old-policy sampling.

Complete grounded review

7. Important: the source uses a simplified sampled KL term

The book's implementation does not explicitly compute the full vocabulary-wide distributional KL above.

Instead, it computes a sampled log-probability difference:

\boxed{ \text{KL loss} = \text{kl\_coeff} \times \operatorname{mean} ( \log p_{\text{new}} - \log p_{\text{ref}} ) }

This is the exact form shown in the source's implementation. (Source: Build a Reasoning Model (From Scratch))

So, for this course, keep the distinction clear:

\boxed{ \text{the source's KL term is a KL-like sampled regularization term} }

rather than silently treating it as the full exact distributional KL computation.

That distinction matters because the sampled log-probability difference can itself be negative.

8. Why compare log probabilities?

Suppose the current policy assigns:

p_{\text{new}}=0.2

to a sampled token, while the reference assigns:

p_{\text{ref}}=0.1.

Then:

\log p_{\text{new}} = \log 0.2

and:

\log p_{\text{ref}} = \log 0.1.

Their difference is:

\log 0.2-\log0.1 = \log2.

Therefore:

\boxed{0.6931}

approximately.

The current policy is assigning substantially more probability to that sampled token than the reference policy.

9. If the current model becomes less likely

Suppose:

p_{\text{new}}=0.05

and:

p_{\text{ref}}=0.1.

Then:

\log0.05-\log0.1 = \log0.5 \approx \boxed{-0.6931}.

So the sampled log-probability difference can be negative.

Again, this is why the exact source implementation should not be confused with the mathematical definition of nonnegative full KL divergence.

10. Why does a reference model act like an anchor?

Imagine:

Original model
      │
      │  ← reference anchor
      │
      ├───────────────┐
      ↓               ↓
  RL update 1      RL update 2
      ↓               ↓
 current model     current model

Without an anchor:

\text{maximize reward}

could continually push the model toward increasingly specialized strategies.

With a KL regularizer:

\boxed{ \text{maximize reward} + \text{stay reasonably close to reference} }

The model therefore faces a tradeoff.

11. The total loss

We previously had:

L_{\text{PG}}

or, with clipping:

L_{\text{clip}}.

Now add:

L_{\text{KL}}.

The source uses:

\boxed{ L_{\text{total}} = L_{\text{PG}} + L_{\text{KL}} }

in its simplified KL extension. (Source: Build a Reasoning Model (From Scratch))

12. The KL coefficient

The source introduces:

\boxed{\text{kl\_coeff}}

which controls how strongly the reference constraint affects training. (Source: Build a Reasoning Model (From Scratch))

Conceptually:

L_{\text{KL}} = \beta \times \text{KL-like divergence}

where:

\beta=\text{kl\_coeff}.

Therefore:

Small \beta

Weak constraint:

\boxed{\text{reward dominates}}
Large \beta

Strong constraint:

\boxed{\text{stay closer to reference}}

The source states that larger kl_coeff values impose a stronger restriction on how far the policy can move. It gives a practical range around 0.001 to 0.05 for its implementation. (Source: Build a Reasoning Model (From Scratch))

13. The source's implementation

The relevant structure is:

if kl_coeff:
    kl_loss = kl_coeff * torch.mean(logps - ref_logps)
else:
    kl_loss = torch.tensor(0.0)

loss = pg_loss + kl_loss

(Source: Build a Reasoning Model (From Scratch))

Let's decode it.

logps

Current policy sequence log probabilities:

\log p_{\text{new}}.
ref_logps

Reference policy sequence log probabilities:

\log p_{\text{ref}}.
Difference
\log p_{\text{new}}-\log p_{\text{ref}}.
Mean

Average across rollouts.

Multiply by coefficient

Apply the regularization strength.

Add to policy loss
L=L_{\text{PG}}+L_{\text{KL}}.

14. The source's exact worked example

The source has:

Policy-gradient loss
\boxed{-2.5764}
KL loss term
\boxed{-0.0075}

Therefore:

L_{\text{total}} = -2.5764+(-0.0075)

giving:

\boxed{ -2.5839 }

(Source: Build a Reasoning Model (From Scratch); rl-grpo-slides)

15. Why does the KL term become negative here?

This can look strange.

You may have learned:

D_{KL}(P\|Q)\ge0.

That is true for the full KL divergence.

But the source's implementation computes:

\operatorname{mean} ( \log p_{\text{new}} - \log p_{\text{ref}} )

on sampled outputs.

That quantity is not guaranteed to be nonnegative.

So the source can legitimately show:

\boxed{-0.0075}.

This is a crucial technical detail.

16. Do not make this mistake in an exam

Do not write:

“KL divergence can be negative.”

That would be wrong for mathematical KL divergence.

Instead say:

The full KL divergence is nonnegative; the source's sampled log-probability difference used as its simplified KL regularization term need not be nonnegative.

That is the source-faithful explanation.

17. Numerical KL example

Suppose we have four sampled responses.

Current logprobs:

[-2.0,-3.0,-4.0,-5.0]

Reference logprobs:

[-2.1,-2.9,-4.2,-5.1].

Differences:

[0.1,-0.1,0.2,0.1].

Mean:

\frac{0.1-0.1+0.2+0.1}{4} = \frac{0.3}{4} = \boxed{0.075}.

Suppose:

\beta=0.02.

Then:

L_{\text{KL}} = 0.02(0.075) = \boxed{0.0015}.

Therefore, if:

L_{\text{PG}}=-2.4,

then:

L_{\text{total}} = -2.4+0.0015 = \boxed{-2.3985}.

18. What is KL actually trying to prevent?

Suppose:

L_{\text{PG}}

strongly rewards a strange output.

The policy may want to assign much greater probability to that output.

KL says:

\boxed{ \text{“Before doing that, check how different you are becoming from the reference.”} }

So the combined objective balances:

\boxed{\text{task improvement}}

against:

\boxed{\text{distributional stability}}.

19. Clipping vs KL

This distinction is extremely important.

Clipping

Compares:

\pi_{\text{current}}

with:

\pi_{\text{old}}.

Its goal is:

\boxed{\text{prevent an overly large policy update}}

for the current optimization step.

KL

Compares:

\pi_{\text{current}}

with:

\pi_{\text{reference}}.

Its goal is:

\boxed{\text{prevent excessive drift from the reference behavior}}

The source explicitly describes these as complementary mechanisms. (Source: Build a Reasoning Model (From Scratch); rl-grpo-slides)

20. Visualize them together

                  CURRENT POLICY
                        │
            ┌───────────┴───────────┐
            │                       │
            ↓                       ↓
        OLD POLICY             REFERENCE POLICY
            │                       │

                        ↓

This is the cleanest mental model.

21. Why keep the reference model frozen?

Suppose the reference model were updated every optimizer step.

Then:

\pi_{\text{ref}} \approx \pi_{\text{current}}.

The KL difference could remain artificially small.

That would weaken its role as a long-term anchor.

So the source uses the original model for the KL reference and says it is kept fixed or refreshed relatively rarely. (Source: Build a Reasoning Model (From Scratch))

22. Resource cost of KL

There is a cost.

You need an additional reference copy.

The source explicitly notes that adding KL increases resource use because you now need an additional copy of the original model. (Source: Build a Reasoning Model (From Scratch))

So:

\boxed{ \text{KL stability} \leftrightarrow \text{extra memory/computation} }

23. Full GRPO structure so far

Now our simplified complete pipeline is:

q \rightarrow \{o_1,\ldots,o_G\}

then:

\{o_i\} \rightarrow \{R_i\}

then:

R_i \rightarrow A_i

then:

o_i \rightarrow \log p_{\text{new},i}

then:

\log p_{\text{old},i} \rightarrow r_i

then:

r_i \rightarrow \operatorname{clip}(r_i)

then:

A_i,\;r_i \rightarrow L_{\text{clip}}

and finally:

\log p_{\text{new}}, \log p_{\text{ref}} \rightarrow L_{\text{KL}}

and:

\boxed{ L_{\text{total}} = L_{\text{clip}} + L_{\text{KL}} }

24. One important source nuance

There are two levels of GRPO formulation appearing in the source materials.

The Chapter 6 implementation begins with:

-\operatorname{mean}(A\log p)

and Chapter 7 progressively adds clipping and KL.

The DeepSeekMath slide material presents a more complete token-level GRPO objective directly.

Meanwhile, the source's DeepSeek-R1 discussion notes a sequence-level simplification for the ratio.

Therefore, when studying papers, do not assume every GRPO paper uses precisely the same granularity.

The source explicitly contrasts:

\boxed{\text{DeepSeekMath: token-level ratio}}

with:

\boxed{\text{DeepSeek-R1: sequence-level ratio}}

and also notes later variants such as DAPO and GSPO. (Source: rl-grpo-slides)

We will handle those differences separately rather than mixing them together.

29. Level 5 — identify the correct component

Suppose a training system observes:

The model changes moderately every step, but after thousands of updates its behavior has drifted dramatically from the starting model.

Which mechanism specifically addresses this problem?

\boxed{\text{KL regularization}}

because its role is to constrain divergence from the reference policy over the training trajectory.

Clipping primarily addresses the size of individual updates. (Source: Build a Reasoning Model (From Scratch))

30. Complete mathematical picture

We can now write:

Group advantage
\boxed{ A_i= \frac{R_i-\mu_R} {\sigma_R+\epsilon} }
Policy ratio
\boxed{ r_i= \frac{\pi_\theta(o_i|q)} {\pi_{\mathrm{old}}(o_i|q)} }
Clipped ratio
\boxed{ \tilde r_i = \operatorname{clip}(r_i,1-\epsilon,1+\epsilon) }
Clipped objective
\boxed{ L_{\mathrm{clip}} = -\mathbb E \left[ \min(r_iA_i,\tilde r_iA_i) \right] }
Source's KL regularization implementation
\boxed{ L_{\mathrm{KL}} = \beta\, \operatorname{mean} \left( \log p_{\mathrm{new}} - \log p_{\mathrm{ref}} \right) }
Total loss
\boxed{ L_{\mathrm{total}} = L_{\mathrm{clip}} + L_{\mathrm{KL}} }

The last two equations reflect the source's simplified implementation. (Source: Build a Reasoning Model (From Scratch))

31. The deepest intuition

Everything we've built has a very specific job:

\boxed{ \text{Reward} }

asks:

Did the answer work?

\boxed{ \text{Advantage} }

asks:

Was this answer better than the other answers?

\boxed{ \text{Policy ratio} }

asks:

How much did the current model change its probability for this behavior?

\boxed{ \text{Clipping} }

says:

Don't change too much in one step.

\boxed{ \text{KL} }

says:

Don't drift too far from the reference behavior over time.

That gives us the complete control system.

32. One final analogy

Think of training a chef.

Reward
\text{“Customers liked this dish.”}
Advantage
\text{“This version was better than the chef's other attempts.”}
Policy ratio
\text{“How much did the chef change the recipe this round?”}
Clipping
\text{“Don't radically change the recipe in one update.”}
KL
\text{“Don't gradually turn the restaurant into a completely different restaurant.”}

That is exactly the logic of the source's chef analogy. (Source: Build a Reasoning Model (From Scratch))

Step 5.6 checkpoint

You should now be able to distinguish all four:

\boxed{ R \rightarrow \text{quality} }
\boxed{ A \rightarrow \text{relative quality} }
\boxed{ r \rightarrow \text{policy change relative to old} }
\boxed{ KL \rightarrow \text{policy drift relative to reference} }

and:

\boxed{ \text{clipping}+\text{KL} = \text{two complementary stability mechanisms} }

The source's worked example ends with:

\boxed{ -2.5764 + (-0.0075) = -2.5839 }

for the policy-plus-KL objective. (Source: Build a Reasoning Model (From Scratch); rl-grpo-slides)
