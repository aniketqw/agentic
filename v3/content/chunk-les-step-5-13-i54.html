Step-by-step derivation

  1. Generate teacher solutions offline, verify/curate them, and train the student against their text. The teacher need not be resident during each student minibatch.
  2. The target carrier is teacher-generated tokens, not necessarily teacher logits, hidden states or softened probabilities.
  3. Classical KD minimizes a temperature-scaled distribution discrepancy; R1 released students use SFT on curated responses. Temperature for teacher sampling is distinct from KD temperature.
  4. The approximate 800K mixture is supported by the R1 report. Exact 804745/domain counts and average length 5355 are the supplied DeepSeek book account, not exact figures independently established by the original short report.
  5. Teacher/student parameter ratio measures parameter compression, not exact latency, FLOPs or memory compression for an MoE teacher.

Step 5.13 — DeepSeek-R1 Distillation: From a 671B Teacher to Small Reasoning Models

Plan node: I8 · chat order #54

We have now completed the RL side:

\text{DeepSeekMath} \rightarrow \text{GRPO} \rightarrow \text{R1-Zero} \rightarrow \text{R1}.

Now comes the final transformation:

\boxed{ \text{DeepSeek-R1} \rightarrow \text{small reasoning models} }

This is knowledge distillation, but there is an important twist:

DeepSeek-R1 does not primarily distill its logits into the student. It distills the reasoning text it generates.

That distinction is central to this step. (Source: Build a DeepSeek Model (From Scratch))

5.13.1 Why do we need distillation at all?

The source describes DeepSeek-R1 as a:

\boxed{671B\text{-parameter}}

Mixture-of-Experts model.

Although only about:

\boxed{37B}

parameters are active per token, the entire model's weights still have to be available in memory. The source estimates about:

\boxed{1342\text{ GB}}

to store the 671B parameters in FP16. (Source: Build a DeepSeek Model (From Scratch))

So the teacher is powerful, but expensive.

The deployment problem is:

\boxed{ \text{great reasoning} \quad\text{vs}\quad \text{practical inference} }

We want to transfer the capability to something much smaller.

For example:

1.5B,\;7B,\;14B,\;32B,\;8B,\;70B.

The supplied R1 slides identify these as the student scale range. (Source: deepseek-r1-slides)

5.13.2 What exactly is distillation?

The source defines knowledge distillation as a model-compression technique where:

\boxed{ \text{large teacher} \rightarrow \text{small student} }

and the student learns to reproduce the teacher's behavior.

The important idea is:

\boxed{ \text{teacher = already trained} }
\boxed{ \text{student = trainable} }
\boxed{ \text{teacher is frozen} }

The student's parameters change; the teacher's do not. (Source: Build a DeepSeek Model (From Scratch))

5.13.3 Classical distillation: what we learned earlier

In classical knowledge distillation, suppose the teacher produces logits:

z_T.

The student produces:

z_S.

We convert them into soft distributions:

p_T = \operatorname{softmax} \left(\frac{z_T}{T}\right)

and:

p_S = \operatorname{softmax} \left(\frac{z_S}{T}\right).

Then use:

\boxed{ D_{KL}(p_T\|p_S) }

as a training signal.

The source's implementation combines:

\boxed{ L= \alpha L_{\text{hard}} + (1-\alpha)T^2L_{\text{soft}} }

where the hard term grounds the student to the true label and the soft term transfers the teacher's distribution. (Source: Build a DeepSeek Model (From Scratch))

5.13.4 Why is that natural for classification?

Suppose the classes are:

[\text{cat},\text{dog},\text{fox},\text{horse}].

The teacher might produce:

[0.80,0.10,0.08,0.02].

The student can learn not only:

\text{cat is correct},

but also:

\text{dog is more plausible than horse}.

That relative structure is what we earlier called:

\boxed{\text{dark knowledge}}.

5.13.5 Why is LLM reasoning different?

An LLM does not output one class.

It generates:

o_1,o_2,\ldots,o_T.

For a reasoning problem, the important object is often the entire reasoning trajectory.

Suppose the teacher solves:

Solve a difficult algebra problem.

The teacher might generate:

First isolate the variable...
This approach seems inconvenient.
Let's rewrite the equation...
Now substitute...
Therefore x = 17.

The useful thing is not just the probability of:

\text{“Therefore”}

at one token.

The important thing is the strategy represented by the entire sequence.

The source explicitly frames this as a paradigm shift from logits to language. (Source: Build a DeepSeek Model (From Scratch))

5.13.6 What is valuable in a reasoning trace?

The source identifies several useful properties in the teacher's generated reasoning:

\boxed{ \text{problem decomposition} }
\boxed{ \text{mathematical technique selection} }
\boxed{ \text{intermediate reasoning} }
\boxed{ \text{verification} }

and the overall coherent strategy.

So the teacher's output is effectively a demonstration of a solution procedure. (Source: Build a DeepSeek Model (From Scratch))

5.13.7 Therefore DeepSeek changes the distillation target

Classical KD:

\boxed{ \text{teacher logits} \rightarrow \text{student logits} }

DeepSeek-R1:

\boxed{ \text{teacher reasoning text} \rightarrow \text{student next-token training} }

This is the single most important equation of this step.

5.13.8 DeepSeek-R1's distillation is text-based SFT

Suppose the teacher sees:

q

and generates:

o=(y_1,y_2,\ldots,y_N).

The student is then trained using ordinary autoregressive language modeling:

\boxed{ L = -\frac1N \sum_{t=1}^{N} \log P_S(y_t\mid q,y_{<t}) }

This is just standard next-token cross-entropy.

There is:

\boxed{\text{no temperature}}

and:

\boxed{\text{no teacher-student KL}}

during student training in the DeepSeek-R1 distillation approach described by the source. (Source: Build a DeepSeek Model (From Scratch))

5.13.9 This is why the teacher can disappear after data generation

This is a very important engineering advantage.

Classical online KD

For every training batch:

input
 │
 ├──> teacher
 │       │
 │       └──> soft targets
 │
 └──> student
         │
         └──> loss against teacher

The teacher must be present during training.

DeepSeek-R1 text distillation

First:

prompt
  │
  ▼
teacher
  │
  ▼
reasoning trace
  │
  ▼
filter + curate
  │
  ▼
static dataset

Then:

static dataset
  │
  ▼
student SFT

The teacher is no longer needed during student training.

The source explicitly highlights this separation. (Source: Build a DeepSeek Model (From Scratch))

5.13.10 Why is this useful for a 671B teacher?

Imagine trying to simultaneously hold:

671B

teacher parameters plus a:

32B

student on GPUs during training.

That is an enormous memory burden.

DeepSeek instead pays the teacher cost once to create the dataset.

Then:

\boxed{ \text{teacher inference cost} }

is separated from:

\boxed{ \text{student training cost} }.

This is one of the major practical attractions of text-based reasoning distillation. (Source: Build a DeepSeek Model (From Scratch))

5.13.11 The teacher therefore becomes a data generator

This leads to a very useful mental model:

\boxed{ \text{R1 teacher} = \text{reasoning data generator} }

rather than:

\boxed{ \text{R1 teacher} = \text{network that must stay online during student training} }.

The data generated by R1 becomes the actual transfer mechanism.

5.13.12 Rejection sampling is what makes this dataset good

You should now connect this to the previous step.

The teacher could generate:

o_1,o_2,\ldots,o_K

for the same problem.

Not every output is good.

So:

\boxed{ \text{generate many} \rightarrow \text{verify} \rightarrow \text{filter} \rightarrow \text{keep strong traces} }

This is rejection sampling. The source defines it as generating multiple candidates, verifying them, and retaining only correct, well-formatted responses. (Source: Build a DeepSeek Model (From Scratch))

5.13.13 Example

Suppose one problem produces:

Response 1 → wrong
Response 2 → correct but messy
Response 3 → correct and well formatted
Response 4 → wrong
Response 5 → correct and well formatted

The dataset should preferably contain:

o_3,o_5

rather than:

o_1,o_2,o_4.

Thus the student doesn't just learn:

\text{what the teacher produces}.

It learns from:

\boxed{ \text{the teacher's high-quality outputs} }.

5.13.14 Correctness filtering

For mathematical reasoning:

\boxed{ \text{final answer} \rightarrow \text{compare with ground truth} }

For coding:

\boxed{ \text{code} \rightarrow \text{execute/test} }

For domains without deterministic verification, the supplied source describes model-based quality judgments as necessary. (Source: Build a DeepSeek Model (From Scratch))

5.13.15 Why formatting matters during distillation

This is a subtle but powerful idea.

Suppose the teacher's response is mathematically correct but chaotic:

maybe x=10...
wait
No
Actually
嗯...
Let's try again

If you train the student on thousands of such responses, the student can learn that style too.

The source explicitly notes:

the student learns to mimic the style of the training data, not merely its content.

Therefore:

\boxed{ \text{bad teacher data} \rightarrow \text{bad student behavior} }

This is why data curation is central to distillation. (Source: Build a DeepSeek Model (From Scratch))

The resulting DeepSeek-R1 distillation dataset contains approximately:

\boxed{804,745}

samples according to the source. (Source: Build a DeepSeek Model (From Scratch))

The approximate breakdown is:

\boxed{395K\text{ Math}}
\boxed{211K\text{ Code}}

\boxed{10K\text{ Logic}}
\boxed{178K\text{ General}}

5.13.18 Why include general data?

Because otherwise we risk:

\text{reasoning specialist} \rightarrow \text{bad general assistant}.

The source explicitly says the 178K general samples help preserve:

  • ordinary conversation,
  • factual QA,
  • writing,
  • translation,
  • general instruction following.

(Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{reasoning data} + \text{general data} }

produces a more balanced student.

5.13.19 The average sample is long

The source reports an average sample length of approximately:

\boxed{5,355\text{ tokens}}.

This is extremely important.

These are not short labels like:

Answer = 17

They are long reasoning traces.

Therefore the student sees:

\boxed{ \text{how to reason} }

rather than just:

\boxed{ \text{what the answer is} }.

(Source: Build a DeepSeek Model (From Scratch))

5.13.20 Why long reasoning traces matter

Suppose the teacher gives only:

17

The student learns:

q\rightarrow17.

But if the teacher provides:

We first isolate x...
Substitute the known value...
Simplify...
Check the result...
Therefore x=17.

the student is exposed to:

q \rightarrow \text{subproblem decomposition} \rightarrow \text{calculation} \rightarrow \text{verification} \rightarrow 17.

This is what makes chain-of-thought distillation different from simply labeling the answer.

5.13.21 Sequence-level SFT objective

Suppose:

x= [q,y_1,y_2,\ldots,y_N].

During training:

\text{input} = [q,y_1,\ldots,y_{N-1}]

and:

\text{target} = [y_1,y_2,\ldots,y_N].

The model learns:

P(y_t\mid q,y_{<t}).

Loss:

\boxed{ L_{\mathrm{SFT}} = -\sum_t \log P_S(y_t\mid q,y_{<t}) }

or the mean over non-masked target positions.

This is simply the same next-token objective we learned when studying GPT pretraining.

5.13.22 This is a beautiful connection

At the beginning of the course we learned:

\boxed{ \text{LLM pretraining} = \text{predict the next token} }

Now at the end we use exactly the same mathematical objective:

\boxed{ \text{next-token prediction} }

but the target sequences have been selected from:

\boxed{\text{a much stronger teacher}}.

So the training objective is familiar; the remarkable part is the source of the training data.

5.13.23 Compare ordinary SFT and R1 distillation

Ordinary SFT
\text{human-curated answer} \rightarrow \text{student}.
R1 distillation
\text{R1-generated reasoning} \rightarrow \text{filter} \rightarrow \text{student}.

Thus:

\boxed{ \text{teacher-generated SFT dataset} }

is the core innovation.

5.13.24 Teacher vs student

The teacher:

\boxed{\text{DeepSeek-R1}}

has learned strong reasoning through:

\text{SFT + RL + rejection sampling + final RL}.

The student:

\boxed{\text{Qwen/Llama base}}

does not have to rediscover all those behaviors using RL.

Instead it sees examples produced by the stronger teacher.

So:

\boxed{ \text{teacher discovered} \rightarrow \text{student imitates} }

This explains why distillation can be substantially easier than asking a small model to discover the same reasoning strategy from reward alone.

5.13.25 The source's strongest comparison: distillation vs direct RL

This is perhaps the most important empirical result in the entire distillation chapter.

Take the same architecture:

\boxed{\text{Qwen2.5-32B}}.

Train one version using large-scale RL.

Train another using R1-generated distillation data with SFT.

The source reports:

\boxed{ \text{Distill-32B AIME}=72.6\% }

versus:

\boxed{ \text{RL-only 32B AIME}=47.0\% }.

Difference:

72.6-47.0 = \boxed{25.6\text{ percentage points}}.

(Source: Build a DeepSeek Model (From Scratch))

5.13.26 Why is this experiment so powerful?

Because the architecture is held constant.

So:

\text{same model size}
\text{same basic architecture}

but:

\boxed{\text{different training strategy}}.

And the distilled version wins substantially.

That is strong evidence that:

\boxed{ \text{training data quality can be more important than simply applying more RL} }

for the particular comparison presented by the source.

Notice something:

The advantage is not only in math.

It also appears in:

\boxed{\text{coding}}

5.13.28 Why might direct RL be difficult for a smaller model?

The source's broader analysis emphasizes a capacity and exploration problem.

A small model may lack the capacity or good initial distribution needed to discover strong reasoning strategies efficiently.

So direct RL is asking:

\text{small model} + \text{reward} \rightarrow \text{discover strategy}.

Distillation instead gives:

\text{small model} + \text{successful strategy demonstrations} \rightarrow \text{learn strategy}.

The second problem can be much easier.

5.13.29 This is the key asymmetry

RL:

\boxed{ \text{discover} }

Distillation:

\boxed{ \text{transfer} }

Therefore:

\boxed{ \text{teacher pays exploration cost} }

and:

\boxed{ \text{student pays imitation cost} }.

This is one of the deepest insights from the entire R1 pipeline.

5.13.31 Base models matter

The source notes an important difference:

The smaller Qwen students use:

specialized bases.

The larger Qwen students use general-purpose Qwen2.5 bases.

The Llama students use Llama bases. (Source: Build a DeepSeek Model (From Scratch))

Therefore:

\boxed{ \text{student performance} \neq f(\text{student parameter count})\text{ only} }

It also depends on:

\boxed{ \text{base model quality and specialization} }.

5.13.32 Example: Qwen vs Llama at similar size

The source reports:

while:

So the slightly larger Llama model still performs worse in this comparison.

Difference:

55.5-50.4 = \boxed{5.1\text{ points}}.

The source attributes this broad pattern partly to the stronger math-specialized bases used by the smaller Qwen variants. (Source: Build a DeepSeek Model (From Scratch))

calculate the incremental gains:

\boxed{ +26.6,\;+14.2,\;+2.9 }

This is a simple but useful scaling question.

5.13.35 The 1.5B result

The source reports:

\boxed{ \text{R1-Distill-Qwen-1.5B}=28.9\%\text{ AIME} }

and:

\boxed{ \text{GPT-4o}=9.3\% }

for the benchmark comparison shown. (Source: Build a DeepSeek Model (From Scratch))

Difference:

28.9-9.3 = \boxed{19.6\text{ points}}.

So the tiny distilled student strongly outperforms GPT-4o on that specific benchmark comparison.

That does not mean it is globally more capable than GPT-4o.

5.13.36 Capacity gap

Now notice the student's uneven performance.

The source reports for the 1.5B student:

\text{MATH}=83.9\%

but:

\text{LiveCodeBench}=16.9\%.

Gap:

83.9-16.9 = \boxed{67.0\text{ points}}.

(Source: Build a DeepSeek Model (From Scratch))

This demonstrates:

\boxed{ \text{small student cannot absorb every capability equally} }

5.13.37 Why math transfers relatively well

The source interprets the high math performance as evidence that mathematical reasoning patterns can compress effectively into smaller models. (Source: Build a DeepSeek Model (From Scratch))

But coding requires a broader capability space involving:

\text{syntax} + \text{APIs} + \text{libraries} + \text{architectural patterns}.

The source uses this to explain why the very small student struggles much more on coding. (Source: Build a DeepSeek Model (From Scratch))

5.13.38 Very important: distillation is not magic parameter compression

Suppose:

R1=671B.

and:

Student=1.5B.

We are not doing:

W_{1.5B}=f(W_{671B})

in the sense of mechanically shrinking the weight matrix.

Instead:

\boxed{ \text{R1} \rightarrow \text{generate training data} }

then:

\boxed{ \text{1.5B model} \rightarrow \text{train on that data}. }

The source explicitly says the student's architecture and pretrained weights remain those of its original Qwen/Llama base; what R1 contributes is the training data. (Source: Build a DeepSeek Model (From Scratch))

5.13.39 This explains the word “distillation”

The knowledge is transferred indirectly.

Think:

671B teacher
     │
     │ generates
     ▼
reasoning traces
     │
     │ curate
     ▼
800K examples
     │
     │ SFT
     ▼
1.5B / 7B / 14B / 32B / ...

The teacher is not physically compressed.

Its behavior is reproduced by another model.

5.13.40 Classical KD vs R1 distillation

Memorize this table:

Property Classical KD DeepSeek-R1 text distillation
Teacher output Logits/probabilities Generated reasoning text
Main loss KL + hard CE Standard next-token CE
Temperature Used Not used
Teacher required during student training Typically yes No
Teacher/student simultaneously loaded Yes No
Transfer object Probability distribution Reasoning trajectories
Data Teacher produces soft targets online Teacher-generated dataset prepared offline

The source explicitly calls the R1 approach fundamentally different from logit/temperature-based classical distillation. (Source: Build a DeepSeek Model (From Scratch))

5.13.41 Why does the R1 approach fit reasoning particularly well?

Because the teacher's valuable asset is:

\boxed{ \text{how it solves problems} }

rather than simply:

\boxed{ \text{its probability over the next token} }.

A student can learn:

\text{“break this problem into subproblems”}

through repeated exposure to teacher traces.

This is why the source describes the process as:

\boxed{ \text{reasoning-trace distillation} }.

(Source: Build a DeepSeek Model (From Scratch))

5.13.42 A subtle distinction: knowledge vs behavior

Classical KD often focuses on:

\text{teacher's predictive distribution}.

R1-style distillation focuses more directly on:

\text{teacher's observable behavior}.

So:

\boxed{ \text{classical KD} \approx \text{distribution matching} }
\boxed{ \text{R1 distillation} \approx \text{behavior imitation} }

This distinction will be extremely useful when we later discuss black-box vs white-box distillation.

Suppose:

teacher parameters and:

student parameters.

\frac{671}{1.5} \approx447.3.

So the teacher is approximately:

\boxed{447\times}

larger by parameter count.

\boxed{804K}

approximately matches the reported:

5.13.45 Exam numerical — average token volume

Suppose:

804,745

examples have an average length of:

5,355

tokens.

Approximate token volume:

804,745\times5,355.

This is approximately:

\boxed{4.31\times10^9}

tokens, or:

\boxed{\approx4.31B\text{ tokens}}.

This is an enormous supervised training set in token terms.

5.13.46 Why teacher cost is amortized

Suppose generating the complete dataset costs:

C_T.

Once generated, the same dataset can be used for:

S_1,S_2,S_3,\ldots,S_N.

Then:

\boxed{ \text{one teacher-generation investment} }

supports:

\boxed{ \text{many students} }.

The source explicitly emphasizes this property and notes that DeepSeek trained six students from the same dataset. (Source: Build a DeepSeek Model (From Scratch))

5.13.47 This is economically very different from direct RL

Direct RL:

\text{each student} \rightarrow \text{its own rollouts} \rightarrow \text{its own verification} \rightarrow \text{its own optimization}.

Distillation:

\text{teacher} \rightarrow \text{one dataset} \rightarrow \boxed{ \text{many students} }.

Therefore:

\boxed{ \text{distillation amortizes teacher computation} }

This is one reason it is attractive for deployment.

5.13.48 The deepest conceptual lesson

R1 first uses RL to make the large model discover or sharpen reasoning behavior.

Then distillation uses SFT to make smaller models imitate that behavior.

So:

\boxed{ \text{RL = capability discovery / optimization} }
\boxed{ \text{distillation = capability transfer} }

This is the central bridge between the two parts of the course.
