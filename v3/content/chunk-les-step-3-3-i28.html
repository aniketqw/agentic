Motivation

Translate one low-rank matrix update into selected projections of an entire transformer.

Prerequisites

  • Combined multihead QKV projection dimensions
  • Single-layer LoRA count
  • Weight sharing

Notation and units

  • L layers; m targeted matrices per layer
  • General count=sum over targets r_i(din_i+dout_i)
  • d hidden width; head width dh=d/H; token length n

Assumptions

  • Four-square-projection example assumes ordinary combined MHA
  • Equal rank and dimensions only for simplified Lmr(d+out) formula
  • Grouped-query/multiquery key and value projections can be narrower

Step-by-step derivation

  1. Adapt Q=XWQ+s(XBQ)AQ, then retain ordinary score, causal mask, softmax and AV operations.
  2. Repeat only for explicitly targeted WQ, WK, WV, WO; target selection is a configuration, not a theorem.
  3. One square adapter has 2rd entries; multiply by target matrices and layers, not by heads again.
  4. Batch and sequence dimensions affect arithmetic and activation memory; they do not create copies of shared trainable matrices.
  5. Use actual rectangular K/V dimensions for GQA; sum counts per module rather than applying 4d² blindly.

    Continuation · checked fixture P03 — LoRA trainable counts and whole-model scope

    Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

    Distinguish one adapted projection from total model storage and trainable parameters.

    Prerequisites: LoRA orientation and the complete slide numerical, Parameter accounting and tied weights

    Notation and assumptions

    Adapter weights=r(din+dout); frozen base still stored. Sum counts over selected unique modules. Square same-width matrices give d/(2r) reduction against those matrices only.

    Derivation and mechanism

    1. Count both thin matrices.
    2. Sum over actual target modules and shapes.
    3. Compare that sum to the stated denominator: adapted bases or entire model.
    P_{adapter}=\sum_{m\in targets}r_m(d_{in,m}+d_{out,m})

    Worked example

    One4096² projection, r8:16,777,216 base weights versus65,536 adapter weights→256×. All four such projections in32layers→8,388,608 trainable weights. Against6.74B total that is≈.12446%, not a claim that the entire model shrinks256×.

    Limitations

    • GQA, different FFN widths, unadapted embeddings and extra trainable biases alter the full-model ratio.
    • Trainable-count reduction is not an equal factor reduction in total training memory or runtime.

    Connections to later concepts

    • Q08 and A08 separate trainable adapter count from frozen base storage and optimizer-state memory.

    Step 3.3 — Where LoRA Goes Inside a Transformer

    Plan node: I3 · chat order #28

    We now know the mathematics of LoRA:

    \boxed{ W'=W_0+\frac{\alpha}{r}BA }

    But we have not yet answered the most important practical question:

    Which W in a Transformer do we actually replace with LoRA?

    This step connects the abstract LoRA matrix to the Transformer we already studied.

    The PEFT lecture's concrete model-scale example applies LoRA to the four attention projections:

    \boxed{W_Q,\;W_K,\;W_V,\;W_O}

    in every layer. (Source: peft-slides)

    3.3.1 First Recall the Transformer Attention Block

    From our earlier Transformer lessons:

    X\in\mathbb{R}^{n\times d}.

    We calculate:

    Q=XW_Q
    K=XW_K
    V=XW_V.

    Then:

    S=\frac{QK^T}{\sqrt{d_k}}

    followed by:

    A=\operatorname{softmax}(S+M)

    and:

    O=AV.

    Finally, multi-head attention applies the output projection:

    \boxed{ \operatorname{MHA}(X)=\operatorname{Concat}(\text{heads})W_O. }

    These projection matrices are part of the standard Transformer mathematical structure. (Source: Step1_Transformers_Mathematical_Cheatsheet)

    3.3.2 There Are Four Important Attention Matrices

    So one Transformer attention module contains:

    \boxed{W_Q}
    \boxed{W_K}
    \boxed{W_V}
    \boxed{W_O}.

    They have different jobs.

    W_Q

    Creates queries:

    Q=XW_Q.
    W_K

    Creates keys:

    K=XW_K.
    W_V

    Creates values:

    V=XW_V.
    W_O

    Projects the concatenated head outputs back into the model dimension.

    3.3.3 Now Apply LoRA

    Instead of directly changing:

    W_Q,

    we can write:

    \boxed{ W_Q' = W_Q+ \frac{\alpha}{r}B_QA_Q. }

    Similarly:

    \boxed{ W_K' = W_K+ \frac{\alpha}{r}B_KA_K }
    \boxed{ W_V' = W_V+ \frac{\alpha}{r}B_VA_V }

    and:

    \boxed{ W_O' = W_O+ \frac{\alpha}{r}B_OA_O. }

    So the original attention becomes a frozen base path plus trainable low-rank corrections.

    3.3.4 What Does the Forward Pass Now Look Like?

    Originally:

    Q=XW_Q.

    With LoRA:

    Q=XW_Q'.

    Substitute:

    Q = X\left(W_Q+\frac{\alpha}{r}B_QA_Q\right).

    Therefore:

    \boxed{ Q=XW_Q+\frac{\alpha}{r}(XB_Q)A_Q. }

    Exactly the same idea we derived in Step 3.2.

    Likewise:

    \boxed{ K=XW_K+\frac{\alpha}{r}(XB_K)A_K }

    and:

    \boxed{ V=XW_V+\frac{\alpha}{r}(XB_V)A_V. }

    Then attention proceeds normally.

    3.3.5 The Important Insight

    LoRA does not replace attention.

    It does not change:

    QK^T

    or:

    \operatorname{softmax}

    or:

    AV.

    Instead, it changes how the model constructs the projections feeding attention.

    So:

    Original Transformer

X
│
├── WQ ──> Q
├── WK ──> K
└── WV ──> V
          │
          ▼
      Attention
          │
          ▼
         WO

    becomes:

    LoRA Transformer

             frozen WQ
X ───────────────┐
                 ├──> Q
        LoRA ────┘

             frozen WK
X ───────────────┐
                 ├──> K
        LoRA ────┘

             frozen WV
X ───────────────┐
                 ├──> V
        LoRA ────┘

              Attention
                  │
                  ▼

             frozen WO
                  │
             + LoRA
                  │
                  ▼
                 output

    3.3.6 Why Are These Good Places to Adapt?

    The attention projections determine the representations used to decide:

    What information should interact with what other information?

    Recall:

    QK^T

    determines compatibility.

    So changing:

    W_Q,W_K

    can change the attention relationships.

    Changing:

    W_V

    changes the content being transported.

    Changing:

    W_O

    changes how the resulting head information is recombined.

    Thus, even though the LoRA matrices are small, they sit at important transformation points inside the network.

    The supplied PEFT material directly demonstrates the attention-projection application; broader claims about why these are universally optimal target modules are not established by the slide itself, so we should not treat that as a source-derived guarantee.

    3.3.7 Let's Do the Full Attention Computation

    Suppose:

    X\in\mathbb{R}^{n\times d}.

    With LoRA:

    W_Q' = W_Q+\frac{\alpha}{r}B_QA_Q.

    Then:

    Q=XW_Q'.

    Similarly:

    K=XW_K'

    and:

    V=XW_V'.

    Then:

    \boxed{ S=\frac{QK^T}{\sqrt{d_k}} }
    \boxed{ A=\operatorname{softmax}(S+M) }
    \boxed{ O=AV. }

    Finally:

    \boxed{ Y=OW_O' }

    for the simplified single-matrix representation.

    The attention mathematics itself has not changed.

    Only the learned projections have received low-rank trainable updates.

    3.3.8 A Small Numerical Shape Example

    Suppose:

    n=8, \qquad d=16, \qquad d_k=4.

    For one attention projection:

    W_Q\in\mathbb{R}^{16\times4}.

    Take:

    r=2.

    Then:

    B_Q\in\mathbb{R}^{16\times2}

    and:

    A_Q\in\mathbb{R}^{2\times4}.

    Therefore:

    B_QA_Q

    has shape:

    (16\times2)(2\times4) = \boxed{16\times4}.

    Exactly the shape of:

    W_Q.

    3.3.9 Parameter Count for W_Q

    Original:

    16\times4=64

    parameters.

    LoRA:

    2(16+4) = 40.

    So for this deliberately small example, the reduction is:

    \frac{64}{40}=1.6.

    Notice something important:

    LoRA is only strongly parameter-efficient when r is much smaller than the layer dimensions.

    That is why the condition:

    \boxed{ r\ll d,d_{\text{out}} }

    matters.

    3.3.10 Now Use a Realistic Hidden Size

    The PEFT lecture uses:

    d=4096

    and:

    r=8.

    For a square attention projection:

    W_Q\in\mathbb{R}^{4096\times4096}.

    Full parameter count:

    4096^2 = \boxed{16,777,216}.

    LoRA parameter count:

    8(4096+4096)
    = 8(8192)
    = \boxed{65,536}.

    This is the source's exact numerical example. (Source: peft-slides)

    3.3.11 Reduction for One Projection

    \frac{16,777,216}{65,536} = \boxed{256}.

    So instead of training:

    16.78\text{ million}

    parameters for one projection, we train:

    65,536.

    The reduction is:

    \boxed{256\times}.

    3.3.12 But One Transformer Layer Has Four Projections

    The source applies LoRA to:

    \boxed{ W_Q,W_K,W_V,W_O. }

    So there are:

    4

    such matrices.

    Each requires:

    65,536

    LoRA parameters.

    Therefore:

    4\times65,536
    = \boxed{262,144}

    trainable parameters per layer.

    3.3.13 Now 32 Transformer Layers

    Suppose:

    L=32.

    Then:

    32\times262,144
    = \boxed{8,388,608}.

    Therefore:

    \boxed{ 8,388,608 }

    LoRA parameters are trainable across all four attention projections of all 32 layers.

    This exact full-model calculation appears in your PEFT lecture. (Source: peft-slides)

    3.3.14 Compare Against the Full Model

    The source's model is described as:

    \boxed{6.74B}

    total parameters.

    LoRA trains:

    8,388,608.

    Calculate the fraction:

    \frac{8,388,608}{6.74\times10^9}.

    Approximately:

    0.001244.

    As a percentage:

    0.1244\%.

    So:

    \boxed{ \approx0.124\% }

    of the model parameters are trained.

    The remaining approximately:

    \boxed{99.876\%}

    are frozen under this setup.

    This is the exact percentage highlighted by the PEFT lecture. (Source: peft-slides)

    3.3.15 This Is the Key Full-Model Numerical

    Memorize the derivation, not just the answer.

    Given:

    d=4096, \quad r=8, \quad L=32.

    One projection:

    r(2d) = 8(8192) = 65,536.

    Four projections:

    4(65,536) = 262,144.

    32 layers:

    32(262,144) = \boxed{8,388,608}.

    Therefore:

    \boxed{ 8.39\text{ million trainable parameters}. }

    3.3.16 Exam Question

    A 32-layer Transformer has hidden size 4096. LoRA rank is 8. LoRA is applied to W_Q,W_K,W_V,W_O in every layer. How many trainable LoRA parameters are introduced?

    Step 1 — One projection
    8(4096+4096) = 65,536.
    Step 2 — Four projections
    4(65,536) = 262,144.
    Step 3 — 32 layers
    32(262,144) = \boxed{8,388,608}.

    3.3.17 Exam Question — What If Rank Doubles?

    Suppose:

    r=16

    instead of:

    r=8.

    Because:

    N_{\text{LoRA}}\propto r,

    the number doubles:

    8,388,608\times2 = \boxed{16,777,216}.

    So:

    \boxed{ r\uparrow2\times \Rightarrow N_{\text{trainable}}\uparrow2\times. }

    3.3.18 Exam Question — What If Layers Double?

    Suppose:

    L=64

    instead of 32, with everything else unchanged.

    Since:

    N\propto L,

    we get:

    8,388,608\times2 = \boxed{16,777,216}.

    Therefore:

    \boxed{ N_{\text{LoRA}}\propto Lr }

    when the target dimensions and number of target matrices per layer remain fixed.

    3.3.19 General Full-Model Formula

    Suppose:

    • L = number of layers,
    • m = number of targeted matrices per layer,
    • each matrix has dimensions d\times d_{\text{out}},
    • LoRA rank r.

    Then:

    \boxed{ N_{\text{LoRA,total}} = L\,m\,r(d+d_{\text{out}}). }

    For the source example:

    L=32
    m=4
    r=8
    d=d_{\text{out}}=4096.

    Therefore:

    32\times4\times8(4096+4096)
    = \boxed{8,388,608}.

    This formula is one of the most useful exam formulas from this section.

    3.3.20 Important: Number of Heads Does Not Appear Here

    You might ask:

    "The Transformer has multiple attention heads. Why didn't we multiply by the number of heads?"

    Because in the standard combined projection representation:

    W_Q\in\mathbb{R}^{d\times d}

    already produces the projections for all heads.

    For example:

    d=4096.

    If:

    H=32,

    then each head might have:

    d_h=\frac{4096}{32}=128.

    But the combined W_Q is still:

    4096\times4096.

    So you do not multiply its parameter count by 32 again.

    This is an important exam trap.

    3.3.21 Let's See Why

    The combined projection produces:

    Q=XW_Q.

    Suppose:

    X:n\times4096

    and:

    W_Q:4096\times4096.

    Then:

    Q:n\times4096.

    Afterward, reshape:

    n\times4096

    into:

    32\times n\times128.

    So the head separation happens after the projection.

    Therefore:

    \boxed{ W_Q\text{ already contains all head projections}. }

    3.3.22 Connection to Our Earlier MHA Lesson

    Previously we learned:

    d_h=\frac{d}{H}.

    For:

    d=4096,\quad H=32,

    we get:

    d_h=128.

    The Q tensor can be viewed as:

    Q\in\mathbb{R}^{n\times32\times128}

    or, depending on convention:

    32\times n\times128.

    But the LoRA target matrix before reshaping is:

    \boxed{ W_Q:4096\times4096. }

    This connects the LoRA lesson directly back to the Transformer mathematics we already completed.

    3.3.23 What About W_O?

    After attention:

    \text{Concat(head}_1,\ldots,\text{head}_H)

    returns to model width:

    n\times d.

    Then:

    W_O\in\mathbb{R}^{d\times d}

    projects it.

    So for:

    d=4096,

    we again have:

    4096\times4096.

    Therefore W_O receives exactly the same LoRA parameter count in the source's simplified model:

    \boxed{65,536}.

    3.3.24 Full One-Layer Picture

    For one Transformer layer:

                      X
                  │
        ┌─────────┼─────────┐
        │         │         │
       WQ        WK        WV
        │         │         │
      +LoRA     +LoRA     +LoRA
        │         │         │
        ▼         ▼         ▼
        Q         K         V
         \        │        /
          \       │       /
             Attention
                 │
                 ▼
             Concat heads
                 │
               WO
              +LoRA
                 │
                 ▼
             Attention
              output

    So LoRA is attached to the linear projections, while the attention operation itself remains the same.

    3.3.25 Does LoRA Change the Causal Mask?

    No.

    The causal mask is still:

    M_{ij} = \begin{cases} 0,&j\le i\\ -\infty,&j>i. \end{cases}

    LoRA changes the learned projections:

    W_Q,W_K,W_V,W_O.

    It does not remove the autoregressive constraint.

    Therefore:

    \boxed{ \text{LoRA adaptation}\neq\text{change to causal masking}. }

    The attention mathematics remains:

    A= \operatorname{softmax} \left( \frac{QK^T}{\sqrt{d_k}}+M \right).

    3.3.26 Does LoRA Change the Softmax?

    Again:

    \boxed{\text{No.}}

    The ordinary attention calculation remains.

    LoRA changes:

    Q,\ K,\ V

    through their projections.

    Then the usual:

    QK^T

    and softmax operate on those adapted representations.

    3.3.27 Does LoRA Change the Transformer Architecture?

    At the conceptual level:

    \boxed{ \text{No major architectural redesign is required.} }

    You have:

    \text{same Transformer} + \text{small trainable low-rank branches}.

    This is why PEFT is attractive: the pretrained architecture remains largely intact.

    3.3.28 LoRA Training Flow

    Now imagine training.

    Step 1

    Load pretrained model:

    W_0.
    Step 2

    Freeze:

    W_0.
    Step 3

    Insert LoRA factors:

    A,B.
    Step 4

    Initialize them according to the LoRA scheme.

    Step 5

    Run forward pass:

    XW_0+\frac{\alpha}{r}(XB)A.
    Step 6

    Calculate task loss:

    L.
    Step 7

    Backpropagate.

    Gradients update:

    \boxed{A,B}

    but not:

    \boxed{W_0}.

    3.3.29 Which Parameters Receive Gradients?

    For full fine-tuning:

    \nabla_{W_0}L\neq0

    and optimizer updates W_0.

    For LoRA:

    \boxed{ W_0\text{ frozen} }

    so it is not updated.

    Instead:

    \boxed{ \nabla_A L,\nabla_B L }

    are used to train the adapters.

    This is where the huge reduction in trainable state comes from.

    3.3.30 A Critical Training-Memory Point

    Suppose:

    N_{\text{base}}=6.74B

    but:

    N_{\text{LoRA}}=8.39M.

    The base model still has to exist in memory for the forward pass.

    So do not conclude:

    "Only 8.39M parameters exist during training."

    No.

    Rather:

    \boxed{ 6.74B\text{ base parameters exist, but only }8.39M\text{ are trainable in this example}. }

    This distinction becomes especially important when we reach:

    \boxed{\text{quantization + QLoRA}}

    because quantization then attacks the memory footprint of the frozen base model itself.

    3.3.31 Why This Leads Naturally to QLoRA

    We now have two different problems:

    LoRA solves
    \boxed{ \text{too many trainable parameters}. }

    But the frozen model can still be enormous.

    Quantization solves
    \boxed{ \text{large memory footprint of model weights}. }

    Therefore the natural combination is:

    \boxed{ \text{quantized frozen base} + \text{trainable LoRA adapters}. }

    That will become QLoRA later.

    Do not jump there yet—we first need to complete the LoRA mechanics.

    3.3.32 Exam Numerical — Full Attention Adapter Count

    Given:

    L=24
    d=2048
    r=16

    and LoRA on:

    W_Q,W_K,W_V,W_O.

    One projection:

    16(2048+2048) = 16(4096) = 65,536.

    Four:

    4(65,536) = 262,144.

    24 layers:

    24(262,144) = \boxed{6,291,456}.

    3.3.33 Exam Numerical — Percentage

    Suppose the base model has:

    3.2B

    parameters.

    Suppose LoRA trains:

    6,291,456.

    Percentage:

    \frac{6,291,456}{3.2\times10^9}\times100
    \approx \boxed{0.1966\%}.

    So approximately:

    \boxed{0.20\%}

    of the parameters are trainable.

    3.3.34 Exam Trap — Four Projections

    If the question says:

    Apply LoRA to all four attention projections.

    You multiply by:

    \boxed{4}.

    If it says:

    Apply LoRA only to W_Q and W_V.

    You multiply by:

    \boxed{2}.

    If it says only:

    W_Q,

    multiply by:

    \boxed{1}.

    So always identify:

    \boxed{ m=\text{number of target matrices per layer}. }

    Then:

    N=Lmr(d+d_{\text{out}}).

    3.3.35 Exam Trap — Do Not Multiply by Sequence Length

    The LoRA parameter count:

    Lmr(d+d_{\text{out}})

    does not depend on:

    n=\text{sequence length}.

    Why?

    Because the trainable matrices are model parameters.

    The sequence length changes the amount of computation/activation processing, but it does not create new copies of W_Q.

    Therefore:

    \boxed{ N_{\text{LoRA parameters}}\neq f(n). }

    3.3.36 Exam Trap — Do Not Multiply by Batch Size

    Similarly:

    B=\text{batch size}

    does not multiply the number of LoRA parameters.

    The same LoRA matrices are shared across every example in the batch.

    Therefore:

    \boxed{ N_{\text{LoRA parameters}} \text{ is independent of batch size}. }

    3.3.37 The Four Different Dimensions You Must Keep Separate

    This is particularly important for numerical questions.

    \boxed{d}

    = model/hidden dimension.

    \boxed{d_h}

    = per-head dimension.

    \boxed{r}

    = LoRA rank.

    \boxed{n}

    = sequence length.

    Do not substitute one for another.

    For example:

    d=4096, \quad H=32, \quad d_h=128, \quad r=8, \quad n=2048.

    All five numbers have completely different meanings.

    3.3.38 Full Numerical Shape Problem

    Suppose:

    n=128
    d=4096
    H=32
    d_h=128
    r=8.

    For W_Q:

    W_Q:4096\times4096.

    LoRA:

    B_Q:4096\times8
    A_Q:8\times4096.

    Input:

    X:128\times4096.

    Then:

    XB_Q: (128\times4096)(4096\times8)
    = \boxed{128\times8}.

    Then:

    (XB_Q)A_Q: (128\times8)(8\times4096)
    = \boxed{128\times4096}.

    This is added to:

    XW_Q: (128\times4096)(4096\times4096) = \boxed{128\times4096}.

    Everything is dimensionally consistent.

    3.3.39 Now Connect It to the Attention Heads

    The resulting:

    Q:128\times4096

    is reshaped into:

    \boxed{ 32\times128\times128 }

    depending on tensor ordering.

    That's:

    H\times n\times d_h.

    So:

    32\times128\times128 = 524,288

    elements, which is exactly:

    128\times4096.

    Again, the LoRA operation happened before the head split in this standard combined-projection representation.

    \boxed{ W_Q,W_K,W_V,W_O }

    with:

    d=4096,\quad r=8,

    across:

    32

    layers, giving:

    \boxed{ 8,388,608 }

    3.3.41 Master Formula for This Step

    For L layers, m target matrices per layer, matrix shape d\times d_{\text{out}}, and rank r:

    \boxed{ N_{\text{LoRA}} = Lmr(d+d_{\text{out}}) }

    For square attention projections:

    d=d_{\text{out}},

    therefore:

    \boxed{ N_{\text{LoRA}} = 2Lmrd. }

    For the supplied example:

    2(32)(4)(8)(4096)
    = \boxed{8,388,608}.
