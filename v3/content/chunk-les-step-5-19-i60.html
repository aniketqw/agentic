Step-by-step derivation

  1. The student absorbs a subset of sampled, curated teacher behavior and may combine it with capabilities already present in its own base model.
  2. A teacher ceiling is an intuition, not a universal theorem: better optimization, task specialization, external data or pre-existing student knowledge can let a student exceed a teachers measured score.
  3. Different benchmark scores cannot measure capacity on a common scale. An83.9 MATH versus16.9 coding gap compares task-specific accuracies, not67 points of missing knowledge.
  4. Doubling length quadruples dense attention-score pair count, while total model runtime also contains linear projections, MLP and hardware-dependent terms.
  5. Adaptive reasoning budgets trade tokens for quality; savings must be measured alongside accuracy, latency and tool/verification cost.
  6. Distillation, reward-based refinement and inference-time search act at different stages and can be combined. Process rewards remain noisy and hard to define, not automatically superior.

Step 5.19 — Limits of Distillation + Future Directions

Plan node: I8 · chat order #60

We have reached the final conceptual part of the distillation block.

So far we established:

\text{Teacher} \rightarrow \text{high-quality traces} \rightarrow \text{curated dataset} \rightarrow \text{student SFT} \rightarrow \text{smaller reasoning model}.

Now we need to understand the opposite question:

What can distillation NOT do?

This is where we introduce the two most important boundaries:

\boxed{\text{Capacity frontier}}

and

\boxed{\text{Knowledge frontier}}.

The source then connects these limitations to the future of reasoning models: better teachers, inference-time scaling, richer process rewards, and multi-reward agent training. (Source: Build a DeepSeek Model (From Scratch))

5.19.1 First limitation — Student capacity

The first problem is simple:

\boxed{ \text{Teacher is more capable than student} }

A student has fewer parameters and therefore a smaller representational budget.

Suppose the teacher has learned:

R_1,R_2,\ldots,R_{1000}

useful reasoning patterns.

A tiny student may only be able to represent a subset:

R_1,R_2,\ldots,R_{300}.

The remaining patterns may be:

  • poorly represented,
  • generalized incorrectly,
  • or simply not retained.

This is what the source calls the capacity gap. (Source: Build a DeepSeek Model (From Scratch))

5.19.2 Capacity gap is not simply “small model = bad”

This distinction matters.

A small model can be excellent on a narrow task while being poor on another.

The source's 1.5B example demonstrates this:

\boxed{83.9\%\text{ on MATH-500}}

but:

\boxed{16.9\%\text{ on LiveCodeBench}}.

(Source: Build a DeepSeek Model (From Scratch))

So the model has enough capacity for many mathematical patterns but not enough to represent the huge diversity required for coding.

5.19.3 Why does task structure matter?

The source's explanation is:

Mathematics

Often contains relatively structured solution patterns:

\text{identify problem type} \rightarrow \text{select technique} \rightarrow \text{calculate} \rightarrow \text{verify}.
Coding

Requires a much wider space involving:

\text{syntax} + \text{APIs} + \text{design patterns} + \text{error handling} + \text{program structures} +\cdots

The source therefore argues that mathematical reasoning can compress more effectively than complex coding behavior. (Source: Build a DeepSeek Model (From Scratch))

5.19.4 A very useful mental model

Think of student capacity as a bottleneck:

\boxed{ \text{teacher information} \xrightarrow{\text{capacity bottleneck}} \text{student representation} }

If:

C_S<C_T

where C_S is student capacity and C_T is the effective complexity of the teacher's behavior, some information will not transfer perfectly.

This is a conceptual model, not a formally defined capacity equation from the source.

5.19.5 The source's practical student-size guidance

The source gives a practical rule of thumb:

\boxed{1.5B\text{–}3B}

for narrow, well-defined reasoning domains.

\boxed{7B\text{–}14B}

as a useful range for broader reasoning involving math and coding.

\boxed{32B\text{–}70B}

for near-teacher-quality behavior across many domains, at significantly higher hardware cost. (Source: Build a DeepSeek Model (From Scratch))

These should be treated as source-specific practical guidelines, not universal laws.

5.19.6 Numerical: coding gap

For the 1.5B model:

\text{Math}=83.9
\text{Code}=16.9.

Difference:

83.9-16.9 = \boxed{67.0\text{ points}}.

That is a huge capability imbalance.

This is the clearest numerical demonstration of the capacity gap in the supplied material. (Source: Build a DeepSeek Model (From Scratch))

5.19.7 Second limitation — Knowledge frontier

Now the deeper limitation.

Suppose the teacher cannot solve a class of problems.

Then during rejection sampling:

\text{incorrect teacher responses} \rightarrow \text{rejected}.

Therefore the final distilled dataset contains no successful teacher demonstrations for that capability.

The source describes this as a knowledge frontier:

\boxed{ \text{student cannot simply inherit a capability that the teacher never successfully demonstrated} }

(Source: Build a DeepSeek Model (From Scratch))

Correction: Teacher knowledge is not a formal universal upper bound on student benchmark score: base student knowledge, specialization, curation and optimization can exceed a teacher’s measured result. The no-new-information intuition is only conditional on the stipulated data and training setup.

Complete grounded review

5.19.8 The teacher-ceiling intuition

Suppose:

\text{Teacher accuracy}=90\%.

Can a student trained only on that teacher's successful demonstrations be expected to systematically become:

\boxed{99\%}

through ordinary distillation alone?

Not as a consequence of distillation itself.

The training data is derived from teacher behavior.

So distillation is primarily:

\boxed{\text{transfer/compression}}

rather than:

\boxed{\text{frontier discovery}}.

The source explicitly states that advancing beyond the teacher's boundary requires more powerful base models and/or larger-scale RL. (Source: Build a DeepSeek Model (From Scratch))

5.19.9 But there is an important nuance

The source itself later cites research that makes the claim more precise.

It discusses a 2025 study arguing that teacher distillation can improve capability when the teacher introduces knowledge that was absent from the base student. It distinguishes this from simply transferring reasoning patterns that the base model already knows. (Source: Build a DeepSeek Model (From Scratch))

So the stronger conceptual statement is:

\boxed{ \text{Distillation can transfer information the student does not have} }

but:

\boxed{ \text{distillation is not, by itself, a reliable mechanism for pushing beyond the teacher's available knowledge frontier} }.

That is a more precise interpretation.

5.19.10 Three different ceilings

You should now distinguish:

Teacher ceiling

How capable is the teacher?

C_T
Data ceiling

How much of the teacher's useful behavior was successfully captured and curated?

C_D
Student ceiling

How much can the student represent?

C_S

Conceptually:

\boxed{ \text{Student performance} \lesssim \min(C_T,C_D,C_S) }

This is a useful conceptual bound, not a theorem stated in the source.

5.19.11 Where can information be lost?

At least four places:

\boxed{ \text{Teacher} \rightarrow \text{generation} }

Some good behavior may never be sampled.

Then:

\boxed{ \text{generation} \rightarrow \text{filtering} }

Some useful but difficult-to-verify behavior may be rejected.

Then:

\boxed{ \text{dataset} \rightarrow \text{student} }

The student may fail to absorb some patterns.

Finally:

\boxed{ \text{student training} \rightarrow \text{deployment behavior} }

The learned behavior may not always appear under a particular inference strategy.

Thus:

\boxed{ \text{distillation is an information bottleneck at multiple stages} }

5.19.12 Third limitation — Teacher quality matters

Suppose Student A receives:

\text{Teacher A traces}.

Student B receives:

\text{Teacher B traces}.

Even if:

\text{student architecture}

is identical, the final performance can differ substantially.

The source's small Qwen3 experiments show this clearly:

DeepSeek-R1 teacher run:

33.6\%\text{ MATH-500}

at epoch 3.

The Qwen3 235B-A22B teacher run:

45.0\%\text{ MATH-500}

at epoch 1 in the reported experiment.

(Source: Build a Reasoning Model (From Scratch))

So:

\boxed{ \text{better teacher supervision} \rightarrow \text{better potential student} }

5.19.13 Teacher-student compatibility also matters

The source suggests that the Qwen3-teacher run may benefit because:

  • teacher and student are in the same family,
  • tokenizer conventions align,
  • prompting conventions align,
  • response style is more compatible.

This can make the teacher outputs easier for the student to imitate. (Source: Build a Reasoning Model (From Scratch))

So we can think of an additional factor:

\boxed{ \text{teacher quality} + \text{teacher-student compatibility} }

affecting transfer efficiency.

5.19.14 Numerical: teacher improvement

DeepSeek-R1 student result:

33.6\%.

Qwen3-teacher student result:

45.0\%.

Difference:

45.0-33.6 = \boxed{11.4\text{ percentage points}}.

This comparison should not be interpreted as a pure teacher-size experiment, because the setups also differ in teacher family/data characteristics. The source itself attributes part of the difference to family alignment. (Source: Build a Reasoning Model (From Scratch))

5.19.15 Fourth limitation — Dataset coverage

Suppose a student training set contains:

75\%

math + code.

That is excellent for reasoning transfer.

But the student may receive relatively less direct supervision for:

  • creative writing,
  • translation,
  • general conversation,
  • factual QA.

That is why the source deliberately keeps:

178K

general-purpose examples in the larger dataset.

The objective is to avoid creating a narrow specialist. (Source: Build a DeepSeek Model (From Scratch))

5.19.16 Dataset composition is therefore a tradeoff

Increasing reasoning data gives:

\boxed{\text{more reasoning specialization}}

but reducing general data may risk:

\boxed{\text{less general-purpose behavior}}.

So the dataset must solve:

\boxed{ \text{reasoning quality} \leftrightarrow \text{general usability} }

This is an important system-design problem.

5.19.17 Fifth limitation — Long reasoning traces cost compute

The source's dataset averages:

5,355

tokens per sample. (Source: Build a DeepSeek Model (From Scratch))

Long traces mean:

\text{more tokens} \rightarrow \text{more forward/backward computation}.

And standard dense attention has approximately:

O(N^2)

attention complexity.

So:

N\uparrow \Rightarrow \text{cost}\uparrow.

Thus:

\boxed{ \text{better reasoning supervision} }

can conflict with:

\boxed{ \text{training efficiency} }.

5.19.18 Numerical: doubling sequence length

Suppose:

N=2,000.

Now double it:

N'=4,000.

Under the simple dense-attention quadratic model:

\frac{(4000)^2}{(2000)^2} = \left(\frac{4000}{2000}\right)^2 = \boxed{4}.

So the attention-score computation scales by roughly:

\boxed{4\times}

under this simplified complexity model.

This is why reasoning traces cannot simply be made arbitrarily long.

5.19.19 Future direction 1 — Better reasoning teachers

The source says the broad future pattern remains:

\boxed{ \text{stronger reasoning teacher} \rightarrow \text{higher-quality traces} \rightarrow \text{smaller students} }.

This creates a self-reinforcing architecture:

\boxed{ \text{improve teacher} \rightarrow \text{improve data} \rightarrow \text{improve students} }.

5.19.20 Why doesn't this stop at one student?

Because the dataset is reusable.

Once you have:

D_T

the teacher-generated dataset, you can train:

S_1,S_2,S_3,\ldots,S_N.

Thus:

\boxed{ \text{one expensive teacher process} \rightarrow \text{many deployment-oriented models} }

which was one of the major economic benefits we covered earlier. (Source: Build a DeepSeek Model (From Scratch))

5.19.21 Future direction 2 — Inference-time scaling

This is a different idea.

So far we've changed the model during training.

Inference-time scaling asks:

Can we change how much reasoning computation the model uses depending on the problem?

The source points out that not every task deserves the same reasoning budget. Some need only short responses, while difficult tasks benefit from longer multi-step reasoning.

So instead of:

\boxed{ \text{fixed reasoning budget} }

we want:

\boxed{ \text{adaptive reasoning budget} }.

5.19.22 Think of a reasoning budget

Suppose each problem receives a token budget B.

For easy task:

B=100.

For medium task:

B=500.

For hard task:

B=4000.

Then:

\boxed{ B=f(\text{difficulty}) }

rather than:

B=\text{constant}.

This is an example of inference-time scaling.

5.19.23 Why is adaptive inference valuable?

Suppose 80% of tasks are easy.

If every task gets:

4000

reasoning tokens, you waste compute.

Instead:

\boxed{ \text{easy}\rightarrow\text{short} }
\boxed{ \text{hard}\rightarrow\text{long} }

This improves the compute/quality tradeoff.

The source presents this as a future direction at the application layer.

5.19.24 Numerical: fixed vs adaptive budget

Suppose 100 questions:

80\text{ easy}, \quad 20\text{ hard}.

Fixed budget:

4,000

tokens each.

Total:

100\times4000 = \boxed{400,000}

reasoning tokens.

Adaptive budget:

Easy:

500

Hard:

4,000.

Total:

80(500)+20(4000)
=40,000+80,000
=\boxed{120,000}.

So the adaptive strategy uses:

\frac{120,000}{400,000} = 0.30.

That is:

\boxed{70\%}

less reasoning-token budget in this illustrative scenario.

This is a general example, not a source-reported measurement.

5.19.25 Future direction 3 — Process rewards

Earlier in GRPO, we focused mainly on final-answer reward:

\boxed{ R=R_{\text{final correctness}} }.

But suppose a response has:

Step 1: correct
Step 2: correct
Step 3: wrong
Step 4: accidentally correct final answer

A final-answer verifier may give:

R=1.

But the reasoning process contains an error.

The source therefore identifies process rewards as a future direction: evaluate intermediate reasoning rather than only the final answer.

5.19.26 Outcome reward vs process reward

Outcome supervision
\boxed{ \text{Did the final answer match?} }
Process supervision
\boxed{ \text{Were the intermediate steps sound?} }

Conceptually:

R_{\text{total}} = R_{\text{outcome}} + \lambda R_{\text{process}}.

This equation is a general conceptual formulation; the source discusses process rewards but does not prescribe this exact universal equation in the section.

5.19.27 Why process reward could help

Suppose two solutions both produce:

\boxed{42}.

Solution A uses:

\text{correct reasoning} \rightarrow 42.

Solution B contains:

\text{wrong step} \rightarrow \text{compensating mistake} \rightarrow 42.

A final-answer-only reward treats them identically.

A process-aware reward could distinguish:

\boxed{ A>B }

because A uses a more reliable strategy.

This may encourage models to learn robust reasoning rather than lucky trajectories.

The source explicitly identifies this as an area for improvement.

5.19.28 Future direction 4 — Reasoning inside agents

The source then extends reasoning beyond isolated math/code benchmarks.

A reasoning model can become the engine inside an agent that must:

\text{plan} \rightarrow \text{call tools} \rightarrow \text{observe result} \rightarrow \text{recover from failure} \rightarrow \text{continue}.

This is a much harder problem.

Now the model is not simply solving:

q\rightarrow answer.

Instead:

\boxed{ q \rightarrow plan \rightarrow tool \rightarrow observation \rightarrow new plan \rightarrow tool \rightarrow final outcome }

5.19.29 Why does this require new rewards?

Math correctness alone cannot measure:

\text{tool selection}.

It also cannot measure:

\text{whether retrieval was useful}.

Nor:

\text{whether the agent recovered from an API failure}.

The source therefore describes the need for richer reward signals such as:

  • successful tool use,
  • information retrieval,
  • policy compliance,
  • broader task success.

5.19.30 Multi-reward training

Instead of:

R=R_{\text{math}}

an agent might need:

\boxed{ R= w_1R_{\text{task}} + w_2R_{\text{tool}} + w_3R_{\text{retrieval}} + w_4R_{\text{policy}} }

This is a conceptual representation of the source's multi-reward training direction.

The challenge is that the objectives may conflict.

For example:

\text{fast response}

versus:

\text{more careful verification}.

Or:

\text{tool usage}

versus:

\text{cost}.

5.19.31 Distillation still matters in agents

Why?

Because agent reasoning can become expensive.

A huge teacher might be excellent at:

\text{planning} + \text{tool calling} + \text{recovery} + \text{long workflows}.

But deploying the huge teacher for every interaction may be costly.

So again:

\boxed{ \text{strong agentic teacher} \rightarrow \text{rich traces} \rightarrow \text{smaller agentic student} }

is attractive.

The source explicitly says distillation is likely to remain important for transferring richer behaviors into smaller, easier-to-deploy systems.

5.19.32 The future combined recipe

Now the entire book's strategy becomes:

\boxed{ \text{Pretraining} }

↓

\boxed{ \text{SFT} }

↓

\boxed{ \text{RL / GRPO} }

↓

\boxed{ \text{strong teacher} }

↓

\boxed{ \text{distillation} }

↓

\boxed{ \text{student RLVR} }

↓

\boxed{ \text{inference-time scaling} }

This is not necessarily one fixed production recipe; the source proposes combining these methods as a practical next step.

5.19.33 Why combine distillation and RL?

Because they solve different problems.

Distillation

Good at:

\boxed{ \text{transferring known successful behavior} }
RL

Good at:

\boxed{ \text{searching / optimizing behavior under reward} }

So:

\boxed{ \text{Distill first} \rightarrow \text{RL refine later} }

can be more attractive than asking a small model to discover everything from scratch.

The source explicitly proposes this combination as a practical next experiment.

5.19.34 Why this can be better than RL-from-scratch

Suppose a small model starts with:

\text{baseline reasoning ability}=20.

Distillation gives it:

\text{strong reasoning initialization}=70.

Then RL could potentially optimize it further:

70\rightarrow75\rightarrow78.

The exact numbers are illustrative.

The idea is:

\boxed{ \text{distillation provides a better starting policy} }

and:

\boxed{ \text{RL performs further optimization/exploration} }.

5.19.35 This also explains the earlier 32B result

We previously saw:

\text{32B distilled}=72.6\%

versus:

\text{32B RL-only}=47.0\%.

(Source: Build a DeepSeek Model (From Scratch))

That experiment strongly supports the idea that training initialization and supervision matter enormously at this scale.

5.19.36 But distillation is not “better than RL” universally

This is important.

The source explicitly says:

\boxed{ \text{distillation and RL complement each other} }

rather than declaring one universally superior. (Source: Build a DeepSeek Model (From Scratch))

Use distillation when you have:

\boxed{\text{strong teacher behavior to transfer}}

Use RL when you need:

\boxed{\text{further optimization or potentially new behavior}}

and the reward signal is reliable.

5.19.37 A final conceptual map

Think of the three techniques as three different operations:

\boxed{\textbf{RL}}

Discover / strengthen

\downarrow
\boxed{\textbf{Distillation}}

Transfer / compress

\downarrow
\boxed{\textbf{Inference-time scaling}}

Spend more or less computation per problem

These operate at different stages.

5.19.38 Training-time vs inference-time

This is a very important exam distinction.

Training-time

Parameters change:

\boxed{ \theta\rightarrow\theta' }

Examples:

  • SFT,
  • RL,
  • distillation.
Inference-time

Parameters remain fixed:

\boxed{ \theta=\text{constant} }

but computation changes.

Examples:

  • self-consistency,
  • longer reasoning budgets,
  • self-refinement.

Therefore:

\boxed{ \text{distillation}=training-time }

while:

\boxed{ \text{inference scaling}=deployment-time }.

5.19.39 Numerical: training vs inference

Suppose a model has:

10B

parameters.

During inference-time scaling, asking it to reason for:

1000

tokens instead of:

500

tokens does not change the:

10B

parameters.

So:

\boxed{ \text{model size unchanged} }

but:

\boxed{ \text{compute per query increases} }.

This distinction is fundamental.

5.19.42 Five exam questions you should be able to answer

1. Why can't a 1.5B model absorb everything from a 671B teacher?

Because the student's finite capacity creates a bottleneck; different domains have different compression difficulty. The source demonstrates this through the large math-versus-coding gap. (Source: Build a DeepSeek Model (From Scratch))

2. Why can't distillation alone guarantee a capability beyond the teacher?

Because the distilled dataset is generated from teacher behavior, and the source frames distillation as transferring existing capabilities rather than being the primary mechanism for pushing the reasoning frontier. (Source: Build a DeepSeek Model (From Scratch))

3. Why does the base model matter?

Because the student already has pretrained representations before distillation. The compatibility of tokenizer, prompting style, and pretrained capabilities can affect how easily it absorbs teacher behavior. (Source: Build a Reasoning Model (From Scratch))

4. Why are process rewards interesting?

Because final-answer rewards can treat a correct final answer as equally good even when intermediate reasoning is unreliable. Process rewards attempt to evaluate intermediate reasoning quality.

5. Why combine distillation with RL?

Because distillation can provide successful teacher behavior efficiently, while RL can subsequently optimize or explore behavior under a reward signal. The source explicitly recommends combining the techniques experimentally.

5.19.43 The final lesson of the entire distillation chapter

The source's final message can be reduced to:

\boxed{ \text{Scale creates the frontier} }

but:

\boxed{ \text{Distillation spreads the frontier} }.

A huge teacher can be expensive to train and deploy.

A distilled student can take some of the teacher's successful behavior and put it into a much smaller model.

But three things limit the result:

\boxed{ \text{student capacity} }
\boxed{ \text{teacher/data quality} }
\boxed{ \text{teacher knowledge frontier} }.

And future reasoning systems increasingly combine:

\boxed{ \text{RL} + \text{distillation} + \text{adaptive inference} + \text{process-aware rewards} + \text{agentic tool use} }.
