Motivation

Motivation: let learned compatibility and transmitted content use different projections. Prerequisites: dot products, row-oriented matrix multiplication, stable softmax and dimensions. The database analogy describes roles; it does not establish literal semantic labels or explain a trained model causally.

Notation and units

  • A_{ij}=\operatorname{softmax}_{j}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)_{ij}
  • O=AV,\qquad O_i=\sum_j A_{ij}V_j

Assumptions

  • X=[T,d], W_Q/W_K=[d,d_k], W_V=[d,d_v]; Q/K have matching head width, while d_v can differ. The equal-width multi-head companion specializes to d_k=d_v=d/h. Printed Raschka values are rounded; source-seeded PyTorch parameters have not been regenerated in this environment.

Step-by-step derivation

  1. Project Q=XW_Q, K=XW_K and V=XW_V. Entry S_ij is the contraction Σ_c Q_ic K_jc, giving [T,T] scores. The query index is the row; the key index is the column.
  2. With q=[1,2], k1=[1,0], k2=[0,1], the unscaled scores are [1,2]. After division by √2, normalize only over the permitted keys. Multiply those weights by values [10,0] and [0,20] to get a content mixture.
  3. The book shows the second query [0.4306,1.4551] on physical page 168, scores [1.2705,1.8524,1.8111,1.0795,0.5577,1.5440] on page 172 and scaled weights on page 174. Normalizing these rounded scores agrees with the printed weights within 0.00006. It is a consistency check from rounded inputs, not a full-precision regeneration of the source initialization.
  4. For a complete fully specified application, inspect the decoder trace: each independent layer prints Q/K/V, scaled scores, causal weights, concatenated heads and output. The scalar-loop reference reconstructs the complete logits without calling these forward functions.
  5. Backpropagate through the output projection, AV, row softmax and QKᵀ. Accumulate Q, K and V input gradients before returning to normalization. The finite-difference checks cover all projections in both blocks.

    Mastery answers and retained exercise context

    1. Q1: Q has shape [10,64].
    2. Q2: QKᵀ has shape [10,10].
    3. Q3: Every one of n query rows has a compatibility score for every one of n key rows.
    4. Q4: A query supplies the matching vector for the receiving position; a key supplies the matching vector for a candidate source position.
    5. Q5: V supplies transmitted content; Q/K determine the coefficients used to combine it.
    6. Q6: W_Q is a persistent learned parameter tensor; A_ij is a coefficient computed for the current input and mask.
    7. Q7: Learning projections lets loss gradients adjust the compatibility and content spaces.
    8. Q8: k2, since its score is 2 versus 1 for k1.
    9. Q9: QKᵀ computes every query-key dot product in one matrix operation.
    10. Q10: X → Q/K/V projections → QKᵀ/√d_k → add mask → row softmax A → AV (then concatenate/project for MHA).

    Edge cases and remaining gaps

    • A high raw score is relative to the other permitted scores; it is not a probability or semantic proof. Softmax probabilities need their normalization set.
    • In a causal decoder, future keys are masked before softmax. The book example quoted here is an unmasked attention illustration; do not transfer its six-key weights directly to a causal second-token query.
    • Scaling by √d_k controls score variance under suitable distributional assumptions; it does not guarantee a particular gradient magnitude for arbitrary trained vectors.
    • All-masked rows have no defined categorical distribution and are rejected. Stable max subtraction prevents overflow on finite logits; it does not make NaNs valid.
    • Attention weights are input-dependent coefficients, not generally faithful standalone explanations. Q/K/V role language remains an analogy.

    Queries and keys determine weights; values supply the information combined by those weights. Separate projections let these roles be learned differently.

    2. Check that Q and K share a score dimension.
    3. Keep values separate from attention probabilities.

    Step 1.5 — Q, K, V: Why Are There Three Different Vectors?

    Plan node: I1 · chat order #12

    We are now entering the core of the Transformer.

    So far we have:

    \boxed{ \text{text} \rightarrow \text{tokens} \rightarrow \text{IDs} \rightarrow \text{embeddings} \rightarrow \text{position} \rightarrow \text{residual stream }X }

    Now we need the mechanism that lets one token decide:

    Which other tokens should I use, and how much information should I take from them?

    That mechanism is self-attention.

    The first step of self-attention is:

    \boxed{ Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V }

    Your Transformer slides define these three projections and give the intuition:

    • Query: what this token is looking for
    • Key: what this token advertises about itself
    • Value: what this token hands over if attended to.

    Raschka's book derives the same construction using three trainable matrices and then computes attention scores from query-key dot products.

    1.5.1 First Understand the Goal

    Suppose we have:

    The animal didn't cross the road because it was tired.

    When processing:

    it

    the model wants to determine which previous tokens are relevant.

    Conceptually:

                     "it"
                  │
                  │
           Which tokens matter?
          /      |       |      \
       animal   road    tired   the
         ↑       ↑
       maybe    maybe

    We need a numerical mechanism for doing this.

    Our earlier foundation already gave us the key mathematical operation:

    \boxed{x^Ty}

    the dot product.

    The idea is:

    Compare one vector against other vectors using dot products.

    But we need more than the raw token embedding.

    That is why we construct Q, K, and V.

    1.5.2 Start With One Token

    Suppose a token's current representation is:

    x_i\in\mathbb R^d

    We create three different versions:

    q_i=x_iW_Q
    k_i=x_iW_K
    v_i=x_iW_V

    So the same underlying representation x_i is transformed in three different ways.

    Think:

                     x_i
              /   |   \
             /    |    \
           W_Q   W_K   W_V
            ↓     ↓     ↓
           q_i   k_i   v_i

    1.5.3 Why Not Just Use X Directly?

    This is the most important conceptual question of this step.

    Suppose we used:

    X X^T

    directly.

    That would say:

    similarity is determined by comparing the original token representations in exactly the same space.

    But attention needs two different roles:

    Role 1: Matching

    We need to ask:

    "Does this token's current need match that token's available information?"

    That requires a query space and a key space.

    Role 2: Information transfer

    After deciding which token matters, we need to decide:

    "What information should I actually take from it?"

    That is the value.

    Thus:

    \boxed{ Q,K\text{ determine relevance} }

    while:

    \boxed{ V\text{ carries the information} }

    That separation is the fundamental reason for the three projections.

    Raschka's source explicitly explains that the trainable matrices project input embeddings into query, key, and value vectors and that keys/queries are used for attention scores while values are weighted to produce the context vector.

    1.5.4 The Database Analogy

    Your source gives a very useful analogy.

    Imagine a database:

    Query → search
Key   → matching/index
Value → retrieved content

    Suppose you search:

    "students interested in AI"

    The query describes what you're looking for.

    Each database record has a key describing how it can be matched.

    Once a record matches, you retrieve its value.

    Attention does something mathematically analogous:

    \boxed{ \text{Query} \rightarrow \text{match Keys} \rightarrow \text{retrieve Values} }

    Raschka explicitly uses this query/key/value analogy from information retrieval and databases.

    1.5.5 Important Warning About This Analogy

    The database analogy helps intuition, but don't take it literally.

    A Transformer does not have a literal database lookup table where each key corresponds to one fixed semantic label.

    Instead, the model learns continuous vectors and compares them through dot products.

    So:

    q_i^Tk_j

    is a learned numerical compatibility score.

    The words:

    "what it is looking for"

    and:

    "what it advertises"

    are intuition, not formal definitions.

    Formally:

    \boxed{ Q=XW_Q,\quad K=XW_K,\quad V=XW_V }

    and:

    \boxed{ S=QK^T }

    1.5.6 Shapes First

    Let:

    X\in\mathbb R^{n\times d}

    where:

    • n = number of tokens
    • d = model width

    Choose:

    W_Q\in\mathbb R^{d\times d_k}
    W_K\in\mathbb R^{d\times d_k}
    W_V\in\mathbb R^{d\times d_v}

    Then:

    Q=XW_Q

    has shape:

    (n\times d)(d\times d_k)

    so:

    \boxed{Q\in\mathbb R^{n\times d_k}}

    Similarly:

    \boxed{K\in\mathbb R^{n\times d_k}}

    and:

    \boxed{V\in\mathbb R^{n\times d_v}}

    These are the shapes shown in your Transformer slides.

    1.5.7 Why Can d_k Be Different From d?

    Because we may want the attention mechanism to work in a smaller space.

    For example:

    d=768

    but a head may use:

    d_k=64

    Then:

    768\rightarrow64

    for queries and keys.

    Similarly values may have:

    d_v=64

    This reduces the size of the individual attention computation.

    In multi-head attention, we use several such smaller spaces.

    We will get there later.

    1.5.8 The First Really Important Equation

    Once we have:

    Q

    and:

    K

    we compare them.

    For query q_i and key k_j:

    \boxed{ s_{ij}=q_i^Tk_j }

    This is simply a dot product.

    Interpretation:

    \boxed{ \text{How compatible is query }i\text{ with key }j? }

    If:

    q_i^Tk_j

    is large, they are strongly aligned in the learned attention space.

    If it's small or negative, they are less aligned.

    1.5.9 From One Dot Product to the Whole Matrix

    Suppose:

    Q= \begin{bmatrix} q_1\\ q_2\\ q_3 \end{bmatrix}

    and:

    K= \begin{bmatrix} k_1\\ k_2\\ k_3 \end{bmatrix}

    Then:

    QK^T = \begin{bmatrix} q_1^Tk_1&q_1^Tk_2&q_1^Tk_3\\ q_2^Tk_1&q_2^Tk_2&q_2^Tk_3\\ q_3^Tk_1&q_3^Tk_2&q_3^Tk_3 \end{bmatrix}

    Therefore:

    \boxed{ S=QK^T }

    contains every query-key comparison.

    Shape:

    (n\times d_k)(d_k\times n)

    giving:

    \boxed{ S\in\mathbb R^{n\times n} }

    This is why we emphasized matrix multiplication in Step 0.1.

    1.5.10 What Does One Row Mean?

    This is extremely important.

    Take row i:

    S_{i,:}

    It contains:

    [q_i^Tk_1,\;q_i^Tk_2,\ldots,q_i^Tk_n]

    So row i answers:

    For token i, how well does my query match every token's key?

    For example:

    S_{2,:} = [1.2,\;2.8,\;0.4,\;1.7]

    means token 2 has strongest raw compatibility with token 2 itself, then token 4, then token 1, then token 3.

    But these are still scores, not probabilities.

    We will convert them to attention weights in the next step.

    1.5.11 Why the Value Vector Is Separate

    This is one of the most subtle ideas.

    Suppose:

    q_i^Tk_j=10

    That tells us:

    token j is highly relevant to query i.

    But it does not tell us what information token j should contribute.

    That's what:

    v_j

    contains.

    Therefore the architecture separates:

    \boxed{ \text{matching} \quad\text{from}\quad \text{content transfer} }

    Mathematically:

    \text{matching} = q_i^Tk_j

    then later:

    \text{information received} = a_{ij}v_j

    and finally:

    o_i=\sum_j a_{ij}v_j

    This separation is the conceptual heart of attention.

    1.5.17 The Difference Between Parameter Weights and Attention Weights

    This distinction is so important that your book gives it its own section.

    Parameter weights
    W_Q,W_K,W_V

    These are learned model parameters.

    They are updated during training.

    Attention weights

    Later we compute:

    A_{ij}

    These depend on the current input.

    They change from context to context.

    Therefore:

    \boxed{ W_Q,W_K,W_V = \text{learned parameters} }

    while:

    \boxed{ A = \text{dynamic, input-dependent weights} }

    Raschka explicitly warns not to confuse these two meanings of "weight."

    1.5.18 Why Are the Projection Matrices Trainable?

    Suppose we used fixed projections.

    Then:

    Q=XW_Q

    would always create the same type of query transformation.

    But we want the model to learn what dimensions are useful for matching.

    During training, the loss produces gradients such as:

    \frac{\partial L}{\partial W_Q}
    \frac{\partial L}{\partial W_K}
    \frac{\partial L}{\partial W_V}

    and these are updated:

    W_Q \leftarrow W_Q-\eta\frac{\partial L}{\partial W_Q}

    and similarly for W_K,W_V.

    Thus the model learns:

    What should a query look like?

    What should a key look like?

    What information should a value carry?

    That is why attention becomes useful through training.

    Raschka explicitly says these matrices are trained so the attention module can learn to produce useful context vectors.

    1.5.19 Why Three Different Matrices Instead of One?

    Suppose we used:

    Q=K=V=X

    Then one representation would simultaneously have to serve three purposes:

    1. search query,
    2. search key,
    3. transmitted information.

    That's unnecessarily restrictive.

    Instead:

    Q=XW_Q
    K=XW_K
    V=XW_V

    allows three different learned transformations.

    This gives the model much more flexibility.

    For example, one dimension of Q might learn to represent something useful for determining:

    "Am I looking for a subject?"

    while a dimension of K may learn to represent:

    "I can serve as a subject."

    Meanwhile V can encode the content that should actually be transmitted.

    Again, this is an intuition about what the learned spaces can represent, not a guarantee that individual dimensions correspond to such human labels.

    1.5.20 A Tiny Hand Example

    Suppose:

    q=[1,2]

    and two keys are:

    k_1=[1,0]
    k_2=[0,1]

    Compute:

    q^Tk_1 = 1(1)+2(0) = 1

    and:

    q^Tk_2 = 1(0)+2(1) = 2

    Therefore:

    k_2

    matches the query more strongly.

    Now suppose values are:

    v_1=[10,0]
    v_2=[0,20]

    Later, after converting scores into attention weights, the model will take a weighted combination of these values.

    Notice the separation:

    Q × K  → decide relevance

relevance × V → transfer information

    That is the entire basic mechanism in one picture.

    1.5.21 Matrix-Level View

    For the entire sequence:

    Q=XW_Q
    K=XW_K
    V=XW_V

    Then:

    S=QK^T

    So:

    \boxed{ X \rightarrow (Q,K,V) \rightarrow S }

    Shapes:

    X:n\times d
    Q:n\times d_k
    K:n\times d_k
    V:n\times d_v
    S:n\times n

    This is exactly the shape checklist included in your mathematical Transformer cheat sheet. (Source: Step1_Transformers_Mathematical_Cheatsheet)

    1.5.22 Why Is the Score Matrix n\times n?

    Because every query compares to every key.

    If:

    n=4

    then:

              Keys
         k1 k2 k3 k4
       ┌──────────────┐
q1     │ •  •  •  •   │
q2     │ •  •  •  •   │
q3     │ •  •  •  •   │
q4     │ •  •  •  •   │
       └──────────────┘

    There are:

    4\times4=16

    query-key comparisons.

    For a sequence of length:

    n=1000

    there are:

    1,000,000

    pairwise scores in one attention head before considering batching and heads.

    This n^2 behavior will later become central to the attention complexity problem and motivates efficient-attention techniques.

    1.5.23 Self-Attention vs Cross-Attention

    At this stage, we're discussing self-attention.

    Why?

    Because:

    Q,K,V

    all come from the same input sequence:

    X

    That is:

    Q=XW_Q,\quad K=XW_K,\quad V=XW_V

    Therefore:

    \boxed{\text{self-attention}}

    means:

    queries, keys, and values are derived from the same sequence.

    In cross-attention, the query source and key/value source differ.

    We will not divert into that yet because your current course is centered on decoder-only self-attention.

    1.5.24 What We Have NOT Done Yet

    We've only reached:

    \boxed{ Q,K,V }

    and:

    \boxed{ S=QK^T }

    The scores are still raw.

    For example:

    [1.2705,1.8524,1.8111,\ldots]

    But we want something like:

    [0.15,0.23,0.22,\ldots]

    that can act as normalized attention weights.

    Therefore we still need:

    \boxed{ \frac{QK^T}{\sqrt{d_k}} }

    then:

    \boxed{ \operatorname{softmax} }

    and eventually:

    \boxed{ AV }

    And because we are building a decoder-only language model, we also need the causal mask.

    1.5.25 The Complete Attention Pipeline

    Now you can see the entire structure emerging:

    \boxed{ X }

    ↓

    \boxed{ Q=XW_Q,\quad K=XW_K,\quad V=XW_V }

    ↓

    \boxed{ S=QK^T }

    ↓

    \boxed{ \tilde S=\frac{S}{\sqrt{d_k}} }

    ↓

    \boxed{ \tilde S+M }

    ↓

    \boxed{ A=\operatorname{softmax}(\tilde S+M) }

    ↓

    \boxed{ O=AV }

    This is the equation we have been building toward from the beginning.

    1.5.27 The Deepest Intuition to Keep

    Forget the terminology for a moment.

    Self-attention is essentially:

    Ask → Match → Retrieve → Mix

    Ask
    q_i

    What does the current token need?

    Match
    q_i^Tk_j

    Which tokens are relevant?

    Retrieve
    v_j

    What information does each relevant token provide?

    Mix
    o_i=\sum_j a_{ij}v_j

    Combine the useful information.

    So:

    \boxed{ Q=\text{asking} }
    \boxed{ K=\text{matching} }
    \boxed{ V=\text{information} }

    1.5.28 Connect It Back to the Residual Stream

    Remember Step 1.4.

    Attention does not usually replace the residual stream.

    It creates an update:

    O=\operatorname{Attention}(X)

    then:

    \boxed{ X_{\text{new}} = X+O }

    So the flow is:

    Residual stream X
       ↓
   Q, K, V
       ↓
attention
       ↓
   update O
       ↓
X + O
       ↓
new residual stream

    This is exactly the architecture described in your slides.
