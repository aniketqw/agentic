Motivation

Separate floating-point format range, rounding and scale metadata from raw payload memory savings.

Prerequisites

  • Linear algebra and chain rule
  • Binary floating-point normal/subnormal encodings
  • Quantization scale convention
  • Tensor shape and loss normalization

Notation and units

  • X:[N, K], W:[K, O], Y=XW:[N, O] row convention
  • s_q: fmax/amax quantization multiplier; s_d:1/s_q reconstruction multiplier
  • Nc:128 reduction/group channels in cited design
  • G: dL/dY; dX=GW^T; dW=X^TG

Assumptions

  • All toy numerical inputs and normalization conventions are stated explicitly.
  • The teaching companion requires NumPy and runs on CPU; it claims no production backend execution.
  • Finite saturating E4M3FN RTNE is simulated; tensor arithmetic uses NumPy higher precision.

Step-by-step derivation

  1. A normal binary value is(-1)^sign*(1+mantissa/2^m)*2^(exponent-bias); subnormal values replace the implicit1 with 0 and use minimum exponent. Special encodings are format-specific.
  2. E4M3FN hasfinite maximum 448 and minimum positive subnormal 2^-9; E5M2 hasmaximum 57344 and minimum subnormal 2^-16. E4M3FNUZ differs and must not be conflated.
  3. Compute current amax, choose multiplier 448/amax, cast to nearest representable E4M3FN, then reconstruct bydivision. Handle zero amax, NaN, Inf and saturation explicitly.
  4. Weights-only payload memory P*b/8 excludes master copies, gradients, optimizer states, activations, scales and allocator overhead.

Continuation · checked fixture Q05 — FP8 format variants and finite extrema

Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

Bit-field counts alone do not define overflow, NaN and finite-range behavior.

Prerequisites: Normal, subnormal and special float values

Notation and assumptions

Explicit positive finite enumeration: E4M3FN bias7, exponent15/mantissa7 reserved NaN; E5M2 IEEE-style exponent31 reserved. Signed values mirror finite positive values.

Derivation and mechanism

  1. Enumerate exponent/mantissa codes using the declared normal/subnormal rules.
  2. Exclude variant-specific special encodings.
  3. Read maximum finite and smallest positive subnormal from the remaining set.

Worked example

E4M3FN maximum=(1+6/8)2^8=448; smallest subnormal=2^-9. E5M2 maximum=(1+3/4)2^15=57344; smallest subnormal=2^-16. These are not E4M3FNUZ constants.

Limitations

  • Enumeration checks representation values, not a GPU matmul or hardware rounding kernel.
  • Scale factors, accumulation and master weights determine training behavior.

Connections to later concepts

  • Q01 scales tensor magnitudes into a representable numeric range; accumulation precision is a separate training contract.

Step 5.49 — FP8 Quantization

Plan node: A4 · chat order #95

↩ Back to main text: Step 3.5 — Quantization → QLoRA · Step 3.6B — GGUF, K-Quants, QAT, BitNet, and 1.58-bit LLMs

We now move to the second major part of Chapter 5.

So far:

\boxed{\text{MLA}} \rightarrow \text{reduce KV-cache memory}
\boxed{\text{MoE}} \rightarrow \text{increase parameter capacity without activating everything}
\boxed{\text{MTP}} \rightarrow \text{richer future-prediction training signal}.

Now we ask a different question:

How can we perform the enormous number of numerical operations required to train such a model more efficiently?

The source's answer is:

\boxed{\text{FP8 quantization}}

The source frames quantization as the mechanism for trading a small amount of numerical precision for substantial memory and computational efficiency. (Source: Build a DeepSeek Model (From Scratch))

5.49.1 What is quantization?

Start from the simplest possible fact:

A neural network is ultimately manipulating numbers.

For example, a weight matrix may contain:

W= \begin{bmatrix} 0.13 & -0.72\\ 1.42 & 0.003 \end{bmatrix}.

An activation matrix might contain:

X= \begin{bmatrix} 0.81 & -1.24\\ 0.002 & 2.31 \end{bmatrix}.

The computer has to represent every one of those numbers using some numerical format.

The source begins with:

\boxed{\text{FP32}}

as its high-precision baseline. (Source: Build a DeepSeek Model (From Scratch))

5.49.2 FP32 means 32 bits per number

A floating-point number is represented using:

\boxed{\text{sign + exponent + mantissa}}.

For FP32, the source gives:

\boxed{ 1\text{ sign bit} + 8\text{ exponent bits} + 23\text{ mantissa bits} = 32\text{ bits}. }

(Source: Build a DeepSeek Model (From Scratch))

Conceptually:

FP32
┌─────┬──────────┬───────────────────────┐
│ S   │ Exponent │      Mantissa         │
│ 1   │    8     │          23           │
└─────┴──────────┴───────────────────────┘

5.49.3 What do the three pieces mean?

This is fundamental.

Sign

One bit determines whether the number is positive or negative.

\boxed{ S=0\Rightarrow +,\qquad S=1\Rightarrow - }
Exponent

The exponent controls the scale or dynamic range.

It answers roughly:

How large or how small can this number be?

More exponent bits:

\boxed{\text{larger dynamic range}}

The source explicitly describes the exponent as controlling magnitude and dynamic range. (Source: Build a DeepSeek Model (From Scratch))

Mantissa

The mantissa/significand controls the precision.

It answers:

How many meaningful digits can I represent?

More mantissa bits:

\boxed{\text{greater precision}}

and therefore smaller gaps between nearby representable values.

The source explicitly makes this distinction between exponent and mantissa. (Source: Build a DeepSeek Model (From Scratch))

5.49.4 Very important distinction

Memorize this:

\boxed{ \text{Exponent bits}\rightarrow\text{range} }
\boxed{ \text{Mantissa bits}\rightarrow\text{precision} }

So when a format redistributes bits:

  • more exponent bits → broader numerical range,
  • more mantissa bits → finer numerical precision.

This single distinction will explain almost all of the FP8 design decisions later.

5.49.5 Why not always use FP32?

Because large models contain an enormous number of values.

Suppose:

70\text{ billion parameters}.

At FP32:

70\times10^9\times4\text{ bytes}

because:

32\text{ bits}=4\text{ bytes}.

Therefore:

\boxed{280\text{ GB}}.

This is exactly the kind of memory calculation shown in the source for a 70B model. (Source: Build a DeepSeek Model (From Scratch))

5.49.6 What happens at FP16?

FP16 uses:

16\text{ bits}=2\text{ bytes}

per value.

So for 70B parameters:

70\times10^9\times2 = 140\text{ GB}.

Thus:

\boxed{ 280\text{ GB}\rightarrow140\text{ GB}. }

The source uses precisely this comparison. (Source: Build a DeepSeek Model (From Scratch))

5.49.7 General memory formula

For P parameters and b bits per parameter:

\boxed{ M=P\frac{b}{8} }

bytes.

Or in GB, approximately:

\boxed{ M_{\text{GB}} = \frac{P\times b}{8\times10^9}. }

This assumes decimal GB and ignores additional memory such as gradients, optimizer states, activations, fragmentation, etc.

For just the weight storage calculation, this is the important formula.

5.49.8 Exam numerical

A model has:

P=10^{10}

parameters.

How much memory do the weights require at FP32?

Each parameter:

4\text{ bytes}.

Therefore:

10^{10}\times4 = 4\times10^{10}\text{ bytes}.

Approximately:

\boxed{40\text{ GB}}.

At FP16:

10^{10}\times2 = 2\times10^{10}

bytes:

\boxed{20\text{ GB}}.

So merely changing numerical representation halves the raw weight-storage requirement.

5.49.9 This is the central quantization trade-off

Quantization means reducing the numerical precision/bit-width.

Conceptually:

\boxed{ FP32\rightarrow FP16\rightarrow FP8 }

means:

\boxed{ 32\rightarrow16\rightarrow8\text{ bits per number}. }

But we are giving something up.

We are reducing the set of numbers that can be represented accurately.

The source uses the analogy of an image whose color palette is reduced from many colors to only a small number: individual details can be lost, but the overall structure can remain recognizable. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{less precision} \rightarrow \text{less memory + potentially faster computation}. }

5.49.10 Why does lower precision help computation?

Suppose the GPU must perform:

Y=WX

for enormous matrices.

The arithmetic itself is only part of the cost.

The system also has to:

\boxed{ \text{move data} \rightarrow \text{store data} \rightarrow \text{load data} \rightarrow \text{compute}. }

Smaller numerical representations mean less data movement.

The source explicitly identifies faster training/inference and reduced memory as two major benefits of lower-precision parameters. (Source: Build a DeepSeek Model (From Scratch))

5.49.11 FP16 is not the same as FP8

This is important.

FP16:

\boxed{ 16\text{ bits} }

FP8:

\boxed{ 8\text{ bits} }

So FP8 cuts the per-value storage in half again:

2\text{ bytes}\rightarrow1\text{ byte}.

Compared with FP32:

4\text{ bytes}\rightarrow1\text{ byte}.

Therefore the raw representation is:

\boxed{ 4\times\text{ smaller than FP32}. }

But the numerical precision/range is also much more constrained.

5.49.12 Compare the common formats

The source gives the following configurations:

Format Sign Exponent Mantissa Total
FP32 1 8 23 32
FP16 1 5 10 16
BF16 1 8 7 16
INT8 1 — 7-bit integer value 8
FP8 E4M3 1 4 3 8
FP8 E5M2 1 5 2 8

The source presents these progressively as the numerical foundations for the FP8 discussion. (Source: Build a DeepSeek Model (From Scratch))

5.49.13 FP16

FP16:

\boxed{ 1+5+10=16. }

Compared with FP32:

1+8+23=32.

So both range and precision are reduced.

The source notes that FP16 can suffer from:

\boxed{\text{overflow}}

and:

\boxed{\text{underflow}}.

(Source: Build a DeepSeek Model (From Scratch))

5.49.14 What is overflow?

Suppose the format can represent values only up to some maximum:

x_{\max}.

If a calculation produces:

x>x_{\max},

the number cannot be represented normally in that format.

Conceptually:

\boxed{ \text{too large}\rightarrow\text{overflow}. }

5.49.15 What is underflow?

At the opposite extreme, suppose the format cannot preserve sufficiently small values.

Then:

|x|

becomes so small relative to the format that numerical detail is lost.

Conceptually:

\boxed{ \text{too small}\rightarrow\text{underflow}. }

These two problems become especially important when moving toward FP8.

5.49.16 BF16: why is it different?

BF16 also uses 16 bits, but the distribution is:

\boxed{ 1+8+7=16. }

Notice:

\boxed{ \text{same 8 exponent bits as FP32}. }

but only:

\boxed{ 7\text{ mantissa bits}. }

Therefore BF16 sacrifices precision much more aggressively than FP16, but retains the broad dynamic range of FP32.

The source describes BF16 as particularly useful for training because its large exponent range makes it resistant to overflow. (Source: Build a DeepSeek Model (From Scratch))

5.49.17 This gives us a beautiful comparison

FP16
\boxed{ 5\text{ exponent},10\text{ mantissa} }

More precision than BF16, less range.

BF16
\boxed{ 8\text{ exponent},7\text{ mantissa} }

More range than FP16, less precision.

Thus:

\boxed{ FP16\leftrightarrow BF16 = \text{range vs precision trade-off}. }

5.49.18 Numerical-format mental model

Think of a ruler.

Exponent

Determines how long the ruler is:

\boxed{\text{range}}
Mantissa

Determines how finely marked the ruler is:

\boxed{\text{precision}}

You can have:

  • a very long ruler with coarse marks,
  • a short ruler with extremely fine marks.

That is essentially the trade-off between exponent and mantissa allocation.

5.49.19 INT8 is different

INT8 is not floating-point.

It has:

\boxed{ 8\text{ bits} }

but no exponent/mantissa structure.

The source describes signed INT8 as having a range of approximately:

\boxed{-127\text{ to }127}.

(Source: Build a DeepSeek Model (From Scratch))

This means INT8 has an extremely limited direct numerical range compared with floating-point formats.

5.49.20 Why is FP8 more attractive?

FP8 retains:

\boxed{ \text{sign + exponent + mantissa}. }

So even though it uses only 8 bits, it retains floating-point flexibility.

The source specifically focuses on:

\boxed{\text{E4M3}}

with:

\boxed{ 1\text{ sign}+4\text{ exponent}+3\text{ mantissa}=8. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.21 Why doesn't FP8 alone solve everything?

Because 8 bits are extremely restrictive.

Suppose a tensor contains:

[0.001,\;0.01,\;0.1,\;1,\;10,\;1000].

The values span many orders of magnitude.

Trying to represent all of them directly in a narrow low-precision format can cause:

\boxed{ \text{overflow} }

for large values or:

\boxed{ \text{loss of precision} }

for small values.

This is why the next concept is absolutely fundamental:

\boxed{\text{scaling}}.

5.49.22 Scaling: the key prerequisite

The source's basic quantization mechanism is:

\boxed{ \text{find range} \rightarrow \text{scale} \rightarrow \text{quantize} \rightarrow \text{dequantize}. }

The purpose is to map a high-precision tensor into the representable range of the low-precision format while preserving relative relationships. (Source: Build a DeepSeek Model (From Scratch))

5.49.23 Step 1 — Find the maximum absolute value

Suppose:

x=[2.0,\;3.0,\;-7.59,\;10.8].

Find:

\alpha=\max_i|x_i|.

Therefore:

\boxed{\alpha=10.8}.

The source uses exactly 10.8 as its illustrative maximum. (Source: Build a DeepSeek Model (From Scratch))

5.49.24 Why absolute value?

Because we care about both positive and negative extremes.

For:

x=[-10,2,5],

the maximum value is:

5,

but the maximum absolute value is:

\boxed{10}.

For symmetric signed ranges such as:

[-127,127],

the quantity that determines scaling is:

\boxed{ \max |x|. }

5.49.25 Step 2 — Calculate the scaling factor

For the INT8 example:

q_{\max}=127.

Original maximum:

\alpha=10.8.

So the source computes:

\boxed{ s=\frac{127}{10.8}. }

Numerically:

s\approx11.7593.

(Source: Build a DeepSeek Model (From Scratch))

This tells us how much to stretch the original values to fit the target integer range.

5.49.26 Step 3 — Quantize

Take:

x=-7.59.

Multiply by:

s=\frac{127}{10.8}.

So:

-7.59\times\frac{127}{10.8}.

Approximately:

-89.2.

Round:

\boxed{-89}.

The source gives the same example. (Source: Build a DeepSeek Model (From Scratch))

Therefore:

\boxed{ q=\operatorname{round}(xs). }

5.49.27 Step 4 — Dequantize

Now suppose we have stored:

q=-89.

To approximately recover the original value:

x\approx\frac{q}{s}.

Thus:

x\approx \frac{-89}{127/10.8}.

Which is approximately:

\boxed{-7.59}.

The result is approximate because rounding introduced quantization error. (Source: Build a DeepSeek Model (From Scratch))

5.49.28 The basic formulas

The source's scaling mechanism can therefore be summarized as:

\boxed{ \alpha=\max_i|x_i| }
\boxed{ s=\frac{q_{\max}}{\alpha} }
\boxed{ q_i=\operatorname{round}(x_i s) }

and:

\boxed{ \hat{x}_i=\frac{q_i}{s}. }

These are extremely important formulas.

5.49.29 Why do we need scaling?

Suppose the target range is:

[-127,127]

but the original tensor contains:

[-10.8,10.8].

We cannot simply store:

10.8

inside a signed integer format that directly represents only integers in:

[-127,127].

Scaling maps:

[-10.8,10.8]

onto approximately:

[-127,127].

So:

\boxed{ \text{scaling changes representation range, not the underlying relative ordering}. }

5.49.30 Quantization is not “rounding everything to an integer”

This is a common misconception.

Quantization means:

\boxed{ \text{representing values using a lower-precision numerical space}. }

Scaling is one mechanism used to achieve this.

For INT8:

\text{scaled integer}.

For FP8:

\text{scaled low-precision floating-point}.

So:

\boxed{ \text{quantization}\neq\text{INT8 only}. }

The source explicitly introduces scaling as the prerequisite for its later FP8 framework. (Source: Build a DeepSeek Model (From Scratch))

5.49.31 Quantization error

Suppose original:

x=-7.59.

After quantization/dequantization:

\hat{x}\approx-7.56

for illustration.

Then quantization error is:

e=x-\hat{x}.

So:

\boxed{ e\neq0 }

in general.

Quantization is therefore a controlled approximation.

The goal is not:

\boxed{\text{zero error}}

but:

\boxed{ \text{small enough error that model quality/training stability remain acceptable}. }

5.49.32 Exam numerical — direct scaling

Given:

x=[-4,2,6].

Target signed INT8 range:

[-127,127].

Find the scale.

First:

\alpha=\max(|-4|,|2|,|6|) =6.

Therefore:

s=\frac{127}{6} \approx21.1667.

Quantize x=2:

q= \operatorname{round} \left(2\times21.1667\right)
= \operatorname{round}(42.3334)
\boxed{42}.

Dequantize:

\hat{x} = \frac{42}{21.1667} \approx \boxed{1.984}.

So quantization introduced a small error.

5.49.33 Exam numerical — memory

A model contains:

P=70\times10^9

parameters.

Calculate raw weight memory at:

FP32
70\times10^9\times4 = 280\times10^9

bytes:

\boxed{280\text{ GB}}.
FP16
70\times10^9\times2 = 140\times10^9

bytes:

\boxed{140\text{ GB}}.
FP8
70\times10^9\times1 = 70\times10^9

bytes:

\boxed{70\text{ GB}}.

Thus, purely for weight storage:

\boxed{ FP32:280GB \rightarrow FP16:140GB \rightarrow FP8:70GB. }

This follows the source's core memory argument, although the source's explicit worked example stops at the 32-bit → 16-bit comparison. (Source: Build a DeepSeek Model (From Scratch))

5.49.34 But there is a trap

You might think:

“Great. Just convert the entire model to FP8.”

That is not the DeepSeek strategy.

The source explicitly says DeepSeek uses a mixed precision framework.

That means:

\boxed{ \text{not everything becomes FP8}. }

Some parts use lower precision for speed.

Other sensitive parts remain in higher precision for stability. (Source: Build a DeepSeek Model (From Scratch))

5.49.35 The five pillars

Once the basic scaling foundation is established, the source introduces five pillars:

\boxed{ 1.\ \text{Mixed Precision Framework} }
\boxed{ 2.\ \text{Fine-Grained Quantization} }
\boxed{ 3.\ \text{Increasing Accumulation Precision} }
\boxed{ 4.\ \text{Mantissa Over Exponents} }
\boxed{ 5.\ \text{Online Quantization} }

(Source: Build a DeepSeek Model (From Scratch))

This list is the roadmap for the rest of FP8.

5.49.36 Why five pillars instead of one trick?

Because FP8 has a severe problem:

\boxed{ 8\text{ bits} \Rightarrow \text{very limited numerical precision/range}. }

So DeepSeek combines several techniques.

Conceptually:

                   FP8
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
   lower-cost   scale better   accumulate safely
       │            │            │
       └────────────┼────────────┘
                    ▼
              stable training

The source emphasizes that these techniques work together rather than operating independently.

5.49.37 The first pillar — Mixed Precision

Now we enter:

\boxed{\text{5.5.6 Pillar 1: The Mixed Precision Framework}}

The source's central idea is:

\boxed{ \text{Not all numbers are equally sensitive to precision loss}. }

So instead of:

\text{everything}=FP32

or:

\text{everything}=FP8,

use:

\boxed{ \text{different formats for different jobs}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.38 Think of a factory

Imagine a factory where:

  • cheap fast tools perform repetitive work,
  • precision tools handle sensitive operations,
  • final quality control uses accurate measurements.

DeepSeek applies the same principle numerically.

For huge matrix multiplications:

\boxed{FP8}

For sensitive stored state:

\boxed{FP32/BF16}.

The source calls this the central bargain of mixed precision. (Source: Build a DeepSeek Model (From Scratch))

5.49.39 The first mixed-precision example

Consider a linear layer:

\boxed{ y=Wx. }

The naive approach would perform the whole calculation in one precision.

DeepSeek instead uses different representations for different stages.

The source's forward-pass flow is:

x:\ BF16 \rightarrow FP8
W:\ FP32/BF16 \rightarrow FP8

then:

FP8\times FP8 \rightarrow FP32\text{ accumulation}

then:

FP32\rightarrow BF16

for stored output. (Source: Build a DeepSeek Model (From Scratch))

5.49.40 Why convert BF16 to FP8?

Because the expensive matrix multiplication is where the source wants the performance benefit.

So conceptually:

\boxed{ \text{storage precision} \neq \text{compute precision}. }

A tensor can be:

BF16\text{ in memory}

but:

FP8\text{ during GEMM}.

This is one of the most important mixed-precision ideas.

5.49.41 Why accumulate in FP32?

Suppose:

y=Wx.

Each output is a sum:

y_i= \sum_jW_{ij}x_j.

There may be thousands of terms.

Even if each multiplication is approximately represented in FP8, repeatedly summing low-precision products can accumulate numerical error.

The source therefore says the FP8 products are accumulated using FP32 precision. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{low-precision multiplication} + \text{high-precision accumulation}. }

This idea will become an entire separate pillar later.

5.49.42 Why convert the result back to BF16?

Because the output does not necessarily need to remain FP32 in storage.

The source says:

FP32\text{ accumulated result} \rightarrow BF16

for storage/inter-layer transmission. (Source: Build a DeepSeek Model (From Scratch))

Thus:

\boxed{ FP8 \rightarrow FP32 \rightarrow BF16 }

is not contradictory.

Each format is being used for a different purpose.

5.49.43 Source's forward-pass pipeline

The source's conceptual flow can be written:

\boxed{ x_{BF16} \rightarrow x_{FP8} }
\boxed{ W_{master} \rightarrow W_{FP8} }

then:

\boxed{ x_{FP8}W_{FP8} \rightarrow \text{FP32 accumulator} }

then:

\boxed{ y_{FP32} \rightarrow y_{BF16}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.44 This is the philosophy of DeepSeek FP8

Not:

\boxed{ \text{“FP8 everywhere.”} }

But:

\boxed{ \text{“Use FP8 where speed matters; use higher precision where errors matter.”} }

That is the core of the mixed-precision framework. (Source: Build a DeepSeek Model (From Scratch))

5.49.45 First mixed-precision exam numerical

Suppose a linear layer has:

W\in\mathbb R^{4096\times4096}.

How many multiplication pairs are involved in a matrix multiplication with:

x\in\mathbb R^{4096}

for one output vector?

Each output requires:

4096

multiplications.

There are:

4096

outputs.

Therefore:

4096\times4096 = \boxed{16,777,216}

multiply operations for the matrix product.

The source's mixed-precision idea is to perform this huge volume of arithmetic using low-precision FP8 computation while preserving higher precision where needed. (Source: Build a DeepSeek Model (From Scratch))

5.49.46 Important caveat about the source's terminology

The source describes the forward propagation as the standard prediction step and says this is also the primary computation during inference. In the broader chapter, however, the focus is specifically on the training framework and later sections discuss Fprop, Dgrad, Wgrad and optimizer state. So for our course-level understanding, treat Fprop here as the forward computation inside the mixed-precision training pipeline as well as the analogous operation used for inference. (Source: Build a DeepSeek Model (From Scratch))

5.49.47 What we have established

The progression is now:

\boxed{ \text{FP32} }

gives:

\text{high precision + large range}

↓

\boxed{ \text{FP16/BF16} }

gives:

\text{lower memory with different range/precision trade-offs}

↓

\boxed{ \text{FP8} }

gives:

\text{even lower memory / higher computational efficiency}

but creates serious numerical challenges.

Therefore DeepSeek builds:

\boxed{ \text{five complementary FP8 techniques}. }
