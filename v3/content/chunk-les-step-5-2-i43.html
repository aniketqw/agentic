Motivation

Prerequisites

  • probability chain rule
  • derivatives
  • expectation

Notation and units

  • q=prompt; o_i=response i; G=same-prompt group size; t=policy-token position.
  • pi=current; old=rollout-producing snapshot; ref=declared KL anchor; R=reward; A=fixed advantage.
  • Natural logs/nats unless explicitly stated; epsilon_clip and epsilon_std are different constants.

Assumptions

  • Toy numericals use finite probability support and explicit valid-token masks.
  • Sample standard deviation ddof=1 and stabilization1e-4 reproduce the book example; population convention is separately compared.
  • Worked arithmetic is independently checked; model-training outcomes remain reported source results.

Step-by-step derivation

  1. Write J(theta)=sum_y p_theta(y)R(y). Differentiate the probability rather than the discrete sampling operation.
  2. Use grad p=p grad log p, giving grad J=E[R grad log p]. With a state-dependent baseline independent of the chosen action, its expected score contribution vanishes.
  3. Expand log p(y|q)=sum_t log pi(y_t|q,y_<t), so terminal reward credits the sampled token decisions.
  4. For a same-prompt reward group compute mean, declared ddof standard deviation, then centered normalized advantages. Detach these coefficients during the policy step.
  5. The finite-group mean includes the sample being scored; it is not the same unbiased independent baseline as a learned value baseline. Normalization changes scaling and induces additional dependencies.
  6. Minimize minus the average advantage-weighted log probability. Numerical loss sign alone is not a reward or a measure of gradient size.

    Step 5.2 — RL Mathematics From the Ground Up

    Plan node: I6 · chat order #43

    Now we build the mathematical bridge from:

    \boxed{\text{LLM probability}}

    to:

    \boxed{\text{policy gradient}}

    and only after that will we derive GRPO.

    The source's Chapter 6 explicitly builds toward this sequence: generate rollouts → calculate rewards → compute advantages → score sequence log probabilities → construct the policy-gradient loss. (Source: Build a Reasoning Model (From Scratch))

    1. First: what exactly is the model doing?

    Suppose our prompt is:

    Solve 2x+5=17.

    The LLM generates:

    y_1,y_2,\ldots,y_T.

    For example:

    Subtract 5
→
2x = 12
→
x = 6

    At each step, the model has a probability distribution:

    \pi_\theta(y_t\mid x,y_{<t}).

    Here:

    • x = prompt
    • y_{<t} = tokens generated before step t
    • y_t = current token
    • \theta = model parameters
    • \pi_\theta = policy

    So the LLM is a policy because it determines:

    \boxed{\text{probability of each possible next action}}

    The source describes the policy as the LLM's probability distribution over next tokens. (Source: Build a DeepSeek Model (From Scratch))

    2. State, action, policy

    These three terms must become automatic.

    State

    At generation step t:

    s_t=(x,y_1,\ldots,y_{t-1})

    This is everything the model currently sees.

    Action

    The model chooses:

    a_t=y_t.

    For an LLM, the action is therefore the next token.

    Policy

    The policy gives:

    \pi_\theta(a_t\mid s_t).

    For the LLM:

    \boxed{ \pi_\theta(y_t\mid x,y_{<t}) }

    is simply its next-token probability.

    3. A complete generated response is a trajectory

    An RL trajectory is the sequence of actions taken.

    For an LLM:

    \tau=(y_1,y_2,\ldots,y_T).

    The model generates the trajectory autoregressively:

    P_\theta(y\mid x) = \prod_{t=1}^{T} \pi_\theta(y_t\mid x,y_{<t}).

    This is just the chain rule of probability.

    Why is this important?

    Because RL evaluates the whole generated response, not merely one token.

    The probability of the entire response comes from multiplying the probabilities of all its token decisions.

    4. Why do we take logarithms?

    The product above can become extremely tiny.

    Suppose:

    p_1=0.5,\quad p_2=0.4,\quad p_3=0.2.

    Then:

    P(y\mid x) = 0.5(0.4)(0.2) = 0.04.

    For a long sequence of hundreds or thousands of tokens, the product becomes numerically tiny.

    So we use:

    \log P_\theta(y\mid x).

    Using:

    \log(ab)=\log a+\log b,

    we obtain:

    \boxed{ \log P_\theta(y\mid x) = \sum_{t=1}^{T} \log \pi_\theta(y_t\mid x,y_{<t}) }

    This is the sequence log probability, or sequence logprob.

    The source later explicitly scores rollouts using this quantity. (Source: Build a Reasoning Model (From Scratch))

    5. Numerical example: sequence log probability

    Suppose:

    p=[0.5,0.4,0.2].

    We already found:

    P(y\mid x)=0.04.

    Therefore:

    \log P(y\mid x) = \log(0.04).

    Using natural logarithm:

    \boxed{\log(0.04)\approx -3.219}

    Alternatively:

    \log(0.5)+\log(0.4)+\log(0.2)
    \approx -0.6931-0.9163-1.6094 = -3.2188.

    Same result.

    6. Reward enters after generation

    Now suppose a verifier evaluates the response.

    For a math problem:

    R(y)= \begin{cases} 1 & \text{correct}\\ 0 & \text{incorrect} \end{cases}

    The important point is:

    \boxed{ \text{the model generates first, then receives reward} }

    The source uses exactly this RLVR setup for mathematical verification. (Source: Build a Reasoning Model (From Scratch))

    7. Expected reward is what RL ultimately wants

    Different random samples can produce different answers.

    Suppose the model has:

    70\%

    chance of generating a correct answer and:

    30\%

    chance of generating an incorrect answer.

    With reward:

    R= \begin{cases} 1 & \text{correct}\\ 0 & \text{incorrect} \end{cases}

    the expected reward is:

    \mathbb E[R] = 0.7(1)+0.3(0) = \boxed{0.7}.

    So the goal of policy optimization is conceptually:

    \boxed{ \max_\theta\mathbb E_{\tau\sim\pi_\theta}[R(\tau)] }

    That is:

    Change the model parameters so that high-reward trajectories become more likely.

    8. Why can't we simply differentiate the reward?

    This is a very important conceptual difficulty.

    Suppose:

    R(y)=1

    for correct and:

    R(y)=0

    for incorrect.

    The verifier is not necessarily differentiable with respect to the LLM weights.

    For example:

    LLM output
   ↓
"answer = 42"
   ↓
string parsing / execution / verifier
   ↓
0 or 1

    There is no ordinary backpropagation path:

    R\rightarrow\nabla_\theta R.

    So we need a way to learn from the reward without differentiating through the environment/verifier.

    That is the role of the policy-gradient trick.

    9. Start with the objective

    Define:

    J(\theta) = \mathbb E_{y\sim\pi_\theta}[R(y)].

    We want:

    \boxed{ \max_\theta J(\theta) }

    Expand the expectation:

    J(\theta) = \sum_y \pi_\theta(y\mid x)R(y).

    Take the gradient:

    \nabla_\theta J(\theta) = \nabla_\theta \sum_y \pi_\theta(y\mid x)R(y).

    Since reward is treated as fixed with respect to the policy parameters during this calculation:

    = \sum_y R(y)\nabla_\theta\pi_\theta(y\mid x).

    10. The log-derivative trick

    Use:

    \boxed{ \nabla_\theta \pi_\theta = \pi_\theta\nabla_\theta\log\pi_\theta }

    because:

    \nabla_\theta\log\pi_\theta = \frac{1}{\pi_\theta}\nabla_\theta\pi_\theta.

    Therefore:

    \nabla_\theta J(\theta) = \sum_y R(y)\pi_\theta(y\mid x) \nabla_\theta\log\pi_\theta(y\mid x).

    Recognize the expectation:

    \boxed{ \nabla_\theta J(\theta) = \mathbb E_{y\sim\pi_\theta} \left[ R(y) \nabla_\theta \log\pi_\theta(y\mid x) \right] }

    This is the core policy-gradient idea.

    11. Intuition behind the equation

    Look at:

    R(y)\nabla_\theta\log\pi_\theta(y\mid x).

    Suppose:

    R(y)>0.

    Then the sampled response was good.

    The update pushes:

    \log\pi_\theta(y\mid x)

    upward.

    So the model becomes more likely to produce it.

    Conversely, a lower-reward sample gets a weaker or negative learning signal.

    Thus:

    \boxed{ \text{good sampled behavior} \rightarrow \text{increase its probability} }
    \boxed{ \text{bad sampled behavior} \rightarrow \text{decrease its probability} }

    That is the essence of policy gradient.

    12. Why the LLM uses sequence log probability

    For a complete response:

    \log\pi_\theta(y\mid x) = \sum_t \log \pi_\theta(y_t\mid x,y_{<t}).

    Therefore:

    \nabla_\theta \log\pi_\theta(y\mid x) = \sum_t \nabla_\theta \log \pi_\theta(y_t\mid x,y_{<t}).

    So a reward assigned to the complete answer can influence the token-level decisions that created it.

    This is how a sequence-level reward gets converted into a learning signal for token probabilities.

    13. From reward to advantage

    Raw reward alone is often not the best signal.

    Suppose four responses get:

    [1,1,0,0].

    What do we really want to say?

    Not merely:

    response 1 → 1
response 2 → 1
response 3 → 0
response 4 → 0

    We want a relative signal:

    Which responses were better than the other responses generated for the same problem?

    This motivates the advantage.

    For the simplified GRPO setup in the source:

    \boxed{ A_i = \frac{R_i-\mu}{\sigma+\epsilon} }

    where:

    \mu=\text{mean reward in the group}

    and:

    \sigma=\text{standard deviation of rewards in the group}.

    The source explicitly implements group-relative reward normalization this way. (Source: Build a DeepSeek Model (From Scratch))

    14. Why subtract the mean?

    Take:

    R=[1,1,0,0].

    Mean:

    \mu=\frac{1+1+0+0}{4} = 0.5.

    Subtract:

    R-\mu = [0.5,0.5,-0.5,-0.5].

    Now we immediately have:

    \boxed{\text{positive}=\text{better than group average}}
    \boxed{\text{negative}=\text{worse than group average}}

    That is what makes the signal relative.

    15. Compute the normalized advantages

    For:

    [1,1,0,0],

    using sample standard deviation as in PyTorch, approximately:

    \sigma\approx0.577.

    Therefore:

    A_1=A_2 \approx \frac{0.5}{0.577} \approx0.866

    and:

    A_3=A_4 \approx \frac{-0.5}{0.577} \approx-0.866.

    Thus:

    \boxed{ A=[0.866,0.866,-0.866,-0.866] }

    which matches the numerical GRPO example in the source. (Source: Build a Reasoning Model (From Scratch))

    16. This is the big conceptual leap

    Before normalization:

    R=[1,1,0,0]

    After normalization:

    A=[+0.866,+0.866,-0.866,-0.866].

    Now the algorithm knows:

    Rollout 1 → reinforce
Rollout 2 → reinforce
Rollout 3 → suppress
Rollout 4 → suppress

    That is much more useful than simply saying:

    reward = 1
reward = 0

    The source explicitly describes this as converting binary verifier rewards into reinforcement and penalization signals. (Source: Build a DeepSeek Model (From Scratch))

    17. A critical GRPO property: relative, not absolute

    Suppose all four responses are correct:

    R=[1,1,1,1].

    Mean:

    \mu=1.

    Therefore:

    R_i-\mu=0.

    Thus:

    A=[0,0,0,0].

    The source explicitly notes that when all rewards in a group are equal, the advantages are all zero and no policy update occurs for that prompt. (Source: Build a Reasoning Model (From Scratch))

    Why?

    Because the group provides no information about which behavior was better.

    18. What happens when all responses are wrong?

    Suppose:

    R=[0,0,0,0].

    Mean:

    \mu=0.

    Therefore:

    A=[0,0,0,0].

    Again:

    \boxed{\text{no relative learning signal}}

    This is important because you do not want to reinforce some arbitrary wrong answer simply because it happened to be sampled.

    19. Now combine advantage and log probability

    We have:

    Advantage
    A_i

    which tells us:

    How good was this rollout relative to its group?

    Log probability
    \log \pi_\theta(y^{(i)}\mid x)

    which tells us:

    How much probability does the current model assign to this rollout?

    The source combines them into:

    \boxed{ L_{\text{PG}} = -\frac{1}{N} \sum_{i=1}^{N} A_i \log\pi_\theta(y^{(i)}\mid x) }

    For the sequence version, the log probability expands into the sum over generated tokens. (Source: Build a Reasoning Model (From Scratch))

    20. Why the minus sign?

    Our RL objective naturally wants to maximize:

    A_i\log\pi_\theta(y^{(i)}\mid x).

    But PyTorch optimizers conventionally minimize a loss.

    Therefore:

    \boxed{ L_{\text{PG}} = -\text{desired objective} }

    so minimizing L_{\text{PG}} is equivalent to maximizing the desired RL objective.

    The source explicitly explains this sign flip. (Source: Build a Reasoning Model (From Scratch))

    21. Numerical calculation of the policy-gradient loss

    Take:

    A=[0.866,0.866,-0.866,-0.866].

    And suppose the sequence log probabilities are:

    [-7.9243,-20.1546,-16.6130,-23.3677].

    Then:

    L_{\text{PG}} = -\frac{1}{4} \left[ 0.866(-7.9243) + 0.866(-20.1546) + (-0.866)(-16.6130) + (-0.866)(-23.3677) \right].

    Evaluating gives approximately:

    \boxed{-2.5764}

    which is the exact numerical result shown in the source. (Source: Build a Reasoning Model (From Scratch))

    22. Why do negative advantages work?

    Take one good response:

    A=+0.866.

    Its log probability is negative because probabilities are below 1:

    \log p<0.

    The optimizer sees:

    -(+0.866)\log p.

    Minimizing this encourages the log probability to become larger, meaning the probability increases.

    For a bad response:

    A=-0.866.

    Now:

    -(-0.866)\log p

    creates the opposite pressure.

    So:

    \boxed{ A>0 \Rightarrow \text{increase probability} }
    \boxed{ A<0 \Rightarrow \text{decrease probability} }

    This is the mechanism you should visualize.

    23. Why do we use detach() on advantages?

    The source's implementation contains:

    pg_loss = -(advantages.detach() * logps).mean()

    Why?

    Because advantages are treated as fixed learning signals during the policy update.

    We do:

    \boxed{ A=\text{constant for this optimization step} }

    rather than allowing gradients to flow through the reward/advantage calculation.

    The source explicitly explains that this prevents gradients from flowing back through the advantage computation. (Source: Build a Reasoning Model (From Scratch))

    24. The entire mathematical chain

    Now you can see the whole construction:

    Step 1 — generate
    y^{(i)} \sim \pi_\theta(\cdot\mid x)
    Step 2 — verify
    R_i=R(x,y^{(i)})
    Step 3 — normalize
    A_i = \frac{R_i-\mu}{\sigma+\epsilon}
    Step 4 — score the sequence
    \log\pi_\theta(y^{(i)}\mid x) = \sum_t \log\pi_\theta(y_t^{(i)}\mid x,y_{<t}^{(i)})
    Step 5 — policy loss
    \boxed{ L_{\text{PG}} = -\frac{1}{N} \sum_i A_i \log\pi_\theta(y^{(i)}\mid x) }
    Step 6 — backpropagation
    \nabla_\theta L_{\text{PG}}
    Step 7 — update
    \theta \leftarrow \theta-\eta\nabla_\theta L_{\text{PG}}

    This is the simplified GRPO foundation used in Chapter 6.

    25. Tensor shapes

    This becomes important when you implement it.

    Suppose:

    B=\text{batch size}

    and:

    G=\text{number of rollouts per prompt}.

    Rewards:

    \boxed{ R\in\mathbb R^{B\times G} }

    Advantages:

    \boxed{ A\in\mathbb R^{B\times G} }

    Suppose generated response length is T.

    Per-token log probabilities:

    \boxed{ \log p\in\mathbb R^{B\times G\times T} }

    For sequence-level log probability:

    \log P(y\mid x) = \sum_{t=1}^{T}\log p_t

    giving:

    \boxed{ \log P\in\mathbb R^{B\times G} }

    Then:

    A\odot\log P

    also has shape:

    \boxed{ [B,G] }

    and finally mean over the rollout dimensions gives a scalar loss.

    The source later shows the full clipped implementation using shapes [batch_size, group_size, tokens] for token log probabilities and [batch_size, group_size] for advantages. (Source: Build a DeepSeek Model (From Scratch))

    26. Level 1 exam numerical

    Rewards:

    [1,0,1,0]

    Calculate the mean.

    \mu= \frac{1+0+1+0}{4} = \boxed{0.5}.

    27. Level 2 exam numerical

    Using:

    R=[1,0,1,0]

    and:

    \sigma\approx0.577,

    calculate:

    A_i=\frac{R_i-0.5}{0.577}.

    For reward 1:

    A=\frac{0.5}{0.577} \approx\boxed{0.866}.

    For reward 0:

    A=\frac{-0.5}{0.577} \approx\boxed{-0.866}.

    Therefore:

    \boxed{ A=[0.866,-0.866,0.866,-0.866] }

    28. Level 3 exam numerical

    Suppose:

    A=[1,-1]

    and:

    \log p=[-2,-4].

    Then:

    L = -\frac{1}{2} [ (1)(-2)+(-1)(-4) ].

    Therefore:

    L = -\frac{1}{2}(-2+4)
    = \boxed{-1}.

    The positive-advantage response is encouraged, while the negative-advantage response is discouraged.

    29. Level 4 tensor numerical

    Suppose:

    B=8,\qquad G=4,\qquad T=128.

    Then:

    \text{rewards shape}=[8,4]
    \text{advantages shape}=[8,4]
    \text{token logprobs shape}=[8,4,128].

    After summing token log probabilities:

    [8,4,128] \rightarrow [8,4].

    Then multiply:

    [8,4]\odot[8,4] \rightarrow [8,4].

    Mean:

    [8,4]\rightarrow\boxed{\text{scalar}}.

    30. One major warning before GRPO

    The equation we have derived:

    L_{\text{PG}} = -\frac1N\sum_i A_i\log\pi_\theta(y_i|x)

    is the simplified policy-gradient objective used in Chapter 6.

    The source deliberately postpones two important stabilizing mechanisms:

    \boxed{\text{clipped policy ratios}}

    and:

    \boxed{\text{KL regularization}}

    until Chapter 7. (Source: Build a Reasoning Model (From Scratch))

    So do not mentally replace today's equation with the full modern GRPO equation yet.

    31. The key picture to memorize

                     PROMPT
                    │
                    ▼
             Current LLM πθ
                    │
           sample multiple
              rollouts
                    │
                    ▼
          y1, y2, ..., yG
                    │
                    ▼
               Verifier
                    │
                    ▼
             Rewards R1...RG
                    │
                    ▼
          Normalize within group
                    │
                    ▼
          Advantages A1...AG
                    │
                    ▼
      Sequence log probabilities
                    │
                    ▼
       - mean(A × log probability)
                    │
                    ▼
              Backprop
                    │
                    ▼
            Update θ

    This is the mathematical skeleton of the RLVR→GRPO pipeline. (Source: Build a Reasoning Model (From Scratch))

    The three equations you should now know

    Sequence probability
    \boxed{ P_\theta(y\mid x) = \prod_t \pi_\theta(y_t\mid x,y_{<t}) }
    Sequence log probability
    \boxed{ \log P_\theta(y\mid x) = \sum_t \log\pi_\theta(y_t\mid x,y_{<t}) }
    Simplified GRPO policy-gradient loss
    \boxed{ L_{\text{PG}} = -\frac1N \sum_i A_i\log P_\theta(y^{(i)}\mid x) }

    with:

    \boxed{ A_i= \frac{R_i-\mu}{\sigma+\epsilon} }

    These four equations form the bridge from RL theory to GRPO implementation. (Source: Build a DeepSeek Model (From Scratch); Build a Reasoning Model (From Scratch))
