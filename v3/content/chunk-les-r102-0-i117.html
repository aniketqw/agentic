Motivation

Translate completed-response reward into a mathematically defined policy update rather than confusing it with supervised labels.

Prerequisites

  • Conditional probabilities
  • Log probability of token sequences
  • Expected-value derivatives

Notation and units

  • s_t=prompt+prefix
  • a_t=next token
  • pi_theta(a|s)
  • R: completed-response reward
  • A=R-b(s)

Assumptions

  • Rollouts are sampled from the declared behavior policy
  • Prompt/transition distribution is fixed for score-function derivation
  • Baseline is action-independent under the unbiased identity

Step-by-step derivation

  1. A completion probability is the product of conditional token probabilities; its log probability is their sum.
  2. For J=E_tau[R(tau)], differentiate the probability distribution: grad J=E_tau[R(tau)*grad log p_theta(tau)].
  3. Deterministic token-appending transitions contribute no trainable probability, so grad log trajectory is sum_t grad log pi_theta(a_t|s_t).
  4. Subtract an action-independent baseline using E_a[grad log pi(a|s)]=grad sum_a pi(a|s)=0; this changes variance rather than the expected gradient.
  5. For terminal reward and no discount, the same observed return can be used across generated actions; this is statistically useful but imperfect token-level credit attribution.
  6. Positive advantage reinforces sampled actions; negative advantage suppresses them. Reward0 without a baseline gives no raw REINFORCE signal, not a negative one.
  7. Prompt and padding tokens are excluded from policy-gradient action loss; exploration requires stochastic rollouts but evaluation can use a separately declared decoding protocol.

We now begin Chapter 7: Reinforcement Learning — From Policy Gradients to GRPO.

This is a major conceptual transition.

Up to Chapter 6, our Mini-DeepSeek was trained with:

\boxed{\text{“Here is the correct next token. Predict it.”}}

That is supervised next-token learning.

Chapter 7 asks a different question:

What if we don't specify every correct token, and instead evaluate the completed response and reward the model when it succeeds?

That is the basic idea of reinforcement learning for LLMs. The source explicitly frames Chapter 7 as the post-training stage where a pretrained model is pushed toward useful reasoning behavior, eventually connecting RL to GRPO and DeepSeek-R1. (Source: Build a DeepSeek Model (From Scratch))

1. Why do we need RL after pre-training?

Our base model already knows how to predict text.

But:

\boxed{ \text{good next-token prediction} \neq \text{good problem solving} }

A model can be excellent at language modeling while still producing poor reasoning solutions.

The source therefore distinguishes pre-training from post-training.

Pre-training

Learn language patterns:

x_1,x_2,\ldots,x_t \rightarrow x_{t+1}.
Reinforcement learning

Generate a response, evaluate its outcome, and change the policy so successful behavior becomes more likely.

The source describes this as moving from simply predicting tokens toward deliberate problem solving. (Source: Build a DeepSeek Model (From Scratch))

2. Supervised learning vs reinforcement learning

This distinction is foundational.

Suppose the problem is:

Roger has 5 tennis balls. He buys 2 cans with 3 balls in each can. How many balls does he have?

The answer is:

5+2(3)=11.
Supervised learning

You might provide:

Prompt:
Roger has 5 tennis balls...

Target:
11

or even provide a complete reasoning trace.

The model is trained to imitate the supplied target.

Reinforcement learning

You give the model the problem and let it generate a response:

Prompt
  ↓
model generates response
  ↓
verifier checks response
  ↓
reward

You do not necessarily specify the exact sequence of intermediate tokens the model should produce.

The source explicitly highlights this distinction: RL does not require the exact correct action at every step; feedback may arrive only after several actions. (Source: Build a DeepSeek Model (From Scratch))

3. First build ordinary RL

Before translating RL to LLMs, the source uses a simple agent-environment example: a cleaning robot. (Source: Build a DeepSeek Model (From Scratch))

Imagine:

Robot = agent
Room = environment

At each step:

observe state
    ↓
choose action
    ↓
environment changes
    ↓
receive reward
    ↓
new state
    ↓
repeat

There are four core objects:

\boxed{ \text{State} ,\ \text{Action} ,\ \text{Reward} ,\ \text{Policy} }

The source deliberately establishes these four before translating them into language generation. (Source: Build a DeepSeek Model (From Scratch))

4. State

The state represents the current situation.

For the cleaning robot, it might contain:

  • where dust remains,
  • obstacles,
  • battery level,
  • charging-dock location.

So:

s_t = \text{current situation at time }t.

5. Action

The robot selects an action:

a_t.

Examples:

move forward
turn left
vacuum
return to dock

So:

\boxed{ a_t=\text{what the agent does next} }

6. Reward

After taking an action, the environment provides a reward.

For example:

+1

for cleaning useful dust,

and potentially:

-1

for wasting battery or colliding with something.

The reward tells the agent whether its behavior was beneficial.

So:

\boxed{ R_t=\text{learning signal about the outcome} }

7. Policy

The policy is the rule that chooses actions from states.

Conceptually:

\boxed{ \pi(a\mid s) }

means:

probability of taking action a when in state s.

For a neural-network agent, the policy is represented by the model parameters.

Training changes the parameters so actions associated with higher long-term reward become more likely. (Source: Build a DeepSeek Model (From Scratch))

8. Now make the surprising translation to an LLM

A language model doesn't look like a robot.

It does not move around a physical room.

But token generation is still a sequential decision process.

The source maps the RL components to LLM generation as follows. (Source: Build a DeepSeek Model (From Scratch))

RL concept LLM equivalent
State Prompt + tokens generated so far
Action Next sampled token
Transition Append sampled token to context
Reward Score of the completed response
Policy LLM's token probability distribution

This table is the conceptual bridge between classical RL and reasoning-model training.

9. Let's trace one LLM rollout

Suppose the prompt is:

Roger has 5 tennis balls...

Initially:

s_0=\text{prompt}.

The model samples:

a_0=\text{“Roger”}.

Now the state becomes:

s_1= \text{prompt}+\text{“Roger”}.

Then the model samples another token.

Maybe:

a_1=\text{“has”}.

Now:

s_2= \text{prompt}+\text{“Roger has”}.

And so on.

Therefore:

s_0 \xrightarrow{a_0} s_1 \xrightarrow{a_1} s_2 \xrightarrow{a_2} \cdots

until the response ends.

The source uses essentially this exact progression to explain LLM RL. (Source: Build a DeepSeek Model (From Scratch))

10. The action is a TOKEN

This point is easy to misunderstand.

In LLM RL, the action is not:

“solve the entire math problem.”

The action at each generation step is:

\boxed{ \text{one sampled next token} }

For example:

"Therefore"

is one action.

Then:

" the"

is another action.

Then:

" answer"

is another.

So an entire response is a sequence of actions:

a_1,a_2,\ldots,a_T.

11. The policy is the LLM itself

At every step, the model produces:

\pi_\theta(a_t\mid s_t).

For example, given the current context:

"Roger has"

the model might assign:

P(\text{5})=0.10
P(\text{7})=0.03
P(\text{bought})=0.05

and so on.

The model samples one of these possible tokens.

So the policy is literally the LLM's probability distribution over the next token.

12. Why sampling matters

This is an especially important point in the source.

During ordinary inference, you might use:

\text{greedy decoding}

or low-temperature sampling.

But in RL rollouts, sampling is central.

Why?

Because RL needs exploration.

Suppose the model always chooses:

\arg\max_a \pi(a\mid s).

Then it repeatedly follows essentially the same response path.

It becomes difficult to discover alternative reasoning paths.

Instead:

\boxed{ \text{sample multiple possible responses} }

so the training system can compare them according to their rewards.

The source explicitly says this sampling allows exploration of different responses for the same prompt. (Source: Build a DeepSeek Model (From Scratch))

13. One prompt can produce multiple trajectories

Suppose we give the same problem to the model three times.

It might generate:

Prompt P

Response A → reward 1
Response B → reward 0
Response C → reward 1

The responses are different because generation is stochastic.

That gives RL useful information:

\boxed{ \text{which sampled behaviors tended to succeed?} }

This group-based comparison later becomes central to GRPO.

14. Now the difficult problem: sparse rewards

Here comes one of the biggest differences between ordinary supervised learning and RL for reasoning.

Suppose the model generates:

Token 1
Token 2
Token 3
...
Token 100

and only after the final answer do we know whether it is correct.

For the math problem:

\text{final answer}=11

might give:

R=1.

A wrong final answer might give:

R=0.

The source calls this a sparse reward because the reward arrives only after the sequence of actions is complete. (Source: Build a DeepSeek Model (From Scratch))

15. Why sparse reward creates credit assignment

Suppose the model produced 100 tokens and got:

R=0.

Which token was responsible?

Maybe:

token 14 → misunderstood problem

or:

token 47 → arithmetic mistake

or:

token 91 → final answer malformed

The final reward alone does not directly identify the cause.

That is:

\boxed{ \text{credit assignment problem} }

The source explicitly raises this issue after introducing sparse rewards. (Source: Build a DeepSeek Model (From Scratch))

16. Yet the policy-gradient method has a way to use that reward

Here is the key idea.

Suppose the model sampled a response:

a_1,a_2,\ldots,a_T

and the response receives reward:

R.

We want:

Successful response
\boxed{ \text{increase probability of the sampled actions} }
Poor response
\boxed{ \text{decrease probability of the sampled actions} }

The source introduces policy-gradient methods specifically to make this connection. (Source: Build a DeepSeek Model (From Scratch))

17. Policy-gradient intuition

The central quantity is the log probability of the sampled actions.

A simplified objective can be thought of as:

\boxed{ R\sum_t \log\pi_\theta(a_t\mid s_t) }

and the corresponding gradient is proportional to:

\boxed{ R\sum_t \nabla_\theta \log\pi_\theta(a_t\mid s_t) }

The source explains the intuition:

the gradient of the log probability tells us how to change the model so the sampled action becomes more or less likely, while the reward controls the direction and strength. (Source: Build a DeepSeek Model (From Scratch))

This is the bridge from:

\boxed{\text{reward}}

to:

\boxed{\text{parameter update}}.

18. Successful response

Suppose:

R=1.

Then, conceptually:

+\nabla\log\pi_\theta(a_t\mid s_t).

We increase the likelihood of the sampled trajectory.

So:

successful response
       ↓
positive learning signal
       ↓
sampled tokens become more likely

19. Unsuccessful response

Now suppose the response receives a lower signal.

Relative to a baseline, its advantage can be negative.

Then:

A<0.

The policy update pushes against the sampled behavior.

So:

poor response
     ↓
negative advantage
     ↓
sampled behavior becomes less likely

This is much more informative than simply thinking "reward = number."

20. Why raw reward is not enough

The source makes an important observation.

Imagine:

Prompt A — very easy

Most responses receive:

R=1.
Prompt B — very difficult

Most responses receive:

R=0.

Suppose one response from Prompt A gets reward 1.

That's not necessarily impressive.

But a response from difficult Prompt B that somehow performs better than most alternatives may still be valuable.

So raw reward does not tell us:

\boxed{ \text{how good was this response relative to what was expected?} }

This motivates the advantage. (Source: Build a DeepSeek Model (From Scratch))

21. Advantage

The source gives:

\boxed{ A_k=R_k-\text{baseline}(s_k) }

(Source: Build a DeepSeek Model (From Scratch))

Interpret it as:

\text{Advantage} = \text{actual outcome} - \text{expected outcome}.

So:

Better than expected
A>0.
Worse than expected
A<0.
About as expected
A\approx0.

Correction: The unbiased baseline identity requires action-independent b(s) under the sampled policy. Group-dependent estimates and normalization can introduce finite-sample differences; reduced variance is not an unconditional theorem for every implementation.

Complete grounded review

22. Why the baseline helps

Without a baseline:

R

can be noisy.

With a baseline:

A=R-b.

we ask:

Did this response do unusually well or unusually badly relative to the reference level?

The source says the baseline does not change which actions are optimal, but can dramatically reduce variance, producing more stable training. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{baseline} \rightarrow \text{lower variance} \rightarrow \text{more stable updates} }

23. A concrete example

Suppose three responses to the same prompt produce rewards:

R_1=1
R_2=0
R_3=0.5.

Suppose the baseline is:

b=0.5.

Then:

A_1=1-0.5=+0.5
A_2=0-0.5=-0.5
A_3=0.5-0.5=0.

Therefore:

Response 1 → positive signal → reinforce
Response 2 → negative signal → discourage
Response 3 → approximately neutral

This is the intuition that will eventually lead us to GRPO.

24. Why this is especially powerful for reasoning

Suppose we don't know the ideal reasoning chain.

Maybe there are 20 valid ways to solve the same problem.

Supervised learning asks:

Which exact target sequence should I imitate?

RL can instead ask:

Did the response actually solve the problem?

That is why reward-based reasoning is interesting.

The model can explore different token sequences as long as the resulting behavior receives useful reward.

The source connects this idea to DeepSeek-R1 and objectively verifiable reasoning tasks. (Source: Build a DeepSeek Model (From Scratch))

25. But there is a limitation

Sparse reward is powerful, but the credit assignment is imperfect.

If an entire 100-token answer gets reward:

R=1,

the simple policy-gradient interpretation can apply that positive signal across the generated response tokens.

The source later explicitly explains that the completion-level advantage is applied across generated tokens, which is useful statistically but is not perfect token-level credit assignment. (Source: Build a DeepSeek Model (From Scratch))

This is an important limitation to remember.

28. Where PPO enters

The source's next step is PPO — Proximal Policy Optimization.

Why do we need it?

Because a naive policy-gradient update can change the model's probabilities too aggressively.

Suppose the old policy produced a rollout.

Then we update the model.

If the new model becomes radically different from the old one in a single update, the rollout data becomes a poor basis for that update.

PPO therefore introduces a mechanism to keep the policy update close to the old policy. (Source: Build a DeepSeek Model (From Scratch))

That gives the next progression:

\boxed{ \text{Policy Gradient} \rightarrow \text{Advantage} \rightarrow \text{PPO} \rightarrow \text{GRPO} }

\boxed{\text{to measure outcome relative to a baseline and reduce variance}}
