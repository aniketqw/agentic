Step-by-step derivation

  1. Validation CE assesses teacher-target imitation on a fixed held-out split. Task accuracy assesses generated answers against a verifier; these are different objectives.
  2. Evaluate with model.eval/no-grad and declared prompt, tokenizer, reasoning tags, temperature, top-p, max length and extraction rules.
  3. For n questions, accuracy=correct/n. Repeated generations of the same small benchmark do not become independent new questions for uncertainty estimates.

  5. The supplied small-scale book results show validation loss falling while Qwen-teacher task accuracy can decline. This establishes non-equivalence in that setup rather than a universal negative correlation.
  6. Teacher-family compatibility is an explanatory hypothesis; do not identify teacher size as the sole cause from a confounded teacher comparison.

    The single most important takeaway from Step 5.18educationally expanded; source-located at concept-group level
    Continuation · checked fixture B02 — Pass-at-k versus selected-answer accuracy

    Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

    Availability of a correct candidate and ability to select it are different evaluation outcomes.

    Prerequisites: Expectation and population variance, Self-consistency voting needs answer canonicalization

    Notation and assumptions

    n sampled candidates,c successful,k≤n. Combinatorial estimator1-C(n-c,k)/C(n,k). This does not score a learned verifier.

    Derivation and mechanism

    1. Count successes under a fixed validity/correctness evaluator.
    2. Count k-subsets with no successful candidate.
    3. Subtract their fraction from1. Compare with the actual selection method.
    \widehat{\mathrm{pass@}k}=1-{\binom{n-c}{k}\over\binom nk}

    Worked example

    n4,c1,k2 gives1-3/6=.5. A selector that always chooses a wrong answer still has selected-answer accuracy0, despite candidate availability.

    Limitations

    • The iid formula1-(1-p)^k is a different probabilistic model.
    • Sample budget, temperature and test contamination affect interpretation.

    Connections to later concepts

    • I01 evaluates selected answers with a declared matching rule; an available candidate only counts as successful under that rule.

    Step 5.18 — Evaluating the Distilled Reasoning Model

    Plan node: I8 · chat order #59

    We have now completed the entire training side:

    \text{R1 teacher} \rightarrow \text{candidate responses} \rightarrow \text{rejection sampling} \rightarrow \text{curated data} \rightarrow \text{student SFT} \rightarrow \text{checkpoint}

    Now comes the crucial question:

    \boxed{\textbf{Did the student actually become a better reasoning model?}}

    And this is where an important distinction appears:

    \boxed{ \text{training loss} \neq \text{reasoning accuracy} }

    The supplied source demonstrates this very clearly. (Source: Build a Reasoning Model (From Scratch))

    5.18.1 There are two different things we can measure

    During training, we measure:

    \boxed{L_{\text{train}}}

    and:

    \boxed{L_{\text{val}}}.

    After training, we can measure:

    \boxed{\text{task accuracy}}.

    For example:

    \boxed{\text{MATH-500 accuracy}}.

    These answer different questions.

    Validation loss asks:

    How well does the student predict the teacher-style target sequence on held-out examples?

    MATH-500 accuracy asks:

    Can the trained model actually solve unseen mathematical problems?

    That distinction is fundamental.

    5.18.2 The evaluation pipeline

    The source evaluates saved student checkpoints using the MATH-500 verifier-based evaluation utilities. (Source: Build a Reasoning Model (From Scratch))

    Conceptually:

    Student checkpoint
       │
       ▼
     Prompt
       │
       ▼
 Student generates response
       │
       ▼
Extract final answer
       │
       ▼
Compare with gold answer
       │
       ▼
Correct / Incorrect

    Then:

    \boxed{ \text{accuracy} = \frac{\text{number correct}} {\text{number evaluated}} }

    5.18.3 MATH-500 numerical definition

    Suppose the model solves:

    360

    out of:

    500

    questions.

    Then:

    \text{Accuracy} = \frac{360}{500} = 0.72.

    Therefore:

    \boxed{72\%}.

    Very simple mathematically, but very important experimentally.

    5.18.4 Why accuracy is different from cross-entropy

    Suppose two models produce the correct answer.

    Model A assigns:

    P(\text{correct token})=0.51.

    Model B assigns:

    P(\text{correct token})=0.99.

    Both can ultimately generate the same correct answer.

    Thus the benchmark may score both:

    \boxed{1}

    while their token-level losses are very different.

    So:

    \boxed{ \text{same benchmark outcome} \not\Rightarrow \text{same probability distribution} }

    and:

    \boxed{ \text{lower CE} \not\Rightarrow \text{proportionally higher benchmark accuracy} }.

    5.18.5 The source's tiny demonstration

    The source reports the following tiny training run:

    Stage Train loss Validation loss
    Epoch 1, step 5 0.9648 0.9082
    Epoch 1, step 10 0.9844 0.8871
    Epoch 2, step 15 0.8008 0.8707
    Epoch 2, step 20 0.7148 0.8586

    (Source: Build a Reasoning Model (From Scratch))

    Notice the overall trend:

    L_{\text{val}}: 0.9082 \rightarrow 0.8871 \rightarrow 0.8707 \rightarrow 0.8586.

    So:

    \boxed{ L_{\text{val}}\downarrow }

    which indicates the student is becoming better at matching the teacher-generated target distribution on held-out examples.

    5.18.6 Why does the source care more about validation loss?

    Because training loss is evaluated on the examples currently being optimized.

    Validation loss is evaluated on a fixed held-out set.

    The source explicitly says validation loss is:

    \boxed{\text{less noisy}}

    and more informative for estimating whether the training improvement generalizes. (Source: Build a Reasoning Model (From Scratch))

    So the hierarchy is:

    \text{training loss} \rightarrow \text{optimization signal}

    while:

    \text{validation loss} \rightarrow \text{generalization signal}.

    5.18.7 What should happen to validation loss?

    Ideally:

    \boxed{ L_{\text{val}}\downarrow }

    as the student learns.

    But the source gives an important observation:

    \boxed{ \text{initial sharp decrease} \rightarrow \text{flattening} }

    This indicates diminishing returns from additional training. (Source: Build a Reasoning Model (From Scratch))

    5.18.8 Numerical: diminishing returns

    Suppose:

    L_{\text{val},1}=0.5436

    and:

    L_{\text{val},3}=0.5343.

    The improvement is:

    0.5436-0.5343 = \boxed{0.0093}.

    Relative reduction:

    \frac{0.0093}{0.5436}\times100 \approx \boxed{1.71\%}.

    So later training gives a much smaller improvement than the initial learning phase.

    5.18.9 Now compare actual benchmark accuracy

    For the DeepSeek-R1 teacher-generated run, the source reports:

    Epoch Validation loss MATH-500 accuracy
    1 0.5436 30.6%
    2 0.5349 32.4%
    3 0.5343 33.6%

    (Source: Build a Reasoning Model (From Scratch))

    This gives us an important parallel.

    Validation loss:

    0.5436 \rightarrow 0.5349 \rightarrow 0.5343.

    Accuracy:

    30.6 \rightarrow 32.4 \rightarrow 33.6.

    So in this particular run, both metrics improve together.

    5.18.10 But the improvement is not proportional

    From epoch 1 to epoch 3:

    Accuracy improvement:

    33.6-30.6 = \boxed{3.0\text{ points}}.

    Validation-loss reduction:

    0.5436-0.5343 = \boxed{0.0093}.

    There is no simple equation such as:

    \text{accuracy}\propto-\text{loss}.

    They are related, but they measure different phenomena.

    5.18.11 Why does lower CE not perfectly predict reasoning accuracy?

    Because cross-entropy evaluates:

    \boxed{ \text{token-level conditional prediction} }

    while benchmark accuracy evaluates:

    \boxed{ \text{successful completion of an entire task} }.

    A mathematical problem may require:

    100

    correctly generated tokens.

    A tiny probability change at several crucial positions can alter the final answer from correct to incorrect.

    Thus:

    \boxed{ \text{token-level improvement} }

    doesn't translate linearly into:

    \boxed{ \text{task-level success} }.

    5.18.12 This is especially important for reasoning models

    Suppose the teacher's solution is:

    A\rightarrow B\rightarrow C\rightarrow D\rightarrow E.

    Student predicts:

    A\rightarrow B\rightarrow C\rightarrow D\rightarrow X.

    Only the final critical token might be wrong.

    Token-level loss could still look reasonably good.

    But the benchmark answer may be:

    \boxed{\text{incorrect}}.

    So:

    \boxed{ \text{one critical generation error} \rightarrow \text{entire problem failure} }.

    That is why evaluation must include task-level metrics.

    5.18.13 The source's MATH-500 result

    The source's compact DeepSeek-R1 distillation experiment reaches:

    \boxed{33.6\%}

    after epoch 3. (Source: Build a Reasoning Model (From Scratch))

    Compare that to the original Qwen3 0.6B reasoning model used as the reference:

    \boxed{48.2\%}.

    (Source: Build a Reasoning Model (From Scratch))

    So the compact experiment does transfer useful reasoning ability, but does not fully reproduce the stronger reasoning model.

    5.18.14 Calculate the gap

    48.2-33.6 = \boxed{14.6\text{ percentage points}}.

    Relative to the 48.2% reference:

    \frac{48.2-33.6}{48.2}\times100 \approx \boxed{30.3\%}.

    So the student reaches about:

    \frac{33.6}{48.2}\times100 \approx \boxed{69.7\%}

    of the reference model's MATH-500 accuracy.

    This is a derived comparison from the source's numbers, not a source-reported “69.7% retention” metric.

    5.18.15 Why is the Qwen3 235B-A22B teacher better?

    The source includes another experiment in which the student is trained on outputs generated by:

    \boxed{\text{Qwen3 235B-A22B}}.

    It reports:

    Epoch Validation loss MATH-500
    1 0.4043 45.0%
    2 0.3963 43.8%
    3 0.3948 44.2%

    (Source: Build a Reasoning Model (From Scratch))

    Notice something fascinating.

    Validation loss:

    0.4043 \rightarrow 0.3963 \rightarrow 0.3948

    continually improves.

    But MATH-500:

    45.0 \rightarrow 43.8 \rightarrow 44.2.

    It does not monotonically improve.

    This is an extremely useful lesson.

    5.18.16 Very important conclusion

    \boxed{ \text{Validation loss can improve while benchmark accuracy fluctuates.} }

    Therefore:

    \boxed{ L_{\text{val}}\downarrow \not\Rightarrow \text{accuracy strictly}\uparrow }

    on every checkpoint.

    This is exactly why evaluation must include both training metrics and downstream task evaluation.

    5.18.17 Why might this happen?

    A benchmark evaluates one particular behavioral objective.

    Cross-entropy evaluates token prediction across the validation distribution.

    So the student can become better at reproducing teacher-style text without necessarily becoming proportionally better at solving the exact benchmark problems.

    The source does not provide a formal causal decomposition of this fluctuation, so we should not assign a specific mechanism beyond this metric distinction.

    5.18.18 Now comes <think> tokens

    This is one of the most interesting experiments in the source.

    The training data can contain:

    <think>
reasoning...
</think>

final answer

    or omit the explicit:

    <think>...</think>

    structure.

    The source describes <think> and </think> as ordinary tokens used to delimit the reasoning region. (Source: Build a Reasoning Model (From Scratch))

    5.18.19 Why use <think>?

    Conceptually:

    \boxed{ \texttt{<think>} }

    marks:

    \text{reasoning region}.

    And:

    \boxed{ \texttt{</think>} }

    marks the end.

    Then the final response can be generated outside that region.

    This gives the model an explicit structural convention:

    \boxed{ \text{reasoning} \rightarrow \text{final answer} }.

    5.18.20 Important: <think> is not the reasoning itself

    This is a subtle point.

    The token:

    <think>

    does not magically create reasoning.

    The useful signal comes from the tokens between the delimiters.

    Therefore:

    \boxed{ \texttt{<think>} \neq \text{reasoning capability} }

    It is a structural marker for reasoning-style text.

    5.18.21 The source performs an ablation

    The source asks:

    What happens if we train without the explicit <think>...</think> tokens?

    This is an ablation study.

    We keep the rest of the training setup similar and remove one component.

    Then compare:

    \boxed{\text{with think tokens}}

    versus:

    \boxed{\text{without think tokens}}.

    This is exactly how experimental causality is tested in ML engineering.

    5.18.22 The results are surprising

    The source's appendix reports:

    Model / epoch Without <think> With <think>
    DeepSeek-R1 1 loss 0.5436, 31.8% loss 0.5404, 30.6%
    DeepSeek-R1 2 loss 0.5349, 31.8% loss 0.5339, 32.4%
    DeepSeek-R1 3 loss 0.5343, 30.2% loss 0.5306, 33.6%
    Qwen3 235B teacher 1 0.4043, 44.8% 0.3130, 45.0%
    Qwen3 235B teacher 2 0.3963, 39.4% 0.3087, 43.8%
    Qwen3 235B teacher 3 0.3948, 39.8% 0.3078, 44.2%

    (Source: Build a Reasoning Model (From Scratch))

    5.18.23 The key surprising observation

    For the Qwen3-teacher run, removing <think> gives:

    \boxed{\text{lower validation loss}}

    yet:

    \boxed{\text{worse MATH-500 accuracy}}

    in nearly all cases.

    The source explicitly highlights this. (Source: Build a Reasoning Model (From Scratch))

    Therefore:

    \boxed{ \text{lower loss} \neq \text{better reasoning benchmark} }

    even more strongly than before.

    5.18.24 Let's quantify one example

    Qwen3 teacher, epoch 3:

    With think:

    L_{\text{val}}=0.3078

    Accuracy:

    44.2\%.

    Without think:

    L_{\text{val}}=0.3948

    Accuracy:

    39.8\%.

    Here both metrics agree.

    But epoch 2:

    With think:

    0.3087,\quad43.8\%.

    Without think:

    0.3963,\quad39.4\%.

    Again they agree.

    The more interesting point is that within some other comparisons, loss and benchmark accuracy need not move together; the source's DeepSeek-R1 and later observations illustrate that these are distinct evaluation dimensions. (Source: Build a Reasoning Model (From Scratch))

    5.18.25 Why might explicit reasoning structure help?

    A reasonable interpretation, consistent with the source's framing, is:

    Without explicit markers:

    \text{reasoning text}

    and:

    \text{final answer}

    are less structurally separated.

    With markers:

    \boxed{ \text{reasoning region} } \rightarrow \boxed{ \text{answer region} }

    the training examples contain a more explicit response structure.

    The source says these tokens make the output structure explicit and help separate reasoning from the final result. (Source: Build a Reasoning Model (From Scratch))

    5.18.26 But don't overclaim the result

    The source does not establish a universal theorem:

    \boxed{ \text{think tokens always improve reasoning} }

    Instead, it presents an experiment in this particular small-model setup.

    The correct exam statement is:

    In the supplied experiment, omitting <think> tokens produced slightly worse MATH-500 modeling results in almost all cases, even in cases where validation loss was lower. (Source: Build a Reasoning Model (From Scratch))

    5.18.27 Another major evaluation lesson: checkpoint selection

    Suppose three checkpoints have:

    L_{\text{val}} = 0.54,\;0.53,\;0.52.

    You might automatically choose:

    \boxed{0.52}.

    But if benchmark accuracy is:

    30\%,\;34\%,\;32\%

    then the best benchmark checkpoint is the middle one.

    Therefore:

    \boxed{ \text{lowest validation loss} \neq \text{best benchmark checkpoint} }

    in general.

    This is why the source evaluates saved checkpoints rather than assuming the final checkpoint is always best. (Source: Build a Reasoning Model (From Scratch))

    5.18.28 This connects to early stopping

    Suppose:

    L_{\text{val}}

    continues to improve only marginally while:

    \text{benchmark accuracy}

    stops improving.

    Then more training may have little practical value.

    So one can conceptually select:

    \boxed{ \text{best checkpoint according to the desired downstream metric} }

    rather than simply:

    \boxed{ \text{last checkpoint} }.

    The source does not provide an explicit early-stopping algorithm here, but its checkpoint-based evaluation supports this reasoning.

    5.18.29 Evaluation must also use the correct prompting format

    This is an important connection to the earlier reasoning-model chapters.

    The source shows that MATH-500 performance can depend on:

    • whether the reasoning model mode is used,
    • prompt formatting,
    • maximum generation length,
    • reasoning-style output conventions.

    For example, the earlier evaluation results show the reasoning Qwen3 model substantially outperforming the base model on MATH-500, with longer responses and higher computation.

    Therefore:

    \boxed{ \text{model} + \text{prompt} + \text{generation settings} \rightarrow \text{measured accuracy} }

    The metric is not solely a property of the model weights.

    5.18.30 Why maximum generation length matters

    Suppose evaluation allows only:

    100

    new tokens.

    A reasoning model may not have enough space to complete its solution.

    If we allow:

    4096

    tokens, the model has much more room for intermediate reasoning.

    The source's distillation evaluation command uses:

    \boxed{\text{max\_new\_tokens}=4096}

    in its longer evaluation run. (Source: Build a Reasoning Model (From Scratch))

    This is important because reasoning models may require more generation steps than ordinary answer-only models.

    5.18.31 But longer output is not automatically better

    Earlier in the source, reasoning models are shown to generate substantially longer answers.

    However:

    \boxed{ \text{longer response} \neq \text{guaranteed correctness} }

    More tokens provide room for:

    • intermediate calculations,
    • checking,
    • alternative approaches,

    but they also consume more compute.

    The broader chapter emphasizes this tradeoff.

    5.18.32 Evaluation as an engineering stack

    We can now define four layers.

    Layer 1 — Training loss
    L_{\text{train}}

    Did the student fit the training examples?

    Layer 2 — Validation loss
    L_{\text{val}}

    Does that behavior generalize to held-out teacher-style examples?

    Layer 3 — Benchmark accuracy
    \text{MATH-500 accuracy}

    Can it solve an external task?

    Layer 4 — Generation behavior

    Inspect:

    • reasoning structure,
    • response length,
    • formatting,
    • final-answer extraction.

    This is a much stronger evaluation framework than looking at one scalar loss.

    5.18.34 Why use a held-out validation set?

    Suppose all training examples are memorized.

    Then:

    L_{\text{train}}

    can be very low.

    But the model might not generalize.

    A validation set provides examples the optimizer did not directly use for parameter updates.

    Therefore:

    \boxed{ \text{training loss} \rightarrow \text{fit} }
    \boxed{ \text{validation loss} \rightarrow \text{generalization} }.

    5.18.35 Why still evaluate MATH-500?

    Because the validation set is drawn from the distillation-data distribution.

    MATH-500 is a downstream benchmark.

    So there are two generalization questions:

    Question A

    Can the student reproduce teacher-style responses on held-out data?

    Question B

    Can the student solve external mathematical tasks?

    Question B is closer to the actual capability goal.

    5.18.36 A very important exam distinction

    Suppose:

    L_{\text{val}}=0.30.

    Can you conclude:

    \boxed{\text{MATH-500 accuracy}=70\%?}

    No.

    There is no direct conversion:

    \boxed{ L\not\leftrightarrow\text{benchmark accuracy} }

    without additional empirical information.

    This is a conceptual trap worth remembering.

    5.18.42 The most important experimental lesson

    Never evaluate a new training technique using only one metric.

    For example, suppose you change:

    \text{with think} \rightarrow \text{without think}.

    You should inspect:

    \boxed{L_{\text{train}}}
    \boxed{L_{\text{val}}}
    \boxed{\text{benchmark accuracy}}

    and:

    \boxed{\text{actual generated responses}}.

    Why?

    Because these metrics capture different dimensions of model behavior.
