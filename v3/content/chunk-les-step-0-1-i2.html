Motivation

Represent a sequence as rows of features, then use compatible matrix maps to compute all token interactions at once. Prerequisites: scalar arithmetic and ordered lists.

Prerequisites

  • Read the prerequisite chain stated in the original lesson and this review motivation.

Notation and units

  • C_{ij}=\sum_{k=1}^{n}A_{ik}B_{kj}
  • Q=XW_Q\in\mathbb R^{n\times d_k},\qquad QK^\top\in\mathbb R^{n\times n}

Assumptions

  • Real-valued vectors; token vectors use row convention in X, while a single-vector dot product can use column notation. Tensor dimension counts refer to axes, not the number of scalar entries.

Step-by-step derivation

  1. For A of shape m×n and B of shape n×p, each output C[i,j] sums n products A[i,k]B[k,j]. There are m choices of i and p choices of j, so the output is m×p.
  2. A query row X[i,:] is multiplied by the d×d_k projection. Every key row has d_k entries. Transposing K turns its n rows into n columns, allowing QKᵀ to compare each of n queries with n keys.
  3. The written example A=[[1,2],[3,4]], B=[[5,6],[7,8]] gives AB=[[19,22],[43,50]]. The dot product [2,3,1]·[4,−1,2] is 7.
  4. The miniature projection with identity weights gives the complete score matrix [[5,11,17],[11,25,39],[17,39,61]], extending the inherited first-row calculation.

    Why this matters

    A token representation can be projected only when the matrix dimensions match. Shapes catch errors before the arithmetic.

    Prerequisites: Start here.

    Symbols, shapes and assumptions

    Use row-token matrices. A has shape m×n and B has shape n×p; C has shape m×p. This is matrix multiplication, not elementwise multiplication.

    Derivation or mechanism

    1. Fix an output row i and column j.
    2. Multiply A[i,r] by B[r,j] for each shared index r.
    3. Sum those products; repeat for every output entry.
    C_{ij}=\sum_{r=1}^{n}A_{ir}B_{rj}

    Worked numerical

    For X=[[1,2],[3,4]] and W=[[1,-1],[0.5,2]], Y=XW=[[2,3],[5,5]]. The first entry is 1×1+2×0.5=2; the second is 1×(-1)+2×2=3. The same operation later creates every Q/K/V projection.

    Edge cases and limits

    • A 1×2 matrix cannot multiply another 1×2 matrix.
    • Ragged rows are not a rectangular matrix. Matrix multiplication generally does not commute.

    Connections

    • T03 uses the same rule for Q/K/V.
    • F08 differentiates a loss built from this product.

    Why this matters

    Attention needs each query dotted with each key. Transposing K exposes key vectors as columns.

    Prerequisites: Matrix multiplication and shape contracts

    Symbols, shapes and assumptions

    For A∈R^(m×n), Aᵀ∈R^(n×m) and (Aᵀ)[j,i]=A[i,j]. A reshape changes grouping and is a different operation.

    Derivation or mechanism

    1. Take each column of A in its original order.
    2. Use it as the corresponding row of Aᵀ.
    3. Check that transposing twice recovers A.
    (A^\top)_{ji}=A_{ij}

    Worked numerical

    A=[[1,2,3],[4,5,6]] becomes Aᵀ=[[1,4],[2,5],[3,6]]. A row-major reshape to 3×2 would instead yield [[1,2],[3,4],[5,6]]. They have the same shape and different entries.

    Edge cases and limits

    • Matching shapes do not prove that a transpose or reshape was applied correctly.

    0.1 — SCALARS, VECTORS AND MATRICES

    0.1.1 Scalar

    A scalar is simply one number.

    For example:

    x=5

    or

    x=-2.7.

    We can think of:

    x\in\mathbb R.

    Here:

    \mathbb R

    means the set of real numbers.

    Why do we care?

    Neural networks ultimately perform enormous numbers of operations on scalar values.

    But manipulating one scalar at a time would be impossible.

    So we group scalars into vectors and matrices.

    0.1.2 Vector

    A vector is an ordered collection of numbers.

    For example:

    x= \begin{bmatrix} 2\\ 4\\ 7 \end{bmatrix}.

    This is a 3-dimensional vector:

    x\in\mathbb R^3.

    We can also write:

    x=(2,4,7).

    The individual values are components:

    x_1=2,\qquad x_2=4,\qquad x_3=7.

    WHY DOES AN LLM NEED VECTORS?

    Because a token such as:

    cat

    cannot directly participate in operations such as:

    Q=XW_Q.

    We first convert the token into numbers.

    Eventually:

    \text{cat} \rightarrow \text{token ID} \rightarrow \text{embedding vector}.

    For example:

    \text{cat} \rightarrow [0.21,-0.53,0.72,\ldots].

    That vector contains a learned numerical representation of the token.

    Raschka's book follows precisely this progression from token representations into vector operations and later Q/K/V projections. (Source: Build a Large Language Model (From Scratch))

    0.1.3 Matrix

    A matrix is a rectangular arrangement of numbers.

    For example:

    A= \begin{bmatrix} 1&2&3\\ 4&5&6 \end{bmatrix}.

    This has:

    2\text{ rows}

    and

    3\text{ columns}.

    Therefore:

    \boxed{A\in\mathbb R^{2\times3}}

    The notation

    m\times n

    means:

    m=\text{number of rows}
    n=\text{number of columns}.

    WHY DO TRANSFORMERS NEED MATRICES?

    Because instead of transforming one token vector at a time, we want to transform an entire sequence simultaneously.

    Suppose:

    n=4

    tokens and embedding dimension:

    d=8.

    Then the input representation is:

    X\in\mathbb R^{4\times8}.

    Conceptually:

    X= \begin{bmatrix} ---x_1---\\ ---x_2---\\ ---x_3---\\ ---x_4--- \end{bmatrix}.

    Each row represents one token.

    So:

    \boxed{ \text{rows}=\text{tokens} }

    and:

    \boxed{ \text{columns}=\text{features} }

    This shape convention will appear throughout the entire course.

    0.1.4 Matrix multiplication

    Suppose:

    A\in\mathbb R^{m\times n}

    and

    B\in\mathbb R^{n\times p}.

    Then:

    AB\in\mathbb R^{m\times p}.

    The crucial rule is:

    \boxed{ \text{inner dimensions must match} }

    because:

    (m\times n)(n\times p) \rightarrow (m\times p).

    EXAMPLE

    Let:

    A= \begin{bmatrix} 1&2\\ 3&4 \end{bmatrix}

    and:

    B= \begin{bmatrix} 5&6\\ 7&8 \end{bmatrix}.

    Then:

    AB= \begin{bmatrix} 1(5)+2(7)&1(6)+2(8)\\ 3(5)+4(7)&3(6)+4(8) \end{bmatrix}

    so:

    AB= \begin{bmatrix} 19&22\\ 43&50 \end{bmatrix}.

    Notice what happened.

    For example:

    (AB)_{11} = 1(5)+2(7).

    That is a dot product.

    So matrix multiplication is essentially a huge collection of dot products.

    0.1.5 Why this becomes Q = XW

    This is our first major connection.

    Suppose:

    X\in\mathbb R^{n\times d}

    and:

    W_Q\in\mathbb R^{d\times d_k}.

    Then:

    Q=XW_Q

    is legal because:

    (n\times d)(d\times d_k)

    gives:

    \boxed{ Q\in\mathbb R^{n\times d_k}. }

    This is not arbitrary notation.

    The matrix multiplication is doing the following to every token simultaneously:

    x_i \rightarrow x_iW_Q.

    Raschka's book explicitly implements these projections using:

    \texttt{query = x @ W\_query}

    and shows that changing the number of columns of the weight matrix changes the dimensionality of the resulting query vector. (Source: Build a Large Language Model (From Scratch))

    This is the first reason I want you to become comfortable with dimensions before we enter attention.

    0.1.6 Dot product

    Given:

    x= \begin{bmatrix} x_1\\ x_2\\ \vdots\\ x_d \end{bmatrix}

    and:

    y= \begin{bmatrix} y_1\\ y_2\\ \vdots\\ y_d \end{bmatrix},

    their dot product is:

    \boxed{ x^\top y = \sum_{i=1}^{d}x_i y_i }

    For example:

    x= \begin{bmatrix} 2\\ 3\\ 1 \end{bmatrix}, \qquad y= \begin{bmatrix} 4\\ -1\\ 2 \end{bmatrix}.

    Then:

    x^\top y = 2(4)+3(-1)+1(2)
    =8-3+2
    =7.

    WHY IS DOT PRODUCT SO IMPORTANT?

    Because it measures alignment/similarity between two vectors.

    Geometrically:

    x^\top y = \|x\|\,\|y\|\cos\theta.

    Therefore:

    Same direction
    \theta=0

    so:

    \cos\theta=1.

    Large positive dot product.

    Orthogonal
    \theta=90^\circ

    so:

    \cos\theta=0.

    Dot product:

    0.
    Opposite directions
    \theta=180^\circ

    so:

    \cos\theta=-1.

    Negative dot product.

    THIS IS EXACTLY WHY ATTENTION USES IT

    Later we will calculate:

    s_{ij}=q_i^\top k_j.

    Meaning:

    How compatible is query i with key j?

    So the attention mechanism starts with something extremely simple:

    \boxed{ \text{query-key compatibility} = \text{dot product} }

    The NLP-with-Transformers book describes attention scores precisely as dot products between query and key vectors and then builds the attention matrix from those scores. (Source: NLP_TRANSFORMER)

    0.1.7 Dimensions — THE RULE YOU MUST MASTER

    Suppose:

    X\in\mathbb R^{n\times d}.

    Then:

    W_Q\in\mathbb R^{d\times d_k}

    gives:

    Q=XW_Q

    with:

    Q\in\mathbb R^{n\times d_k}.

    Likewise:

    K=XW_K

    gives:

    K\in\mathbb R^{n\times d_k}.

    Now:

    K^\top\in\mathbb R^{d_k\times n}.

    Therefore:

    QK^\top

    has shape:

    (n\times d_k)(d_k\times n)
    \boxed{ =n\times n. }

    That n\times n matrix is the attention-score matrix.

    This is one of the most important dimensional relationships in the entire course.

    0.1.8 Why n\times n matters

    Suppose:

    n=4.

    Then:

    QK^\top = \begin{bmatrix} s_{11}&s_{12}&s_{13}&s_{14}\\ s_{21}&s_{22}&s_{23}&s_{24}\\ s_{31}&s_{32}&s_{33}&s_{34}\\ s_{41}&s_{42}&s_{43}&s_{44} \end{bmatrix}.

    Interpretation:

    s_{ij} = \text{how much token }i \text{ relates to token }j.

    Therefore:

    • row 1 = what token 1 is interested in
    • row 2 = what token 2 is interested in
    • etc.

    This is why attention is fundamentally a token-to-token interaction mechanism.

    0.1.9 Weight parameters vs attention weights

    This distinction is extremely important and often causes confusion.

    Weight parameters

    For example:

    W_Q.

    These are:

    \boxed{\text{learned during training}}

    and remain fixed during a particular inference pass.

    Attention weights

    For example:

    A_{ij}.

    These are:

    \boxed{\text{computed dynamically for the current input}}

    and can change for every sequence and position.

    Raschka explicitly warns about this distinction: the W matrices are learned model parameters, whereas attention weights determine how strongly the current context vector depends on different input positions. (Source: Build a Large Language Model (From Scratch))

    0.1.10 Matrix vs tensor

    A matrix:

    X\in\mathbb R^{n\times d}

    has two dimensions.

    A batch of sequences:

    X\in\mathbb R^{B\times n\times d}

    has three dimensions.

    Where:

    B=\text{batch size}
    n=\text{sequence length}
    d=\text{embedding/model dimension}.

    So:

    \boxed{ \text{tensor shape} = (B,n,d) }

    is what we will normally use in actual PyTorch implementations.

    The NLP-with-Transformers source explicitly discusses batch matrix multiplication for attention, where the batch dimension is handled independently for each sequence. (Source: NLP_TRANSFORMER)

    0.1.11 Why we care about this for the entire course

    This seemingly basic material will keep reappearing.

    Transformer
    Q=XW_Q
    LoRA
    W'=W+BA
    Quantization
    W\rightarrow\hat W
    Distillation
    p_{\text{teacher}} \rightarrow q_{\text{student}}

    \pi_\theta(a|s)
    GRPO
    r_i(\theta) = \frac{\pi_\theta(o_i|q)} {\pi_{\text{old}}(o_i|q)}

    Everything is ultimately built from transformations of numerical objects.

    0.1.12 CHEATSHEET CONNECTION

    From the master sheet:

    \boxed{ X:(n,d) }
    \boxed{ W_Q:(d,d_k) }
    \boxed{ Q=XW_Q:(n,d_k) }
    \boxed{ QK^\top:(n,n) }

    The reason these shapes work is exactly the matrix-multiplication rule we just learned.

    So when you see the Transformer equation later, you should not memorize it.

    You should be able to reconstruct it.

    0.1.13 MINI NUMERICAL TRANSFORMER EXAMPLE

    Let's make this concrete.

    Suppose:

    n=3

    and:

    d=2.

    Let:

    X= \begin{bmatrix} 1&2\\ 3&4\\ 5&6 \end{bmatrix}.

    Suppose:

    W_Q= \begin{bmatrix} 1&0\\ 0&1 \end{bmatrix}.

    Then:

    Q=XW_Q

    so:

    Q= \begin{bmatrix} 1&2\\ 3&4\\ 5&6 \end{bmatrix}.

    Here:

    d_k=2.

    Therefore:

    QK^\top

    will have:

    3\times3

    entries.

    For example, if:

    K=Q,

    then:

    s_{11} = [1,2] \begin{bmatrix} 1\\ 2 \end{bmatrix} = 1^2+2^2 = 5.

    And:

    s_{12} = [1,2] \begin{bmatrix} 3\\ 4 \end{bmatrix} = 3+8 = 11.

    So token 1 has:

    \boxed{ [5,\;11,\;17] }

    as its raw similarity scores with the three tokens.

    This is the first concrete appearance of attention.

    We have not yet applied:

    \frac1{\sqrt{d_k}}

    or:

    \operatorname{softmax}

    or:

    \text{causal masking}.

    Those will be the next concepts.

    0.1.14 What we have actually learned

    We started with:

    \text{numbers}

    and reached:

    \boxed{ \text{token representations} \rightarrow \text{matrix transformations} \rightarrow \text{query/key representations} \rightarrow \text{pairwise token similarities} }

    The next question is:

    Why should those raw similarities become probabilities?

    That leads directly to softmax.

    But before we jump there, we need the probability foundation.

    MASTER CONNECTION

    Our chain so far is:

    \boxed{ \text{Scalar} \rightarrow \text{Vector} \rightarrow \text{Matrix} \rightarrow \text{Matrix multiplication} \rightarrow \text{Dot product} \rightarrow \text{Similarity} \rightarrow QK^\top }

    Next:

    \boxed{ QK^\top \rightarrow \text{scaled scores} \rightarrow \text{softmax} \rightarrow \text{attention probabilities} }

    Later:

    \boxed{ \text{attention probabilities} \rightarrow AV \rightarrow \text{context vector} }

    And eventually:

    \boxed{ \text{context} \rightarrow \text{Transformer block} \rightarrow \text{logits} \rightarrow \text{probability} \rightarrow \text{decoding} }
