Step 5.1 — Why Reinforcement Learning for LLM Reasoning?

Plan node: I6 · chat order #42

We now move to the Reinforcement Learning block, specifically the material covering RL → RLHF → RLVR → GRPO. The source organizes this as Chapter 6, followed by Chapter 7 for improvements to GRPO. (Source: Build a Reasoning Model (From Scratch))

The most important question to answer first is:

\boxed{\text{Why do we need RL at all after pretraining/SFT?}}

1. Start from what the pretrained LLM already does

During pretraining, our LLM learns:

\boxed{\text{predict the next token}}

For a sequence

x_1,x_2,\ldots,x_T,

the model learns probabilities such as

P_\theta(x_t\mid x_{<t}).

The usual training objective is next-token cross-entropy:

L_{\text{CE}} = -\sum_{t=1}^{T} \log P_\theta(x_t\mid x_{<t}).

So pretraining answers:

“Given the previous text, what token is likely to come next?”

The source's framing is that pretraining mainly builds knowledge, while RL can shape how the model uses that knowledge, including reasoning behavior. (Source: Build a Reasoning Model (From Scratch))

2. The limitation of next-token training

Consider the math problem:

\frac{3x-9}{2}=x+37.

Suppose the model produces:

Multiply both sides by 2. 3x-9=2x+74 x=83.

Now compare that with:

Multiply both sides by 2. 3x-9=2x+74 x=12.

At the token level, both are sequences of language.

But from the perspective of the task, they are not equivalent.

One receives:

\boxed{\text{correct}}

and the other:

\boxed{\text{incorrect}}.

That is the fundamental motivation for RL in reasoning tasks.

3. RL changes what the model is optimizing

Instead of only asking:

\text{“Did I predict the training token?”}

we can ask:

\boxed{\text{“Was the complete generated response good?”}}

That means the training signal can depend on the whole output.

The source explicitly contrasts pretraining's token-level objective with RL's ability to optimize whole outputs such as correctness or preference. (Source: Build a Reasoning Model (From Scratch))

4. Think of an LLM as a policy

This is the first RL term you must understand.

The source defines:

\boxed{\text{policy}=\text{the LLM being trained}}

So instead of writing simply:

P_\theta(x_t\mid x_{<t}),

we can call it a policy:

\boxed{ \pi_\theta(a_t\mid s_t) }

where:

  • s_t = current state/context,
  • a_t = action/token selected,
  • \pi_\theta = probability distribution produced by the LLM.

For an LLM:

s_t = (x_1,\ldots,x_{t-1})

and:

a_t=x_t.

Therefore:

\boxed{ \pi_\theta(x_t\mid x_{<t}) = P_\theta(x_t\mid x_{<t}) }

This is the bridge between ordinary language-model notation and RL notation.

5. What is an “action” for an LLM?

In ordinary RL, an agent might choose:

\text{left},\text{right},\text{jump}.

For an LLM, the action can be the next token.

So:

Prompt
  ↓
"solve 3x - 9 ..."
  ↓
token 1
  ↓
token 2
  ↓
token 3
  ↓
...

At every generation step, the LLM chooses an action:

a_t=x_t.

Thus a generated answer is an action sequence:

y=(y_1,y_2,\ldots,y_T).

6. What is the reward?

Now comes the central RL concept.

After the model generates a response:

y,

some evaluator produces:

\boxed{R(y)}

called the reward.

For example:

R(y)=1

if the math answer is correct, and:

R(y)=0

if incorrect.

That exact binary-style verifier reward is the example used for RLVR in the source. (Source: Build a Reasoning Model (From Scratch))

7. The entire RL loop

This is the most important diagram for the chapter:

Prompt
  ↓
LLM / Policy πθ
  ↓
Generate response
  ↓
Verifier / Reward mechanism
  ↓
Reward R
  ↓
RL objective
  ↓
Update θ
  ↓
Better future responses

Mathematically:

x \rightarrow y\sim\pi_\theta(\cdot\mid x) \rightarrow R(x,y) \rightarrow \text{update }\theta.

8. Compare SFT and RL

Supervised fine-tuning

You have:

(x,y^*)

where y^* is the target response.

You directly train:

\boxed{ \text{make student likely to produce }y^* }

using cross-entropy.

Reinforcement learning

You may not have an exact target sequence.

Instead:

x \rightarrow y \rightarrow R(y).

Now the model learns:

\boxed{ \text{increase probability of high-reward behavior} }

and:

\boxed{ \text{decrease probability of low-reward behavior} }

through the RL objective.

That distinction is foundational.

9. Why RL is particularly interesting for reasoning

Suppose there are many valid reasoning paths.

Problem:

2x+5=17.

A model could produce:

2x = 12
x = 6

or:

Subtract 5 from both sides:
2x = 12
Divide by 2:
x = 6

There is not necessarily one unique correct token sequence.

SFT traditionally relies on target examples.

RL can instead use:

\boxed{ R=1 }

for any answer satisfying the verifier.

This makes RL especially attractive for tasks where correctness can be evaluated without prescribing one exact wording.

That is exactly the motivation for RLVR.

10. RLHF comes first historically in the chapter

The source introduces Reinforcement Learning with Human Feedback (RLHF) before RLVR. (Source: Build a Reasoning Model (From Scratch))

The idea is:

\boxed{ \text{humans provide preference information} }

rather than a deterministic mathematical verifier.

Suppose the model produces:

Response A

The laptop has 16 GB RAM and is suitable for programming.

Response B

Buy anything.

Humans may rank:

A>B.

Those preferences are used to train a reward model.

11. RLHF has two major stages

The source's RLHF pipeline is:

\boxed{ \text{human preferences} \rightarrow \text{reward model} }

followed by:

\boxed{ \text{reward model} \rightarrow \text{RL training of LLM} }

So the full structure is:

Prompt
  ↓
LLM generates responses
  ↓
Humans rank responses
  ↓
Train reward model
  ↓
Reward model scores new responses
  ↓
RL updates LLM

The source describes the reward model as producing a single scalar score representing response quality. (Source: Build a Reasoning Model (From Scratch))

12. Why do we need a reward model?

Because humans cannot practically score every output during every RL training step.

Imagine:

1,000,000

generated responses.

You do not want humans individually rating every one.

So instead:

\text{human judgments} \rightarrow \text{learned reward function}.

Then:

R_\phi(x,y)

can automatically score new outputs.

13. The reward model is different from the policy

This distinction is exam-important.

Policy
\boxed{\pi_\theta}

is the model we want to improve.

Reward model
\boxed{R_\phi}

judges the policy's outputs.

So:

Policy → generates answer
Reward model → judges answer
RL → changes policy

Do not confuse the reward model with the policy.

14. RLVR removes the learned reward model

Now we reach:

\boxed{\text{RLVR}}

= Reinforcement Learning with Verifiable Rewards.

Instead of:

\text{LLM reward model}

we use:

\boxed{\text{automatic verifier}}

when one exists.

Example:

Question
  ↓
LLM
  ↓
generated solution
  ↓
math verifier
  ↓
0 or 1 reward

The source explicitly gives mathematics and code compilation/correctness as examples of tasks where deterministic verification is possible. (Source: Build a Reasoning Model (From Scratch))

15. RLHF vs RLVR

Property RLHF RLVR
Reward source Human preferences → reward model Verifier
Reward Learned Deterministic when verifier is deterministic
Human annotation during RL Not at every step Not required
Suitable for Preference/style/helpfulness Verifiable tasks
Example “Which answer is better?” “Is the math answer correct?”

Source basis: the chapter explicitly contrasts human judgments for RLHF with automated verification for RLVR. (Source: Build a Reasoning Model (From Scratch))

16. Why RLVR is powerful

There are three major advantages stated in the source.

First: no separate reward model

You do not need to train and maintain another large model.

Second: deterministic rewards

For the same output:

R(y)

can always produce the same value.

Third: scalable automatic evaluation

Once a verifier exists, enormous numbers of generated answers can be scored automatically.

(Source: Build a Reasoning Model (From Scratch))

17. But RLVR has a major restriction

You need a reliable verifier.

For mathematics:

\boxed{\text{correctness can often be checked}}

For program compilation:

\boxed{\text{compilation/tests can often be checked}}

But for:

“Which explanation is more insightful?”

there may be no simple deterministic verifier.

Therefore:

\boxed{ \text{RLVR is powerful but domain-dependent} }

The source explicitly says its limitation is access to reliable verification signals. (Source: Build a Reasoning Model (From Scratch))

18. The DeepSeek-R1 connection

This is where our earlier distillation chapter connects.

The source describes DeepSeek-R1 reasoning training as using:

\boxed{\text{RLVR + GRPO}}

and identifies GRPO as the policy-optimization algorithm. (Source: Build a Reasoning Model (From Scratch))

So:

\boxed{ \text{RLVR determines the reward signal} }

while:

\boxed{ \text{GRPO determines how that signal updates the policy} }

This sentence is worth memorizing conceptually.

19. Extremely important distinction

Do not say:

“GRPO is the reward.”

Wrong.

Do not say:

“RLVR is the optimization algorithm.”

Also wrong.

Instead:

\boxed{ \text{RLVR}=\text{where the learning signal comes from} }
\boxed{ \text{GRPO}=\text{how the policy is optimized using that signal} }

(Source: Build a Reasoning Model (From Scratch))

20. Where DeepSeekMath fits

GRPO was originally introduced in the DeepSeekMath work, which the source identifies as the basis for the algorithm used later in DeepSeek-R1. (Source: Build a Reasoning Model (From Scratch))

So our conceptual chain becomes:

\boxed{ \text{DeepSeekMath} \rightarrow \text{GRPO} \rightarrow \text{DeepSeek-R1 reasoning training} }

Later we will unpack exactly why GRPO is different from PPO.

Do not jump to that formula yet. First we need the RL foundations.

21. A simple numerical example

Suppose the model generates four answers for one reasoning problem:

Rollout Reward
y_1 1
y_2 0
y_3 1
y_4 0

Average reward:

\bar R = \frac{1+0+1+0}{4} = \boxed{0.5}

Interpretation:

\boxed{50\%}

of the sampled responses were successful.

At this stage, this is not yet the GRPO advantage. We are simply measuring reward.

Later we will transform rewards into learning signals called advantages.

22. Another numerical example

Suppose:

R(y)= \begin{cases} 1 & \text{correct}\\ 0 & \text{incorrect} \end{cases}

and the model produces:

20

responses.

Suppose:

13

are correct.

Then empirical reward rate is:

\frac{13}{20} = 0.65.

Therefore:

\boxed{65\%}

of the rollouts receive reward 1.

Again, this is a reward statistic, not yet the parameter update.

23. Why “whole output” matters mathematically

Let:

y=(y_1,\ldots,y_T).

The probability of the entire generated sequence is:

P_\theta(y\mid x) = \prod_{t=1}^{T} P_\theta(y_t\mid x,y_{<t}).

Taking logarithms:

\log P_\theta(y\mid x) = \sum_{t=1}^{T} \log P_\theta(y_t\mid x,y_{<t}).

This equation becomes extremely important later because policy-gradient methods use sequence probabilities/log-probabilities.

The source later explicitly has a section on scoring rollouts with sequence log probabilities. (Source: Build a Reasoning Model (From Scratch))

24. The conceptual difference from ordinary CE

In supervised learning:

\boxed{ \text{teacher tells us what token should be produced} }

In RL:

\boxed{ \text{environment/verifier tells us how good the generated result was} }

So:

SFT:
Prompt → target sequence → CE

RLVR:
Prompt → sampled sequence → verifier → reward → policy update

This is the central conceptual transition.

25. Why reasoning can emerge through this mechanism

Imagine a model repeatedly attempts a difficult math problem.

Initially:

attempt 1 → wrong
attempt 2 → wrong
attempt 3 → wrong
attempt 4 → correct

The successful trajectory receives higher reward.

The policy update increases the likelihood of actions associated with rewarding trajectories.

Over many iterations:

\boxed{ \text{trial} \rightarrow \text{feedback} \rightarrow \text{policy update} \rightarrow \text{better trial} }

This is the trial-and-error mechanism underlying RL.

The DeepSeek-R1 material describes reasoning RL in precisely this framework. (Source: Build a Reasoning Model (From Scratch))

26. Where GRPO will enter

Eventually the loop becomes:

Question
   ↓
Current policy
   ↓
Generate multiple rollouts
   ↓
Verifier
   ↓
Rewards
   ↓
Compare rollouts
   ↓
Advantages
   ↓
GRPO loss
   ↓
Backpropagation
   ↓
Update policy

The source's GRPO implementation follows essentially this progression: load model → load math data → sample rollouts → calculate rewards → prepare advantages → compute sequence log probabilities → calculate GRPO loss → update model. (Source: Build a Reasoning Model (From Scratch))

27. One subtle but crucial idea

At this stage, do not think:

\text{reward}=\text{gradient}.

They are different.

We have:

\boxed{\text{reward}}

which evaluates the generated outcome.

Then we transform it into:

\boxed{\text{advantage / learning signal}}

and then construct:

\boxed{\text{policy-gradient loss}}

which produces gradients.

The chain is:

\boxed{ R \rightarrow A \rightarrow L_{\text{policy}} \rightarrow \nabla_\theta L \rightarrow \theta' }

This chain will become the backbone of the GRPO lessons.

29. Exam-style numerical — Level 2

Suppose a generated response contains:

T=8

tokens.

Each token probability is:

[0.5,0.4,0.8,0.25,0.6,0.9,0.7,0.5].

Sequence probability is:

P(y|x) = 0.5(0.4)(0.8)(0.25)(0.6)(0.9)(0.7)(0.5).

Multiply:

\boxed{0.001512}

approximately.

The sequence log-probability is:

\log P(y|x) = \sum_{t=1}^{8}\log p_t.

Later, GRPO will use this quantity much more directly.

30. Exam-style numerical — Level 3

Suppose 5 rollouts receive:

[1,1,0,0,0].

Average reward:

\bar R = \frac{2}{5} = 0.4.

Interpretation:

\boxed{40\%}

success rate.

Notice something important:

A reward of 1 says:

this rollout was successful.

A reward of 0 says:

this rollout was unsuccessful.

But neither alone tells us:

exactly how much more strongly should this rollout influence the policy than another rollout?

That is why we need advantages.

And that is exactly where GRPO becomes interesting.

31. What you should remember from Step 5.1

The entire lesson can be compressed to this:

\boxed{ \text{Pretraining} \rightarrow \text{learn knowledge} }
\boxed{ \text{SFT} \rightarrow \text{imitate target behavior} }
\boxed{ \text{RL} \rightarrow \text{optimize behavior using feedback} }
\boxed{ \text{RLHF} \rightarrow \text{human-derived reward} }
\boxed{ \text{RLVR} \rightarrow \text{automatically verifiable reward} }
\boxed{ \text{GRPO} \rightarrow \text{policy optimization using relative rollout signals} }

and the complete RLVR reasoning loop is:

\boxed{ \text{Prompt} \rightarrow \text{Rollouts} \rightarrow \text{Rewards} \rightarrow \text{Advantages} \rightarrow \text{GRPO Loss} \rightarrow \text{Gradient} \rightarrow \text{Updated Policy} }

The source explicitly emphasizes that RLVR defines the learning signal and GRPO defines how that signal is used to update the model. (Source: Build a Reasoning Model (From Scratch))
