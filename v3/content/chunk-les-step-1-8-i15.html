Motivation

Run several learned compatibility/content spaces and return their concatenated results to the residual width.

Prerequisites

  • Single-head causal attention
  • Tensor reshape and transpose
  • Matrix projection

Notation and units

  • Q,K,V after split [B,h,T,d/h]
  • A [B,h,T,T]
  • Concat [B,T,h*d_v]; W_O [h*d_v,d]

Assumptions

  • Equal-width standard MHA assumes d divisible by h
  • Each head independently normalizes its key axis
  • Values can have a different width in the general formula

Step-by-step derivation

  1. Project [B,T,d] once into packed Q/K/V, reshape to [B,T,h,d_k] then transpose token/head axes into [B,h,T,d_k]. Reshape alone does not swap axes.
  2. Compute each head score Q_h K_h^T/sqrt(d_k), broadcast the same eligibility mask, normalize over its final T axis, and multiply by V_h.
  3. Each head returns [B,T,d_v]; transpose back and concatenate along the last feature axis into [B,T,h*d_v].
  4. Multiply by W_O[h*d_v,d] to mix head contributions and return [B,T,d], permitting residual addition.
  5. For d=12,h=3, head width=4; for h=4,d_v=16, concatenation width=64.
  6. For standard d_k=d_v=d/h, the four attention projection matrices total 4d² weights. Score storage has BhT² entries, so adding heads at fixed d does not linearly multiply all projection parameters.
  7. Distinct projection parameters permit different coefficients, but heads may become redundant; a head number is not a fixed semantic category.

    Why this matters

    Separate learned attention operations can produce different context mixtures before the output projection combines their feature spaces.

    Prerequisites: Scores to attention weights to output, Matrix multiplication and shape contracts

    Symbols, shapes and assumptions

    This fixture uses a projected width divisible by H. Split along features, not tokens. Concatenating H head outputs returns H×dv features; Wout then maps to the residual width.

    Derivation or mechanism

    1. Partition each projected feature row into head slices.
    2. Compute attention independently for each head.
    3. Concatenate per-token head outputs, then multiply by Wout.
    \mathrm{MHA}(Q,K,V)=\mathrm{Concat}(O_1,\ldots,O_H)W_O

    Worked numerical

    The executable two-head fixture has two tokens and four projected features: each head receives two features. The checker independently computes both NumPy head outputs and concatenates them. For the first causal token, the concatenated value is [1,2,3,4] before the identity output projection.

    Edge cases and limits

    • Heads are concatenated here, not averaged.
    • This implementation rejects width 3 with two equal heads.
    • No guarantee assigns a head to a particular linguistic phenomenon.

    • T12 composes a multi-head sublayer with residuals.
    • Later MQA/GQA alter key/value sharing and need distinct checks.

    Batch 1 · checked example T14 — Attention dropout is not another normalized probability row

    New teaching capsule and stated examples only; inherited prose/formulas/code remain pending

    ← Previous audit card

    Why this matters

    The weighted-average interpretation needs qualification when dropout is applied to the attention weights during training.

    Prerequisites: Scores to attention weights to output, Expectation and population variance

    Symbols, shapes and assumptions

    Let the dropout keep probability be 1-r. Inverted dropout divides retained entries by 1-r. The expected entry matches its pre-dropout value, but an individual row sum need not be one.

    Derivation or mechanism

    1. Start with the normalized attention row.
    2. Zero the sampled dropped entries.
    3. Scale retained entries by the inverse keep probability; do not renormalize unless the implementation explicitly does so.
    \widetilde A_{ij}=A_{ij}D_{ij}/(1-r),\qquad \mathbb E[\widetilde A_{ij}]=A_{ij}

    Worked numerical

    For A=[0.25,0.75], dropout rate 0.5, and keep mask [0,1], the row becomes [0,1.5]. Its sum is 1.5. The standard-library attention companion omits dropout and labels its weights pre-dropout.

    Edge cases and limits

    • This is a specified mask example, not a stochastic training experiment.
    • The PyTorch scaled-dot-product API applies its supplied dropout probability; evaluation behavior must follow that API contract. PyTorch was not installed here, so no API execution is claimed.

    • T04 row-normalization checks apply before dropout.

    Step 1.8 — Multi-Head Attention (MHA)

    Plan node: I1 · chat order #15

    We now know a single causal attention head completely:

    \boxed{ O= \operatorname{softmax} \left( \frac{QK^T}{\sqrt{d_k}}+M \right)V }

    The next question is fundamental:

    Why don't we just use one attention operation? Why does a Transformer use multiple heads?

    Your sources answer this in essentially the same way: different heads can learn different patterns of relationships simultaneously. One head may emphasize one kind of relationship while another emphasizes a different one; these relations are learned, not manually assigned. (Source: NLP_TRANSFORMER)

    The key idea is:

    \boxed{ \text{One head = one learned attention pattern} }
    \boxed{ \text{Multiple heads = multiple learned attention patterns in parallel} }

    1.8.1 First: What Was the Limitation of One Head?

    Suppose we have:

    The quick brown fox jumps

    A single attention head has one set of learned projections:

    W_Q,\;W_K,\;W_V.

    Therefore, it creates one compatibility structure:

    A= \operatorname{softmax} \left( \frac{QK^T}{\sqrt{d_k}}+M \right).

    That one attention distribution has to determine what relationships matter for that head.

    But language contains many relationships simultaneously:

    • a word may depend on its subject,
    • a verb may relate to an object,
    • an adjective may relate to a noun,
    • a token may need nearby contextual information,
    • a token may need information from something much earlier.

    The NLP with Transformers source gives this intuition explicitly: one head tends to focus on a particular aspect of similarity, while multiple heads allow several aspects to be considered at once. (Source: NLP_TRANSFORMER)

    So instead of:

    \boxed{\text{one attention pattern}}

    we use:

    \boxed{ \text{head}_1,\text{ head}_2,\ldots,\text{head}_h }

    1.8.2 The Most Important Mental Model

    Imagine a meeting with 8 analysts.

    Each analyst sees the same document, but each has learned to pay attention to different relationships.

    One might focus on:

    \text{subject}\leftrightarrow\text{verb}

    another on:

    \text{noun}\leftrightarrow\text{adjective}

    another on:

    \text{long-range dependency}.

    The model does not explicitly tell head 1:

    "You are the subject-verb head."

    Instead, every head has its own learned parameters, so different patterns emerge from training. Your source specifically warns against assuming that each head corresponds to a clean human-interpretable concept. (Source: Understanding_Attention_Handbook_01)

    So the safe statement is:

    \boxed{ \text{different heads can learn different patterns} }

    not:

    \boxed{ \text{head 1 always means grammar, head 2 always means nouns} }

    1.8.3 One Head First

    Suppose:

    X\in\mathbb{R}^{n\times d}

    where:

    • n = number of tokens
    • d = model/embedding dimension.

    A single head creates:

    Q=XW_Q
    K=XW_K
    V=XW_V.

    If:

    W_Q,W_K\in\mathbb{R}^{d\times d_k}

    and:

    W_V\in\mathbb{R}^{d\times d_v},

    then:

    Q,K\in\mathbb{R}^{n\times d_k}

    and:

    V\in\mathbb{R}^{n\times d_v}.

    Then:

    QK^T\in\mathbb{R}^{n\times n}.

    Then:

    A\in\mathbb{R}^{n\times n}.

    Finally:

    O=AV

    gives:

    O\in\mathbb{R}^{n\times d_v}.

    That is one head.

    1.8.4 Now Create Two Heads

    Suppose:

    d=8

    and we choose:

    h=2

    attention heads.

    A standard design divides the model width between heads:

    d_k=d_v=\frac{d}{h}.

    Therefore:

    d_k=d_v=\frac{8}{2}=4.

    So instead of one large attention operation with width 8, we have:

    \boxed{ 2\text{ heads}\times4\text{ dimensions per head} }

    The NLP with Transformers source gives the analogous example of BERT using 12 heads with:

    768/12=64

    dimensions per head. (Source: NLP_TRANSFORMER)

    1.8.5 Each Head Gets Its Own Projections

    This is critical.

    Head 1 has:

    W_Q^{(1)},W_K^{(1)},W_V^{(1)}.

    Head 2 has:

    W_Q^{(2)},W_K^{(2)},W_V^{(2)}.

    So:

    Q_1=XW_Q^{(1)}
    K_1=XW_K^{(1)}
    V_1=XW_V^{(1)}

    and:

    Q_2=XW_Q^{(2)}
    K_2=XW_K^{(2)}
    V_2=XW_V^{(2)}.

    Because the matrices are different:

    \boxed{ \text{Head 1 and Head 2 see the same input through different learned projections.} }

    This is the mathematical reason they can learn different relationships.

    1.8.6 Each Head Performs the Same Attention Algorithm

    Head 1 computes:

    O_1 = \operatorname{softmax} \left( \frac{Q_1K_1^T}{\sqrt{d_k}}+M \right)V_1.

    Head 2 computes:

    O_2 = \operatorname{softmax} \left( \frac{Q_2K_2^T}{\sqrt{d_k}}+M \right)V_2.

    Notice what changed?

    Only the learned projections.

    The attention mechanism itself is identical.

    Therefore:

    \boxed{ \text{MHA = several independent attention calculations} }

    1.8.7 Why Do the Heads Actually Behave Differently?

    Because:

    W_Q^{(1)}\neq W_Q^{(2)}

    and similarly for W_K,W_V.

    Therefore:

    Q_1\neq Q_2
    K_1\neq K_2
    V_1\neq V_2.

    So their score matrices differ:

    Q_1K_1^T \neq Q_2K_2^T.

    Hence their attention probabilities can differ:

    A_1\neq A_2.

    And consequently:

    O_1\neq O_2.

    This is the heart of multi-head attention.

    1.8.8 Small Illustrative Example

    Suppose token 3 has three permissible positions to attend to.

    Head 1 might learn:

    A_1^{(3)} = [0.8,0.1,0.1].

    So it strongly uses position 1.

    Head 2 might learn:

    A_2^{(3)} = [0.1,0.8,0.1].

    So it strongly uses position 2.

    Same input.

    Same causal constraint.

    Different learned projections.

    Therefore:

    \boxed{ \text{different heads can retrieve different information} }

    This is an illustrative example of the mechanism, not a claim about what actual named heads in a trained model necessarily do.

    1.8.9 What Happens to the Head Outputs?

    Suppose:

    O_1\in\mathbb{R}^{n\times4}

    and:

    O_2\in\mathbb{R}^{n\times4}.

    We cannot simply add them and call it multi-head attention.

    Instead, we concatenate them.

    \boxed{ O_{\text{concat}} = \operatorname{Concat}(O_1,O_2) }

    So:

    [n\times4] \quad || \quad [n\times4]

    becomes:

    \boxed{ n\times8 }

    because:

    4+4=8.

    1.8.10 Why Concatenate Instead of Add?

    Suppose:

    O_1=[a,b,c,d]

    and:

    O_2=[e,f,g,h].

    Adding produces:

    O_1+O_2 = [a+e,b+f,c+g,d+h].

    Information from the two heads gets mixed immediately.

    Concatenation instead preserves both:

    \boxed{ [a,b,c,d,e,f,g,h] }

    So the model can retain the outputs of the different heads separately before learning how to combine them.

    This is why the architecture uses:

    \boxed{ \operatorname{Concat}(head_1,\ldots,head_h) }

    rather than simply summing the heads.

    1.8.11 But We Now Have the Wrong Width

    After concatenation, we have:

    n\times(hd_v).

    With the typical choice:

    d_v=\frac dh,

    we get:

    hd_v = h\frac dh = d.

    So the concatenated result is already:

    n\times d.

    But there is still another learned transformation.

    That is:

    \boxed{W_O}

    the output projection.

    1.8.12 The Output Projection

    We calculate:

    \boxed{ O_{\text{MHA}} = O_{\text{concat}}W_O }

    where:

    W_O\in\mathbb{R}^{d\times d}.

    Therefore:

    [n\times d][d\times d]

    gives:

    \boxed{ n\times d. }

    So the complete MHA equation is:

    \boxed{ \operatorname{MHA}(X) = \operatorname{Concat} (head_1,\ldots,head_h)W_O }

    This is the standard formulation given in your attention handbook. (Source: Understanding_Attention_Handbook_01)

    1.8.13 Why Do We Need W_O?

    This is another subtle point.

    The heads independently produce useful representations.

    Concatenation simply places those representations side-by-side:

    [head_1\;|\;head_2\;|\;\cdots\;|\;head_h].

    But the model still needs to learn:

    How should information from these different heads be combined?

    That is what W_O does.

    So conceptually:

    \boxed{ \text{heads extract different information} }

    then:

    \boxed{ W_O\text{ learns how to combine it} }

    Then this result can be added back into the residual stream.

    1.8.14 Complete MHA Flow

    Let's put everything together.

    Start:

    X\in\mathbb{R}^{n\times d}.

    For each head h:

    Q_h=XW_Q^{(h)}
    K_h=XW_K^{(h)}
    V_h=XW_V^{(h)}.

    Then:

    A_h= \operatorname{softmax} \left( \frac{Q_hK_h^T}{\sqrt{d_k}}+M \right).

    Then:

    head_h=A_hV_h.

    Do this for all heads:

    head_1,\ldots,head_H.

    Concatenate:

    O_{\text{concat}} = \operatorname{Concat} (head_1,\ldots,head_H).

    Finally:

    \boxed{ O= O_{\text{concat}}W_O }

    This is multi-head attention.

    1.8.15 Tensor Shapes — This Is Extremely Important

    Let's use:

    B=2,\qquad n=5,\qquad d=8,\qquad h=2.

    Then:

    d_k=d_v=4.
    Input
    X: \boxed{2\times5\times8}

    meaning:

    2 sequences
× 5 tokens
× 8 features
    Project queries

    For each head:

    Q_h: \boxed{2\times5\times4}

    Similarly:

    K_h: \boxed{2\times5\times4}
    V_h: \boxed{2\times5\times4}.
    Scores
    Q_hK_h^T

    gives:

    \boxed{2\times5\times5}.

    Why?

    For every batch example:

    5\text{ query positions} \times 5\text{ key positions}.
    Attention weights

    After scaling, masking, softmax:

    A_h: \boxed{2\times5\times5}.
    Head output
    A_hV_h:
    [2\times5\times5] [2\times5\times4]

    conceptually gives:

    \boxed{2\times5\times4}.

    So each head returns:

    \boxed{B\times n\times d_v}.
    Concatenation

    Two heads:

    2\times5\times4

    and:

    2\times5\times4

    concatenate along the final dimension:

    \boxed{ 2\times5\times8 }

    because:

    4+4=8.
    Output projection
    W_O: 8\times8.

    Then:

    [2\times5\times8] \rightarrow [2\times5\times8].

    So:

    \boxed{ \operatorname{MHA}(X) : B\times n\times d }

    The mathematical cheatsheet you generated earlier summarizes exactly this shape preservation. (Source: Step1_Transformers_Mathematical_Cheatsheet)

    1.8.16 How Do We Implement Many Heads Efficiently?

    There are two conceptual implementations.

    Method 1 — Literally create separate heads

    You can imagine:

    head1 = AttentionHead(...)
head2 = AttentionHead(...)
head3 = AttentionHead(...)

    and then:

    outputs = [head(x) for head in heads]

    Your Raschka source first presents multi-head attention this way: multiple single-head attention modules with their own weights, followed by concatenation. (Source: Build a Large Language Model (From Scratch))

    Conceptually very easy.

    But this is not the most efficient implementation.

    1.8.17 Method 2 — Project Once, Then Split

    A more efficient implementation combines the projections.

    Instead of explicitly doing separate matrix multiplications one by one, we can calculate a larger projection:

    Q=XW_Q

    where:

    W_Q\in\mathbb{R}^{d\times(hd_k)}.

    So the output is:

    Q\in\mathbb{R}^{n\times(hd_k)}.

    Then reshape it into:

    \boxed{ h\times n\times d_k }

    or, with batches:

    \boxed{ B\times h\times n\times d_k. }

    Do the same for K and V.

    Raschka explicitly describes this optimized implementation as projecting and then reshaping to split the tensors into multiple heads, rather than maintaining separate attention classes. (Source: Build a Large Language Model (From Scratch))

    1.8.18 Why Is This Valid?

    Suppose:

    d=8,\quad h=2,\quad d_k=4.

    A single combined query projection can produce:

    Q\in\mathbb{R}^{n\times8}.

    We then interpret it as:

    Q= [Q^{(1)}\;|\;Q^{(2)}]

    where:

    Q^{(1)}\in\mathbb{R}^{n\times4}

    and:

    Q^{(2)}\in\mathbb{R}^{n\times4}.

    So:

    \boxed{ n\times8 \rightarrow 2\times n\times4 }

    is just reorganizing the same projected numbers into separate head dimensions.

    No information is magically lost by the reshape itself.

    1.8.19 The Shape Flow You Should Memorize by Understanding

    For standard MHA:

    \boxed{ X:B\times n\times d }

    ↓

    project:

    Q,K,V:B\times n\times(hd_k)

    ↓

    split heads:

    \boxed{ B\times h\times n\times d_k }

    for Q,K, and analogous V.

    ↓

    attention:

    \boxed{ B\times h\times n\times n }

    ↓

    weighted values:

    \boxed{ B\times h\times n\times d_v }

    ↓

    transpose/reshape/concatenate:

    \boxed{ B\times n\times(hd_v) }

    ↓

    output projection:

    \boxed{ B\times n\times d }

    This shape chain is one of the most important things for implementing Transformers correctly.

    1.8.20 Where Does the Causal Mask Go?

    Every head uses causal attention.

    Therefore each head has:

    A_h= \operatorname{softmax} \left( \frac{Q_hK_h^T}{\sqrt{d_k}}+M \right).

    So the causal mask is applied to the score matrix for every head.

    The model therefore gets:

    \boxed{ \text{multiple attention patterns} + \text{future-token protection}. }

    1.8.21 MHA Does NOT Mean Different Heads Have Different Sequence Positions

    This is a common misunderstanding.

    Every head sees the same token sequence.

    For example:

    The cat is sleeping

    All heads receive representations corresponding to:

    The | cat | is | sleeping

    What changes is the learned projection:

    W_Q^{(h)},W_K^{(h)},W_V^{(h)}.

    Therefore the heads can produce different views of the same sequence.

    So:

    \boxed{ \text{different heads} \neq \text{different input sequences}. }

    1.8.22 MHA vs Single-Head Attention

    Single head Multi-head attention
    One W_Q,W_K,W_V Separate learned projections per head
    One attention pattern Multiple attention patterns
    One head output Multiple head outputs
    One d_k subspace Several d_k subspaces
    One context-mixing pattern Several patterns simultaneously
    Output already in one value space Outputs concatenated then projected with W_O

    The source framing is essentially: multiple attention operations in parallel, concatenate, then apply an output projection. (Source: Understanding_Attention_Handbook_01)

    1.8.23 Why Not Just Make One Huge Head?

    Excellent question.

    Suppose:

    d=512.

    We could use one head with:

    d_k=512.

    Instead, suppose we use:

    h=8

    with:

    d_k=64.

    Each head gets its own learned projection.

    So rather than requiring one representation space to learn one large compatibility pattern, we get:

    8

    different learned subspaces and compatibility patterns.

    This gives the architecture a richer way to represent relationships.

    The NLP with Transformers source gives precisely this motivation: multiple heads let the model focus on multiple aspects simultaneously. (Source: NLP_TRANSFORMER)

    1.8.24 But There Is an Important Nuance

    Do not conclude:

    More heads always means better performance.

    That is not what the sources establish.

    The important architectural principle is:

    \boxed{ \text{multiple independently projected attention computations} }

    The actual useful behavior and quality depend on the learned model, dimensions, architecture, training, etc.

    Also, the handbook emphasizes that head semantics are emergent and are not guaranteed to correspond to clean human concepts. (Source: Understanding_Attention_Handbook_01)

    1.8.25 One More Very Important Distinction: h vs H_{kv}

    For the basic Transformer MHA we are studying now:

    H_q=H_{kv}=h.

    But later, when we study modern LLM architectures, you will encounter:

    • MHA
    • MQA
    • GQA

    The attention handbook makes this distinction explicit: modern grouped attention can have a different number of query heads and key/value heads. (Source: Understanding_Attention_Handbook_01)

    So don't assume forever that:

    \boxed{ \text{number of query heads} = \text{number of KV heads}. }

    For standard MHA, yes.

    For GQA/MQA, not necessarily.

    We'll handle this later when we reach modern inference architectures and KV caching.

    1.8.26 The Full Mathematical Definition

    For head i:

    \boxed{ head_i = \operatorname{Attention} (Q_i,K_i,V_i) }

    with:

    Q_i=XW_Q^{(i)}
    K_i=XW_K^{(i)}
    V_i=XW_V^{(i)}.

    And:

    \boxed{ head_i = \operatorname{softmax} \left( \frac{Q_iK_i^T}{\sqrt{d_k}}+M \right)V_i }

    Then:

    \boxed{ \operatorname{MHA}(X) = \operatorname{Concat} (head_1,\ldots,head_h)W_O }

    That is the equation you should understand rather than memorize blindly.

    1.8.27 Connect MHA to Our Previous Steps

    Look how the architecture has grown.

    Step 1.5 — Q/K/V
    X \rightarrow Q,K,V
    Step 1.6 — Scaling
    QK^T \rightarrow \frac{QK^T}{\sqrt{d_k}}
    Step 1.7 — Causal masking
    \frac{QK^T}{\sqrt{d_k}} \rightarrow \frac{QK^T}{\sqrt{d_k}}+M
    Now Step 1.8 — Multi-head

    Instead of one:

    \boxed{ Q,K,V }

    we create:

    \boxed{ Q_1,K_1,V_1 }
    \boxed{ Q_2,K_2,V_2 }
    \vdots
    \boxed{ Q_h,K_h,V_h }

    perform attention independently, concatenate, and project.

    So MHA is not a completely new attention mechanism.

    It is:

    \boxed{ \text{the same attention mechanism, performed in multiple learned subspaces.} }

    1.8.28 Connect MHA to the Residual Stream

    Remember our residual-stream formulation:

    x\leftarrow x+\operatorname{Attn}(\operatorname{norm}(x)).

    Now "Attn" is actually:

    \operatorname{MHA}.

    So a decoder block begins conceptually as:

    y= x+ \operatorname{MHA}(\operatorname{norm}(x),M).

    Then later:

    h= y+ \operatorname{FFN}(\operatorname{norm}(y)).

    That gives the block structure we saw earlier in the Transformer slides.
