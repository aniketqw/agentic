Motivation

Prevent scale inversions, then show why calibration-aware weight compensation optimizes output fidelity rather than raw weight distance.

Prerequisites

  • Matrix multiplication, quadratic forms and partial derivatives.
  • Integer quantization with rounding, clipping and zero points.

Notation and units

  • Delta_x and Delta_w are real units per integer code.
  • A is an exact integer accumulator; Delta_y is the next output step.
  • e is a weight-row error, H=XX^T its calibration quadratic.

Assumptions

  • Toy dot products use zero-centered integer codes without affine zero points.
  • Compensation fixture uses a symmetric positive-definite H and one fixed coordinate error; this is not the full sequential GPTQ implementation.

Step-by-step derivation

  1. Write x≈Delta_x*q_x and w≈Delta_w*q_w. Substitute into their dot product to get y≈Delta_x*Delta_w*sum(q_x*q_w).
  2. To enter the next integer format, q_y≈round(y/Delta_y). If a slide defines reciprocal scale s=1/Delta, use division rather than multiplying that s during reconstruction.
  3. For row error e, squared output error is e^T*(XX^T)*e. Calibration covariance weights directions differently from raw ||e||².
  4. Partition e into one fixed error e_j and free coordinates e_R. Differentiate the quadratic: H_RR*e_R+H_Rj*e_j=0, so solve e_R=-H_RR^-1*H_Rj*e_j.
  5. With H=[[1,.9],[.9,1]] and e1=.1, e2=-.09 and cost .0019. Independent rounding e2=0 would cost .01.
  6. BitNet/ternary output recovery includes both activation and weight scale factors. The exact denominator follows the stated activation code range; binary, ternary and general INT8 conventions must not be silently interchanged.

    Mastery answers and retained exercise context

    1. Can dequantization be fused? Yes; expected units must be recovered, but an explicit float buffer is not mathematically necessary.

    3. Why restore two scale factors? Both operands were encoded using their own real-to-code transformations.

    Continuation · checked fixture Q01 — Quantization scale units and rounding

    Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

    Map real values to integer codes and reconstruct them with a clearly defined scale.

    Prerequisites: Matrix multiplication and shape contracts

    Notation and assumptions

    Step Δ is real units per code; q=clip(round(x/Δ)+z); xhat=Δ(q-z). This uses nearest-even rounding. The slide reciprocal scale s=1/Δ has code units per real unit.

    Derivation and mechanism

    1. Choose integer range, real step and zero-point.
    2. Divide by step, round, shift and clip.
    3. Subtract zero-point and multiply by step to reconstruct.
    q=\operatorname{clip}(\operatorname{round}(x/\Delta)+z,q_{min},q_{max}),\quad\hat x=\Delta(q-z)

    Worked example

    x=[-2,-.6,0,.6,2],Δ.5,z0,range[-3,3]→codes[-3,-1,0,1,3], reconstruction[-1.5,-.5,0,.5,1.5]. Values outside representable range saturate. Halfway .25 and.75 map to0 and2 under nearest-even.

    Limitations

    • Saturation error can exceed half a step.
    • Do not multiply a dequantization-step scale where a reciprocal quantization scale is required.

    Connections to later concepts

    • Q06 recovers integer products using the same scale-unit discipline. Q09 uses fake quantization during training.

    Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

    Recover a real-valued output from an integer product without reversing the scale convention.

    Prerequisites: Quantization scale units and rounding

    Notation and assumptions

    Declared fixture weights≈a·sign(W),activation codes≈round(qmax·x/b). Integer product C reconstructs as a·b·C/qmax.

    Derivation and mechanism

    1. Track weight step a and activation absmax b separately.
    2. Compute the signed-weight/integer-activation product.
    3. Multiply by both real-unit steps; activation step is b/qmax.
    \hat Y=(ab/q_{max})C

    Worked example

    C127,a2,b3,qmax127 gives real output6. Multiplying by127 instead of dividing introduces a scale error. The existing bridge already supplies this unit qualification; the checker now verifies it.

    Track units through an integer matrix product

    Use one convention consistently. If real activations satisfy x≈s_x q_x and weights satisfy w≈s_w q_w, then the integer accumulator A=q_xq_w represents y≈s_x s_w A. Slides using q≈s x have reciprocal scales and therefore divide on recovery. Slide 32 uses that reciprocal convention: 12614/4032.25≈3.128. Multiplication and division can both be correct when their scale definitions differ.

    y\approx s_xs_wA,\qquad q_y\approx\operatorname{round}\!\left(\frac{s_xs_w}{s_y}A\right)

    Derived toy example: A=200, s_x=.02, s_w=.05 gives y=.2. If the next layer uses s_y=.01, q_y=20. This explains the semantic conversion of units. It does not require every implementation to write an intermediate floating-point buffer: linear rescaling can be fused or approximated in integer arithmetic. Nonlinearities, residual paths, clipping, zero points, and per-channel scales need their own consistent treatment. The source’s “cannot skip dequantizing” statement should be read with these implementation assumptions.

    GPTQ cares about output error, not just weight proximity

    \|(W-\widehat W)X\|_F^2=\operatorname{tr}\!\left((W-\widehat W)XX^{\mathsf T}(W-\widehat W)^{\mathsf T}\right),\quad E(e)=e^{\mathsf T}He

    For a row error e and H=XXᵀ, correlated calibration inputs determine which weight-error directions change the output. Some authors call 2XXᵀ the Hessian; that constant factor changes the reported objective scale but not its minimizer. The unweighted weight MSE ignores H. With positive diagonal terms and the first coordinate error fixed, minimizing a two-coordinate quadratic over the second gives ∂E/∂e₂=2(H₂₁e₁+H₂₂e₂)=0, so e₂*=−H₂₁e₁/H₂₂. That is the compensation idea, not a complete GPTQ implementation.

    Slide 40 reports output error 151.4 for independent rounding versus 71.8 for sequential compensation, a derived reduction of 52.576%. It also reports worse raw weight MSE for GPTQ (.00137 versus .00067). Preserve both measurements: they optimize different metrics. These are the slide’s specific 64-weight illustrative experiment, not a universal model-level accuracy improvement.

    BitNet restores both scales

    Slide 53 writes y_dequantized=Y·αβ/2^(b−1). Its Y is the integer/ternary accumulator, α is the weight scaling factor, β the activation range factor, and b the activation-bit parameter in the preceding quantization convention. Recovering the output must account for both transformations. A factor missing from either side produces a systematic amplitude error. For an explicitly toy example Y=64, α=.5, β=2, b=8, the recovered value is .5; saturation and rounding error remain even after scales are restored.

    \widehat y=Y\frac{\alpha\beta}{2^{b-1}}

    This scaling identity does not establish that any ordinary FP16 layer can accept an arbitrary integer accumulator directly. It first needs values in its expected units.
