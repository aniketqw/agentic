Assumptions

  • Sample standard deviation ddof=1 and stabilization1e-4 reproduce the book example; population convention is separately compared.

Step-by-step derivation

  1. Concatenate P prompt tokens and A response tokens, total L=P+A. Inputs t[:-1] and targets t[1:] each have L-1 positions.
  2. Logit index P-1 predicts the first response token. Keep positions j>=P-1 and mask padding independently; retained target count is A=L-P.
  3. Teacher-force the response prefix during training; generated evaluation uses the students own prefixes, so exposure conditions differ.
  4. Mean CE equals minus the mean log probability of eligible hard targets. At one position grad_z CE=softmax(z)-one_hot(target).
  5. For multiple lengths, explicitly select token-weighted or equally response-weighted CE. Both are meaningful choices and need not yield equal losses.
  6. Ordinary hard-target SFT has no obligatory KD temperature or teacher/student KL term. Label smoothing or extra losses would be additional declared choices.

Step 5.14 — DeepSeek-R1 Distillation Training Mechanics

Plan node: I8 · chat order #55

Now we will go from the idea of distillation to the exact computation performed for one training example.

This step is important because here we connect:

\boxed{ \text{teacher response} \rightarrow \text{tokens} \rightarrow \text{shifted input/targets} \rightarrow \text{prompt masking} \rightarrow \text{student logits} \rightarrow \text{cross-entropy} \rightarrow \text{backpropagation} }

The supplied source gives the exact implementation pattern used for the answer-only loss. (Source: Build a Reasoning Model (From Scratch))

5.14.1 First: what exactly does the student receive?

Suppose the original question is:

Half the value of 3x-9 is x+37. Find x.

The teacher might generate:

Multiply both sides by 2.
3x - 9 = 2x + 74.
Subtract 2x from both sides.
x - 9 = 74.
Therefore x = 83.

The student training example is essentially:

\boxed{ (\text{prompt},\text{teacher-generated reasoning + answer}) }

The teacher's generated tokens become the supervised targets.

The source explicitly describes this as hard distillation, which is essentially SFT on teacher-generated synthetic data.

5.14.2 Important: the teacher is NOT providing probabilities

For DeepSeek-R1 distillation, the student does not need:

z_T

the teacher logits.

It does not need:

p_T=\operatorname{softmax}(z_T/T).

It does not need:

D_{KL}(p_T\|p_S).

Instead, it needs the teacher's generated sequence:

\boxed{ y_1,y_2,\ldots,y_N }

and learns to reproduce it. (Source: Build a DeepSeek Model (From Scratch))

5.14.3 One complete training example

Let's construct a tiny artificial example.

Suppose the full sequence is:

[ P_1,P_2,P_3,P_4,A_1,A_2,A_3,A_4,A_5 ]

where:

  • P_1,\ldots,P_4 are prompt tokens,
  • A_1,\ldots,A_5 are teacher-answer/reasoning tokens.

Thus:

\boxed{\text{prompt\_len}=4}

and:

\boxed{\text{total length}=9}.

5.14.4 Why do we shift the sequence?

Because an autoregressive language model is trained to predict:

\boxed{\text{next token}}

not the token it has already seen.

So the source constructs:

\text{input\_ids} = \text{tok}[:-1]

and:

\text{target\_ids} = \text{tok}[1:].

(Source: Build a Reasoning Model (From Scratch))

For our sequence:

Original
[P_1,P_2,P_3,P_4,A_1,A_2,A_3,A_4,A_5]
Input
[P_1,P_2,P_3,P_4,A_1,A_2,A_3,A_4]
Target
[P_2,P_3,P_4,A_1,A_2,A_3,A_4,A_5]

5.14.5 Align them side by side

This is the most important visualization:

Input token Target token
P_1 P_2
P_2 P_3
P_3 P_4
P_4 A_1
A_1 A_2
A_2 A_3
A_3 A_4
A_4 A_5

This is ordinary autoregressive training.

5.14.6 Now comes the subtle part: we do NOT want prompt loss

The student is supposed to learn:

\boxed{\text{teacher's reasoning and answer}}

not:

\boxed{\text{how to reproduce the prompt}}

because the prompt is already supplied at inference time.

The source therefore discards the logits/targets corresponding only to the prompt portion when calculating the distillation loss. (Source: Build a Reasoning Model (From Scratch))

5.14.7 Which target positions correspond to the teacher response?

Look at the shifted table again:

Logit index Input Target Desired loss?
0 P_1 P_2 No
1 P_2 P_3 No
2 P_3 P_4 No
3 P_4 A_1 Yes
4 A_1 A_2 Yes
5 A_2 A_3 Yes
6 A_3 A_4 Yes
7 A_4 A_5 Yes

Notice the first answer target A_1 appears at:

\boxed{\text{index}=3}.

And:

\text{prompt\_len}-1 = 4-1 = 3.

Exactly as in the source:

\boxed{ \text{answer\_start} = \max(\text{prompt\_len}-1,0) }

(Source: Build a Reasoning Model (From Scratch))

5.14.8 Why is it prompt_len − 1?

This is one of the most common places students make mistakes.

The model sees:

P_1,P_2,P_3,P_4

and the logit generated after reading P_4 predicts:

A_1.

But because we shifted the target by one position, that prediction appears at:

4-1=3.

Therefore:

\boxed{ \text{first answer logit index} = \text{prompt length}-1 }

This is not an arbitrary indexing trick. It follows directly from the one-token shift.

5.14.9 A second example

Suppose:

\text{prompt\_len}=7.

Then:

\text{answer\_start} = 7-1 = \boxed{6}.

So the logit at index 6 predicts the first teacher-response token.

5.14.10 What does the source code do?

The source's exact structure is:

input_ids = torch.tensor(
    token_ids[:-1], dtype=torch.long, device=device
).unsqueeze(0)

target_ids = torch.tensor(
    token_ids[1:], dtype=torch.long, device=device
)

logits = model(input_ids).squeeze(0)

answer_start = max(prompt_len - 1, 0)

answer_logits = logits[answer_start:]
answer_targets = target_ids[answer_start:]

loss = torch.nn.functional.cross_entropy(
    answer_logits, answer_targets
)

This is the core implementation. (Source: Build a Reasoning Model (From Scratch))

5.14.11 Tensor shapes

Suppose:

L=9

tokens in the original sequence.

Then:

\text{input shape}=[1,8]

after adding batch dimension.

The model produces:

\text{logits shape} = [1,8,V]

where V is vocabulary size.

After:

.squeeze(0)

we have:

\boxed{ [8,V] }

Then:

\text{answer\_start}=3.

So:

\text{answer\_logits} \in \mathbb R^{5\times V}

and:

\text{answer\_targets} \in \mathbb R^{5}.

Therefore cross_entropy compares:

\boxed{ 5\text{ prediction positions} }

against:

\boxed{ 5\text{ teacher target tokens}. }

5.14.12 Why does the student need logits for every answer token?

Suppose the teacher response is:

A_1,A_2,A_3,A_4,A_5.

The student is trained to learn:

P_S(A_1|q)

then:

P_S(A_2|q,A_1)

then:

P_S(A_3|q,A_1,A_2)

and so on.

Thus:

\boxed{ P_S(A_t|q,A_{<t}) }

for every teacher token.

This is exactly the standard autoregressive language-model objective.

5.14.13 The loss for one token

Suppose the vocabulary is:

V=\{A,B,C\}

and the target token is A.

The student logits are:

z=[2,1,0].

Softmax gives:

p_A=\frac{e^2}{e^2+e^1+e^0}.

Using:

e^2\approx7.389, \quad e^1\approx2.718, \quad e^0=1,

denominator:

7.389+2.718+1=11.107.

Thus:

p_A\approx\frac{7.389}{11.107} \approx0.665.

5.14.14 Cross-entropy

For the correct target A:

L=-\log p_A.

Therefore:

L=-\log(0.665).

Approximately:

\boxed{L\approx0.408}.

So the model is not terribly wrong because it assigned the correct teacher token a probability of about 66.5%.

5.14.15 Suppose the student becomes more confident

New logits:

[4,1,0].

Now:

e^4\approx54.598.

Denominator:

54.598+2.718+1 = 58.316.

Therefore:

p_A \approx \frac{54.598}{58.316} \approx0.936.

Loss:

-\log(0.936) \approx \boxed{0.066}.

So:

0.408\rightarrow0.066.

Lower loss means the student has become much better at predicting the teacher's target token.

5.14.16 What if the model predicts the wrong token?

Suppose:

p_A=0.05.

Then:

L=-\log(0.05) \approx \boxed{2.996}.

So:

p_{\text{correct}}\downarrow \Rightarrow L\uparrow.

This is standard cross-entropy behavior.

5.14.17 Multi-token loss

Suppose the teacher response has three target tokens.

Student assigns:

P(A_1)=0.8
P(A_2)=0.5
P(A_3)=0.9.

Then:

L_1=-\ln(0.8)\approx0.223
L_2=-\ln(0.5)\approx0.693
L_3=-\ln(0.9)\approx0.105.

Mean loss:

L = \frac{0.223+0.693+0.105}{3}.
\boxed{L\approx0.340}.

This is what cross-entropy does across the selected target positions.

5.14.18 Why is this called “answer-only loss”?

Because the source deliberately selects:

\boxed{ \text{answer\_logits} }

and:

\boxed{ \text{answer\_targets} }

starting at:

\text{answer\_start}.

So the prompt prediction positions are discarded. (Source: Build a Reasoning Model (From Scratch))

It is more accurately understood as:

\boxed{ \text{teacher-response-only loss} }

because the target includes the reasoning trace and final answer, not merely the final numeric answer.

5.14.19 Why is prompt masking necessary?

Imagine the prompt contains 50 tokens and the teacher response contains 500 tokens.

If you trained on both:

50+500=550

positions.

But 50 positions are merely teaching the model to reproduce an input it already receives.

The useful distillation signal is:

\boxed{500}

teacher-response positions.

So masking focuses the learning budget on the teacher's behavior.

5.14.20 Important distinction: prompt is still used by the student

Prompt tokens are excluded from the loss, but they are absolutely not removed from the input.

This is a subtle but critical distinction.

The student needs:

q

as context to learn:

P(A_1|q).

So:

Prompt → INPUT
Prompt → NOT a loss target
Teacher response → INPUT progressively
Teacher response → LOSS TARGET

Therefore:

\boxed{ \text{mask from loss} \neq \text{remove from context} }

5.14.21 Teacher forcing

This also connects to the concept of teacher forcing.

During training, after predicting A_1, the model is given the true teacher token A_1 when predicting A_2.

So:

P_S(A_2|q,A_1)

uses the teacher's actual A_1, not the student's sampled prediction.

Likewise:

P_S(A_3|q,A_1,A_2).

This makes SFT training stable and efficient.

The source uses ordinary next-token cross-entropy for the generated reasoning sequence.

5.14.22 This is different from RL generation

During RL:

o_t \sim \pi_\theta(\cdot|q,o_{<t})

the model samples its own token.

During distillation SFT:

o_t

comes from the teacher dataset and serves as the target.

So:

\boxed{ \text{RL: sample behavior} }
\boxed{ \text{distillation SFT: imitate recorded behavior} }

5.14.23 Gradient calculation

For one token, cross-entropy is:

L=-\log p_y.

With softmax:

p_j=\frac{e^{z_j}}{\sum_k e^{z_k}}.

The gradient with respect to logit z_j is:

\boxed{ \frac{\partial L}{\partial z_j} = p_j-\mathbf 1[j=y] }

where:

\mathbf1[j=y] = \begin{cases} 1 & j=y\\ 0 & j\ne y. \end{cases}

This is the central reason the student learns.

5.14.24 Numerical gradient example

Suppose:

p=[0.665,0.245,0.090]

and the correct teacher token is class A.

Then:

y=[1,0,0].

Therefore:

\frac{\partial L}{\partial z} = [0.665-1,\;0.245-0,\;0.090-0]
= \boxed{[-0.335,\;0.245,\;0.090]}.

The gradient says:

\boxed{ \text{increase correct-token logit} }

and:

\boxed{ \text{decrease competing logits} }

after the optimizer applies the negative gradient direction.

5.14.25 Where does the gradient go?

The teacher is not part of the computation graph.

The training flow is:

Teacher response
       │
       │ stored as tokens
       ▼
Static dataset
       │
       ▼
Student model
       │
       ▼
logits
       │
       ▼
cross-entropy
       │
       ▼
backpropagation
       │
       ▼
student parameters update

Therefore:

\boxed{ \nabla_{\theta_S}L\neq0 }

while:

\boxed{ \nabla_{\theta_T}L=0 }

because the teacher has already generated the target data and is not being trained alongside the student.

The source explicitly contrasts this with classical KD, where the teacher normally participates during training to produce soft targets. (Source: Build a DeepSeek Model (From Scratch))

5.14.27 Why does this dramatically simplify training?

Classical KD requires:

\boxed{ \text{teacher forward pass} }

for each training batch.

R1 text distillation requires:

\boxed{ \text{teacher inference only once during data generation} }

Then:

\boxed{ \text{student training} = \text{ordinary SFT} }

This is one of the key practical advantages emphasized in the source. (Source: Build a DeepSeek Model (From Scratch))

5.14.28 What happens with padding?

In a real batch, examples have different lengths.

Suppose:

L_1=500,\quad L_2=800,\quad L_3=650.

To batch them, you might pad to:

L_{\max}=800.

Then padded positions must not contribute to loss.

The source's implementation discussion emphasizes excluding padding tokens in practical setups; its simple example avoids batching to keep the code compact, with broader batching discussion deferred elsewhere. (Source: Build a Reasoning Model (From Scratch))

Conceptually:

\boxed{ \text{valid response tokens} \rightarrow \text{loss} }
\boxed{ \text{prompt tokens} \rightarrow \text{no loss} }
\boxed{ \text{padding tokens} \rightarrow \text{no loss} }

5.14.29 Three masks/regions to mentally separate

For a real training sequence, think of three categories:

\boxed{ \begin{array}{c} \text{Prompt}\\ \text{Teacher response}\\ \text{Padding} \end{array} }

Their roles are:

Region Input to model? Contributes to loss?
Prompt Yes No
Teacher response Yes Yes
Padding Padded input No

This is an important implementation pattern.

5.14.30 Why not simply use ignore_index=-100?

That is another common implementation.

You can construct target IDs such that:

prompt targets → -100
response targets → actual token IDs
padding targets → -100

and then:

F.cross_entropy(logits, targets, ignore_index=-100)

But the source's simple implementation does something even more direct:

\boxed{ \text{slice away the prompt region} }

before calling cross-entropy. (Source: Build a Reasoning Model (From Scratch))

So both are conceptually doing:

\boxed{\text{loss masking}}

but the source uses explicit slicing in its compact example.

5.14.31 The source's numerical sanity check

The source reports that the direct cross-entropy computation gives approximately:

\boxed{1.68}

and that this matches the result from its earlier sequence-logprob calculation.

This is important because it validates that:

\boxed{ \text{cross\_entropy} }

is implementing the same underlying quantity as:

\boxed{ -\text{mean log probability of target tokens} }

in this context. (Source: Build a Reasoning Model (From Scratch))

5.14.32 Let's derive that equivalence

For target tokens:

y_1,\ldots,y_N

the mean negative log-likelihood is:

L = -\frac1N \sum_{t=1}^N \log P_S(y_t|x,y_{<t}).

Cross-entropy computes exactly this average over the selected targets.

Therefore:

\boxed{ \text{CrossEntropy} = -\text{mean target-token log probability} }

for the selected positions.

That is why the two source implementations give essentially the same value.

5.14.33 Numerical equivalence

Suppose three teacher target probabilities are:

[0.8,0.5,0.9].

Sequence log probability:

\log P_{\text{seq}} = \ln0.8+\ln0.5+\ln0.9.

Approximately:

-0.223-0.693-0.105 = -1.021.

Mean negative log probability:

\frac{1.021}{3} = \boxed{0.340}.

That exactly matches our cross-entropy calculation.

5.14.34 But don't confuse mean NLL with sequence probability

The sequence probability is:

P_{\text{seq}} = 0.8\times0.5\times0.9 = 0.36.

Sequence negative log probability:

-\ln0.36 \approx1.021.

Mean token-level CE:

\boxed{0.340}.

So:

\boxed{ \text{sequence NLL}=1.021 }

while:

\boxed{ \text{mean token CE}=0.340 }.

They differ by the number of tokens:

1.021/3\approx0.340.

This distinction matters when interpreting reported losses.

5.14.35 Full one-example algorithm

Now write the entire computation as an algorithm.

Step 1

Take:

[\text{prompt}+\text{teacher response}].
Step 2

Convert text to token IDs:

t=[t_1,t_2,\ldots,t_L].
Step 3

Shift:

X=[t_1,\ldots,t_{L-1}]

and:

Y=[t_2,\ldots,t_L].
Step 4

Run the student:

Z=f_{\theta_S}(X).
Step 5

Find:

s=\text{prompt\_len}-1.
Step 6

Keep:

Z_{s:}

and:

Y_s:.
Step 7

Compute:

\boxed{ L= -\frac1N \sum_t \log P_S(Y_t\mid X_{\le t}) }

only over teacher-response targets.

Step 8

Backpropagate:

\nabla_{\theta_S}L.
Step 9

Update:

\theta_S \leftarrow \theta_S-\eta\nabla_{\theta_S}L.

That is the complete distillation training loop for one example.

5.14.36 Why is this still “knowledge distillation”?

Because the student is learning behavior produced by a stronger teacher.

The teacher's knowledge has been converted into:

\boxed{ \text{synthetic supervision} }

and the student absorbs that supervision.

The source explicitly calls this hard distillation and identifies DeepSeek-R1's smaller models as using this approach.

5.14.37 What exactly is transferred?

Not:

\boxed{\text{teacher parameters}}

Not:

\boxed{\text{teacher hidden states}}

Not:

\boxed{\text{teacher logits}}

but:

\boxed{\text{teacher-generated behavior}}

represented as text.

That is why:

\boxed{ \text{R1 distillation = behavior transfer through synthetic text} }

is the best mental model.

5.14.38 Why can a smaller model learn something difficult this way?

Suppose the large teacher has discovered:

\text{problem decomposition} \rightarrow \text{intermediate algebra} \rightarrow \text{verification}.

The student repeatedly sees this mapping.

Instead of discovering the entire strategy through random exploration, it gets thousands or millions of demonstrations of successful trajectories.

Thus:

\boxed{ \text{learning a strategy from demonstrations} }

can be easier than:

\boxed{ \text{discovering the strategy through RL exploration} }.

This is consistent with the source's comparison showing distilled 32B substantially outperforming the RL-only 32B. (Source: Build a DeepSeek Model (From Scratch))

5.14.39 Numerical: direct RL vs distillation

Given:

\text{AIME}_{\text{distill}}=72.6\%
\text{AIME}_{\text{RL}}=47.0\%

the difference is:

72.6-47.0 = \boxed{25.6\text{ percentage points}}.

This is the same architecture size comparison from the source. (Source: Build a DeepSeek Model (From Scratch))

5.14.40 Numerical: prompt indexing

Suppose:

\text{prompt length}=12.

Then:

\text{answer\_start} = 12-1 = \boxed{11}.

If total token length is:

100,

then the shifted target sequence has:

99

positions.

Answer targets begin at index:

11.

Therefore the number of selected teacher-response target positions is:

99-11 = \boxed{88}.

5.14.41 Numerical: exact number of answer positions

Suppose:

L=50

original tokens and:

P=10

prompt tokens.

Then:

\text{input length}=49.
\text{target length}=49.

Answer starts at:

P-1=9.

Therefore:

49-9 = \boxed{40}

target positions contribute to the loss.

That matches:

L-P=50-10=\boxed{40}

teacher-response tokens.

This equality is a useful check:

\boxed{ (L-1)-(P-1)=L-P }

5.14.42 Numerical: cross-entropy

Suppose three target probabilities are:

0.9,\;0.8,\;0.5.

Then:

L = -\frac13 (\ln0.9+\ln0.8+\ln0.5).

Using:

\ln0.9\approx-0.105,
\ln0.8\approx-0.223,
\ln0.5\approx-0.693,

we get:

L = \frac{0.105+0.223+0.693}{3}.
\boxed{L\approx0.340}.

5.14.43 Numerical: teacher response gets longer

Suppose:

\text{prompt}=20\text{ tokens}

and:

\text{teacher response}=180\text{ tokens}.

Original sequence:

L=200.

Shifted sequence length:

199.

Answer start:

20-1=19.

Loss positions:

199-19 = \boxed{180}.

Exactly the number of response tokens.

This is another excellent sanity check.

5.14.44 Numerical: batch size and token workload

Suppose:

B=64

examples and each averages:

T=5,355

teacher-response tokens.

Approximate number of supervised target-token events per batch:

64\times5,355 = \boxed{342,720}.

This illustrates why long reasoning traces create substantial training compute even though the optimization algorithm itself is just ordinary SFT.

The source reports a batch size of 64 for the large-scale distilled models.

5.14.45 Why long sequences matter for memory

Suppose the teacher response grows from:

2,000

to:

8,000

tokens.

That's:

4\times

the sequence length.

The model must process far more token positions, and self-attention has quadratic dependence on sequence length in standard dense attention.

Thus:

\boxed{ \text{long reasoning traces} \rightarrow \text{valuable supervision} }

but also:

\boxed{ \text{long reasoning traces} \rightarrow \text{higher training cost} }.

This is one reason the dataset construction and context-length choices matter.

5.14.46 Why teacher-generated data must be filtered

Suppose 100 teacher outputs contain:

40\text{ correct},
30\text{ incorrect},
20\text{ poorly formatted},
10\text{ incoherent}.

Training blindly on all 100 would expose the student to bad behavior.

Rejection sampling instead aims to retain:

\boxed{\text{correct + well-formatted + high-quality}}

examples.

The source explicitly describes rejection sampling as the process of generating multiple candidates, verifying them, and keeping correct, well-formatted responses. (Source: Build a DeepSeek Model (From Scratch))

5.14.47 This creates a subtle dependency

The quality chain is:

\boxed{ \text{Teacher quality} }
\downarrow
\boxed{ \text{Generated traces} }
\downarrow
\boxed{ \text{Filtering quality} }
\downarrow
\boxed{ \text{Student training data} }
\downarrow
\boxed{ \text{Student quality} }

Therefore:

\boxed{ \text{distillation quality is limited by the quality of the synthetic data} }

This is why the source repeatedly emphasizes data curation.

5.14.48 Why the source prefers built-in cross_entropy

The source first computes sequence log probabilities using a custom method.

Then it directly computes cross-entropy.

Both produce approximately:

\boxed{1.68}

in its example.

Therefore the source uses PyTorch's optimized:

torch.nn.functional.cross_entropy(...)

for actual training rather than the custom sequence-logprob function. (Source: Build a Reasoning Model (From Scratch))

This is a useful engineering lesson:

\boxed{ \text{understand the mathematics manually} }

then:

\boxed{ \text{use optimized library primitives in production} }.

5.14.51 The three key equations

You only need three equations to reconstruct the whole implementation.

1. Shift
\boxed{ X=t[:-1],\qquad Y=t[1:] }
2. Answer-only selection
\boxed{ s=\max(P-1,0) }
\boxed{ X_{\text{loss}}=Z[s:],\qquad Y_{\text{loss}}=Y[s:] }
3. Cross-entropy
\boxed{ L = -\frac1N \sum_{t=1}^{N} \log P_S(y_t|q,y_{<t}) }

Everything else is implementation.

5.14.52 The critical conceptual comparison

RL
\boxed{ \text{model generates} \rightarrow \text{reward} \rightarrow \text{advantage} \rightarrow \text{gradient} }
R1 text distillation
\boxed{ \text{teacher generates} \rightarrow \text{filter} \rightarrow \text{target sequence} \rightarrow \text{cross-entropy} \rightarrow \text{student gradient} }

So the gradient source is fundamentally different.

5.14.53 Why this matters for the whole DeepSeek story

We can now see the complete division of labor:

\boxed{ \text{R1} \rightarrow \text{RL discovers/strengthens reasoning} }

then:

\boxed{ \text{R1} \rightarrow \text{generate successful reasoning traces} }

then:

\boxed{ \text{rejection sampling} \rightarrow \text{curated supervision} }

then:

\boxed{ \text{ordinary SFT} \rightarrow \text{small student learns those traces} }

So the large teacher pays the difficult exploration cost once.

The student then learns through a familiar supervised-learning objective.

in the R1 distilled-model training described by the source.
