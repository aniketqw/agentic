Motivation

Compress frozen-base storage while preserving a trainable high-precision adaptation path.

Prerequisites

  • Bits/bytes
  • Rounding and reconstruction error
  • LoRA frozen/trainable split

Notation and units

  • Symmetric multiplier s=qmax/max|x|; inverse step delta=1/s
  • Affine signed floor=-2^(b-1), ceiling=2^(b-1)-1
  • NF4 is a 16-level nonuniform codebook, not uniform INT4

Assumptions

  • Scalar illustration rounds ties-to-even
  • Explicit clamping at code limits
  • All-zero tensors have zero codes and reconstruction without division
  • Raw storage examples exclude runtime terms

Step-by-step derivation

  1. Map maximum magnitude to qmax, round sx and reconstruct q/s. For un-clipped nearest rounding error≤1/(2s).
  2. For asymmetric multiplier convention derive s=(2^b-1)/(max-min); choose z=round(-s·min)+floor; q=clip(round(sx+z)); reconstruct(q-z)/s.
  3. Do not mix inverse delta=(max-min)/(2^b-1) with multiplier equations; alternatively write q=round(x/delta)+z and reconstruct delta(q-z).
  4. Partition blocks to localize outliers; scales add overhead.
  5. QLoRA stores a frozen NF4 base, reconstructs for higher-precision compute, and learns LoRA factors; NF4 optimality is conditional on the modelled normal weight distribution.
  6. Double quantization reduces block-scale overhead; paged optimizers manage spikes rather than guaranteeing any model fits any device.

Continuation · checked fixture Q02 — Affine zero-point and representability

Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

Shift the integer origin so real zero is represented by a specific code.

Prerequisites: Quantization scale units and rounding

Notation and assumptions

Integer z within range represents zero exactly under xhat=Δ(q-z). Min/max range fitting may round z and change endpoint reconstruction.

Derivation and mechanism

  1. Select step from the chosen real and code spans.
  2. Compute the ideal zero-point, then apply the selected integer rounding/clamping convention.
  3. Verify zero and endpoints after all rounding.

Worked example

Δ.25,z3,range[0,15]: real0 maps to code3 and reconstructs0. Code0 represents-.75; code15 represents3. The real interval follows from stored integer z, not an unrounded ideal offset.

Limitations

  • An all-positive calibration interval does not imply zero lies inside that interval.
  • Per-channel/per-group scales need explicit broadcasting axes and metadata.

Step 3.5 — Quantization → QLoRA

Plan node: I4 · chat order #30

We have reached the natural next step.

With ordinary LoRA, we solved:

\boxed{\text{“How do I train only a tiny fraction of the parameters?”}}

But a second problem remains:

\boxed{\text{“How do I fit the huge frozen base model itself into GPU memory?”}}

That is the problem quantization addresses.

The supplied quantization slides build the foundation using INT8/INT4, scaling, dequantization, block-wise quantization, outliers, clipping, calibration, GPTQ, and QAT. The PEFT slides explicitly place QLoRA after LoRA, and the original QLoRA paper then combines 4-bit quantization with LoRA. (Source: peft-slides)

1. First understand the problem: numbers need memory

A model weight might be stored as FP32.

Each FP32 value uses:

32\text{ bits}=4\text{ bytes}.

Suppose we have:

1,000,000,000

weights.

FP32 memory:

1\times10^9\times4 = 4\times10^9\text{ bytes}

approximately:

\boxed{4\text{ GB}}

just for the weights.

Now use 16-bit precision:

2\text{ bytes/weight}

so:

\boxed{2\text{ GB}}.

Now use 8-bit:

1\text{ byte/weight}

so:

\boxed{1\text{ GB}}.

Now 4-bit:

\frac{4}{8}=0.5\text{ bytes/weight}

so approximately:

\boxed{0.5\text{ GB}}.

This is the fundamental attraction of quantization.

2. What is quantization?

The quantization slides define the basic idea as taking a representation containing more information and discretizing it into one containing less information. The classic example is converting FP32 values to INT8. (Source: quantization-slides)

Conceptually:

\boxed{ \text{many possible real values} \longrightarrow \text{small finite set of representable values} }

For example:

FP32

1.384729
1.392814
1.401294
1.417382
...
millions of possible values

becomes something like:

INT8

... -3 -2 -1 0 1 2 3 ...

The price:

\boxed{\text{less memory + less numerical precision}}

The challenge is to lose as little useful information as possible.

3. Why can't we simply throw away decimal values?

Suppose the original weights are:

[0.91,\ 0.87,\ 0.82,\ -0.76].

If we simply round:

[1,\ 1,\ 1,\ -1]

we destroy a lot of information.

So quantization needs a mapping.

We want:

\boxed{\text{real value}} \rightarrow \boxed{\text{small integer/code}}

and later:

\boxed{\text{code}} \rightarrow \boxed{\text{approximate real value}}.

That is why quantization has two directions:

\boxed{\text{quantize}}

and

\boxed{\text{dequantize}}.

4. INT8 gives us a finite grid

The quantization slides describe signed INT8 as a grid of 256 evenly spaced integer codes, with the symmetric quantization scheme using:

-127,\ldots,0,\ldots,127.

There is no decimal-point concept built into INT8; the quantization scale determines how the real-valued tensor maps onto that grid. (Source: quantization-slides)

Think of this as:

Real number line

----|----|----|----|----|---->
  -10   -5    0    5    10

                ↓ scaling

INT8 grid

-127 ... -64 ... 0 ... 64 ... 127

The key is:

\boxed{\text{scale determines how much one integer step means}}

5. Symmetric quantization

This is the first formula you absolutely need.

Suppose a tensor is:

X=[x_1,x_2,\ldots,x_n].

Find the largest absolute magnitude:

\boxed{ \alpha=\max_i |x_i| }

For b-bit symmetric quantization, the quantization slides define the positive integer limit as:

q_{\max}=2^{b-1}-1.

Then the scale is:

\boxed{ s=\frac{q_{\max}}{\alpha} }

and quantization is:

\boxed{ x_q=\operatorname{round}(sx) }

while dequantization is:

\boxed{ x_{\text{deq}}=\frac{x_q}{s} }

The supplied slides give exactly this formulation. (Source: quantization-slides)

6. Why multiply by s?

This is the part students often memorize without understanding.

Suppose:

\alpha=10.8

and INT8 symmetric range is:

[-127,127].

We want:

10.8\rightarrow127.

Therefore:

s=\frac{127}{10.8} \approx11.76.

So:

10.8\times11.76\approx127.

And:

5.47\times11.76\approx64.33.

Thus:

5.47\rightarrow64.

The slides use exactly this worked example. (Source: quantization-slides)

So the scale is essentially answering:

“How many integer units should represent one real-valued unit?”

7. Full numerical example

Take:

X=[5.47,\ 3.08,\ -7.59,\ 0,\ -1.95,\ -4.57,\ 10.8].

Largest magnitude:

\alpha=10.8.

For INT8:

q_{\max}=127.

Therefore:

s=\frac{127}{10.8} \approx11.76.

Now:

5.47(11.76)\approx64.33

so:

x_q=64.

For 3.08:

3.08(11.76)\approx36.22

so:

x_q=36.

For -7.59:

-7.59(11.76)\approx-89.26

so:

x_q=-89.

And:

10.8(11.76)=127

so:

x_q=127.

Therefore:

\boxed{ X_q=[64,36,-89,0,-23,-54,127] }

The slides show these values explicitly. (Source: quantization-slides)

8. Dequantization

Now suppose the stored value is:

64.

Recover an approximation:

x_{\text{deq}}=\frac{64}{11.76} \approx5.44.

Original:

5.47.

So quantization introduced:

|5.47-5.44| = \boxed{0.03}.

Likewise:

36/11.76\approx3.06.

So the error is:

|3.08-3.06| = 0.02.

The supplied worked example shows these reconstruction errors. (Source: quantization-slides)

9. Where did the error come from?

Notice something very important.

Before rounding:

5.47(11.76)=64.33.

After rounding:

64.

The information loss happens at:

\boxed{\operatorname{round}(\cdot)}

not during ordinary multiplication or division.

That is precisely how the slides frame the symmetric quantization process: the rounding step is the information-losing step. (Source: quantization-slides)

This gives the important chain:

x \rightarrow sx \rightarrow \boxed{\operatorname{round}} \rightarrow x_q \rightarrow \frac{x_q}{s}.

10. Exam numerical: quantization

Suppose:

x=2.4

and

s=10.

Then:

sx=24.

So:

x_q=\operatorname{round}(24)=24.

Dequantize:

x_{\text{deq}}=\frac{24}{10}=2.4.

Error:

\boxed{0}.

Now instead:

x=2.43.

Then:

sx=24.3

and:

x_q=24.

Therefore:

x_{\text{deq}}=2.4.

Error:

|2.43-2.4| = \boxed{0.03}.

11. Why symmetric quantization can be bad

Now imagine:

X=[0.1,\ 0.2,\ 0.3,\ 100].

The maximum absolute value is:

100.

So the entire scale is determined by 100.

For INT8:

s=\frac{127}{100}=1.27.

Now:

0.1(1.27)=0.127

and:

0.2(1.27)=0.254.

Both round to:

0.

So several meaningful small values collapse to the same code.

This is the outlier problem.

The supplied slides explicitly demonstrate that a single extreme value can ruin the precision available to the rest of the tensor. (Source: quantization-slides)

12. Block-wise quantization solves much of this

Instead of using one scale for the entire tensor:

X\rightarrow1\text{ scale}

split it into blocks:

X= \underbrace{B_1}_{\text{scale }s_1} \underbrace{B_2}_{\text{scale }s_2} \underbrace{B_3}_{\text{scale }s_3} \cdots

Then each block gets its own scale.

The QLoRA paper formalizes this as flattening the tensor and dividing it into contiguous blocks, each independently quantized with its own quantization constant.

This is extremely important because an outlier in block 1 does not necessarily ruin the precision of block 2.

13. Tiny block-wise example

Suppose:

X=[0.1,0.2,0.3,100,\quad 2,3,4,5].

With one global scale, the 100 dominates.

Instead make blocks:

B_1=[0.1,0.2,0.3,100]
B_2=[2,3,4,5].

Then:

s_1

is based on 100, while:

s_2

is based on 5.

Therefore the second block gets a much finer representation.

This is one of the key ideas behind modern low-bit weight quantization.

Correction: The asymmetric multiplier must be s=(2^b-1)/(alpha-beta), as quantization-slide page 20 states. Its reciprocal is incompatible with round(sx+z) and (q-z)/s. With inverse step delta, quantize as round(x/delta)+z and reconstruct as delta(q-z). Include signed-code clamping and a constant-range policy.

14. Symmetric vs asymmetric quantization

Symmetric quantization assumes:

[-\alpha,\alpha].

But what if data looks like:

[10,12,15,18,20]?

It is nowhere near symmetric around zero.

The slides therefore introduce asymmetric quantization, which maps the actual minimum and maximum to the full integer range and introduces a zero-point z. (Source: quantization-slides)

Let:

\beta=\min(X)

and

\alpha=\max(X).

For b-bit integer storage:

\boxed{ s= \frac{\alpha-\beta}{2^b-1} }

and:

\boxed{ z= \operatorname{round} \left(-s\beta\right) -2^{b-1} }

under the signed convention used by the slides.

The quantized value has the form:

\boxed{ x_q=\operatorname{round}(sx+z) }

and dequantization:

\boxed{ x_{\text{deq}} = \frac{x_q-z}{s}. }

The zero-point is needed because the real interval may not be centered at zero. (Source: quantization-slides)

15. Intuition for zero-point

Think of symmetric quantization as:

REAL:

      -10          0          +10
        |----------|-----------|

INTEGER:

     -127          0          127

But asymmetric quantization might need:

REAL:

      +10        +15         +20
        |----------|-----------|

INTEGER:

     -128          0          127

There is no reason the real zero has to sit at integer zero.

So:

\boxed{z=\text{shift}}

moves the quantized grid into the correct position.

16. Why QLoRA does not simply use INT4

This is where things become interesting.

If we use ordinary uniform INT4, then we have only:

2^4=16

possible codes.

The quantization levels are essentially uniformly spaced.

But neural-network weights tend to concentrate around zero rather than being uniformly distributed.

The QLoRA paper therefore introduces:

\boxed{\text{NF4 = NormalFloat 4-bit}}

rather than ordinary INT4 for its 4-bit weight representation. The paper describes NF4 as information-theoretically optimal for normally distributed weights.

Hugging Face's documentation likewise describes NF4 as a 4-bit data type designed for normally distributed weights.

17. Why NF4?

Imagine the weight distribution looks approximately like:

              /\
             /  \
            /    \
___________/      \___________
          -      0      +

Most weights are near zero.

So we want:

\boxed{\text{more quantization resolution near zero}}

instead of wasting equal numbers of codes in the tails.

NF4 uses 16 levels derived from quantiles of the standard normal distribution. It is therefore not the same thing as a 4-bit floating-point format with ordinary sign/exponent/mantissa fields.

This distinction is important:

\boxed{\text{NF4}\neq\text{ordinary FP4}}

18. What does “non-uniform levels” mean?

Uniform 4-bit quantization might conceptually look like:

-1  -0.875  -0.75 ... 0 ... 0.75 0.875 1

Every interval is equally spaced.

NF4 instead places levels more densely around the high-probability central region and more sparsely in the tails.

Conceptually:

tail       center             tail

*    *   * **** ** **** *   *    *
          ^^^^^^^^^^^
          more density

So:

\boxed{\text{same 4 bits, better allocation of representational resolution}}

for the weight distribution QLoRA targets.

19. But how can 4-bit weights participate in matrix multiplication?

This is the critical QLoRA trick.

You store the base model's weights in 4-bit form.

But you do not conceptually perform the whole neural-network computation using 4-bit arithmetic.

The QLoRA formulation uses a low-bit storage representation and dequantizes to a higher-precision computation representation. In the paper's formulation, the stored NF4 weights are dequantized to BF16 for computation, while gradients are only needed for the LoRA parameters.

So think:

                 STORAGE
                    ↓
             4-bit NF4 weights
                    ↓
                dequantize
                    ↓
              BF16 computation
                    ↓
                 forward
                    ↓
                backward
                    ↓
          update LoRA parameters

This is the heart of QLoRA.

20. QLoRA = Quantization + LoRA

Now combine the two things we learned.

Ordinary LoRA:

W=W_0+\Delta W

with

\Delta W\approx AB.

QLoRA says:

What if W_0 itself is stored in 4-bit form?

Then:

\boxed{ W_0^{\text{NF4}} }

is frozen.

During computation it is approximately reconstructed:

\boxed{ \operatorname{dequant}(W_0^{\text{NF4}}) \rightarrow W_0^{\text{BF16}} }

and the LoRA branch is added.

The QLoRA paper gives the linear-layer formulation in the form

Y^{BF16} = X^{BF16} \operatorname{doubleDequant} (c_1,c_2,W^{NF4}) + X^{BF16}L_1L_2.

21. Very important: what is trainable?

This is the exam-critical comparison.

Full fine-tuning
W_0

trainable.

LoRA
W_0

frozen,

A,B

trainable.

QLoRA
W_0^{NF4}

frozen,

A,B

trainable.

So:

\boxed{ \text{QLoRA does NOT train the 4-bit base weights} }

It trains the LoRA adapters.

The QLoRA paper explicitly describes gradients being propagated through the frozen quantized model into the low-rank adapters.

22. Then why do gradients “pass through” the quantized model?

Excellent distinction.

Suppose:

Y= XW_q+XAB.

The loss depends on Y.

To calculate how A,B should change, the computational graph still needs derivatives through the operations involving W_q.

But:

\boxed{ \frac{\partial L}{\partial W_q} }

is not used to update the base model.

So:

gradient path:

Loss
  ↓
LoRA output
  ↓
A, B  ← UPDATE

and the gradient calculation passes through

quantized base model
  ↓
but W0 stays FROZEN

This is a subtle but fundamental difference between:

\boxed{\text{gradient computation}}

and

\boxed{\text{parameter update}}.

23. Why do we need double quantization?

Ordinary block-wise quantization needs:

\text{quantized weights} + \text{scale for each block}.

The scale itself is generally stored at higher precision.

Suppose every block contains:

64

weights.

If every block requires one FP32 scale:

32\text{ bits}

per 64 weights.

Overhead per weight:

\frac{32}{64} = 0.5\text{ bits/weight}.

That is surprisingly large.

The QLoRA paper therefore introduces double quantization:

Quantize the quantization constants themselves.

24. Double quantization concept

First quantization:

W \rightarrow W^{4bit} + c_2

where c_2 contains quantization constants such as scales.

Then:

c_2 \rightarrow c_2^{k-bit} + c_1

So:

Original FP32 weights
        |
        | first quantization
        ↓
   4-bit weights + FP32 scales
                    |
                    | second quantization
                    ↓
   4-bit weights + quantized scales + scale-of-scales

The supplied quantization slides explicitly connect nested scale quantization to the same double-quantization idea used by QLoRA. (Source: quantization-slides)

The QLoRA paper reports an average saving of approximately:

\boxed{0.37\text{ bits/parameter}}

from double quantization.

25. Numerical understanding of double quantization

Suppose:

64

weights share a scale.

Without double quantization:

64\times4=256\text{ bytes}

for the 4-bit weights? Careful: 4 bits = 0.5 bytes, so:

64\times0.5 = 32\text{ bytes}.

And one FP32 scale:

4\text{ bytes}.

Thus total:

32+4=36\text{ bytes}

for 64 parameters.

That gives:

\frac{36\times8}{64} = \boxed{4.5\text{ bits/parameter}}

ignoring other metadata.

So “4-bit quantization” does not necessarily mean exactly 4.000 bits/parameter once the required scale information is counted.

Double quantization reduces that overhead further.

26. Double-quantization saving from the QLoRA paper

The paper gives a more detailed example.

For block size:

64

the FP32 second-level constants would contribute:

\frac{32}{64}=0.5

bits per parameter.

After quantizing those constants, the paper reports:

\frac{8}{64} + \frac{32}{64\times256} = 0.127

bits per parameter.

Therefore the saving is:

0.5-0.127 = \boxed{0.373\text{ bits/parameter}}.

This is a very good numerical question.

27. What are paged optimizers?

There is one more QLoRA component.

Even when the model itself fits, training can temporarily require extra memory.

This can happen from:

\boxed{\text{optimizer states}}

or memory spikes associated with long sequences/checkpointing.

QLoRA therefore introduced paged optimizers, using NVIDIA unified memory so optimizer state can be moved between GPU and CPU memory during spikes.

Think:

             GPU memory
        ┌───────────────────┐
        │ active tensors    │
        │ model computation │
        └───────────────────┘
                 ↕
          paging when needed
                 ↕
        ┌───────────────────┐
        │ CPU RAM           │
        │ optimizer states  │
        └───────────────────┘

So the three famous QLoRA ideas are:

\boxed{ \text{NF4} + \text{Double Quantization} + \text{Paged Optimizers} }

The original paper explicitly identifies these three innovations.

Now put everything together.

                     INPUT X

The important arrows are:

\boxed{ W_0:\text{stored low-bit, frozen} }

\boxed{ A,B:\text{higher precision, trainable} }

29. LoRA vs QLoRA

Method Base weights Adapter Main memory idea
Full FT FP16/FP32 + trainable None Expensive
LoRA FP16/FP32 + frozen Trainable Fewer trainable parameters
QLoRA 4-bit + frozen Trainable Fewer trainable params and smaller base-weight storage

Thus:

\boxed{ \text{LoRA solves training-parameter memory} }

while

\boxed{ \text{QLoRA additionally attacks base-model memory} }

30. Memory numerical: 7B model

Suppose a model has:

7\times10^9

parameters.

Approximate weight storage:

FP32
7\times10^9\times4 \approx \boxed{28\text{ GB}}
FP16
7\times10^9\times2 \approx \boxed{14\text{ GB}}
INT8
7\times10^9\times1 \approx \boxed{7\text{ GB}}
4-bit
7\times10^9\times0.5 \approx \boxed{3.5\text{ GB}}

These are idealized raw-storage calculations and omit scales, metadata, temporary activations, KV cache, and other runtime memory.

But they show why 4-bit storage is so attractive.

31. Memory numerical: 65B model

For:

65\times10^9

parameters:

FP16
65\times10^9\times2 = 130\text{ GB}

just for weights.

The original QLoRA paper reports that conventional 16-bit fine-tuning of a 65B LLaMA model required more than 780 GB of GPU memory, because training requires much more than just storing the weights. QLoRA reduced the reported fine-tuning memory requirement to below 48 GB.

That distinction is crucial:

\boxed{\text{weight memory}\neq\text{total training memory}}

32. Why 4-bit does NOT mean “everything is 4-bit”

This is one of the biggest exam traps.

A QLoRA setup can have:

\boxed{ \text{base storage}=4\text{-bit NF4} }

while:

\boxed{ \text{computation}\approx16\text{-bit} }

and:

\boxed{ \text{LoRA parameters}\approx16\text{-bit} }

The QLoRA paper specifically describes the 4-bit storage datatype being dequantized into BF16 for computation, with LoRA weights operating in higher precision.

So never say:

“QLoRA trains the whole model in 4-bit.”

That is misleading.

A better statement is:

QLoRA stores the frozen base model in a 4-bit representation and performs computation through dequantization while training only the higher-precision LoRA adapters.

33. Quantization vs QAT

The quantization slides also distinguish:

\boxed{\text{PTQ = Post-Training Quantization}}

from:

\boxed{\text{QAT = Quantization-Aware Training}}.
PTQ

Train first:

W_{\text{trained}}

then quantize:

W_{\text{trained}} \rightarrow W_q.

The model never trained while seeing the quantization error.

QAT

The training process includes quantization-like behavior.

The supplied slides describe a “fake” quantization step where values are quantized and immediately dequantized, allowing the forward pass to experience the rounding effects while gradients still flow through the higher-precision computation. (Source: quantization-slides)

This encourages solutions that are more tolerant of the quantization grid. (Source: quantization-slides)

34. Do not confuse QAT with QLoRA

Very important:

\boxed{\text{QAT}\neq\text{QLoRA}}

QAT is a broad training strategy where the model is trained with quantization effects in the loop.

QLoRA is:

\boxed{ \text{4-bit quantized frozen base} + \text{LoRA adapters} }

plus the specific memory-saving techniques of NF4, double quantization, and paged optimizers.

35. One complete mathematical picture

For one linear layer, think of QLoRA approximately as:

\boxed{ Y = X\,\operatorname{Dequant}(W_q) + XAB }

where:

W_q=\text{frozen 4-bit base weights}.

More specifically, with the QLoRA formulation:

\boxed{ Y^{BF16} = X^{BF16} \operatorname{doubleDequant} (c_1,c_2,W^{NF4}) + X^{BF16}L_1^{BF16}L_2^{BF16} }

as given in the QLoRA paper.

And the optimization is conceptually:

\boxed{ \min_{A,B} L\left( X\operatorname{Dequant}(W_q)+XAB \right) }

subject to:

\boxed{W_q\text{ fixed}}.

That is the clean mathematical definition to keep in your head.

36. Exam traps you should know

Trap 1

“4-bit means exactly 4 bits per parameter.”

Not necessarily.

Scales and metadata add overhead.

The quantization slides explicitly show that practical formats can cost more than the nominal weight bit-width. (Source: quantization-slides)

Trap 2

“LoRA and QLoRA both reduce the base model's parameter count.”

No.

They reduce trainable parameters in LoRA and storage precision of the frozen base in QLoRA.

Trap 3

“QLoRA updates the 4-bit weights.”

No.

The base is frozen; gradients are used to update LoRA adapters.

Trap 4

“NF4 is simply INT4.”

No.

NF4 is a non-uniform 4-bit representation designed around normally distributed weights.

Trap 5

“Dequantization means the base model becomes permanently FP16.”

No.

The idea is to keep the compact low-bit representation for storage and reconstruct higher-precision values when needed for computation.

40. What you should now be able to explain without memorizing

A good exam/interview explanation is:

Quantization reduces the number of bits used to represent model values, reducing memory at the cost of some numerical precision. In symmetric quantization, the tensor is scaled according to its maximum absolute value, rounded to an integer grid, and later dequantized. Block-wise quantization gives different blocks different scales to reduce outlier effects. QLoRA combines this idea with LoRA: the pretrained base model is kept frozen in a 4-bit representation, typically NF4, dequantized for higher-precision computation, while only the LoRA adapters are trained. Double quantization further compresses the quantization constants, and paged optimizers help manage training-time memory spikes. (Source: quantization-slides)
