    Continuation · checked fixture D01 — Greedy versus beam search

    Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

    A locally best token need not lead to the globally best fixed-length continuation.

    Prerequisites: Conditional sequence probability and log likelihood

    Notation and assumptions

    Fixed two-step tree, beam width B, cumulative natural log probability. No EOS, length normalization or constraints in this fixture.

    Derivation and mechanism

    1. Greedy keeps one partial sequence. Beam retains B.
    2. Expand each surviving prefix using its own conditional distribution.
    3. Add log probabilities, rank the union, retain B again.

    Worked example

    Slide9: bright=.5,sunny=.35,cold=.15. bright→outside=.5; sunny→outside=.95. Greedy yields .5×.5=.25. Width2 keeps sunny and finds .35×.95=.3325. It also retains bright outside=.25.

    Limitations

    • Finite-width beam is approximate, not an exact global optimizer.
    • A wider beam need not improve human quality; pruning/early stopping/EOS conventions matter.

    Connections to later concepts

    • D02 changes beam rankings by replacing raw sequence likelihood with a normalized score.

    Continuation · checked fixture D02 — Beam length-score conventions

    Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

    Sequence lengths change cumulative log scores; an explicit normalization can change rankings.

    Prerequisites: Greedy versus beam search

    Notation and assumptions

    GNMT variant lp=((5+length)/6)^alpha. Log probabilities are negative. This is distinct from length^alpha in other implementations.

    Derivation and mechanism

    1. Compute the raw sum of conditional log probabilities.
    2. Compute the selected length penalty.
    3. Divide the raw log score; compare candidates using the same convention.
    s(Y)=\log P(Y)/[((5+|Y|)/6)^\alpha]

    Worked example

    At alpha=.6, two tokens each .6 score≈-.9314; four each .75 score≈-.9022. Raw probabilities favor the shorter sequence; this normalization favors the longer. That is a design choice, not proof of correctness.

    • Length normalization changes the objective and does not certify output quality.

    Step 2.1 — Decoding: From a Probability Distribution to an Actual Token

    Plan node: I2 · chat order #21

    We have completed the Transformer itself.

    The model ultimately produces:

    \boxed{ P_\theta(x_{t+1}\mid x_{\le t}) }

    a probability distribution over the vocabulary.

    But there is a crucial gap:

    A probability distribution is not yet a generated token.

    The model might say:

    P(\text{cat})=0.45
    P(\text{dog})=0.35
    P(\text{car})=0.10
    P(\text{bird})=0.10.

    Something must decide which token to actually output.

    That process is called:

    \boxed{\text{Decoding}}

    Your decoding slides explicitly frame decoding as the process of choosing tokens from the model's probability distribution, and distinguish strategies such as greedy decoding, beam search, and sampling. (Source: decoding-sampling-slides)

    2.1.1 First Understand the Boundary

    We should clearly separate model prediction from decoding.

    The model does:

    \boxed{ \text{context} \rightarrow \text{logits} \rightarrow \text{softmax} \rightarrow \text{probability distribution} }

    Then decoding does:

    \boxed{ \text{probability distribution} \rightarrow \text{chosen token} }

    So:

    \boxed{ \text{Transformer} \neq \text{decoding strategy} }

    The Transformer produces the distribution.

    The decoding algorithm chooses what to do with it.

    This distinction becomes extremely important later when we compare:

    • greedy,
    • beam search,
    • temperature sampling,
    • top-k,
    • top-p.

    2.1.2 Why Doesn't the Model Just Output the Highest Probability?

    Sometimes it does.

    That is called:

    \boxed{\text{Greedy decoding}}

    But choosing the highest-probability token at the current step can fail to produce the highest-probability sequence overall.

    This is the central reason we need to study multiple decoding strategies.

    Your decoding slides make exactly this point: greedy is cheap and deterministic, but it is myopic—it optimizes the immediate choice rather than the whole sequence. (Source: decoding-sampling-slides)

    2.1.3 Greedy Decoding

    The rule is:

    \boxed{ y_t= \arg\max_v P_\theta(v\mid y_{<t},x) }

    where:

    • v = candidate vocabulary token,
    • y_{<t} = previously generated tokens,
    • x = prompt/input context.

    In other words:

    At each step, pick the token with the largest current probability.

    Your decoding source uses this as the basic deterministic decoding strategy. (Source: decoding-sampling-slides)

    2.1.4 Numerical Example — One Step

    Suppose the model gives:

    Token Probability
    bright 0.50
    sunny 0.35
    cold 0.15

    Greedy asks:

    \arg\max[0.50,0.35,0.15].

    Therefore:

    \boxed{\text{bright}}

    is selected.

    This exact example appears in your decoding slides. (Source: decoding-sampling-slides)

    2.1.5 What Happens After Choosing "bright"?

    The model now receives the expanded context:

    The weather today is bright

    and produces a new distribution.

    Suppose:

    Token Probability
    outside 0.50
    today 0.30
    again 0.20

    Greedy again chooses:

    \boxed{\text{outside}}

    So the generated sequence becomes:

    bright outside

    The slides use exactly this example. (Source: decoding-sampling-slides)

    2.1.6 Sequence Probability

    Now comes an extremely important mathematical concept.

    For a sequence:

    Y=(y_1,y_2,\ldots,y_T),

    the probability is:

    \boxed{ P(Y\mid X) = \prod_{t=1}^{T} P(y_t\mid y_{<t},X) }

    This comes directly from the chain rule.

    So for:

    bright outside

    if:

    P(\text{bright}\mid X)=0.50

    and:

    P(\text{outside}\mid X,\text{bright})=0.50,

    then:

    P(\text{bright},\text{outside}\mid X) = 0.50\times0.50
    \boxed{ =0.25 }

    The decoding slide gives this exact numerical result. (Source: decoding-sampling-slides)

    2.1.7 Why Does This Create a Problem for Greedy Decoding?

    Because greedy chooses:

    \boxed{ \text{best next token} }

    not:

    \boxed{ \text{best complete sequence}. }

    Let's modify the example.

    At step 1:

    Token Probability
    bright 0.50
    sunny 0.35
    cold 0.15

    Greedy chooses:

    \boxed{\text{bright}}

    because:

    0.50>0.35>0.15.

    Now suppose the second-step probabilities are:

    If first token = bright
    P(\text{outside}\mid\text{bright})=0.50.

    So:

    P(\text{bright outside}) = 0.50(0.50) = 0.25.
    If first token = sunny

    Suppose:

    P(\text{outside}\mid\text{sunny})=0.95.

    Then:

    P(\text{sunny outside}) = 0.35(0.95)
    = \boxed{0.3325}.

    Thus:

    0.3325>0.25.

    So the globally better sequence is:

    \boxed{\text{sunny outside}}

    even though "sunny" had a lower first-step probability.

    This exact construction appears in the decoding slides. (Source: decoding-sampling-slides)

    2.1.8 This Is the Core Problem With Greedy

    Greedy sees:

    0.50>0.35

    and commits immediately to:

    \boxed{\text{bright}}.

    But the future says:

    0.35\times0.95 > 0.50\times0.50.

    Therefore:

    \boxed{ \text{locally best} \neq \text{globally best}. }

    This is called the myopic nature of greedy decoding.

    2.1.9 Why Does the Probability Become a Product?

    Because of the chain rule.

    For:

    Y=(y_1,y_2,y_3),

    we have:

    P(y_1,y_2,y_3\mid X)
    = P(y_1\mid X) P(y_2\mid y_1,X) P(y_3\mid y_1,y_2,X).

    So:

    \boxed{ P(Y\mid X) = \prod_t P(y_t\mid y_{<t},X). }

    The model itself predicts these conditional probabilities one step at a time.

    A sequence score therefore combines all those local decisions.

    2.1.10 Why Do We Usually Use Log-Probabilities?

    Suppose a sequence has 100 tokens.

    Each token probability might be around:

    0.1.

    Then:

    0.1^{100}

    is extremely tiny.

    Numerically, repeated multiplication can underflow.

    So instead of multiplying probabilities, we take logarithms.

    Recall:

    \log(ab)=\log a+\log b.

    Therefore:

    \boxed{ \log P(Y\mid X) = \sum_t \log P(y_t\mid y_{<t},X) }

    This is much easier numerically.

    The decoding slides explicitly mention scoring sequences with total probability or log-probability to avoid tiny products underflowing. (Source: decoding-sampling-slides)

    2.1.11 Numerical — Product vs Log

    Suppose:

    p_1=0.8,\quad p_2=0.5,\quad p_3=0.25.

    Sequence probability:

    P=0.8(0.5)(0.25)
    =\boxed{0.10}.

    Log probability:

    \log P = \log0.8+\log0.5+\log0.25.

    Using natural log:

    \ln0.8\approx-0.2231
    \ln0.5\approx-0.6931
    \ln0.25\approx-1.3863.

    Therefore:

    \boxed{ \log P\approx-2.3025. }

    And indeed:

    e^{-2.3025}\approx0.10.

    So the two scoring methods are mathematically equivalent:

    \boxed{ P\leftrightarrow\log P. }

    The log form is usually more convenient computationally.

    2.1.12 Why Are Log Probabilities Negative?

    Because probabilities lie in:

    0<p\le1.

    And:

    \log(p)\le0.

    For example:

    \ln1=0
    \ln0.5<0
    \ln0.1<0.

    Therefore:

    \boxed{ \text{higher probability} \rightarrow \text{less negative log-probability}. }

    Example:

    \ln0.9\approx-0.105

    while:

    \ln0.1\approx-2.303.

    So:

    -0.105>-2.303.

    Thus maximizing probability is equivalent to maximizing log probability.

    2.1.13 Greedy Decoding and Log Probability

    At one step:

    \arg\max_v P(v\mid context)

    is equivalent to:

    \arg\max_v \log P(v\mid context).

    Because log is monotonic.

    So greedy could be implemented from:

    • probabilities, or
    • logits/log-probabilities.

    2.1.14 Even More Directly: Greedy Can Use Logits

    Remember:

    p_i=\operatorname{softmax}(z_i).

    Softmax preserves ordering.

    Therefore:

    \boxed{ \arg\max_i z_i = \arg\max_i p_i. }

    So to choose the greedy token, we do not actually need to explicitly calculate the softmax probabilities.

    We can simply calculate:

    \boxed{ y_t=\arg\max_i z_i. }

    This is computationally convenient.

    2.1.15 Numerical Example — Logits to Greedy Token

    Suppose the model outputs:

    z=[2.1,\;0.5,\;4.2,\;1.3].

    The maximum is:

    4.2.

    Therefore:

    \boxed{ \text{token 3} }

    is the greedy choice.

    We could compute softmax first, but it would not change which token has the highest probability.

    2.1.16 The Autoregressive Loop

    Greedy decoding can be written as:

    Prompt
  ↓
Model
  ↓
Logits
  ↓
argmax
  ↓
Next token
  ↓
Append token
  ↓
Model again
  ↓
Logits
  ↓
argmax
  ↓
Next token
  ↓
...

    Mathematically:

    y_t = \arg\max_v P(v\mid y_{<t},X).

    Then:

    y_{<t+1} = (y_1,\ldots,y_t).

    The new token becomes part of the context for the next prediction.

    Raschka's text-generation implementation follows this iterative pattern: obtain logits, focus on the last time step, choose a token, append it, and repeat. (Source: Build a Large Language Model (From Scratch))

    2.1.17 Numerical: Three-Step Greedy Generation

    Suppose the model gives:

    Step 1
    P=[0.5,0.35,0.15].

    Choose:

    \boxed{1}.
    Step 2

    Conditioned on token 1:

    P=[0.2,0.7,0.1].

    Choose:

    \boxed{2}.
    Step 3

    Conditioned on tokens 1,2:

    P=[0.4,0.1,0.5].

    Choose:

    \boxed{3}.

    So greedy generates:

    \boxed{[1,2,3]}.

    Its sequence probability is:

    0.5\times0.7\times0.5
    = \boxed{0.175}.

    2.1.18 A Crucial Question: Why Not Search Every Possible Sequence?

    Suppose vocabulary size is:

    V=50,000.

    For one step:

    50,000

    possible choices.

    For two:

    50,000^2.

    For three:

    50,000^3.

    For T tokens:

    \boxed{ 50,000^T }

    possible sequences.

    This becomes astronomically large.

    Therefore exhaustive search is impractical.

    This motivates approximate decoding strategies.

    2.1.19 Search-Space Numerical

    Suppose:

    V=10

    and:

    T=5.

    Then exhaustive sequence count is:

    10^5 = \boxed{100,000}.

    At:

    T=20:
    10^{20}.

    Already enormous.

    For:

    V=50,000

    and:

    T=20:
    50,000^{20}

    which is completely infeasible to enumerate.

    So decoding is fundamentally a search problem under a huge branching factor.

    2.1.20 Beam Search: The Next Idea

    Greedy keeps:

    \boxed{1}

    partial sequence.

    Beam search keeps:

    \boxed{B}

    partial sequences.

    Here:

    B

    is called the beam width.

    The decoding source defines the procedure as:

    1. keep the best partial sequences,
    2. expand them,
    3. score the resulting candidates,
    4. prune down to the top B,
    5. repeat.

    (Source: decoding-sampling-slides)

    2.1.21 The Key Relationship

    If:

    B=1,

    beam search becomes:

    \boxed{\text{greedy decoding}}.

    Why?

    Because you keep exactly one candidate after every step.

    The slides explicitly make this point. (Source: decoding-sampling-slides)

    Thus:

    \boxed{ BeamSearch(B=1)=Greedy. }

    2.1.22 Simple Beam-Width Example

    Suppose the first-step probabilities are:

    Token Probability
    bright 0.50
    sunny 0.35
    cold 0.15

    With:

    B=1,

    keep:

    \boxed{\text{bright}}.

    With:

    B=2,

    keep:

    \boxed{\text{bright},\text{sunny}}.

    The "cold" branch is discarded.

    So beam search keeps multiple possibilities alive.

    2.1.23 Why Does This Help?

    Because we saw earlier:

    \text{sunny}

    was initially second-best:

    0.35<0.50.

    Greedy throws it away immediately.

    Beam width 2 keeps it alive.

    Then later, if:

    P(\text{outside}\mid\text{sunny})=0.95,

    the sequence:

    \text{sunny outside}

    can overtake:

    \text{bright outside}.

    So beam search introduces a limited amount of look-ahead.

    2.1.24 Beam Search Numerical

    Suppose:

    B=2.

    At step 1:

    A:0.50,\quad B:0.35,\quad C:0.15.

    Keep:

    A,B.

    At step 2:

    For A:

    A\rightarrow X:0.50
    A\rightarrow Y:0.30

    For B:

    B\rightarrow X:0.95
    B\rightarrow Y:0.05.

    Now compute sequence probabilities.

    AX
    0.50\times0.50=0.25.
    AY
    0.50\times0.30=0.15.
    BX
    0.35\times0.95=0.3325.
    BY
    0.35\times0.05=0.0175.

    The top two are:

    \boxed{BX=0.3325}

    and:

    \boxed{AX=0.25}.

    So beam search keeps those two.

    This is already better than greedy's single path.

    2.1.25 Why Do We Use Log Scores in Beam Search?

    Rather than:

    P(y_1,\ldots,y_t) = \prod_{i=1}^{t}p_i,

    we can maintain:

    \boxed{ \log P(y_1,\ldots,y_t) = \sum_{i=1}^{t}\log p_i. }

    Suppose:

    \log p_1=-0.693

    and:

    \log p_2=-0.051.

    Then sequence log probability is:

    -0.693-0.051 = -0.744.

    This is much easier to update incrementally:

    \boxed{ score_{new}=score_{old}+\log p_{new}. }

    No repeated multiplication is necessary.

    2.1.26 Beam Search Algorithm Conceptually

    Suppose:

    B=3.
    Start
    \{\epsilon\}

    where \epsilon is the empty sequence.

    Expand

    Generate all possible next-token extensions.

    Score

    Use:

    \text{score}(Y)=\log P(Y\mid X)

    or another beam score.

    Prune

    Keep only the best 3.

    Then:

    \boxed{ \text{expand}\rightarrow\text{score}\rightarrow\text{prune} }

    repeat.

    2.1.27 But Beam Search Has Another Problem: Length

    Consider two sequences.

    Sequence A
    P(A)=0.8.
    Sequence B

    Suppose it has two token probabilities:

    0.7,\;0.7.

    Then:

    P(B)=0.49.

    No surprise that A is higher.

    But as sequence length grows, multiplying values smaller than 1 repeatedly shrinks the probability.

    For example:

    0.8^5=0.32768
    0.8^{20}\approx0.0115.

    So raw sequence probabilities naturally get smaller as sequences become longer.

    That creates a length bias.

    2.1.28 Why This Is a Problem

    Suppose:

    Sequence A

    5 tokens with average probability 0.8:

    P(A)\approx0.8^5=0.32768.
    Sequence B

    10 tokens with average probability 0.8:

    P(B)\approx0.8^{10}=0.10737.

    Even though both have exactly the same average local probability of 0.8, the longer sequence gets a much smaller joint probability.

    Therefore maximizing raw:

    P(Y)

    can prefer shorter sequences.

    This is why beam search often uses length normalization.

    Your decoding slides identify length normalization as a key part of beam-search scoring. (Source: decoding-sampling-slides)

    2.1.29 Length Normalization

    The decoding slides use the formulation:

    \boxed{ lp(Y) = \frac{(5+|Y|)^\alpha}{(5+1)^\alpha} }

    and score:

    \boxed{ s(Y) = \frac{\log P(Y)} {lp(Y)}. }

    (Source: MASTER_Mathematical_Cheatsheet_All_Lecture_PDFs_v2)

    Here:

    • |Y| = sequence length,
    • \alpha = length-normalization strength.

    The idea is:

    \boxed{ \text{penalize length less harshly than raw probability does}. }

    We will derive this carefully in the next decoding step because it produces good exam numericals.

    2.1.30 Deterministic vs Stochastic Decoding

    We can now divide decoding strategies into two broad categories.

    Deterministic

    Same model + same prompt + same decoding settings gives the same output.

    Examples:

    \boxed{\text{Greedy}}

    and typically:

    \boxed{\text{Beam search}}

    depending on implementation and tie handling.

    Stochastic

    The next token can vary across runs.

    Example:

    \boxed{\text{Sampling}}

    because a token is sampled from the probability distribution.

    Your decoding slides explicitly distinguish reproducibility/debugging use cases from tasks where variety is useful. (Source: decoding-sampling-slides)

    2.1.31 Why Would We Ever Want Randomness?

    Suppose:

    P= [0.40,0.35,0.25].

    Greedy always picks:

    \boxed{\text{token 1}}.

    Sampling could produce:

    \text{token 1}

    40% of the time,

    \text{token 2}

    35%,

    and:

    \text{token 3}

    25%.

    Thus different generations can be produced from the same prompt.

    This can be useful when multiple outputs are valid, such as stories or brainstorming; the slides explicitly frame sampling as useful for such diversity-oriented tasks. (Source: decoding-sampling-slides)

    2.1.32 But Random Sampling Has a Problem

    Suppose:

    P= [0.95,0.01,0.01,0.01,0.01,0.01].

    Sampling from the complete vocabulary technically allows the tiny-probability tokens too.

    A very unlikely token could be selected.

    That motivates filtering methods such as:

    \boxed{\text{Top-k}}

    and later:

    \boxed{\text{Top-p / nucleus sampling}}.

    2.1.33 Numerical: Top-k

    Suppose:

    Token Probability
    A 0.40
    B 0.25
    C 0.15
    D 0.10
    E 0.06
    F 0.04

    Choose:

    k=3.

    Keep:

    A,B,C.

    Set:

    D,E,F\rightarrow0.

    But now:

    0.40+0.25+0.15=0.80.

    These do not sum to 1.

    Therefore we renormalize.

    The new probabilities are:

    P'(A)=\frac{0.40}{0.80}=0.50
    P'(B)=\frac{0.25}{0.80}=0.3125
    P'(C)=\frac{0.15}{0.80}=0.1875.

    So:

    \boxed{ P'=[0.50,0.3125,0.1875]. }

    This is the core operation of top-k filtering.

    Raschka's source implements this by replacing logits below the k-th largest logit with -\infty, then applying softmax again. (Source: Build a Large Language Model (From Scratch))

    2.1.34 Why Top-k Works at the Logit Level

    Suppose:

    z=[5,4,2,-1,-3].

    For:

    k=2,

    keep:

    5,\;4.

    Replace the others with:

    -\infty.

    So:

    z'=[5,4,-\infty,-\infty,-\infty].

    Softmax then gives probabilities only to the two retained tokens.

    This is exactly analogous to the causal-mask mechanism we learned earlier:

    -\infty \rightarrow e^{-\infty}=0.

    Notice how concepts from the Transformer section reappear in decoding.

    2.1.35 A Unified View of Filtering

    Causal masking:

    \text{forbid future tokens}

    using:

    -\infty.

    Top-k:

    \text{forbid low-ranked tokens}

    using:

    -\infty.

    So mathematically both use the same powerful idea:

    \boxed{ \text{remove a candidate by giving its logit }-\infty. }

    The reason for excluding the candidate is different.

    2.1.36 The Decoding Pipeline

    We now have:

    \boxed{ \text{Model} \rightarrow \text{logits} \rightarrow \text{optional filtering/scaling} \rightarrow \text{softmax} \rightarrow \text{selection/sampling} \rightarrow \text{next token} }

    Examples:

    Greedy
    z \rightarrow \arg\max
    Sampling
    z \rightarrow softmax \rightarrow sample.
    Temperature sampling
    z \rightarrow \frac zT \rightarrow softmax \rightarrow sample.
    Top-k sampling
    z \rightarrow \text{top-k filter} \rightarrow \frac zT \rightarrow softmax \rightarrow sample.

    This gives us the roadmap for the remainder of decoding.

    2.1.37 Numerical Complexity of Greedy vs Beam Search

    Suppose vocabulary size:

    V=50,000

    and generated length:

    T=100.
    Greedy

    At each step, we examine approximately V candidate tokens.

    Rough conceptual search work:

    O(TV).
    Beam width B

    You maintain B sequences and expand them.

    A simplified conceptual view is roughly:

    O(TBV)

    before accounting for efficient top-k selection and implementation details.

    Thus increasing beam width increases search cost.

    This is the fundamental trade-off:

    \boxed{ \text{better search} \leftrightarrow \text{more computation}. }

    2.1.38 A Critical Concept: Decoding Does Not Retrain the Model

    Changing:

    T

    or:

    k

    or:

    B

    does not modify:

    W_Q,W_K,W_V,\ldots

    during generation.

    The model parameters remain fixed.

    Decoding changes how we interpret the model's output distribution.

    So:

    \boxed{ \text{training changes the model} }

    while:

    \boxed{ \text{decoding changes token selection}. }

    2.1.39 Connection to KV Cache

    When generating token after token:

    y_1\rightarrow y_2\rightarrow y_3\rightarrow\cdots

    the model repeatedly runs inference.

    Your DeepSeek-model source explains the redundancy: after a new token is appended, the previous token representations and corresponding Q/K/V computations overlap with the previous pass. (Source: Build a DeepSeek Model (From Scratch))

    This later motivates:

    \boxed{\text{KV caching}}

    which lets us reuse past keys and values during autoregressive decoding.

    So the conceptual chain is:

    \boxed{ \text{autoregressive decoding} \rightarrow \text{repeated inference} \rightarrow \text{redundant past K/V} \rightarrow \text{KV cache}. }

    We'll return to this when we enter the inference-optimization material.

    2.1.40 Exam Numerical — Greedy vs Global Sequence

    This is a high-probability style of question.

    Suppose first-token probabilities are:

    A=0.6,\quad B=0.3,\quad C=0.1.

    Greedy selects:

    \boxed{A}.

    But suppose:

    P(X\mid A)=0.2

    and:

    P(X\mid B)=0.9.

    Then:

    P(AX)=0.6(0.2)=0.12

    while:

    P(BX)=0.3(0.9)=0.27.

    Thus:

    \boxed{ B X }

    is the better two-token sequence.

    Greedy fails because it committed to A too early.

    2.1.41 Exam Numerical — Log-Probability Comparison

    Suppose:

    P(A)=0.6,\qquad P(B)=0.3.

    Then:

    \log P(A)\approx-0.5108
    \log P(B)\approx-1.2040.

    Since:

    -0.5108>-1.2040,

    A is preferred.

    Now suppose:

    P(X\mid A)=0.2

    and:

    P(X\mid B)=0.9.

    Then:

    \log P(AX) = \ln0.6+\ln0.2
    \approx-0.5108-1.6094
    =-2.1202.

    And:

    \log P(BX) = \ln0.3+\ln0.9
    \approx-1.2040-0.1054
    =-1.3094.

    Since:

    -1.3094>-2.1202,

    the BX sequence is better.

    This demonstrates that sequence scoring is additive in log space.

    2.1.42 Exam Numerical — Beam Width

    Suppose:

    V=6

    and:

    B=2.

    At the first step, there are 6 candidates.

    How many are retained?

    \boxed{2}.

    At the next step, each of those 2 sequences is expanded by all 6 tokens:

    2\times6=12

    candidates.

    Then prune back to:

    \boxed{2}.

    So the repeated pattern is:

    2 \rightarrow 12 \rightarrow 2 \rightarrow 12 \rightarrow 2.

    This is beam search in concrete terms.

    2.1.43 Exam Numerical — Top-k

    Given probabilities:

    [0.40,0.25,0.15,0.10,0.06,0.04]

    find the probabilities after:

    k=3.

    We already calculated:

    \boxed{ [0.50,0.3125,0.1875,0,0,0]. }

    Notice the sum:

    0.50+0.3125+0.1875=1.

    Renormalization is essential.

    2.1.44 Exam Numerical — Sequence Count

    If vocabulary size is:

    V=100

    and the model generates:

    T=8

    tokens, exhaustive sequence enumeration requires:

    100^8

    possibilities.

    Since:

    100^8=10^{16},

    we get:

    \boxed{10^{16}}

    candidate sequences.

    That is why practical decoding cannot exhaustively search all possible sequences.

    Your decoding slides provide a useful practical classification:

    Task characteristic Typical strategy
    One/few correct outputs Beam search, often with length normalization
    Many equally valid outputs Temperature + top-k/top-p
    Exact reproducibility Greedy

    (Source: decoding-sampling-slides)

    2.1.46 Important Conceptual Comparison

    Greedy
    \boxed{ \text{one path, no look-ahead} }
    Beam search
    \boxed{ \text{multiple paths, limited look-ahead} }
    Sampling
    \boxed{ \text{randomized path selection} }
    Top-k sampling
    \boxed{ \text{randomized selection from top }k }
    Top-p
    \boxed{ \text{randomized selection from a probability-mass nucleus} }

    2.1.47 One Major Exam Trap

    A student may say:

    "Beam search finds the globally optimal sequence."

    That is too strong.

    Beam search is a heuristic approximate search.

    Why?

    Because it prunes candidates.

    A candidate discarded early can never come back.

    Therefore beam search can still miss the globally highest-probability sequence.

    So:

    \boxed{ \text{Beam search}\neq\text{exhaustive search}. }

    Your production source also notes that beam search can miss better outputs and is not guaranteed to produce the best output. (Source: Building LLMs for Production)

    2.1.48 Another Exam Trap

    A student may say:

    "Greedy chooses the most probable sequence."

    No.

    It chooses:

    \boxed{ \text{the most probable token at each step}. }

    Those are different optimization problems.

    2.1.49 The Complete Decoding Mathematics So Far

    Conditional token distribution
    \boxed{ q_\theta(v\mid y_{<t},x) }
    Greedy
    \boxed{ y_t=\arg\max_vq_\theta(v\mid y_{<t},x) }
    Sequence probability
    \boxed{ P(Y\mid X) = \prod_t q_\theta(y_t\mid y_{<t},X) }
    Sequence log probability
    \boxed{ \log P(Y\mid X) = \sum_t \log q_\theta(y_t\mid y_{<t},X) }
    Beam width
    \boxed{ B=1\Rightarrow\text{greedy}. }
    Top-k principle

    Keep the k largest logits, suppress the rest, then renormalize.
