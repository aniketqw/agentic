Motivation

Separate storage containers, quantization-aware optimization and architectures designed for ultra-low-bit arithmetic.

Prerequisites

  • Block metadata accounting
  • Quantization/dequantization
  • Derivative of rounding and surrogate gradients

Notation and units

  • GGUF container versus Q4_K tensor encoding
  • gamma=mean absolute W; ternary RoundClip(W/(gamma+epsilon),-1,1)
  • STE is a surrogate derivative, not the exact derivative of rounding

Assumptions

  • Ties-to-even examples use NumPy rounding
  • Scale metadata must be counted
  • Performance needs kernels/hardware suited to low-bit arithmetic

Step-by-step derivation

  1. Nested block scales trade local precision against metadata. Effective bits=(payload+scale bits)/weight count.
  2. QAT forward applies fake quantization and reconstructs floats; backward uses a declared gradient surrogate such as STE.
  3. Literal round derivative is zero almost everywhere, so ordinary finite differences of rounded forward cannot validate an STE gradient.
  4. Binary weights select ±input; ternary adds a skip state, but scaling, accumulation and non-linear layers still cost arithmetic.
  5. Ternary entropy upper bound log2(3)=1.5849625 assumes three equally likely states and efficient packing; naive fixed-width codes need 2bits.
  6. Absmean normalization plus clipping constrains every code to{-1,0,1}; zero tensors need epsilon or a special case. Mean centering alone does not guarantee half of values lie on each side.

Corrections and source qualifications

  • heading: 23.; text: Subtracting the mean centers values but does not guarantee half positive and half negative. A highly skewed weight distribution can violate that intuition.
  • heading: 36.; text: Declare rounding ties. NumPy/PyTorch ties-to-even maps .5→0 and 2.5→2, yielding [0,0,-1,1,-1]. The inherited [0,1,-1,1,-1] uses half-away-from-zero.
  • heading: 35.; text: Use RoundClip(W/(gamma+epsilon),-1,1) for clipping and all-zero protection. Absmean quantization does not guarantee most weights are zero.
  • heading: 47.; text: With ties-to-even, [-2,1,.5,0,-1.5] rounds to [-2,1,0,0,-2], then clamps to [-1,1,0,0,-1]. Positive .5→1 assumes another rule.

Step 3.6B — GGUF, K-Quants, QAT, BitNet, and 1.58-bit LLMs

Plan node: I4 · chat order #32

We now finish the major quantization section.

So far we established:

\text{FP32/FP16} \rightarrow \text{INT8/INT4} \rightarrow \text{calibration} \rightarrow \text{GPTQ}

Now the supplied quantization deck moves into four related but distinct ideas:

\boxed{ \text{GGUF/K-quants} \rightarrow \text{QAT} \rightarrow \text{BitNet 1-bit} \rightarrow \text{BitNet b1.58} }

The crucial thing is that these are not interchangeable.

1. First: what problem is GGUF trying to solve?

We already learned block-wise quantization.

Suppose:

W= [B_1,B_2,B_3,\ldots]

and each block gets its own scale:

s_1,s_2,s_3,\ldots

This is better than giving the entire tensor one scale.

But now imagine a large model.

Every block has:

\boxed{\text{quantized weights}+\text{scale}}

So we have introduced metadata overhead.

GGUF's K-quants organize this information more efficiently using two nested levels. (Source: quantization-slides)

2. GGUF is a format, not simply “another 4-bit algorithm”

This distinction is important.

Think of:

\boxed{\text{GGUF}}

as a model-file/storage format used by the llama.cpp ecosystem.

Inside that format, you can have different quantization schemes such as:

\boxed{\text{Q2\_K},\text{ Q4\_K},\text{ Q6\_K},\ldots}

The supplied deck specifically discusses the K-quant family within GGUF. (Source: quantization-slides)

So:

GGUF is the container/format; Q4_K, Q6_K, etc. are quantization levels/schemes within it.

3. Why two levels of blocks?

Ordinary block quantization:

Large tensor
    |
    +--- Block 1 -> scale s1
    |
    +--- Block 2 -> scale s2
    |
    +--- Block 3 -> scale s3

GGUF K-quants:

Large super-block
       |
       +--- sub-block 1 -> scale s1
       |
       +--- sub-block 2 -> scale s2
       |
       +--- sub-block 3 -> scale s3
       |
       +--- ...

The supplied deck describes a super-block containing several sub-blocks, with each sub-block receiving its own scale. (Source: quantization-slides)

Why?

Because we want:

\boxed{\text{fine-grained scaling}}

without the overhead of having completely independent full-precision scale information for every tiny piece.

4. Then GGUF does something clever with the scales

Suppose:

s_1,s_2,s_3,\ldots

are the sub-block scales.

Why store every s_i as a full-precision number?

GGUF can quantize the sub-block scales themselves.

So:

s_i \rightarrow s_i^{q}.

But to reconstruct them, we need another scale:

s_{\text{super}}.

Thus:

\boxed{ \text{weights} \rightarrow \text{sub-block scales} \rightarrow \text{super-block scale} }

The deck explicitly describes this as a second level of quantization and compares the idea to QLoRA's double quantization. (Source: quantization-slides)

5. Visualize the nesting

Think:

                 SUPER-BLOCK
        ┌──────────────────────────┐
        │                          │
        │  Sub-block 1             │
        │  weights + q(scale)      │
        │                          │
        │  Sub-block 2             │
        │  weights + q(scale)      │
        │                          │
        │  Sub-block 3             │
        │  weights + q(scale)      │
        │                          │
        │  Super-block scale        │
        └──────────────────────────┘

This provides two levels of granularity:

\boxed{\text{local scale}}

and:

\boxed{\text{global/super-block scale}}.

6. Why not use one scale for every weight?

Because that would require:

N_{\text{weights}}

scales.

If we have:

7\times10^9

weights, that would be ridiculous metadata overhead.

One scale per huge block is too coarse.

Therefore:

\boxed{ \text{nested blocks} }

provide a compromise between:

\text{precision}

and:

\text{metadata overhead}.

7. Q4_K does not mean exactly 4 bits per parameter

This is an excellent exam trap.

The nominal weight code is:

4\text{ bits}.

But we must also count:

  • sub-block scale information,
  • super-block scale information,
  • other format overhead.

Therefore the effective cost can be larger.

The supplied deck specifically reports:

\boxed{\text{Q4\_K}\approx4.5\text{ bits/weight}}

once scale overhead is included. (Source: quantization-slides)

So:

\boxed{4\text{-bit weight code}\neq4.000\text{ bits/weight overall}}

8. Numerical example: effective bits/weight

Suppose we have:

1000

weights and the total encoded file information works out to:

4500

bits.

Then:

\frac{4500}{1000} = \boxed{4.5\text{ bits/weight}}.

That is the correct way to think about practical quantization cost.

9. Compare Q4_K and Q2_K conceptually

Nominally:

Q2_K\rightarrow2\text{ bits}
Q4_K\rightarrow4\text{ bits}
Q6_K\rightarrow6\text{ bits}.

But the actual effective cost includes scale/metadata overhead.

Therefore lower nominal bit-width does not automatically imply a simple exact:

2,\ 4,\ 6

bits/weight in the stored file.

The supplied deck explicitly frames K-quants as trading weight bit-width against how finely scales are represented. (Source: quantization-slides)

10. GGUF vs QLoRA double quantization

This is another easy place to get confused.

Both use:

\boxed{\text{quantize the quantization constants}}

but they are not the same implementation.

QLoRA

Uses double quantization for its quantization constants in its 4-bit training approach.

GGUF K-quants

Use nested sub-block/super-block scale quantization for efficient model storage.

The supplied deck explicitly says the idea is analogous, but applied in a different integer-format context. (Source: quantization-slides)

So:

\boxed{\text{same high-level idea, different systems}}

11. Now move to QAT

So far, our quantization discussion has mostly been:

\boxed{\text{train first}\rightarrow\text{quantize afterward}}

This is:

\boxed{\text{PTQ = Post-Training Quantization}}

The supplied deck now introduces:

\boxed{\text{QAT = Quantization-Aware Training}}

The difference is fundamental.

12. PTQ

Suppose training produces:

W^*.

Then we quantize:

W^* \rightarrow Q(W^*).

The model never experienced that quantization during training.

So:

TRAIN
  ↓
FP model
  ↓
finished
  ↓
QUANTIZE
  ↓
INT8 / INT4 model

13. QAT

QAT says:

Let training know that quantization is coming.

Conceptually:

TRAINING
   |
   +--> quantization simulation
   |
   +--> model learns
   |
   +--> quantization-aware weights
   |
   ↓
DEPLOYABLE LOW-BIT MODEL

The deck says QAT trains the network while accounting for the quantization grid rather than imposing the grid only after training. (Source: quantization-slides)

14. What is “fake quantization”?

This is the key mechanism.

Suppose:

x

is FP32.

We calculate:

x_q=\operatorname{round}(sx)

and then immediately reconstruct:

\hat x=\frac{x_q}{s}.

So the training graph sees:

x \rightarrow Q(x) \rightarrow D(Q(x)).

The result is not kept compressed permanently.

It's a simulation of what low-bit inference will do.

The supplied slides call this a “fake” quantization step. (Source: quantization-slides)

15. Why do this?

Suppose normal training finds:

W^*.

Imagine W^* lies in a very narrow low-loss region.

After quantization:

W^*\rightarrow Q(W^*)

the small rounding perturbation may push the parameters outside that good region.

So:

\boxed{\text{low training loss before quantization}}

does not guarantee:

\boxed{\text{low loss after quantization}}.

16. Wide minima vs narrow minima

Imagine the loss landscape:

Loss
 ^
 |             narrow minimum
 |                 \/
 |                /  \
 |      wide     /    \
 |     minimum  /      \
 |       \______/        \
 +----------------------------> weights

A narrow minimum is sensitive to small changes.

A wide minimum is more tolerant.

Quantization introduces a perturbation:

W\rightarrow W+\epsilon.

A wide minimum can remain low-loss:

L(W+\epsilon)\approx L(W).

A narrow minimum may become:

L(W+\epsilon)\gg L(W).

The supplied deck uses exactly this wide-vs-narrow-minimum intuition. (Source: quantization-slides)

17. Why QAT can produce more robust weights

Because during training the model repeatedly sees the quantization effect.

Therefore optimization is encouraged toward parameter regions where:

\boxed{\text{quantization perturbations hurt less}}

The supplied slides state that QAT can steer training toward wider minima that tolerate quantization. (Source: quantization-slides)

So:

\boxed{ \text{QAT learns weights that are friendly to the quantization grid} }

rather than:

\boxed{ \text{learn first and hope quantization doesn't break them} }

18. But how can gradients pass through rounding?

This is where implementation becomes subtle.

The exact rounding function:

\operatorname{round}(x)

has zero derivative almost everywhere and is therefore not directly useful for ordinary gradient descent.

The deck does not develop the detailed derivative approximation, but it explains the practical mechanism: forward computation experiences quantization/dequantization while gradients continue in higher precision. (Source: quantization-slides)

The common implementation concept is a straight-through estimator (STE).

For studying the supplied deck, remember:

\boxed{ \text{forward sees rounding} \quad+\quad \text{backward still permits gradient flow} }

rather than trying to differentiate the literal integer rounding operation normally.

19. Numerical QAT example

Suppose:

x=0.83

and:

s=10.

Quantize:

x_q=\operatorname{round}(8.3)=8.

Dequantize:

\hat x=\frac8{10}=0.8.

So the forward pass effectively uses:

\boxed{0.8}

instead of:

0.83.

The training process therefore experiences the same type of perturbation that deployment will encounter.

20. PTQ vs QAT

Property PTQ QAT
Quantization introduced after training during training
Training sees quantization effects no yes
Calibration/training overhead lower higher
Can adapt weights to quantization no yes
Goal compress a finished model train a model robust to low-bit representation

The supplied deck explicitly contrasts the two in terms of whether the model “knew” the quantization was coming. (Source: quantization-slides)

21. Now: BitNet

We have:

\text{QAT}

but BitNet takes the idea much further.

The deck describes BitNet as:

QAT taken to its extreme

Instead of taking an ordinary FP16 Linear layer and later quantizing it, BitNet replaces the Linear layer with a BitLinear layer whose weights are trained to live in extremely low precision from the beginning. (Source: quantization-slides)

So:

\boxed{ \text{Linear} \rightarrow \text{BitLinear} }

22. BitNet 1-bit weights

The first BitNet idea is:

\boxed{ W_q\in\{-1,+1\} }

instead of ordinary floating-point weights.

So every weight is represented by one of just two values:

-1

or:

+1.

The supplied deck calls this 1-bit weight quantization. (Source: quantization-slides)

Correction: Subtracting the mean centers values but does not guarantee half positive and half negative. A highly skewed weight distribution can violate that intuition.

Complete grounded review

23. How are the 1-bit weights produced?

The deck uses:

\boxed{ w_q=\operatorname{Sign}(w-\alpha) }

where:

\alpha=\operatorname{mean}(w).

So we first center weights around their mean.

Then:

w-\alpha

is positive or negative.

The sign function gives:

\operatorname{Sign}(x)= \begin{cases} +1,&x\ge0\\ -1,&x<0 \end{cases}

according to the stated convention.

The supplied slides explain that subtracting the mean centers the weights so that approximately half lie on either side before collapsing them to -1/+1. (Source: quantization-slides)

24. Numerical BitNet example

Suppose:

W= [0.8,\ 0.2,\ -0.1,\ 0.5,\ -0.4].

Mean:

\alpha= \frac{0.8+0.2-0.1+0.5-0.4}{5}
= \frac{1.0}{5} = 0.2.

Center:

W-\alpha = [0.6,\ 0,\ -0.3,\ 0.3,\ -0.6].

Sign:

W_q= [+1,+1,-1,+1,-1].

Thus:

\boxed{ [0.8,0.2,-0.1,0.5,-0.4] \rightarrow [1,1,-1,1,-1] }

25. But 1-bit weights alone aren't enough

The deck doesn't simply say:

“Everything becomes 1 bit.”

Instead, it uses different precisions for different pieces.

The supplied BitLinear pipeline is:

\boxed{ \text{FP16 input} \rightarrow \text{LayerNorm} \rightarrow \text{INT8 activations} \rightarrow \text{1-bit weights} }

then:

\boxed{ \text{matmul} \rightarrow \text{dequantize} \rightarrow \text{FP16 output} }

The deck explicitly gives this pipeline. (Source: quantization-slides)

26. Why INT8 activations instead of 1-bit?

Because activations change with every input.

The deck gives the intuition that activations carry more information and therefore are retained at a finer precision than the weights. (Source: quantization-slides)

So:

\boxed{ W:\text{1-bit} }

while:

\boxed{ X:\text{INT8} }

This is asymmetric precision by design.

27. BitLinear pipeline mathematically

Conceptually:

X \rightarrow X_q

and:

W \rightarrow W_q.

Then:

Y_q=X_qW_q.

Finally recover a higher-precision result:

Y_{\text{deq}}

using the relevant scales.

The deck states that the product is dequantized back to FP16 before leaving the BitLinear layer. (Source: quantization-slides)

28. Why is this computationally interesting?

Now suppose:

w_q\in\{-1,+1\}.

Consider a dot product:

y=\sum_i w_i x_i.

Since:

w_i\in\{-1,+1\},

every term becomes:

w_ix_i= \begin{cases} +x_i,&w_i=+1\\ -x_i,&w_i=-1. \end{cases}

So we no longer need a conventional multiplication for the weight.

Instead:

\boxed{ +x_i\quad\text{or}\quad-x_i }

followed by accumulation.

This is the key intuition behind low-bit/bitwise computation.

29. Numerical 1-bit dot product

Suppose:

x=[3,5,2,7]

and:

w=[+1,-1,+1,-1].

Ordinary multiplication:

(+1)(3)+(-1)(5)+(1)(2)+(-1)(7)
=3-5+2-7
=\boxed{-7}.

Notice:

  • +1\times3=3
  • -1\times5=-5
  • +1\times2=2
  • -1\times7=-7

The multiplication by the binary weight itself is trivial.

Thus:

\boxed{\text{multiply-by-weight becomes sign selection}}

30. Now BitNet b1.58

The next step is even more interesting.

Instead of:

\{-1,+1\},

BitNet b1.58 uses:

\boxed{ \{-1,0,+1\} }

for the quantized weights.

The supplied deck explains that this adds the zero value, creating three possible states. (Source: quantization-slides)

31. Why is it called 1.58 bits?

Three possible states require:

\log_2(3)

bits to represent information theoretically.

Compute:

\log_2(3)\approx1.58496.

Therefore:

\boxed{ \log_2 3\approx1.58 }

Hence the name:

\boxed{\text{BitNet b1.58}}.

The supplied deck explicitly gives this reasoning. (Source: quantization-slides)

32. Why does zero matter?

Suppose:

w_i=0.

Then:

w_ix_i=0.

The input contributes nothing to the dot product.

Therefore:

\boxed{0}

acts like a natural “skip this contribution” state.

This creates a potentially sparse computation.

The deck explicitly connects the ternary weight representation to additions, subtractions, and dropped terms. (Source: quantization-slides)

33. Ternary dot-product example

Suppose:

x=[4,7,3,9,2]

and:

w=[+1,0,-1,+1,0].

Then:

y = (+1)(4) +(0)(7) +(-1)(3) +(+1)(9) +(0)(2)
= 4+0-3+9+0
=\boxed{10}.

No meaningful multiplication remains:

\boxed{4-3+9}

with the zero-weight positions dropped.

34. This is why the computation can become addition/subtraction

For:

w_i\in\{-1,0,+1\},

we have:

w_ix_i \in \{-x_i,0,+x_i\}.

So:

\boxed{ w_ix_i= +x_i,\ -x_i,\ \text{or nothing} }

Therefore:

\boxed{ \text{dot product}\rightarrow \text{additions + subtractions + skips} }

The deck explicitly describes this as the multiplication disappearing. (Source: quantization-slides)

Correction: Use RoundClip(W/(gamma+epsilon),-1,1) for clipping and all-zero protection. Absmean quantization does not guarantee most weights are zero.

Complete grounded review

35. How are b1.58 weights quantized?

The deck changes the normalization strategy here.

Earlier BitNet uses a mean-centering approach.

For b1.58, the supplied deck gives absmean quantization.

Define:

\boxed{ \alpha= \operatorname{mean}(|w|) }

Then:

\boxed{ w_q= \operatorname{round} \left( \frac{w}{\alpha} \right) }

and because the result is restricted to the ternary set:

\boxed{ w_q\in\{-1,0,+1\} }

The supplied slide specifically states that dividing by the mean absolute weight causes most values to round to 0, while larger values round to \pm1. (Source: quantization-slides)

Correction: Declare rounding ties. NumPy/PyTorch ties-to-even maps .5→0 and 2.5→2, yielding [0,0,-1,1,-1]. The inherited [0,1,-1,1,-1] uses half-away-from-zero.

Complete grounded review

36. Numerical b1.58 example

Take:

W=[0.1,\ 0.2,\ -0.3,\ 1.0,\ -0.4].

Calculate mean absolute value:

\alpha = \frac{ |0.1|+|0.2|+|{-0.3}|+|1.0|+|{-0.4}| }{5}
= \frac{0.1+0.2+0.3+1.0+0.4}{5}
= \frac{2.0}{5} = 0.4.

Now divide:

W/\alpha = [0.25,\ 0.5,\ -0.75,\ 2.5,\ -1].

Round:

[0,\ 1,\ -1,\ 3,\ -1].

But b1.58 restricts the values to:

\{-1,0,+1\}.

So values beyond +1 are clipped to +1:

\boxed{ W_q=[0,1,-1,1,-1] }

under the simple clipped-ternary interpretation.

37. Why does zero create sparsity?

Suppose:

W/\alpha

contains many values such as:

0.1,\ 0.2,\ -0.3,\ 0.4.

These are near zero.

Rounding them to the ternary grid gives:

0.

So many weights become:

\boxed{0}.

The deck explicitly notes this as a sparsifying side effect of absmean ternary quantization. (Source: quantization-slides)

Thus b1.58 offers:

\boxed{ \text{low precision} + \text{potential sparsity} + \text{simple arithmetic} }

Suppose we have:

1,000,000,000

weights.

FP16

so:

16\times10^9\text{ bits}

or:

\boxed{2\text{ GB}}

ignoring metadata.

or:

Actual implementation storage is affected by packing and additional scaling information.

39. Important conceptual distinction: QLoRA vs BitNet

They look similar because both involve low-bit weights.

But they solve different problems.

QLoRA
\boxed{ \text{existing pretrained model} + \text{4-bit frozen storage} + \text{LoRA training} }
BitNet
\boxed{ \text{architecture/training designed around ultra-low-bit weights} }

The supplied deck explicitly describes BitNet as replacing ordinary Linear layers with BitLinear layers and training them in the low-bit regime from the outset. (Source: quantization-slides)

So:

\boxed{ \text{QLoRA = PEFT + quantized base} }

whereas:

\boxed{ \text{BitNet = low-bit model architecture/training} }

40. Important conceptual distinction: GPTQ vs BitNet

GPTQ

Post-training:

\boxed{ \text{already-trained model} \rightarrow \text{carefully quantized model} }

using calibration data and output-error-aware compensation.

BitNet

Training itself is designed around low-bit weights:

\boxed{ \text{training and low-bit representation are integrated} }

So:

\boxed{ \text{GPTQ adapts an existing model to quantization} }

while:

\boxed{ \text{BitNet trains the model in the low-bit regime} }
