Step-by-step derivation

  1. R1-Zero applies RL directly to the pretrained base without a preliminary reasoning SFT stage; it still inherits all pretraining knowledge and data.
  2. Accuracy and formatting rewards define a verifiable objective, but correctness-only language in an explanation must not erase the explicit format reward.
  3. R1 uses cold-start SFT, reasoning RL, rejection-sampling plus general-data SFT, then broad-domain RL. Learned preference rewards appear in the final general-task stage.
  4. R1-Zero can contribute useful traces to curation, but this does not mean every R1 weight is obtained by directly continuing the R1-Zero checkpoint.
  5. Language reward is target-language words divided by all counted words; tokenization/language classification and zero-word cases must be declared.
  6. Version matters: R1 v1 reports Zero 71.0 AIME pass@1, while v2 and the supplied slides report 77.9. Epsilon=10 and 400-step reference refresh details are supported by v2.

Step 5.12 — DeepSeek-R1 From Scratch: R1-Zero → R1 → Distill

Plan node: I8 · chat order #53

We now arrive at the most important part of the RL section.

DeepSeekMath gave us:

\boxed{\text{RLVR + GRPO}}

DeepSeek-R1 asks a more ambitious question:

Can a pretrained language model discover strong reasoning behavior through reinforcement learning, without first being shown human-written chain-of-thought?

The answer demonstrated by R1-Zero was yes, for verifiable reasoning tasks. But R1-Zero had important usability problems, which led to the much more carefully engineered DeepSeek-R1 pipeline. (Source: deepseek-r1-slides)

5.12.1 First understand the three names

Do not mix them up.

DeepSeek-R1-Zero

The pure RL experiment.

\boxed{ \text{Base model} \rightarrow \text{GRPO + verifiable rewards} }

No supervised reasoning examples first. (Source: deepseek-r1-slides)

DeepSeek-R1

The final, more usable reasoning model.

\boxed{ \text{SFT} \rightarrow \text{RL} \rightarrow \text{rejection sampling} \rightarrow \text{SFT} \rightarrow \text{final RL} }

It is a pipeline, not simply R1-Zero trained for more steps.

DeepSeek-R1-Distill

Smaller models trained using reasoning data generated by R1.

\boxed{ \text{R1-generated data} \rightarrow \text{SFT on smaller model} }

The supplied slides explicitly state that these distilled models do not repeat the full RL pipeline. (Source: deepseek-r1-slides)

5.12.2 R1-Zero: the central experiment

The key design is surprisingly simple:

\boxed{ \text{DeepSeek-V3-Base} + \text{GRPO} + \text{verifiable correctness reward} }

The model starts without supervised reasoning demonstrations.

The reward is based on whether the final answer is correct on verifiable tasks. (Source: deepseek-r1-slides)

So the model is not told:

“Here is how humans reason. Copy this.”

Instead, it is told implicitly through reward:

“Try to solve the problem. Successful solutions are reinforced.”

5.12.3 Why is this scientifically interesting?

Traditional chain-of-thought training says:

\text{human reasoning trace} \rightarrow \text{SFT} \rightarrow \text{model learns reasoning style}.

But that has an obvious limitation:

\boxed{ \text{the model is constrained by what humans demonstrate} }

R1-Zero asks:

\boxed{ \text{Can RL discover useful reasoning strategies itself?} }

That is the experiment's central design choice. (Source: deepseek-r1-slides)

5.12.4 The reward is extremely important

For a math problem:

q=\text{question}

the model generates:

o\sim\pi_\theta(\cdot|q).

Then a verifier checks:

V(q,o).

For a binary reward:

R(q,o)= \begin{cases} 1,&\text{correct}\\ 0,&\text{incorrect}. \end{cases}

Then GRPO compares multiple responses for the same question.

For example:

R=[1,0,1,0].

Mean:

\mu_R=0.5.

So:

R-\mu_R=[0.5,-0.5,0.5,-0.5].

After normalization:

A_i = \frac{R_i-\mu_R}{\sigma+\epsilon}.

The successful trajectories are pushed upward; unsuccessful trajectories are pushed downward.

That is the mechanism we studied in Steps 5.2–5.10.

5.12.5 The remarkable observation: reasoning emerges

The supplied R1 material describes an “aha moment” in a model response.

The model begins one approach, effectively notices the approach is flawed, interrupts itself, and tries another strategy.

The key point is:

\boxed{ \text{nobody explicitly supervised that exact behavior} }

The behavior emerged under optimization for correctness. (Source: Build a DeepSeek Model (From Scratch))

This is what the source calls emergent reasoning-like behavior.

We must be precise, though:

\boxed{ \text{emergent reasoning-like behavior} \neq \text{proof of human-like reasoning} }

It means the training dynamics produced behaviors resembling reflection, backtracking, and longer reasoning trajectories.

5.12.6 Why did response length grow?

The source reports that during R1-Zero training:

\boxed{\text{accuracy increases}}

and:

\boxed{\text{response length also increases}}

even though there was no explicit reward saying:

“Write longer answers.”

(Source: deepseek-r1-slides)

Why can this happen?

Because longer reasoning gives the model more opportunities to:

\text{try} \rightarrow \text{check} \rightarrow \text{detect mistake} \rightarrow \text{revise} \rightarrow \text{finish}.

If this improves the probability of getting reward 1, then RL can reinforce those longer trajectories.

So:

\boxed{ \text{longer reasoning} \rightarrow \text{higher success probability} \rightarrow \text{positive reinforcement} }

may emerge.

5.12.7 But important: RL did not reward length directly

This distinction is extremely important.

The reward is approximately:

R= \text{correctness}.

Not:

R= \text{length}.

Therefore:

\boxed{ \text{length growth is an emergent consequence of optimization} }

rather than a direct objective.

The source explicitly warns elsewhere that longer output by itself does not constitute better reasoning; length is meaningful when it accompanies better correctness. (Source: Build a DeepSeek Model (From Scratch))

5.12.8 R1-Zero's reported AIME improvement

The supplied R1 slides give a striking result:

\boxed{ 15.6\% \rightarrow 77.9\% }

on AIME 2024 Pass@1 during RL training.

With 16-sample self-consistency:

\boxed{ 86.7\% }

is reported. (Source: deepseek-r1-slides)

So the absolute Pass@1 improvement is:

77.9-15.6 = \boxed{62.3\text{ percentage points}}.

That is enormous.

5.12.9 Numerical question

Suppose a model starts with:

15.6\%

accuracy and ends with:

77.9\%.

Absolute gain:

\boxed{62.3\text{ percentage points}}.

Relative gain:

\frac{77.9-15.6}{15.6}\times100
= \frac{62.3}{15.6}\times100 \approx399.4\%.

So the relative improvement is approximately:

\boxed{399\%}.

Be careful:

62.3\text{ points} \neq 399\%.

5.12.10 Self-consistency connection

We studied self-consistency earlier.

The model generates multiple responses:

o_1,o_2,\ldots,o_K

and takes the majority answer.

R1-Zero gets:

77.9\%

Pass@1 and:

86.7\%

with 16-sample self-consistency in the supplied slide. (Source: deepseek-r1-slides)

This connects three concepts we already learned:

\boxed{ \text{RL training} + \text{sampling} + \text{majority selection} }

5.12.11 But R1-Zero had serious problems

The pure RL experiment was powerful, but it was not a polished assistant.

The supplied R1 slides identify three major problems.

Problem 1 — Poor readability

The reward emphasizes correctness, not human-friendly presentation.

So the model can generate:

\text{correct but chaotic reasoning}.
Problem 2 — Language mixing

DeepSeek-V3-Base is multilingual.

Without language-related constraints, reasoning can switch between languages inside the same response.

Problem 3 — Narrow task specialization

Training heavily on reasoning rewards does not automatically produce a strong general-purpose assistant.

Writing, open-domain QA, and ordinary instruction following are not directly optimized by those reasoning rewards.

(Source: deepseek-r1-slides)

This gives the fundamental lesson:

\boxed{ \text{reasoning ability} \neq \text{complete assistant behavior} }

5.12.12 This motivates DeepSeek-R1

DeepSeek-R1 changes the strategy.

Instead of:

\text{pure RL only},

use:

\boxed{ \text{SFT + RL + data generation + SFT + final RL} }

The four-stage pipeline in the supplied R1 slides is:

\boxed{ \begin{aligned} 1.&\ \text{Cold-start SFT}\\ 2.&\ \text{Reasoning RL}\\ 3.&\ \text{Rejection-sampling SFT}\\ 4.&\ \text{Final RL} \end{aligned} }

Each stage fixes a specific weakness of the previous stage. (Source: deepseek-r1-slides)

5.12.13 Stage 1 — Cold-start SFT

This is the first major difference from R1-Zero.

DeepSeek creates a relatively small collection of:

\boxed{\text{long chain-of-thought examples}}

with:

\boxed{\text{human-friendly conversational structure}}.

The supplied slides describe these as thousands rather than millions of examples. They are collected using few-shot prompting, direct prompting for detailed reasoning/reflection/verification, and manual post-processing of R1-Zero outputs. (Source: deepseek-r1-slides)

Then:

\boxed{ \text{DeepSeek-V3-Base} \rightarrow \text{SFT} \rightarrow \text{Dev-1} }

5.12.14 Why do this?

Because pure RL has to discover too many things simultaneously.

Without cold-start SFT:

\text{RL must discover} \begin{cases} \text{correctness}\\ \text{structured output}\\ \text{readability}\\ \text{useful reasoning style} \end{cases}

With cold-start:

\text{SFT gives initial structure}

then:

\text{RL focuses more strongly on outcome optimization}.

The source describes cold-start SFT as giving the model a better initial reasoning format and a better starting point for subsequent RL. (Source: Build a DeepSeek Model (From Scratch))

5.12.15 This is an important SFT vs RL division

Remember:

\boxed{ \text{SFT = “start behaving like this”} }

while:

\boxed{ \text{RL = “make behaviors producing good outcomes more probable”} }

Therefore they are complementary.

The source explicitly makes this point: SFT is useful for format, style, and imitation, while RL is useful for optimizing outcomes under a reward. (Source: Build a DeepSeek Model (From Scratch))

5.12.16 Stage 2 — Reasoning RL

Now the model is:

\text{Dev-1}.

Apply:

\boxed{\text{reasoning RL}}

using rule-based/verifiable rewards.

This creates:

\boxed{\text{Dev-2}}.

The basic reasoning RL is similar to R1-Zero, but there is one important addition:

\boxed{\text{language-consistency reward}}.

(Source: deepseek-r1-slides)

5.12.17 What is language-consistency reward?

Suppose the target language is English.

A response has 50 words in its reasoning.

If:

45

are English:

R_{\text{language}} = \frac{45}{50} = \boxed{0.90}.

For another response:

33

out of:

60

are English:

R_{\text{language}} = \frac{33}{60} = \boxed{0.55}.

These exact examples appear in the supplied R1 slides. (Source: deepseek-r1-slides)

5.12.18 General formula

The language reward is:

\boxed{ R_{\text{language}} = \frac{ N_{\text{target-language words}} }{ N_{\text{total words}} } }

So:

0\le R_{\text{language}}\le1.

A value close to:

1

means strong consistency with the target language.

5.12.19 Why add this reward?

Because otherwise the model may generate something like:

English reasoning
→
Chinese reasoning
→
English
→
Chinese
→
English

while still getting the correctness reward.

From the model's optimization perspective:

\boxed{ \text{language consistency is irrelevant unless rewarded} }

Therefore the reward must encode the behavior we want.

5.12.20 Reward composition

Conceptually:

\boxed{ R_{\text{total}} = R_{\text{reasoning}} + R_{\text{language}} }

for this stage as depicted in the supplied slides.

The important tradeoff is that adding the language-consistency reward causes a slight accuracy regression, which the source describes as a deliberate readability tradeoff. (Source: deepseek-r1-slides)

This is a beautiful practical lesson:

\boxed{ \text{better reward alignment} \not\Rightarrow \text{every benchmark metric improves} }

You often trade one objective against another.

5.12.21 Numerical example

Suppose:

R_{\text{reasoning}}=1.0

and:

R_{\text{language}}=0.85.

If simply summed:

R_{\text{total}} = 1.0+0.85 = \boxed{1.85}.

This is a source-level conceptual example.

In a real implementation, coefficients can be applied to individual reward components; do not assume every reward is always given equal weight unless the source specifies it.

5.12.22 Stage 3 — Rejection sampling

Now we have a stronger reasoning model:

\boxed{\text{Dev-2}}.

Instead of directly making the next model learn from every generated output, we generate many candidate responses.

For one prompt:

o_1,o_2,\ldots,o_N.

Then filter them.

Keep:

\boxed{\text{high-quality responses}}

and reject:

\boxed{\text{bad responses}}.

The accepted responses become a supervised dataset. (Source: deepseek-r1-slides)

5.12.23 This is NOT RL

This distinction is extremely important.

RL:

\text{response} \rightarrow \text{reward} \rightarrow \text{policy update}.

Rejection sampling:

\text{response} \rightarrow \text{filter} \rightarrow \text{accepted dataset} \rightarrow \text{SFT}.

So:

\boxed{ \text{rejection sampling = data construction} }

not an RL algorithm.

The source explicitly emphasizes this distinction. (Source: Build a DeepSeek Model (From Scratch))

5.12.24 Why does rejection sampling work so well here?

Because RL has already improved the generator.

Suppose the initial model produces:

10\%

high-quality responses.

After reasoning RL, suppose it produces:

50\%

high-quality responses.

Now we can sample many responses and retain only strong ones.

Therefore:

\boxed{ \text{RL improves generator} }

then:

\boxed{ \text{rejection sampling harvests generator's best outputs} }

then:

\boxed{ \text{SFT learns those outputs} }

This is the key data flow from R1-Zero-like reasoning behavior into R1.

5.12.25 Stage 3 dataset composition

The supplied R1 slides describe approximately:

\boxed{600K\text{ reasoning samples}}

and:

\boxed{200K\text{ non-reasoning samples}}.

Total:

\boxed{\sim800K}.

(Source: deepseek-r1-slides)

5.12.26 Why not use only reasoning data?

Because that creates another failure mode.

Imagine training almost entirely on:

\text{math + code + logic}.

The model may become excellent at these tasks but worse at:

  • ordinary conversation,
  • writing,
  • editing,
  • factual QA,
  • general instruction following.

The source explicitly describes this as a reason for adding broader non-reasoning data. (Source: Build a DeepSeek Model (From Scratch))

So the dataset is deliberately mixed:

\boxed{ 600K\text{ reasoning} + 200K\text{ general} }

5.12.27 Stage 3 SFT

The combined dataset is used to fine-tune:

\text{DeepSeek-V3-Base}

to produce:

\boxed{\text{Dev-3}}.

The supplied slides state:

\boxed{\text{2 epochs}}

over approximately 800K examples. (Source: deepseek-r1-slides)

Conceptually:

\boxed{ \text{Dev-2 outputs} \rightarrow \text{filter} \rightarrow \text{600K reasoning} }

plus:

\boxed{ \text{200K general data} }

then:

\boxed{ \text{SFT} \rightarrow \text{Dev-3}. }

5.12.28 Why this stage is so clever

Stage 2 says:

\text{“Discover stronger reasoning.”}

Stage 3 says:

\text{“Turn the discovered behavior into reusable supervised knowledge.”}

So:

\boxed{ \text{RL} \rightarrow \text{data generation} \rightarrow \text{SFT} }

This is the same fundamental bridge we later use for distillation.

5.12.29 Stage 4 — Final RL

Now we have a model that is:

  • good at reasoning,
  • better formatted,
  • better at general tasks.

But the problem becomes:

How do we align the final model with broader human preferences?

This requires more than deterministic math/code verifiers.

So the final stage uses a:

\boxed{\text{hybrid reward}}.

(Source: deepseek-r1-slides; Build a DeepSeek Model (From Scratch))

5.12.30 Reward source depends on the task

For math/code/logic:

\boxed{ R_{\text{reasoning}} = \text{rule-based verifier} }

For open-ended tasks:

\boxed{ R_{\text{general}} = \text{learned reward model} }

The supplied book specifically explains that a deterministic verifier is excellent when a task has an objective answer, but is insufficient for open-ended helpfulness, style, nuanced factuality, or harmlessness. (Source: Build a DeepSeek Model (From Scratch))

5.12.31 Why doesn't RLVR replace reward models completely?

Because not every task has a unique correct answer.

For example:

Math
2+2=4

can be verified.

Coding

Run the test suite.

Open-ended writing

There is not necessarily one mathematically correct output.

Helpfulness

Multiple valid answers may exist.

Harmlessness

This involves preferences and safety judgments, not a single deterministic answer.

Therefore:

\boxed{ \text{RLVR where exact verification exists} }

and:

\boxed{ \text{learned reward where preference judgment is required} }

The source explicitly makes this distinction. (Source: Build a DeepSeek Model (From Scratch))

5.12.32 Final reward structure

The supplied R1 slides show the conceptual form:

\boxed{ R= R_{\text{reasoning}} + R_{\text{general}} + R_{\text{language}} }

with the appropriate terms active for the relevant data. (Source: deepseek-r1-slides)

So the model is not optimized for one objective.

It is optimizing a mixture of objectives.

5.12.33 Why introduce general preference reward only near the end?

This is one of the most interesting engineering decisions.

The supplied slides say that general-preference data and its reward are introduced only in the final 400 of 1,700 steps.

Thus:

\boxed{ 1700-400=1300 }

steps happen before the final general-preference phase.

The motivation is reward hacking: using the model-based preference reward for too long led to undesirable behavior. (Source: deepseek-r1-slides)

5.12.34 Why delay the preference reward?

Because first we want:

\boxed{\text{strong reasoning}}

then:

\boxed{\text{general alignment}}

rather than allowing a broad learned reward to interfere with the reasoning optimization for the whole run.

Conceptually:

First:
reasoning capability
        ↓
strong reasoning model
        ↓
then:
general preference alignment

This is a staged optimization strategy.

5.12.35 Numerical question

Final RL has:

1700

steps.

General-preference reward is introduced for:

400

steps.

Fraction of the run:

\frac{400}{1700} \approx0.2353.

So approximately:

\boxed{23.5\%}

of the final RL stage uses the general-preference component according to the slide's description.

5.12.36 Why the final stage can still have rule-based rewards

Because the model must continue solving reasoning tasks.

So:

\text{math prompt} \rightarrow \text{rule-based correctness}.

While:

\text{general prompt} \rightarrow \text{learned preference reward}.

This is a task-conditional reward architecture.

Now put everything together.

5.12.38 The arrow from R1-Zero to R1 is NOT parameter transfer

This is one of the most important conceptual points.

You might incorrectly imagine:

R1-Zero
   │
   │ copy weights
   ▼
R1

That is not the pipeline described in the source.

Instead:

R1-Zero / RL outputs
          │
          ▼
    sample outputs
          │
          ▼
      filter them
          │
          ▼
   training dataset
          │
          ▼
       SFT model

So:

\boxed{ \text{data flow, not parameter flow} }

The book explicitly emphasizes this. (Source: Build a DeepSeek Model (From Scratch))

5.12.39 Why is this distinction important?

Because RL and SFT are solving different problems.

R1-Zero discovers:

\text{useful reasoning traces}.

Then these traces become:

\text{supervised examples}.

The next model learns from those examples.

Therefore:

\boxed{ \text{RL-generated behavior} \rightarrow \text{training data} \rightarrow \text{SFT} }

This same pattern later becomes:

\boxed{ \text{R1} \rightarrow \text{distillation dataset} \rightarrow \text{small students} }

5.12.40 Why R1 is better than R1-Zero conceptually

R1-Zero is optimized primarily for:

\text{reasoning correctness}.

R1 adds:

\text{readability} + \text{language consistency} + \text{general capability} + \text{preference alignment}.

Therefore:

\boxed{ \text{R1}= \text{reasoning} + \text{usability} }

rather than reasoning alone.

5.12.41 SFT and RL solve different failure modes

This is a very important interview answer.

Pure SFT problem

SFT can imitate known examples very effectively.

But:

\boxed{ \text{human demonstrations limit the discovered behavior} }

because the model is trained on examples humans provided.

Pure RL problem

RL can discover useful behavior under reward.

But it may produce:

\text{poor readability}
\text{language mixing}
\text{narrow specialization}

or reward hacking.

Therefore:

\boxed{ \text{SFT + RL} }

is more powerful than thinking of either as a complete solution. (Source: deepseek-r1-slides; Build a DeepSeek Model (From Scratch))

5.12.42 Failed approach — Process Reward Models

The supplied R1 slides discuss an unsuccessful attempt to use Process Reward Models (PRMs) directly for large-scale RL.

A PRM tries to reward each reasoning step rather than only the final answer.

That sounds attractive:

S_1,S_2,S_3,S_4

each receives feedback.

But the source identifies major difficulties:

\boxed{\text{What exactly is a “step”?}}

and:

\boxed{\text{How do we reliably judge each intermediate step?}}

and:

\boxed{\text{How do we prevent reward hacking?}}

(Source: deepseek-r1-slides)

5.12.43 Why math final answers are easier than process verification

Final answer:

x=83.

Easy to verify.

Intermediate reasoning:

3x - 9 = 2x + 74

Maybe easy.

But in an arbitrary reasoning problem:

“The previous approach seems wrong; let's try another theorem.”

Is that a valid reasoning step?

There may be no simple deterministic checker.

Thus:

\boxed{ \text{outcome verification} }

can scale more readily than:

\boxed{ \text{step-by-step process verification} }.

This explains why final-answer RLVR is so attractive for mathematics.

5.12.44 Failed approach — Monte Carlo Tree Search

The supplied slides also discuss MCTS.

MCTS works beautifully for domains like Go because:

\text{state space}

is structured and the possible actions are well-defined.

Token generation is dramatically different.

At every token, the model can choose among a large vocabulary, and the branching structure grows exponentially with sequence length.

The source therefore argues that directly applying MCTS to language generation does not transfer the AlphaGo recipe cleanly. (Source: deepseek-r1-slides)

5.12.45 The mathematical reason the search space explodes

Suppose vocabulary size is:

V=50,000

and we consider:

T=10

steps.

The naive number of possible sequences is:

V^T = 50,000^{10}.

That is astronomically large.

This is why brute-force search over token trajectories becomes impractical.

5.12.46 The central engineering insight of R1

The model doesn't need to be explicitly told:

\text{“Use strategy X.”}

Instead:

\boxed{ \text{provide a scalable reward} }

and let optimization discover useful trajectories.

For verifiable reasoning:

\text{answer} \rightarrow \text{checker} \rightarrow R.

Then:

R \rightarrow A \rightarrow \text{GRPO} \rightarrow \theta'.

That is the core mechanism.

5.12.47 But reward design controls what emerges

This connects directly to Step 5.8.

Suppose:

R= R_{\text{format}}

only.

The model may learn:

\text{beautiful formatting}.

Suppose:

R= R_{\text{correctness}}

only.

It may learn:

\text{correctness}

but exhibit poor readability or language mixing.

Therefore:

\boxed{ \text{reward = specification of desired behavior} }

This is one of the deepest engineering lessons of the whole R1 pipeline.

5.12.48 Numerical — combined reward

Suppose:

R_{\text{reasoning}}=1

and:

R_{\text{language}}=0.8.

If equally weighted:

R=1+0.8 = \boxed{1.8}.

Now suppose an incorrect answer has:

R_{\text{reasoning}}=0

but:

R_{\text{language}}=1.

Then:

R=1.

This shows exactly why auxiliary rewards can create unintended incentives if they are too strong.

It connects directly to the format-reward failure mode from Step 5.8.

5.12.49 Numerical — rejection sampling

Suppose we generate:

10,000

responses.

After correctness and quality filtering:

2,500

remain.

Acceptance rate:

\frac{2500}{10000} = 0.25.

Therefore:

\boxed{25\%}.

The remaining:

75\%

were rejected.

5.12.50 Numerical — Stage 3 composition

Suppose:

600K

reasoning samples and:

200K

general samples.

Total:

800K.

Reasoning fraction:

\frac{600}{800} = 0.75.

Thus:

\boxed{75\%}

reasoning data.

General fraction:

\boxed{25\%}.

This is a useful exam calculation from the slide's approximate composition.

5.12.51 Numerical — language reward

Target-language words:

72.

Total words:

90.

Then:

R_{\text{language}} = \frac{72}{90} = 0.8.

So:

\boxed{R_{\text{language}}=0.8}.

5.12.52 Numerical — R1 pipeline timing

Suppose final RL has:

1700

steps, of which:

400

contain general-preference reward.

Then:

1300

steps precede that final phase.

Thus:

\boxed{ 76.47\% }

of the steps:

\frac{1300}{1700}\times100 \approx76.47\%

And:

\boxed{23.53\%}

are in the final preference phase.

5.12.57 Exam-style conceptual question

Why is R1-Zero important even though it is not the final R1 system?

Because it isolates an important scientific question:

\boxed{ \text{Can reasoning-like behavior emerge under pure RLVR?} }

By removing supervised reasoning demonstrations, the experiment demonstrates that useful reasoning behaviors can emerge from reinforcement learning on verifiable tasks. (Source: deepseek-r1-slides)

R1 then adds engineering stages to make those capabilities usable.

5.12.58 Exam-style conceptual question

Why not just train R1-Zero longer until it becomes R1?

Because the problems are not merely insufficient training time.

R1-Zero has structural deficiencies:

\text{readability}
\text{language mixing}
\text{general-assistant capability}.

R1 explicitly introduces different training mechanisms to address those issues. The source states that the R1 pipeline is not simply R1-Zero trained longer. (Source: Build a DeepSeek Model (From Scratch))

5.12.59 Exam-style conceptual question

Why is R1 not a “no reward model” system?

Because:

\boxed{ \text{reasoning tasks} \rightarrow \text{rule-based verifier} }

but:

\boxed{ \text{helpfulness/harmlessness/open-ended tasks} \rightarrow \text{learned reward model}. }

The final stage therefore uses a hybrid reward architecture. (Source: Build a DeepSeek Model (From Scratch))

The core lesson of Step 5.12

The DeepSeek-R1 story is not:

\boxed{\text{“Just apply RL to a huge model.”}}

It is:

\boxed{ \text{Use SFT to establish useful behavior} }
\downarrow
\boxed{ \text{Use RLVR to discover/strengthen reasoning} }
\downarrow
\boxed{ \text{Harvest strong outputs through rejection sampling} }
\downarrow
\boxed{ \text{Use SFT to broaden and stabilize behavior} }
\downarrow
\boxed{ \text{Use hybrid final RL for broader alignment} }

That is why the final R1 system is much more than R1-Zero.

The most important conceptual equation for the whole chapter is:

\boxed{ \text{SFT teaches} \quad+\quad \text{RL discovers/optimizes} \quad+\quad \text{rejection sampling harvests} \quad+\quad \text{SFT packages} }

And then:

\boxed{ \text{R1} \rightarrow \text{distillation} \rightarrow \text{small reasoning models}. }

The supplied sources explicitly position DeepSeek-R1-Distill as the next step, where R1's reasoning traces are transferred into smaller Qwen and Llama models through supervised fine-tuning rather than repeating the full RL pipeline. (Source: deepseek-r1-slides)
