Motivation

Audit per-task and per-language comparisons before attributing a gain to specialized pretraining.

Prerequisites

  • Train/dev/test separation and task-specific fine-tuning
  • Tokenizer, vocabulary, multilingual pretraining
  • Accuracy, precision/recall and F1; distinguish points from relative percent
  • Ablation controls and confounding variables

Notation and units

  • L is a language; task and language jointly define an evaluation set
  • Scores are on a declared 0..100 scale; score differences are points
  • Corpus tokens depend on the counting tokenizer and release; a token is not necessarily a word

Assumptions

  • All historical counts are attributed to the supplied release/paper, not presented as live 2026 leaderboard facts
  • Translated parallel examples share content and are not statistically independent across languages
  • Reported scores require fixed checkpoint, preprocessing, split, prompt and metric implementation

Step-by-step derivation

  1. Build columns for each task and rows for exact model variants; choose the strongest baseline per task before counting wins. A family-level envelope across variants is not a single model row.
  2. The7/9 claim compares the IndicBERT v2 family with massively multilingual baselines; preserve the stated variant and source table. A higher mean alone can conceal losses on individual tasks.
  3. Use an MLM-only IndicCorp ablation to test whether parallel data is necessary for the observed gain. It cannot isolate corpus composition from every other architecture/training difference.
  4. Inspect low-resource language scores rather than corpus totals. Lack of data, lack of shared script and absence of a close language correlate with transfer deficits; these observations are not a controlled causal decomposition.
  5. Distinguish percentage-point loss from relative percent decrease: if Hindi80 and another language60, the20-point loss is25% relative to80. The deck wording “25.9% lower” requires source table interpretation; do not casually rename it25.9 points.
  6. Report missing evaluation languages separately;19/24=79.1667% corpus-language coverage does not justify claims on the other5.

    Step 5.30 — Does IndicXTREME Actually Distinguish Good Models?

    Plan node: I10 · chat order #71

    Now we move from benchmark design to the most important question:

    \boxed{ \text{Does this benchmark actually reveal meaningful differences between models?} }

    A benchmark is useful only if strong and weak systems produce distinguishable results.

    \boxed{\text{Yes}}

    and then shows why. (Source: indicxtreme-slides)

    5.30.13 Another important result: IndicBERT-only ablation

    The deck says that the pattern persists even for the ablation trained purely on:

    \boxed{\text{IndicCorp v2}}

    using:

    \boxed{\text{MLM}}

    with:

    \boxed{\text{no parallel data}}.

    The slide's explanation is that models that do not need to share capacity with unrelated high-resource languages perform better on Indic tasks. (Source: indicxtreme-slides)

    This is a very important experiment.

    5.30.14 Why is the ablation important?

    Suppose the improvement came only because the model received a lot of parallel multilingual data.

    Then we might conclude:

    \boxed{ \text{parallel translation data caused the gain} }

    But the IndicCorp-only MLM ablation still performs strongly.

    That suggests:

    \boxed{ \text{Indic-focused monolingual pretraining itself is valuable} }

    in the reported benchmark.

    The source explicitly highlights this observation. (Source: indicxtreme-slides)

    5.30.15 Why does “no parallel data” matter?

    Parallel data looks like:

    \boxed{ \text{sentence in language A} \leftrightarrow \text{corresponding sentence in language B} }

    For example:

    \text{Hindi sentence} \leftrightarrow \text{English sentence}.

    The ablation instead relies purely on:

    \boxed{ \text{IndicCorp v2 + MLM} }

    so the model can learn Indic-language structure directly from monolingual text.

    This makes the experiment stronger evidence for the usefulness of Indic-focused pretraining.

    5.30.16 Think about capacity sharing

    A general multilingual model has to represent:

    \text{English} + \text{Chinese} + \text{Arabic} + \text{Hindi} + \text{Tamil} +\cdots

    inside one model.

    IndicBERT focuses heavily on Indic languages.

    So conceptually:

    \boxed{ \text{shared model capacity} }

    versus:

    \boxed{ \text{Indic-focused capacity} }.

    The deck interprets the ablation result as evidence that avoiding capacity sharing with unrelated high-resource languages can benefit Indic tasks. (Source: indicxtreme-slides)

    5.30.17 Important caution

    Do not turn that into:

    “Multilingual models are bad.”

    The table shows:

    \boxed{ \text{mBERT/XLM-R/MuRIL can be very strong} }

    on particular tasks.

    For example:

    \text{MuRIL Naamapadam}=74.3

    beats the strongest listed IndicBERT-family result:

    66.6.

    And:

    \text{XLM-R IndicXPara}=56.7

    is above the strongest IndicBERT-family result:

    56.4.

    So specialization improves many tasks, but not every one. (Source: indicxtreme-slides)

    5.30.18 Now we move to the bigger issue: language-level performance

    A model can have:

    \boxed{\text{excellent average performance}}

    while still failing badly on particular languages.

    Therefore the researchers break performance down by language.

    This produces the next major result:

    \boxed{ \text{Winners vs Left-Behinds} }

    (Source: indicxtreme-slides)

    5.30.19 What are Winners and Left-Behinds?

    The taxonomy used earlier assigns languages a resource class.

    At one extreme:

    \boxed{ 5=\text{Winner} }

    meaning resource-rich.

    At the other:

    \boxed{ 1=\text{Left-Behind} }

    meaning extremely under-resourced.

    (Source: indicxtreme-slides)

    So the benchmark can ask:

    \boxed{ \text{Does performance track resource availability?} }

    5.30.20 The answer is yes

    The deck says extremely low-resource languages—those below the 10th percentile of the corpus-resource distribution—show a sharp and consistent performance drop. (Source: indicxtreme-slides)

    This is one of the most important findings of the entire IndicXTREME material.

    5.30.21 The concrete COPA example

    On IndicCOPA:

    \boxed{\text{Santhali}}

    scores:

    \boxed{25.9\%}

    lower than Hindi.

    And:

    \boxed{\text{Sindhi}}

    scores:

    \boxed{17.7\%}

    lower than Hindi. (Source: indicxtreme-slides)

    These are percentage-point gaps, not relative percentage reductions.

    That distinction matters.

    5.30.22 Percentage points vs percentage reduction

    Suppose Hindi gets:

    60\%

    and Santhali is:

    25.9\text{ points lower}.

    Then Santhali would be:

    60-25.9 = \boxed{34.1\%}.

    But saying “Santhali is 25.9% worse” would normally suggest a relative reduction:

    60(1-0.259) = 44.46\%.

    That is not what the deck's wording means.

    So:

    \boxed{ 25.9\text{ points lower} \neq 25.9\%\text{ relative lower} }

    Very important exam distinction.

    5.30.23 Why are Left-Behinds performing worse?

    The slide identifies three related causes.

    First:

    \boxed{\text{lack of pretraining data}}

    Second:

    \boxed{\text{no shared script}}

    Third:

    \boxed{ \text{no linguistic “cousin” in the corpus to bridge transfer} }

    (Source: indicxtreme-slides)

    Let's unpack them.

    5.30.24 Cause 1 — Lack of pretraining data

    Suppose Hindi has a huge amount of training text but a low-resource language has very little.

    Then the model receives much more statistical evidence for Hindi.

    Conceptually:

    N_{\text{Hindi}}\gg N_{\text{low-resource}}.

    The model can therefore learn:

    P(\text{patterns}\mid\text{Hindi})

    much more reliably than:

    P(\text{patterns}\mid\text{very-low-resource language}).

    This follows directly from the resource-imbalance problem established earlier in the deck. (Source: indicxtreme-slides)

    5.30.25 Cause 2 — No shared script

    This is particularly interesting.

    Suppose a low-resource language uses a script that is also well represented in the training corpus.

    Then there may be useful shared orthographic patterns.

    But if its script is poorly represented:

    \boxed{ \text{less direct script-level transfer} }

    is available.

    The deck explicitly identifies the lack of a shared script as one of the compounding reasons for the performance drop. (Source: indicxtreme-slides)

    5.30.26 Cause 3 — No linguistic “cousin”

    Suppose a low-resource language has related languages that are well represented.

    Then the model may potentially exploit transfer through shared linguistic structure.

    Conceptually:

    L_{\text{low}} \leftrightarrow L_{\text{related}}

    and:

    L_{\text{related}} \rightarrow \text{learned representations}.

    But if there is no well-represented linguistic cousin in the corpus:

    \boxed{ \text{less indirect transfer support} }

    is available.

    Again, the “linguistic cousin” explanation is explicitly given by the slide. (Source: indicxtreme-slides)

    5.30.27 This gives us a three-factor failure model

    For an extremely low-resource language:

    \boxed{ \text{small data} }
    +
    \boxed{ \text{weak script sharing} }
    +
    \boxed{ \text{weak linguistic-transfer support} }

    can compound.

    So the problem is not merely:

    \boxed{ \text{“not enough text.”} }

    It can be:

    \boxed{ \text{not enough text + poor representational bridges}. }

    That is the more complete lesson.

    5.30.28 The benchmark itself still has a limitation

    Here is an extremely important detail.

    IndicCorp v2 contains:

    \boxed{24\text{ languages}}.

    But IndicXTREME can evaluate only:

    \boxed{19}

    of them.

    Therefore:

    24-19 = \boxed{5}

    languages still have no evaluation set.

    The deck calls these remaining languages “left-behind” in the context of benchmark coverage. (Source: indicxtreme-slides)

    5.30.29 Why is this ironic?

    The benchmark was created to address:

    \boxed{ \text{poor benchmark coverage} }

    but it still cannot evaluate:

    \boxed{5/24}

    of the corpus languages.

    The fraction is:

    \frac{5}{24} \approx 0.2083.

    So approximately:

    \boxed{20.8\%}

    of the IndicCorp v2 language set lacks IndicXTREME evaluation according to this slide.

    This is our calculation from the source's explicit 24 and 19 figures. (Source: indicxtreme-slides)

    5.30.30 This is a major research lesson

    A benchmark itself can have a coverage frontier.

    Even if we improve:

    \text{model}

    and:

    \text{training corpus},

    we still cannot measure performance on a language for which:

    \boxed{ \text{no reliable evaluation dataset exists}. }

    So:

    \boxed{ \text{Data problem} \rightarrow \text{Model problem} \rightarrow \text{Evaluation problem} }

    are interconnected.

    5.30.31 Let's connect corpus size to benchmark behavior

    Earlier we learned:

    20.9\text{B tokens}

    total.

    But the bottom 11 lowest-resource languages contribute only:

    1.08\text{B}.

    Therefore:

    \frac{1.08}{20.9}\times100 \approx \boxed{5.17\%}.

    So nearly all of the corpus is concentrated outside that bottom group.

    This explains why simply saying:

    “The model has 20.9B Indic tokens”

    can hide the real distribution problem.

    5.30.32 Important numerical inference

    Suppose two models both see:

    20.9\text{B total tokens}.

    Model A has balanced distribution.

    Model B has highly concentrated distribution.

    They have the same total:

    \boxed{20.9\text{B}}

    but potentially very different low-resource performance.

    Therefore:

    \boxed{ \text{total corpus size} \neq \text{resource balance} }

    This is a conceptual inference from the corpus and benchmark results.

    5.30.33 Why does the benchmark distinguish good models?

    We can now answer the original question at three levels.

    Level 1 — Task level

    Models differ significantly across the 9 tasks.

    Level 2 — Model level

    IndicBERT v2 family outperforms major multilingual baselines on 7/9 tasks.

    Level 3 — Language level

    Performance changes sharply according to language resource level, especially for Left-Behinds.

    So:

    \boxed{ \text{benchmark discriminates both models and languages} }

    (Source: indicxtreme-slides)

    5.30.34 The strongest conceptual conclusion

    The results suggest:

    \boxed{ \text{Indic-specific pretraining helps} }

    but also:

    \boxed{ \text{Indic-specific pretraining does not eliminate the low-resource gap} }

    That is extremely important.

    We improve the overall model:

    \text{IndicBERT v2 family}

    yet still see:

    \text{Winner} > \text{Left-Behind}.

    So better Indic resources reduce some problems without magically solving resource inequality.

    5.30.35 Full causal chain

    Now connect the entire IndicXTREME lecture:

    \boxed{ \text{Some Indic languages have little/no data} }
    \downarrow
    \boxed{ \text{generic multilingual models allocate uneven capacity} }
    \downarrow
    \boxed{ \text{existing benchmarks omit many Indic languages} }
    \downarrow
    \boxed{ \text{IndicCorp + IndicXTREME} }
    \downarrow
    \boxed{ \text{Indic-focused pretraining improves many tasks} }
    \downarrow
    \boxed{ \text{but extreme low-resource languages remain substantially weaker} }
    \downarrow
    \boxed{ \text{future work must improve both data and evaluation coverage} }

    This is the central story of the IndicXTREME material. (Source: indicxtreme-slides)

    5.30.37 Exam-style conceptual question

    Question: Why is the 7/9 result more informative than saying “IndicBERT v2 has a higher average score”?

    Because a single average can hide task-specific failures. The 7/9 comparison shows that the IndicBERT v2 family beats the strongest massively multilingual baseline on most individual benchmark tasks while still losing on two, namely IndicXPara and Naamapadam in the strongest-family comparison. (Source: indicxtreme-slides)

    5.30.38 Another exam question

    Question: Why is the IndicCorp-only MLM ablation important?

    Because it shows that the reported Indic gains are not dependent entirely on parallel multilingual data. The supplied slide says the advantage persists for a model trained purely on IndicCorp v2 with MLM and no parallel data, supporting the value of Indic-focused pretraining. (Source: indicxtreme-slides)

    5.30.39 Another exam question

    Question: Why do Left-Behind languages perform worse?

    The source identifies:

    \boxed{ \text{insufficient pretraining data} + \text{lack of shared script} + \text{lack of a linguistic cousin represented in the corpus} }

    as compounding factors. (Source: indicxtreme-slides)

    5.30.40 Final mental model

    The entire results section can be reduced to:

    \boxed{ \text{Indic specialization} \rightarrow \text{better performance on most tasks} }

    but:

    \boxed{ \text{resource inequality} \rightarrow \text{persistent language inequality} }

    Therefore:

    \boxed{ \text{better model} \neq \text{problem solved for every language} }

    \boxed{ \text{24 corpus languages} \quad\neq\quad \text{24 evaluated languages} }
