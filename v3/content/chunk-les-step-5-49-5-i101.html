Motivation

Refresh local scale measurements when tensor distributions change between training steps.

Prerequisites

  • Linear algebra and chain rule
  • Binary floating-point normal/subnormal encodings
  • Quantization scale convention
  • Tensor shape and loss normalization

Notation and units

  • X:[N, K], W:[K, O], Y=XW:[N, O] row convention
  • s_q: fmax/amax quantization multiplier; s_d:1/s_q reconstruction multiplier
  • Nc:128 reduction/group channels in cited design
  • G: dL/dY; dX=GW^T; dW=X^TG

Assumptions

  • All toy numerical inputs and normalization conventions are stated explicitly.
  • The teaching companion requires NumPy and runs on CPU; it claims no production backend execution.
  • Finite saturating E4M3FN RTNE is simulated; tensor arithmetic uses NumPy higher precision.

Step-by-step derivation

  1. Delayed scaling estimates amax from past tensors. If current amax grows, the old quantization multiplier is too large and clipping can occur; if the signal shrinks, it is too small and codes may underflow.
  2. Online calibration measures current amax for each local group, then casts and stores the corresponding current scales. Perfect calibration means range alignment, not lossless reconstruction.
  3. amax reduction and casting require memory reads and work; kernel fusion can reduce overhead but does not make it free. Running history remains useful in some frameworks.
  4. Nonfinite amax, zero amax, rapid spikes and group-local outliers require explicit guards; scale metadata must remain aligned with the lifetime of its codes.

5.49.5.1 First: recall what a scaling factor is

From our earlier quantization foundation:

Suppose a tensor is:

X=[x_1,x_2,\ldots,x_n].

Find its maximum absolute value:

\boxed{ \alpha=\max_i|x_i| }

Then derive a scaling factor from the target representable range.

For the simple symmetric INT8 example we used:

\boxed{ s=\frac{q_{\max}}{\alpha} }

where:

q_{\max}=127.

Then:

\boxed{ q_i=\operatorname{round}(x_i s). }

So everything depends on:

\boxed{\alpha}.

And that gives us the question behind Pillar 5:

Where does \alpha come from?

5.49.5.2 Two possibilities

Suppose we are currently quantizing:

X_t.

There are two broad approaches.

Approach A — use old statistics

Use something like:

\alpha_{t-1}

or a running historical estimate.

This is what the source calls:

\boxed{\text{Delayed Quantization}}.
Approach B — inspect the current tensor

Calculate:

\alpha_t=\max|X_t|.

This is:

\boxed{\text{Online Quantization}}.

The source contrasts exactly these two approaches. (Source: Build a DeepSeek Model (From Scratch))

5.49.5.3 What does “delayed” mean?

Suppose the previous batches looked like:

X_{t-3},X_{t-2},X_{t-1}.

Their maximum magnitudes might have been:

10,\quad12,\quad11.

A delayed scheme keeps history such as:

\alpha_{\text{history}}\approx12.

Then when the new tensor arrives:

X_t,

you quantize it using information derived from the past.

The important point is:

\boxed{ \text{the scale used now is not necessarily determined by the current tensor}. }

The source explicitly describes delayed quantization as maintaining a running history of maximum values and using that historical information for the current step. (Source: Build a DeepSeek Model (From Scratch))

5.49.5.4 Why could that be a problem?

Because the distribution of neural-network tensors can change.

The source identifies two opposite cases.

Case 1

Current maximum:

\alpha_t \gg \alpha_{\text{history}}.
Case 2

Current maximum:

\alpha_t \ll \alpha_{\text{history}}.

These create two different numerical failures.

5.49.5.5 Case 1 — Current values are much larger

Suppose historical maximum:

\alpha_{\text{history}}=10.

But the current tensor contains:

\alpha_t=100.

Suppose the target FP8 range has some maximum representable magnitude q_{\max}.

The old scale was derived from:

10.

Therefore the scale is approximately:

s_{\text{old}} = \frac{q_{\max}}{10}.

But the current value is:

100.

So its scaled value becomes:

100 \frac{q_{\max}}{10} = 10q_{\max}.

That is far beyond the intended target range.

So:

\boxed{ \text{old scale + unexpectedly large current tensor} \rightarrow \text{overflow}. }

The source explicitly identifies this failure. (Source: Build a DeepSeek Model (From Scratch))

5.49.5.6 Concrete toy numerical

For simplicity, use:

q_{\max}=127.

Historical maximum:

\alpha_h=10.

Therefore:

s_h=\frac{127}{10}=12.7.

Now current tensor contains:

x=100.

Quantization tries:

100(12.7)=1270.

But the target range is:

[-127,127].

So:

\boxed{1270>127}.

Overflow occurs.

This example is derived from the source's stated failure mode.

5.49.5.7 Case 2 — Current values are much smaller

Now reverse the situation.

Historical maximum:

\alpha_h=100.

Current maximum:

\alpha_t=1.

The old scale:

s_h=\frac{127}{100}=1.27.

Take a current value:

x=0.1.

Then:

0.1(1.27)=0.127.

After rounding:

\boxed{q=0}.

So:

0.1 \rightarrow 0

in the quantized representation.

The source describes this as underflow / catastrophic precision loss, connected to the same “squashing” problem we encountered earlier. (Source: Build a DeepSeek Model (From Scratch))

5.49.5.8 Why is this the same “squashing” problem?

Remember our earlier example:

[2,3,500].

The 500 forced the global scale to accommodate a huge range.

Then:

2,3

were mapped into a tiny part of the quantized range.

Here the problem is temporal rather than spatial.

Previously:

\boxed{ \text{one scale is shared by very different values}. }

Now:

\boxed{ \text{one old scale is reused for a very different current tensor}. }

So both create:

\boxed{ \text{poor use of the available quantization range}. }

5.49.5.9 The important difference between Pillar 2 and Pillar 5

This is a very useful distinction.

Pillar 2 — Fine-Grained Quantization

Question:

\boxed{ \text{How large should the region be?} }

Answer:

\text{small groups/blocks}.
Pillar 5 — Online Quantization

Question:

\boxed{ \text{When should the scaling factor be measured?} }

Answer:

\text{from the current tensor}.

So:

\boxed{ \text{Pillar 2 = spatial/local adaptation} }

while:

\boxed{ \text{Pillar 5 = temporal/current-step adaptation}. }

This is an important conceptual connection that emerges from the source's two sections. (Source: Build a DeepSeek Model (From Scratch))

5.49.5.10 Online Quantization

Now the DeepSeek solution.

The source says:

calculate the scaling factor in real time from the current tensor itself.

The source's three-step workflow is:

\boxed{ 1.\text{ scan current tensor} }
\boxed{ 2.\text{ calculate current maximum} }
\boxed{ 3.\text{ derive and apply fresh scale} }

(Source: Build a DeepSeek Model (From Scratch))

5.49.5.11 Step 1 — Current tensor arrives

Suppose:

X_t.

We do not first consult:

X_{t-1}.

Instead:

\boxed{ \text{inspect }X_t. }

5.49.5.12 Step 2 — Find current maximum

Compute:

\boxed{ \alpha_t=\max_i|x_i|. }

Suppose:

X_t= [-2.1,\;0.4,\;1.7,\;-3.8,\;2.2].

Then:

|X_t| = [2.1,0.4,1.7,3.8,2.2].

Therefore:

\boxed{ \alpha_t=3.8. }

5.49.5.13 Step 3 — Calculate the fresh scale

Using our symmetric quantization example:

s_t=\frac{127}{3.8}.

Therefore:

\boxed{ s_t\approx33.421. }

Now the current tensor is calibrated specifically for the current dynamic range.

5.49.5.14 Step 4 — Quantize

For:

x=-2.1:
q = \operatorname{round} (-2.1\times33.421).

Approximately:

-70.18.

So:

\boxed{-70}.

For:

x=0.4:
0.4\times33.421 \approx13.37

so:

\boxed{13}.

For:

x=-3.8:
-3.8\times33.421 \approx-127

so:

\boxed{-127}.

Notice that the largest current magnitude maps almost exactly to the maximum available representation.

5.49.5.15 Why this is “perfectly calibrated”

The source uses the phrase that the fresh scaling factor is tailored to the dynamic range of the tensor being processed at that exact moment. (Source: Build a DeepSeek Model (From Scratch))

The important idea is:

\boxed{ \alpha_t \rightarrow s_t \rightarrow X_t }

rather than:

\boxed{ \alpha_{t-1} \rightarrow s_{t-1} \rightarrow X_t. }

5.49.5.16 Compare delayed vs online numerically

Suppose:

Historical tensor
X_{t-1}

has:

\alpha_{t-1}=100.
Current tensor
X_t

has:

\alpha_t=1.
Delayed
s_{\text{old}}=\frac{127}{100}=1.27.

A current value:

x=0.1

becomes:

0.127\rightarrow0.

So the value is lost.

Online
s_t=\frac{127}{1}=127.

Then:

0.1\times127=12.7

and:

\boxed{q=13}.

Much more of the quantization range is used.

So:

\boxed{ \text{online scaling preserves small current values much better}. }

5.49.5.17 Now reverse it

Historical:

\alpha_{t-1}=1.

Current:

\alpha_t=100.
Delayed
s_{\text{old}}=127.

Current maximum:

100\times127=12,700.

But target:

127.

So:

\boxed{\text{overflow}}.
Online
s_t=127/100=1.27.

Current maximum:

100(1.27)=127.

So:

\boxed{\text{properly scaled}}.

5.49.5.18 So online quantization solves both directions

Current tensor larger than historical
\boxed{ \alpha_t\uparrow \rightarrow s_t\downarrow }

so overflow risk is reduced.

Current tensor smaller than historical
\boxed{ \alpha_t\downarrow \rightarrow s_t\uparrow }

so the smaller values use more of the available representation range.

Therefore:

\boxed{ \text{online scaling adapts in both directions}. }

5.49.5.19 Why not use a running average?

You might ask:

Why not estimate the current maximum from an exponential moving average?

That is precisely the general family of delayed/statistical approaches the source contrasts with online calculation.

The source's argument is that the current tensor provides the most direct information about the current dynamic range. (Source: Build a DeepSeek Model (From Scratch))

So DeepSeek prioritizes:

\boxed{ \text{current information} }

over:

\boxed{ \text{historical prediction of current information}. }

5.49.5.20 But there is a cost

Online quantization requires:

\boxed{ \text{an additional pass over the tensor} }

to compute:

\max|X|.

So we have:

\boxed{ \text{extra computation}. }

Why accept that?

Because the source says maximum-finding is much cheaper than the massive matrix multiplications that dominate the workload. (Source: Build a DeepSeek Model (From Scratch))

5.49.5.21 Compare the complexity qualitatively

Suppose a matrix multiplication performs approximately:

O(MNK)

arithmetic work.

Finding the maximum of a tensor with:

N

elements costs approximately:

O(N)

work.

So:

\boxed{ O(N)\ll O(MNK) }

for a large GEMM.

This is the fundamental reason the extra maximum-finding pass can be acceptable.

The source explicitly makes this comparison qualitatively, describing max-finding as an order of magnitude faster than the dominant matrix multiplication workload. (Source: Build a DeepSeek Model (From Scratch))

5.49.5.22 A concrete complexity intuition

Suppose:

X\in\mathbb R^{4096\times4096}.

Number of values:

4096^2 = 16,777,216.

Finding the maximum requires scanning approximately:

\boxed{16.8M}

values.

Now suppose the same matrix participates in a multiplication:

4096\times4096

with another compatible matrix.

The multiplication requires approximately:

4096^3 = 68,719,476,736

multiply operations under a simple count.

So:

\boxed{ 16.8M \ll 68.7B. }

This is our derived illustration of why the calibration pass can be relatively inexpensive.

5.49.5.23 But this is not literally “free”

Even if:

O(N)

is much smaller than:

O(N^3),

the max operation still consumes:

  • memory bandwidth,
  • GPU cycles,
  • synchronization,
  • kernel-launch resources.

So the correct statement is:

\boxed{ \text{small relative overhead} }

not:

\boxed{\text{zero overhead}}.

The source explicitly acknowledges a small computational overhead. (Source: Build a DeepSeek Model (From Scratch))

5.49.5.24 Why online quantization complements fine-grained quantization

Now combine Pillar 2 and Pillar 5.

Suppose we have activation groups:

G_1,G_2,\ldots,G_m.

Fine-grained quantization says:

\alpha_{t,g} = \max_{x\in G_g}|x|.

Online quantization says:

\boxed{ \alpha_{t,g} \text{ is calculated from the current tensor/group} }

rather than a stale:

\alpha_{t-1,g}.

So the combination is:

\boxed{ \text{local} + \text{current}. }

That is an excellent way to remember the two techniques.

5.49.5.25 Spatial and temporal adaptation

This is the clean conceptual model:

\boxed{ \text{Fine-Grained} = \text{where do I measure?} }

Answer:

\text{locally}.
\boxed{ \text{Online} = \text{when do I measure?} }

Answer:

\text{now}.

Therefore DeepSeek's scaling strategy is approximately:

\boxed{ \text{local spatial statistics} + \text{current temporal statistics}. }

That is the strongest conceptual connection to retain.

5.49.5.26 Connect online quantization to E4M3

Remember Pillar 4.

DeepSeek wants:

\boxed{E4M3}

because it gives more mantissa bits.

But E4M3 has less dynamic range than E5M2.

Fine-grained quantization reduces:

\boxed{\text{local range problem}}.

Online quantization reduces:

\boxed{\text{stale-scale problem}}.

Therefore the model can more aggressively exploit:

\boxed{ \text{precision-oriented E4M3}. }

The source's five-pillar presentation specifically treats these ideas as synergistic.

5.49.5.29 Exam numerical — delayed vs online

Suppose:

Historical maximum:

\alpha_h=50.

Current maximum:

\alpha_t=2.
Delayed

=\operatorname{round}(0.254) = \boxed0.

\boxed{ \text{online preserves the small value much better}. }

Historical:

\alpha_h=2.

Current:

Delayed scale:

Therefore:

\boxed{ 3175>127 }

and the representation cannot accommodate it.

Online:

s_t=\frac{127}{50}=2.54

and:

50(2.54)=127.

Perfectly calibrated.

5.49.5.31 What online quantization does NOT solve

This is important.

Online quantization does not magically eliminate all quantization error.

Even with a perfectly fresh scale:

\boxed{ \text{rounding still occurs}. }

There can still be:

\boxed{\text{quantization error}}

because FP8 has limited representational precision.

Online quantization specifically attacks the problem of:

\boxed{ \text{using an inappropriate stale scale}. }

Likewise, it does not replace:

  • fine-grained grouping,
  • FP32 accumulation,
  • mixed precision,
  • E4M3 selection.

It is one component of the complete framework.
