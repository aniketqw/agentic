Motivation

Adapt an already capable model while separating base-weight storage from trainable gradients and optimizer state.

Prerequisites

  • Gradient descent and chain rule
  • Matrix dimensions and rank
  • Bits, bytes and decimal GB

Notation and units

  • Nbase: frozen/base parameter count
  • Ntrain: optimizer-updated parameter count
  • W: d×out row-input weight; rank r

Assumptions

  • Parameter-count examples exclude biases unless named
  • Storage uses decimal GB and 16-bit values only
  • PEFT can still require activation gradients through frozen layers

Step-by-step derivation

  1. Full update has d·out independent entries. A factorization through r has dr+r·out entries.
  2. Each column of the factor product lies in the span of the d×r input factor; rank cannot exceed r.
  3. Trainable fraction=Ntrain/Nbase; reduction in trainable count does not remove the base weights.
  4. Memory separates base bytes, adapter bytes, gradients, optimizer state, activations and cache. A count reduction is not an equal wall-clock speedup.
  5. Adapters add modules, BitFit selects biases, LoRA reparameterizes updates, and soft prompts train vectors; the four families need different execution paths.

Worked numericals and independent verification

One projection

Given: d=out=4096, r=8

  1. Full entries=4096²=16,777,216.
  2. Factor entries=8(4096+4096)=65,536.
  3. Reduction=16,777,216/65,536=256.

Answer: 65536

Alternative shape

Given: d=out=2048, r=4

  1. Count both thin matrices.
  2. 4×4096=16,384; full 4,194,304; ratio 256.

    Step 3.1 — Why PEFT Exists: Full Fine-Tuning as the Baseline

    Plan node: I3 · chat order #26

    We are now moving from:

    \boxed{\text{How do we generate text?}}

    to:

    \boxed{\text{How do we adapt a pretrained LLM to a new task?}}

    The first thing we must understand is ordinary full fine-tuning. LoRA only makes sense once the cost of full fine-tuning is completely clear.

    Your PEFT slides define full fine-tuning as updating every weight matrix of a pretrained model using gradients computed from a smaller task-specific labeled dataset. (Source: peft-slides)

    3.1.1 Start With a Pretrained LLM

    Suppose we have a pretrained model:

    f_\theta(x)

    where:

    \theta=\{W_1,W_2,\ldots,W_L\}

    represents all learned parameters.

    The model has already learned general language structure from large-scale pretraining.

    For example, imagine a pretrained LLM understands:

    • grammar,
    • syntax,
    • general facts,
    • language patterns,
    • long-range dependencies.

    Now we want to specialize it for:

    \boxed{\text{medical classification}}

    or:

    \boxed{\text{spam detection}}

    or:

    \boxed{\text{instruction following}}.

    We have a smaller task-specific dataset:

    D=\{(x_i,y_i)\}_{i=1}^{N}.

    3.1.2 What Does Fine-Tuning Actually Do?

    During fine-tuning, we calculate the task loss:

    \boxed{ L(\theta) }

    and use backpropagation to determine how each parameter should change.

    For a parameter matrix W:

    \boxed{ \Delta W }

    represents the desired update.

    Ordinary gradient descent is conceptually:

    \boxed{ W' = W-\eta\nabla_W L }

    where:

    • W = pretrained weights,
    • L = loss,
    • \nabla_W L = gradient of the loss with respect to W,
    • \eta = learning rate,
    • W' = updated weight matrix.

    So full fine-tuning means:

    \boxed{ \text{every trainable weight gets updated}. }

    3.1.3 The Important Problem

    Suppose the LLM contains:

    7\text{ billion parameters}.

    Full fine-tuning says:

    \boxed{ \text{train all 7 billion}. }

    Even though the task-specific dataset may be relatively small.

    This creates a huge computational and storage burden.

    The PEFT slides specifically motivate PEFT because storing and updating gradients for every parameter of a multi-billion-parameter model can make fine-tuning impractical on a single consumer GPU. (Source: peft-slides)

    3.1.4 What Does "Trainable" Actually Mean?

    A parameter is trainable if:

    \boxed{ \text{gradient is computed for it and optimizer can update it}. }

    For full fine-tuning:

    \boxed{ \text{almost/all pretrained parameters are trainable}. }

    For PEFT:

    \boxed{ \text{most pretrained parameters are frozen} }

    and only a small set is trained.

    The PEFT slides describe this as often training under 1% of the model's parameters while keeping the rest frozen. (Source: peft-slides)

    3.1.5 Frozen vs Trainable

    Imagine:

    \theta= \{W_1,W_2,W_3,W_4,W_5\}.
    Full fine-tuning
    W_1,W_2,W_3,W_4,W_5

    all update.

    PEFT

    We might have:

    W_1,W_2,W_3,W_4,W_5

    frozen and introduce a small trainable component:

    \phi.

    Then:

    \boxed{ \theta_{\text{base}} \text{ is frozen} }

    while:

    \boxed{ \phi \text{ is trainable}. }

    The model becomes conceptually:

    f_{\theta,\phi}(x)

    where:

    \boxed{ \theta=\text{large frozen base} }

    and:

    \boxed{ \phi=\text{small trainable adaptation}. }

    3.1.6 Why Not Simply Train a Smaller Model?

    This is an important conceptual question.

    Suppose you already have a powerful pretrained model.

    Its millions or billions of parameters contain useful general knowledge.

    The PEFT idea is:

    Don't throw away that pretrained knowledge or rebuild it from scratch. Keep the base model and learn a small task-specific modification.

    So we want:

    \boxed{ \text{retain general knowledge} + \text{learn small task-specific change}. }

    This is the fundamental motivation for parameter-efficient fine-tuning.

    3.1.7 The Four PEFT Families in Your Slides

    Your PEFT slides divide PEFT methods into four families. (Source: peft-slides)

    1. Additive

    Introduce new trainable modules.

    Example:

    \boxed{\text{Adapters}}

    The original model remains mostly frozen, while a small bottleneck module is trained.

    2. Selective

    Train only a subset of existing parameters.

    Example:

    \boxed{\text{BitFit}}

    where only bias terms are trained.

    3. Reparameterization

    Represent the weight update in a compressed form.

    Example:

    \boxed{\text{LoRA}}

    This is our main focus.

    4. Soft-prompt

    Add trainable vectors to the input or activations.

    Examples:

    \boxed{\text{Prompt tuning}}

    and:

    \boxed{\text{Prefix tuning}}.

    The important point is that all four share the same broad goal:

    \boxed{ \text{adapt the model without updating the full base model}. }

    3.1.8 Full Fine-Tuning vs PEFT

    Let's make the contrast mathematically.

    Suppose the model has:

    N_\theta

    parameters.

    Full fine-tuning

    Trainable parameters:

    \boxed{ N_{\text{train}}=N_\theta }
    PEFT

    Trainable parameters:

    \boxed{ N_{\text{train}}\ll N_\theta. }

    Often:

    \boxed{ N_{\text{train}}<1\%\times N_\theta }

    according to the PEFT lecture's characterization. (Source: peft-slides)

    3.1.9 Numerical Example — 7B Model

    Suppose:

    N_\theta=7,000,000,000.

    For full fine-tuning:

    \boxed{ 7,000,000,000 }

    parameters are trainable.

    Now suppose a PEFT method trains:

    0.1\%

    of the model.

    Calculate:

    7,000,000,000\times0.001 = 7,000,000.

    So:

    \boxed{ 7\text{ million trainable parameters} }

    instead of:

    \boxed{ 7\text{ billion}. }

    Reduction factor:

    \frac{7,000,000,000}{7,000,000} = \boxed{1000}.

    So the trainable parameter count is reduced by:

    \boxed{1000\times}.

    3.1.10 Important: Fewer Trainable Parameters Does Not Mean Smaller Base Model

    This is a common misconception.

    Suppose:

    N_\theta=7B.

    and:

    N_{\text{adapter}}=7M.

    The model is still fundamentally a:

    \boxed{7B\text{-parameter base model}}.

    We are just training:

    \boxed{7M}

    additional/task-specific parameters.

    So:

    \boxed{ \text{parameter-efficient training} \neq \text{parameter-free inference}. }

    3.1.11 What Is Actually Saved?

    PEFT reduces the amount of trainable state.

    The PEFT slides emphasize that full fine-tuning requires gradients and optimizer-related training state for the full parameter set, while PEFT keeps most pretrained weights untouched. (Source: peft-slides)

    So the major benefit is:

    \boxed{ \text{less training memory and computation}. }

    It also makes it much easier to create multiple task-specific versions.

    3.1.12 Multiple Customers Example

    Imagine we have one base model:

    W_0.

    Suppose we want specialized versions for:

    \text{Customer A}
    \text{Customer B}
    \text{Customer C}.
    Full fine-tuning

    We might store:

    W_A
    W_B
    W_C.

    Each is a complete model copy.

    PEFT

    Instead, keep:

    W_0

    once, and store:

    \phi_A,\quad\phi_B,\quad\phi_C.

    Then:

    f_A=f(W_0,\phi_A)
    f_B=f(W_0,\phi_B)
    f_C=f(W_0,\phi_C).

    The Raschka appendix specifically highlights this advantage: keeping LoRA matrices separate allows multiple customized versions without storing multiple complete LLM copies. (Source: Build a Large Language Model (From Scratch))

    This becomes extremely useful in multi-customer or multi-task deployment.

    3.1.13 Numerical Example — Storage

    Suppose:

    W_0=7B\text{ parameters}.

    Imagine a specialized adapter contains:

    10M

    trainable parameters.

    If we use 16-bit values:

    2\text{ bytes/parameter}.
    Full model
    7B\times2 = 14B\text{ bytes}.

    Approximately:

    \boxed{14\text{ GB}}

    using decimal GB.

    Adapter
    10M\times2 = 20M\text{ bytes}

    approximately:

    \boxed{20\text{ MB}}.

    This illustrates why task-specific adapter storage can be dramatically smaller.

    This storage comparison is a derived numerical illustration; the supplied sources establish the architectural advantage, not this particular 7B/10M example.

    3.1.14 But Why Should a Tiny Update Be Enough?

    This is the key question.

    Suppose a weight matrix is:

    W\in\mathbb{R}^{d\times d_{\text{out}}}.

    Full fine-tuning learns:

    \Delta W

    with:

    d\times d_{\text{out}}

    free entries.

    That is potentially a huge number of independent changes.

    PEFT asks:

    Do we actually need arbitrary changes in every direction?

    LoRA's answer is:

    \boxed{\text{perhaps not}.}

    Many task-specific adaptations may be approximated using a much smaller number of effective directions.

    That brings us directly to:

    \boxed{\text{rank}}

    and:

    \boxed{\text{low-rank updates}}.

    3.1.15 Before LoRA, We Need Rank

    Your PEFT slides explicitly introduce rank before LoRA. (Source: peft-slides)

    For a matrix:

    M,

    the rank is:

    \boxed{ \text{number of linearly independent rows} }

    which is equivalently the number of linearly independent columns.

    Your source emphasizes the idea as:

    how much genuinely new information the matrix contains.

    A row that is merely a multiple or linear combination of existing rows does not add a new independent direction. (Source: peft-slides)

    This concept is the mathematical foundation of LoRA.

    3.1.16 Simple Rank Example

    Consider:

    M= \begin{bmatrix} 1&2\\ 2&4 \end{bmatrix}.

    Notice:

    R_2=2R_1.

    Therefore only one row is independent.

    So:

    \boxed{ \operatorname{rank}(M)=1. }

    Even though:

    M\in\mathbb{R}^{2\times2},

    its rank is only 1.

    3.1.17 Full-Rank Example

    Consider:

    I_3= \begin{bmatrix} 1&0&0\\ 0&1&0\\ 0&0&1 \end{bmatrix}.

    No row can be written as a linear combination of the others.

    Therefore:

    \boxed{ \operatorname{rank}(I_3)=3. }

    Your PEFT slides use essentially these two examples to introduce rank. (Source: peft-slides)

    3.1.18 Why Is Rank Relevant to Fine-Tuning?

    Suppose:

    W_0

    is a pretrained matrix.

    Full fine-tuning gives:

    W'=W_0+\Delta W.

    Here:

    \Delta W

    could be a full-rank matrix.

    LoRA instead tries to constrain:

    \boxed{ \Delta W }

    to have low rank.

    Conceptually:

    \boxed{ \text{full update} \rightarrow \text{potentially huge number of directions} }

    versus:

    \boxed{ \text{low-rank update} \rightarrow \text{small number of important directions}. }

    Raschka describes LoRA precisely as restricting model adjustments to a lower-dimensional subspace and aiming to capture influential directions of the weight changes. (Source: peft-slides)

    3.1.19 The Transition to LoRA

    Now we're ready for the fundamental transformation.

    Full fine-tuning
    \boxed{ W'=W_0+\Delta W }

    where \Delta W is fully learned.

    LoRA

    Instead of directly learning every element of \Delta W, represent it as:

    \boxed{ \Delta W\approx BA }

    where A and B are much smaller matrices.

    The PEFT slides summarize LoRA exactly this way: constrain the update to a low-rank product of two thin matrices. (Source: peft-slides)

    3.1.20 Why Does This Save Parameters?

    Suppose:

    W\in\mathbb{R}^{d\times d_{\text{out}}}.

    Full update:

    \Delta W\in\mathbb{R}^{d\times d_{\text{out}}}.

    Therefore full trainable parameter count is:

    \boxed{ d\,d_{\text{out}}. }

    LoRA instead uses:

    B\in\mathbb{R}^{d\times r}

    and:

    A\in\mathbb{R}^{r\times d_{\text{out}}}.

    Therefore:

    |B|=dr

    and:

    |A|=rd_{\text{out}}.

    Total:

    \boxed{ r(d+d_{\text{out}}) }

    trainable parameters.

    Your master cheatsheet gives exactly these two formulas. (Source: MASTER_Mathematical_Cheatsheet_All_Lecture_PDFs_v2)

    3.1.21 First LoRA Numerical

    Take a square matrix:

    W\in\mathbb{R}^{4096\times4096}.

    Full fine-tuning:

    4096\times4096 = \boxed{16,777,216}

    trainable parameters.

    Now use:

    r=8.

    LoRA:

    r(d+d_{\text{out}})

    because:

    d=d_{\text{out}}=4096.

    Therefore:

    8(4096+4096)
    =8(8192)
    =\boxed{65,536}.

    Reduction factor:

    \frac{16,777,216}{65,536} = \boxed{256}.

    Your PEFT slides use this exact numerical example. (Source: peft-slides)

    So a single 4096\times4096 matrix changes from:

    16.78\text{ million}

    trainable parameters to:

    65,536.

    3.1.22 Why Does Rank r Control the Cost?

    The LoRA parameter count is:

    \boxed{ r(d+d_{\text{out}}) }

    Therefore:

    \boxed{ \text{trainable parameters grow linearly with }r. }

    If we double r:

    r\rightarrow2r,

    the number of LoRA parameters approximately doubles.

    So:

    \boxed{ r=\text{adaptation capacity vs efficiency knob}. }

    Your Raschka source explicitly explains that the inner dimension r determines the number of extra trainable parameters and balances adaptability against efficiency. (Source: Build a Large Language Model (From Scratch))

    3.1.23 Numerical — Different Ranks

    Again let:

    d=d_{\text{out}}=4096.

    Then:

    N_{\text{LoRA}}=8192r.
    r=4
    8192(4)=32,768.
    r=8
    8192(8)=65,536.
    r=16
    8192(16)=131,072.
    r=32
    8192(32)=262,144.

    So:

    \boxed{ N\propto r. }

    3.1.24 The Big-O Picture

    Full fine-tuning:

    \boxed{ O(d\,d_{\text{out}}) }

    LoRA:

    \boxed{ O(r(d+d_{\text{out}})) }

    For a square matrix:

    d_{\text{out}}=d,

    so:

    \text{Full}=O(d^2)

    while:

    \text{LoRA}=O(rd).

    When:

    r\ll d,

    we have:

    \boxed{ rd\ll d^2. }

    That's the mathematical reason LoRA is efficient.

    3.1.25 Ratio Formula

    For a general matrix:

    \text{reduction factor} = \frac{d\,d_{\text{out}}} {r(d+d_{\text{out}})}.

    For a square matrix:

    \frac{d^2}{2rd} = \boxed{ \frac{d}{2r}. }

    So for:

    d=4096,\quad r=8,

    we get:

    \frac{4096}{16}=256.

    Exactly the source result.

    3.1.26 One More Important Distinction

    LoRA does not replace the pretrained model's knowledge.

    It keeps:

    \boxed{W_0}

    and learns an additional update:

    \boxed{\Delta W}.

    So the adapted matrix is:

    \boxed{ W'=W_0+\Delta W. }

    And LoRA approximates:

    \boxed{ \Delta W\approx BA. }

    This is the central idea we will build on in the next step.

    3.1.27 Why the Update Is Called "Low Rank"

    Because:

    \Delta W=BA

    has rank bounded by:

    \boxed{ \operatorname{rank}(BA)\le r. }

    Why?

    Because:

    B\in\mathbb{R}^{d\times r}

    can provide at most r independent directions through its r-dimensional middle space.

    This is a mathematical consequence of matrix multiplication; the PEFT source's key conceptual point is that LoRA constrains the update to a low-dimensional subspace. (Source: peft-slides)

    3.1.28 Example of the Dimension Bottleneck

    Suppose:

    B\in\mathbb{R}^{4096\times8}

    and:

    A\in\mathbb{R}^{8\times4096}.

    Then:

    BA

    has shape:

    (4096\times8)(8\times4096)

    which gives:

    \boxed{ 4096\times4096. }

    So the final update has exactly the same shape as the original weight matrix.

    But internally it passes through only:

    \boxed{8}

    dimensions.

    That is what "low rank" means here.

    3.1.29 This Is the Key Mathematical Trick

    We want a large matrix:

    4096\times4096.

    Instead of directly learning:

    16,777,216

    independent values, we learn:

    4096\times8

    plus:

    8\times4096.

    That is:

    32,768+32,768 = 65,536.

    So:

    \boxed{ 16,777,216\rightarrow65,536. }

    And yet:

    BA

    still produces a:

    4096\times4096

    update.

    That is why LoRA can have such a large parameter reduction.

    3.1.30 What We Have Established

    We started with:

    \boxed{\text{Full fine-tuning}}

    where:

    W'=W_0+\Delta W.

    Problem:

    \boxed{ \Delta W\text{ is huge}. }

    PEFT says:

    \boxed{ \text{freeze most of }W_0 }

    and learn a much smaller task-specific adaptation.

    LoRA goes one step further:

    \boxed{ \Delta W\approx BA }

    with:

    \boxed{ r\ll d. }

    Therefore:

    \boxed{ d\,d_{\text{out}} \quad\longrightarrow\quad r(d+d_{\text{out}}) }

    trainable parameters.

    3.1.31 Exam Numerical Bank — Step 3.1

    Level 1

    A model has 2 billion parameters. Full fine-tuning trains how many?

    \boxed{2\text{ billion}}
    Level 2

    A 2048\times2048 matrix is fully fine-tuned.

    2048^2 = \boxed{4,194,304}

    trainable parameters.

    Level 3

    For the same matrix with:

    r=4,

    LoRA trains:

    4(2048+2048) = \boxed{16,384}.
    Level 4

    Reduction factor:

    \frac{4,194,304}{16,384} = \boxed{256}.
    Level 5

    Explain why increasing r from 4 to 16 increases LoRA trainable parameters by a factor of 4.

    Because:

    N_{\text{LoRA}}=r(d+d_{\text{out}})

    and therefore:

    N\propto r.

    So:

    \frac{16}{4} = \boxed{4}.

    3.1.32 Exam Trap

    Do not confuse:

    \boxed{r}

    with:

    \boxed{d}.

    Here:

    • d = original input/hidden dimension,
    • d_{\text{out}} = output dimension,
    • r = LoRA's low-rank bottleneck dimension.

    For LoRA:

    \boxed{ r\ll d,d_{\text{out}}. }

    The PEFT slides explicitly specify this relationship. (Source: peft-slides)
