Motivation

Derive an efficient adaptation branch and its merge from matrix distributivity rather than memorizing BA.

Prerequisites

  • Matrix multiplication
  • Rank and column spans
  • Linear-layer row convention

Notation and units

  • Slide B: d×r; A: r×out; s=alpha/r
  • Book A: d×r; B: r×out; actual scale is alpha in its implementation
  • H=XW0+s(XB)A in slide notation

Assumptions

  • No dropout during merge equivalence
  • Same orientation and scale in both paths
  • Weights represented in the same arithmetic precision

Step-by-step derivation

  1. Set W′=W0+sBA. Shape BA=d×out permits addition.
  2. Expand X(W0+sBA)=XW0+s(XB)A; compute thin branches without materializing a free dense update.
  3. rank(BA)≤min(rank(B), rank(A))≤r; W0+sBA may retain full rank.
  4. Count dr+r·out; savings require r<d·out/(d+out), not merely r<d.
  5. An invertible r×r C gives (BC)(C⁻¹A)=BA, so factor parameters are not unique independent degrees of freedom.
  6. Zero either factor preserves initial output; randomize the other to avoid both gradients being stuck at zero. Names must follow their declared shapes.

Learn a small factored update while freezing the large base matrix.

Prerequisites: Matrix multiplication and shape contracts

Notation and assumptions

Row inputs X:n×din, W:din×dout, B:din×r,A:r×dout; scale alpha/r. The original paper uses a column-vector naming convention, so compare dimensions rather than letters.

Derivation and mechanism

  1. Multiply B and A to obtain a rank-at-most-r update.
  2. Compute base XW and adapter (XB)A separately.
  3. Multiply adapter by alpha/r and add.
Y=XW+(\alpha/r)(XB)A

Limitations

  • The rank is at most r, not necessarily exactly r.
  • Orientations and A/B zero initialization labels must be translated together.

Step 3.2 — LoRA Factorization: Why \Delta W = BA Works

Plan node: I3 · chat order #27

We now go inside the LoRA equation rather than treating it as a formula to memorize.

The central idea from the PEFT lecture is:

\boxed{\Delta W \approx BA}

where the large update matrix is represented through two much thinner matrices. The rank r is the inner dimension and controls how many trainable parameters LoRA introduces. (Source: peft-slides; MASTER_Mathematical_Cheatsheet_All_Lecture_PDFs)

3.2.1 Start From Ordinary Fine-Tuning

Suppose a pretrained linear layer has:

W_0\in\mathbb{R}^{d\times d_{\text{out}}}.

For an input:

X\in\mathbb{R}^{n\times d},

the original layer computes:

\boxed{ H=XW_0 }

where:

H\in\mathbb{R}^{n\times d_{\text{out}}}.

During ordinary fine-tuning, we want to change W_0.

So:

\boxed{ W'=W_0+\Delta W }

and therefore:

H=XW' = X(W_0+\Delta W).

Expanding:

\boxed{ H=XW_0+X\Delta W. }

The problem is that:

\Delta W

has the same huge shape as W_0.

3.2.2 LoRA Changes Only the Update

Instead of directly learning:

\Delta W

as a full matrix, LoRA constrains it to a low-rank product:

\boxed{ \Delta W=BA. }

Then:

\boxed{ W'=W_0+\frac{\alpha}{r}BA }

in the notation used by your PEFT slides/master cheatsheet. (Source: MASTER_Mathematical_Cheatsheet_All_Lecture_PDFs; peft-slides)

The corresponding layer output is:

\boxed{ H=X\left(W_0+\frac{\alpha}{r}BA\right). }

3.2.3 Understand the Shapes First

This is the most important part.

Let:

W_0\in\mathbb{R}^{d\times d_{\text{out}}}.

LoRA introduces:

\boxed{ B\in\mathbb{R}^{d\times r} }

and:

\boxed{ A\in\mathbb{R}^{r\times d_{\text{out}}}. }

The PEFT slide gives exactly these shapes and requires:

r\ll\min(d,d_{\text{out}}).

(Source: peft-slides)

Now multiply:

B A

with shapes:

(d\times r)(r\times d_{\text{out}}).

The inner dimensions cancel:

r=r.

So the result is:

\boxed{ BA\in\mathbb{R}^{d\times d_{\text{out}}}. }

Exactly the same shape as:

W_0.

That is why we can add them.

3.2.4 Dimension Check

Suppose:

d=4, \qquad d_{\text{out}}=6, \qquad r=2.

Then:

B:4\times2

and:

A:2\times6.

Therefore:

BA: (4\times2)(2\times6) = 4\times6.

And:

W_0:4\times6.

So:

\boxed{ W_0+BA }

is valid.

3.2.5 Why Introduce the Middle Dimension r?

Imagine directly learning:

\Delta W\in\mathbb{R}^{4096\times4096}.

That gives:

16,777,216

free parameters.

LoRA instead does:

4096\times r

followed by:

r\times4096.

For:

r=8,

we get:

4096\times8

and:

8\times4096.

This means the update must pass through an 8-dimensional bottleneck.

So the update cannot represent an arbitrary 4096\times4096 matrix.

That restriction is exactly the point.

3.2.6 The Bottleneck Intuition

Think of:

\boxed{ d \rightarrow r \rightarrow d_{\text{out}} }

instead of:

\boxed{ d \rightarrow d_{\text{out}} }

directly.

For example:

4096\rightarrow8\rightarrow4096.

The adaptation first compresses into r=8 directions and then expands back.

That is why LoRA is called low-rank adaptation.

The source describes the rank as the inner dimension that controls the number of trainable parameters and the adaptation capacity. (Source: Build a Large Language Model (From Scratch))

3.2.7 A Tiny Numerical Example

Let's use something we can calculate by hand.

Take:

B= \begin{bmatrix} 1\\ 2 \end{bmatrix}

and:

A= \begin{bmatrix} 3&4&5 \end{bmatrix}.

Shapes:

B:2\times1
A:1\times3.

Therefore:

BA

has shape:

2\times3.

Calculate:

BA= \begin{bmatrix} 1\\ 2 \end{bmatrix} \begin{bmatrix} 3&4&5 \end{bmatrix}.

Multiply each element of B by the whole row A:

\boxed{ BA= \begin{bmatrix} 3&4&5\\ 6&8&10 \end{bmatrix} }

Notice something:

R_2=2R_1.

Therefore:

\boxed{ \operatorname{rank}(BA)=1. }

And that is exactly what we expected because:

r=1.

3.2.8 Why Rank Cannot Exceed r

This is the mathematical heart of LoRA.

We have:

B\in\mathbb{R}^{d\times r}

and:

A\in\mathbb{R}^{r\times d_{\text{out}}}.

Their product passes information through an r-dimensional intermediate space.

Therefore:

\boxed{ \operatorname{rank}(BA)\le r. }

This relationship appears explicitly in your master mathematical cheatsheet. (Source: MASTER_Mathematical_Cheatsheet_All_Lecture_PDFs)

So if:

r=4,

the update can have rank at most:

\boxed{4}.

It cannot become rank 5, 100, or 4096.

3.2.9 Why Does This Save Parameters?

The full matrix contains:

d\,d_{\text{out}}

parameters.

The factors contain:

dr

for B, and:

rd_{\text{out}}

for A.

Therefore:

\boxed{ N_{\text{LoRA}} = dr+rd_{\text{out}} = r(d+d_{\text{out}}) }

as given in the master cheatsheet. (Source: MASTER_Mathematical_Cheatsheet_All_Lecture_PDFs)

3.2.10 Derive the Parameter Formula Yourself

Suppose:

B\in\mathbb{R}^{d\times r}.

Number of entries:

d\times r.

Suppose:

A\in\mathbb{R}^{r\times d_{\text{out}}}.

Number of entries:

r\times d_{\text{out}}.

Add:

dr+rd_{\text{out}}.

Factor r:

\boxed{ r(d+d_{\text{out}}). }

That is why you do not need to memorize where it comes from.

3.2.11 Numerical Parameter Count

Suppose:

d=1024, \qquad d_{\text{out}}=1024, \qquad r=8.

Full update:

1024\times1024 = \boxed{1,048,576}.

LoRA:

8(1024+1024)
=8(2048)
=\boxed{16,384}.

Reduction:

\frac{1,048,576}{16,384} = \boxed{64}.

So LoRA uses:

\boxed{64\times}

fewer trainable parameters for this matrix.

3.2.12 Why the Reduction Becomes Huge When r\ll d

For a square matrix:

d_{\text{out}}=d.

Then:

N_{\text{full}}=d^2

and:

N_{\text{LoRA}}=2dr.

Therefore:

\text{reduction factor} = \frac{d^2}{2dr} = \boxed{\frac{d}{2r}}.

So if:

d=4096,\quad r=8,

then:

\frac{4096}{16} = \boxed{256}.

This is the exact example from your PEFT lecture. (Source: peft-slides)

3.2.13 Now Look at the Forward Pass

This is where the matrix factorization becomes even more intuitive.

We have:

H = X\left(W_0+\frac{\alpha}{r}BA\right).

By the distributive law:

\boxed{ H=XW_0+\frac{\alpha}{r}XBA. }

We can associate the multiplications as:

\boxed{ H=XW_0+\frac{\alpha}{r}(XB)A. }

This is computationally useful because:

X

first passes through the small matrix B, then through A.

3.2.14 Shape of the Forward Pass

Suppose:

X\in\mathbb{R}^{n\times d}.

Then:

B\in\mathbb{R}^{d\times r}.

So:

XB

has shape:

\boxed{ n\times r. }

Then:

A\in\mathbb{R}^{r\times d_{\text{out}}}.

Therefore:

(XB)A

has shape:

\boxed{ n\times d_{\text{out}}. }

Exactly what we need to add to:

XW_0.

3.2.15 Tiny Forward Numerical

Let's take:

X= \begin{bmatrix} 1&2 \end{bmatrix}

so:

X:1\times2.

Take:

B= \begin{bmatrix} 1\\ 2 \end{bmatrix}

so:

B:2\times1.

And:

A= \begin{bmatrix} 3&4 \end{bmatrix}

so:

A:1\times2.

First:

XB = [1\;\;2] \begin{bmatrix} 1\\ 2 \end{bmatrix} = 1+4 = [5].

Then:

(XB)A = [5] \begin{bmatrix} 3&4 \end{bmatrix}
= \boxed{ [15,\;20]. }

So a low-rank transformation has converted a 2-dimensional input into a 2-dimensional output through:

\boxed{2\rightarrow1\rightarrow2}.

3.2.16 Compare Direct Full Update

A full update could have been:

\Delta W= \begin{bmatrix} a&b\\ c&d \end{bmatrix}.

Then:

X\Delta W

could produce any arbitrary 2-dimensional output.

With rank-1 LoRA:

\Delta W=BA,

the update is restricted to a rank-1 structure.

So LoRA trades:

\boxed{\text{full flexibility}}

for:

\boxed{\text{parameter efficiency}}.

That is the fundamental tradeoff.

3.2.17 Why Can a Low-Rank Update Still Be Useful?

This is the intuition emphasized in the Raschka appendix:

LoRA assumes task-specific changes can often be captured effectively in a lower-dimensional subspace, allowing the model to focus on influential directions rather than learning an unrestricted update for every weight.

So the base model already contains a large amount of useful structure.

The task-specific adaptation does not necessarily need to redesign everything.

Conceptually:

\boxed{ \text{large pretrained knowledge} + \text{small task-specific correction} }

rather than:

\boxed{ \text{rewrite the entire model}. }

3.2.18 A Crucial Point: BA Is Large, Even Though A and B Are Small

This often confuses students.

Suppose:

B=4096\times8

and:

A=8\times4096.

Both are relatively small.

But their product:

BA

is:

4096\times4096.

So:

\boxed{ BA\text{ has the full weight shape}. }

The savings come because we store and train A and B rather than storing a free full-rank \Delta W.

We do not need to maintain BA as a separate trainable parameter matrix.

3.2.19 Think of BA as an Implicit Matrix

Instead of learning:

\Delta W= \begin{bmatrix} \text{millions of independent values} \end{bmatrix},

we learn:

B,\;A.

Then:

\boxed{ \Delta W=BA }

is generated from those factors.

3.2.20 Why the Rank Is a Capacity Knob

Consider:

r=1.

Then:

\operatorname{rank}(\Delta W)\le1.

Very restrictive.

Now:

r=8.

Then:

\operatorname{rank}(\Delta W)\le8.

More expressive.

Now:

r=64.

Then:

\operatorname{rank}(\Delta W)\le64.

More expressive again, but more trainable parameters.

Thus:

\boxed{ r\uparrow \Rightarrow \text{capacity}\uparrow }

and:

\boxed{ r\uparrow \Rightarrow \text{trainable parameters}\uparrow. }

The source explicitly describes r as the balance between adaptability and efficiency. (Source: Build a Large Language Model (From Scratch))

Suppose:

\boxed{ \text{rank}\neq\text{number of trainable parameters}. }

They are different concepts.

3.2.25 Now Introduce the Scaling Factor \alpha

Your PEFT slides use:

\boxed{ W'=W_0+\frac{\alpha}{r}BA }

rather than simply:

W_0+BA.

Why?

Because we want a way to control the strength of the LoRA contribution.

The source describes \alpha as a fixed scaling factor controlling how strongly the adaptation affects the original layer output. (Source: peft-slides; Build a Large Language Model (From Scratch))

3.2.26 What Does \alpha/r Do?

Define:

\boxed{ s=\frac{\alpha}{r}. }

Then:

W'=W_0+sBA.

So:

s

simply controls the magnitude of the low-rank update.

For example:

r=8,\quad\alpha=16

gives:

\boxed{ \frac{\alpha}{r}=2. }

Therefore:

W'=W_0+2BA.

3.2.27 Why Divide by r?

The source formulation uses the normalized scaling:

\frac{\alpha}{r}.

Conceptually, this separates:

  • the chosen rank r,
  • the desired adaptation scale \alpha.

This lets the rank control capacity while \alpha separately controls update strength.

We should therefore distinguish:

\boxed{ r=\text{capacity/number of low-rank directions} }

from:

\boxed{ \alpha=\text{scale of the LoRA contribution}. }

3.2.32 Separate Computation vs Merged Computation

LoRA can be viewed in two mathematically equivalent ways.

Separate form
\boxed{ H=XW_0+\frac{\alpha}{r}(XB)A }
Merged form

First construct:

\boxed{ W'=W_0+\frac{\alpha}{r}BA }

then:

\boxed{ H=XW'. }

By distributivity:

X\left(W_0+\frac{\alpha}{r}BA\right) = XW_0+\frac{\alpha}{r}XBA.

Therefore they produce the same result.

The PEFT slide explicitly demonstrates this equivalence numerically. (Source: peft-slides)

3.2.33 Why Is This Useful?

It means after training, we can merge:

\frac{\alpha}{r}BA

into:

W_0.

Then inference can simply use:

\boxed{ W' }

instead of maintaining a separate LoRA branch.

Your PEFT lecture describes this as allowing the LoRA update to be merged into the pretrained weights, producing zero additional inference latency from maintaining a separate LoRA computation path. (Source: peft-slides)

3.2.34 Why Is Initialization Important?

Your source says:

B

is initialized to zero, while the other factor is initialized with small/random values. Therefore initially:

BA=0.

Hence:

W' = W_0+\frac{\alpha}{r}(0) = W_0.

So at the beginning of LoRA training:

\boxed{ \text{adapted model behaves exactly like the pretrained model}. }

This is a very important design choice.

Raschka explicitly explains that zero-initializing B makes the initial LoRA contribution zero. (Source: Build a Large Language Model (From Scratch))

3.2.35 Why Not Initialize Both Randomly?

Suppose both A and B were random.

Then:

BA\neq0

in general.

So the model would begin training from:

W_0+\frac{\alpha}{r}BA

rather than:

W_0.

The source's design instead gives:

\boxed{ \Delta W=0 }

at initialization.

This preserves the pretrained model's behavior at the start.

3.2.37 Training Then Changes the Factors

During training, gradients update A and B.

Eventually:

A\neq A_0

and:

B\neq0.

Therefore:

BA\neq0.

Now:

\boxed{ W'\neq W_0. }

The task-specific knowledge is encoded in the learned low-rank update.

3.2.38 Why Freeze W_0?

This is essential.

If:

W_0

were also trainable, then we would lose much of the parameter-efficiency advantage.

LoRA therefore uses:

\boxed{ W_0:\text{frozen} }

and:

\boxed{ A,B:\text{trainable}. }

Your PEFT slides explicitly frame LoRA as leaving pretrained weights frozen while only the low-rank matrices are trained. (Source: peft-slides)

3.2.49 One Very Important Caveat

Low rank does not mean the final adapted model's complete weight matrix W' has low rank.

We have:

W'=W_0+\frac{\alpha}{r}BA.

The update:

BA

is low-rank.

But W_0 itself can be full rank.

Therefore:

\boxed{ \text{LoRA makes the update low-rank, not necessarily the final weight matrix.} }

This distinction is essential.
