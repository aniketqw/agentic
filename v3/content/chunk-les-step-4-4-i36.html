Motivation

Separate the actual R1 teacher-text training procedure from classical temperature/KL matching.

Prerequisites

  • Autoregressive conditional likelihood
  • SFT response masking
  • Data validation and held-out evaluation

Notation and units

  • x prompt; y=(y1…ym) retained teacher response
  • L=-sum log Pstudent(yt|x, y<t)/m
  • N samples; k candidates/prompt; p candidate acceptance

Assumptions

  • Synthetic data is explicitly distinguished from ground truth
  • Reported DeepSeek experiments are historical source results, not reruns
  • IID acceptance only for binomial toy calculations

Step-by-step derivation

  1. Generate candidate responses from a teacher, verify final answers/code where possible, and filter readability/format.
  2. Retain prompt-response pairs and tokenize with the student tokenizer; text supervision permits teacher/student vocabularies to differ.
  3. Freeze the synthetic dataset for reproducibility, provenance and disjoint evaluation.
  4. Train answer tokens by ordinary teacher-forced next-token CE; no teacher-logit KL term is required.
  5. No temperature scaling in the student SFT loss does not imply no sampling temperature during teacher generation.
  6. Detailed 804,745/domain counts are from the supplied book; the original R1 report gives approximately 800K and broad reasoning/non-reasoning split. Treat rounded category counts as approximate.

Step 4.4 — DeepSeek-R1 Distillation: Why It Uses Text/Reasoning Traces Instead of Classical Soft-KL Distillation

Plan node: I5 · chat order #36

We now cross an important boundary.

So far, we built:

\boxed{ L_{\text{KD}} = \alpha L_{\text{hard}} + (1-\alpha)T^2 KL(P_T^T\|P_S^T) }

That is classical knowledge distillation.

But the supplied DeepSeek material makes an important point:

DeepSeek-R1’s distilled models do not use this classical soft-logit matching recipe.

Instead, the teacher generates reasoning traces, those traces are filtered, and the student is trained with supervised fine-tuning on the resulting text. (Source: Build a Reasoning Model (From Scratch); Build a DeepSeek Model (From Scratch))

This is the key idea of this step.

1. First understand the fundamental difference

There are two different things a teacher can give a student.

Classical soft distillation

Teacher gives:

\boxed{ \text{probability distribution over the vocabulary/classes} }

For one token:

P_T= [0.52,0.27,0.14,0.07,\ldots]

The student tries to reproduce that distribution.

DeepSeek-R1 hard/text distillation

Teacher gives:

\boxed{ \text{actual generated text} }

For example:

Let's solve this step by step.

First, multiply both sides by 2.
3x - 9 = 2x + 74

Subtract 2x:
x - 9 = 74

Add 9:
x = 83

The student is trained to reproduce these teacher-generated tokens.

The source explicitly describes this as hard distillation and says that this is the setup used for the smaller DeepSeek-R1 distilled models. (Source: Build a Reasoning Model (From Scratch))

2. Why is this distinction so important?

Because a reasoning model has a special kind of knowledge.

For a classifier, you might have:

\text{image} \rightarrow \text{cat/dog/horse}

The teacher's class probability distribution is extremely useful.

But a reasoning LLM does something much richer:

\text{problem} \rightarrow \text{step 1} \rightarrow \text{step 2} \rightarrow \text{step 3} \rightarrow \text{correction} \rightarrow \text{answer}

The source describes DeepSeek-R1's valuable supervision as the long chain-of-thought reasoning traces produced while solving problems, rather than merely the per-token probability distributions. (Source: Build a DeepSeek Model (From Scratch))

So the training target changes from:

\boxed{\text{“What probabilities did the teacher assign?”}}

to:

\boxed{\text{“What reasoning did the teacher actually produce?”}}

Let's first make the old pipeline completely clear.

The teacher's logits must be available during training.

That is crucial.

The source states that soft distillation requires access to teacher logits or log probabilities. (Source: Build a Reasoning Model (From Scratch))

Correction: Absence of temperature-scaled KL in student SFT does not imply absence of teacher-generation temperature; teacher sampling has its own decoding temperature.

Notice what disappeared.

There is no requirement for:

\boxed{T}

No requirement for:

No requirement for:

\boxed{teacher\ logits}

The teacher's generated text itself becomes the supervision.

That is exactly the paradigm shift described in the supplied material. (Source: Build a DeepSeek Model (From Scratch))

5. What exactly is a reasoning trace?

Suppose the prompt is:

Solve 3x-9=2x+74.

A teacher might generate:

Multiply both sides by 1.
3x - 9 = 2x + 74

Subtract 2x from both sides:
x - 9 = 74

Add 9:
x = 83

Therefore, x = 83.

The teacher has produced a sequence:

y_1,y_2,\ldots,y_N.

The student now sees the prompt and is trained to maximize:

P_S(y_t\mid x,y_{<t}).

Therefore the loss is ordinary autoregressive cross-entropy:

\boxed{ L_{\text{SFT}} = -\frac1N \sum_{t=1}^{N} \log P_S(y_t\mid x,y_{<t}) }

This connects directly to the cross-entropy formulation from the reasoning-model material. (Source: Build a Reasoning Model (From Scratch))

6. This is actually ordinary supervised fine-tuning

This is a very important conceptual simplification.

Suppose we have:

\text{prompt} \rightarrow \text{teacher-generated response}.

Then the response becomes the target sequence.

That is simply:

\boxed{\text{Supervised Fine-Tuning on synthetic data}}

The source explicitly makes this connection:

hard distillation is supervised fine-tuning on synthetic data. (Source: Build a Reasoning Model (From Scratch))

So DeepSeek does not need to invent a completely new optimizer or loss for this stage.

Instead:

\boxed{ \text{powerful teacher} + \text{high-quality synthetic data} + \text{SFT} }

is enough for the student to learn much of the teacher's behavior.

7. Why generate the dataset first?

This gives us an extremely useful architecture distinction.

Online classical KD

During training:

x \rightarrow T(x)

and:

x \rightarrow S(x)

happen together.

Teacher is repeatedly involved during student training.

Offline hard distillation

First:

x \rightarrow T(x) \rightarrow \text{text dataset}.

Then:

\text{dataset} \rightarrow S

The teacher is no longer needed for every student training step.

This is one of the major practical advantages of hard distillation described by the source. The student only needs teacher-generated text, not teacher logits. (Source: Build a Reasoning Model (From Scratch))

8. Why not simply trust every teacher response?

This is one of the most important DeepSeek ideas.

A teacher can generate:

\boxed{\text{correct response}}

but it can also generate:

\boxed{\text{incorrect response}}

or:

\boxed{\text{correct but poorly formatted response}}.

If we blindly train the student on everything:

\text{student} \leftarrow \text{teacher outputs}

then the student will learn the bad examples too.

Therefore DeepSeek uses:

\boxed{\text{rejection sampling + quality filtering}}

before SFT. (Source: Build a DeepSeek Model (From Scratch))

9. Rejection sampling: the basic idea

Suppose one problem gets four teacher responses.

Prompt
 |
 +--> Response 1 --> correct --> keep
 |
 +--> Response 2 --> incorrect --> reject
 |
 +--> Response 3 --> correct --> keep
 |
 +--> Response 4 --> malformed --> reject

The student sees only the retained examples.

So:

\boxed{ \text{Generate many} \rightarrow \text{verify} \rightarrow \text{filter} \rightarrow \text{keep good data} }

10. Why generate multiple responses?

Suppose the teacher generates:

R_1,R_2,R_3,R_4,R_5.

One may be wrong.

Another may be correct.

Another may be correct but poorly written.

By generating multiple candidates:

\boxed{ \text{probability of obtaining a high-quality candidate increases} }

provided the filtering mechanism can reliably identify quality.

This is why rejection sampling is so useful in the pipeline.

11. Verification for mathematics

For math problems, verification can be relatively direct.

Suppose ground truth is:

83.

Candidate outputs:

83,\quad 71,\quad 83,\quad 91.

A verifier checks:

\text{candidate} = 83?

Then:

Candidate Correct?
83 ✓
71 ✗
83 ✓
91 ✗

Only the valid solutions are retained.

The chapter states that for math, the final answer can be compared against known ground truth. (Source: Build a DeepSeek Model (From Scratch))

12. Verification for code

Code is handled differently.

Suppose the teacher produces a Python program.

Instead of asking:

“Does this look correct?”

the system can execute it.

Conceptually:

\text{generated code} \rightarrow \text{tests} \rightarrow \text{pass/fail}

The supplied chapter describes code responses being executed and tested for correctness. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{math: compare answer} }
\boxed{ \text{code: execute and test} }

13. What about tasks without one exact answer?

This is where the system needs a different mechanism.

Consider:

Explain why quantum computing is important.

There may not be one unique correct answer.

So deterministic checking is difficult.

The source describes using DeepSeek-V3 as a generative reward model for domains where correctness is not reducible to a simple deterministic answer. (Source: Build a DeepSeek Model (From Scratch))

Conceptually:

\text{candidate response} + \text{reference information} \rightarrow \text{judge} \rightarrow \text{quality assessment}.

14. Correctness is not enough

This is an excellent point for exams and interviews.

Imagine the teacher outputs:

x=83!!!!!!!!!! asdfasdfasdf

The answer is technically correct.

But this is poor training data.

Why?

Because the student learns not only:

\text{content}

but also:

\text{style}

and:

\text{format}.

The source therefore says filtering also removes technically correct but chaotic, difficult-to-read, mixed-language, excessively formatted, or incoherent responses. (Source: Build a DeepSeek Model (From Scratch))

Thus:

\boxed{ \text{training data quality} = \text{correctness} + \text{quality/readability} }

15. The student learns the distribution of behavior

This is a subtle but powerful idea.

Teacher generates:

\text{problem} \rightarrow \text{reasoning trace} \rightarrow \text{answer}.

Student is trained on those examples.

Over many samples, the student begins to learn:

\boxed{ \text{how the teacher tends to solve problems} }

rather than merely:

\boxed{ \text{which token had highest probability} }

This is the key conceptual reason the source presents text-based distillation as appropriate for reasoning models. (Source: Build a DeepSeek Model (From Scratch))

16. Classical soft KD vs R1 hard distillation

Let's put them side by side.

Teacher output logits/probabilities generated text
Temperature Yes No
KL divergence Yes No
Teacher logits required Yes No

The source directly supports this distinction. (Source: Build a Reasoning Model (From Scratch))

17. Numerical comparison

Suppose vocabulary has four tokens.

Teacher probabilities:

P_T=[0.50,0.30,0.15,0.05].
Classical KD

Student tries to approximate:

[0.50,0.30,0.15,0.05].

So we calculate:

KL(P_T\|P_S).
Hard distillation

Suppose teacher actually sampled:

\boxed{\text{token 1}}

as the next token.

Then the hard target is effectively:

y=[1,0,0,0].

Student loss becomes:

L_{\text{CE}} = -\log P_S(1).

So classical KD uses the whole distribution, while hard distillation can use the actual teacher-generated token.

18. But reasoning happens across many tokens

This is where the LLM case becomes different from a one-step classification problem.

Suppose teacher generates:

y_1,y_2,\ldots,y_{1000}.

Then the student learns the entire sequence:

P_S(y_1|x)
P_S(y_2|x,y_1)
P_S(y_3|x,y_1,y_2)

and so on.

Total loss:

\boxed{ L= -\frac1N \sum_{t=1}^{N} \log P_S(y_t|x,y_{<t}) }

This means the complete reasoning trajectory becomes supervision.

19. Why chain-of-thought is so powerful for the student

Suppose the final answer is:

83.

A hard answer-only dataset teaches:

Question → 83

But a reasoning dataset teaches:

Question
→ transform equation
→ isolate x
→ calculate
→ verify
→ 83

So the student receives intermediate states of the solution process.

The source emphasizes that the teacher's value for DeepSeek-R1 lies in these detailed reasoning traces. (Source: Build a DeepSeek Model (From Scratch))

20. Numerical example: answer-only vs reasoning trace

Suppose you have:

10,000

math problems.

Dataset A

Only final answers:

\text{problem}\rightarrow\text{answer}.
Dataset B

Detailed reasoning:

\text{problem} \rightarrow \text{multi-step solution} \rightarrow \text{answer}.

Both contain the same number of final answers.

But Dataset B contains many more training tokens and much more intermediate supervision.

For a reasoning model, that intermediate information is exactly what the source argues is valuable.

30. Why can a smaller model learn from a much larger model?

Imagine:

\text{Teacher}=671B

and:

\text{Student}=1.5B.

The student cannot store the teacher's complete internal state.

But it can learn a compressed approximation of useful behaviors from many examples:

(x,y_T).

This is analogous to learning a function:

f_T(x)

with a smaller approximation:

f_S(x)\approx f_T(x).

The student does not reproduce every internal mechanism.

It learns a useful external behavior.

may not be able to represent everything learned by:

Therefore:

\boxed{ \text{better teacher} \neq \text{perfect student} }

The source explicitly discusses the capacity gap and notes that smaller students can absorb some capabilities much better than others. (Source: Build a DeepSeek Model (From Scratch))

32. Distillation vs RL

This is one of the deepest connections across your course.

RL

The model:

\text{tries} \rightarrow \text{gets reward} \rightarrow \text{updates} \rightarrow \text{tries again}.

It can potentially discover new behavior.

Distillation

The teacher:

\text{already has useful behavior}

and produces:

\text{successful examples}.

The student:

\text{imitates those examples}.

So conceptually:

\boxed{ RL\rightarrow \text{discover/strengthen} }
\boxed{ Distillation\rightarrow \text{transfer/compress} }

The source makes essentially this distinction. (Source: Build a DeepSeek Model (From Scratch))

35. Why this is economically attractive

Classical online soft KD requires:

\text{teacher forward pass} + \text{student forward pass} + \text{KL computation}

during training.

Hard distillation allows:

\text{expensive teacher generation}

to happen once, followed by:

\text{student SFT}.

Then potentially many student variants can reuse the same dataset.

The source specifically highlights this simpler and more predictable training economics. (Source: Build a DeepSeek Model (From Scratch))

36. Very important exam comparison

Question:

Why doesn't DeepSeek-R1 distillation require teacher logits?

Answer:

Because it uses hard/text-based distillation. The teacher generates complete reasoning traces, and the resulting tokens become supervised targets for the student. Therefore teacher probability distributions and logits are not required during student training. (Source: Build a Reasoning Model (From Scratch))

37. Very important exam comparison

Question:

Why is classical soft distillation less directly suited to this reasoning-transfer setup?

The source's framing is:

\text{classification KD} \rightarrow \text{distribution matching}

whereas:

\text{reasoning-model KD} \rightarrow \text{long generated reasoning traces}.

For R1, the useful teacher signal is the actual reasoning behavior contained in the generated sequence, not merely the probability distribution over the next token. (Source: Build a DeepSeek Model (From Scratch))
