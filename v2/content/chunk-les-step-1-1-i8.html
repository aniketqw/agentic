Why this matters

The target at each input position is the following token. A causal model must not access that target through future input positions.

Prerequisites: Conditional sequence probability and log likelihood, Softmax Jacobian and the CE logit gradient

Symbols, shapes and assumptions

Token stream length T+1 gives T input/target pairs. Logits have shape B×T×V; targets B×T. A loss mask and an attention mask serve different purposes.

Derivation or mechanism

  1. Take tokens[:-1] as the input window.
  2. Take tokens[1:] as targets.
  3. Select each target log probability, then average over the valid target count.
L=-\frac{\sum_{b,t}m_{bt}\log p(x_{b,t+1}\mid x_{b,\leq t})}{\sum_{b,t}m_{bt}}

Worked numerical

Stream [2,0,1,2] becomes inputs [2,0,1] and targets [0,1,2]. If two positions share F10 logits and only the first is valid, with targets [2,-100] and mask [1,0], the mean loss is log 2, not log 2 divided by 2. The ignored target is never indexed.

Edge cases and limits

  • An all-ignored batch has no denominator; the companion rejects it.
  • Padding is not automatically removed merely because its token ID exists.
  • This example uses binary masks; weighted losses have another normalization contract.

Connections

  • T05 supplies the causal attention constraint.
  • Later SFT, distillation and ReTool need task-specific loss masks.

Step 1.1 — What Exactly Is a Language Model?

Plan node: I1 · chat order #8

We have finished the mathematical foundation. Now we move from mathematics → the actual objective of an LLM.

This is the most important conceptual transition in the whole course because almost everything that comes later—Transformer attention, decoding, fine-tuning, RL, GRPO, reasoning models—builds on this basic objective.

Your Transformer slides explicitly define the training goal as predicting the probability of the next token given all previous tokens.

Raschka's book gives the same foundation from the LLM perspective: an LLM is trained on large amounts of text, with parameters optimized to predict the next word/token and thereby learn context, structure, and relationships in language.

1.1.1 First: What is a Language Model?

Imagine that I give you:

The cat is sitting on the

What should come next?

Possible tokens might be:

\{\text{mat},\text{floor},\text{chair},\text{roof},...\}

A language model does not simply say:

"The answer is mat."

Instead, its fundamental output is a probability distribution:

P(x_{t+1}\mid x_1,x_2,\ldots,x_t)

For example:

Next token Probability
mat 0.55
floor 0.20
chair 0.10
roof 0.01
... ...

So:

A language model is fundamentally a function that maps previous tokens to a probability distribution over possible next tokens.

That is the central idea.

1.1.2 Why "Language Model" Instead of "Next-Token Predictor"?

Because predicting the next token lets us model the probability of an entire sequence.

Suppose:

x_1,x_2,x_3,x_4

is

I love machine learning

The model wants to assign a probability to the whole sequence:

P(x_1,x_2,x_3,x_4)

But directly learning a probability for every possible complete sentence would be absurdly difficult.

There are an enormous number of possible sequences.

So we use the chain rule of probability.

1.1.3 The Chain Rule

The chain rule says:

P(x_1,x_2,\ldots,x_T) = \prod_{t=1}^{T}P(x_t\mid x_1,\ldots,x_{t-1})

We usually write:

P(x_{1:T}) = \prod_{t=1}^{T} P(x_t\mid x_{<t})

where

x_{<t} = (x_1,\ldots,x_{t-1})

means:

all tokens before position t.

Your Transformer slides explicitly use this autoregressive factorization.

1.1.4 Let's Understand This Equation Slowly

Take:

I love deep learning

Let

x_1=\text{I}
x_2=\text{love}
x_3=\text{deep}
x_4=\text{learning}

Then:

P(\text{I, love, deep, learning})

becomes

P(\text{I}) \cdot P(\text{love}\mid\text{I}) \cdot P(\text{deep}\mid\text{I,love}) \cdot P(\text{learning}\mid\text{I,love,deep})

This is incredibly important.

The model doesn't need to learn:

"What is the probability of this entire sentence?"

Instead, it learns a sequence of next-token predictions.

That is what makes language modeling tractable.

1.1.5 Why Is This Called "Autoregressive"?

Because every prediction depends on what came before.

At position t:

P(x_t\mid x_{<t})

The model uses the previous tokens to predict the current token.

So information flows:

x_1 \rightarrow x_2 \rightarrow x_3 \rightarrow x_4 \rightarrow \cdots

Conceptually:

"I"
 ↓
"I love"
 ↓
"I love deep"
 ↓
"I love deep learning"

At generation time, the newly generated token becomes part of the context for the next prediction.

That is why it is called autoregressive:

the model uses its own previous outputs as part of the input for future outputs.

1.1.6 The Crucial Distinction: Training vs Generation

This is one of the things you must understand before going further.

During training

Suppose the training text is:

I love deep learning

We already know the complete sequence.

So we can create:

Input:   I     love    deep
Target:  love  deep    learning

The model performs many next-token predictions simultaneously.

Conceptually:

I          → predict love
I love     → predict deep
I love deep → predict learning

The future tokens are known to us because this is training data.

But the model is prevented from looking at them when computing the prediction. That is where causal masking will become essential in Step 1.8.

The slides explicitly connect causal masking with the next-token training objective. (Source: Understanding_Attention_Handbook_01)

1.1.7 During Generation

Now imagine that the user gives:

I love

The model predicts:

P(x_3\mid x_1,x_2)

Suppose it chooses:

deep

Now the input becomes:

I love deep

Then it predicts:

P(x_4\mid x_1,x_2,x_3)

Suppose it chooses:

learning

Now:

I love deep learning

This continues one token at a time.

Raschka's generation procedure describes exactly this loop: encode the prompt, run the model, select a next token, append it to the sequence, and repeat.

1.1.8 The Most Important Picture So Far

Think of an LLM as this pipeline:

TEXT
  ↓
TOKENS
  ↓
TOKEN IDs
  ↓
EMBEDDINGS
  ↓
TRANSFORMER
  ↓
LOGITS
  ↓
SOFTMAX
  ↓
NEXT-TOKEN PROBABILITIES

The Transformer is not itself the probability distribution.

It produces representations and ultimately logits.

Then softmax converts those logits into probabilities.

The slides explicitly separate:

  • logits,
  • softmax,
  • probability assigned to the actual token,
  • sequence loss.

1.1.9 What Are Logits?

Suppose the vocabulary contains only five tokens:

V=\{\text{cat},\text{dog},\text{car},\text{tree},\text{book}\}

The model might produce:

z= \begin{bmatrix} 2.5\\ 1.2\\ 0.1\\ -1.0\\ 0.4 \end{bmatrix}

These are logits.

They are raw scores.

They are not probabilities.

Notice:

  • they can be negative,
  • they do not sum to 1,
  • they do not need to lie between 0 and 1.

1.1.10 Why Do We Need Softmax?

We want:

P(\text{cat}),P(\text{dog}),\ldots

such that:

P_i\geq0

and

\sum_i P_i=1

So we apply:

\operatorname{softmax}(z_i) = \frac{e^{z_i}} {\sum_j e^{z_j}}

Therefore:

z \rightarrow \operatorname{softmax}(z) \rightarrow p

where p is a probability distribution.

Your slide deck explicitly describes softmax as turning the logits into a normalized distribution over the vocabulary.

1.1.11 Tiny Numerical Example

Suppose:

z=[2,1,0]

Compute exponentials:

e^2\approx7.389
e^1\approx2.718
e^0=1

Sum:

7.389+2.718+1=11.107

Therefore:

P_1=\frac{7.389}{11.107}\approx0.665
P_2=\frac{2.718}{11.107}\approx0.245
P_3=\frac{1}{11.107}\approx0.090

So:

p\approx[0.665,0.245,0.090]

and:

0.665+0.245+0.090\approx1

Now we have an actual distribution.

1.1.12 From Probability to Loss

Suppose the correct next token is token 1.

The model assigned:

P(x_t\mid x_{<t})=0.665

How should we measure whether this was good?

We use negative log-likelihood:

L_t=-\log P(x_t\mid x_{<t})

Thus:

L_t=-\log(0.665)
L_t\approx0.408

Smaller is better.

Imagine two models

Model A:

P(\text{correct token})=0.9

Then:

-\log(0.9)\approx0.105

Model B:

P(\text{correct token})=0.1

Then:

-\log(0.1)\approx2.303

So:

Correct probability ↑  → loss ↓
Correct probability ↓  → loss ↑

This is exactly why the loss teaches the model to increase the probability of the correct token.

1.1.13 Sequence Loss

For a sequence of T tokens:

L = -\frac{1}{T} \sum_{t=1}^{T} \log P(x_t\mid x_{<t})

This is the average negative log-likelihood across the sequence.

Your Transformer slide gives this sequence-level objective directly.

This equation connects everything we have learned:

\boxed{ \text{next-token probability} \rightarrow \text{log probability} \rightarrow \text{negative log likelihood} \rightarrow \text{loss} }

1.1.14 Why Does Log Appear?

Recall:

P(x_{1:T}) = \prod_{t=1}^{T}P(x_t\mid x_{<t})

Suppose:

P_1=0.8,\quad P_2=0.7,\quad P_3=0.9

Then:

P(x_{1:3}) = 0.8\times0.7\times0.9 = 0.504

For long sequences, multiplying hundreds or thousands of numbers below 1 can become numerically tiny.

Use logarithms:

\log P(x_{1:T}) = \sum_{t=1}^{T} \log P(x_t\mid x_{<t})

So:

\boxed{ \log\left(\prod_t p_t\right) = \sum_t\log p_t }

This is one of the reasons log-probabilities are so important later in:

  • decoding,
  • sequence scoring,
  • knowledge distillation,
  • RL,
  • GRPO,
  • reasoning models.

1.1.15 Cross-Entropy Connection

Earlier we learned:

H(p,q) = -\sum_i p_i\log q_i

For a one-hot target, suppose the correct token is k.

Then:

p_k=1

and all other entries are zero.

So:

H(p,q) = -\log q_k

That is exactly the next-token loss:

L_t=-\log P(x_t\mid x_{<t})

Therefore:

Next-token language-model training is a cross-entropy classification problem applied at every token position.

This is a major conceptual connection.

The model is effectively performing:

At every position:
        "Which of the |V| vocabulary tokens is correct next?"

So if:

|V|=50,257

the model performs a 50,257-way classification at every position.

Raschka's GPT implementation has a final linear layer whose output dimension equals the vocabulary size, producing logits for every vocabulary token.

1.1.16 What Exactly Does the Transformer Predict?

Suppose:

B=2

batch size,

T=5

sequence length,

d=768

hidden dimension,

and

|V|=50,257

vocabulary size.

After embeddings:

X\in\mathbb R^{2\times5\times768}

After the Transformer:

H\in\mathbb R^{2\times5\times768}

Then the output projection maps:

768\rightarrow50,257

giving:

Z\in\mathbb R^{2\times5\times50,257}

This means:

batch 1
 ├── position 1 → 50,257 logits
 ├── position 2 → 50,257 logits
 ├── position 3 → 50,257 logits
 ├── position 4 → 50,257 logits
 └── position 5 → 50,257 logits

batch 2
 ├── position 1 → 50,257 logits
 ...

Raschka's GPT implementation shows the same architectural progression: token embeddings + positional embeddings → Transformer blocks → final normalization → vocabulary projection → logits.

1.1.17 Why Are There Logits at Every Position?

This is a subtle but very important point.

Suppose our input is:

I love deep learning

We can construct:

Input                 Target

I                     love
I love                 deep
I love deep            learning

Therefore, every position produces a prediction.

In matrix form:

Z= \begin{bmatrix} z_1\\ z_2\\ z_3\\ z_4 \end{bmatrix}

where each:

z_t\in\mathbb R^{|V|}

So the model simultaneously produces:

P(x_2|x_1)
P(x_3|x_1,x_2)
P(x_4|x_1,x_2,x_3)

and so on.

This is why training can be highly parallelized across positions.

1.1.18 The Input/Target Shift

This is worth memorizing.

Suppose token IDs are:

[10, 25, 17, 42, 91]

We create:

Input
[10, 25, 17, 42]
Target
[25, 17, 42, 91]

Notice:

\text{target}_t=\text{input}_{t+1}

So:

Input:    10   25   17   42
             ↓    ↓    ↓    ↓
Target:   25   17   42   91

The model learns:

10       → 25
10,25    → 17
10,25,17 → 42
10,25,17,42 → 91

This is commonly called teacher forcing in autoregressive training.

Why?

Because during training the correct previous tokens come directly from the training sequence rather than from the model's own sampled outputs.

1.1.19 Why Doesn't Training Have to Generate One Token at a Time?

This often confuses people.

Generation:

token 1
   ↓
token 2
   ↓
token 3
   ↓
token 4

must be sequential because token 3 is unknown until token 2 has been generated.

Training is different.

The whole sequence is already known:

I love deep learning

Therefore we can feed the entire sequence into the Transformer.

The causal mask ensures:

position 1 sees: 1
position 2 sees: 1,2
position 3 sees: 1,2,3
position 4 sees: 1,2,3,4

but never:

position 2 → position 3,4
position 3 → position 4

That allows parallel computation while preserving the autoregressive objective. The attention handbook in your source set explains this distinction explicitly: causal masking permits parallel training across positions, while generation remains sequential because future generated tokens do not yet exist. (Source: Understanding_Attention_Handbook_01)

We will derive exactly how this happens when we reach Step 1.8 — Causal Mask.

1.1.20 What Does the Model Actually Learn?

At the beginning, the model is essentially terrible.

For example:

"The capital of France is ___"

Paris   → 0.003
London  → 0.002
Berlin  → 0.002
Paris  → ...

During training, the loss generates gradients.

Earlier we learned:

\theta \leftarrow \theta-\eta\nabla_\theta L

So the complete learning loop is:

text
 ↓
tokens
 ↓
Transformer
 ↓
logits
 ↓
softmax
 ↓
probability of correct token
 ↓
loss
 ↓
backpropagation
 ↓
gradients
 ↓
update weights

repeat billions of times

This connects our Step 0.6 tensor calculus directly to language-model training.

1.1.21 Important: The Model Does Not Store a Dictionary of Sentences

A beginner often imagines:

"The model sees 'The capital of France is Paris' many times and memorizes the sentence."

That is not the fundamental mechanism.

The model parameters are adjusted so that, across massive numbers of contexts, the network learns statistical patterns that help predict tokens.

For example:

"The capital of France is"
            ↓
representation
            ↓
high score for "Paris"

But those predictions arise through the learned neural-network parameters and contextual computation.

Raschka emphasizes that the model's parameters are optimized during training to perform next-word prediction and that this objective causes the model to learn context, structure, and relationships in language.

1.1.22 The Vocabulary Dimension

Suppose:

|V|=10,000

Then at every position the model must output:

10,000

scores.

So:

z_t\in\mathbb R^{10,000}

After softmax:

p_t\in\mathbb R^{10,000}

and:

\sum_{i=1}^{10,000}p_{t,i}=1

The correct token corresponds to one position in this vector.

For example:

token ID     probability
0             0.0001
1             0.0021
2             0.0003
...
713           0.7612  ← correct token
...
9999          0.0000

The loss looks only at the probability assigned to token 713 for this particular training example:

L=-\log(0.7612)

1.1.23 Training Tensor Shapes — Memorize This

For a decoder-only language model:

Token IDs
\boxed{[B,T]}

where:

  • B = batch size
  • T = sequence length
Embeddings
\boxed{[B,T,d]}

where:

  • d = model/embedding dimension
Transformer output
\boxed{[B,T,d]}
Logits
\boxed{[B,T,|V|]}
Target IDs
\boxed{[B,T]}

This shape progression is one of the most important pieces of practical understanding:

[B, T]
   ↓ embedding
[B, T, d]
   ↓ Transformer
[B, T, d]
   ↓ output projection
[B, T, V]

Raschka's concrete GPT implementation follows this exact conceptual structure, with the final linear layer projecting each hidden representation into vocabulary-sized logits.

1.1.24 Tiny PyTorch Example

Here is the core of next-token training without implementing the Transformer yet:

import torch
import torch.nn.functional as F

# --------------------------------------------------
# Example logits
# Shape: [batch=1, sequence=4, vocab=5]
# --------------------------------------------------
logits = torch.tensor([
    [
        [2.0, 0.5, 0.1, 0.0, -1.0],  # position 1
        [0.2, 1.8, 0.4, 0.1, -0.5],  # position 2
        [0.1, 0.2, 2.5, 0.3, -0.2],  # position 3
        [0.0, 0.4, 0.2, 2.2, -0.1],  # position 4
    ]
], dtype=torch.float32)

# --------------------------------------------------
# Correct next-token IDs
# One target for each position
# Shape: [1, 4]
# --------------------------------------------------
targets = torch.tensor([
    [0, 1, 2, 3]
])

# --------------------------------------------------
# Cross entropy expects:
# logits -> [N, C]
# targets -> [N]
# --------------------------------------------------
loss = F.cross_entropy(
    logits.reshape(-1, logits.size(-1)),
    targets.reshape(-1)
)

print("Loss:", loss.item())

The important transformation is:

logits:
[B, T, V]

reshape:

[B*T, V]

targets:
[B, T]

reshape:

[B*T]

So PyTorch effectively sees this as:

"B*T classification problems,
each having V possible classes"

That is exactly what next-token training is.

1.1.26 Training vs Generation — Final Comparison

Training Generation
Full target sequence is known Future tokens are unknown
Uses shifted input/target Uses current generated prefix
Many positions processed in parallel New tokens generated sequentially
Loss is computed Tokens are selected/sampled
Backpropagation occurs Usually no gradient computation
Goal: improve parameters Goal: produce text

During generation, Raschka's implementation takes the logits from the last position, turns them into probabilities, chooses the next token, appends it, and repeats.

This distinction will become extremely important when we study:

  • decoding,
  • KV caching,
  • inference-time scaling,
  • reasoning models.

1.1.27 One Very Important Correction in Terminology

You will see both:

next-word prediction

and

next-token prediction.

For modern LLMs, next-token prediction is the more precise term.

A token may be:

word
subword
punctuation
number
part of a word
special token

For example, tokenization could conceptually produce:

"Transformers are powerful"
        ↓
["Transform", "ers", " are", " powerful"]

The exact tokenizer determines the actual token boundaries.

So the mathematical objective is:

\boxed{ P(x_t\mid x_{<t}) }

where x_t is a token, not necessarily an entire word.

1.1.28 The Big Mental Model

At this point you should be able to explain an LLM like this:

An autoregressive language model receives a sequence of tokens, transforms them into contextual representations using a decoder-only Transformer, produces vocabulary-sized logits for each position, converts those logits to a probability distribution over the next token, and is trained by minimizing the negative log-likelihood/cross-entropy of the correct next token.

That single sentence contains almost the entire mathematical backbone of the course.
