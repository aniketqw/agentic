We now reach the final major idea in the book:

\boxed{\text{Knowledge Distillation}}

The problem is no longer:

How do we make the large model reason?

We already did that with the R1 pipeline.

The new problem is:

How do we transfer that reasoning capability into a much smaller, cheaper model?

The source's Chapter 8 answers this with an important distinction:

\boxed{ \text{classical knowledge distillation} \neq \text{DeepSeek-R1's reasoning distillation approach} }

(Source: Build a DeepSeek Model (From Scratch))

1. Why do we need distillation?

The source begins with the deployment problem.

It describes DeepSeek-R1 as having:

\boxed{671\text{B total parameters}}

while only a subset is activated per token because of MoE.

But the full model weights still need to be stored and accessible. The source gives approximately:

671\text{B}\times2\text{ bytes} \approx 1342\text{ GB}

for FP16 weights alone. (Source: Build a DeepSeek Model (From Scratch))

So there is an enormous gap between:

\text{frontier model capability}

and:

\text{practical deployment}.

This motivates distillation.

2. Teacher and student

The basic paradigm is:

\boxed{ \text{large capable teacher} \rightarrow \text{small student} }

The teacher already contains learned capabilities.

The student has fewer parameters and is therefore cheaper to train and deploy.

The source defines knowledge distillation as training a smaller student to reproduce the behavior of a larger teacher in a more compact form. (Source: Build a DeepSeek Model (From Scratch))

3. The first version: classical knowledge distillation

Before understanding DeepSeek's approach, the source first teaches the classical version.

Imagine classification.

The correct class is:

\text{cat}.

A hard label might be:

[1,0,0,0].

But the teacher might output:

[0.70,0.20,0.08,0.02].

This contains more information.

It says:

"Cat is most likely, but class 2 is somewhat related/possible, while class 4 is very unlikely."

These non-winning probabilities contain what the source calls:

\boxed{\text{dark knowledge}}

(Source: Build a DeepSeek Model (From Scratch))

4. Why hard labels lose information

Suppose two teacher outputs are:

[0.99,0.01,0,0]

and:

[0.60,0.30,0.08,0.02].

If we convert both to hard labels, both become:

[1,0,0,0].

The student loses the distinction.

But the second distribution tells the student much more about relationships among the alternatives.

That is the motivation for soft-target distillation.

5. Temperature scaling

The source then introduces:

\boxed{T>1}

to soften the teacher's probability distribution.

The teacher computes:

p_i = \operatorname{softmax} \left( \frac{z_i}{T} \right).

When:

T=1,

we have the ordinary distribution.

When:

T>1,

the distribution becomes flatter.

The source says this exposes more of the relative probabilities among incorrect classes, revealing more dark knowledge. (Source: Build a DeepSeek Model (From Scratch))

6. Why does larger T reveal more information?

Suppose the teacher's logits are:

[6,3,1,0].

At:

T=1,

the largest logit dominates strongly.

Dividing by a larger temperature:

[6/T,3/T,1/T,0/T]

reduces the differences between them.

Therefore the softmax becomes less peaked.

The source's example uses T=3 to obtain a richer teacher distribution. (Source: Build a DeepSeek Model (From Scratch))

7. Classical distillation loss

The source's complete classical KD objective combines:

\boxed{\text{hard-label loss}}

and:

\boxed{\text{soft-target KL loss}}.

It gives:

\boxed{ L = \alpha L_{\text{hard}} + \beta T^2 KL(p_{\text{teacher}}^T\|p_{\text{student}}^T) }

(Source: Build a DeepSeek Model (From Scratch))

In the implementation shown in the source:

def distillation_loss(
    student_logits,
    teacher_logits,
    labels,
    temperature=3.0,
    alpha=0.3
):
    soft_teacher = F.softmax(
        teacher_logits / temperature,
        dim=-1
    )

    soft_student = F.log_softmax(
        student_logits / temperature,
        dim=-1
    )

    kl_loss = F.kl_div(
        soft_student,
        soft_teacher,
        reduction='batchmean'
    )

    hard_loss = F.cross_entropy(
        student_logits,
        labels
    )

    return (
        alpha * hard_loss
        + (1 - alpha)
        * temperature**2
        * kl_loss
    )

(Source: Build a DeepSeek Model (From Scratch))

8. Why two losses?

The source gives each a specific role.

Hard loss
L_{\text{hard}}

keeps the student grounded in the actual correct answer.

Soft loss
KL(p_T\|p_S)

transfers information from the teacher's richer distribution.

So:

                 Student

           ┌───────┴────────┐
           ▼                ▼
       Hard target       Teacher
           │             distribution
           ▼                │
       correctness           ▼
                         dark knowledge
           │                │
           └───────┬────────┘
                   ▼
              total loss

(Source: Build a DeepSeek Model (From Scratch))

9. Why T^2?

This is a subtle mathematical detail.

When logits are divided by:

T,

the gradients from the soft-target term become smaller in magnitude.

The source states that the gradients scale down approximately with:

\frac1{T^2}.

Therefore the soft loss is multiplied by:

\boxed{T^2}

to compensate for that reduction. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ T^2 \text{ corrects the scale of the soft-target gradient} }

in the classical distillation objective.

10. Now comes the crucial DeepSeek insight

Classical KD assumes:

The teacher's most valuable information is its output probability distribution.

For a reasoning model like R1, the source argues that the more important thing is different.

The teacher's real value is:

\boxed{ \text{the reasoning process contained in the generated text} }

rather than simply:

\text{per-token probability distribution}.

(Source: Build a DeepSeek Model (From Scratch))

11. Why logits aren't the main thing for reasoning transfer

Imagine R1 solves a difficult problem.

It generates:

First identify the relevant quantities...

Then derive equation A...

That gives...

Wait, this assumption is incorrect.

Let's reconsider...

Therefore...
Final answer: ...

What makes this response valuable?

Not simply:

P(\text{next token}).

The value is in the strategy:

\boxed{ \text{decompose problem} \rightarrow \text{reason} \rightarrow \text{check} \rightarrow \text{correct} \rightarrow \text{answer} }

The source explicitly makes this argument when contrasting classical KD with reasoning distillation. (Source: Build a DeepSeek Model (From Scratch))

12. The paradigm shift

So instead of:

\boxed{ \text{Teacher logits} \rightarrow \text{KL} \rightarrow \text{Student} }

DeepSeek's reasoning distillation uses:

\boxed{ \text{Teacher-generated reasoning text} \rightarrow \text{SFT} \rightarrow \text{Student} }

The source calls this a fundamentally different approach. (Source: Build a DeepSeek Model (From Scratch))

13. This is why it is still supervised fine-tuning

Suppose the teacher produces:

Prompt:
Solve X.

Teacher:
Let me reason...

Step 1...
Step 2...
Therefore...
Final answer: Y

That entire response becomes a training target.

The student is trained with ordinary next-token prediction:

\boxed{ P_\theta(t_{k+1}\mid t_{\le k}) }

using standard language-model cross-entropy.

So the student's objective is not:

KL(\text{teacher logits}\|\text{student logits})

but rather ordinary SFT over teacher-generated text.

(Source: Build a DeepSeek Model (From Scratch))

14. Teacher and student are decoupled

This gives an important engineering advantage.

Classical KD

Teacher and student typically run simultaneously:

input
 ├──→ Teacher → soft targets
 └──→ Student → prediction
                 │
                 ▼
               KD loss

Teacher must therefore be available during student training.

DeepSeek approach

Teacher generates data offline:

Teacher
   ↓
generate responses
   ↓
filter
   ↓
store dataset
   ↓
teacher can be removed

Then:

static dataset
     ↓
student
     ↓
ordinary SFT

The source explicitly highlights that the 671B-class teacher is no longer needed during student training. (Source: Build a DeepSeek Model (From Scratch))

15. Why rejection sampling is essential

We already learned rejection sampling in R1.

Now it gets reused for another purpose.

For each prompt:

P

the teacher generates multiple candidates:

C_1,C_2,\ldots,C_G.

Then:

\boxed{ \text{verify} + \text{quality filter} }

keeps the best responses.

The source describes rejection sampling as the quality-control mechanism for constructing the distillation dataset. (Source: Build a DeepSeek Model (From Scratch))

16. The actual source code pattern

The source gives a simplified implementation:

def rejection_sample(
    teacher,
    prompts,
    n_samples=4
):
    dataset = []

    for prompt in prompts:
        candidates = []

        for _ in range(n_samples):
            response = teacher.generate(
                prompt,
                temperature=0.6,
                top_p=0.95,
                max_tokens=32768
            )

            candidates.append(response)

        for resp in candidates:
            answer = extract_answer(resp)
            truth = get_ground_truth(prompt)

            if verify(answer, truth):
                if is_clean(resp):
                    dataset.append((prompt, resp))
                    break

    return dataset

(Source: Build a DeepSeek Model (From Scratch))

Let's understand the logic rather than memorize the exact toy code.

17. Step A — Generate multiple candidates

For one prompt:

C_1,C_2,C_3,C_4.

Why multiple?

Because the first response might be wrong or poor even when the teacher is strong.

Sampling gives us several candidate reasoning trajectories.

18. Step B — Extract the answer

The system determines what answer the response is claiming.

For example:

response:
...
Final answer: 42

extract:

42.

19. Step C — Verify correctness

Compare with:

\text{ground truth}.

For math:

42=42?

For code:

\text{run tests}.

The source explicitly describes correctness filtering in this way. (Source: Build a DeepSeek Model (From Scratch))

20. Step D — Check quality

A response can be correct but still poor training data.

For example:

Correct answer ✔
Mixed language ✘
Chaotic structure ✘
Unreadable reasoning ✘

The source says such outputs may be filtered out.

The reason is fundamental:

\boxed{ \text{student learns the style of its training data} }

So bad reasoning traces can produce bad student behavior even when the final answer is correct. (Source: Build a DeepSeek Model (From Scratch))

21. What dataset is produced?

The source describes an approximately:

\boxed{800K}

sample distillation dataset.

It gives an approximate breakdown:

395K\ \text{math}
211K\ \text{code}
10K\ \text{STEM}
10K\ \text{logic}
178K\ \text{general}

(Source: Build a DeepSeek Model (From Scratch))

The important pattern is:

\boxed{ \text{heavy reasoning data} + \text{general-purpose data} }

rather than reasoning tasks alone.

22. Why include general data in distillation too?

Exactly the same reason we needed mixed-data SFT in R1.

A student trained only on reasoning problems may become a narrow reasoning specialist.

The source says the general-purpose portion helps preserve:

\boxed{\text{conversation}}
\boxed{\text{factual QA}}
\boxed{\text{instruction following}}

and other general capabilities. (Source: Build a DeepSeek Model (From Scratch))

So:

\text{reasoning data} \rightarrow \text{depth}

and:

\text{general data} \rightarrow \text{breadth}.

23. A very important source-specific distinction

The book describes two different uses of rejection sampling:

In R1 post-training
RL-trained model
→ generate strong responses
→ curate data
→ mixed SFT
In R1 distillation
R1 teacher
→ generate strong responses
→ curate ~800K dataset
→ student SFT

So rejection sampling is fundamentally a data-construction mechanism that appears at multiple stages.

It is not itself the learning algorithm.

24. What happens to the student's parameters?

This is important.

The student does not receive:

W_{\text{teacher}}

directly.

Instead:

\boxed{ \text{teacher behavior} \rightarrow \text{text dataset} \rightarrow \text{student parameter updates} }

So the teacher's weights are not compressed numerically into the student.

The behavior is transferred through training examples.

The source explicitly explains this distinction. (Source: Build a DeepSeek Model (From Scratch))

25. Why can such a small model learn reasoning?

Because the student is not starting from zero.

The source notes that the distilled models retain the architecture and pretrained weights of their respective base models; R1 contributes the training data. (Source: Build a DeepSeek Model (From Scratch))

So think:

Pretrained student
       +
R1-generated reasoning data
       ↓
      SFT
       ↓
Reasoning-capable smaller model

That is much more accurate than saying:

“R1's 671B weights were compressed into 1.5B weights.”

They were not directly compressed parameter-by-parameter in this approach.

26. The student still uses ordinary LM training

This is perhaps the most elegant part.

The student simply sees:

Prompt
+
teacher-generated reasoning response

and learns:

\boxed{ \text{next-token prediction} }

just like a normal language model.

So after all the sophisticated RL machinery used to create R1, the final student-training objective can return to something extremely familiar:

\boxed{\text{Cross Entropy}}

The source explicitly says there is no temperature scaling or KL divergence in this DeepSeek reasoning-distillation approach. (Source: Build a DeepSeek Model (From Scratch))

30. The most important warning about “distillation”

There are two meanings floating around:

Broad meaning

Any process of transferring teacher capability into a student.

Classical KD

Explicitly match teacher/student probability distributions using:

KL + T.
DeepSeek-R1 reasoning distillation

Use:

\boxed{ \text{teacher-generated reasoning traces} }

as supervised training data.

The source's terminology makes this distinction essential. (Source: Build a DeepSeek Model (From Scratch))

31. Capacity gap

There is one final limitation.

A small student cannot necessarily absorb everything a huge teacher knows.

The source reports that the 1.5B student performs very well on mathematical reasoning but struggles more on coding tasks, illustrating that capacity matters. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{distillation transfers capability} }

but:

\boxed{ \text{student capacity limits how much can be retained} }

The source's broader conclusion is that distillation transfers existing capabilities efficiently; it does not magically create capabilities beyond what the teacher and student architecture can support. (Source: Build a DeepSeek Model (From Scratch))
