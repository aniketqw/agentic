Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

Represent positional differences directly in attention dot products while preserving vector length.

Prerequisites: Three projections: Q, K, and V, Matrix multiplication and shape contracts

Notation and assumptions

Adjacent-pair convention, even head width d. For pair i use frequency base^(-2i/d); rotate Q and K at their absolute positions. Other pair layouts need explicit conversion.

Derivation and mechanism

  1. Construct a 2×2 orthogonal rotation for each pair.
  2. Use angle position×frequency.
  3. Because R(m)^T R(n)=R(n-m), a rotated dot product depends on relative displacement.
R(\theta)=\begin{bmatrix}\cos\theta&-\sin\theta\\\sin\theta&\cos\theta\end{bmatrix}
(R(m)q)^\top R(n)k=q^\top R(n-m)k

Worked example

At position2, [1,0,0,1] becomes [cos2,sin2,-sin.02,cos.02]≈[-.416147,.909297,-.019999,.999800]. Squared norm remains2. The checker verifies the relative-dot identity at two positions on both frequencies.

Limitations

  • Do not rotate every pair at the same frequency.
  • Norm preservation does not prove unlimited-context accuracy. Odd rotary width is rejected.

Why this matters

A repeated token ID retrieves the same token embedding. The model also needs a way to distinguish where tokens occur.

Prerequisites: Embedding lookup and one-hot equivalence, Scores to attention weights to output

Symbols, shapes and assumptions

Absolute position embeddings have the same feature width as token embeddings and are added by position. Unmasked, position-free attention is permutation equivariant; a causal mask changes the symmetry.

Derivation or mechanism

  1. Without positional features, permute Q/K/V together.
  2. Score rows and columns permute consistently; row softmax and value aggregation follow that permutation.
  3. Add position features to distinguish repeated tokens at different positions; specify the chosen position scheme.
X_t=E[id_t,:]+P[t,:]

Worked numerical

Two copies of token ID 2 initially share [1,1]. Adding position rows [0,0] and [0.1,0.2] would make them [1,1] and [1.1,1.2]. Separately, the checker permutes an unmasked attention fixture and confirms the output follows the same permutation.

Edge cases and limits

  • The unmasked equivariance proof must not be applied unchanged to a fixed causal mask.
  • Learned absolute positions, sinusoidal encodings, and RoPE are distinct methods. Only the basic position mechanism is covered by this capsule; RoPE remains pending.

Step 1.3 — Position: How Does a Transformer Know Word Order?

Plan node: I1 · chat order #10

We now have:

\text{text} \rightarrow \text{tokens} \rightarrow \text{token IDs} \rightarrow \text{token embeddings}

At this point, however, there is a fundamental problem:

The token embedding tells us what the token is, but not where it occurs.

This is exactly the issue identified in the Transformer slides: self-attention by itself does not tell the model that token 3 comes after token 2, so position information must be injected. (Source: transformers-slides)

Raschka's Chapter 2.8 makes the same point: the same token ID always receives the same embedding regardless of where it occurs in the sequence.

1.3.1 The Problem

Suppose we have:

\text{A dog bites a man}

and:

\text{A man bites a dog}

The tokens are the same:

A
dog
bites
a
man

versus

A
man
bites
a
dog

but the order is different.

And order changes the meaning.

So the model needs two kinds of information:

\boxed{\text{What token is this?}}

and

\boxed{\text{Where is this token?}}

The token embedding answers the first.

Positional information answers the second.

1.3.2 Why Token Embeddings Alone Are Not Enough

Suppose:

E(\text{dog})= [0.2,0.7,-0.1,\ldots]

Whenever token "dog" appears, the lookup table gives exactly this same vector.

For example:

Position 1: dog → [0.2, 0.7, -0.1, ...]
Position 5: dog → [0.2, 0.7, -0.1, ...]

The embedding layer doesn't inherently know whether the dog is:

  • first,
  • third,
  • fifth,
  • tenth.

Raschka explicitly illustrates this: the same token ID produces the same vector regardless of its position.

So we need to add another signal.

1.3.3 The Simplest Solution: Add a Position Vector

Suppose the sequence length is:

T=4

and embedding dimension:

d=3

Our token embeddings might be:

X_{\text{token}} = \begin{bmatrix} 0.7&0.1&0.2\\ 0.4&0.9&0.3\\ 0.8&0.2&0.5\\ 0.1&0.6&0.7 \end{bmatrix}

Create a positional embedding matrix:

P = \begin{bmatrix} 0.1&0.0&0.2\\ 0.0&0.2&0.1\\ 0.2&0.1&0.0\\ 0.3&0.0&0.1 \end{bmatrix}

Then simply add:

\boxed{ X=X_{\text{token}}+P }

giving:

X= \begin{bmatrix} 0.8&0.1&0.4\\ 0.4&1.1&0.4\\ 1.0&0.3&0.5\\ 0.4&0.6&0.8 \end{bmatrix}

Now the representation contains:

\text{token information}+\text{position information}

The Transformer slides give precisely this conceptual operation:

\boxed{X\leftarrow X+P}

where P has the same shape as the token representation matrix. (Source: transformers-slides)

Raschka's implementation also uses addition of token and positional embeddings.

1.3.4 Why Addition?

A natural question is:

Why add instead of concatenate?

We could theoretically do:

[X_{\text{token}};P]

which would give:

d+d=2d

dimensions.

But then every following layer would need to process twice as many dimensions.

Addition keeps:

\boxed{\text{model width}=d}

So the existing Transformer architecture can process the result without changing its width.

The positional vector has the same dimension as the token embedding:

P_t\in\mathbb R^d

and therefore:

X_t=E_t+P_t

is also:

X_t\in\mathbb R^d

Raschka explicitly notes that positional vectors have the same dimensionality as token embeddings so they can be added directly.

1.3.5 Shape Mathematics

Suppose:

B=8
T=128
d=768

Then:

Token embeddings
X_{\text{token}}\in\mathbb R^{8\times128\times768}
Positional embeddings

For absolute learned positional embeddings:

P\in\mathbb R^{128\times768}

PyTorch broadcasts P across the batch:

[8,128,768] + [128,768]

becomes:

\boxed{[8,128,768]}
Final input
\boxed{ X=X_{\text{token}}+P \in\mathbb R^{8\times128\times768} }

Raschka gives essentially this exact pattern with a batch of 8 sequences, 4 tokens per sequence, and 256-dimensional embeddings.

1.3.6 Absolute vs Relative Position

Now we reach an important distinction.

There are two broad approaches.

Absolute positional information

Ask:

What is the exact position of this token?

For example:

0,1,2,3,4,\ldots

Position 0 has one positional vector.

Position 1 has another.

Position 2 has another.

So:

P_0,P_1,P_2,\ldots

Raschka describes this as assigning a unique embedding to each position and adding it to the token embedding.

Relative positional information

Instead of asking:

"What is your absolute position?"

we care about:

"How far are you from the other token?"

For example:

The cat sat on the mat

When "mat" attends to "cat":

\text{distance}=4

It may be more useful for the model to understand this relationship than to simply know:

"mat" is at position 6.

Raschka explains relative positional approaches in terms of the distance between tokens.

1.3.7 Why Relative Position Can Be Attractive

Imagine training sequences mostly have lengths around 100.

An absolute-position scheme learns:

P_0,\ldots,P_{99}

But what if inference gives a sequence of length 500?

Absolute position representations can become problematic depending on the implementation and training regime.

Relative approaches can focus more naturally on relationships such as:

j-i

rather than exact positions.

Raschka notes the potential advantage of relative position methods for generalizing to different sequence lengths.

1.3.8 Learned Absolute Positional Embeddings

This is the simplest version to understand and the one implemented in Raschka's GPT-from-scratch chapter.

We create:

P\in\mathbb R^{T_{\max}\times d}

and treat P as a learnable parameter.

For example:

P= \begin{bmatrix} P_0\\ P_1\\ P_2\\ \vdots\\ P_{T_{\max}-1} \end{bmatrix}

Each:

P_i\in\mathbb R^d

is learned during training.

So:

X_t=E(x_t)+P_t

This means the same token gets different final initial representations depending on where it occurs.

For "cat":

E(\text{cat})+P_2

is different from:

E(\text{cat})+P_8

Raschka's PyTorch implementation creates a positional Embedding layer and uses:

torch.arange(context_length)

to retrieve the position vectors.

1.3.9 Exact PyTorch Implementation

The core implementation is surprisingly small:

import torch
import torch.nn as nn

batch_size = 2
seq_len = 5
embedding_dim = 8

# Token IDs
input_ids = torch.tensor([
    [1, 4, 7, 2, 9],
    [3, 5, 8, 6, 0]
])

# Token embedding table
token_embedding = nn.Embedding(
    num_embeddings=10,
    embedding_dim=embedding_dim
)

# Position embedding table
position_embedding = nn.Embedding(
    num_embeddings=seq_len,
    embedding_dim=embedding_dim
)

# Token embeddings
token_embeddings = token_embedding(input_ids)

# Positions: [0, 1, 2, 3, 4]
positions = torch.arange(seq_len)

# Positional embeddings
position_embeddings = position_embedding(positions)

# Add token + position
X = token_embeddings + position_embeddings

print("Token IDs:          ", input_ids.shape)
print("Token embeddings:  ", token_embeddings.shape)
print("Position embeddings:", position_embeddings.shape)
print("Final input X:      ", X.shape)

Shapes:

Token IDs
[2, 5]

Token embeddings
[2, 5, 8]

Positions
[5]

Position embeddings
[5, 8]

Final X
[2, 5, 8]

So:

\boxed{ [ B,T] \rightarrow [B,T,d] + [T,d] \rightarrow [B,T,d] }

This follows the positional-embedding procedure shown in Raschka's implementation.

1.3.10 But What Did the Original Transformer Do?

Now an important historical distinction.

The original Transformer used sinusoidal positional encodings rather than learned position vectors.

The standard equations are:

\boxed{ PE_{(pos,2i)} = \sin \left( \frac{pos}{10000^{2i/d_{\text{model}}}} \right) }

and

\boxed{ PE_{(pos,2i+1)} = \cos \left( \frac{pos}{10000^{2i/d_{\text{model}}}} \right) }

Here:

  • pos = token position
  • i = dimension index
  • d_{\text{model}} = model dimension

Your DeepSeek book explains this construction as using smooth sine/cosine waves at different frequencies, replacing crude discrete position encodings with continuous signals. (Source: Build a DeepSeek Model (From Scratch))

1.3.11 Why Sine and Cosine?

This formula looks scary:

\sin\left(\frac{pos}{10000^{2i/d}}\right)

but the underlying idea is simple.

We want every position to generate a distinctive pattern.

So imagine several waves:

dimension 1:  ~~~~~ very fast
dimension 2:  ~~~~  fast
dimension 3:  ~~~   medium
dimension 4:  ~~    slower
dimension 5:  ~     very slow

Each dimension changes at a different frequency.

Thus position 10 and position 11 produce slightly different patterns, while position 10 and position 100 produce much more different patterns.

The DeepSeek book explains exactly this multi-frequency intuition. (Source: Build a DeepSeek Model (From Scratch))

1.3.12 Small Numerical Example

Take:

d_{\text{model}}=4

and position:

pos=1

For dimension 2i=0:

PE(1,0) = \sin(1) \approx0.8415

For dimension 2i+1=1:

PE(1,1) = \cos(1) \approx0.5403

For the next pair, the denominator becomes larger:

10000^{2/4}=100

so:

PE(1,2)=\sin(0.01)\approx0.0100
PE(1,3)=\cos(0.01)\approx0.99995

So approximately:

PE_1 = [0.8415,0.5403,0.0100,0.99995]

Another position, say pos=2, produces another vector:

PE_2 = [\sin2,\cos2,\sin0.02,\cos0.02]

Hence the position is encoded as a pattern across dimensions.

1.3.13 The Beautiful Part of Sinusoidal Encoding

The low-frequency dimensions change slowly.

The high-frequency dimensions change rapidly.

So together they provide:

\boxed{ \text{fine positional information} + \text{coarse positional information} }

Think of it like having multiple clocks running at different speeds.

One clock distinguishes nearby positions.

Another captures broader location.

Another changes even more slowly.

The DeepSeek book's discussion specifically emphasizes this multi-frequency structure. (Source: Build a DeepSeek Model (From Scratch))

1.3.14 Learned Absolute vs Sinusoidal

Now keep these distinct.

Method Position representation Learned?
Learned absolute One vector per position Yes
Sinusoidal Sine/cosine functions No
Relative methods Position relationships/distances Depends
RoPE Rotates Q/K by position Learned projections + fixed rotational structure

Raschka's book, in its GPT-from-scratch implementation, uses learned absolute positional embeddings.

The original Transformer used sinusoidal encodings.

Your Transformer slides then point out an important modern development:

RoPE (Rotary Position Embedding). (Source: transformers-slides)

1.3.15 RoPE — The Modern Direction

We will study RoPE more deeply later, but you should understand the core idea now.

Instead of doing:

X=E+P

RoPE modifies the query and key vectors according to their positions.

For a simplified 2D pair:

R_m(\theta) = \begin{bmatrix} \cos(m\theta)&-\sin(m\theta)\\ \sin(m\theta)&\cos(m\theta) \end{bmatrix}

Then:

q_m=R_mq

and:

k_n=R_nk

The important mathematical consequence is:

q_m^Tk_n

becomes dependent on the relative displacement:

n-m

The attention handbook in your source set derives this relationship explicitly. (Source: Understanding_Attention_Handbook_01)

So RoPE gives attention a way to incorporate positional relationships inside the Q/K interaction.

1.3.16 Why This Is Different From Adding P

Compare:

Learned absolute position
\boxed{ X_t=E_t+P_t }

Position is injected into the representation.

RoPE
\boxed{ Q_t\rightarrow R_tQ_t,\qquad K_t\rightarrow R_tK_t }

Position is incorporated directly into the attention compatibility calculation.

This distinction becomes extremely important when we study the actual attention equation.

1.3.17 A Subtle but Important Point: Causal Mask ≠ Positional Encoding

Do not confuse these.

A causal mask says:

You are not allowed to look at future positions.

For example:

position 4 can see:
1 2 3 4

but cannot see:
5 6 7

That provides a directional constraint.

But it does not fully tell the model:

"Token 4 is exactly four positions after token 0."

The attention handbook explicitly distinguishes these: a causal mask imposes directional ordering constraints, but does not itself provide a rich representation of position or distance. (Source: Understanding_Attention_Handbook_01)

So:

\boxed{ \text{Causal mask} \neq \text{positional encoding} }

This will save you from a very common interview mistake.

1.3.18 Why Position Matters for Attention

We are now ready to connect position to what comes next.

Without positional information:

X= \begin{bmatrix} e_{\text{cat}}\\ e_{\text{sat}}\\ e_{\text{here}} \end{bmatrix}

Self-attention computes interactions between these representations.

But if you permute the rows, plain self-attention without position-dependent information treats the operation symmetrically with respect to that permutation: the outputs permute along with the inputs.

The attention handbook describes this as permutation equivariance. (Source: Understanding_Attention_Handbook_01)

That's the mathematical reason position must be injected.

1.3.19 The Full Input Representation Now

Previously:

x_t=E(x_t)

Now:

\boxed{ x_t=E(x_t)+P_t }

or, for the complete sequence:

\boxed{ X=X_{\text{token}}+X_{\text{position}} }

Therefore:

token ID
   ↓
token embedding
   +
position information
   ↓
position-aware representation
   ↓
Transformer

This is the complete input to the attention mechanism in the learned-absolute-position formulation.

1.3.20 Connecting All Three Steps

We now have:

Step 1.1 — Language model
P(x_t\mid x_{<t})
Step 1.2 — Token representation
x_t \rightarrow \text{token ID} \rightarrow E(x_t)
Step 1.3 — Position
E(x_t) \rightarrow E(x_t)+P_t

Therefore:

\boxed{ \text{text} \rightarrow \text{tokens} \rightarrow \text{IDs} \rightarrow \text{token embeddings} \rightarrow \text{position-aware embeddings} \rightarrow \text{attention} }

And now we can finally understand the heart of the Transformer.

1.3.21 The Next Question

Suppose we have:

The animal didn't cross the road because it was tired.

When processing:

it

the model should probably look strongly at:

animal

rather than:

road

So we need a mechanism that answers:

For the current token, which other tokens are relevant, and by how much?

That mechanism is self-attention.

And this is where our earlier mathematical concepts suddenly become useful:

\boxed{ Q=XW_Q }
\boxed{ K=XW_K }
\boxed{ V=XW_V }

followed by:

\boxed{ S=QK^T }

then:

\boxed{ A=\operatorname{softmax} \left( \frac{S}{\sqrt{d_k}} \right) }

and:

\boxed{ O=AV }

We already saw these equations abstractly in the mathematical foundation. Now we are going to derive why every single one of them exists.
