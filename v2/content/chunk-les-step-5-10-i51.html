Step 5.10 — The Actual DeepSeekMath GRPO Objective

Plan node: I7 · chat order #51

Now we go one level deeper.

In the previous steps, we used a simplified sequence-level GRPO implementation to understand the mechanics. That was useful for learning, but it is important not to confuse it with the original DeepSeekMath formulation.

The supplied DeepSeekMath slides make this distinction explicit:

\boxed{\text{DeepSeekMath: token-level clipping}}

whereas the later DeepSeek-R1 formulation shown in the supplied R1 slides uses:

\boxed{\text{one sequence-level ratio for the whole response}}

(Source: deepseekmath-slides; deepseek-r1-slides)

This distinction is extremely important for exams and for understanding later GRPO variants.

5.10.1 Start from the big picture

For one prompt q:

q

the old/current policy generates G responses:

o_1,o_2,\ldots,o_G.

Each response contains tokens:

o_i=(o_{i,1},o_{i,2},\ldots,o_{i,|o_i|}).

Then:

\boxed{ \text{prompt} \rightarrow \text{multiple responses} \rightarrow \text{reward} \rightarrow \text{advantages} \rightarrow \text{policy update} }

The original DeepSeekMath objective then performs the policy update at the token level. (Source: deepseekmath-slides)

5.10.2 The full objective

The supplied slide gives the DeepSeekMath objective in the following structure:

\boxed{ J_{\mathrm{GRPO}}(\theta) = \mathbb E \left[ \frac1G \sum_{i=1}^{G} \frac1{|o_i|} \sum_{t=1}^{|o_i|} \min \left( r_{i,t}(\theta)A_{i,t}, \operatorname{clip} \left(r_{i,t}(\theta),1-\epsilon,1+\epsilon\right) A_{i,t} \right) - \beta D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}}) \right] }

where

\boxed{ r_{i,t}(\theta) = \frac{ \pi_\theta(o_{i,t}\mid q,o_{i,<t}) }{ \pi_{\theta_{\mathrm{old}}}(o_{i,t}\mid q,o_{i,<t}) } }

and the advantage is derived from the rewards of the group.

This is the key equation for this step. (Source: deepseekmath-slides)

5.10.3 Now we decode the formula piece by piece

Do not try to memorize the entire equation at once.

We will construct it.

Part 1 — G

G

is the number of sampled responses for one prompt.

Example:

G=4.

Then:

o_1,o_2,o_3,o_4.

The group comparison is what makes this Group Relative Policy Optimization.

5.10.4 Part 2 — o_i

For response i:

o_i=(o_{i,1},o_{i,2},\ldots,o_{i,T_i})

where:

T_i=|o_i|

is its number of generated tokens.

Example:

Response 1 = [token1, token2, token3, token4]

then:

|o_1|=4.

5.10.5 Part 3 — Why divide by G?

The objective averages across sampled responses:

\frac1G\sum_{i=1}^{G}.

Without this normalization, increasing group size would automatically increase the magnitude of the objective.

So:

\boxed{ \frac1G }

makes the contribution an average over the group.

5.10.6 Part 4 — Why divide by |o_i|?

Inside each response:

\frac1{|o_i|} \sum_{t=1}^{|o_i|}.

This means the token-level contributions are averaged over the response length.

That matters because otherwise a longer response contains more terms in the sum and can contribute disproportionately.

For example, imagine:

|o_1|=10

and:

|o_2|=100.

Without length normalization, the second response has ten times as many token-level terms.

The original formulation explicitly includes:

\boxed{\frac1{|o_i|}}

to average the token contributions within each response. (Source: deepseekmath-slides)

5.10.7 Part 5 — The token probability ratio

Now we reach the most important quantity:

\boxed{ r_{i,t}(\theta) = \frac{ \pi_\theta(o_{i,t}\mid q,o_{i,<t}) }{ \pi_{\theta_{\mathrm{old}}}(o_{i,t}\mid q,o_{i,<t}) } }

Read this in English:

How much more or less likely is the current policy to generate this particular token compared with the policy that generated the rollout?

5.10.8 Example

Suppose the old policy assigned:

P_{\text{old}}=0.20

to the sampled token.

After updating the model, the current policy assigns:

P_{\text{new}}=0.30.

Then:

r= \frac{0.30}{0.20} = 1.5.

Therefore:

\boxed{r=1.5}

means the current model considers that sampled token:

\boxed{50\%\text{ more likely}}

than the old model did.

5.10.9 Three interpretations of the ratio

r=1
P_{\text{new}}=P_{\text{old}}

No probability change.

r>1
P_{\text{new}}>P_{\text{old}}

The current policy is increasing the probability.

r<1
P_{\text{new}}<P_{\text{old}}

The current policy is decreasing the probability.

Thus:

\boxed{ r\text{ measures policy movement} }

5.10.10 Part 6 — The advantage

The ratio alone doesn't say whether we want the probability to increase or decrease.

That comes from:

\boxed{A_{i,t}}.

The advantage answers:

Was this sampled behavior better or worse relative to the other responses?

For outcome-based reward, the same group-level reward signal can conceptually be applied across the generated tokens of a response.

Suppose:

R=[1,1,0,0].

Then:

\mu_R=0.5.

The correct responses have:

R_i-\mu_R>0

and wrong responses have:

R_i-\mu_R<0.

After normalization:

A>0

for stronger responses and:

A<0

for weaker responses.

The supplied GRPO material defines this group-relative signal from the within-group rewards. (Source: Build a DeepSeek Model (From Scratch))

5.10.11 Why the product rA?

This is the key RL intuition.

We have:

r\times A.

Suppose:

A>0.

This means:

We want to reinforce this action.

So increasing its probability is desirable.

If:

r>1,

then:

rA

gets larger.

That is good.

Now suppose:

A<0.

This means:

We want to suppress this action.

If:

r<1,

the policy is reducing its probability.

That is desirable.

So the sign of A tells the optimizer:

\boxed{\text{up or down}}

while r tells it:

\boxed{\text{how much the probability moved}}

5.10.12 A numerical example

Suppose:

A=0.8.

And:

r=1.2.

Then:

rA = 1.2(0.8) = 0.96.

A positive contribution.

Now suppose:

A=-0.8

and:

r=0.8.

Then:

rA = 0.8(-0.8) = -0.64.

The update is moving the probability downward for a negatively advantaged action.

5.10.13 Why can't we just use rA?

Because the model could move too aggressively.

Suppose:

A=1

and:

r=10.

Then:

rA=10.

The model has dramatically increased the probability of this sampled behavior in one update.

Repeated aggressive changes can destabilize policy optimization.

This is where clipping enters.

5.10.14 Part 7 — Clipping

The clipped ratio is:

\boxed{ \operatorname{clip}(r,1-\epsilon,1+\epsilon) }

Suppose:

\epsilon=0.2.

Then:

1-\epsilon=0.8

and:

1+\epsilon=1.2.

Therefore:

r<0.8 \Rightarrow 0.8

and:

r>1.2 \Rightarrow 1.2.

So the allowed effective ratio range is:

\boxed{[0.8,1.2]}.

5.10.15 Numerical example

Suppose the ratios are:

[1.1,1.3,0.7,1.0].

With:

\epsilon=0.2

the clipped ratios become:

[1.1,1.2,0.8,1.0].

So:

\boxed{ [1.1,1.3,0.7,1.0] \rightarrow [1.1,1.2,0.8,1.0] }

5.10.16 Why use \min?

The objective has:

\min \left( rA,\, \operatorname{clip}(r,1-\epsilon,1+\epsilon)A \right).

This is inherited from the PPO-style clipped objective.

The idea is:

Don't allow the optimizer to obtain an arbitrarily large benefit from moving the policy too far in one update.

5.10.17 Positive-advantage case

Suppose:

A=+1.

and:

r=1.5.

Then:

rA=1.5.

Clipped:

1.2\times1=1.2.

Therefore:

\min(1.5,1.2)=1.2.

So the objective does not give the model the full benefit of pushing that probability from 1.0 to 1.5.

5.10.18 Negative-advantage case

Suppose:

A=-1

and:

r=0.5.

Then:

rA=-0.5.

Clipped:

0.8(-1)=-0.8.

Therefore:

\min(-0.5,-0.8) = -0.8.

This case is subtle.

Because the objective is being maximized, the clipped surrogate prevents exploiting an overly large probability reduction as an arbitrarily favorable update.

When implementing it as a PyTorch minimization loss, the whole objective is negated.

5.10.19 The three-policy distinction

You should now permanently separate these three models.

Current policy

\boxed{\pi_\theta}

This is the model being trained.

It changes after optimizer steps.

Old policy

\boxed{\pi_{\theta_{\text{old}}}}

This is the policy that generated the sampled responses.

It provides the denominator:

\frac{\pi_\theta}{\pi_{\theta_{\text{old}}}}.

Its purpose is:

\boxed{\text{control the size of the current update}}

Reference policy

\boxed{\pi_{\text{ref}}}

This is used for KL regularization.

Its purpose is:

\boxed{\text{prevent excessive long-term drift}}

The supplied DeepSeekMath slide explicitly identifies the current policy, pre-update/old policy, and fixed reference policy as separate roles. (Source: deepseekmath-slides)

5.10.20 Old vs Reference — an interview favorite

Think:

OLD POLICY
     │
     │ ratio
     ▼
"How far did I move from
the policy that generated
these samples?"

while:

REFERENCE POLICY
     │
     │ KL
     ▼
"How far have I drifted
from my long-term anchor?"

So:

\boxed{ \text{old}=\text{short-term comparison} }
\boxed{ \text{reference}=\text{long-term anchor} }

5.10.21 Part 8 — KL regularization

The objective subtracts:

\boxed{ \beta D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}}) }

from the reward-maximizing objective.

The intuition is:

\text{maximize task performance} - \text{penalty for excessive drift}.

Thus:

\boxed{\beta}

controls the strength of this constraint.

5.10.22 What happens when \beta changes?

Small \beta

The model is allowed to move further from the reference.

Potential benefit:

\text{more freedom}

Potential risk:

\text{policy drift / instability}.
Large \beta

The model is strongly constrained.

Potential benefit:

\text{stability}

Potential risk:

\text{learning can become too weak}.

The supplied material discusses exactly this tradeoff. (Source: Build a Reasoning Model (From Scratch))

5.10.23 Now the most important distinction: token-level vs sequence-level

This is where the earlier lessons become connected.

DeepSeekMath

For each token:

\boxed{ r_{i,t} = \frac{ \pi_\theta(o_{i,t}|q,o_{i,<t}) }{ \pi_{\text{old}}(o_{i,t}|q,o_{i,<t}) } }

So:

r_{i,1},r_{i,2},r_{i,3},\ldots

can all be different.

The clipping happens independently at the token level. (Source: deepseekmath-slides)

DeepSeek-R1 formulation shown in the supplied slides

The R1 slide instead uses:

\boxed{ r_i = \frac{\pi_\theta(o_i|q)} {\pi_{\text{old}}(o_i|q)} }

one ratio for the entire response.

The slide explicitly calls this a change from DeepSeekMath's token-level formula to a sequence-level ratio. (Source: deepseek-r1-slides)

5.10.24 Where does the sequence probability come from?

An autoregressive model factorizes a response probability as:

\boxed{ \pi(o_i|q) = \prod_{t=1}^{|o_i|} \pi(o_{i,t}|q,o_{i,<t}) }

Therefore the sequence ratio becomes:

\frac{\pi_\theta(o_i|q)} {\pi_{\text{old}}(o_i|q)} = \frac{ \prod_t \pi_\theta(o_{i,t}|q,o_{i,<t}) }{ \prod_t \pi_{\text{old}}(o_{i,t}|q,o_{i,<t}) }

which is:

\boxed{ r_i = \prod_{t=1}^{|o_i|} r_{i,t} }

This relation is mathematically extremely important.

5.10.25 Why log probabilities are used in practice

Products of many probabilities can become extremely tiny.

Instead use:

\log \pi(o_i|q) = \sum_t \log\pi(o_{i,t}|q,o_{i,<t}).

Therefore:

\log r_i = \log\pi_\theta(o_i|q) - \log\pi_{\text{old}}(o_i|q).

Then:

\boxed{ r_i = \exp( \log\pi_\theta(o_i|q) - \log\pi_{\text{old}}(o_i|q) ) }

This connects directly to the log-probability implementation we already built.

5.10.26 Numerical demonstration: token-level vs sequence-level

Suppose one response contains 3 tokens and the token ratios are:

r_1=1.1, \quad r_2=1.3, \quad r_3=0.7.

The sequence ratio is:

r_{\text{seq}} = 1.1\times1.3\times0.7.

Calculate:

1.1\times1.3=1.43

then:

1.43\times0.7=1.001.

So:

\boxed{r_{\text{seq}}\approx1.001}

even though the individual token ratios include:

1.3

and:

0.7.

This is a fundamental difference.

5.10.27 Why this matters more for long responses

Suppose every token moves by only:

1.01.

For 100 tokens:

r_{\text{seq}} = 1.01^{100}.

Using the approximation:

1.01^{100}\approx2.705.

So tiny per-token movements can compound into a large sequence-level ratio.

Likewise, if:

r_t=0.99

for 100 tokens:

0.99^{100}\approx0.366.

Thus sequence-level ratios are highly sensitive to accumulated token-level changes.

This is one reason the distinction between sequence-level and token-level optimization matters enormously for long reasoning traces.

5.10.28 Exam numerical — ratio

Old probability:

0.25.

Current probability:

0.30.

Then:

r=\frac{0.30}{0.25}=1.2.

Answer:

\boxed{1.2}

5.10.29 Exam numerical — clipping

Given:

r=1.5,\qquad \epsilon=0.2.

The clipping range is:

[0.8,1.2].

Therefore:

\boxed{\operatorname{clip}(1.5,0.8,1.2)=1.2}.

5.10.30 Exam numerical — sequence ratio

Suppose:

r_1=1.2,\quad r_2=0.9,\quad r_3=1.1.

Then:

r_{\text{seq}} = 1.2(0.9)(1.1).
=1.188.

Therefore:

\boxed{r_{\text{seq}}=1.188}.

5.10.31 Exam numerical — log-ratio

Suppose:

\log p_{\text{new}}=-5

and:

\log p_{\text{old}}=-5.4.

Then:

\log r = -5-(-5.4) = 0.4.

Therefore:

r=e^{0.4} \approx1.492.

So the current policy assigns approximately:

\boxed{49.2\%}

more probability to the sampled event.

5.10.32 Tensor shapes

Suppose:

  • batch size B=2,
  • group size G=4,
  • response length T=128.

Then token log-probabilities can be represented as:

\boxed{ [B,G,T]=[2,4,128]. }

So:

\text{logp}_{\text{new}} \in \mathbb R^{2\times4\times128}.

Similarly:

\text{old\_logp}, \text{ref\_logp} \in \mathbb R^{2\times4\times128}.

The ratio:

r=\exp(\text{new\_logp}-\text{old\_logp})

therefore also has:

\boxed{[2,4,128]}

shape.

For outcome-level reward, advantages might initially have:

[B,G]=[2,4]

and be expanded across the token dimension to:

[2,4,128].

This matches the structure of the token-level objective.

5.10.33 One complete toy example

Let:

G=4

with rewards:

R=[1,1,0,0].

Suppose normalized advantages are approximately:

A=[+0.866,+0.866,-0.866,-0.866].

Now consider the first response with three token ratios:

r=[1.1,1.3,0.9].

Take:

\epsilon=0.2.

Thus:

r_{\text{clip}} = [1.1,1.2,0.9].

For:

A=0.866,

the unclipped terms are:

[1.1(0.866),1.3(0.866),0.9(0.866)]
\approx [0.953,1.126,0.779].

Clipped terms:

[1.1(0.866),1.2(0.866),0.9(0.866)]
\approx [0.953,1.039,0.779].

Take the minimum token by token:

\boxed{ [0.953,1.039,0.779] }

Then average over the three response tokens:

\frac{0.953+1.039+0.779}{3} \approx0.924.

That is the token-level surrogate contribution for this response before averaging over the group and applying the KL component.

5.10.34 What exactly changed between our earlier simplified code and this?

Earlier we used essentially:

L = -\frac1N \sum_i A_i\log p_i

and later:

\text{ratio}=\exp(\text{new logp}-\text{old logp})

with clipping and KL.

That was intentionally educational.

The full DeepSeekMath-style expression adds:

\boxed{ \text{token-level ratio} }

and:

\boxed{ \frac1{|o_i|} \sum_t }

inside each response.

So the progression is:

\boxed{ \text{simple policy gradient} }
\downarrow
\boxed{ \text{group-relative advantage} }
\downarrow
\boxed{ \text{clipped importance ratio} }
\downarrow
\boxed{ \text{KL reference constraint} }
\downarrow
\boxed{ \text{full token-level GRPO} }

5.10.35 Why did we learn the simplified version first?

Because the full equation hides the idea under notation.

The conceptual dependency is:

\boxed{ A \rightarrow r \rightarrow \text{clip} \rightarrow \text{KL} }

Once you understand those four pieces independently, the full objective becomes straightforward.

That is exactly the conceptual bridge between the chapter's introductory implementation and the original algorithm. The source itself notes that its simpler earlier implementation omitted parts of the full objective for pedagogical reasons. (Source: Build a Reasoning Model (From Scratch))

5.10.36 Another important connection: GRPO vs Online RFT

The supplied DeepSeekMath slides make a powerful observation.

Online RFT and GRPO both:

\boxed{\text{sample from the current policy}}

but their learning coefficients differ.

Online RFT essentially uses a binary correctness signal.

GRPO uses the group-relative advantage:

\boxed{ A_i= \frac{R_i-\mu_R}{\sigma_R+\epsilon} }

so above-average responses receive stronger positive reinforcement and below-average responses receive negative reinforcement. (Source: deepseekmath-slides)

Therefore:

\boxed{ \text{same online data source} \neq \text{same learning rule} }

5.10.38 And this explains later GRPO variants

The Chapter 7 material lists later modifications such as:

\boxed{\text{DAPO}}

with token-level loss,

\boxed{\text{GSPO}}

with sequence-level importance sampling/clipping,

and:

\boxed{\text{CISPO}}

which clips importance weights directly. (Source: Build a Reasoning Model (From Scratch))

So when you later see these names, don't treat them as random new algorithms.

They are modifications of specific pieces of the GRPO machinery:

GRPO
 │
 ├── advantage normalization
 ├── importance ratio
 ├── clipping
 ├── KL
 └── response/token aggregation
        │
        ├── DAPO
        ├── Dr. GRPO
        ├── GSPO
        └── CISPO

5.10.39 The complete reasoning chain

Now you should be able to narrate the algorithm without looking at the formula:

For each question, sample several responses from the old policy. Verify each response and obtain rewards. Compare those rewards within the group to produce relative advantages. For every generated token, compare the current policy probability with the old policy probability using an importance ratio. Clip that ratio so one update cannot move the policy too aggressively. Average the token contributions within each response and the responses within the group. Finally, use a KL penalty to discourage excessive drift from the reference policy.

That is the DeepSeekMath GRPO objective in words. (Source: deepseekmath-slides)

5.10.40 Master formula map

Keep this hierarchy in your notes:

\boxed{ A_i = \frac{R_i-\mu_R}{\sigma_R+\epsilon} }

then:

\boxed{ r_{i,t} = \frac{\pi_\theta(o_{i,t}|q,o_{i,<t})} {\pi_{\text{old}}(o_{i,t}|q,o_{i,<t})} }

then:

\boxed{ \tilde r_{i,t} = \operatorname{clip}(r_{i,t},1-\epsilon,1+\epsilon) }

then:

\boxed{ \min(r_{i,t}A_{i,t},\tilde r_{i,t}A_{i,t}) }

then:

\boxed{ \frac1{|o_i|} \sum_t(\cdot) }

then:

\boxed{ \frac1G\sum_i(\cdot) }

then:

\boxed{ -\beta D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}}) }

and finally:

\boxed{ J_{\mathrm{GRPO}} = \text{clipped policy improvement} - \text{reference-policy drift penalty} }
