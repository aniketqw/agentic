R102.3 — RLVR: Turning a Verifier Into the Reward Function

Plan node: B2 · chat order #120

↩ Back to main text: Step 5.7 — The Full GRPO Training Algorithm · Step 5.12 — DeepSeek-R1 From Scratch: R1-Zero → R1 → Distill

We have now reached the point where GRPO becomes especially powerful for reasoning tasks.

Recall the GRPO pipeline:

\text{prompt} \rightarrow \text{multiple completions} \rightarrow \text{rewards} \rightarrow \text{group-relative advantages} \rightarrow \text{GRPO update}.

The next question is:

Where do those rewards come from?

The source introduces:

\boxed{\text{RLVR = Reinforcement Learning with Verifiable Rewards}}

The central idea is simple:

\boxed{ \text{replace a learned reward model with a deterministic verifier} }

when the task has objectively checkable outcomes. (Source: Build a DeepSeek Model (From Scratch))

1. Reward is the missing piece

We already have:

\pi_\theta

generating responses.

For one prompt:

Prompt
  │
  ├── Response 1
  ├── Response 2
  ├── Response 3
  └── Response 4

Now we need:

r_1,r_2,r_3,r_4.

The reward answers:

How successful was each response?

In PPO/GRPO, this reward could come from a learned reward model.

But for some tasks, we can do something much simpler.

2. Math gives us an obvious verifier

Suppose the prompt is:

What is 5+2\times3?

The correct answer is:

11.

The model generates:

Response A → 11
Response B → 8
Response C → 11
Response D → 9

A deterministic program can check them.

For example:

if extracted_answer == gold_answer:
    reward = 1
else:
    reward = 0

Therefore:

[1,0,1,0].

No neural reward model is required.

That is RLVR. (Source: Build a DeepSeek Model (From Scratch))

3. Why is a verifier attractive?

A learned reward model approximates a judgment.

A deterministic verifier directly computes it.

For an objective task:

\boxed{ \text{correct answer} \rightarrow \text{known rule} \rightarrow \text{reward} }

This has several advantages.

The source emphasizes that RLVR can provide a less subjective and automatically computable reward signal without requiring human labels for every generated response. (Source: Build a DeepSeek Model (From Scratch))

4. Code is another natural RLVR task

Suppose the prompt says:

Write a Python function to reverse a string.

The model produces code.

We can run:

generated code
      ↓
unit tests
      ↓
pass/fail
      ↓
reward

For example:

R= \begin{cases} 1,&\text{tests pass}\\ 0,&\text{tests fail} \end{cases}

The source explicitly gives code tests or a compiler as examples of deterministic verification. (Source: Build a DeepSeek Model (From Scratch))

5. Symbolic tasks also work

The source also mentions symbolic tasks.

For example, if the model has to produce something satisfying a formal rule:

\text{candidate} \rightarrow \text{formal checker} \rightarrow R.

So the general criterion is not:

“Is this task about math?”

It is:

\boxed{ \text{Can correctness be reliably checked automatically?} }

6. RLVR is not the same as “reward = 1 if answer is correct”

That is only the simplest example.

The source emphasizes that verifier design itself matters.

A verifier has to answer two questions:

Correctness
\boxed{\text{Did the model actually solve the task?}}
Extraction / protocol
\boxed{\text{Can I reliably identify what the model claims as its answer?}}

Both matter.

(Source: Build a DeepSeek Model (From Scratch))

7. Why answer parsing matters

Imagine the model produces:

I first thought the answer might be 12.

After checking, I get 11.

Final answer: 11

A naive verifier that simply searches for the first number might extract:

12

and mark the response wrong.

But the actual answer was:

11.

So the verifier itself introduces noise.

The source therefore recommends defining a structured response protocol, such as placing the final answer after a marker like:

Final answer:

(Source: Build a DeepSeek Model (From Scratch))

8. Format becomes part of the RL problem

Suppose we require:

<think>
reasoning...
</think>

Final answer: 11

Now the verifier knows exactly where to look.

This can make reward assignment much more reliable.

The source notes that format rules can be used alongside correctness rewards, especially in the DeepSeek-R1-Zero discussion. (Source: Build a DeepSeek Model (From Scratch))

9. DeepSeek-R1-Zero's reward design

This takes us directly to the DeepSeek reasoning story.

The source describes R1-Zero as using rule-based rewards for reasoning tasks, including:

\boxed{\text{correctness reward}}

and:

\boxed{\text{format reward}}.

The correctness component checks whether the final answer is correct.

The format component encourages the expected reasoning/final-answer structure.

(Source: Build a DeepSeek Model (From Scratch))

So conceptually:

\boxed{ R = R_{\text{correctness}} + R_{\text{format}} }

This is a conceptual decomposition from the source's description; the exact weighting/formula is not established in the excerpt, so we should not invent it.

10. Why is RLVR especially suitable for reasoning?

This is the important insight.

Suppose we have a difficult math problem.

We may not know the exact reasoning sequence the model should use.

There may be many valid paths:

Path A ──→ correct
Path B ──→ correct
Path C ──→ correct
Path D ──→ wrong

Supervised learning would ideally need target traces for those paths.

RLVR doesn't.

It can simply ask:

\boxed{ \text{Did the generated solution reach the correct result?} }

Then GRPO can compare multiple candidate solutions.

This is exactly the setting in which the source says RL can discover reasoning behavior instead of merely imitating human-written reasoning traces. (Source: Build a DeepSeek Model (From Scratch))

11. But RLVR does NOT solve all alignment

This is a crucial qualification from the source.

RLVR works beautifully when correctness is objectively verifiable.

But what about:

“Was this answer helpful?”

There is no simple deterministic checker.

Or:

“Was the tone appropriate?”

Again, not a simple mathematical predicate.

Or:

“Was this creative story better?”

No objective verifier.

So:

\boxed{ \text{RLVR is not a universal replacement for reward models} }

For open-ended behavior, the source says learned reward models, preference data, or human evaluation may still be necessary. (Source: Build a DeepSeek Model (From Scratch))

12. Math vs open-ended assistant behavior

Think of the difference:

Math
answer=11?

Easy to verify.

Code
\text{does program pass tests?}

Often automatically verifiable.

Helpful conversation
\text{is response useful?}

Requires a more subjective signal.

Safety
\text{is behavior harmless?}

Not generally reducible to a single deterministic checker.

Therefore:

\boxed{ \text{objective task} \rightarrow \text{RLVR is natural} }

while:

\boxed{ \text{subjective task} \rightarrow \text{preference/reward-model signals} }

The source later describes DeepSeek-R1 itself as using this hybrid idea. (Source: Build a DeepSeek Model (From Scratch))

13. Now combine GRPO + RLVR

We have:

GRPO

Generates:

G

responses for one prompt.

RLVR

Scores each response with a deterministic verifier.

So:

Prompt P
   │
   ├── Completion 1 → verifier → r₁
   ├── Completion 2 → verifier → r₂
   ├── Completion 3 → verifier → r₃
   └── Completion 4 → verifier → r₄
                              │
                              ▼
                       group normalization
                              │
                              ▼
                       advantages A₁...A₄
                              │
                              ▼
                         GRPO objective

This is the combination that produces the central DeepSeek-R1-Zero experiment. (Source: Build a DeepSeek Model (From Scratch))

14. Now comes the famous R1-Zero question

The source asks a very interesting experimental question:

Can reasoning emerge from RL alone, without supervised reasoning examples first?

The setup is:

\boxed{ \text{DeepSeek-V3-Base} + \text{GRPO} + \text{verifiable rewards} }

with no initial supervised chain-of-thought training.

(Source: Build a DeepSeek Model (From Scratch))

That produces:

\boxed{\text{DeepSeek-R1-Zero}}

in the source's framing.

15. What does “without SFT” mean here?

It does not mean:

“No pre-training happened.”

The starting point is already a pretrained base model:

\boxed{\text{DeepSeek-V3-Base}}

The absence is specifically:

\boxed{ \text{no supervised chain-of-thought examples before the RL experiment} }

This distinction is extremely important.

The pipeline is:

Pretrained Base Model
        │
        ▼
       GRPO
        │
   Verifiable rewards
        │
        ▼
    R1-Zero

not:

random model → RL

The source explicitly states that R1-Zero starts from DeepSeek-V3-Base. (Source: Build a DeepSeek Model (From Scratch))

16. What behavior did the source highlight?

During training, the model begins allocating more tokens to difficult problems.

The source is careful here:

\boxed{ \text{longer responses are not valuable by themselves} }

Rather, longer reasoning can provide room to:

  • try an approach,
  • inspect intermediate results,
  • detect mistakes,
  • revise.

(Source: Build a DeepSeek Model (From Scratch))

So:

\text{length}\uparrow

is interesting only when:

\text{correctness}\uparrow

too.

17. The “aha moment”

The source highlights an example from the DeepSeek-R1 report in which the model notices that its current approach needs to be reconsidered.

This is presented as an “aha moment” example. (Source: Build a DeepSeek Model (From Scratch))

The important interpretation is not:

“The model magically became conscious.”

Rather, the source's technical interpretation is that RL pressure can produce increasingly self-corrective reasoning behavior on verifiable tasks.

18. What is <think>?

The source makes a useful clarification.

The:

<think>

marker is:

\boxed{\text{not a Python construct}}

and:

\boxed{\text{not a special interpreter}}

It is a formatting convention used in the reported response to distinguish the reasoning-style region from the final answer region. (Source: Build a DeepSeek Model (From Scratch))

So:

<think>
reasoning-style text
</think>

final answer

is simply part of the model's output protocol in that context.

19. A critical qualification about R1-Zero

We should not overstate the result.

The source explicitly says:

\boxed{ \text{R1-Zero demonstrates reasoning-like behavior under RL pressure} }

but not:

\boxed{ \text{any model + any reward ⇒ reasoning} }

Nor does R1-Zero automatically become a polished assistant.

The source notes issues such as:

  • poor readability,
  • language mixing.

These limitations motivate the more engineered DeepSeek-R1 pipeline. (Source: Build a DeepSeek Model (From Scratch))

20. Now the three names become clear

This is one of the most important pieces to understand.

DeepSeek-R1-Zero
\boxed{ \text{pure RL experiment} }

starting from:

\text{V3-Base}

with:

\text{GRPO + verifiable rewards}

and no supervised reasoning traces beforehand.

DeepSeek-R1
\boxed{ \text{engineered reasoning pipeline} }

The source describes:

\text{cold-start SFT} \rightarrow \text{reasoning RL} \rightarrow \text{rejection sampling} \rightarrow \text{mixed-data SFT} \rightarrow \text{final RL}.

(Source: Build a DeepSeek Model (From Scratch))

DeepSeek-R1-Distill
\boxed{ \text{smaller student models trained from R1-generated data} }

This comes later in the knowledge-distillation chapter.

(Source: Build a DeepSeek Model (From Scratch))

21. A subtle but very important data-flow distinction

The source explicitly warns against thinking:

R1\text{-Zero} \rightarrow R1

means:

“Take R1-Zero's weights and continue training.”

That's not the intended interpretation.

Instead:

\boxed{ R1\text{-Zero outputs} \rightarrow \text{sample} \rightarrow \text{filter} \rightarrow \text{training data} \rightarrow R1 }

So this is a:

\boxed{\text{data flow}}

not a direct:

\boxed{\text{parameter flow}}.

(Source: Build a DeepSeek Model (From Scratch))

This distinction will become extremely important when we reach distillation.

22. Why R1 needed more than pure RL

R1-Zero demonstrates that pure RL can create useful reasoning behavior.

But pure verifier-driven optimization does not directly optimize:

\text{readability}
\text{language consistency}
\text{general assistant behavior}.

Therefore DeepSeek-R1 adds supervised stages and later broader reward signals.

The source describes its later final RL stage as hybrid:

\boxed{ \text{rule-based rewards for verifiable tasks} + \text{learned rewards for preference-based tasks} }

(Source: Build a DeepSeek Model (From Scratch))

24. The most important distinction in one table

Concept Main idea
PPO Improve policy while constraining policy updates; commonly uses a learned value baseline
GRPO Remove learned value model; derive advantages from multiple completions for the same prompt
RLVR Generate reward with a deterministic verifier when correctness is objectively checkable
R1-Zero Test whether GRPO + verifiable rewards can induce reasoning behavior directly from a pretrained base model
R1 Add staged SFT, filtering, broader data, and hybrid rewards to make the model more usable
R1-Distill Transfer R1-generated reasoning behavior into smaller students

(Source: Build a DeepSeek Model (From Scratch))

25. Final mental model

The entire transformation is:

\boxed{ \text{Predict tokens} }

becomes:

\boxed{ \text{Generate candidate solutions} }

then:

\boxed{ \text{Verify outcomes} }

then:

\boxed{ \text{Compare candidates} }

then:

\boxed{ \text{Increase probability of better trajectories} }

then:

\boxed{ \text{repeat at scale} }

This is the conceptual engine behind the source's DeepSeek reasoning story.

You should now be able to answer:

\boxed{\text{What is RLVR?}}

RL where the reward is produced by a deterministic verifier instead of a learned reward model, for tasks whose correctness can be objectively checked. (Source: Build a DeepSeek Model (From Scratch))

\boxed{\text{Why is math ideal?}}

Because many mathematical answers can be checked mechanically.

\boxed{\text{Why is code ideal?}}

Generated programs can often be evaluated with tests/compiler execution.

\boxed{\text{Why can't RLVR solve all alignment?}}

Many useful properties—helpfulness, style, nuanced preferences, harmlessness—are not deterministically verifiable. (Source: Build a DeepSeek Model (From Scratch))

\boxed{\text{What is R1-Zero?}}

The source's pure-RL experiment starting from DeepSeek-V3-Base, using GRPO and verifiable reasoning rewards without prior supervised chain-of-thought training. (Source: Build a DeepSeek Model (From Scratch))

\boxed{\text{R1-Zero}\rightarrow\text{R1}: \text{parameter flow or data flow?}}
\boxed{\text{Data flow}}

R1-Zero outputs are sampled and filtered into training data for the staged R1 pipeline. (Source: Build a DeepSeek Model (From Scratch))
