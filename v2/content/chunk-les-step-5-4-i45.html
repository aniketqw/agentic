Continuation · checked fixture R01 — Group advantages and standard-deviation conventions

Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

Compare answers to the same prompt relative to their sampled siblings.

Prerequisites: Expectation and population variance

Notation and assumptions

A=(reward-mean)/(std+epsilon). Record population divisor G or sample divisor G-1. Epsilon is distinct from PPO clip epsilon.

Derivation and mechanism

  1. Compute group mean.
  2. Compute the declared spread and denominator.
  3. Center each reward and divide; equal rewards give zero reward advantages with positive epsilon.

Worked example

Toy rewards[1,1,1,0]:mean.75. Population std√3/4 gives advantages[1/√3,1/√3,1/√3,-√3]. Sample std.5 instead gives[.5,.5,.5,-1.5]. The supplied slide13 uses a different group[1,1,0,0] and sample std, hence approximately±.8659.

Limitations

  • Zero reward advantages remove that policy-gradient signal, not necessarily KL or auxiliary updates.
  • Low-variance normalization can amplify small reward differences; no-spread groups need a defined rule.

Connections to later concepts

  • R02 uses these advantages with policy ratios. R03 can still contribute a KL gradient when reward advantages vanish.

Step 5.4 — Complete GRPO Worked Example, From Prompt to Policy Loss

Plan node: I6 · chat order #45

Now we will do the entire Chapter 6 GRPO example by hand, exactly following the source's worked setup.

The purpose of this step is to make every arrow in

\boxed{ \text{Prompt} \rightarrow \text{Rollouts} \rightarrow \text{Rewards} \rightarrow \text{Advantages} \rightarrow \text{Logprobs} \rightarrow \text{Policy loss} }

completely concrete. The source presents this as the core GRPO procedure. (Source: Build a Reasoning Model (From Scratch))

1. The problem

The prompt used in the source is:

“Half the value of 3x-9 is x+37. What is the value of x? Write the final result in \boxed{}.”

Mathematically:

\frac{3x-9}{2}=x+37.

Multiply by 2:

3x-9=2x+74.

Therefore:

x=83.

So the ground-truth answer is:

\boxed{83}.

2. The model generates multiple rollouts

Instead of generating one answer, GRPO samples several answers for the same prompt.

The source uses four:

o_1=\boxed{83}
o_2=\text{“The correct answer is }\boxed{83}\text{”}
o_3=\text{“The final answer is 83”}
o_4=\text{“We get }\boxed{38}\text{”}

These are the four rollouts used in the worked example. (Source: Build a Reasoning Model (From Scratch))

Think of them as four attempts by the same policy.

                     SAME PROMPT
                          │
             ┌────────────┼────────────┐
             ↓            ↓            ↓
           Rollout 1    Rollout 2   ... Rollout 4

This is why GRPO needs a group.

3. Stage 1 — Sampling rollouts

The model samples rather than simply taking argmax.

The source uses the earlier chapter's sampling machinery, including temperature/top-p generation. The important point here is:

o_i\sim\pi_\theta(\cdot\mid q).

So all four outputs come from the current policy.

The source's practical implementation explicitly uses multiple calls to the sampling function to obtain different rollouts. (Source: Build a Reasoning Model (From Scratch))

4. Stage 2 — Calculate rewards

Now the verifier examines each rollout.

The source's reward function requires:

  1. the answer to be correct, and
  2. the answer to use the required \boxed{} format. (Source: Build a Reasoning Model (From Scratch))

So:

Rollout 1
\boxed{83}

Correct answer and correct format:

R_1=1.
Rollout 2
\text{The correct answer is }\boxed{83}

Also correct and properly formatted:

R_2=1.
Rollout 3
\text{The final answer is 83}

Correct numerical answer, but no \boxed{} format.

Under this source's reward function:

R_3=0.
Rollout 4
\boxed{38}

Wrong answer:

R_4=0.

Therefore:

\boxed{ R=[1,1,0,0] }

This is exactly the reward vector shown in the source. (Source: Build a Reasoning Model (From Scratch))

5. Important: reward is not probability

At this moment we have:

[1,1,0,0].

These numbers do not mean:

rollout 1 has 100% probability.

They mean:

rollout 1 received reward 1.

So keep these quantities separate:

\boxed{ R_i=\text{quality signal} }

versus:

\boxed{ \pi_\theta(o_i\mid q)=\text{model probability} }

This distinction is fundamental.

6. Stage 3 — Calculate the group mean

Rewards:

[1,1,0,0].

Mean:

\mu_R = \frac{1+1+0+0}{4} = \frac24 = \boxed{0.5}.

Interpretation:

\boxed{\text{average rollout reward}=0.5}

or:

\boxed{50\%}

of these sampled responses succeeded under this verifier.

7. Why do we subtract the group mean?

Calculate:

R_i-\mu_R.

For rollout 1:

1-0.5=0.5.

Rollout 2:

1-0.5=0.5.

Rollout 3:

0-0.5=-0.5.

Rollout 4:

0-0.5=-0.5.

Thus:

R-\mu_R = [0.5,0.5,-0.5,-0.5].

Now we have a relative interpretation:

+0.5 → better than group average
-0.5 → worse than group average

That is the entire meaning of relative in GRPO.

8. Calculate the standard deviation

Using the sample-standard-deviation convention used in the source's PyTorch code:

\sigma_R\approx0.577.

Then the normalized advantage is:

\boxed{ A_i= \frac{R_i-\mu_R} {\sigma_R+\epsilon} }

with a small \epsilon for numerical stability. (Source: Build a Reasoning Model (From Scratch))

9. Calculate all four advantages

For the correct first rollout:

A_1 = \frac{1-0.5}{0.577+10^{-4}} \approx \boxed{0.8659}.

Similarly:

A_2\approx\boxed{0.8659}.

For rollout 3:

A_3 = \frac{0-0.5}{0.577+10^{-4}} \approx \boxed{-0.8659}.

And:

A_4\approx\boxed{-0.8659}.

Therefore:

\boxed{ A=[0.8659,0.8659,-0.8659,-0.8659] }

which is the source's exact worked result. (Source: Build a Reasoning Model (From Scratch))

10. What the advantages now tell the optimizer

This is the most useful interpretation:

Rollout Reward Advantage Learning direction
\boxed{83} 1 +0.8659 Reinforce
Correct + boxed 1 +0.8659 Reinforce
Correct but not boxed 0 -0.8659 Suppress
\boxed{38} 0 -0.8659 Suppress

Notice something subtle.

The third answer is numerically correct, but this particular reward function gives it zero because the source has explicitly included a formatting requirement. (Source: Build a Reasoning Model (From Scratch))

So the policy is not merely learning:

\text{“answer 83.”}

It is learning:

\boxed{ \text{“answer correctly and follow the required response protocol.”} }

11. Why not simply use the rewards?

You might ask:

Why not use 1,1,0,0 directly?

You could construct a policy-gradient estimator around raw rewards, but GRPO specifically derives a relative, normalized learning signal from the group.

The source describes the purpose of the advantage as identifying which outputs performed better or worse relative to the other outputs for the same prompt. (Source: Build a Reasoning Model (From Scratch))

So:

R=[1,1,0,0]

becomes:

A=[+0.8659,+0.8659,-0.8659,-0.8659].

12. Stage 4 — Score each rollout with sequence log probability

Now we take a separate branch from the rollouts.

For each answer, we ask:

How likely does the current LLM think this generated response is?

The source calls this sequence-level log probability. (Source: Build a Reasoning Model (From Scratch))

Mathematically:

\log P_\theta(o_i\mid q) = \sum_{t=1}^{T_i} \log P_\theta(y_t^{(i)}\mid q,y_{<t}^{(i)}).

So we sum the log probability of every generated answer token.

13. The source's actual logprob results

For the four rollouts, the source obtains:

\boxed{ [-7.9243,\,-20.1546,\,-16.6130,\,-23.3677] }

respectively. (Source: Build a Reasoning Model (From Scratch))

So our complete table is now:

Rollout Reward Advantage Sequence logprob
\boxed{83} 1 +0.8659 -7.9243
Correct + boxed 1 +0.8659 -20.1546
Correct but unboxed 0 -0.8659 -16.6130
\boxed{38} 0 -0.8659 -23.3677

This table is the heart of the worked example.

14. Why are log probabilities negative?

Because:

0<P<1.

For any:

0<P<1,

we have:

\log P<0.

For example:

\log(0.5)\approx-0.693.

So a negative sequence logprob is perfectly normal.

15. Why is the shorter answer less negative?

The first response:

\boxed{83}

is very short.

Its logprob is:

-7.9243.

The second response is longer:

The correct answer is \boxed{83}

and has:

-20.1546.

The source explicitly notes that summed sequence log probabilities naturally tend to favor shorter/concise outputs because more token log probabilities are being summed. (Source: Build a Reasoning Model (From Scratch))

This is an important nuance.

A higher sequence logprob does not automatically mean “better reasoning.”

It is simply the summed likelihood of the generated sequence under the policy.

16. Why do we need logprob at all?

Reward says:

\boxed{\text{Was the answer good?}}

Advantage says:

\boxed{\text{Was it better or worse than its peers?}}

Log probability says:

\boxed{\text{How much probability does the policy assign to this sampled behavior?}}

We need both.

So the optimizer can connect:

\text{quality of behavior}

to:

\text{probability assigned to that behavior}.

17. Stage 5 — Build the policy-gradient loss

Now combine:

A_i

with:

\log P_\theta(o_i\mid q).

The simplified source objective is:

\boxed{ L_{\text{PG}} = -\frac1N \sum_{i=1}^{N} A_i \log P_\theta(o_i\mid q) }

The implementation is:

logps = torch.stack(rollout_logps)
pg_loss = -(advantages.detach() * logps).mean()

(Source: Build a Reasoning Model (From Scratch))

18. Substitute the actual numbers

We have:

A= [0.8659,0.8659,-0.8659,-0.8659]

and:

\log P= [-7.9243,-20.1546,-16.6130,-23.3677].

Therefore:

L_{\text{PG}} = -\frac14 [ (0.8659)(-7.9243) + (0.8659)(-20.1546)
+ (-0.8659)(-16.6130) + (-0.8659)(-23.3677) ].

19. Calculate term by term

Rollout 1
(0.8659)(-7.9243) \approx -6.858.
Rollout 2
(0.8659)(-20.1546) \approx -17.454.
Rollout 3
(-0.8659)(-16.6130) \approx 14.383.
Rollout 4
(-0.8659)(-23.3677) \approx 20.229.

So:

-6.858-17.454+14.383+20.229 \approx10.300.

Then:

-\frac{10.300}{4} \approx-2.575.

With the exact source values and floating-point calculations:

\boxed{ L_{\text{PG}}=-2.5764 }

which is the result reported in the source. (Source: Build a Reasoning Model (From Scratch))

20. Now understand the sign

This is much more important than the arithmetic.

For a good rollout:

A_i>0.

The optimizer tries to increase:

\log P_\theta(o_i\mid q).

Since larger log probability means larger probability:

\boxed{ \text{good rollout} \rightarrow \text{make it more probable} }

For a bad rollout:

A_i<0.

The optimization pressure goes in the opposite direction:

\boxed{ \text{bad rollout} \rightarrow \text{make it less probable} }

This is policy learning.

21. A microscopic two-rollout intuition

Forget the whole batch.

Suppose:

A=+1

for a successful response, and its probability is:

P=0.1.

Then:

\log P=\log(0.1)\approx-2.303.

Its contribution to:

-A\log P

is:

-1(-2.303) = 2.303.

Optimization tries to reduce the loss, which pushes the model toward increasing the probability of this successful response.

For a bad response:

A=-1,

the direction reverses.

22. Stage 6 — Backpropagation

Now:

L_{\text{PG}}

is differentiable with respect to the model parameters because the sequence log probabilities came from the model.

Therefore:

\boxed{ \nabla_\theta L_{\text{PG}} }

can be calculated.

The source explains that PyTorch's computation graph retains the path from the model parameters through the sequence log probabilities, allowing backpropagation. (Source: Build a Reasoning Model (From Scratch))

23. Stage 7 — Update the model

Once we have:

\nabla_\theta L,

an optimizer such as AdamW updates the model:

\boxed{ \theta \leftarrow \theta-\eta\nabla_\theta L }

where:

  • \theta = policy parameters,
  • \eta = learning rate.

The next time the same type of problem appears, the policy has slightly different token probabilities.

Here is the complete chain:

Response \boxed{83} correct + boxed correct, unboxed \boxed{38}
Reward 1 1 0 0

Deviation +0.5 +0.5 −0.5 −0.5
Advantage +0.8659 +0.8659 −0.8659 −0.8659

Then:

\boxed{ L_{\text{PG}}=-2.5764 }

(Source: Build a Reasoning Model (From Scratch))

25. Why this works even though the verifier is not differentiable

This is one of the most beautiful parts of the method.

The verifier produces:

R_i.

We don't backpropagate through:

R_i.

Instead:

R_i \rightarrow A_i

and then treat:

A_i

as a fixed learning signal.

The differentiable path is through:

\log P_\theta(o_i\mid q).

So:

Verifier
   ↓
Reward
   ↓
Advantage ──────────────┐
                        ×
Model ──→ logprob ──────┘
             ↓
            loss
             ↓
        backpropagation

This is why advantages.detach() appears in the implementation. (Source: Build a Reasoning Model (From Scratch))

26. The zero-signal case

Now consider:

R=[0,0,0,0].

Mean:

\mu=0.

Therefore:

R_i-\mu=0.

Thus:

\boxed{ A=[0,0,0,0] }

and therefore:

L_{\text{PG}}=0.

Similarly, if:

R=[1,1,1,1],

then:

A=[0,0,0,0].

The source explicitly highlights this as an intentional property: when all rollouts are equally good or equally bad, there is no relative signal telling GRPO which behavior to reinforce or suppress. (Source: Build a Reasoning Model (From Scratch))

27. This gives GRPO its most important behavior

Suppose four answers all fail:

[0,0,0,0].

GRPO does not say:

“Pick one wrong answer and reinforce it.”

Instead:

\boxed{\text{No relative preference} \Rightarrow \text{zero group signal}}

This is one of the reasons the group formulation is meaningful.

\boxed{\text{reinforce this behavior}}

33. One important source-specific subtlety

The source's Chapter 6 implementation is deliberately simplified.

At this stage it uses:

\boxed{ L_{\text{PG}} = -\operatorname{mean}(A\cdot\log P) }

and postpones the more complete policy-ratio clipping and KL machinery to Chapter 7. (Source: Build a Reasoning Model (From Scratch))

So what we have just derived is:

\boxed{\text{simplified GRPO foundation}}

not yet the final stabilized GRPO formulation.

34. The full conceptual chain

You should now be able to explain this without looking at notes:

\boxed{ q \rightarrow \{o_1,o_2,\ldots,o_G\} }

Generate multiple responses for one prompt.

Then:

\boxed{ \{o_i\} \rightarrow \{R_i\} }

The verifier evaluates them.

Then:

\boxed{ \{R_i\} \rightarrow \{A_i\} }

Normalize the rewards relative to the group.

Then:

\boxed{ o_i \rightarrow \log P_\theta(o_i\mid q) }

Measure how much probability the policy gives the sampled response.

Then:

\boxed{ A_i\times \log P_\theta(o_i\mid q) }

Connect behavioral quality to policy probability.

Finally:

\boxed{ L_{\text{PG}} = -\frac1G \sum_i A_i\log P_\theta(o_i\mid q) }

and:

\boxed{ L \rightarrow \nabla_\theta L \rightarrow \theta' }

Update the model.

35. The one sentence that captures the entire mechanism

GRPO samples several answers to the same problem, rewards them, determines which answers were better or worse than their peers, and changes the policy to make the better behaviors more probable and the worse behaviors less probable.

That is exactly the bridge from:

\boxed{\text{verifiable reward}}

to:

\boxed{\text{model learning}}.

The source's worked example implements these steps in sequence and then combines them in compute_grpo_loss.
