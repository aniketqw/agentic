R100.5 — DeepSeekAttention: MLA + Decoupled RoPE + KV Cache

Plan node: A6 · chat order #107

↩ Back to main text: Step 1.13 — Stacking Transformer Blocks → Final Norm → Unembedding → Log

We now reach the most important integration point in the Mini-DeepSeek implementation.

Previously we learned each idea separately:

\text{MLA} \qquad \text{RoPE} \qquad \text{KV Cache}

Now the source puts them together inside one DeepSeekAttention module.

The source describes this module as two parallel paths:

\boxed{\text{Content Path}}

for semantic/content information, and

\boxed{\text{Position Path}}

for positional information. Their attention scores are added before the normal softmax/context calculation. (Source: Build a DeepSeek Model (From Scratch))

1. First see the whole thing

Before touching code, keep this picture in mind:

                         x
                         │
          ┌──────────────┴──────────────┐
          │                             │
          ▼                             ▼
   CONTENT PATH                  POSITION PATH
       MLA                            RoPE
          │                             │
          │                        q_r, k_r
          │                             │
     q_c, c_kv                           │
          │                              │
      k_c, v_c                           │
          │                              │
          └──────────────┬───────────────┘
                         ▼
                attention scores
                         │
                         ▼
              content + position
                         │
                         ▼
                  causal mask
                         │
                         ▼
                      softmax
                         │
                         ▼
                     weights
                         │
                         ▼
                       v_c
                         │
                         ▼

                         │
                         ▼
                       W_o
                         │

The critical architectural idea is:

\boxed{ \text{content and position are represented separately} }

and then fused at the attention-score level. (Source: Build a DeepSeek Model (From Scratch))

2. Why do we need this split?

This comes from the tension we previously studied.

MLA wants a highly compressed representation for the KV cache.

RoPE, however, is inherently position-dependent.

The source describes the architecture as resolving this tension by keeping:

  • content information in a compressed latent cache,
  • positional information in a separate RoPE path.

It explicitly says this allows the cache-friendly MLA design to coexist with position-dependent RoPE. (Source: Build a DeepSeek Model (From Scratch))

So the conceptual solution is:

\boxed{ \text{compress content} }

while:

\boxed{ \text{keep positional information separate}. }

3. Start with the dimensions

Let the model input be:

x\in\mathbb R^{B\times S\times D}

where:

  • B = batch size
  • S = sequence length
  • D=d_{\text{model}}

For the source's default ModelArgs:

D=512
H=8
d_{\text{latent}}=128
d_{\text{rope}}=32.

Therefore:

d_{\text{head}} = \frac{512}{8} = 64.

So:

\boxed{x:[B,S,512]}.

4. The constructor

The source's DeepSeekAttention creates four content-path projections:

self.W_q_content
self.W_dkv_content
self.W_uk_content
self.W_uv_content

and two position-path projections:

self.W_k_pos
self.W_q_pos

plus the RoPE module and final output projection. (Source: Build a DeepSeek Model (From Scratch))

The architecture is therefore:

\boxed{ x \rightarrow \begin{cases} q_c,\ c_{kv}\\ q_r,\ k_r \end{cases} }

This is the first major departure from ordinary MHA.

5. Content Path — Step 1: Query

The source does:

q_c = self.W_q_content(x).view(
    B, S, self.num_heads, self.d_head
).transpose(1, 2)

(Source: Build a DeepSeek Model (From Scratch))

First:

W_{q,\text{content}}: D\rightarrow D.

So:

[B,S,D] \rightarrow [B,S,D].

Then reshape:

[B,S,D] \rightarrow [B,S,H,d_{\text{head}}].

Because:

D=H\cdot d_{\text{head}}.

Finally:

.transpose(1, 2)

changes:

[B,S,H,d_{\text{head}}]

into:

\boxed{ [B,H,S,d_{\text{head}}]. }

So:

\boxed{ q_c:[B,H,S,d_{\text{head}}]. }

For the default configuration:

\boxed{ q_c:[B,8,S,64]. }

6. Content Path — Step 2: Compress Key/Value information

Now the crucial MLA operation:

c_kv_new = self.W_dkv_content(x)

(Source: Build a DeepSeek Model (From Scratch))

The projection is:

W_{dkv}: d_{\text{model}} \rightarrow d_{\text{latent}}.

Therefore:

[B,S,512] \rightarrow [B,S,128].

So:

\boxed{ c_{kv,\text{new}}:[B,S,d_{\text{latent}}]. }

This is the compressed latent representation.

And this is what gives MLA its cache advantage.

7. Why is this so important?

Compare ordinary MHA.

A conventional cache stores full K and V representations:

[B,H,S,d_{\text{head}}].

Since:

H d_{\text{head}}=D,

that's effectively:

[B,S,D]

for each of K and V.

MLA instead keeps:

\boxed{ c_{kv}:[B,S,d_{\text{latent}}]. }

With the source configuration:

512\rightarrow128.

So the stored latent content representation is one quarter of the model dimension.

That is the central memory-saving mechanism represented in this implementation. The source emphasizes that only the compressed latent tensor is needed for the content portion of the cache. (Source: Build a DeepSeek Model (From Scratch))

8. Cached inference changes the latent tensor

The source then does:

c_kv = torch.cat(
    [past_kv[0], c_kv_new],
    dim=1
) if past_kv else c_kv_new

(Source: Build a DeepSeek Model (From Scratch))

Suppose:

past\_len=P

and the current input contains:

S

new tokens.

Then:

past_kv[0]

contains:

[B,P,d_{\text{latent}}]

and:

c_{kv,\text{new}}

contains:

[B,S,d_{\text{latent}}].

Concatenating along the sequence dimension gives:

\boxed{ c_{kv}:[B,P+S,d_{\text{latent}}]. }

So the cache grows with the sequence.

9. Then decompress the latent representation

The source uses:

k_c = self.W_uk_content(c_kv)
v_c = self.W_uv_content(c_kv)

and reshapes them into attention heads. (Source: Build a DeepSeek Model (From Scratch))

Thus:

c_{kv} \rightarrow k_c

and:

c_{kv} \rightarrow v_c.

Dimensionally:

[B,P+S,128] \rightarrow [B,P+S,512]

then:

\boxed{ [B,H,P+S,64]. }

So every head can reconstruct its own content Key and Value from the shared latent representation.

This is the reason the source emphasizes that MLA can retain head diversity even though the cache itself is compressed. (Source: Build a DeepSeek Model (From Scratch))

10. This is a very important distinction

The cache stores:

\boxed{c_{kv}}

not:

\boxed{k_c,v_c}.

But during attention computation, the implementation reconstructs:

k_c,v_c

from that latent state.

Therefore:

cache:
    compact

computation:
    reconstruct full head-specific K/V

That is MLA's fundamental pattern in this implementation.

11. Position Path — Key and Query

Now we move to the second branch.

The source does:

k_r_unrotated = self.W_k_pos(x).view(
    B, S, self.num_heads, self.d_rope
).transpose(1, 2)

q_r_unrotated = self.W_q_pos(x).view(
    B, S, self.num_heads, self.d_rope
).transpose(1, 2)

(Source: Build a DeepSeek Model (From Scratch))

Unlike the content query, these projections have output dimension:

H\cdot d_{\text{rope}}.

Thus:

[B,S,D] \rightarrow [B,S,H,d_{\text{rope}}] \rightarrow \boxed{[B,H,S,d_{\text{rope}}]}.

For the default configuration:

\boxed{ q_r,k_r:[B,8,S,32]. }

12. Apply RoPE

We already finished the RoPE implementation.

Now:

k_r_new = self.rope(
    k_r_unrotated,
    position_offset=position_offset
)

and:

q_r = self.rope(
    q_r_unrotated,
    position_offset=position_offset
)

(Source: Build a DeepSeek Model (From Scratch))

Therefore:

\boxed{ q_r^{\text{unrotated}} \rightarrow q_r }

and:

\boxed{ k_r^{\text{unrotated}} \rightarrow k_r. }

The positional information exists only in this path.

13. Why is the Key cached?

The new positional Key is:

k_{r,\text{new}}.

The source appends it to the previous positional Key cache:

k_r = torch.cat(
    [past_kv[1], k_r_new],
    dim=2
) if past_kv else k_r_new

(Source: Build a DeepSeek Model (From Scratch))

Notice:

dim=2

because k_r has shape:

[B,H,S,d_{\text{rope}}].

Dimension 2 is the sequence dimension.

So:

[B,H,P,d_{\text{rope}}]

plus:

[B,H,S,d_{\text{rope}}]

becomes:

\boxed{ [B,H,P+S,d_{\text{rope}}]. }

14. Therefore the cache has two components

This is one of the most important things to memorize.

The source returns:

new_cache = (c_kv, k_r)

(Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{KV Cache} = (c_{kv},k_r). }

where:

c_{kv} = \text{compressed content state}

and:

k_r = \text{position-aware Key state}.

This is not the ordinary:

(K,V)

cache of standard MHA.

That distinction matters enormously.

15. Now calculate content attention scores

The source computes:

content_scores = (
    q_c @ k_c.transpose(-2, -1)
) / math.sqrt(self.d_head)

(Source: Build a DeepSeek Model (From Scratch))

We know:

q_c\in \mathbb R^{B\times H\times S\times d_{\text{head}}}

and:

k_c\in \mathbb R^{B\times H\times(P+S)\times d_{\text{head}}}.

Transpose the final two dimensions of k_c:

k_c^T: [B,H,d_{\text{head}},P+S].

Then matrix multiplication:

[S,d_{\text{head}}] \times [d_{\text{head}},P+S]

gives:

[S,P+S].

Therefore:

\boxed{ content\_scores \in \mathbb R^{B\times H\times S\times(P+S)}. }

16. Why divide by \sqrt{d_{\text{head}}}?

This is standard scaled dot-product attention, which we learned earlier.

The source uses:

\boxed{ \frac{q_ck_c^T}{\sqrt{d_{\text{head}}}} }

so that the score magnitude remains controlled as the dimensionality increases.

Nothing new mathematically is being introduced here.

17. Now positional attention scores

The source does:

position_scores = (
    q_r @ k_r.transpose(-2, -1)
) / math.sqrt(self.d_rope)

(Source: Build a DeepSeek Model (From Scratch))

Here:

q_r: [B,H,S,d_{\text{rope}}]

and:

k_r: [B,H,P+S,d_{\text{rope}}].

So:

\boxed{ position\_scores: [B,H,S,P+S]. }

Notice the denominator is:

\sqrt{d_{\text{rope}}}

rather than:

\sqrt{d_{\text{head}}}.

That matches the dimensionality of this separate positional pathway in the source. (Source: Build a DeepSeek Model (From Scratch))

18. The central fusion step

Now the two paths finally meet.

The source says:

attn_scores = content_scores + position_scores

(Source: Build a DeepSeek Model (From Scratch))

Mathematically:

\boxed{ A = \frac{q_ck_c^T}{\sqrt{d_{\text{head}}}} + \frac{q_rk_r^T}{\sqrt{d_{\text{rope}}}} }

This is the core equation of the decoupled implementation.

Think of it as:

\boxed{ \text{semantic compatibility} + \text{positional compatibility} }

producing the final attention score.

19. Why add scores instead of vectors?

This is a subtle architectural choice.

The content path answers:

How relevant is this previous token based on its learned content representation?

The position path answers:

How relevant is it based on positional information?

The architecture combines these before softmax:

\boxed{ \text{scores} \rightarrow \text{addition} \rightarrow \text{softmax}. }

So positional information changes the attention distribution itself.

20. Then causal masking

After combining the paths, the source applies the causal mask. The earlier implementation shows:

attn_scores = attn_scores.masked_fill(
    self.mask[:, :, :seq_len, :seq_len],
    float('-inf')
)

followed by softmax. (Source: Build a DeepSeek Model (From Scratch))

Conceptually:

Future positions
      ↓
score = -∞
      ↓
softmax
      ↓
probability ≈ 0

Therefore the model cannot use future tokens.

This is the same causal mechanism we established during the batch-construction step.

21. Softmax

Now:

\boxed{ A\rightarrow\operatorname{softmax}(A). }

The result is:

\boxed{ attn\_weights \in \mathbb R^{B\times H\times S\times(P+S)}. }

Each query position gets a probability distribution over the available keys.

22. The important question: which Value gets used?

The answer is:

\boxed{v_c}.

Not a positional Value.

The source describes the positional branch as providing positional information in the attention scores, while the resulting attention weights are applied to the content-only Value. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{Position path modifies where we attend} }

while:

\boxed{ \text{Content path supplies what information is retrieved}. }

That is a very useful mental model.

23. Context vector

The source calculates conceptually:

context_vector = attn_weights @ v_c

(Source: Build a DeepSeek Model (From Scratch))

Dimensions:

[B,H,S,P+S]

times:

[B,H,P+S,d_{\text{head}}].

Therefore:

\boxed{ [B,H,S,d_{\text{head}}]. }

Then it transposes and reshapes back to model dimension:

[B,H,S,d_{\text{head}}] \rightarrow [B,S,H,d_{\text{head}}] \rightarrow \boxed{ [B,S,D]. }

24. Final output projection

Finally:

output = self.W_o(context_vector)

The source defines:

W_o: d_{\text{model}}\rightarrow d_{\text{model}}.

So:

[B,S,D] \rightarrow \boxed{[B,S,D]}.

That is the output of the attention sublayer.

26. Now see what changes during generation

Suppose 256 tokens have already been cached.

Now the model receives:

S=1

new token.

Then:

P=256.

The new query has:

q_c: [B,H,1,64].

But the cached content latent becomes:

c_{kv}: [B,257,128].

The reconstructed keys/values become:

k_c,v_c: [B,8,257,64].

Likewise the positional cache becomes:

k_r: [B,8,257,32].

So the new query compares itself against all 257 available positions:

[1]\times[257]

giving:

\boxed{ attention\ scores:[B,8,1,257]. }

The crucial efficiency point is that we do not recompute the entire 257-token history from scratch.

The history is already represented in the cache.

27. And this connects to position_offset

For that same example:

P=256.

The model determines:

\boxed{ position\_offset=256. }

That value reaches RoPE.

So the new token is treated as:

\boxed{\text{absolute position }256}

rather than:

\boxed{\text{position }0}.

At the same time, the cached Keys remain available for attention.

Therefore:

\boxed{ KV\ Cache + position\_offset }

solve two different problems:

  • cache → reuse prior attention information
  • offset → assign correct absolute positional encoding to newly processed tokens.

28. Why the cache tuple is unusual

In ordinary MHA we often think:

\text{cache}=(K,V).

Here the source has:

\boxed{ \text{cache}=(c_{kv},k_r). }

Why?

Because the value-related content information is encoded inside the compressed latent representation:

c_{kv}.

The positional component requires:

k_r.

So the cache stores the minimal representations needed by this decoupled design.

The source explicitly highlights these two cached tensors in its architecture discussion. (Source: Build a DeepSeek Model (From Scratch))

29. One subtle source distinction

The source's explanatory text refers to maintaining the cache-friendly "absorption trick" for the content path. (Source: Build a DeepSeek Model (From Scratch))

However, the Chapter 6 code listing we are studying explicitly reconstructs k_c and v_c from c_kv before calculating the score/context.

So for this teaching sequence, keep the distinction:

\boxed{ \text{architectural idea: compressed cache / absorption-friendly MLA} }

versus:

\boxed{ \text{this simplified implementation: materialize }k_c,v_c\text{ for the calculation}. }

That prevents us from conflating the conceptual optimization with every low-level optimization used by a production implementation.

30. What has actually been integrated now?

We started with three independent ideas.

MLA
x\rightarrow c_{kv}\rightarrow k_c,v_c
RoPE
q_r,k_r\rightarrow\operatorname{RoPE}
KV Cache
past\rightarrow\text{append new states}.

Now the complete structure is:

\boxed{ \begin{aligned} x &\rightarrow q_c,\ c_{kv}\\ x &\rightarrow q_r,\ k_r\\ c_{kv} &\rightarrow k_c,v_c\\ q_r,k_r &\rightarrow \text{RoPE}\\ q_ck_c^T &\rightarrow \text{content score}\\ q_rk_r^T &\rightarrow \text{position score}\\ \text{two scores} &\rightarrow \text{addition}\\ &\rightarrow \text{causal mask}\\ &\rightarrow \text{softmax}\\ &\rightarrow v_c\\ &\rightarrow W_o\\ &\rightarrow output. \end{aligned} }

That is DeepSeekAttention in this Mini-DeepSeek implementation. (Source: Build a DeepSeek Model (From Scratch))

31. The single most important conceptual takeaway

When you see:

\boxed{ \text{MLA + Decoupled RoPE} }

don't imagine one enormous attention formula.

Imagine two questions being answered separately:

\boxed{ \text{Content: "What is relevant?"} }

and:

\boxed{ \text{Position: "Where is it relevant?"} }

Then:

\boxed{ \text{combine their scores} }

and use those combined scores to retrieve content through v_c.

That is the core intuition behind this implementation.
