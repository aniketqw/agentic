Step 5.3 — Why GRPO Instead of PPO?

Plan node: I6 · chat order #44

We now reach the key algorithmic question:

\boxed{\text{Why did DeepSeekMath introduce GRPO when PPO already existed?}}

The source gives the central answer:

GRPO removes the separate value model and gets its baseline from multiple sampled responses to the same prompt.

This is the single most important idea in this step.

1. First understand what PPO is trying to solve

From Step 5.2, we saw:

\nabla_\theta J(\theta) = \mathbb E \left[ R\nabla_\theta \log\pi_\theta \right].

But using the raw reward R can have high variance.

Imagine two prompts:

Prompt A
2 + 2 = ?

Reward:

R=1
Prompt B
Prove a difficult theorem.

Reward:

R=1

Both got the same raw reward, but these tasks are not equally informative.

A more useful question is:

\boxed{\text{Was this outcome better or worse than what was expected?}}

That quantity is represented by an advantage.

2. What is advantage?

The general intuition is:

\boxed{ A = \text{actual outcome} - \text{expected outcome} }

In a value-function formulation:

A_t = R_t - V_\phi(s_t)

in the simplified form used in the source material.

Here:

  • R_t = observed return/reward
  • V_\phi(s_t) = value model's estimate of expected outcome
  • \phi = value-model parameters

The source explicitly describes the value model as predicting how good the current partial response is expected to be. (Source: Build a DeepSeek Model (From Scratch))

3. Why does PPO need a value model?

The PPO-style setup therefore has two learned components:

                PPO
                 │
       ┌─────────┴─────────┐
       ↓                   ↓
    Policy              Value model
    πθ                    Vϕ
       │                   │
 generates tokens      predicts expected
                         reward

The policy answers:

What token should I generate?

The value model answers:

Given where I am, how good should the eventual outcome be?

Then advantage is based on the comparison.

The source emphasizes that this additional value model is expensive because it adds memory, forward passes, training loss, and engineering complexity. (Source: Build a DeepSeek Model (From Scratch))

4. Why this becomes painful for LLMs

Suppose your policy is a huge LLM.

Now you need another large network:

V_\phi.

Conceptually:

\boxed{ \text{policy} + \text{value model} }

instead of only:

\boxed{ \text{policy} }

So you pay for:

  • extra model memory,
  • extra computation,
  • value-model training,
  • extra optimizer state,
  • additional engineering.

This is exactly the motivation highlighted by the DeepSeekMath and GRPO slides.

5. GRPO asks a different question

Instead of asking:

“Can a separate neural network estimate the expected reward?”

GRPO asks:

“Why not simply generate several answers to the same problem and compare them?”

Suppose the prompt is:

q

and the model generates four responses:

o_1,o_2,o_3,o_4.

Suppose their rewards are:

[1,0,1,0].

Then:

\mu = \frac{1+0+1+0}{4} = 0.5.

Now:

R_i-\mu = [0.5,-0.5,0.5,-0.5].

Immediately we know:

o1 → above group average
o2 → below group average
o3 → above group average
o4 → below group average

No learned value function was required.

That is the group relative idea. (Source: deepseekmath-slides)

6. Why is the group average a useful baseline?

This is the clever part.

Suppose the model is answering a very easy question.

Maybe nearly every rollout gets:

R=1.

Then the model is already good.

Suppose the model is answering a difficult question.

Maybe only one out of four attempts succeeds.

Then a successful rollout is especially valuable relative to its peers.

So the baseline becomes:

\boxed{ \text{What did the model typically achieve on this exact prompt?} }

That is much more prompt-specific than a generic global reward expectation.

The DeepSeekMath slides explicitly frame the group average as replacing the value model's job of estimating the typical reward for the current situation. (Source: deepseekmath-slides)

7. PPO versus GRPO visually

PPO

  ↓

  ↓

  │
  └──────→ Value model estimates baseline
                    ↓

Thus:

\boxed{ \text{PPO baseline}=\text{learned value model} }

while:

\boxed{ \text{GRPO baseline}=\text{empirical group statistics} }

8. Why GRPO requires multiple rollouts

Now notice an important consequence.

If:

G=1

then there is only one response.

Its reward is:

R_1.

The group mean is also:

\mu=R_1.

Therefore:

R_1-\mu=0.

So there is no meaningful relative comparison.

Hence GRPO needs:

\boxed{G>1}

for meaningful group-relative learning.

The source explicitly notes that GRPO requires multiple completions per prompt so that the group baseline is meaningful. (Source: Build a DeepSeek Model (From Scratch))

9. Group-relative advantage formula

For a prompt q, suppose we sample:

G

completions.

Rewards:

r_1,r_2,\ldots,r_G.

Mean:

\mu = \frac1G\sum_{j=1}^{G}r_j.

Standard deviation:

\sigma = \operatorname{std}(r_1,\ldots,r_G).

Then the simplified group-relative advantage is:

\boxed{ A_i = \frac{r_i-\mu}{\sigma+\epsilon} }

where \epsilon prevents division by zero. (Source: Build a DeepSeek Model (From Scratch))

10. Numerical example — full GRPO advantage calculation

Suppose:

G=4

and:

r=[1,0,1,0].

Step 1: mean

\mu=0.5.

Step 2: deviations

[0.5,-0.5,0.5,-0.5].

Step 3: standard deviation

Using the sample standard deviation convention used by the source's PyTorch example:

\sigma\approx0.577.

Step 4: normalize

A= \left[ \frac{0.5}{0.577}, \frac{-0.5}{0.577}, \frac{0.5}{0.577}, \frac{-0.5}{0.577} \right]

giving:

\boxed{ A\approx[0.866,-0.866,0.866,-0.866] }

This is the same type of worked group-relative signal shown in the source. (Source: Build a DeepSeek Model (From Scratch))

11. Now connect advantage to policy learning

Suppose the generated responses have sequence log probabilities:

\log p= [-7,-8,-15,-16].

Advantages:

A= [0.866,-0.866,0.866,-0.866].

The simplified policy-gradient objective is:

L_{\text{PG}} = -\frac14 \sum_{i=1}^{4} A_i\log p_i.

So:

L_{\text{PG}} = -\frac14[ (0.866)(-7) + (-0.866)(-8) + (0.866)(-15) + (-0.866)(-16) ].

The important thing is not memorizing the final number.

The important thing is understanding:

\boxed{ A_i \text{ determines the direction and strength of the update} }

while:

\boxed{ \log p_i \text{ tells us how the current policy assigns probability to the sampled response} }

12. But PPO and GRPO still share important machinery

This is a subtle point.

GRPO does not throw away all PPO ideas.

The source explicitly says that moving from PPO to GRPO keeps:

  • old-policy log probabilities,
  • policy ratios,
  • clipped objective,
  • reference-policy KL.

The main structural change is the source of the advantage. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{GRPO is not “PPO with everything removed”} }

It is better to think:

\boxed{ \text{GRPO} = \text{policy optimization} + \text{group-derived advantages} - \text{value model} }

with other stabilization machinery retained in the broader formulation.

13. What is the “old policy”?

Suppose the current model has parameters:

\theta.

It generates some rollout.

After generation, we don't want to keep changing the reference probability used to interpret that sample.

So we keep an older version:

\pi_{\theta_{\text{old}}}.

Then compare:

\pi_\theta

against:

\pi_{\theta_{\text{old}}}.

This gives the probability ratio:

\boxed{ r_i(\theta) = \frac{ \pi_\theta(y_i\mid x) }{ \pi_{\theta_{\text{old}}}(y_i\mid x) } }

The source later computes this using log probabilities.

14. Why use the ratio?

Suppose:

\pi_{\text{old}}(y)=0.1

and:

\pi_{\text{new}}(y)=0.2.

Then:

r = \frac{0.2}{0.1} = \boxed{2}.

So the new model considers that response:

\boxed{2\times}

as likely as the old model.

If:

\pi_{\text{old}}=0.2, \qquad \pi_{\text{new}}=0.1,

then:

r=0.5.

The probability was cut in half.

15. Why use log probabilities in implementation?

Because:

\frac{\pi_{\text{new}}}{\pi_{\text{old}}} = \exp( \log\pi_{\text{new}} - \log\pi_{\text{old}} ).

Therefore:

\boxed{ r_i = \exp( \log p_i^{\text{new}} - \log p_i^{\text{old}} ) }

This is numerically convenient.

The source uses exactly this construction:

log_ratio = new_logps - old_logps
ratio = torch.exp(log_ratio)

(Source: Build a Reasoning Model (From Scratch))

16. Numerical ratio example

Suppose:

\log p_{\text{new}}=-2

and:

\log p_{\text{old}}=-3.

Then:

\log r = -2-(-3) = 1.

Therefore:

r=e^1 \approx \boxed{2.718}.

So the new model assigns about:

\boxed{2.72\times}

the previous probability to that sampled outcome.

17. Why do we need clipping?

Suppose:

A=1.

And the ratio suddenly becomes:

r=20.

Without any limitation:

rA=20.

That gives a huge influence to this rollout.

A single aggressive update could push the policy far from the policy that produced the samples.

That can destabilize training.

The source explicitly motivates clipping as a mechanism for limiting overly large model updates and avoiding instability. (Source: Build a Reasoning Model (From Scratch))

18. Clipping formula

Define a clipping range:

[1-\epsilon,1+\epsilon].

Then:

\boxed{ \operatorname{clip}(r,1-\epsilon,1+\epsilon) }

limits the ratio.

For example, if:

\epsilon=0.2,

then:

r\in[0.8,1.2].

A ratio of:

1.5

becomes:

1.2.

A ratio of:

0.6

becomes:

0.8.

19. The source's striking example

The source uses:

\epsilon=10.

Therefore:

1-\epsilon=-9, \qquad 1+\epsilon=11.

Since probability ratios are nonnegative, the practical lower bound is effectively not restrictive here.

The source's example has:

r=[20.0855,1.2214,0.1353,1.0].

After clipping:

\boxed{ [11.0,1.2214,0.1353,1.0] }

(Source: Build a Reasoning Model (From Scratch))

20. Why is this related to PPO?

Because clipping is the characteristic PPO idea brought into this GRPO implementation.

The source explicitly cites the PPO paper as the source of clipped policy ratios used here. (Source: Build a Reasoning Model (From Scratch))

So the lineage is:

\boxed{ \text{PPO} \rightarrow \text{clipped policy ratio} \rightarrow \text{GRPO uses it} }

while:

\boxed{ \text{PPO} \rightarrow \text{value model} }

is the component GRPO removes.

21. GRPO's core simplification

Now write this side-by-side:

Component PPO GRPO
Policy Yes Yes
Old policy Yes Yes
Clipped ratio Yes Yes
Reference policy / KL Yes in typical LLM setups Yes in the broader GRPO formulation
Value model Yes No
Advantage source Value estimate Group-relative rewards
Multiple responses per prompt Not fundamentally required Required for group baseline

The source directly emphasizes that the main code change is the source of the advantage. (Source: Build a DeepSeek Model (From Scratch))

22. Why this saves resources

Suppose:

\text{policy}=7\text{B parameters}.

A PPO-style setup may require another large value network of comparable scale.

GRPO removes that requirement.

Instead of:

7B + 7B,

you conceptually keep:

\boxed{7B}

for the main policy plus whatever reference-policy arrangement is used.

The exact memory footprint in a real implementation depends on parameter sharing, precision, optimizer state, reference handling, etc. The source's claim is architectural: GRPO eliminates the separately trained value model.

23. But there is a tradeoff

GRPO does not make computation free.

Instead of spending compute on a value model, we spend compute generating:

G

different responses.

So:

\boxed{ \text{less model-side overhead} \leftrightarrow \text{more rollout generation} }

The DeepSeekMath material frames the tradeoff as worthwhile because sampling a few extra responses can be cheaper than training and running another full-size value model. (Source: deepseekmath-slides)

24. One very important conceptual comparison

PPO asks:
\boxed{ \text{“What reward should I expect from this state?”} }

and learns a function:

V_\phi(s).
GRPO asks:
\boxed{ \text{“Among the responses I actually generated for this prompt, which ones did better?”} }

and computes a baseline from:

\mu_{\text{group}}.

That is why it is called:

\boxed{\text{Group Relative Policy Optimization}}

The phrase group relative is not decorative terminology.

It literally refers to the group of sampled responses.

25. Level 1 numerical

Four rollouts produce:

[1,0,1,0].

Mean reward:

\boxed{0.5}

Above-average rollouts:

\boxed{2}

Below-average rollouts:

\boxed{2}.

26. Level 2 numerical

Suppose:

r=[1,0,1,0]

and:

\sigma=0.577.

Compute the advantage for the third rollout.

Since:

r_3=1,
A_3 = \frac{1-0.5}{0.577} \approx \boxed{0.866}.

27. Level 3 numerical

Suppose:

\log p_{\text{new}}=-4

and:

\log p_{\text{old}}=-5.

Then:

r = e^{-4-(-5)} = e^1 = \boxed{2.718}.

With:

\epsilon=0.2,

the clipped ratio is:

\boxed{1.2}.

28. Level 4 numerical — batch shapes

Suppose:

B=16

prompts and:

G=8

rollouts per prompt.

Then:

R\in\mathbb R^{16\times8}.

Advantages:

A\in\mathbb R^{16\times8}.

Suppose each response has:

T=512

generated tokens.

Token-level log probabilities:

\boxed{ \log p\in\mathbb R^{16\times8\times512} }

Sequence log probabilities after summing over tokens:

\boxed{ [16,8] }

Then the final mean produces:

\boxed{\text{scalar loss}}.

29. Level 5 exam-style numerical

You have:

G=4

responses with rewards:

[1,0,0,1].

Their sequence log probabilities under the current policy are:

[-4,-5,-6,-7].

Using:

\mu=0.5, \qquad \sigma\approx0.577,

the advantages are:

[0.866,-0.866,-0.866,0.866].

Compute:

L_{\text{PG}} = -\frac14 \sum_i A_i\log p_i.

Products:

0.866(-4)=-3.464
-0.866(-5)=4.330
-0.866(-6)=5.196
0.866(-7)=-6.062.

Sum:

-3.464+4.330+5.196-6.062 \approx0.

Therefore:

\boxed{L_{\text{PG}}\approx0}

This is a useful exam lesson:

A nonzero advantage vector does not guarantee a nonzero aggregate loss; the weighted terms can cancel.

31. What you must be able to explain in an exam/interview

Why PPO?

Because policy gradients benefit from an advantage estimate, and PPO uses a learned value model to help construct that learning signal while using clipped policy updates for stability.

Why GRPO?

Because for reasoning tasks, we can sample several answers to the same prompt and use their relative performance as the baseline, eliminating the separate value model.

What does “group” mean?

The multiple completions generated for the same prompt.

What does “relative” mean?

A response is evaluated relative to the group's mean reward.

What does “policy optimization” mean?

Changing the LLM parameters so that desirable sampled responses become more probable.

These points are directly aligned with the source's PPO-vs-GRPO explanation. (Source: Build a DeepSeek Model (From Scratch))

32. One subtle point to lock in

GRPO removes the value model.

It does not mean:

\text{“GRPO has no reference model.”}

Wrong.

The source explicitly says:

\boxed{ \text{GRPO removes the value model, not the reference model} }

The frozen reference policy is still used for KL control in the broader formulation. (Source: Build a DeepSeek Model (From Scratch))

That distinction becomes extremely important in the next steps.

Step 5.3 takeaway

The entire motivation can be summarized mathematically as:

PPO
\boxed{ A_i \approx R_i-V_\phi(s_i) }

where V_\phi is learned.

GRPO
\boxed{ A_i= \frac{R_i-\operatorname{mean}(R)} {\operatorname{std}(R)+\epsilon} }

where the baseline comes from other sampled responses to the same prompt.

Therefore:

\boxed{ \text{GRPO = relative group comparison instead of a learned value baseline} }

while retaining the broader policy-optimization machinery such as old-policy comparison, clipping, and reference-policy KL. (Source: deepseekmath-slides; Build a DeepSeek Model (From Scratch))
