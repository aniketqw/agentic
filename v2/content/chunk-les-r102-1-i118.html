R102.1 — PPO: Why We Need a “Safe” Policy Update

Plan node: B1 · chat order #118

↩ Back to main text: Step 5.3 — Why GRPO Instead of PPO? · Step 5.7 — The Full GRPO Training Algorithm

We now move from the basic policy-gradient idea to Proximal Policy Optimization (PPO).

The problem is simple to state:

\boxed{\text{A reward tells us what behavior was good, but a naive update can change the policy too much.}}

The source introduces PPO as the practical stabilization mechanism and then uses it as the conceptual foundation for GRPO. (Source: Build a DeepSeek Model (From Scratch))

1. Start from what we already have

Our RL pipeline is currently:

Prompt
   ↓
LLM policy πθ
   ↓
sample response
   ↓
reward
   ↓
advantage A
   ↓
update policy

Suppose the sampled token was:

a_k.

The policy assigned it probability:

\pi_\theta(a_k\mid s_k).

The basic policy-gradient idea says:

\boxed{ \text{increase probability of actions with positive advantage} }

and:

\boxed{ \text{decrease probability of actions with negative advantage}. }

So why isn't that enough?

2. The problem with a large policy update

Suppose our current policy assigns:

P_{\text{old}}(a)=0.20.

The rollout tells us that this action was good.

A naive gradient step might push it to:

P_{\text{new}}(a)=0.90.

That sounds good because we increased the probability of a rewarded action.

But notice what happened:

0.20\rightarrow0.90.

That's a massive behavioral change from one update.

The source's motivation for PPO is exactly this: if the model changes too much after the sampled rollouts, the training signal can become unreliable because the new policy may assign very different probabilities to the actions on which the rollout was based. (Source: Build a DeepSeek Model (From Scratch))

3. Think of the rollout as evidence from the old policy

This is the key conceptual setup.

At time of sampling, we had:

\pi_{\text{old}}.

It generated:

(a_1,a_2,\ldots,a_T).

Then we calculate rewards and use that data to train a new policy:

\pi_\theta.

But the data was generated by:

\pi_{\text{old}}

not by the new policy.

Therefore we need to ask:

\boxed{ \text{How different is }\pi_\theta\text{ from }\pi_{\text{old}}\text{ on the sampled actions?} }

PPO answers this with a probability ratio.

4. The PPO probability ratio

The source defines:

\boxed{ r_k(\theta) = \frac{ \pi_\theta(a_k\mid s_k) }{ \pi_{\text{old}}(a_k\mid s_k) } }

(Source: Build a DeepSeek Model (From Scratch))

Read it literally:

\boxed{ r = \frac{\text{new probability}} {\text{old probability}} }

5. Why the ratio is useful

Suppose:

\pi_{\text{old}}(a\mid s)=0.20

and the new policy gives:

\pi_\theta(a\mid s)=0.22.

Then:

r=\frac{0.22}{0.20}=1.10.

The new policy made the sampled action:

10\%

more likely.

That's a relatively small change.

6. Example: large increase

Suppose:

P_{\text{old}}=0.20

and:

P_{\text{new}}=0.60.

Then:

r=\frac{0.60}{0.20}=3.

The new policy is assigning:

\boxed{3\times}

the old probability.

That's a very large policy change.

7. Example: probability decreased

Suppose:

P_{\text{old}}=0.20

and:

P_{\text{new}}=0.10.

Then:

r=\frac{0.10}{0.20}=0.5.

So the new policy assigns only half the old probability.

8. The meaning of the three important values

\boxed{r=1}

means:

\text{new probability = old probability}.

So the policy hasn't changed for that sampled action.

\boxed{r>1}

means the new policy makes that action more likely.

\boxed{r<1}

means the new policy makes that action less likely.

This interpretation is directly given in the source. (Source: Build a DeepSeek Model (From Scratch))

9. Now combine ratio with advantage

We already have:

A_k.

Suppose:

A_k>0.

That means:

This sampled action was better than expected.

We therefore want:

r_k>1.

We want to increase its probability.

Conversely, if:

A_k<0,

we want:

r_k<1.

So the natural quantity is:

\boxed{ r_k A_k }

because the advantage tells us direction, while the ratio tells us how much the probability moved relative to the rollout policy.

10. Why not just maximize rA?

Because then the optimizer could try to make:

r\rightarrow\infty

for positive-advantage actions.

For example:

A>0

encourages:

r=1.1\rightarrow2\rightarrow5\rightarrow10\rightarrow\cdots

There is nothing in the basic ratio term itself preventing a very large policy change.

That's why PPO introduces clipping.

11. PPO clipping

The source says PPO clips the ratio to prevent overly large updates. (Source: Build a DeepSeek Model (From Scratch))

The standard clipped form is:

\boxed{ \operatorname{clip}(r,1-\epsilon,1+\epsilon) }

where \epsilon is a small allowed deviation.

For example, if:

\epsilon=0.2,

then:

1-\epsilon=0.8

and:

1+\epsilon=1.2.

So the ratio is constrained to:

\boxed{[0.8,1.2]}

inside the clipped term.

12. What clipping means intuitively

Think of:

r=1

as:

“the new policy is identical to the old policy for this action.”

PPO says:

You can move away from 1, but don't let one update gain unlimited benefit from moving very far away.

So:

old policy
     │
     │
     ▼
    r=1
   /   \
0.8     1.2
│        │
lower   upper
boundary

This is the "proximal" idea.

Stay reasonably close to where you started.

13. The full clipped surrogate idea

The source later uses the standard structure:

\boxed{ \min\left( r_k A_k,\; \operatorname{clip}(r_k,1-\epsilon,1+\epsilon)A_k \right) }

This is the core PPO/GRPO surrogate term. (Source: Build a DeepSeek Model (From Scratch))

The reason for the min is crucial.

It chooses the more conservative improvement estimate.

14. Let's understand this with a positive advantage

Suppose:

A=+2.

and:

\epsilon=0.2.

Therefore the upper bound is:

1.2.

Suppose the new policy produces:

r=1.1.

Then:

rA=1.1\times2=2.2.

Clipped:

1.1\times2=2.2.

So:

\min(2.2,2.2)=2.2.

No problem.

15. Positive advantage, large ratio

Now suppose:

r=1.8.

Then unclipped:

1.8\times2=3.6.

But clipping gives:

1.2\times2=2.4.

Therefore:

\min(3.6,2.4)=2.4.

The optimizer cannot keep gaining objective value simply by making this rewarded action increasingly probable.

That is the central stabilization mechanism.

16. Negative advantage

Now suppose:

A=-2.

Suppose:

r=0.5.

Then:

rA=0.5(-2)=-1.

The clipped ratio is:

0.8.

So:

0.8(-2)=-1.6.

The objective takes:

\min(-1,-1.6)=-1.6.

The negative side is therefore also bounded by the clipping mechanism.

The important conceptual point is not memorizing individual arithmetic cases, but understanding that PPO prevents the optimizer from exploiting arbitrarily large policy changes.

17. PPO therefore has two policies

This is important.

Old policy
\boxed{\pi_{\text{old}}}

This generated the rollout.

Current/trainable policy
\boxed{\pi_\theta}

This is being optimized.

Their probability ratio is:

\boxed{ \frac{\pi_\theta}{\pi_{\text{old}}} }

The source explicitly emphasizes this comparison. (Source: Build a DeepSeek Model (From Scratch))

18. Now introduce the four PPO components

For LLM post-training, the source describes four components. (Source: Build a DeepSeek Model (From Scratch))

             PPO training

          ┌─────────────────┐
          │ Policy model    │
          │ trainable LLM   │
          └────────┬────────┘
                   │
              generates
                   │
                   ▼
              responses
                   │
          ┌────────┴────────┐
          ▼                 ▼
      Reward             Value model
      signal             / critic
          │                 │
          └───────┬─────────┘
                  ▼
              Advantage
                  │
                  ▼
             PPO update
                  ▲
                  │
          Reference model
          (frozen, KL)

Let's separate their roles.

19. Component 1 — Policy model

This is the actual LLM we are training.

\boxed{\pi_\theta}

It chooses the next token.

Its parameters are updated.

20. Component 2 — Reward

The response receives some reward.

The source allows for:

  • a learned reward model, or
  • a verifier.

So:

\boxed{ \text{response} \rightarrow R }

The exact reward source depends on the task. (Source: Build a DeepSeek Model (From Scratch))

21. Component 3 — Value model

This is new.

The value model estimates:

\boxed{ V_\phi(s_k) }

which represents expected future reward from the current state.

The source describes it as a learned critic that predicts how promising a partial response is. (Source: Build a DeepSeek Model (From Scratch))

22. Value model gives us the baseline

Recall:

A_k=R_k-\text{baseline}(s_k).

In PPO, the source gives the baseline specifically as:

\boxed{ A_k=R_k-V_\phi(s_k) }

(Source: Build a DeepSeek Model (From Scratch))

So:

state
  ↓
value model
  ↓
Vφ(s)
  ↓
expected reward

and then:

R-V_\phi(s)

tells us whether the sampled outcome was better or worse than expected.

23. What exactly is the value model learning?

Suppose the model is halfway through a response.

Current state:

Prompt + "Let's calculate..."

The value model asks:

From this point, how much reward do I expect this trajectory to eventually produce?

So:

V_\phi(s_k) \approx E[\text{future return}\mid s_k].

This is why the value model is sometimes called the critic.

The policy says:

What action should I take?

The value model says:

How promising is the current state?

24. Why does PPO need a learned value model?

Because the baseline should depend on the current state.

Different partial responses can have different expected outcomes.

For example:

State A → already doing correct algebra
          expected reward high

State B → made a conceptual mistake
          expected reward low

A learned value function can distinguish them.

Thus:

A=R-V_\phi(s)

can be much more informative than:

A=R-\text{one constant}.

25. The cost of the value model

But the source points out an important engineering drawback.

The value model adds:

  • memory,
  • forward passes,
  • training losses,
  • optimization complexity.

(Source: Build a DeepSeek Model (From Scratch))

For very large LLMs, this matters enormously.

And this sets up the motivation for GRPO.

26. Component 4 — Reference model

The fourth component is:

\boxed{\pi_{\text{ref}}}

a frozen reference model.

The source describes it as usually a frozen copy of the model before RL training. (Source: Build a DeepSeek Model (From Scratch))

Its purpose is different from the value model.

Do not confuse:

\boxed{\text{value model}}

with:

\boxed{\text{reference model}}.

27. Value model vs reference model

Value model

Purpose:

\boxed{\text{estimate expected reward}}

Trainable:

\boxed{\text{yes}}

Used for:

\boxed{\text{advantage}}
Reference model

Purpose:

\boxed{\text{keep policy from drifting too far}}

Frozen:

\boxed{\text{yes}}

Used for:

\boxed{\text{KL control}}

This distinction is explicitly emphasized by the source. (Source: Build a DeepSeek Model (From Scratch))

28. Why do we need a reference model?

Suppose our reward only checks:

\text{math answer correct?}

The model might discover a weird way to maximize that reward while harming general behavior.

Or a learned reward model might contain exploitable quirks.

So we want:

\boxed{ \text{improve reward} + \text{stay reasonably close to the original model} }

The reference policy supplies the second constraint.

The source explains that a KL penalty discourages excessive drift from the pretrained/reference distribution. (Source: Build a DeepSeek Model (From Scratch))

29. KL in this context

Conceptually we calculate something like:

KL(\pi_\theta\|\pi_{\text{ref}}).

If this becomes large:

\boxed{\text{the trained policy has drifted substantially}}

and a penalty is applied.

So the training pressure becomes:

              Reward pressure
                    ↓
             "Become better"
                    │
                    ▼
              πθ improves
                    ▲
                    │
              KL pressure
                    │
        "Don't move too far
        from reference"

The source specifically notes that in PPO-style LLM training, KL can be computed token by token for generated tokens. (Source: Build a DeepSeek Model (From Scratch))

30. PPO therefore balances three forces

Conceptually:

\boxed{ \text{Reward improvement} }

versus:

\boxed{ \text{policy-update stability} }

versus:

\boxed{ \text{reference-policy stability} }

More concretely:

\boxed{ \text{advantage} + \text{clipping} + \text{reference KL control} }

This exact combination becomes important again when we arrive at GRPO. (Source: Build a DeepSeek Model (From Scratch))

31. Full PPO conceptual pipeline

Now we can finally draw PPO end-to-end:

                    PROMPT
                       │
                       ▼
              Trainable Policy πθ
                       │
                  sample tokens
                       │
                       ▼
                 RESPONSE
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
         Reward R          Value Model Vφ
             │                   │
             └────────┬──────────┘
                      ▼
               Advantage A
                      │
                      ▼
             compare πθ with
                πold
                      │
                      ▼
                ratio r
                      │
                      ▼
                   CLIP

                      +
                 Reference KL
                      │

                  PPO loss
                      │

                      │
                      ▼
                update πθ

32. Important: old policy and reference policy are not the same thing

This is an extremely common confusion.

We have:

\boxed{\pi_{\text{old}}}

and:

\boxed{\pi_{\text{ref}}}.

They serve different purposes.

Old policy

Used for:

\boxed{ r= \frac{\pi_\theta}{\pi_{\text{old}}} }

It tells us how much the current policy changed relative to the policy that generated the rollout.

Reference policy

Used for:

\boxed{ KL(\pi_\theta\|\pi_{\text{ref}}) }

It acts as the stable anchor.

The source's later GRPO explanation preserves both of these mechanisms. (Source: Build a DeepSeek Model (From Scratch))

33. Why does this lead directly to GRPO?

Now we can see the expensive part of PPO.

We need:

\boxed{ \text{Policy} + \text{Reward} + \text{Value Model} + \text{Reference Model} }

The source's next question is therefore:

Can we get a useful baseline without training a separate value model?

This is exactly what Group Relative Policy Optimization (GRPO) does.

Instead of:

A_i=R_i-V_\phi(s_i),

GRPO uses the rewards of multiple completions for the same prompt to construct a group-relative advantage.

The source explicitly identifies this as its key simplification. (Source: Build a DeepSeek Model (From Scratch))

34. The big picture

We have now reached:

\boxed{ \text{Policy Gradient} \rightarrow \text{Advantage} \rightarrow \text{PPO} }

and next:

\boxed{ \text{PPO} \rightarrow \text{GRPO} }

The conceptual transformation will be:

\boxed{ \text{learned value baseline} \rightarrow \text{group-relative reward baseline} }

while keeping important PPO ideas such as:

\boxed{ \text{old-policy ratio} + \text{clipping} + \text{reference-policy KL} }

The source explicitly states that GRPO removes the value model, not the entire PPO stabilization machinery. (Source: Build a DeepSeek Model (From Scratch))

R102.1 checkpoint

You should now be able to explain:

\boxed{ r_k= \frac{\pi_\theta(a_k|s_k)} {\pi_{\text{old}}(a_k|s_k)} }

as:

How much more or less likely is the sampled action under the new policy than under the policy that generated the rollout?

And:

\boxed{ A_k=R_k-V_\phi(s_k) }

as:

How much better or worse was the observed outcome than the value model expected?

And finally:

\boxed{ \text{PPO clipping} }

as:

A mechanism preventing one RL update from gaining unlimited benefit by moving the policy too far from the rollout policy.
