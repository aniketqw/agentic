Step 5.16 — The 800K Distillation Dataset: Rejection Sampling and Data Composition

Plan node: I8 · chat order #57

We now move from student training to the thing that makes the whole student-training process work:

\boxed{\text{What exactly did DeepSeek put into the student's training set?}}

This is arguably as important as the loss function itself.

The central idea is:

\boxed{ \text{A student cannot learn a reasoning behavior that is not represented well in its training data.} }

The supplied source therefore treats dataset quality as the critical ingredient of the R1 distillation approach. (Source: Build a DeepSeek Model (From Scratch))

5.16.1 Start with the basic problem

Suppose the teacher receives one math question.

It might generate:

R_1,R_2,R_3,\ldots,R_G

where each R_i is a different reasoning attempt.

Some may be:

  • correct,
  • incorrect,
  • partially correct,
  • correct but badly formatted,
  • repetitive,
  • incoherent.

The question is:

Which response should become training data for the student?

DeepSeek's answer is:

\boxed{\text{generate multiple candidates + verify + filter}}

This is rejection sampling in the source's distillation-data pipeline. (Source: Build a DeepSeek Model (From Scratch))

5.16.2 Rejection sampling: the complete flow

Think about a single prompt:

q

The teacher samples:

R_1,R_2,R_3,\ldots,R_K

Then each candidate goes through verification.

Conceptually:

                    Prompt q
                       │
                       ▼
                 DeepSeek-R1
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
         R1            R2           R3   ... RK
          │            │            │
          ▼            ▼            ▼
      Verify         Verify       Verify
          │            │            │
          ▼            ▼            ▼
       Correct?      Correct?     Correct?
          │            │            │
          └────────────┴────────────┘
                       │
                       ▼
                Quality filtering
                       │
                       ▼
             Keep good responses

The retained responses become teacher-generated supervision for the students.

(Source: Build a DeepSeek Model (From Scratch))

5.16.3 Why generate multiple responses?

Because one teacher sample can fail.

Suppose:

P(\text{one generated response is correct})=0.4.

With one attempt:

P(\text{success})=0.4.

But with K=5 independent attempts, the probability that at least one is correct is:

1-(1-0.4)^5.

Therefore:

1-0.6^5 = 1-0.07776 = \boxed{0.92224}.

So approximately:

\boxed{92.2\%}

chance of obtaining at least one correct candidate.

This is a general probabilistic illustration, not a reported DeepSeek sampling probability.

The intuition is:

\boxed{ \text{multiple attempts} \rightarrow \text{higher chance of obtaining a strong trajectory} }

5.16.4 But “correct” is not enough

This is one of the most important parts of the source.

Suppose the teacher generates:

Answer: 42.

and it is correct.

That may be useful.

But suppose instead it generates:

[fragmented multilingual text]
[unnecessary code blocks]
[random formatting]
[repeated reasoning]
42

It may still be technically correct.

The source says such outputs can be filtered because the student learns not only the content, but also the style and structure of the training data. (Source: Build a DeepSeek Model (From Scratch))

Therefore:

\boxed{ \text{Correctness} \neq \text{training-data quality} }

A useful training example needs both.

5.16.5 The two-stage selection idea

A simplified way to understand the pipeline is:

\boxed{ \text{Candidate generation} }

then:

\boxed{ \text{Correctness verification} }

then:

\boxed{ \text{Quality/style filtering} }

So:

\boxed{ \text{Keep} = \text{Correct} \land \text{Well-formatted} }

This is the conceptual rule described in the source. (Source: Build a DeepSeek Model (From Scratch))

5.16.6 Different domains need different verification

This is where the dataset becomes technically interesting.

A mathematical answer often has an objective answer.

Code can often be executed.

But a general response may not have a deterministic ground truth.

So the verifier depends on the domain.

5.16.7 Mathematics

For a math problem:

\boxed{ \text{candidate final answer} \stackrel{?}{=} \text{ground-truth answer} }

For example:

Question:

2x+6=20.

Teacher response:

2x = 14
x = 7

Verifier:

7\stackrel{?}{=}7.

Accept.

But suppose:

2x = 14
x = 8

Then:

8\neq7.

Reject.

The source says mathematical candidates can be checked against known ground-truth answers. (Source: Build a DeepSeek Model (From Scratch))

5.16.8 Why reasoning can still be wrong even when the final answer looks plausible

Imagine the teacher writes:

3x = 18
x = 5

The final answer is wrong.

A verifier that checks only the final extracted value catches this.

But the more interesting issue is that:

\boxed{ \text{correct final answer} }

does not necessarily guarantee:

\boxed{ \text{correct reasoning trace} }.

The supplied source emphasizes correctness checking but does not provide a universal formal proof verifier for every intermediate reasoning statement.

So we should not infer that every retained chain-of-thought step is formally proven correct.

The safe source-grounded conclusion is:

\boxed{ \text{the response was judged sufficiently correct for inclusion} }

through the described verification process.

5.16.9 Code

For code, the source describes a more powerful verifier.

Instead of asking:

“Does this code look right?”

the system can:

\boxed{ \text{execute the code} }

and:

\boxed{ \text{test its output} }.

So:

Teacher code
    ↓
Execute
    ↓
Run tests
    ↓
Pass?
  /   \
Yes    No
 |      |
Keep   Reject

(Source: Build a DeepSeek Model (From Scratch))

This is exactly why code is well suited to verifier-based reinforcement learning and data curation.

5.16.10 But code verification has a limitation

This point is supported by the broader source discussion of verifiers.

Passing a visible set of tests does not necessarily prove correctness on every possible input. The source explicitly discusses this as a reward-hacking/verification concern in the RL context. (Source: Build a DeepSeek Model (From Scratch))

Therefore:

\boxed{ \text{passes tests} \neq \text{mathematically guaranteed correctness} }

The verifier itself becomes part of the quality-control system.

5.16.11 STEM and logic are harder

Suppose the prompt is a scientific reasoning question.

There may not be a simple deterministic answer extractor.

For such cases, the source says DeepSeek used DeepSeek-V3 as a generative reward model.

The V3 model receives:

\boxed{ \text{ground-truth answer} + \text{candidate response} }

and judges whether the response is correct. (Source: Build a DeepSeek Model (From Scratch))

So the pipeline becomes:

\boxed{ (q,y_{\text{gold}},R_i) \rightarrow \text{V3 judge} \rightarrow \text{accept/reject} }

5.16.12 This creates a hierarchy of verification

Conceptually:

Math
\boxed{ \text{exact answer comparison} }
Code
\boxed{ \text{execution/testing} }
STEM / Logic
\boxed{ \text{generative judging} }
General data
\boxed{ \text{quality/content filtering} }

This is a crucial design principle:

\boxed{ \text{verification mechanism should match the task} }

The source makes this same broader point in its RL section: use exact verifiers where possible and learned judgment where deterministic checking is insufficient. (Source: Build a DeepSeek Model (From Scratch))

5.16.13 Correctness is only one filter

The source explicitly lists examples of responses that might be rejected despite being technically correct:

  • mixed languages,
  • chaotic formatting,
  • excessive code blocks,
  • incoherent presentation.

(Source: Build a DeepSeek Model (From Scratch))

Why?

Because:

\boxed{ \text{student imitates training distribution} }

Therefore poor teacher outputs can become poor student habits.

This is a form of behavioral imitation.

5.16.14 A powerful mental model: teacher traces are demonstrations

Instead of thinking:

“The teacher gave the answer.”

think:

“The teacher gave a demonstration of how to solve the problem.”

For example:

q \rightarrow \underbrace{ \text{decomposition} \rightarrow \text{calculation} \rightarrow \text{checking} \rightarrow \text{answer} }_{\text{teacher trajectory}}

The student sees many such trajectories.

So it can learn recurring structures such as:

\text{identify subproblem}
\rightarrow \text{select technique}
\rightarrow \text{perform calculation}
\rightarrow \text{verify}

This is why the source says the value lies in the coherent reasoning strategy, not merely the final answer. (Source: Build a DeepSeek Model (From Scratch))

5.16.15 Now the 800K dataset

After this filtering pipeline, the source reports approximately:

\boxed{804,745\text{ training samples}}

and commonly refers to it as the:

\boxed{800K\text{ distillation dataset}}.

(Source: Build a DeepSeek Model (From Scratch))

This distinction is important:

804,745\approx800K

so “800K” is the rounded description.

Using the rounded values:

395K+211K+10K+10K+178K

5.16.18 Percentage composition

Using the approximate 804,000 rounded total:

Math
\frac{395}{804}\times100 \approx \boxed{49.1\%}.
Code

5.16.19 The biggest insight: 75% is reasoning-heavy

Math + Code:

395K+211K = 606K.

Approximately:

\frac{606}{804}\times100 \approx \boxed{75.4\%}.

The source summarizes this as roughly:

\boxed{75\%}.

(Source: Build a DeepSeek Model (From Scratch))

Therefore the training distribution is heavily biased toward reasoning-intensive domains.

5.16.20 Why not make it 100% math and code?

Because then the student risks becoming a specialist.

Suppose:

100\%

of training consisted of competition math.

The resulting model might become excellent at:

\text{equations}

but worse at:

\text{conversation}, \text{factual QA}, \text{instruction following}, \text{translation}, \text{general interaction}.

The source explicitly says the 178K general-purpose examples help prevent the distilled model from becoming too narrow. (Source: Build a DeepSeek Model (From Scratch))

5.16.21 The role of the General 178K

The source describes this portion as including:

  • general-purpose content,
  • writing,
  • factual QA,
  • self-cognition,
  • translation.

Its purpose is to preserve the assistant-like breadth of the model. (Source: Build a DeepSeek Model (From Scratch))

So the dataset has a deliberate tension:

\boxed{ \text{reasoning specialization} }

versus:

\boxed{ \text{general usefulness} }.

This is a major training-data design decision.

5.16.22 Why STEM and Logic are small but important

STEM:

\approx10K

Logic:

\approx10K.

Together:

20K.

Compared with:

804K

that's only about:

\frac{20}{804}\times100 \approx \boxed{2.49\%}.

Yet the source calls these domains important because they help preserve reasoning ability outside pure mathematics and coding. (Source: Build a DeepSeek Model (From Scratch))

This gives us an important lesson:

\boxed{ \text{sample count} \neq \text{importance} }

A small category can serve an important coverage role.

5.16.23 Average sample length: 5,355 tokens

This is another extremely important fact.

The source reports:

\boxed{5,355\text{ tokens/sample on average}}.

(Source: Build a DeepSeek Model (From Scratch))

That means these are not short “question → answer” pairs.

They are often long reasoning traces.

The intended knowledge transfer is therefore:

\boxed{ \text{how the solution unfolds} }

not simply:

\boxed{ \text{what the final answer is} }.

5.16.24 Approximate token volume

Using the rounded figures:

804,745\times5,355.

Approximately:

\boxed{4.31\times10^9}

tokens.

So the total teacher-generated dataset contains roughly:

\boxed{4.3\text{ billion tokens}}

under the simple assumption that the reported average applies across all samples.

This is a derived estimate from the source's sample count and average length, not an independently reported token total.

5.16.25 Exam numerical

Suppose:

N=800,000

and:

\bar L=5,355.

Then:

N\bar L = 800,000\times5,355
= \boxed{4.284\times10^9}

tokens.

So about:

\boxed{4.28\text{ billion tokens}}.

Using the more precise 804,745 count gives about 4.31B.

5.16.26 Why are long reasoning traces valuable?

Suppose two teachers produce:

Teacher A
x = 83
Teacher B
Multiply both sides by 2.
...
Subtract 2x.
...
Verify the result.
Therefore x = 83.

Both reveal:

\text{answer}=83.

But Teacher B exposes far more intermediate supervision.

The student can see:

\boxed{ \text{problem decomposition} }
\boxed{ \text{operation ordering} }
\boxed{ \text{error correction} }
\boxed{ \text{verification} }.

This is why long chain-of-thought traces can be valuable for reasoning distillation.

The source explicitly describes these samples as detailed, multi-step traces that can include intermediate calculations, corrections, and final verification. (Source: Build a DeepSeek Model (From Scratch))

5.16.27 But long traces also create a cost

Longer sequence:

N\uparrow

means more token computation.

For ordinary dense self-attention, attention cost grows approximately as:

\boxed{O(N^2)}.

Thus:

\text{reasoning trace length}\uparrow

can significantly increase training cost.

This connects directly to everything we learned earlier about:

  • sequence length,
  • attention,
  • KV cache,
  • context windows.

So the dataset itself creates a compute tradeoff:

\boxed{ \text{richer reasoning supervision} \leftrightarrow \text{higher computational cost} }.

5.16.28 General data is different

The source says DeepSeek used their V3 model to generate the non-reasoning/general responses.

For straightforward queries, they did not necessarily attach lengthy reasoning.

For something as simple as:

hello

the source says no chain-of-thought was added.

(Source: Build a DeepSeek Model (From Scratch))

This is important because forcing every example to have an enormous reasoning trace would be wasteful.

So the training data adapts the response style to the task:

\boxed{ \text{hard reasoning problem} \rightarrow \text{long detailed trace} }

while:

\boxed{ \text{simple conversational request} \rightarrow \text{concise response} }.

5.16.29 This prevents a bad student behavior

Imagine every training example looked like:

<very long reasoning>
...
<very long reasoning>
...
Hello!

The student might learn that even trivial queries require enormous responses.

That would be undesirable.

Therefore dataset construction controls not only what the model knows, but also when it should reason at length.

This is an important inference from the source's domain-specific curation strategy.

5.16.30 A critical distinction: data distribution shapes behavior

Suppose:

75\%

of your examples are math + code.

You should expect the student to devote substantial capacity to those behaviors.

Suppose:

22\%

are general.

That helps preserve broader behavior.

Therefore:

\boxed{ P(\text{training behavior}) \rightarrow P(\text{learned behavior}) }

This is not a literal equality, but it is the right conceptual understanding.

5.16.31 The dataset is therefore a “compressed teacher”

Think carefully about this.

The original teacher is:

671B

parameters.

Instead of putting the teacher inside the student-training loop, DeepSeek converts teacher behavior into:

\boxed{ \text{millions of tokens of demonstrations} }

Then:

\boxed{ \text{student parameters} }

absorb patterns from those demonstrations.

So the 800K dataset acts as an intermediate representation of teacher behavior.

Not mathematically lossless.

Not literally the teacher's internal state.

But a practical behavioral interface between teacher and student.

5.16.32 The information bottleneck

We can write the pipeline conceptually as:

\boxed{ \text{Teacher internal knowledge} }

↓

\boxed{ \text{generated text} }

↓

\boxed{ \text{filtering} }

↓

\boxed{ \text{finite dataset} }

↓

\boxed{ \text{student capacity} }

At every arrow, information can be lost.

Therefore:

\boxed{ \text{distillation is fundamentally an information bottleneck} }

This explains the capacity-gap results from Step 5.15.

5.16.33 Why rejection sampling is so important

Imagine no filtering.

Then:

\text{good responses} + \text{bad responses}

become the training set.

The student minimizes:

L_{\text{SFT}}

on all of them.

So it is literally rewarded for increasing probability of bad teacher responses too.

Filtering therefore changes the effective target distribution:

P_{\text{raw teacher}}

into:

\boxed{ P_{\text{curated teacher}} }.

The student is trained on the second distribution.

That is a very deep connection between data curation and optimization.

5.16.34 Simple probability example

Suppose raw teacher data has:

70\%\text{ useful},
30\%\text{ poor}.

Suppose filtering removes 90\% of poor examples but only 10\% of useful ones.

From 10,000 examples:

Useful retained:

7000\times0.9 = 6300.

Poor retained:

3000\times0.1 = 300.

Total:

6600.

Useful fraction:

\frac{6300}{6600}\times100 \approx \boxed{95.45\%}.

So a strong filter can dramatically change the quality distribution.

This is an illustrative calculation, not a reported DeepSeek acceptance rate.

5.16.35 Rejection sampling vs ordinary sampling

Ordinary synthetic-data generation
q \rightarrow \text{one teacher response} \rightarrow \text{dataset}.
Rejection-sampled generation
q \rightarrow R_1,\ldots,R_K \rightarrow \text{verify} \rightarrow \text{filter} \rightarrow \text{dataset}.

The second pipeline spends more compute up front.

But the resulting student data can be much higher quality.

Therefore:

\boxed{ \text{more teacher-generation cost} \rightarrow \text{better training signal} \rightarrow \text{better student} }

This is why the source describes the distillation dataset generation as a deliberate quality-control process. (Source: Build a DeepSeek Model (From Scratch))

5.16.36 The economics then make sense

The teacher-generation stage is expensive.

But once the data exists:

\boxed{ \text{one teacher} \rightarrow \text{one reusable dataset} }

and then:

\boxed{ \text{many students} \rightarrow \text{same dataset} }.

Hence the earlier point:

\boxed{ \text{teacher cost is amortized} }.

(Source: Build a DeepSeek Model (From Scratch))

5.16.37 Dataset design determines specialization

Let's make this concrete.

Suppose a hypothetical dataset were:

95\%\text{ coding}, \quad 5\%\text{ general}.

Then a student might become highly code-oriented.

Conversely:

95\%\text{ general conversation}, \quad 5\%\text{ reasoning}.

Then the reasoning behavior would receive much less supervision.

DeepSeek instead uses:

\boxed{ \text{heavy reasoning data} + \text{meaningful general data} }

to produce a model that is both reasoning-capable and still useful as an assistant. (Source: Build a DeepSeek Model (From Scratch))

5.16.38 One subtle point: the 800K examples are not all the same kind of supervision

There are at least two broad categories:

\boxed{ \text{reasoning examples} }

and:

\boxed{ \text{general-purpose examples} }.

Reasoning examples emphasize:

\text{long-form problem solving}.

General examples emphasize:

\text{normal assistant behavior}.

So the student objective is effectively aggregating multiple behavioral distributions into one model.

5.16.39 This connects directly to catastrophic forgetting

We have already learned that fine-tuning can shift a pretrained model toward the training distribution.

Here, imagine:

\text{base model}

already knows:

\text{conversation + QA + translation + coding + math}.

If distillation data contained only math reasoning, SFT could disproportionately reinforce math and potentially weaken the balance of other behaviors.

The source doesn't present a formal catastrophic-forgetting experiment here, so we should not claim a measured effect from this chapter.

But it explicitly states that the general 178K samples are intended to prevent the distilled models from becoming narrow specialists. (Source: Build a DeepSeek Model (From Scratch))

5.16.40 A compact mathematical model of the dataset

We can conceptualize the student data distribution as:

\boxed{ P_{\text{student-data}} = \sum_d \lambda_d P_d }

where each d is a domain:

d\in \{\text{Math, Code, STEM, Logic, General}\}.

And:

\sum_d\lambda_d=1.

Approximately:

\lambda_{\text{Math}}\approx0.49
\lambda_{\text{Code}}\approx0.26
\lambda_{\text{General}}\approx0.22
\lambda_{\text{STEM}}\approx0.012
\lambda_{\text{Logic}}\approx0.012.

These are derived from the source's rounded counts.

The student's loss is therefore effectively averaging supervision across these domain-specific distributions.

5.16.41 A useful training objective interpretation

If:

L_d(\theta)

is the SFT loss on domain d, then conceptually:

\boxed{ L(\theta) = \sum_d \lambda_dL_d(\theta) }

This is not stated as DeepSeek's explicit published loss equation for the dataset mixture; it is the natural mathematical interpretation of training on a mixed dataset.

It explains why dataset composition matters.

Increasing:

\lambda_{\text{Math}}

increases the relative training pressure from mathematical examples.

5.16.42 Why this is more than “just 800K examples”

The important object is not merely:

N=800,000.

It is:

\boxed{ (N,\text{quality},\text{distribution},\text{length},\text{verification}) }

all together.

Two datasets could both contain 800K examples but yield very different students.

For example:

D_1= \text{high-quality verified reasoning}.

versus:

D_2= \text{uncurated teacher outputs}.

Same sample count.

Very different training signal.

5.16.43 The key design principle

The source's approach can be summarized as:

\boxed{ \text{Generate broadly} \rightarrow \text{verify strictly} \rightarrow \text{filter stylistically} \rightarrow \text{mix domains deliberately} \rightarrow \text{SFT student} }

That is the actual engineering recipe behind the famous “800K distillation” result.

5.16.45 Exam-style conceptual questions

Q1. Why is rejection sampling necessary?

Because a teacher can generate incorrect or poorly formatted responses. Keeping only high-quality verified responses creates a stronger supervised signal for the student. (Source: Build a DeepSeek Model (From Scratch))

Q2. Why is Code easier to verify than General conversation?

Code can often be executed and tested, while open-ended general responses do not always have a single deterministic correctness criterion. The source therefore uses different verification mechanisms for different domains. (Source: Build a DeepSeek Model (From Scratch))

Q3. Why include 178K general examples?

To prevent the distilled models from becoming narrow reasoning specialists and preserve general assistant capabilities such as conversation, factual QA, writing, self-cognition, and translation. (Source: Build a DeepSeek Model (From Scratch))

Q4. Why are long reasoning traces valuable?

They expose intermediate problem-solving behavior, not only final answers, allowing the student to imitate solution strategies and multi-step reasoning. (Source: Build a DeepSeek Model (From Scratch))

Q5. Why aren't long traces free?

Longer sequences require more token computation and increase the cost of processing attention, so richer supervision comes with greater compute requirements.

5.16.46 The deepest connection to everything we've studied

Earlier we learned:

\boxed{\text{GRPO}}

uses rewards to improve a teacher.

Now:

\boxed{\text{Rejection sampling}}

selects successful teacher trajectories.

Then:

\boxed{\text{SFT}}

teaches those trajectories to the student.

So the complete loop is:

\boxed{ \text{RL} \rightarrow \text{better behavior} \rightarrow \text{teacher trajectories} \rightarrow \text{verification} \rightarrow \text{distillation} }

This is the bridge between our RL/GRPO chapters and our knowledge-distillation chapter.

5.16.47 One final distinction you must know for the exam

Do not confuse these three things:

Reward

Used to tell RL:

\boxed{\text{Was this sampled behavior good?}}
Rejection sampling

Used to decide:

\boxed{\text{Should this generated behavior become training data?}}
Cross-entropy

Used to train the student:

\boxed{\text{How well does the student predict the selected teacher tokens?}}

Therefore:

\boxed{ \text{Reward}\neq\text{filter}\neq\text{loss} }

They operate at different stages.

\boxed{ \textbf{High-quality teacher behavior turned into supervised demonstrations} }

\boxed{ \textbf{Distillation succeeds not merely because the teacher is strong, but because its useful behavior is converted into clean, verifiable, appropriately distributed training data.} }
