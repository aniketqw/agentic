Step 5.21 — ReTool PPO Objective, Step by Step

Plan node: I9 · chat order #62

Now we go one level deeper.

In Step 5.20, we established:

\boxed{\text{ReTool = PPO + real code execution + correctness reward}}

The key novelty was the hybrid rollout. Now we need to understand exactly how PPO operates on that rollout.

The ReTool slides explicitly state that the training objective is plain PPO, not GRPO, and that the advantage comes from a learned value function. (Source: retool-slides)

5.21.1 Start from ordinary language-model RL

An LLM can be viewed as a policy:

\boxed{\pi_\theta}

where:

  • \theta = model parameters
  • s_t = state/context at step t
  • o_t = token/action generated at step t

The model gives:

\pi_\theta(o_t\mid s_t)

which means:

probability that the current policy assigns to token o_t, given the current context s_t.

For a language model, the state is essentially the current context.

So:

s_t= (q,o_1,o_2,\ldots,o_{t-1})

where q is the original question.

5.21.2 What does the state look like in ReTool?

This is where ReTool differs.

The context can contain:

\boxed{ \text{question} + \text{reasoning} + \text{code} + \text{interpreter output} }

For example:

Question:
Solve the problem.

Reasoning:
I should search candidate values.

Code:
<code>
...
</code>

Interpreter:
<interpreter>
699
</interpreter>

Reasoning:
The candidate appears to be 699...

Therefore:

\boxed{ s_t=(q,o_{<t};CI) }

where CI represents the code-interpreter context described in the deck. (Source: retool-slides)

5.21.3 The policy generates the next token

At step t:

o_t\sim\pi_\theta(\cdot\mid s_t)

For example:

P(\texttt{calculate}\mid s_t)=0.10
P(\texttt{<code>}\mid s_t)=0.25
P(\texttt{answer}\mid s_t)=0.05.

The model samples one action/token.

The important point is:

\boxed{ \text{tool invocation itself is generated through the policy} }

The model decides to emit code.

5.21.4 Then the environment may intervene

Suppose the model emits:

<code>
x = 17 * 41
print(x)
</code>

The sandbox executes it.

The result:

697

gets inserted into the context.

So the next state becomes:

\boxed{ s_{t+1} = \text{previous state} + \text{interpreter feedback} }

This is why ReTool's trajectory is different from ordinary text-only RL. (Source: retool-slides)

5.21.5 Now ask: how do we update the policy?

Suppose a rollout eventually gets:

R=+1.

We want the model to become more likely to repeat useful behavior that led to that successful trajectory.

But we do not want:

\text{one successful rollout} \Rightarrow \text{massive policy change}.

This is exactly the problem PPO addresses.

5.21.6 Why PPO uses the old policy

During rollout collection, we have:

\pi_{\text{old}}.

After collecting the rollout, we construct a new policy:

\pi_\theta.

For a sampled token o_t, compare:

\pi_\theta(o_t\mid s_t)

against:

\pi_{\text{old}}(o_t\mid s_t).

Define the ratio:

\boxed{ r_t(\theta) = \frac{ \pi_\theta(o_t\mid s_t) }{ \pi_{\text{old}}(o_t\mid s_t) } }

This is the central quantity in PPO. (Source: retool-slides)

5.21.7 Intuition behind the ratio

Suppose old policy:

P_{\text{old}}(o_t)=0.10

and new policy:

P_{\text{new}}(o_t)=0.12.

Then:

r_t = \frac{0.12}{0.10} = \boxed{1.2}.

So the new policy increased the probability by:

20\%.

If:

r_t=1,

nothing changed.

If:

r_t<1,

the new policy decreased the probability.

5.21.8 But probability ratio alone isn't enough

We also need to know:

Was this action good or bad?

That information is represented by the advantage:

\boxed{\hat A_t}

This is the crucial quantity in PPO.

5.21.9 What does advantage mean?

Conceptually:

\boxed{ A(s_t,o_t) = \text{how good this action was} - \text{how good we expected the state to be} }

For a positive advantage:

\hat A_t>0

the action was better than expected.

For a negative advantage:

\hat A_t<0

the action was worse than expected.

Therefore:

\boxed{ \text{positive advantage} \Rightarrow \text{increase probability} }

and:

\boxed{ \text{negative advantage} \Rightarrow \text{decrease probability}. }

5.21.10 Where does PPO get advantage from?

This is the exact difference from GRPO.

PPO uses a learned value function:

\boxed{ V_\phi(s_t) }

where \phi are the parameters of the value model/value head.

The supplied reasoning source explicitly explains:

PPO's value function estimates expected future outcome quality, while GRPO removes this learned value model and gets its relative signal from a sampled group. (Source: Build a DeepSeek Model (From Scratch))

5.21.11 Return vs value

Suppose the eventual rollout produces reward:

R=+1.

The value model might predict:

V_\phi(s_t)=0.4.

Then a simple advantage estimate is:

\hat A_t = R-V_\phi(s_t).

So:

\hat A_t = 1-0.4 = \boxed{0.6}.

Interpretation:

The outcome was considerably better than the value model expected.

5.21.12 Negative example

Suppose:

R=-1

and:

V_\phi(s_t)=-0.2.

Then:

\hat A_t = -1-(-0.2) = \boxed{-0.8}.

So:

\boxed{ \text{strongly negative advantage} }

and PPO pushes the probability of the sampled action downward.

5.21.13 Why not simply use reward?

This question is extremely important.

Suppose every token in a 1,000-token trajectory gets the same reward:

R=+1.

That doesn't tell us what the model expected from each state.

The value function provides a baseline:

V_\phi(s_t).

Thus:

\boxed{ A_t = \text{actual outcome} - \text{expected outcome} }

gives a more informative learning signal.

This is the role of the value model in PPO. (Source: Build a DeepSeek Model (From Scratch))

5.21.14 PPO objective before clipping

Ignoring clipping for a moment:

\boxed{ J(\theta) = \mathbb E \left[ r_t(\theta)\hat A_t \right] }

where:

r_t(\theta) = \frac{\pi_\theta(o_t|s_t)} {\pi_{\text{old}}(o_t|s_t)}.

So:

\boxed{ \text{policy change} \times \text{quality of action} }

determines the learning signal.

5.21.15 Example with positive advantage

Suppose:

r_t=1.15

and:

\hat A_t=0.8.

Then:

r_t\hat A_t = 1.15\times0.8 = \boxed{0.92}.

The action was good, and the new policy increased its probability.

That is desirable.

5.21.16 Example with negative advantage

Suppose:

r_t=0.85

and:

\hat A_t=-0.8.

Then:

r_tA_t = 0.85(-0.8) = \boxed{-0.68}.

The action was bad and the new policy reduced its probability.

That is also desirable.

5.21.17 Why clipping is necessary

Imagine the model suddenly changes:

0.10\rightarrow0.50.

Then:

r_t= \frac{0.50}{0.10} = 5.

A fivefold increase is enormous.

A single rollout could therefore cause an unstable update.

PPO prevents excessive policy movement through clipping.

5.21.18 PPO clipping

Define:

\boxed{ \operatorname{clip}(r_t,1-\epsilon,1+\epsilon) }

Suppose:

\epsilon=0.2.

Then:

1-\epsilon=0.8

and:

1+\epsilon=1.2.

Therefore:

r_t

is restricted to:

\boxed{[0.8,1.2]}.

5.21.19 Full clipped PPO objective

The ReTool slide gives the standard PPO form:

\boxed{ J_{\text{PPO}}(\theta) = \mathbb E_t \left[ \min \left( r_t(\theta)\hat A_t,\, \operatorname{clip} (r_t(\theta),1-\epsilon,1+\epsilon)\hat A_t \right) \right] }

This is the core ReTool training objective. (Source: retool-slides)

Now we will understand exactly why the min is there.

5.21.20 Case A: positive advantage

Suppose:

A_t=+2

and:

r_t=1.5.

Raw objective:

r_tA_t = 1.5\times2 = 3.

Clipped ratio:

\operatorname{clip}(1.5,0.8,1.2) = 1.2.

Therefore:

1.2\times2 = 2.4.

Take minimum:

\boxed{ \min(3,2.4)=2.4 }

So PPO refuses to give the full benefit of the 50% probability increase.

5.21.21 Case B: negative advantage

Now:

A_t=-2

and:

r_t=0.5.

Raw:

0.5(-2) = -1.

Clipped:

\operatorname{clip}(0.5,0.8,1.2) = 0.8.

Then:

0.8(-2) = -1.6.

Take minimum:

\boxed{ \min(-1,-1.6)=-1.6 }

This makes excessive policy movement toward a bad action unattractive.

5.21.22 The geometric intuition

Think of PPO as saying:

\boxed{ \text{"Improve the policy, but don't move too far in one update."} }

So:

\text{good action} \rightarrow \text{increase probability}

but only moderately.

And:

\text{bad action} \rightarrow \text{decrease probability}

but again with controlled updates.

5.21.23 Now bring ReTool back into the equation

Here is where everything becomes interesting.

The action might be a normal reasoning token:

I should search...

or:

<code>

or:

for x in range(...)

The model may therefore receive credit for a sequence like:

\boxed{ \text{reason} \rightarrow \text{call tool} \rightarrow \text{observe} \rightarrow \text{correct} \rightarrow \text{answer} }

The probability ratio is calculated for model-generated tokens within that hybrid trajectory. (Source: retool-slides)

5.21.24 Important subtlety: interpreter output isn't the policy action

Suppose:

<code>
print(5*9)
</code>

produces:

45

The model generated:

\boxed{\texttt{print(5*9)}}

but the environment generated:

\boxed{\texttt{45}}

Therefore the policy ratio is conceptually associated with model-generated decisions, not with the external environment's generated text.

This connects directly to the earlier engineering rule:

\boxed{ \text{mask interpreter tokens} }

from the ReTool deck. (Source: retool-slides)

5.21.25 Full miniature trajectory

Consider:

Question:
Find the valid value of x.

Model:
I should search the candidate space.

Model:
<code>
for x in range(1,1000):
    ...
</code>

Environment:
<interpreter>
699
</interpreter>

Model:
The interpreter found 699.

Model:
\boxed{699}

Policy-generated sequence:

\boxed{ \text{reasoning} + \text{code} + \text{final answer} }

Environment-generated sequence:

\boxed{ \text{699} }

Final reward:

R=+1.

Now PPO computes advantages over the relevant model-generated positions and updates the policy so useful behavior becomes more likely.

5.21.26 Full mathematical pipeline

Here is the entire calculation:

Step 1 — sample trajectory
\tau\sim\pi_{\text{old}}
Step 2 — execute tool calls
\text{code} \rightarrow \text{sandbox} \rightarrow \text{feedback}
Step 3 — obtain final reward
R(\tau)\in\{-1,+1\}
Step 4 — value prediction
V_\phi(s_t)
Step 5 — advantage

Conceptually:

\hat A_t \approx \text{return}-V_\phi(s_t)
Step 6 — policy ratio
r_t= \frac{\pi_\theta(o_t|s_t)} {\pi_{\text{old}}(o_t|s_t)}
Step 7 — clipping
\tilde r_t = \operatorname{clip} (r_t,1-\epsilon,1+\epsilon)
Step 8 — PPO objective
\boxed{ \min(r_tA_t,\tilde r_tA_t) }
Step 9 — gradient update
\theta \leftarrow \theta+\eta\nabla_\theta J_{\text{PPO}}

That is the complete policy-update pipeline at the conceptual level. (Source: retool-slides; Build a DeepSeek Model (From Scratch))

5.21.27 Why ReTool does NOT use GRPO here

Now compare the advantage calculation.

PPO

\boxed{ \hat A_t \approx R_t-V_\phi(s_t) }

Requires:

\boxed{ \text{learned value function} }

GRPO

Uses a group of responses:

r_1,r_2,\ldots,r_G

and constructs group-relative advantages.

For example:

A_i= \frac{r_i-\mu_r}{\sigma_r}.

No value model is required.

The supplied sources make exactly this distinction: GRPO replaces the learned value-model path with group-relative normalization.

5.21.28 Why this distinction matters computationally

PPO:

\boxed{ \text{policy model} + \text{value model} }

GRPO:

\boxed{ \text{policy model} + \text{multiple sampled responses} }

The value model can be expensive for large LLM systems.

GRPO was attractive in DeepSeekMath and DeepSeek-R1 partly because it eliminates that separate learned value model. (Source: Build a Reasoning Model (From Scratch))

ReTool nevertheless uses PPO according to the supplied deck.

5.21.29 Full numerical PPO example

Now let's perform one complete calculation.

Suppose at one model-generated token:

\pi_{\text{old}}(o_t|s_t)=0.20

and after the update candidate:

\pi_{\theta}(o_t|s_t)=0.24.

Then:

r_t= \frac{0.24}{0.20} = \boxed{1.2}.

Suppose:

V_\phi(s_t)=0.3

and final reward:

R=1.

Then simple advantage estimate:

A_t=1-0.3 = \boxed{0.7}.

Set:

\epsilon=0.2.

Then:

\operatorname{clip}(1.2,0.8,1.2)=1.2.

Raw:

1.2(0.7)=0.84.

Clipped:

1.2(0.7)=0.84.

Therefore:

\boxed{ J_t=0.84 }

No clipping penalty occurs because the ratio is exactly at the upper boundary.

5.21.30 Now push beyond the boundary

Suppose instead:

\pi_\theta=0.30.

Then:

r_t=\frac{0.30}{0.20}=1.5.

Advantage:

A_t=0.7.

Raw:

1.5(0.7)=1.05.

Clipped:

1.2(0.7)=0.84.

PPO chooses:

\boxed{ \min(1.05,0.84)=0.84 }

So increasing the probability from 0.20 all the way to 0.30 does not receive unlimited optimization credit.

5.21.31 One very important interpretation

PPO clipping does not literally force:

r_t\in[0.8,1.2].

The new policy can have a ratio outside the interval.

Instead, the objective stops rewarding the excessive movement in the favorable direction.

This is a subtle but highly important exam/interview point.

5.21.32 Why this is valuable for ReTool

Imagine that one successful trajectory contained:

call code
→ get result
→ use result
→ answer correctly

Without clipping, PPO might aggressively increase the probability of all those actions.

With clipping:

\boxed{ \text{successful strategy} \rightarrow \text{reinforced gradually} }

rather than:

\boxed{ \text{successful rollout} \rightarrow \text{huge policy jump} }.

5.21.34 Numerical bank — Level 5 exam question

Consider:

\pi_{\text{old}}=0.08
\pi_\theta=0.16
V_\phi(s_t)=0.25
R=1
\epsilon=0.2.

Calculate the clipped PPO term.

Step 1
r_t=\frac{0.16}{0.08}=2.
Step 2
A_t=1-0.25=0.75.
Step 3

Clip:

\operatorname{clip}(2,0.8,1.2)=1.2.
Step 4

Raw:

2(0.75)=1.5.

Clipped:

1.2(0.75)=0.9.
Step 5
\boxed{ \min(1.5,0.9)=0.9 }

So the PPO objective contribution is:

\boxed{0.9}.

5.21.35 One more exam question: negative advantage

Suppose:

\pi_{\text{old}}=0.20,
\pi_\theta=0.10,
A_t=-1.

Then:

r_t=0.5.

For:

\epsilon=0.2,

we get:

\operatorname{clip}(0.5,0.8,1.2)=0.8.

Raw:

0.5(-1)=-0.5.

Clipped:

0.8(-1)=-0.8.

Therefore:

\boxed{ \min(-0.5,-0.8)=-0.8 }

This demonstrates how PPO treats large probability movement associated with a negative advantage.

5.21.36 The five things you must remember

\boxed{1.\quad r_t= \frac{\pi_\theta}{\pi_{\text{old}}}}

Measures how much the new policy changed the probability of the sampled action.

\boxed{2.\quad A_t}

Measures whether the action/outcome was better or worse than expected.

\boxed{3.\quad V_\phi(s_t)}

Provides PPO's learned baseline for estimating advantage.

\boxed{4.\quad \operatorname{clip}}

Prevents one update from receiving excessive incentive for moving too far.

\boxed{5.\quad \text{ReTool's special part}}

The state/trajectory contains:

\boxed{ \text{reasoning + code + real interpreter feedback} }

rather than text alone. (Source: retool-slides)
