Step 5.7 — The Full GRPO Training Algorithm

Plan node: I6 · chat order #48

We have now learned every individual component:

\boxed{ \text{rollout} \rightarrow \text{reward} \rightarrow \text{advantage} \rightarrow \text{logprob} \rightarrow \text{ratio} \rightarrow \text{clipping} \rightarrow \text{KL} }

Now we put them together into one training iteration.

The source first implements a simplified Chapter 6 version, then adds clipped ratios and KL regularization in Chapter 7. The final conceptual pipeline is exactly this assembly. (Source: Build a Reasoning Model (From Scratch))

1. Before GRPO starts

We begin with a pretrained language model:

\boxed{\pi_\theta}

and a training set containing prompts and verifiable answers.

For example:

Prompt:
Half the value of 3x - 9 is x + 37. Find x.

Ground truth:

x=83.

The model starts with parameters:

\theta_0.

The goal is to obtain:

\theta_1,\theta_2,\ldots

such that the model increasingly produces high-reward reasoning behavior.

The source's training loop begins with a pretrained model and a MATH training subset. (Source: Build a Reasoning Model (From Scratch))

2. Stage 1 — Choose a prompt

At training step k, select:

q_k.

For simplicity, suppose:

q_k=q.

The important point is that multiple responses will be sampled for this same prompt.

3. Stage 2 — Generate a group of rollouts

Use the current/rollout policy to generate:

G

responses:

o_1,o_2,\ldots,o_G.

Mathematically:

\boxed{ o_i\sim\pi_{\theta_{\text{old}}}(\cdot\mid q) }

for:

i=1,\ldots,G.

For example:

o1 = \boxed{83}
o2 = The correct answer is \boxed{83}
o3 = The final answer is 83
o4 = We get \boxed{38}

The source uses exactly this type of four-rollout example. (Source: Build a Reasoning Model (From Scratch))

4. Why do we sample instead of using argmax?

This is essential.

If the model always chooses:

\arg\max_y \pi_\theta(y\mid q),

then every attempt could be nearly identical.

GRPO needs variation.

We want:

o_1\neq o_2\neq\cdots

often enough that the model has different strategies to compare.

So sampling provides the exploration that creates the group-relative learning signal.

5. Stage 3 — Verify each rollout

The verifier calculates:

R_i=R(q,o_i).

For the source's math verifier:

R_i= \begin{cases} 1 & \text{correct and required format}\\ 0 & \text{otherwise}. \end{cases}

So:

R=[1,1,0,0].

The source explicitly computes rewards this way. (Source: Build a Reasoning Model (From Scratch))

6. Stage 4 — Compute group-relative advantages

Calculate:

\mu_R=\frac1G\sum_{i=1}^{G}R_i.

For:

[1,1,0,0],

we have:

\mu_R=0.5.

Then:

\sigma_R\approx0.577.

Therefore:

\boxed{ A_i= \frac{R_i-\mu_R} {\sigma_R+\epsilon} }

giving:

\boxed{ A=[0.8659,0.8659,-0.8659,-0.8659]. }

This is the group-relative learning signal. (Source: Build a Reasoning Model (From Scratch))

7. What information exists after this stage?

We now know:

\boxed{ A_i>0 }

for successful relative-to-group responses.

And:

\boxed{ A_i<0 }

for unsuccessful relative-to-group responses.

But we still haven't told the optimizer how much probability the model currently assigns to each response.

That is the next stage.

8. Stage 5 — Compute current-policy log probabilities

For each rollout:

o_i=(y_1,\ldots,y_T),

calculate:

\log\pi_\theta(o_i\mid q).

Because the response is autoregressive:

\boxed{ \log\pi_\theta(o_i\mid q) = \sum_t \log\pi_\theta(y_t\mid q,y_{<t}) }

The source implements this by selecting the log probability of each generated answer token and summing over the answer positions. (Source: Build a Reasoning Model (From Scratch))

9. Why do prompt tokens not receive the policy loss?

Suppose:

[prompt tokens][answer tokens]

We do not want to train the model to reproduce the prompt.

We want the policy gradient to act on:

\boxed{\text{generated response tokens}}

So the sequence-logprob computation begins at the response portion.

The source's code uses:

\texttt{prompt\_len - 1}

as the starting offset for selected answer log probabilities. (Source: Build a Reasoning Model (From Scratch))

10. Stage 6 — Save old-policy log probabilities

We also need:

\boxed{ \log\pi_{\text{old}}(o_i\mid q) }

for the same generated response.

Why?

Because after the model starts updating, the probability of the response changes.

We need to compare:

\text{before update}

against:

\text{current}.

So:

\boxed{ \log p_{\text{old}} }

acts as our baseline for measuring policy movement.

The source explicitly describes storing/using old log probabilities for fixed rollouts before comparing them with the changing policy. (Source: Build a Reasoning Model (From Scratch))

11. Stage 7 — Compute the policy ratio

For each rollout:

\boxed{ r_i = \frac{ \pi_\theta(o_i\mid q) }{ \pi_{\text{old}}(o_i\mid q) } }

or in log space:

\boxed{ r_i = \exp( \log p_{\text{new},i} - \log p_{\text{old},i} ) }

This tells us how much the policy has changed its probability for that sampled behavior.

The source uses this exact log-difference/exponential implementation. (Source: Build a Reasoning Model (From Scratch))

12. Interpret the ratio

r_i=1

means:

\boxed{\text{no change}}
r_i>1

means:

\boxed{\text{current policy favors this rollout more}}
r_i<1

means:

\boxed{\text{current policy favors it less}}

So ratio is fundamentally a policy movement measurement.

13. Stage 8 — Clip the ratio

Now define:

\boxed{ \tilde r_i = \operatorname{clip} (r_i,1-\epsilon_c,1+\epsilon_c) }

where \epsilon_c is the clipping parameter.

The clipping bounds individual update influence.

The source's example uses:

\epsilon_c=10

for its DeepSeek-R1 illustration, giving an upper limit:

1+\epsilon_c=11.

(Source: Build a Reasoning Model (From Scratch))

14. Why clipping belongs here

We already have:

A_i.

Suppose:

A_i=1.

This is a good rollout.

Now suppose the ratio becomes:

r_i=100.

Without clipping:

r_iA_i=100.

A single sample could dominate the update.

With clipping:

r_i\rightarrow11

in the source-specific example.

Thus:

100 \rightarrow 11.

The rollout still has positive influence, but it cannot explode arbitrarily.

15. Stage 9 — Build the clipped policy objective

For every rollout:

u_i=r_iA_i

and:

c_i=\tilde r_iA_i.

Take:

\boxed{ m_i=\min(u_i,c_i) }

and average:

\boxed{ L_{\text{clip}} = -\frac1G\sum_i m_i }

This is the source's implementation:

unclipped = ratio * adv
clipped = clipped_ratio * adv
obj = torch.minimum(unclipped, clipped)
clipped_pg_loss = -torch.mean(obj)

(Source: Build a Reasoning Model (From Scratch))

16. Why is the objective negative?

We want to maximize:

\mathbb E[m_i].

But the PyTorch optimizer minimizes losses.

Therefore:

\boxed{ L=-\text{objective}. }

This sign-flip principle was already used in the simplified Chapter 6 policy-gradient objective. (Source: Build a Reasoning Model (From Scratch))

17. Stage 10 — Compute reference-policy KL regularization

Now introduce the frozen reference policy:

\boxed{\pi_{\text{ref}}}.

Compute:

\log p_{\text{ref},i}.

The source's simplified KL implementation uses:

\boxed{ L_{\text{KL}} = \beta \operatorname{mean} ( \log p_{\text{new}} - \log p_{\text{ref}} ) }

where:

\beta=\text{kl\_coeff}.

(Source: Build a Reasoning Model (From Scratch))

18. What is the reference model doing?

Imagine the original model knows how to produce ordinary fluent language.

RL starts changing it to improve mathematical reward.

We want:

\boxed{ \text{better mathematical behavior} }

but not:

\boxed{ \text{destroy general behavior while chasing reward} }

The reference model is therefore an anchor.

The source describes it as constraining the policy so that reward improvement does not cause excessive divergence from the original behavior. (Source: Build a Reasoning Model (From Scratch))

19. Stage 11 — Combine the objectives

Now:

\boxed{ L_{\text{total}} = L_{\text{clip}} + L_{\text{KL}} }

In the source's simplified KL extension:

-2.5764 + (-0.0075) = \boxed{-2.5839}.

(Source: Build a Reasoning Model (From Scratch))

20. Stage 12 — Backpropagation

Now we have one scalar:

L_{\text{total}}.

We calculate:

\boxed{ \nabla_\theta L_{\text{total}} }

using backpropagation.

The reward itself is not differentiated.

Instead:

\boxed{ A_i=\text{fixed learning signal} }

and gradients flow through the model's log probabilities.

The source explicitly uses .detach() on advantages for this reason. (Source: Build a Reasoning Model (From Scratch))

21. Stage 13 — Gradient clipping

The source's training loop also applies:

torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)

after the backward pass. (Source: Build a Reasoning Model (From Scratch))

This is different from policy-ratio clipping.

Do not confuse:

\boxed{\text{policy-ratio clipping}}

with:

\boxed{\text{gradient-norm clipping}}.
Policy-ratio clipping

Controls:

\boxed{\text{how much the policy objective can change}}
Gradient clipping

Controls:

\boxed{\text{the magnitude of the computed parameter gradient}}

They operate at different points in the pipeline.

22. Stage 14 — Optimizer update

After gradient clipping:

\boxed{ \theta \leftarrow \theta-\eta\nabla_\theta L }

The source uses AdamW in its training loop. (Source: Build a Reasoning Model (From Scratch))

Now the policy has changed.

That finishes one training step.

23. Stage 15 — Log metrics

The source tracks:

\boxed{\text{average reward}}

and:

\boxed{\text{average response length}}

along with loss values. (Source: Build a Reasoning Model (From Scratch))

Why?

Because loss alone is not enough to understand RL training.

You want to know:

Is reward actually improving?

Are answers becoming abnormally long?

Is training becoming unstable?

24. Stage 16 — Save checkpoints

The training loop periodically saves model checkpoints.

The source's example uses:

\boxed{\text{checkpoint\_every}=50}

by default in the function signature. (Source: Build a Reasoning Model (From Scratch))

This allows later evaluation of the policy at different stages of training.

25. Complete algorithm in pseudocode

Now write the whole algorithm as one thing:

for each training step:

    q = sample_prompt()

    # 1. Generate multiple responses
    rollouts = sample_G_responses(policy, q)

    # 2. Verify
    rewards = [verify(q, o) for o in rollouts]

    # 3. Group-relative advantages
    advantages = normalize_within_group(rewards)

    # 4. Current-policy logprobs
    new_logps = score(policy, q, rollouts)

    # 5. Old-policy logprobs
    old_logps = stored_rollout_logprobs

    # 6. Policy ratio
    ratio = exp(new_logps - old_logps)

    # 7. Clip
    clipped_ratio = clip(ratio, 1-eps, 1+eps)

    # 8. Clipped policy objective
    objective = minimum(
        ratio * advantages,
        clipped_ratio * advantages
    )

    # 9. Reference-policy regularization
    ref_logps = score(reference_model, q, rollouts)
    kl_loss = beta * mean(new_logps - ref_logps)

    # 10. Total loss
    loss = -mean(objective) + kl_loss

    # 11. Optimize
    loss.backward()
    clip_grad_norm(...)
    optimizer.step()

This mirrors the source's progressive Chapter 6 + Chapter 7 implementation. (Source: Build a Reasoning Model (From Scratch))

27. A subtle issue: where does “old policy” come from?

There are multiple implementation arrangements.

The source's large-scale description says:

  1. make a copy of the current model;
  2. generate the rollout pool from it;
  3. calculate old logprobs under that fixed version;
  4. update the current model;
  5. later refresh the reference model.

(Source: Build a Reasoning Model (From Scratch))

Therefore:

\boxed{ \text{old policy must remain fixed while the corresponding update is evaluated} }

Otherwise the ratio would not represent a meaningful before-vs-after comparison.

28. A subtle issue: old policy versus reference policy

Now put them side by side:

Model Question it answers
\pi_{\text{old}} How likely was this rollout when it was generated?
\pi_\theta How likely does the current policy consider it now?
\pi_{\text{ref}} How far have we drifted from the long-term reference?

Therefore:

\boxed{ \text{old} \rightarrow \text{ratio} }
\boxed{ \text{reference} \rightarrow \text{KL} }

This is one of the easiest places to make an interview mistake.

29. Full numerical training step

Let's build one compact example.

Suppose:

R=[1,1,0,0]

and therefore:

A=[0.866,0.866,-0.866,-0.866].

Suppose old logprobs are:

[-10,-9,-12,-11].

Current logprobs:

[-9,-8.8,-12.5,-11].

Rollout 1

\log r=-9-(-10)=1

so:

r=e^1=2.718.

With \epsilon=0.2:

r_{\text{clip}}=1.2.

Advantage:

A=0.866.

Unclipped:

2.718(0.866) \approx2.354.

Clipped:

1.2(0.866) \approx1.039.

Thus:

\min(2.354,1.039) = \boxed{1.039}.

30. Rollout 2

\log r=-8.8-(-9)=0.2.

Thus:

r=e^{0.2} \approx1.221.

This is already inside the clipping range.

Therefore:

r_{\text{clip}}=1.2

with \epsilon=0.2.

Then:

1.221(0.866)\approx1.057

and:

1.2(0.866)\approx1.039.

Thus:

\boxed{1.039}.

31. Rollout 3

\log r=-12.5-(-12)=-0.5.

Therefore:

r=e^{-0.5} \approx0.607.

Since:

0.607<0.8,

it gets clipped:

r_{\text{clip}}=0.8.

Advantage:

A=-0.866.

Unclipped:

0.607(-0.866)\approx-0.526.

Clipped:

0.8(-0.866)\approx-0.693.

Take minimum:

\boxed{-0.693}.

32. Rollout 4

\log r=-11-(-11)=0.

Therefore:

r=1.

No clipping.

Advantage:

A=-0.866.

Contribution:

1(-0.866) = \boxed{-0.866}.

33. Compute the clipped loss

Our objective terms are approximately:

[1.039,\;1.039,\;-0.693,\;-0.866].

Average:

\frac{1.039+1.039-0.693-0.866}{4} \approx0.130.

Therefore:

\boxed{ L_{\text{clip}}\approx-0.130 }

Then we would add the reference-policy KL term.

This is the pattern you need to reproduce in an exam.

34. What if clipping did not exist?

The first rollout would contribute:

2.354

instead of:

1.039.

Thus one response gets disproportionately strong influence.

That is precisely what the clipping mechanism is designed to prevent. The source reports more stable training when clipped ratios are used. (Source: Build a Reasoning Model (From Scratch))

35. What if KL did not exist?

Each training update could still be locally controlled by clipping.

But across many updates:

\theta_0 \rightarrow \theta_1 \rightarrow \theta_2 \rightarrow \cdots

the policy could drift substantially from the original reference.

That is why:

\boxed{\text{clipping and KL solve different stability problems}}

(Source: Build a Reasoning Model (From Scratch))

36. Why reward alone can be misleading

Suppose average reward rises:

0.2\rightarrow0.4\rightarrow0.7.

That sounds good.

But suppose simultaneously response length becomes:

200\rightarrow500\rightarrow2000.

The model may be finding increasingly long strategies that exploit the reward structure.

Therefore the source also tracks response length and other metrics. (Source: Build a Reasoning Model (From Scratch))

37. Advantage statistics

Chapter 7 additionally tracks:

\boxed{\text{advantage mean}}

and:

\boxed{\text{advantage standard deviation}}.

The source notes that these are useful for understanding training dynamics beyond their role in the actual loss. (Source: Build a Reasoning Model (From Scratch))

For normalized advantages, the mean should be around zero within a group.

If you see surprising behavior, these statistics help diagnose it.

38. Entropy

Another diagnostic is:

\boxed{ H(P)=-\sum_i P_i\log P_i }

Entropy measures uncertainty in the token distribution.

The source uses it to monitor whether the model remains exploratory or becomes excessively deterministic. (Source: Build a Reasoning Model (From Scratch))

Roughly:

\text{high entropy} \rightarrow \text{many plausible next tokens}
\text{low entropy} \rightarrow \text{one/few tokens dominate}.

39. Why entropy matters in RL

Imagine the model starts producing one token with near certainty at every position.

Then:

P_{\max}\rightarrow1

and:

H\rightarrow0.

The model may have become too deterministic too quickly.

The source treats sudden collapse to very low entropy as a warning sign of unstable training. (Source: Build a Reasoning Model (From Scratch))

40. The three most useful training diagnostics

For this stage, remember:

\boxed{\text{reward}}

tells you whether the model is improving at the verified task.

\boxed{\text{response length}}

helps identify undesirable output-length behavior.

\boxed{\text{entropy}}

helps identify confidence/exploration collapse.

The source tracks these alongside loss and evaluation performance. (Source: Build a Reasoning Model (From Scratch))

41. Very important source observation: reward can improve but accuracy can later decline

The source's motivation for stabilization comes from actual training behavior: unclipped or less-stable runs can experience reward/accuracy degradation, whereas clipped policy ratios gave a more stable run in the reported example. (Source: Build a Reasoning Model (From Scratch))

So:

\boxed{ \text{higher training reward} \neq \text{guaranteed better generalization} }

This is a general RL lesson.

42. Another important source observation: all-zero rewards

Suppose:

R=[0,0,0,0].

Then:

A=[0,0,0,0].

Therefore:

L_{\text{PG}}=0.

The source explicitly points out that the model should not reinforce an arbitrary wrong behavior when all sampled attempts fail. (Source: Build a Reasoning Model (From Scratch))

43. Another important case: all-one rewards

Suppose:

R=[1,1,1,1].

Again:

A=[0,0,0,0].

The group provides no relative distinction.

Thus:

\boxed{\text{no update from this group's relative signal}}

because every sampled answer was equally successful.

44. Full training-loop architecture

Now we can distinguish one GRPO step from many GRPO steps.

One step
q \rightarrow G\text{ rollouts} \rightarrow R \rightarrow A \rightarrow \text{policy loss} \rightarrow \theta'
Repeated training
\theta_0 \rightarrow \theta_1 \rightarrow \theta_2 \rightarrow \theta_3 \rightarrow \cdots

with new prompts and new sampled rollouts at each iteration.

That repeated loop is what actually produces learning.

The source's training function wraps the GRPO loss computation inside a standard PyTorch optimization loop. (Source: Build a Reasoning Model (From Scratch))

45. The complete stack you have now learned

We can now build the whole hierarchy:

\boxed{ \text{Transformer} }

gives us:

P_\theta(y_t\mid y_{<t}).

Then:

\boxed{ \text{sampling} }

gives us diverse responses.

Then:

\boxed{ \text{RLVR} }

gives us a verifier-defined reward.

Then:

\boxed{ \text{GRPO} }

turns group rewards into policy updates.

Then:

\boxed{ \text{clipping + KL} }

make those updates more controlled and stable.

46. Master equation for this entire step

At the highest level:

\boxed{ \theta_{k+1} = \theta_k - \eta \nabla_\theta \left[ L_{\text{clip}} + L_{\text{KL}} \right] }

where:

L_{\text{clip}} = - \mathbb E \left[ \min \left( rA, \operatorname{clip}(r,1-\epsilon,1+\epsilon)A \right) \right]

and:

A= \frac{R-\mu_R} {\sigma_R+\epsilon_a}.

The source's implementation progressively constructs precisely these pieces. (Source: Build a Reasoning Model (From Scratch))

53. Interview question you should now be able to answer

“Explain GRPO in 60 seconds.”

A strong answer is:

GRPO is a policy-optimization method introduced in DeepSeekMath and later used in DeepSeek-style reasoning training. For each prompt, the current policy samples multiple responses. A verifier assigns rewards, and the rewards are normalized within the group to produce relative advantages. The policy then increases the probability of positively advantaged responses and decreases the probability of negatively advantaged responses. A clipped policy ratio limits how much the current policy can move relative to the rollout policy, while a KL regularization term constrains longer-term drift from a reference policy. Unlike PPO, GRPO does not require a separate learned value model. (Source: Build a Reasoning Model (From Scratch))
