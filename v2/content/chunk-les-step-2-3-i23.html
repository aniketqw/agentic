Continuation · checked fixture D03 — Top-k support and renormalization

Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

Restrict random draws to a fixed number of high-probability tokens.

Prerequisites: Stable softmax and log-softmax

Notation and assumptions

k positive integer ≤vocabulary size. Exact-k with ID tie break; threshold-based APIs may retain ties beyond k.

Derivation and mechanism

  1. Sort probabilities or logits by descending score.
  2. Keep k indices.
  3. Divide retained probabilities by their actual retained mass.
p_i^{new}=p_i\mathbf1_{i\in S}/\sum_{j\in S}p_j

Worked example

p=[.5,.3,.15,.05],k2 retains IDs0,1, mass.8; new p=[.625,.375,0,0]. The sampler cannot choose the discarded tokens.

Limitations

  • k0 is rejected here; some libraries use0 to disable filtering.
  • Tie conventions must be recorded when comparing implementations.

Connections to later concepts

  • D04 and D05 retain variable-size supports; D10 explains why the order of these filters is part of the algorithm.

Step 2.3 — Top-k Sampling

Plan node: I2 · chat order #23

We have just learned temperature:

\boxed{ q_i(T)= \frac{e^{z_i/T}}{\sum_j e^{z_j/T}} }

Temperature changes how concentrated the distribution is.

But temperature does not remove extremely unlikely vocabulary tokens.

That leads to:

\boxed{\text{Top-k sampling}}

The idea from your source is simple:

Keep only the k tokens with the highest logits, suppress all other tokens, and then apply softmax so the remaining tokens form a new probability distribution. (Source: Build a Large Language Model (From Scratch))

This is especially important for exam numericals because the question can give you either probabilities or logits, and you must know exactly what to do in each case.

2.3.1 Why Do We Need Top-k?

Suppose the model has a vocabulary of:

V=50,000.

Imagine its next-token probabilities look roughly like:

[0.40,\;0.25,\;0.15,\;0.07,\;0.04,\ldots]

with thousands of tiny probabilities such as:

0.000001.

Pure sampling technically allows those extremely unlikely tokens.

That can create bizarre outputs, particularly when using a high temperature.

Your Raschka source explicitly describes this issue: temperature-based sampling can increase diversity, but high temperatures can also produce nonsensical tokens; top-k then restricts sampling to the most likely candidates. (Source: Build a Large Language Model (From Scratch))

So top-k introduces:

\boxed{ \text{diversity without allowing the whole low-probability tail}. }

2.3.2 What Does the "k" Mean?

If:

k=3,

we keep exactly:

\boxed{3}

tokens.

If:

k=10,

we keep:

\boxed{10}.

Everything else is removed from the sampling candidate set.

Thus:

\boxed{ k=\text{maximum number of candidate tokens retained}. }

2.3.3 Very Important: Top-k Works on Logits

Suppose the model produces:

z= [z_1,z_2,\ldots,z_V].

Find the k largest values.

Suppose:

z=[6,4,2,1,-1].

For:

k=2,

keep:

6,\;4.

Suppress:

2,\;1,\;-1.

In the source implementation, the suppressed logits are replaced with:

\boxed{-\infty}

before softmax. (Source: Build a Large Language Model (From Scratch))

2.3.4 Why -\infty?

Exactly the same trick we used for the causal mask.

We already learned:

e^{-\infty}=0.

Therefore:

\boxed{ -\infty \overset{\text{softmax}}{\longrightarrow} 0 }

So the discarded tokens receive:

\boxed{ P=0. }

This is a beautiful connection between two topics.

Causal attention

Use -\infty to forbid future positions.

Top-k decoding

Use -\infty to forbid low-ranked vocabulary tokens.

The mathematical mechanism is the same; only the reason for masking is different.

2.3.5 The Top-k Pipeline

The basic operation is:

\boxed{ z \rightarrow \text{find top }k \rightarrow \text{set others to }-\infty \rightarrow \text{softmax} \rightarrow \text{sample} }

If temperature is also used:

\boxed{ z \rightarrow \text{top-k filter} \rightarrow \text{temperature scaling} \rightarrow \text{softmax} \rightarrow \text{sample} }

This is the ordering used in the Raschka implementation. (Source: Build a Large Language Model (From Scratch))

2.3.6 Top-k With Probabilities — First Easy Example

Suppose the original probability distribution is:

Token Probability
A 0.40
B 0.25
C 0.15
D 0.10
E 0.06
F 0.04

Let:

k=3.

The top 3 are:

A,\;B,\;C.

So we remove:

D,\;E,\;F.

The retained probability mass is:

0.40+0.25+0.15 = \boxed{0.80}.

But probabilities must sum to 1.

Therefore we renormalize.

2.3.7 Renormalization

For every retained token:

\boxed{ P'_i=\frac{P_i}{\sum_{j\in TopK}P_j} }

Here the denominator is:

0.80.

Thus:

P'(A)=\frac{0.40}{0.80}=0.50
P'(B)=\frac{0.25}{0.80}=0.3125
P'(C)=\frac{0.15}{0.80}=0.1875.

Therefore:

\boxed{ P'= [0.50,\;0.3125,\;0.1875,\;0,\;0,\;0] }

This is exactly the basic top-k operation.

2.3.8 Why Must We Renormalize?

Suppose we simply zeroed the discarded tokens:

[0.40,0.25,0.15,0,0,0].

The total is:

0.80.

But a probability distribution requires:

\sum_i P_i=1.

Therefore the remaining probability mass must be stretched back to 1.

So:

\boxed{ \text{filter} \rightarrow \text{renormalize}. }

2.3.9 Logit Version of the Same Example

Suppose instead we were given logits:

z=[4,3,2,1,0,-1].

For:

k=3,

retain:

4,3,2.

Replace the others:

1,0,-1

with:

-\infty.

Therefore:

\boxed{ z'=[4,3,2,-\infty,-\infty,-\infty]. }

Then:

P=\operatorname{softmax}(z').

The probability automatically renormalizes over the retained three.

2.3.10 Notice Something Important

If we had first converted the original logits to probabilities, then selected the top 3 and renormalized, we would get the same result as masking the non-top-3 logits with -\infty and applying softmax afterward.

Why?

Because softmax preserves ranking.

And setting the non-selected logits to:

-\infty

makes their probability exactly zero.

So the preferred implementation is simply:

\boxed{ \text{top-k at logit level} \rightarrow \text{softmax}. }

2.3.11 Exact Source Example

Your Raschka source gives a real implementation example where:

k=3.

The top three logits are:

\boxed{ 6.7500,\quad6.2800,\quad4.5100 }

and their token positions are:

\boxed{ 3,\quad7,\quad0. }

The source then sets all logits below the smallest retained logit to:

-\infty

and applies softmax. (Source: Build a Large Language Model (From Scratch))

The resulting nonzero probabilities shown in the source are approximately:

\boxed{ 0.0615,\quad0.5775,\quad0.3610 }

for the three retained positions, with the other vocabulary entries at zero.

This is an excellent example because it demonstrates an important fact:

\boxed{ \text{the top-k logits do not need to be equally probable}. }

The largest retained logit gets the largest probability.

2.3.12 Let's Verify Those Probabilities

The retained logits are:

[6.75,6.28,4.51].

Compute:

e^{6.75}, \quad e^{6.28}, \quad e^{4.51}.

To avoid very large numbers, subtract the maximum:

[6.75,6.28,4.51]-6.75

giving:

[0,-0.47,-2.24].

Now:

e^0=1
e^{-0.47}\approx0.625
e^{-2.24}\approx0.1063.

Total:

1+0.625+0.1063 \approx1.7313.

Therefore:

P_1\approx\frac{1}{1.7313}\approx0.5776
P_2\approx\frac{0.625}{1.7313}\approx0.3610
P_3\approx\frac{0.1063}{1.7313}\approx0.0614.

So approximately:

\boxed{ [0.5775,\;0.3610,\;0.0615]. }

The source displays the same values distributed at their token positions. (Source: Build a Large Language Model (From Scratch))

2.3.13 Important Exam Insight: Top-k Changes the Probability Values

Before filtering, the three tokens had some probabilities.

After filtering:

\boxed{ \text{their probabilities increase because the removed probability mass is redistributed}. }

Suppose:

P(A)=0.40

before top-k.

If all tokens below C are removed and total retained mass is:

0.80,

then:

P'(A)=\frac{0.40}{0.80}=0.50.

So top-k does not merely "delete tokens."

It also changes the probabilities of the survivors.

2.3.14 Top-k vs Temperature

Now compare the two.

Temperature

z_i\rightarrow\frac{z_i}{T}

changes the relative sharpness.

But:

\boxed{ \text{all tokens remain candidates}. }

Top-k

\boxed{ \text{some tokens are completely removed}. }

So:

\boxed{ \text{Temperature = reshape} }
\boxed{ \text{Top-k = truncate/filter}. }

This distinction is extremely important.

2.3.15 Numerical Example — Same Logits, Different Operations

Take:

z=[4,3,1,0,-2].
Temperature only, T=2

Scaled logits:

[2,1,0.5,0,-1].

Every token remains possible.

Top-k only, k=2

Keep:

4,3.

So:

z'=[4,3,-\infty,-\infty,-\infty].

Only two tokens remain possible.

Temperature + top-k

Keep top 2 first:

[4,3,-\infty,-\infty,-\infty]

then divide by:

T=2:
[2,1,-\infty,-\infty,-\infty].

Then softmax.

So only two tokens can be sampled.

2.3.16 Does Temperature Affect Which Tokens Are in Top-k?

For:

T>0,

no.

Because dividing all logits by the same positive number preserves ranking.

If:

z_1>z_2>z_3,

then:

\frac{z_1}{T}> \frac{z_2}{T}> \frac{z_3}{T}.

Therefore:

\boxed{ TopK(z)=TopK(z/T) }

for positive T.

This means top-k membership is unchanged by ordinary positive temperature scaling.

2.3.17 But Temperature Still Changes Top-k Probabilities

Suppose top 3 are fixed.

Temperature can change:

[0.60,0.30,0.10]

to:

[0.80,0.15,0.05]

or:

[0.45,0.35,0.20].

So:

\boxed{ \text{candidate set fixed} }

but:

\boxed{ \text{probability allocation changes}. }

2.3.18 Why Is Top-k Useful at High Temperature?

Suppose:

T=2.

The distribution may become relatively flat.

That gives many unlikely tokens a nontrivial sampling chance.

Top-k then says:

"I want some randomness, but only among the strongest candidates."

So the combined idea is:

\boxed{ \text{temperature for diversity} + \text{top-k for safety/relevance}. }

This is precisely the rationale given in your source. (Source: Build a Large Language Model (From Scratch))

2.3.19 Numerical Example — Top-k After Temperature

Suppose:

z=[5,4,2,1,0].

Take:

T=2.

Then:

z/T=[2.5,2,1,0.5,0].

Now use:

k=3.

Top 3 are still:

2.5,2,1.

So:

z'=[2.5,2,1,-\infty,-\infty].

Softmax:

e^{2.5}\approx12.182
e^2\approx7.389
e^1\approx2.718.

Total:

12.182+7.389+2.718 = 22.289.

Therefore:

P_1\approx0.5467
P_2\approx0.3315
P_3\approx0.1220.

So:

\boxed{ P\approx[0.5467,0.3315,0.1220,0,0]. }

2.3.20 The Same Example Without Top-k

Using:

z/T=[2.5,2,1,0.5,0],

all five tokens would remain possible.

Their probabilities would be:

P_1= \frac{12.182}{12.182+7.389+2.718+1.649+1} \approx0.490.

So top-k increased the top token from approximately:

0.490

to:

0.547.

Why?

Because the tail probability mass was removed and redistributed.

2.3.21 Top-k as a Candidate-Set Operation

It is useful to define:

S_k(z)

as the set of indices corresponding to the k largest logits.

Then:

z_i'= \begin{cases} z_i,&i\in S_k(z)\\ -\infty,&i\notin S_k(z). \end{cases}

Then:

\boxed{ p_i' = \frac{e^{z_i'}} {\sum_j e^{z_j'}} }

and therefore:

p_i'=0

for:

i\notin S_k(z).

That is the mathematical definition of top-k filtering.

2.3.22 Numerical Question — Ties

Suppose:

z=[5,5,4,3].

and:

k=2.

The top 2 values are:

5,5.

So both tied top tokens are retained.

This is straightforward.

More complicated tie handling depends on implementation details, but an exam question will normally specify enough information.

2.3.23 Numerical Question — k=1

Suppose:

z=[4,2,1,-3].

Take:

k=1.

Then:

z'=[4,-\infty,-\infty,-\infty].

Softmax:

\boxed{ [1,0,0,0]. }

Therefore:

\boxed{ Top\text{-}1\text{ sampling becomes greedy selection}. }

This is a very important relationship.

2.3.24 Top-1, Top-k, and No Filtering

We can now see a spectrum.

Top-1
\boxed{\text{one candidate}}

→ deterministic selection.

Top-k
\boxed{k\text{ candidates}}

→ sampling among a fixed-sized shortlist.

No top-k
\boxed{V\text{ candidates}}

→ sampling from the entire vocabulary.

2.3.25 Does Top-k Itself Make Generation Deterministic?

No.

Suppose:

k=3

and after filtering:

P=[0.5,0.3,0.2].

There are still three possible outcomes.

So:

\boxed{ \text{Top-k + sampling = stochastic}. }

Only:

k=1

reduces the candidate set to one token and therefore makes the selection deterministic.

2.3.26 Important Distinction: Filtering vs Sampling

Top-k does not choose the final token by itself.

It only changes the candidate distribution.

The complete process is:

z \rightarrow top-k \rightarrow p \rightarrow sample.

So top-k is a filtering mechanism.

Sampling is the selection mechanism.

2.3.27 PyTorch Implementation From the Source

Raschka's implementation follows this conceptual pattern:

top_logits, _ = torch.topk(
    logits,
    k
)

min_val = top_logits[:, -1]

logits = torch.where(
    logits < min_val,
    torch.tensor(float("-inf")).to(logits.device),
    logits
)

Then:

probs = torch.softmax(logits, dim=-1)

and:

next_token = torch.multinomial(
    probs,
    num_samples=1
)

(Source: Build a Large Language Model (From Scratch))

Now understand the logic.

2.3.28 What Does torch.topk Return?

Suppose:

logits = [2.5, 5.0, 1.0, 4.0]

and:

k=2.

torch.topk conceptually returns:

values = [5.0, 4.0]
positions = [1, 3]

So:

\boxed{ \text{top logits}=[5,4] }

and:

\boxed{ \text{top positions}=[1,3]. }

The source example similarly shows top logits and their token positions. (Source: Build a Large Language Model (From Scratch))

2.3.29 Why Is the Smallest Retained Logit Important?

Suppose the top 3 logits are:

[6.75,6.28,4.51].

The smallest of these is:

4.51.

So every logit less than:

4.51

is discarded.

That gives us a convenient threshold:

\boxed{ z_i<z_{(k)} \Rightarrow z_i=-\infty. }

Here:

z_{(k)}

means the k-th largest logit.

2.3.30 Numerical — Find the Top-k Threshold

Suppose:

z=[7,2,9,4,6,1].

Set:

k=3.

Sort descending:

9,\;7,\;6,\;4,\;2,\;1.

Therefore:

z_{(3)}=6.

So retain logits:

9,7,6.

Discard:

4,2,1.

Thus:

\boxed{ z'=[7,-\infty,9,-\infty,6,-\infty]. }

2.3.31 Numerical — Top-k From Raw Logits

Suppose:

z=[1.5,4.0,-1,3.0,2.0].

Take:

k=2.

Top values:

4.0,\;3.0.

Therefore:

\boxed{ z'=[-\infty,4,-\infty,3,-\infty]. }

Now softmax over:

[4,3].

We have:

e^4\approx54.598
e^3\approx20.086.

Total:

74.684.

Therefore:

P(4)=\frac{54.598}{74.684} \approx0.7311

and:

P(3)=\frac{20.086}{74.684} \approx0.2689.

Thus the final distribution is:

\boxed{ [0,0.7311,0,0.2689,0]. }

2.3.32 Notice the Difference Between Logit Gap and Probability

The two surviving logits were:

4,\;3.

Difference:

1.

The resulting probability ratio is:

\frac{P_1}{P_2} = \frac{e^4}{e^3} = e \approx2.718.

So a logit difference of 1 corresponds to a probability ratio of approximately:

\boxed{2.718:1}

when only those two candidates remain.

This is a useful numerical insight for understanding softmax.

2.3.34 What If Temperature Were T=0.5?

Same original logits:

[6,4].

Scale:

[12,8].

Subtract 12 for numerical stability:

[0,-4].

Then:

The candidate set is identical because top-k is unchanged, but the sampling probabilities are dramatically different.

2.3.36 Why Fixed k Can Be a Limitation

Suppose the model distribution is very concentrated:

[0.95,0.03,0.01,0.01,\ldots].

Using:

k=3

keeps three tokens.

But suppose instead the model is uncertain:

[0.12,0.11,0.10,0.09,0.08,0.07,\ldots].

A fixed:

k=3

keeps only:

0.12,0.11,0.10

and removes many plausible alternatives.

So the same k can be:

  • too wide for a highly confident distribution,
  • too narrow for a flat distribution.

This is precisely the motivation for the next method:

\boxed{\text{Top-p / nucleus sampling}}

where the number of retained tokens can vary based on cumulative probability mass.

Your decoding slides explicitly contrast fixed top-k with top-p's adaptive shortlist size. (Source: decoding-sampling-slides)

2.3.37 Top-k vs Top-p Preview

Top-k

"Keep exactly k tokens."

\boxed{|S|=k}
Top-p

"Keep the smallest set whose cumulative probability exceeds p."

\boxed{|S|\text{ varies}.}

This is the conceptual difference we will derive next.

2.3.38 Important Connection to Causal Attention

Notice how the same mathematical trick has now appeared twice.

Causal attention
S_{ij}\rightarrow-\infty

for future positions.

Then:

softmax\rightarrow0.
Top-k
z_i\rightarrow-\infty

for low-ranked vocabulary tokens.

Then:

softmax\rightarrow0.

So we can write:

\boxed{ -\infty+\operatorname{softmax} = \text{hard exclusion}. }

This is a very useful pattern to recognize in both exams and code.

2.3.39 A Subtle Point: Top-k Does Not Change the Surviving Logit Values

Suppose:

z=[5,4,1,-2].

with:

k=2.

After top-k:

[5,4,-\infty,-\infty].

The surviving logits are still:

5,\;4.

Top-k does not normalize them.

Softmax does that later.

So:

\boxed{ \text{filtering}\neq\text{normalization}. }

2.3.40 Another Exam Trap

Suppose:

P=[0.5,0.3,0.2]

and:

k=2.

A student may answer:

[0.5,0.3,0].

That is incomplete.

After filtering:

[0.5,0.3,0].

Then renormalize:

0.5+0.3=0.8.

Final:

\boxed{ [0.625,0.375,0]. }

2.3.41 Another Exam Trap

Suppose logits are:

[3,2,1,0].

For:

k=2,

do not pick the two tokens with the largest softmax percentages by calculating all four first unless the question explicitly asks for probabilities.

Simply rank logits:

3>2>1>0.

Therefore:

\boxed{ \text{top-2}=\{3,2\}. }

This is much faster.

2.3.42 Another Exam Trap

Top-k does not necessarily mean:

k\% \text{ of vocabulary}.

If:

V=50,000

and:

k=50,

you retain exactly:

\boxed{50}

tokens, not 50%.

2.3.43 Another Exam Trap

If:

k=1,

top-k filtering leaves one token.

But whether the system is called "sampling" operationally depends on the implementation. With exactly one nonzero probability, the outcome is deterministic.

Mathematically:

\boxed{ Top1+sampling\equiv\text{deterministic}. }

2.3.44 Top-k in the Full Generation Loop

The generation loop is:

Current context
       ↓
LLM
       ↓
logits
       ↓
Top-k filtering
       ↓
Temperature
       ↓
Softmax
       ↓
Sample
       ↓
next token
       ↓

Raschka's implementation follows this exact structure, including obtaining only the logits at the final sequence position during generation. (Source: Build a Large Language Model (From Scratch))

\boxed{ \text{filtering controls WHO can be selected} }

2.3.48 Parameter k and Diversity

Smaller k:

\boxed{\text{fewer possible tokens}}

→ more constrained.

Larger k:

\boxed{\text{more possible tokens}}

→ more flexibility.

Extreme cases:

k=1 \rightarrow \text{deterministic}.
k=V \rightarrow \text{no top-k filtering}.

50,257-25 = \boxed{50,232}.

Thus:

\boxed{ 99.9503\% }

of the vocabulary is removed from the candidate set.

This illustrates how aggressive top-k can be.

2.3.51 Top-k and Numerical Stability

Suppose:

z=[1000,999,998,-500].

Take:

k=3.

After filtering:

[1000,999,998,-\infty].

At softmax, subtract maximum:

[0,-1,-2,-\infty].

Then:

e^0=1,\quad e^{-1}\approx0.3679,\quad e^{-2}\approx0.1353.

This is numerically stable.

So a useful implementation trick appears again:

\boxed{ softmax(z)=softmax(z-\max z). }

2.3.52 Why Top-k Is Particularly Useful With Large Vocabularies

Imagine:

V=100,000.

Sampling from all 100,000 tokens means there are many possible low-probability candidates.

Top-k could reduce that to:

k=50.

Now:

100,000\rightarrow50.

So the decoder explores a much smaller candidate set.

This is a major reason top-k is conceptually useful.

2.3.53 But Fixed k Creates the Main Weakness

Suppose two contexts produce:

Context A
[0.90,0.05,0.02,0.01,\ldots]
Context B
[0.12,0.11,0.10,0.09,0.08,\ldots]

Using:

k=3

means:

Context A

retain 90%, 5%, 2%.

That seems reasonable.

Context B

retain only 12%, 11%, 10%, while removing other plausible choices like 9% and 8%.

So fixed k does not adapt to the model's uncertainty.

That is the precise motivation for nucleus sampling.

2.3.54 Top-k Summary Formula

Define the top-k set:

S_k(z).

Then:

\boxed{ z_i'= \begin{cases} z_i,&i\in S_k(z)\\ -\infty,&i\notin S_k(z) \end{cases} }

Then:

\boxed{ p_i= \frac{e^{z_i'}} {\sum_j e^{z_j'}} }

and:

\boxed{ y_t\sim p. }

If temperature is used:

\boxed{ p_i= \operatorname{softmax}\left(\frac{z_i'}{T}\right). }

2.3.55 Top-k Numerical Master Formula

When an exam gives probabilities:

\boxed{ P'_i = \frac{P_i} {\sum_{j\in TopK}P_j} }

for retained tokens.

When an exam gives logits:

\boxed{ \text{rank logits} \rightarrow \text{keep top }k \rightarrow \text{others }-\infty \rightarrow \text{softmax}. }

This distinction should become automatic.

2.3.56 Top-k vs Greedy vs Beam vs Sampling

We can now compare the major methods we've learned:

Strategy Main idea
Greedy Pick highest-probability token immediately
Beam Keep several sequence hypotheses
Sampling Randomly draw from distribution
Top-k sampling Sample only among the k highest-ranked candidates
Temperature Reshape the sampling distribution

A very useful conceptual separation is:

\boxed{ \text{Beam = search over sequences} }

while:

\boxed{ \text{Top-k/temperature = shape the next-token distribution}. }

2.3.58 The Core Understanding

The best way to remember top-k is:

\boxed{ \text{Top-k does not tell the model WHAT to prefer.} }

The model already produced logits.

Top-k says:

"Of all the tokens the model considered, I will only permit the highest k candidates to participate in sampling."

Then softmax redistributes the probability over those candidates.

So:

\boxed{ \text{Top-k = hard candidate filtering} }

while:

\boxed{ \text{Temperature = soft distribution reshaping}. }
