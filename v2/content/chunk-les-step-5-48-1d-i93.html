Additional depths predict later tokens while using only an appropriate teacher-forced prefix.

Prerequisites: Shifted next-token targets and masked loss

Notation and assumptions

Base depth0 predicts token t+1. Additional depth k uses visible tokens through t+k and targets t+k+1. Mask nonexistent end targets.

Derivation and mechanism

  1. Write each position and depth before indexing tensors.
  2. At depth1, feed next-token embedding but predict the following token.
  3. Verify the visible endpoint is strictly earlier than the target.
\mathrm{target}(t,k)=x_{t+k+1}

Worked example

Tokens[10,11,12,13,14],depth1: targets[12,13,14] at base positions0,1,2. Visible endpoints1,2,3 are all before target endpoints2,3,4. The companion prints this alignment.

Limitations

  • Training visibility under teacher forcing differs from free-running speculative inference.
  • Do not feed the exact target embedding at the same prediction depth.

Connections to later concepts

  • A07 uses later-token predictions as speculative proposals at inference; teacher-forced training and proposal verification differ.

Step 5.48.1D — Teacher Forcing, Target Alignment, and the Exact Indexing

Plan node: A3 · chat order #93

↩ Back to main text: Step 1.1 — What Exactly Is a Language Model? · Step 2.5 — Putting the Decoding Strategies Together

This step is extremely important because MTP is easy to understand conceptually but easy to implement incorrectly by one position.

We will carefully distinguish:

\boxed{\text{current token}}
\boxed{\text{future embedding fed into MTP}}
\boxed{\text{target token used for cross-entropy}}

and:

\boxed{\text{logits produced by that MTP stage}}.

The DeepSeek book gives two related implementation snippets. The MTP chapter's Listing 5.4 shows the general causal chain and future-token slicing, while the later Mini-DeepSeek training-path example makes the shifted slicing more explicit. The loss call itself is abbreviated with ..., so I will distinguish exactly what the source states from the indexing inference needed to understand it. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.1 Start with ordinary language-model shifting

Take:

X=[t_1,t_2,t_3,t_4,t_5,t_6].

Standard next-token prediction works like:

INPUT:   t1   t2   t3   t4   t5
TARGET:  t2   t3   t4   t5   t6

Therefore:

\boxed{ t_i\rightarrow t_{i+1}. }

The hidden states are:

h_1,h_2,h_3,h_4,h_5.

and logits are compared with:

t_2,t_3,t_4,t_5,t_6.

This is the standard shift you already know from causal language-model training.

5.48.1D.2 Why MTP needs more shifts

Now suppose:

D=3.

We want:

t_i\rightarrow t_{i+1},t_{i+2},t_{i+3}.

Therefore we need progressively larger shifts.

For an intuitive target table:

Position      +1       +2       +3
─────────────────────────────────────
t1            t2       t3       t4
t2            t3       t4       t5
t3            t4       t5       t6
t4            t5       t6        -
t5            t6        -        -
t6             -        -        -

So:

\boxed{ \text{MTP depth }1\rightarrow +1 }
\boxed{ \text{MTP depth }2\rightarrow +2 }
\boxed{ \text{MTP depth }3\rightarrow +3. }

This is the conceptual alignment used throughout the MTP explanation. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.3 Now introduce the embedding input

Here is the subtle part.

At MTP depth k, the module receives both:

h_i^{k-1}

and a future-token embedding.

The source describes that future embedding as:

\boxed{ \operatorname{Emb}(t_{i+k}) }

and explicitly says that during training it is the ground-truth embedding of that future token. (Source: Build a DeepSeek Model (From Scratch))

Thus the conceptual operation is:

h_i^{k-1} + E(t_{i+k})

then:

\operatorname{RMSNorm} \rightarrow \text{concat} \rightarrow M_k \rightarrow TRM_k.

5.48.1D.4 Concrete example: MTP 1

Take:

[t_1,t_2,t_3,t_4,t_5,t_6].

For MTP 1:

k=1.

The valid positions are:

i=1,\ldots,5.

We therefore use:

[h_1^0,h_2^0,h_3^0,h_4^0,h_5^0]

together with:

[E(t_2),E(t_3),E(t_4),E(t_5),E(t_6)].

Thus:

h1⁰ + E(t2) → MTP1 → logits → target t2
h2⁰ + E(t3) → MTP1 → logits → target t3
h3⁰ + E(t4) → MTP1 → logits → target t4
h4⁰ + E(t5) → MTP1 → logits → target t5
h5⁰ + E(t6) → MTP1 → logits → target t6

So:

\boxed{ L_1 = CE(\text{MTP1 logits},[t_2,t_3,t_4,t_5,t_6]). }

This matches the source's conceptual description of the first head predicting the next token. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.5 MTP 2

Now:

k=2.

We need:

L_2=S-2=4

valid positions.

So:

[h_1^1,h_2^1,h_3^1,h_4^1]

are paired with:

[E(t_3),E(t_4),E(t_5),E(t_6)].

Thus:

h1¹ + E(t3) → MTP2 → logits → target t3
h2¹ + E(t4) → MTP2 → logits → target t4
h3¹ + E(t5) → MTP2 → logits → target t5
h4¹ + E(t6) → MTP2 → logits → target t6

Therefore:

\boxed{ L_2 = CE(\text{MTP2 logits},[t_3,t_4,t_5,t_6]). }

5.48.1D.6 MTP 3

Similarly:

k=3.

Valid length:

L_3=6-3=3.

Inputs:

[h_1^2,h_2^2,h_3^2]

and:

[E(t_4),E(t_5),E(t_6)].

Thus:

h1² + E(t4) → MTP3 → logits → target t4
h2² + E(t5) → MTP3 → logits → target t5
h3² + E(t6) → MTP3 → logits → target t6

Therefore:

\boxed{ L_3 = CE(\text{MTP3 logits},[t_4,t_5,t_6]). }

5.48.1D.7 Put all target sequences beside one another

For:

X=[t_1,t_2,t_3,t_4,t_5,t_6]

we get:

Component Hidden state Future embedding Target
Main h^0_1,\ldots,h^0_6 — next-token targets
MTP 1 h^0_1,\ldots,h^0_5 E(t_2),\ldots,E(t_6) t_2,\ldots,t_6
MTP 2 h^1_1,\ldots,h^1_4 E(t_3),\ldots,E(t_6) t_3,\ldots,t_6
MTP 3 h^2_1,\ldots,h^2_3 E(t_4),\ldots,E(t_6) t_4,\ldots,t_6

The source's explanatory architecture uses exactly this progressive future horizon. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.8 Now compare with the actual Python slicing

The MTP chapter's source code uses:

L = S - depth_k

h_prev_sliced = h_prev[:, :L, :]

future_token_ids = input_ids[:, depth_k:depth_k + L]

future_token_embeds = self.get_embedding(
    future_token_ids
)

(Source: Build a DeepSeek Model (From Scratch))

For:

S=6.
k=1
L=5.

Then:

input_ids[:, 1:6]

which corresponds to:

[t_2,t_3,t_4,t_5,t_6].
k=2
L=4.

Then:

input_ids[:, 2:6]

which gives:

[t_3,t_4,t_5,t_6].
k=3
L=3.

Then:

input_ids[:, 3:6]

which gives:

[t_4,t_5,t_6].

So the future embedding alignment is:

\boxed{ k=1\rightarrow[t_2,\ldots] }
\boxed{ k=2\rightarrow[t_3,\ldots] }
\boxed{ k=3\rightarrow[t_4,\ldots]. }

5.48.1D.9 The source's later training-path snippet

The later integrated Mini-DeepSeek code uses:

h_prev_shifted = h_prev[:, :-(k+1), :]

next_tokens_embed = self.embed(input_ids[:, k:-1])

h_k = mtp_block(
    h_prev_shifted,
    next_tokens_embed
)

logits_k = self.lm_head(self.norm_f(h_k))

(Source: Build a DeepSeek Model (From Scratch))

This looks different at first glance.

For example, when:

k=1,

the code takes:

input_ids[:, 1:-1]

rather than:

input_ids[:, 1:]

and slices the hidden state to:

h_prev[:, :-2, :]

This is an important source-level detail.

5.48.1D.10 Why does this look different?

Because the book contains two implementation presentations with different indexing conventions.

The earlier MTP-specific listing:

L=S-k

and:

input\_ids[:,k:k+L]

directly illustrates the multi-token horizon.

The later integrated Mini-DeepSeek listing shifts the usable hidden-state range as part of its complete next-token training alignment and describes the MTP block as predicting the k+1-th token. (Source: Build a DeepSeek Model (From Scratch))

Most importantly:

\boxed{ \text{the source's cross-entropy target tensors are abbreviated with }... }

So the exact target-slice expression for the loss is not printed in that listing.

We should therefore not pretend the PDF explicitly gives a single final PyTorch target slice when it does not.

5.48.1D.11 What can we state with certainty?

From the source:

Certain

At depth k:

\boxed{ \text{future-token embedding is taken from a future position} }

and:

\boxed{ \text{the MTP head is trained against the corresponding future ground-truth token}. }

The source says the entire sequential process produces D predictions, which are compared with the D actual ground-truth future tokens. (Source: Build a DeepSeek Model (From Scratch))

Also certain

The sequence becomes shorter at deeper prediction depths.

Not explicitly printed

The exact F.cross_entropy(logits_k, target_slice) indexing in the abbreviated Listing 5.4/6.18 code.

So when implementing from scratch, we must choose a consistent indexing convention and apply it consistently to:

\boxed{ \text{hidden slice} \leftrightarrow \text{future embedding slice} \leftrightarrow \text{target slice}. }

5.48.1D.12 The safest conceptual alignment

The cleanest mathematical convention is:

\boxed{ \text{depth }k: \quad h_i^{k-1} + E(t_{i+k}) \rightarrow \text{MTP}_k \rightarrow P(t_{i+k}). }

Then:

\boxed{ Y_k=[t_{k+1},t_{k+2},\ldots,t_S]. }

and:

\boxed{ H_{k-1}=[h_1^{k-1},\ldots,h_{S-k}^{k-1}]. }

Therefore:

\boxed{ |H_{k-1}|=|Y_k|=S-k. }

This gives perfect tensor alignment.

5.48.1D.13 Cross-entropy shape

Suppose:

B=2,
L_k=18,
V=50,000.

Then logits:

Z_k\in\mathbb R^{2\times18\times50000}.

Targets:

Y_k\in\mathbb R^{2\times18}.

That is exactly the shape required conceptually by cross-entropy:

\boxed{ [B,L_k,V] \quad\text{vs}\quad [B,L_k]. }

Usually PyTorch flattens these conceptually to:

[B L_k,V]

and:

[B L_k].

So:

2\times18=36.

Therefore:

\boxed{ [36,50000] \quad\text{vs}\quad [36]. }

5.48.1D.14 Numerical target alignment

Suppose token IDs are:

[10,20,30,40,50,60].

Take:

D=3.
MTP 1

Target:

[20,30,40,50,60].
MTP 2

Target:

[30,40,50,60].
MTP 3

Target:

[40,50,60].

Notice the triangular structure:

Main:   10  20  30  40  50  60

MTP1:       20  30  40  50  60
MTP2:           30  40  50  60
MTP3:               40  50  60

This is the pattern you should reproduce on an exam if asked to construct the MTP targets.

5.48.1D.15 The future embeddings follow the same structure

The embeddings used inside MTP are:

MTP 1
[E(20),E(30),E(40),E(50),E(60)].
MTP 2
[E(30),E(40),E(50),E(60)].
MTP 3
[E(40),E(50),E(60)].

Thus:

\boxed{ \text{future embedding alignment} = \text{future target alignment} }

under this clean conceptual indexing.

5.48.1D.16 But here's the subtle distinction

The future embedding is used as an input to the MTP transformation.

The target is used only to calculate the supervised loss.

So do not confuse:

\boxed{ E(t_{i+k}) }

with:

\boxed{ t_{i+k} }.

The first is a vector:

\mathbb R^d.

The second is a discrete class ID:

\{0,\ldots,V-1\}.

So:

future token ID
      │
      ├────────► Embedding ─────► MTP input
      │
      └─────────────────────────► Ground-truth target

The same underlying ground-truth token participates in two computational roles during training:

\boxed{ \text{embedding input} }

and:

\boxed{ \text{supervision target}. }

This follows directly from the source's statement that the future-token embedding is ground truth and that the predictions are compared against actual ground-truth future tokens. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.17 Why is this teacher forcing?

The relevant training information is already known.

Instead of:

\text{predict token} \rightarrow \text{sample token} \rightarrow \text{embed sampled token} \rightarrow \text{next stage},

the source training path uses the true future token's embedding.

Conceptually:

\boxed{ \text{teacher forcing / ground-truth conditioning}. }

The source does not use the phrase as the central MTP label in the cited implementation text, but its explicit use of ground-truth future-token embeddings establishes the mechanism. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.18 Why isn't this cheating?

Because the purpose of this MTP mechanism is to provide a training signal.

It is not saying:

“At inference, give the model the correct future token.”

Instead, during training, the model is given information that helps construct the learning pathway.

The actual normal inference branch in the source does not use this MTP training loop. It uses KV caching and generates logits from the final current position. (Source: Build a DeepSeek Model (From Scratch))

This distinction is absolutely critical:

\boxed{ \text{training computation} \neq \text{standard inference computation}. }

5.48.1D.19 Exact cross-entropy concept

For one depth k, suppose logits are:

z_i^k\in\mathbb R^V.

For the correct target class:

y_i^k.

Cross-entropy is:

\boxed{ L_i^k = -\log \left( \frac{ e^{z_{i,y_i^k}^k} }{ \sum_{j=1}^{V}e^{z_{i,j}^k} } \right). }

Equivalently:

L_i^k = -\log p_i^k(y_i^k).

Then:

L_k = \frac{1}{N_k} \sum_iL_i^k

for an averaged implementation, where:

N_k=B(S-k)

for a full batch with no additional masking.

5.48.1D.20 Numerical cross-entropy

Suppose the vocabulary has only 4 tokens.

For one MTP prediction:

z=[2.0,1.0,0.5,-1.0].

Suppose the correct target is class 1, whose logit is:

1.0.

Then:

p_1= \frac{e^1} {e^2+e^1+e^{0.5}+e^{-1}}.

Numerically:

e^2\approx7.389
e^1\approx2.718
e^{0.5}\approx1.649
e^{-1}\approx0.368.

Denominator:

7.389+2.718+1.649+0.368 = 12.124.

Therefore:

p_1 \approx \frac{2.718}{12.124} \approx0.224.

Loss:

-\log(0.224) \approx \boxed{1.496}.

This is the individual contribution of that one target position to L_k.

5.48.1D.21 Why longer horizon creates more supervision

For:

S=100,\quad D=3

we already found:

L_1=99
L_2=98
L_3=97.

So the total number of MTP target positions is:

99+98+97 = \boxed{294}.

Standard one-step prediction has:

99

positions.

Therefore, ignoring weighting:

\frac{294}{99} \approx \boxed{2.97}.

So MTP creates almost three times as many prediction terms for the same sequence when D=3.

The source uses this increased number/richness of future-target signals to motivate improved data efficiency. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.22 But compute also increases

Don't make the mistake:

\text{294 target terms} \Rightarrow \text{294 times computation}.

No.

The MTP modules process increasingly shorter sequences:

99,\;98,\;97.

So the additional computation is roughly proportional to the work done by those modules, not just the number of scalar targets.

And each MTP stage has a full Transformer block.

Thus:

\boxed{ \text{MTP gives richer supervision at additional training cost}. }

5.48.1D.23 A classic off-by-one bug

Suppose:

h_prev.shape = [B, 19, d]

but you accidentally use:

future_tokens = input_ids[:, 1:21]

and obtain 20 tokens.

Then you have:

19\neq20.

The MTP module cannot align:

h_i

with:

E(t_{i+k}).

You get either a runtime shape error or, worse, incorrect alignment after some unintended manipulation.

Therefore:

\boxed{ \text{hidden length}= \text{future-embedding length}= \text{target length}. }

This is the golden implementation rule.

5.48.1D.24 Alignment invariant

For every depth k:

\boxed{ L_k=S-k }

and therefore:

\boxed{ H_{k-1}\in\mathbb R^{B\times L_k\times d} }
\boxed{ E_k\in\mathbb R^{B\times L_k\times d} }
\boxed{ Y_k\in\mathbb R^{B\times L_k} }
\boxed{ Z_k\in\mathbb R^{B\times L_k\times V}. }

This is probably the most important tensor-alignment fact in the entire MTP implementation.

5.48.1D.25 The triangular target matrix

For general S and D, think of MTP targets as a triangular matrix:

\boxed{ \begin{array}{cccccc} t_2&t_3&t_4&\cdots&t_S\\ t_3&t_4&t_5&\cdots&t_S\\ t_4&t_5&t_6&\cdots&t_S\\ \vdots&\vdots&\vdots&&\vdots \end{array} }

where row k begins k positions into the original sequence.

Each row corresponds to a prediction depth.

So:

\boxed{ \text{row }k = [t_{k+1},\ldots,t_S]. }

Its length is:

S-k.

5.48.1D.26 Mapping this to the source's code

The source's MTP-specific code:

L = S - depth_k
h_prev_sliced = h_prev[:, :L, :]
future_token_ids = input_ids[:, depth_k:depth_k + L]
future_token_embeds = self.get_embedding(future_token_ids)
h_curr = self.mtp_modules[depth_k - 1](
    h_prev_sliced,
    future_token_embeds
)
logits_k = self.get_output_logits(h_curr)

(Source: Build a DeepSeek Model (From Scratch))

means:

\boxed{ \text{same number of hidden positions} = \text{same number of future embeddings} = L. }

The remaining step is simply:

\boxed{ \text{compare } logits_k \text{ to the matching ground-truth targets}. }

The source then sums the resulting depth-specific losses. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.28 Final mental model for indexing

Whenever you see:

\boxed{k}

ask four questions:

1. How many valid positions?
\boxed{ L_k=S-k }
2. Which future token embedding?
\boxed{ E(t_{i+k}) }
3. Which target?
\boxed{ t_{i+k} }

under the clean conceptual convention.

4. Which hidden state?
\boxed{ h_i^{k-1} }

Then:

\boxed{ (h_i^{k-1},E(t_{i+k})) \rightarrow h_i^k \rightarrow logits_k \rightarrow CE(t_{i+k}). }

5.48.1D.29 The entire MTP training equation

For each depth:

\boxed{ h_i^k = TRM_k \left( M_k \left[ RMSNorm(h_i^{k-1}); RMSNorm(E(t_{i+k})) \right] \right) }

then:

\boxed{ z_i^k=h_i^kW_{out} }

then:

\boxed{ L_k = -\sum_i \log P(t_{i+k}\mid h_i^k) }

and finally:

\boxed{ L_{\text{total}} = L_{\text{main}} + \frac{\lambda}{D} \sum_{k=1}^{D}L_k. }

The source directly supports the architecture, the ground-truth future embeddings, the shared output head, the depth-wise losses, and the weighted MTP contribution. (Source: Build a DeepSeek Model (From Scratch))

5.48.1D.30 One final indexing test

Given:

X=[A,B,C,D,E,F,G]

and:

MTP 1
\boxed{B,C,D,E,F,G}
MTP 2
\boxed{C,D,E,F,G}
MTP 3
\boxed{D,E,F,G}

Lengths:

6,\;5,\;4.

So:

\boxed{ L_k=S-k. }

And the first MTP head starts from:

h^0_1,\ldots,h^0_6,

the second from the corresponding refined:

h^1_1,\ldots,h^1_5,

and the third from:

h^2_1,\ldots,h^2_4.

That triangular structure is the thing to visualize whenever MTP indexing gets confusing.

Step 5.48.1D checkpoint

The four objects must always align:

\boxed{ h_i^{k-1} \quad\leftrightarrow\quad E(t_{i+k}) \quad\leftrightarrow\quad z_i^k \quad\leftrightarrow\quad t_{i+k}. }

And the number of valid positions is:

\boxed{ S-k. }
