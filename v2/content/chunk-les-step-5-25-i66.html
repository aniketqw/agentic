Step 5.25 — ReTool Results and Ablation Logic

Plan node: I9 · chat order #66

Now we will learn how to read the ReTool results scientifically.

Do not just memorize:

26.7\rightarrow40.9\rightarrow40.0\rightarrow67.0

The important question is:

\boxed{\text{What does each comparison isolate?}}

That is what an ablation study is doing.

5.25.1 First: what is an ablation?

Suppose a complete system has components:

A+B+C.

We want to know which component actually matters.

So we remove components one at a time:

A
A+B
A+B+C.

Then compare performance.

This is an ablation.

The key logic is:

\boxed{ \text{change one important ingredient while keeping the rest comparable} }

and observe what happens.

5.25.2 ReTool's four configurations

The supplied slide gives this progression on AIME2024, using the specified Qwen2.5-32B-Instruct setup: (Source: retool-slides)

Configuration AIME2024
Base model, no training 26.7%
+ cold-start SFT, no RL 40.9%
+ RL, text-only, no code interpreter 40.0%
+ RL, with code interpreter — ReTool 67.0%

Let's not jump to the conclusion yet.

We will derive every comparison.

5.25.3 Comparison 1 — Base model → cold-start SFT

We start with:

26.7\%.

After cold-start SFT:

40.9\%.

Absolute improvement:

40.9-26.7 = \boxed{14.2\text{ percentage points}}.

This is exactly the \Delta shown by the slide. (Source: retool-slides)

5.25.4 What does this comparison prove?

It shows that:

\boxed{ \text{cold-start SFT is useful} }

for this setup.

More specifically, the SFT stage provides a substantial gain before RL begins.

This is consistent with what we learned earlier:

\boxed{ \text{SFT teaches the model the code/interpreter protocol} }

so the model can participate in the later RL environment.

5.25.5 What does it NOT prove?

It does not prove:

\boxed{ \text{SFT is better than RL generally} }

because that isn't the experiment being performed.

It also does not prove that:

\boxed{ \text{SFT alone is sufficient} }

because the full ReTool system later improves substantially beyond 40.9%.

So our scientifically correct statement is:

In this reported setup, cold-start SFT produces a 14.2-point improvement over the untrained base model on AIME2024.

Not:

SFT solves tool-use reasoning.

5.25.6 Comparison 2 — Cold-start SFT vs text-only RL

Now compare:

40.9\%

versus:

40.0\%.

Difference:

40.0-40.9 = \boxed{-0.9\text{ percentage points}}.

So text-only RL is actually 0.9 points lower than cold-start SFT in this reported comparison. (Source: retool-slides)

5.25.7 This is the surprising result

You might have expected:

\text{SFT}+RL > \text{SFT}.

But in the reported comparison, the text-only RL configuration reaches:

40.0\%

while SFT alone reaches:

40.9\%.

So:

\boxed{ \text{text-only RL adds almost nothing beyond SFT here} }

The slide explicitly emphasizes this interpretation. (Source: retool-slides)

5.25.8 Why is this important?

Because it isolates something very specific.

It tells us that:

\boxed{ \text{RL by itself is not the source of the giant improvement} }

at least in this particular comparison.

The big gain comes when RL has access to:

\boxed{ \text{real code execution} }

5.25.9 Comparison 3 — Base → text-only RL

The slide also shows:

26.7\%\rightarrow40.0\%.

So the absolute improvement is:

40.0-26.7 = \boxed{13.3\text{ points}}.

This is the slide's reported \Delta. (Source: retool-slides)

So text-only RL does improve over the raw base model.

But compare:

13.3

to SFT's:

14.2.

They are very similar.

Thus the important conclusion isn't:

text-only RL does nothing.

Instead:

\boxed{ \text{text-only RL helps relative to the raw base, but provides little additional gain over the cold-start SFT baseline in this experiment} }

That is a much more precise interpretation.

5.25.10 Comparison 4 — Text-only RL → ReTool

Now comes the major jump.

Text-only RL:

40.0\%.

ReTool:

67.0\%.

Improvement:

67.0-40.0 = \boxed{27.0\text{ percentage points}}.

This is the critical comparison.

5.25.11 Comparison 5 — SFT → ReTool

Cold-start SFT:

40.9\%.

ReTool:

67.0\%.

Improvement:

67.0-40.9 = \boxed{26.1\text{ percentage points}}.

So almost the entire extraordinary jump occurs when the system moves from:

\boxed{ \text{SFT/text reasoning} }

to:

\boxed{ \text{RL + actual code execution} }.

5.25.12 Comparison 6 — Base → ReTool

From:

26.7\%

to:

67.0\%.

Absolute improvement:

67.0-26.7 = \boxed{40.3\text{ percentage points}}.

That is the slide's reported overall gain. (Source: retool-slides)

So relative to the original base performance:

\frac{67.0-26.7}{26.7}\times100 \approx \boxed{151.3\%}

relative improvement.

Be careful:

\boxed{40.3\text{ points}}

and:

\boxed{151.3\%\text{ relative improvement}}

are different quantities.

The slide reports the former; the latter is our arithmetic calculation.

5.25.13 Now identify the actual experimental variable

Let's construct the progression:

26.7
\downarrow +14.2
40.9
\downarrow -0.9
40.0
\downarrow +27.0
67.0.

What changes most dramatically in the last transition?

\boxed{ \text{real code-interpreter interaction} }

That is why the slide concludes that the gain is specifically associated with learning when and how to use the tool, rather than with RL or tools alone. (Source: retool-slides)

5.25.14 Why can't we just say “the tool caused everything”?

Because that would be too strong.

ReTool contains multiple ingredients:

\text{cold-start SFT} + \text{RL} + \text{code interpreter}.

The 67.0% result belongs to the combination.

The ablation demonstrates that the combination performs dramatically better than the text-only variants.

But a single ablation table cannot establish every possible causal decomposition under every alternative training setup.

So the careful statement is:

\boxed{ \text{In the reported experiment, the large additional gain appears when RL is combined with real tool interaction.} }

That is exactly the interpretation supported by the deck. (Source: retool-slides)

5.25.15 Why is the “RL without tool” baseline necessary?

This is a very important experimental-design principle.

Suppose the authors only reported:

40.9\%\rightarrow67.0\%.

Someone could argue:

Maybe RL itself creates the 26-point improvement.

To test that hypothesis, they include:

\boxed{ \text{RL without code interpreter} }

and obtain:

40.0\%.

That comparison weakens the explanation:

\text{“RL alone caused the 27-point jump.”}

Because under this setup:

\boxed{ 40.0\% \not\approx 67.0\% }

5.25.16 This is how you should read ablations

When you see:

A=40.9
B=40.0
C=67.0

ask:

What changed between A and C?

and:

What changed between B and C?

Here:

A vs C
\text{SFT} \rightarrow \text{SFT + RL + tool interaction}
B vs C
\text{text-only RL} \rightarrow \text{tool-integrated RL}.

The second comparison is especially informative because both involve RL, so it more directly isolates the contribution of adding the tool interaction to the RL setup described in the slide.

5.25.17 A simple causal diagram

Conceptually:

             Base model
                │
        ┌───────┴────────┐
        │                │
       SFT             Text RL
        │                │
      40.9              40.0
        │                │
        └──────┬─────────┘
               │
          + real tool
               │

The exact experimental paths are those shown in the deck; this diagram is just a visualization of the ablation logic.

5.25.20 What does this teach us?

It reinforces an idea we already encountered during distillation:

\boxed{ \text{base-model quality matters} }

ReTool isn't independent of the backbone.

Same broad tool/RL idea:

\text{different backbone} \rightarrow \text{different ceiling}.

So:

\boxed{ \text{tool use is an additional capability, not a replacement for model capability} }

That broader wording is an inference from the reported comparison; the deck itself simply reports the stronger-backbone result.

72.5\%.

Difference:

These are arithmetic calculations from the slide's reported numbers. (Source: retool-slides)

5.25.22 Training efficiency: why fewer steps matter

Now consider the learning curves.

The slide reports:

\boxed{ \text{ReTool plateau }\approx\text{ step }400 }

while:

\boxed{ \text{text-only RL continues past step }1000 }

and ReTool reaches its higher accuracy using approximately:

\boxed{37\%}

of the training steps of the text-only RL baseline. (Source: retool-slides)

5.25.23 Numerical interpretation

Suppose the text-only baseline requires:

1000

steps.

Then:

0.37\times1000 = \boxed{370}

steps.

The reported plateau around 400 steps is therefore broadly consistent with the approximate 37% statement.

But notice the wording:

\boxed{\text{about }37\%}

and:

\boxed{\text{around step }400}.

These are approximate empirical observations, not an exact algebraic identity.

5.25.24 Why could tool use make exploration easier?

This is the deeper interpretation proposed by the slide.

Consider text-only RL.

The model must discover:

\text{how to reason} + \text{how to calculate} + \text{how to search} + \text{how to verify}.

All inside generated text.

With a computational tool:

\boxed{ \text{computation is delegated to an external mechanism} }

so the model can explore higher-level strategies such as:

\text{what to calculate}

rather than having to manually simulate every arithmetic step in language.

Thus the slide's interpretation is:

\boxed{ \text{tools do not merely increase the final ceiling;} \text{they make the exploration problem easier.} }

(Source: retool-slides)

5.25.25 Be careful about the word “easier”

The slide says:

tool use doesn't just raise the ceiling; it makes the exploration problem itself easier to solve. (Source: retool-slides)

This is an interpretation of the observed learning curve.

It does not give a formal theorem that external tools mathematically reduce RL sample complexity in every setting.

So in an exam:

Good:

\boxed{ \text{The reported learning curve suggests improved exploration efficiency.} }

Too strong:

\boxed{ \text{Tools always reduce sample complexity.} }

5.25.26 Another important numerical comparison

Compare:

67.0

with:

40.0.

Relative improvement from text-only RL:

\frac{67.0-40.0}{40.0}\times100 = \boxed{67.5\%}.

So ReTool's AIME2024 accuracy is about 67.5% higher relative to the text-only RL baseline in this particular reported comparison.

Again:

27\text{ points}

is the source-friendly quantity;

67.5\%

is our derived relative-improvement calculation.

5.25.27 What exactly do the ablations support?

Let's formalize the conclusions.

Conclusion A
\boxed{ \text{Cold-start SFT is useful.} }

Evidence:

26.7\rightarrow40.9.
Conclusion B
\boxed{ \text{Text-only RL does not provide a large additional gain over SFT in this setup.} }

Evidence:

40.9\rightarrow40.0.
Conclusion C
\boxed{ \text{Adding real code interaction to RL produces the major gain.} }

Evidence:

40.0\rightarrow67.0.
Conclusion D
\boxed{ \text{A stronger reasoning backbone can raise the ReTool result further.} }

Evidence:

67.0\rightarrow72.5.

(Source: retool-slides)

5.25.28 What the ablation does NOT prove

This is equally important.

The table does not establish that:

\boxed{\text{ReTool is universally better than every RL method}}

or:

\boxed{\text{code interpreters are universally better than other tools}}

or:

\boxed{\text{67\% is a universal upper bound}}

or:

\boxed{\text{SFT is unnecessary}}

or:

\boxed{\text{text-only RL never works}}

Those claims go beyond the supplied evidence.

The experiment is about the reported setup and comparisons.

5.25.29 Why this matters for research-paper reading

A common mistake is:

\boxed{ \text{correlation} \Rightarrow \text{absolute causal claim} }

The correct research mindset is:

  1. Identify the controlled comparison.
  2. Identify what changed.
  3. Identify what stayed approximately constant.
  4. Attribute the result only to what the experiment actually isolates.

For ReTool, the most informative isolation is:

\boxed{ \text{text-only RL} \quad\text{vs}\quad \text{RL + real code interpreter} }

because both are RL variants in the reported ablation. (Source: retool-slides)
