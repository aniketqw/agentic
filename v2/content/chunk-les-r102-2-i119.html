R102.2 — GRPO: Removing the Value Model with Group-Relative Rewards

Plan node: B1 · chat order #119

↩ Back to main text: Step 5.3 — Why GRPO Instead of PPO? · Step 5.7 — The Full GRPO Training Algorithm

We have reached the key algorithm behind the DeepSeek reasoning story:

\boxed{\text{GRPO = Group Relative Policy Optimization}}

The source introduces GRPO as the major simplification over PPO:

\boxed{ \text{PPO's learned value model} \;\rightarrow\; \text{group statistics from multiple sampled completions} }

GRPO was introduced in DeepSeekMath, and the source describes the same family of ideas as later being used in the DeepSeek-R1 training recipe. (Source: Build a DeepSeek Model (From Scratch))

1. First remember why PPO was expensive

PPO-style LLM training had four major pieces:

                 PPO
                  │
      ┌───────────┼───────────┐
      ▼           ▼           ▼
   Policy       Reward      Value Model
    πθ             R            Vφ
                                  │
                                  ▼
                              Advantage

                  +

             Reference Model
                πref

The expensive part is the value model.

It must learn:

V_\phi(s)

and provide the baseline for:

A=R-V_\phi(s).

The source explicitly notes that the value model adds memory, forward passes, loss terms, and engineering complexity. (Source: Build a DeepSeek Model (From Scratch))

So DeepSeek asks:

Can we obtain a useful baseline without training another value model?

2. The GRPO idea

Instead of producing one response and asking a value model:

How good was this response compared with expectation?

we produce multiple responses to the same prompt.

For example:

Same prompt P

        ┌─ Response 1 → reward 1
Prompt ─┼─ Response 2 → reward 1
        ├─ Response 3 → reward 0
        └─ Response 4 → reward 0

Now we can compare these responses against one another.

The source's key statement is:

A completion is good if it is better than the other completions sampled for the same prompt, and bad if it is worse than the group. (Source: Build a DeepSeek Model (From Scratch))

That is the "group-relative" part of GRPO.

3. Why must the prompt be the same?

This is extremely important.

Suppose:

Prompt A = easy problem
Prompt B = extremely hard problem

and:

A → reward 1
B → reward 0

Comparing those rewards directly can be misleading.

Maybe the response to B was actually much better than most responses to B.

GRPO instead creates:

\boxed{ \text{local comparison within the same prompt} }

So for each prompt:

P_i \rightarrow \{C_{i1},C_{i2},...,C_{iG}\}.

Each completion in the group is judged relative to the others.

The source specifically says this makes the baseline prompt-specific and avoids mixing easy and hard prompts together. (Source: Build a DeepSeek Model (From Scratch))

4. What is a GRPO group?

Suppose:

G=4.

For one prompt:

Prompt:
Solve 5 + 2 × 3

Completion 1 → 11 → reward 1
Completion 2 → 11 → reward 1
Completion 3 → 8  → reward 0
Completion 4 → 9  → reward 0

So the reward vector is:

\boxed{ [1,1,0,0] }

5. Compute the group mean

The source uses the group mean as part of the group-relative baseline:

\mu= \frac1G\sum_{j=1}^{G}r_j.

For:

[1,1,0,0],

we have:

\mu= \frac{1+1+0+0}{4} = \boxed{0.5}.

Therefore:

Response 1: 1 → above mean
Response 2: 1 → above mean
Response 3: 0 → below mean
Response 4: 0 → below mean

6. Compute the group-relative advantage

The source gives:

\boxed{ A_i= \frac{ r_i-\operatorname{mean}(r_1,\ldots,r_G) }{ \operatorname{std}(r_1,\ldots,r_G)+\epsilon } }

(Source: Build a DeepSeek Model (From Scratch))

This is the central GRPO formula.

Break it into pieces:

r_i-\mu

asks:

Is this completion better or worse than its group's average?

Then dividing by:

\sigma+\epsilon

normalizes the scale.

7. Numerical example

Using the rewards:

[1,1,0,0],

the mean is:

0.5.

For illustration, using the population standard deviation:

\sigma=0.5.

Then approximately:

Completion 1
A_1= \frac{1-0.5}{0.5+\epsilon} \approx+1
Completion 2
A_2\approx+1
Completion 3
A_3\approx-1
Completion 4
A_4\approx-1.

So:

\boxed{ A\approx[+1,+1,-1,-1] }

The source does not specify the exact standard-deviation convention in the displayed formula, so the exact numerical magnitude can depend on implementation; the important source-derived result is that correct-above-group responses get positive advantages and below-group responses get negative ones.

8. Now the magic happens

We no longer need:

V_\phi(s).

Instead:

Same prompt
    ↓
sample G completions
    ↓
reward each completion
    ↓
group mean/std
    ↓
group-relative advantages

Therefore:

\boxed{ \text{No learned value model} }

The model can learn which sampled trajectories were relatively better using only the reward distribution within the group. (Source: Build a DeepSeek Model (From Scratch))

9. Compare PPO and GRPO advantage calculation

PPO
\boxed{ A_i=R_i-V_\phi(s_i) }

where V_\phi is a learned value function.

GRPO
\boxed{ A_i= \frac{R_i-\mu_{\text{group}}} {\sigma_{\text{group}}+\epsilon} }

where \mu and \sigma come from the sampled group.

That's the fundamental algorithmic change.

10. Why is this called "relative"?

Because GRPO does not simply ask:

Is reward = 1 good?

It asks:

How good was this response relative to the other responses for the same prompt?

Suppose:

Prompt A:
[1, 1, 1, 0]

The single incorrect answer is clearly worse than the group.

Now suppose:

Prompt B:
[0, 0, 0, 0]

No completion is better than the others.

The group contains no obvious preference signal.

This is one reason group composition matters.

11. What happens if every completion gets the same reward?

This is a subtle implementation issue explicitly noted by the source.

Suppose:

[1,1,1,1].

Then:

\mu=1

and:

\sigma\approx0.

Without protection, we'd divide by zero.

Therefore the formula includes:

\boxed{\epsilon}

for numerical stability. (Source: Build a DeepSeek Model (From Scratch))

More fundamentally, when all completions have essentially identical reward, there is little relative information telling the policy which completion was better.

12. Why sample multiple completions?

This is not just batching.

Suppose we sample only:

G=1.

Then there is no meaningful within-prompt comparison.

GRPO requires:

\boxed{ G>1 }

in practice so that the reward distribution has some comparative information.

The source explicitly emphasizes that GRPO requires multiple completions per prompt so the group baseline is meaningful. (Source: Build a DeepSeek Model (From Scratch))

13. Bigger group vs smaller group

There is a trade-off.

Larger group

More completions:

G\uparrow

can give a better estimate of the prompt's reward distribution.

But it requires more rollout compute.

Smaller group

Cheaper:

G\downarrow

but the group statistics can become noisier.

The source explicitly frames group size as a compute-versus-baseline-quality trade-off. (Source: Build a DeepSeek Model (From Scratch))

So GRPO doesn't eliminate the computational cost of sampling.

It changes where the computation is spent.

14. Very important correction to a common misconception

GRPO is not:

"PPO, but it samples only one response."

It is almost the opposite.

GRPO explicitly samples:

\boxed{ \text{multiple completions per prompt} }

The source says GRPO is not cheaper because it samples fewer completions. Under a fair comparison with the same total sampled completions, it is cheaper because it removes the value-model training path. (Source: Build a DeepSeek Model (From Scratch))

15. What remains from PPO?

This is another critical point.

GRPO removes:

\boxed{\text{Value Model}}

but it retains important PPO-style machinery:

\boxed{ \text{old-policy probability ratio} }
\boxed{ \text{clipping} }

and:

\boxed{ \text{reference-policy KL control} }

The source explicitly says the group-relative advantage replaces the value-model advantage, but does not replace the stabilizers. (Source: Build a DeepSeek Model (From Scratch))

So:

             PPO
               │
      ┌────────┼──────────┐
      ▼        ▼          ▼
   ratio     clip       KL
      │        │          │
      └────────┼──────────┘
               │
        advantage
            │
         Vφ(s)

becomes:

             GRPO
               │
      ┌────────┼──────────┐
      ▼        ▼          ▼
   ratio     clip       KL
      │        │          │
      └────────┼──────────┘
               │
         group advantage
               │
        no value model

16. The old policy is still needed

We still need:

\pi_{\text{old}}.

Why?

Because we still calculate:

\boxed{ r_i(\theta) = \frac{ \pi_\theta(a_i\mid s_i) }{ \pi_{\text{old}}(a_i\mid s_i) } }

The rollout was generated by the old policy, and the current policy is being optimized.

The source explicitly says the old-policy log probabilities and probability ratio remain when moving from PPO to GRPO. (Source: Build a DeepSeek Model (From Scratch))

17. The reference model is ALSO still needed

We still have:

\pi_{\text{ref}}.

It remains frozen.

Its role is:

\boxed{ \text{prevent excessive drift from the reference distribution} }

The source explicitly warns:

\boxed{ \text{GRPO removes the value model, not the reference model}. }

The reference-policy KL term remains part of DeepSeek-style training. (Source: Build a DeepSeek Model (From Scratch))

18. So what does the complete GRPO update look like?

The source gives the full GRPO-style objective:

\boxed{ L_{\text{GRPO}}(\theta) = \mathbb E \left[ \min \left( r_k(\theta)A_i, \operatorname{clip}(r_k(\theta),1-\epsilon,1+\epsilon)A_i \right) - \beta KL(\pi_\theta\|\pi_{\text{ref}}) \right] }

(Source: Build a DeepSeek Model (From Scratch))

This equation contains three major mechanisms.

19. Part 1 — Policy improvement

r_kA_i

This says:

Use the advantage to push the current policy toward successful sampled behavior.

If:

A_i>0,

increase the probability of that sampled behavior.

If:

A_i<0,

decrease it.

20. Part 2 — Clipping

\operatorname{clip}(r_k,1-\epsilon,1+\epsilon)

This prevents the update from becoming excessively aggressive.

So:

\boxed{ \text{advantage says where to move} }

while:

\boxed{ \text{clipping says don't move too far in one update} }

21. Part 3 — Reference KL

-\beta KL(\pi_\theta\|\pi_{\text{ref}})

penalizes excessive divergence from the frozen reference policy.

So:

\boxed{ \text{reward pressure} - \text{drift pressure} }

is happening simultaneously.

The source describes the KL term as discouraging drift from the frozen reference policy. (Source: Build a DeepSeek Model (From Scratch))

22. One subtle sign issue

The equation above is written as an objective to maximize.

But PyTorch optimizers normally minimize losses.

Therefore the source notes that implementations generally negate this objective when turning it into a minimization loss. (Source: Build a DeepSeek Model (From Scratch))

So conceptually:

\max J(\theta)

becomes:

\boxed{ \min -J(\theta) }

in the training code.

23. The whole GRPO pipeline

Now we can finally see it end-to-end:

                       PROMPT
                          │
            ┌─────────────┼─────────────┐
            ▼             ▼             ▼
       completion 1  completion 2 ... completion G
            │             │             │
            ▼             ▼             ▼
          reward        reward        reward
            │             │             │
            └─────────────┼─────────────┘
                          ▼
                 group mean / std
                          │
                          ▼
                  group advantages
                          │
             ┌────────────┴────────────┐
             ▼                         ▼
      old-policy logprobs       reference logprobs
             │                         │
             ▼                         ▼
        probability ratio            KL
             │                         │
             ▼                         │
          clipping                     │
             │                         │
             └──────────┬──────────────┘
                        ▼
                    GRPO objective
                        │
                        ▼
                    backward()
                        │
                        ▼
                  update policy πθ

The source later summarizes the same conceptual hooks as: verifier → group advantage → GRPO loss → training step. (Source: Build a DeepSeek Model (From Scratch))

24. Now connect this to DeepSeek reasoning

This is where the DeepSeek story becomes much clearer.

We had:

\boxed{\text{pretrained base model}}

Then we sample multiple candidate reasoning trajectories:

\boxed{ \text{same problem} \rightarrow \text{many candidate solutions} }

A verifier evaluates them.

Then:

\boxed{ \text{better solutions} \rightarrow \text{positive advantage} }
\boxed{ \text{worse solutions} \rightarrow \text{negative advantage} }

And GRPO updates the model.

That creates a feedback loop:

\boxed{ \text{generate} \rightarrow \text{score} \rightarrow \text{compare} \rightarrow \text{update} \rightarrow \text{generate better solutions} }

This is the central mechanism underlying the source's transition from DeepSeekMath to reasoning-oriented DeepSeek models. (Source: Build a DeepSeek Model (From Scratch))

25. Why GRPO is attractive for huge LLMs

Compare the systems:

PPO
Policy model
+
Reward
+
Value model
+
Reference model
GRPO
Policy model
+
Reward
+
Reference model
+
multiple completions

So GRPO saves the:

\boxed{\text{value-model path}}

rather than eliminating rollout generation.

The source explicitly identifies this as the main cost saving. (Source: Build a DeepSeek Model (From Scratch))

26. But GRPO is not “simple RL”

This distinction matters.

Removing the critic does not remove:

\text{rollout generation}
\text{reward design}
\text{log-probability computation}
\text{KL control}
\text{clipping}
\text{masking}
\text{optimizer engineering}.

The source explicitly says:

GRPO simplifies the model stack, not the entire training problem. (Source: Build a DeepSeek Model (From Scratch))

29. One final numerical intuition

Imagine the model generates 4 solutions for the same math problem:

A → correct → 1
B → correct → 1
C → wrong   → 0
D → wrong   → 0

GRPO effectively tells the policy:

\boxed{ A,B:\ \text{“do more of behavior like this”} }
\boxed{ C,D:\ \text{“do less of behavior like this”} }

while clipping prevents the change from becoming too aggressive and KL discourages the entire policy from drifting too far from the reference.

That is the complete intuition behind GRPO.
