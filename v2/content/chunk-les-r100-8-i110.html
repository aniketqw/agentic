R100.8 — The TransformerBlock: Putting Attention and MoE Together

Plan node: A6 · chat order #110

↩ Back to main text: Step 1.13 — Stacking Transformer Blocks → Final Norm → Unembedding → Log

We have now built the individual pieces:

\boxed{\text{DeepSeekAttention}}

and:

\boxed{\text{DeepSeekMoE}}

The next step is not a new mathematical innovation. It is the architectural composition layer: the TransformerBlock that puts those two modules into the standard Transformer residual structure.

The source explicitly describes this as a pre-norm block with two residual connections. (Source: Build a DeepSeek Model (From Scratch))

1. First see the complete block

The source's block is:

                    x
                    │
                    ▼
               LayerNorm 1
                    │
                    ▼
             DeepSeekAttention
                    │
                    ▼
               attention h
                    │
                    ▼
                 x + h
                    │
                    ▼
               LayerNorm 2
                    │
                    ▼
               DeepSeekMoE
                    │
                    ▼
                MoE output
                    │
                    ▼
              (x + h) + MoE
                    │
                    ▼
               block output

So mathematically:

\boxed{ h=x+\operatorname{Attention}(\operatorname{LN}_1(x)) }

then:

\boxed{ y=h+\operatorname{MoE}(\operatorname{LN}_2(h)). }

That is the complete block.

2. Why is it called "pre-norm"?

Look at the order:

x \rightarrow \text{Norm} \rightarrow \text{Attention}

rather than:

x \rightarrow \text{Attention} \rightarrow \text{Norm}.

Similarly:

h \rightarrow \text{Norm} \rightarrow \text{MoE}.

Therefore the normalization happens before each major sublayer.

Hence:

\boxed{\text{pre-norm Transformer}.}

The source explicitly labels its implementation this way. (Source: Build a DeepSeek Model (From Scratch))

3. The source code

The source gives:

class TransformerBlock(nn.Module):
    def __init__(self, args: ModelArgs):
        super().__init__()

        # Use LayerNorm for simplicity,
        # though DeepSeek uses RMSNorm
        self.norm1 = nn.LayerNorm(args.d_model)

        self.attention = DeepSeekAttention(args)

        self.norm2 = nn.LayerNorm(args.d_model)

        self.feed_forward = DeepSeekMoE(args)

    def forward(
        self,
        x: torch.Tensor,
        attn_mask: torch.Tensor,
        past_kv: Optional[Tuple[torch.Tensor, torch.Tensor]] = None,
        position_offset: int = 0
    ):
        # Attention block with residual connection
        h, new_cache = self.attention(
            self.norm1(x),
            attn_mask,
            past_kv,
            position_offset
        )

        x = x + h

        # Feed-forward block with residual connection
        x = x + self.feed_forward(
            self.norm2(x)
        )

        return x, new_cache

(Source: Build a DeepSeek Model (From Scratch))

We should understand every line because this is the point where the previous components become one Transformer layer.

4. First normalization

The source creates:

self.norm1 = nn.LayerNorm(args.d_model)

Then:

self.norm1(x)

is fed into attention. (Source: Build a DeepSeek Model (From Scratch))

So:

x \rightarrow LN_1(x) \rightarrow DeepSeekAttention.

If:

x\in\mathbb R^{B\times S\times D},

then LayerNorm preserves the shape:

\boxed{ [B,S,D]\rightarrow[B,S,D]. }

It changes the numerical representation, not the dimensions.

5. An important source qualification: LayerNorm vs RMSNorm

The source explicitly comments:

Use LayerNorm for simplicity, though DeepSeek uses RMSNorm. (Source: Build a DeepSeek Model (From Scratch))

This distinction must be preserved.

So:

\boxed{ \text{Mini-DeepSeek source implementation} = \text{LayerNorm} }

while:

\boxed{ \text{DeepSeek architecture in the source's conceptual discussion} = \text{RMSNorm}. }

We should not silently replace the code's LayerNorm with RMSNorm.

6. Why normalize before attention?

At this level, the source is using the standard pre-norm Transformer organization.

The sequence is:

\boxed{ x \rightarrow LN \rightarrow Attention \rightarrow Residual. }

The residual connection means the original representation has a direct path around the attention computation.

This gives:

x_{\text{new}} = x+ h.

7. Attention call

The source executes:

h, new_cache = self.attention(
    self.norm1(x),
    attn_mask,
    past_kv,
    position_offset
)

(Source: Build a DeepSeek Model (From Scratch))

Notice that four things enter the attention module:

1. Normalized hidden state
LN_1(x)
2. Attention mask
attn\_mask
3. Previous cache
past\_kv
4. Position offset
position\_offset.

This connects the Transformer block directly to everything we have already learned about MLA, RoPE, and cached inference.

8. The attention output has two results

The function returns:

h, new_cache

So attention produces:

\boxed{h}

and:

\boxed{new\_cache}.

The first is the actual attention output.

The second is the updated state needed if the model is doing cached inference.

So conceptually:

normalized x
     │
     ▼
DeepSeekAttention
     │
     ├────────────→ h
     │
     └────────────→ new_cache

9. First residual connection

The source then performs:

x = x + h

(Source: Build a DeepSeek Model (From Scratch))

This is the first residual connection.

So:

\boxed{ x_1=x_0+h. }

where:

h=Attention(LN_1(x_0)).

Therefore:

\boxed{ x_1 = x_0+ Attention(LN_1(x_0)). }

10. Why does the original x remain?

Because attention should be treated as a transformation/refinement of the representation, not as a complete replacement.

The block says:

\boxed{ \text{new representation} = \text{old representation} + \text{learned update}. }

This residual structure is already familiar from the Transformer, but here the "learned update" is now the specialized DeepSeek attention mechanism.

11. Second normalization

After the attention residual:

x_1

goes through:

self.norm2(x)

before entering MoE. (Source: Build a DeepSeek Model (From Scratch))

Thus:

\boxed{ x_1 \rightarrow LN_2(x_1) \rightarrow MoE. }

12. Why a second normalization instead of reusing the first?

Because the attention and MoE sublayers are separate transformations.

The architecture is:

\boxed{ LN_1\rightarrow Attention }

and:

\boxed{ LN_2\rightarrow MoE. }

Each gets its own normalization layer and therefore its own normalization parameters.

The source creates two separate LayerNorm instances:

self.norm1
self.norm2

(Source: Build a DeepSeek Model (From Scratch))

13. Feed-forward is now MoE

The source names the second sublayer:

self.feed_forward = DeepSeekMoE(args)

(Source: Build a DeepSeek Model (From Scratch))

This name can be slightly misleading.

feed_forward here does not mean one ordinary dense FFN.

It means:

\boxed{ \text{DeepSeekMoE}. }

So:

x_1 \rightarrow DeepSeekMoE(LN_2(x_1)).

14. Second residual connection

The source then executes:

x = x + self.feed_forward(
    self.norm2(x)
)

(Source: Build a DeepSeek Model (From Scratch))

Therefore:

\boxed{ x_2 = x_1+ MoE(LN_2(x_1)). }

Combined with the first equation:

x_1 = x_0+ Attention(LN_1(x_0)).

So the entire block is:

\boxed{ x_2= x_0+ Attention(LN_1(x_0)) + MoE(LN_2(x_1)) }

where:

x_1=x_0+Attention(LN_1(x_0)).

15. This means the block has two residual routes

Picture it like this:

                    x₀
                    │
          ┌─────────┴─────────┐
          │                   │
          │                residual
          ▼                   │
        LN₁                   │
          │                   │
          ▼                   │
      Attention               │
          │                   │
          ▼                   │
         h                    │
          │                   │
          └────────┬──────────┘
                   ▼
                  x₁
                   │
          ┌────────┴────────┐
          │                 │
         LN₂             residual
          │                 │
          ▼                 │
         MoE                │
          │                 │
          └────────┬────────┘
                   ▼
                  x₂

This is the complete computational structure of one block.

16. Shape flow through the block

Let:

x:[B,S,D].
Norm 1
[B,S,D].
Attention
[B,S,D] \rightarrow [B,S,D].

So:

h:[B,S,D].
First residual
x_1:[B,S,D].
Norm 2
[B,S,D].
MoE
[B,S,D] \rightarrow [B,S,D].
Second residual
\boxed{ x_2:[B,S,D]. }

The key property is:

\boxed{ \text{TransformerBlock preserves the model dimension}. }

17. What happens to the KV cache?

This is especially important.

The block receives:

past\_kv.

The attention layer may update it and returns:

new\_cache.

Then the block returns:

return x, new_cache

(Source: Build a DeepSeek Model (From Scratch))

Notice:

\boxed{ \text{MoE does not generate the attention cache}. }

The cache belongs to the attention pathway.

That is why the block simply passes new_cache back upward.

18. Training behavior

During training, the source calls:

x, _ = blk(
    x,
    attn_mask=mask
)

(Source: Build a DeepSeek Model (From Scratch))

Notice:

past\_kv

is not supplied.

The source explicitly says the KV cache is ignored during training because the full input sequence is processed at once. (Source: Build a DeepSeek Model (From Scratch))

Therefore:

Training:

x
 ↓
Norm
 ↓
Attention without cache
 ↓
Residual
 ↓
Norm
 ↓
MoE
 ↓
Residual

19. Inference behavior

During cached inference, the same block can receive:

past\_kv.

Then:

new token
    ↓
Norm
    ↓
Attention
    │
    ├── past cache
    └── position_offset
    ↓
new output + new cache
    ↓
MoE
    ↓
block output

The source explicitly threads past_kv and position_offset through the block to DeepSeekAttention. (Source: Build a DeepSeek Model (From Scratch))

This is elegant because the same TransformerBlock supports both modes.

20. One complete numerical shape trace

Use the source's default dimensions:

B=24
S=256
D=512.

Input:

\boxed{x:[24,256,512]}.
First normalization
[24,256,512]
DeepSeekAttention
[24,256,512]
Residual
x_1:[24,256,512].
Second normalization
[24,256,512].
DeepSeekMoE
[24,256,512].
Final residual
\boxed{ x_2:[24,256,512]. }

So despite all the internal complexity:

\boxed{ [B,S,D]\rightarrow[B,S,D]. }

That is exactly what allows us to stack multiple blocks.

21. Why can we stack blocks?

Because the output shape matches the input shape.

Therefore:

x^{(0)} \rightarrow Block_1 \rightarrow x^{(1)}

then:

x^{(1)} \rightarrow Block_2 \rightarrow x^{(2)}

and so on.

The source later constructs:

self.blocks = nn.ModuleList([
    TransformerBlock(args)
    for _ in range(args.n_layers)
])

(Source: Build a DeepSeek Model (From Scratch))

So with:

n_{\text{layers}}=8

the model creates:

\boxed{8\text{ TransformerBlocks}}.

24. What the block does NOT do

The TransformerBlock itself does not:

  • tokenize text,
  • sample tokens,
  • compute the vocabulary logits,
  • calculate the MTP loss,
  • run the optimizer.

Its job is narrower:

\boxed{ \text{transform one hidden-state tensor into the next hidden-state tensor}. }

It delegates specialized computation to attention and MoE.

25. The entire one-block equation

Let:

a(x)=DeepSeekAttention(LN_1(x)).

Then:

h=x+a(x).

Let:

m(h)=DeepSeekMoE(LN_2(h)).

Then:

\boxed{ Block(x)=h+m(h) }

or:

\boxed{ Block(x) = x+ DeepSeekAttention(LN_1(x)) + DeepSeekMoE \left( LN_2 \left[ x+DeepSeekAttention(LN_1(x)) \right] \right). }

That's the full mathematical structure of the block represented by the source's code. (Source: Build a DeepSeek Model (From Scratch))

26. One subtle systems insight

The block is actually carrying two different kinds of state.

Hidden state
x

moves through the network and becomes the representation used by subsequent blocks.

Attention cache
(c_{kv},k_r)

is maintained for efficient autoregressive inference.

So:

Hidden state
    ↓
Block computation
    ↓
next hidden state

KV cache
    ↓
Attention only
    ↓
updated KV cache

The MoE affects the hidden state but not the KV cache.

This distinction becomes very useful when reasoning about inference memory.
