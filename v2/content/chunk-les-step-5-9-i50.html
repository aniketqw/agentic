Step 5.9 — DeepSeekMath: Where GRPO Came From

Plan node: I7 · chat order #50

Now we move from “how GRPO works” to “why DeepSeek created it and how it was used in DeepSeekMath.”

This is an important transition because DeepSeekMath is the bridge:

\boxed{\text{Math-specialized pretraining}} \rightarrow \boxed{\text{SFT}} \rightarrow \boxed{\text{RL with GRPO}} \rightarrow \boxed{\text{DeepSeekMath-RL}} \rightarrow \boxed{\text{DeepSeek-R1}}

The supplied DeepSeekMath slides identify two central contributions: the DeepSeekMath Corpus and GRPO. The book likewise states that GRPO was introduced in the DeepSeekMath paper and later used for DeepSeek-R1. (Source: deepseekmath-slides)

5.9.1 First: what problem was DeepSeekMath trying to solve?

The target was not merely:

“Make a language model bigger.”

The goal was to make an open 7B model very strong at mathematical reasoning.

The supplied slides state that DeepSeekMath-RL 7B reached:

\boxed{51.7\%}

Top-1 accuracy on the competition-level MATH benchmark, without tools or majority voting. (Source: deepseekmath-slides)

That result came from two ingredients:

\boxed{ \text{better math data} + \text{better RL algorithm} }

Specifically:

\boxed{ \text{DeepSeekMath Corpus} + \text{GRPO} }

(Source: deepseekmath-slides)

This is the first major lesson:

Reasoning performance is not only a model-architecture problem. Data construction and post-training matter enormously.

5.9.2 Contribution 1 — The DeepSeekMath Corpus

Before RL can improve mathematical reasoning, the starting model needs sufficient mathematical knowledge.

That means the first question is:

Where do we get enough high-quality mathematical text?

The slides state that DeepSeek built:

\boxed{\text{120B math tokens}}

from Common Crawl using an iterative classifier-based mining pipeline. (Source: deepseekmath-slides)

This is much larger than the earlier public math corpora discussed in the deck.

The slide explicitly gives:

\text{OpenWebMath}\approx13.6B

versus:

\text{DeepSeekMath Corpus}\approx120.2B.

(Source: deepseekmath-slides)

So the approximate ratio is:

\frac{120.2}{13.6} \approx 8.84.

Thus the DeepSeekMath Corpus is about:

\boxed{8.8\times}

the size of OpenWebMath by token count.

5.9.3 Why not simply search the web for “math”?

Because mathematical content is distributed across the web.

A naive keyword filter would miss:

  • pages where equations dominate but the word “math” is absent,
  • mathematical discussions written in unusual styles,
  • educational pages,
  • forums,
  • multilingual mathematical material.

The DeepSeekMath approach therefore uses a classifier.

The core idea is:

\boxed{\text{teach a classifier what math pages look like}}

and then use that classifier to search the enormous Common Crawl corpus. (Source: deepseekmath-slides)

5.9.4 The iterative mining pipeline

This is one of the most important diagrams from the deck.

The pipeline is:

\boxed{ \text{Seed corpus} \rightarrow \text{train fastText classifier} \rightarrow \text{recall math-like pages} \rightarrow \text{find high-recall domains} \rightarrow \text{human URL-path annotation} \rightarrow \text{expand seed} \rightarrow \text{repeat} }

(Source: deepseekmath-slides)

Let's unpack every stage.

Stage A — Start with a seed corpus

They begin with a relatively small set of known mathematical text.

The deck uses OpenWebMath as the starting seed.

Conceptually:

D_0=\{\text{known math pages}\}.

This is not enough to cover the web.

Stage B — Train a fastText classifier

The seed corpus gives examples of:

y=1:\text{math}

and presumably:

y=0:\text{not math}.

The classifier learns:

f(x)\rightarrow P(\text{math}\mid x).

The deck specifically describes a fastText classifier. (Source: deepseekmath-slides)

Stage C — Search Common Crawl

Now run the classifier against a massive collection of web pages.

For each page:

x_i \rightarrow f(x_i) \rightarrow \text{math score}.

High-scoring pages are candidates for inclusion.

So instead of humans reading billions of pages:

\boxed{\text{classifier does the first large-scale filtering}}

5.9.5 Why classify domains instead of every page?

This is a particularly clever part.

Suppose a domain has many pages.

For example, imagine:

100,000

pages from one website.

Suppose more than 10% of the pages already recalled by the classifier are mathematical.

That is evidence that the domain itself has a strong mathematical region.

Instead of asking humans to inspect:

10,000

individual pages, they identify the useful URL paths.

For example:

mathoverflow.net/questions/

could be marked as a valuable path.

The slide explicitly describes this domain-level annotation strategy as a way of converting huge numbers of page-level judgments into a manageable number of URL-pattern judgments. (Source: deepseekmath-slides)

5.9.6 Why is this better?

Suppose there are:

40B

candidate pages.

Manual page-by-page annotation is obviously infeasible.

But perhaps only a relatively small number of domains have obvious mathematical sections.

So the process changes from:

\boxed{\text{annotate billions of pages}}

to approximately:

\boxed{\text{identify useful domains/URL patterns}}

This is a classic scalable-data-engineering idea:

Find structure at a higher level of abstraction.

5.9.7 Stage D — Human annotation improves the classifier's blind spots

This creates the bootstrapping loop.

Initially:

D_0=\text{small seed}.

Train:

C_0.

Use it to discover new mathematical regions:

D_1.

Then train:

C_1.

And repeat:

D_0 \rightarrow C_0 \rightarrow D_1 \rightarrow C_1 \rightarrow D_2 \rightarrow \cdots

The supplied slides describe this as effectively allowing the classifier's own blind spots to guide the next search round. (Source: deepseekmath-slides)

5.9.8 Why does this work?

Imagine the initial classifier has learned mostly:

\text{“textbook-like mathematics”}.

Then it may fail on:

  • forum discussions,
  • competition solutions,
  • specialized technical pages,
  • different writing styles,
  • different languages.

The newly discovered high-quality domains provide examples of these previously unseen patterns.

So the next classifier becomes broader.

This is essentially:

\boxed{\text{iterative data discovery}}

rather than one-shot filtering.

5.9.9 The process converged

The deck says that after four iterations they reached roughly:

\boxed{35.5M\text{ web pages}}

and:

\boxed{120B\text{ tokens}}.

Iteration 4 was stopped because about:

\boxed{98\%}

of its pages had already been found in iteration 3.

That suggests the seed/data-discovery process had largely converged. (Source: deepseekmath-slides)

Conceptually:

\text{new iteration} \rightarrow \text{very little new information}.

So continuing the mining loop gives diminishing returns.

5.9.10 Exam numerical — corpus growth

Given:

13.6B

tokens initially and:

120.2B

tokens after iterative mining.

Compute the increase:

120.2-13.6 = 106.6B.

So:

\boxed{106.6B}

additional tokens were obtained relative to OpenWebMath.

The multiplicative growth is:

\frac{120.2}{13.6}\approx8.84.

So:

\boxed{\approx8.8\times}

5.9.11 Why does corpus size matter for training?

Suppose the model is trained for:

150B

tokens.

Consider a small dataset:

D=15B.

Then the model must see the same data repeatedly:

\frac{150}{15}=10

times.

But with a:

120B

token corpus:

\frac{150}{120}=1.25

corpus-equivalent passes.

So the model can encounter substantially more fresh text before repetition dominates.

The slides explicitly make this point: smaller datasets plateau earlier because the model repeatedly sees the same data, whereas the much larger DeepSeekMath Corpus sustains continued improvement later in training. (Source: deepseekmath-slides)

5.9.12 The controlled experiment

The deck gives an especially important experimental design:

Keep the model and training-token budget the same; change only the corpus.

It describes:

\boxed{\text{same 1.3B model}}
\boxed{\text{same 150B training tokens}}

and vary the corpus.

The DeepSeekMath Corpus wins across the listed benchmarks. (Source: deepseekmath-slides)

This is good experimental methodology because we are trying to isolate:

\text{effect of corpus quality/scale}.

5.9.13 A very important lesson about scaling

We normally hear:

\text{more parameters}\rightarrow\text{better model}.

DeepSeekMath emphasizes another axis:

\boxed{\text{better data}\rightarrow\text{better model}}.

The deck states that DeepSeekMath-Base 7B outperformed the listed open baselines across all eight benchmarks and even outperformed Minerva 540B on those comparisons. (Source: deepseekmath-slides)

Therefore:

\boxed{ \text{parameter count is not the only scaling lever} }

Data quality and domain specialization can move the curve significantly.

5.9.14 The model initialization matters

DeepSeekMath-Base 7B did not start from a generic general-purpose 7B model.

The supplied deck explicitly says it starts from:

\boxed{\text{DeepSeek-Coder-Base-v1.5}}

rather than a general LLM. (Source: deepseekmath-slides)

This is strategically important.

Why would a code-specialized base help math?

Because mathematical reasoning and code reasoning both benefit from representations involving:

  • symbolic structures,
  • precise syntax,
  • algorithmic reasoning,
  • structured sequences.

The slides state the initialization choice, but they do not in the cited passage provide a complete causal proof that this is why it worked. So that explanatory connection should be treated as interpretation, not as a direct claim from the source.

5.9.15 DeepSeekMath is therefore already specialized before RL

Think of the sequence:

Common Crawl
      │
      ▼
Iterative math mining
      │
      ▼
DeepSeekMath Corpus
      │
      ▼
DeepSeek-Coder-Base-v1.5
      │
      ▼
DeepSeekMath-Base
      │
      ▼
instruction tuning
      │
      ▼
DeepSeekMath-Instruct
      │
      ▼
GRPO + verifiable rewards
      │
      ▼
DeepSeekMath-RL

The last three model names are reflected in the supplied materials, and the RL stage explicitly starts from DeepSeekMath-Instruct. (Source: deepseekmath-slides)

5.9.16 What does SFT do here?

At a high level, SFT gives the model examples of:

(\text{problem},\text{desired reasoning/answer}).

It teaches the model to produce useful solution trajectories.

Then RL does something different.

RL asks:

Among the behaviors the model can generate, which ones should become more probable?

This distinction is crucial.

\boxed{ \text{SFT teaches behavior from demonstrations} }

while:

\boxed{ \text{RL optimizes behavior according to reward} }

This will become very important when we compare SFT, RFT, DPO, PPO and GRPO.

5.9.17 DeepSeekMath-Instruct → DeepSeekMath-RL

The supplied slides give a clean controlled RL experiment.

They apply GRPO to:

\boxed{\text{DeepSeekMath-Instruct}}

using only the chain-of-thought instruction-tuning data for:

\boxed{\text{GSM8K and MATH}}

and no new RL training dataset. (Source: deepseekmath-slides)

5.9.18 The performance change

GSM8K

Before RL:

82.9\%

After RL:

88.2\%.

So:

88.2-82.9 = \boxed{5.3\text{ percentage points}}.
MATH

Before:

46.8\%

After:

51.7\%.

Increase:

51.7-46.8 = \boxed{4.9\text{ percentage points}}.
CMATH

Before:

84.6\%

After:

88.8\%.

Increase:

88.8-84.6 = \boxed{4.2\text{ percentage points}}.

(Source: deepseekmath-slides)

5.9.19 Why is CMATH especially interesting?

The RL data came from:

\text{GSM8K + MATH}.

But the improvement also appears on:

\text{CMATH}.

The slides explicitly point out that CMATH is out-of-domain for the RL data and use this to argue that the improvement generalizes beyond exactly the data trained on. (Source: deepseekmath-slides)

This is much more convincing than merely saying:

“The training reward went up.”

We are seeing:

\boxed{ \text{RL training} \rightarrow \text{better external performance} }

even on a related benchmark not used as the exact RL training source.

5.9.20 Why GRPO instead of PPO?

Now the reason should be completely clear from our previous lessons.

PPO typically needs:

\boxed{\text{policy}} + \boxed{\text{value model}}

GRPO removes the learned value-model path and obtains the learning signal through group-relative comparisons. (Source: Build a Reasoning Model (From Scratch))

Thus:

\boxed{ \text{DeepSeekMath} \rightarrow \text{GRPO} \rightarrow \text{later DeepSeek-R1} }

The book explicitly identifies GRPO as the algorithm introduced in DeepSeekMath and later used for DeepSeek-R1. (Source: Build a Reasoning Model (From Scratch))

5.9.21 The key insight: group-relative comparison

Suppose one math prompt produces:

4

responses:

R=[1,1,0,0].

Mean:

\mu=0.5.

So the model doesn't merely learn:

“Response 1 is correct.”

It learns:

“Responses 1 and 2 performed better than the other sampled responses for this same problem.”

Thus:

A_{1},A_{2}>0

and:

A_{3},A_{4}<0.

This produces both:

\boxed{\text{reinforcement}}

and:

\boxed{\text{suppression}}.

The supplied DeepSeekMath slides later make this comparison against Online RFT explicit: GRPO's continuous advantage gives stronger reinforcement to above-average responses and actively penalizes below-average ones. (Source: deepseekmath-slides)

5.9.22 Why Online RFT is weaker than GRPO

This is a beautiful exam/interview concept.

Suppose we use:

R\in\{0,1\}.

Online RFT effectively treats:

R=1

as:

\text{reinforce}.

But all correct responses get roughly the same binary signal.

GRPO instead computes:

A_i= \frac{R_i-\mu}{\sigma+\epsilon}.

Now the coefficient is relative to the group.

The deck describes GRPO's richer gradient coefficient as the reason it beats Online RFT on both GSM8K and MATH in the displayed comparison. (Source: deepseekmath-slides)

5.9.23 An important conceptual decomposition

The DeepSeekMath deck offers a useful unifying perspective:

\boxed{ \text{SFT, RFT, DPO, PPO, GRPO} }

can be viewed through two major questions:

1. Where does the training data come from?

For example:

\text{offline} \quad\text{vs}\quad \text{online}.
2. How strongly should each token be pushed?

That is the gradient coefficient / learning signal.

The supplied deck explicitly frames these methods as differing along these axes.

This perspective becomes extremely useful because it prevents you from treating:

\text{SFT},\text{RFT},\text{DPO},\text{PPO},\text{GRPO}

as five completely unrelated algorithms.

5.9.24 Online vs offline — critical distinction

Offline

Generate responses once from a fixed model:

\pi_0 \rightarrow \text{dataset} \rightarrow \text{train}.

RFT and DPO in the deck are categorized this way.

Online

Keep generating from the current policy:

\pi_t \rightarrow \text{new responses} \rightarrow \text{reward} \rightarrow \pi_{t+1}.

Online RFT and GRPO are described this way. (Source: deepseekmath-slides)

As training progresses:

\pi_t\neq\pi_0.

Therefore online methods continually receive data from the model they are currently training.

5.9.25 Why does this become increasingly important?

Early in training:

\pi_t\approx\pi_0.

So the distinction between frozen-data generation and fresh sampling is smaller.

Later:

\pi_t

may be substantially different.

Then a fixed dataset describes the old policy's behavior, whereas online sampling reveals the current policy's behavior.

The slides explicitly state that online methods pull ahead as the current policy diverges from the original SFT model, with Online RFT outperforming offline RFT in the cited comparison. (Source: deepseekmath-slides)

5.9.26 Numerical checkpoint

Suppose an online RL system generates:

G=8

responses per prompt, and:

3

are correct.

Then:

R=[1,1,1,0,0,0,0,0].

Mean:

\mu_R = \frac{3}{8} = 0.375.

The correct responses have:

R_i-\mu_R = 1-0.375 = 0.625.

The incorrect responses have:

0-0.375 = -0.375.

Before standardization, you can already see the direction:

\boxed{+0.625\text{ for correct}}
\boxed{-0.375\text{ for incorrect}}.

After dividing by the group standard deviation, these become normalized advantages.

5.9.27 Very important: why multiple samples are necessary

Suppose we generate only:

G=1

response.

Then:

\mu=R_1.

Hence:

R_1-\mu=0.

There is no meaningful group-relative comparison.

So GRPO inherently needs:

\boxed{G>1}

for a meaningful group baseline.

This is exactly why GRPO's sampling structure differs from a one-response-per-prompt PPO-style setup. (Source: Build a DeepSeek Model (From Scratch))

5.9.28 DeepSeekMath's central design philosophy

The whole process can now be viewed as:

\boxed{ \text{Start with strong domain data} }

then:

\boxed{ \text{teach the model to solve problems} }

then:

\boxed{ \text{sample multiple attempts} }

then:

\boxed{ \text{verify correctness} }

then:

\boxed{ \text{compare attempts within each problem} }

then:

\boxed{ \text{increase probability of stronger reasoning trajectories} }

That is the conceptual heart of DeepSeekMath.

5.9.29 Exam question: why does better data matter even with the same compute?

Suppose:

\text{Model}=1.3B

and:

\text{Training tokens}=150B.

Experiment A uses corpus A.

Experiment B uses corpus B.

Everything else is held constant.

If:

\text{Performance}_B> \text{Performance}_A,

then the improvement is evidence that:

\boxed{\text{data composition/quality matters}}

rather than the improvement being explained simply by:

\text{model size}

or:

\text{training-token budget}.

That is the logic behind the controlled corpus comparison in the slides. (Source: deepseekmath-slides)

5.9.30 Exam numerical: RL gain

MATH accuracy goes:

46.8\%\rightarrow51.7\%.

Absolute improvement:

\boxed{4.9\text{ percentage points}}.

Relative percentage improvement:

\frac{51.7-46.8}{46.8}\times100
= \frac{4.9}{46.8}\times100 \approx10.47\%.

So the distinction is:

\boxed{4.9\text{ percentage points}}

versus approximately:

\boxed{10.5\%\text{ relative improvement}}.

Do not confuse those two in an exam.

5.9.31 One more numerical: corpus repetition

Suppose:

D=20B

training tokens are available and we train on:

100B

tokens.

Approximate corpus-equivalent exposure:

\frac{100}{20}=5.

So the model sees the equivalent of:

\boxed{5\text{ corpus passes}}.

If instead:

D=120B

and:

T=100B,

then:

\frac{100}{120}=0.833.

So the model does not even need one full corpus-equivalent pass.

This is the intuition behind why a large corpus can avoid rapid repetition. The slides make this exact qualitative point. (Source: deepseekmath-slides)

5.9.32 The DeepSeekMath → DeepSeek-R1 connection

This is worth memorizing:

\boxed{ \text{DeepSeekMath introduced GRPO} }

and later:

\boxed{ \text{DeepSeek-R1 used the same family of ideas} }

The book explicitly presents GRPO as originally introduced in DeepSeekMath and later used for DeepSeek-R1. (Source: Build a Reasoning Model (From Scratch))

So when you study DeepSeek-R1, do not think:

“GRPO suddenly appeared in R1.”

It did not.

The lineage is:

\boxed{ \text{DeepSeekMath} \rightarrow \text{GRPO} \rightarrow \text{DeepSeek-R1} }

5.9.33 The most important mental model from Step 5.9

DeepSeekMath is not simply:

\boxed{\text{7B model + RL}}

It is:

\boxed{ \begin{array}{c} \text{Specialized high-quality math corpus}\\ \downarrow\\ \text{domain-specialized pretrained model}\\ \downarrow\\ \text{instruction tuning}\\ \downarrow\\ \text{online rollouts}\\ \downarrow\\ \text{verifiable rewards}\\ \downarrow\\ \text{group-relative advantages}\\ \downarrow\\ \text{GRPO optimization}\\ \downarrow\\ \text{DeepSeekMath-RL} \end{array} }

And this gives us a clean division of labor:

\boxed{ \text{Pretraining} \rightarrow \text{knowledge} }
\boxed{ \text{SFT} \rightarrow \text{demonstrated behavior} }
\boxed{ \text{GRPO/RL} \rightarrow \text{optimize successful behavior} }
