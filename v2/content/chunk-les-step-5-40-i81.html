Fine-Grained Expert Segmentation + Shared Expert Isolation

We have solved the routing imbalance problem conceptually. Now we address the two architectural problems that ordinary MoE still has:

\boxed{\text{Knowledge Hybridity}}

and

\boxed{\text{Knowledge Redundancy}}

DeepSeek addresses them with:

\boxed{ \text{Fine-Grained Expert Segmentation} }

and:

\boxed{ \text{Shared Expert Isolation} }

The source presents these as the first two major DeepSeek-MoE innovations. (Source: Build a DeepSeek Model (From Scratch))

5.40.1 First, remember what ordinary MoE gave us

Suppose we start with a conventional MoE:

\boxed{16\text{ experts}}

and each expert has hidden dimension:

\boxed{4096}.

Conceptually:

E_1,E_2,\ldots,E_{16}

are sixteen relatively large FFNs.

A router chooses, say:

k=2

for each token.

So:

\boxed{ 16\text{ available experts} \rightarrow 2\text{ active experts/token} }

This is efficient.

But the source asks:

Are 16 large experts really the best way to divide knowledge?

The answer is no.

5.40.2 Problem #1 — Knowledge Hybridity

Imagine the training data contains:

\text{Python} + \text{Mathematics} + \text{Law} + \text{History} + \text{Conversational text}.

With only a few large experts, an individual expert may receive tokens belonging to several unrelated domains.

So instead of becoming:

\boxed{\text{Python specialist}}

it becomes something like:

\boxed{ \text{Python} + \text{law} + \text{grammar} + \text{history} +\cdots }

That is what the source calls:

\boxed{\text{Knowledge Hybridity}}.

The source's intuition is that with too few experts, each expert becomes a “jack-of-all-trades,” preventing deep specialization. (Source: Build a DeepSeek Model (From Scratch))

5.40.3 The obvious idea

Instead of:

16

large experts, create many smaller experts.

For example:

\boxed{64\text{ experts}}

with a smaller hidden dimension:

\boxed{1024}.

So:

Conventional
16\times4096
Fine-grained
64\times1024

The source deliberately gives this exact example. (Source: Build a DeepSeek Model (From Scratch))

5.40.4 First numerical observation

Conventional expert capacity:

16\times4096 = \boxed{65,536}.

Fine-grained expert capacity:

64\times1024 = \boxed{65,536}.

Therefore:

\boxed{ 16\times4096 = 64\times1024 }

The total hidden-dimension capacity is unchanged.

This is the key trick.

5.40.5 What actually changed?

We did not necessarily make the model larger.

We changed:

\boxed{\text{number of containers}}

and:

\boxed{\text{size of each container}}.

Before:

16\text{ large containers}

After:

64\text{ smaller containers}.

So the same overall capacity is divided more finely.

The source explicitly says the total number of expert parameters and activated parameters can remain the same while the knowledge is divided into a larger number of more specialized containers. (Source: Build a DeepSeek Model (From Scratch))

5.40.6 Why does this improve specialization?

Suppose the model has only 4 broad experts:

E_1,E_2,E_3,E_4.

A single expert may have to represent:

\text{code + legal + mathematics}.

But with 64 experts, the routing space is much finer.

The source's conceptual examples include possibilities such as a specialist for:

\text{Python syntax}

another for:

\text{legal terminology}

another for:

\text{poetic language}.

These are illustrative descriptions of possible specialization, not a guarantee that the learned experts acquire exactly those labels. (Source: Build a DeepSeek Model (From Scratch))

5.40.7 Why “fine-grained”?

Because the routing granularity changes.

Think of conventional MoE as having broad bins:

\boxed{ \text{Bin A} \quad \text{Bin B} \quad \text{Bin C} \quad \text{Bin D} }

while fine-grained MoE has:

\boxed{ 64\text{ narrower bins} }

The router gets more choices.

Therefore the token-to-expert mapping can become more precise.

5.40.8 The subtle point about Top-K

Suppose conventional MoE uses:

N=16,\quad k=2.

Then a token gets:

2/16

of the expert choices activated.

Now fine-grained MoE uses:

N=64.

If we still use:

k=2,

then the token sees two of sixty-four experts.

This creates a much narrower routing decision.

But there is another important design possibility:

increase N while also changing expert size and k so that total activated parameters remain approximately comparable.

The source explicitly notes that the total expert parameters and activated parameters can remain the same under the fine-grained construction. (Source: Build a DeepSeek Model (From Scratch))

So don't memorize:

“Fine-grained always means more experts and the exact same k.”

The deeper principle is:

\boxed{ \text{more experts} + \text{smaller experts} }

with capacity controlled appropriately.

5.40.9 Parameter-count derivation

Let an expert FFN have:

d_{\text{model}}=D

and hidden dimension:

H.

Ignoring biases, a two-layer FFN has approximately:

DH+HD

parameters:

\boxed{ 2DH }.

For N experts:

\boxed{ P_{\text{experts}} \approx 2NDH }.

Now suppose we increase experts from:

N

to:

aN

and reduce hidden dimension from:

H

to:

\frac{H}{a}.

Then:

P'_{\text{experts}} = 2(aN)D\left(\frac Ha\right).

Cancel a:

\boxed{ P'_{\text{experts}} = 2NDH }.

So total expert parameters remain approximately unchanged.

This is the mathematical reason the source's example works.

5.40.10 Exam numerical

Suppose:

D=2048.

Conventional MoE:

N=8,\quad H=4096.

Expert parameters:

2(8)(2048)(4096)
= \boxed{134,217,728}.

Now create:

N'=32

experts and:

H'=1024.

Then:

2(32)(2048)(1024)
= \boxed{134,217,728}.

Same total expert parameter count.

But instead of 8 broad experts:

\boxed{32\text{ narrower experts}}.

That is fine-grained segmentation.

5.40.11 Activated-parameter numerical

Suppose the original model has:

N=16,\qquad H=4096

and activates:

k=2.

Activated expert parameters per token are approximately:

2\times2D(4096) = 4D(4096).

Now split into:

N=64,\qquad H=1024

and suppose the architecture chooses:

k'=8

to preserve the same activated capacity.

Then:

8\times2D(1024) = 16D(1024) = 4D(4096).

Thus:

\boxed{ k'H'=kH }

is the key relation for preserving approximately the same activated FFN capacity.

This is an exam-style inference from the parameter formulas; the source's exact discussion states that activated parameters can remain the same, but does not prescribe this exact symbolic derivation.

5.40.12 This solves one problem—but not the other

Fine-grained experts address:

\boxed{\text{Knowledge Hybridity}}

because experts can become narrower specialists.

But now consider this:

Every specialized expert still needs foundational knowledge.

For example:

Python expert

needs:

\text{basic grammar}.
Medical expert

needs:

\text{basic grammar}.
Legal expert

needs:

\text{basic grammar}.
Mathematics expert

needs:

\text{basic language understanding}.

So common information gets duplicated across experts.

That is:

\boxed{\text{Knowledge Redundancy}}.

The source explicitly uses this reasoning to motivate the second innovation. (Source: Build a DeepSeek Model (From Scratch))

5.40.13 Why redundancy is expensive

Suppose each specialized expert has:

100M

parameters.

If every expert spends:

20M

parameters learning shared/common information, then with:

64

experts:

64\times20M = \boxed{1.28B}

parameters are being used for repeated common knowledge.

That capacity could instead be devoted to specialized knowledge.

This numerical example is illustrative; the source's point is qualitative: duplicated foundational knowledge consumes expert capacity and hinders specialization. (Source: Build a DeepSeek Model (From Scratch))

5.40.14 DeepSeek's second idea

Instead of asking every routed expert to relearn common knowledge:

\boxed{\text{create dedicated shared experts}}

These are a small set of dense experts.

So now we divide the MoE layer into:

\boxed{ \text{Shared Experts} + \text{Routed Experts} }

(Source: Build a DeepSeek Model (From Scratch))

5.40.15 Routed experts

These are our fine-grained specialists.

Each token is sent only to:

k

of them.

Thus:

\boxed{ \text{Routed Experts} = \text{sparse} }

For a token:

x_t,

the router determines:

TopK(x_t)

and only those experts execute.

5.40.16 Shared experts

The shared experts are completely different.

Every token passes through:

\boxed{\text{all shared experts}}.

So:

\boxed{ \text{Shared Experts} = \text{dense} }

This is explicitly stated in the source. (Source: Build a DeepSeek Model (From Scratch))

5.40.17 Why should every token see shared experts?

Because they store common knowledge.

Think of the division as:

\boxed{ \text{Shared path} = \text{general knowledge} }

and:

\boxed{ \text{Routed path} = \text{specialized knowledge} }.

Therefore the routed experts don't have to waste as much capacity learning the same fundamentals.

The source describes the shared experts as the central repository for common foundational knowledge, while routed experts are freed to focus on narrower domains. (Source: Build a DeepSeek Model (From Scratch))

5.40.18 Simple analogy

Imagine a hospital.

Every patient first receives care from:

\boxed{\text{general physician}}

for common medical needs.

Then the patient is routed to:

\boxed{\text{cardiologist}}

or:

\boxed{\text{neurologist}}

or:

\boxed{\text{orthopedic specialist}}.

The general physician handles:

\text{common knowledge}.

The specialist handles:

\text{specific knowledge}.

That is a useful conceptual analogy for:

\boxed{ \text{shared experts + routed experts} }.

5.40.19 Mathematical architecture

Let:

x

be a token representation.

Shared expert outputs:

S_j(x),\qquad j=1,\ldots,N_s.

The dense shared output is:

\boxed{ S(x)=\sum_{j=1}^{N_s}S_j(x) }

for the source-style simplified implementation.

Now the routed path:

R(x) = \sum_{i\in TopK(x)} g_iE_i(x).

So the MoE result becomes:

\boxed{ y= x+S(x)+R(x) }

in the source's complete implementation, where the direct x term is the residual path. (Source: Build a DeepSeek Model (From Scratch))

5.40.20 Why is the residual x included?

The source's complete architecture has three parallel paths:

\boxed{ \text{Residual} }
\boxed{ \text{Shared experts} }
\boxed{ \text{Routed experts} }

and sums:

\boxed{ x+shared\_out+routed\_out }.

(Source: Build a DeepSeek Model (From Scratch))

The residual path preserves the original representation and maintains the Transformer residual-stream structure.

5.40.21 Full data flow

Now the architecture looks like this:

\boxed{x}

splits into two computational branches.

Branch A
x \rightarrow \boxed{\text{Shared Expert 1}}
x \rightarrow \boxed{\text{Shared Expert 2}}
\cdots

All tokens pass through them.

Branch B
x \rightarrow \boxed{\text{Router}}
\rightarrow \boxed{\text{Top-K}}
\rightarrow \boxed{\text{selected routed experts only}}

Then:

\boxed{ y=x+shared+routed }

This is the architectural picture you should have in your mind.

5.40.22 The three responsibilities

This gives us a beautiful division:

Component Main responsibility
Shared experts Common/foundational knowledge
Routed experts Specialized knowledge
Router Select which specialists to activate

So:

\boxed{ \text{Shared = generalist} }
\boxed{ \text{Routed = specialist} }
\boxed{ \text{Router = dispatcher} }

5.40.23 Why shared experts do not destroy sparsity

A common confusion is:

“If shared experts process every token, haven't we lost MoE sparsity?”

No.

Only the shared path is dense.

The large pool of routed experts remains sparse.

Suppose:

N_r=64

routed experts and:

k=8.

Every token executes:

8

routed experts, not 64.

Then suppose:

N_s=2

shared experts.

Every token executes those 2 shared experts as well.

So total expert executions per token:

\boxed{2+8=10}

rather than:

66.

This is the key architectural balance.

5.40.24 Parameter numerical: shared + routed

Suppose:

D=2048.

Each routed expert has:

H_r=1024.

There are:

64

routed experts.

Total routed parameters:

2(64)(2048)(1024)
= \boxed{268,435,456}.

Now create:

2

shared experts of hidden dimension:

1024.

Their total parameters:

2(2)(2048)(1024) = \boxed{8,388,608}.

Total expert parameters:

268,435,456+8,388,608 = \boxed{276,824,064}.

But per token, only:

8

routed experts are active plus the:

2

shared experts.

So:

\boxed{10\text{ expert computations/token}}

instead of:

66.

Again, these numbers are illustrative.

5.40.25 Why this creates better specialization

Before:

E_i = \boxed{\text{specialized knowledge + common knowledge}}

After shared isolation:

\boxed{ E_i \approx \text{specialized knowledge} }

while:

\boxed{ S_j \approx \text{common knowledge} }.

Therefore:

\boxed{ \text{routed experts can spend more capacity on specialization} }.

This is exactly the conceptual benefit the source attributes to shared expert isolation. (Source: Build a DeepSeek Model (From Scratch))

5.40.26 Connecting both innovations

Now notice how the two ideas solve two different problems.

Innovation 1

Fine-grained segmentation:

\boxed{ \text{Many small experts} }

solves:

\boxed{ \text{Knowledge Hybridity} }

because each expert has a narrower role.

Innovation 2

Shared expert isolation:

\boxed{ \text{Small dense generalist path} }

solves:

\boxed{ \text{Knowledge Redundancy} }

because common knowledge is centralized.

Together:

\boxed{ \text{Fine-grained specialists} + \text{shared generalists} }

produce the DeepSeek specialization strategy.

5.40.27 A compact comparison

Conventional MoE
\boxed{ \text{few large routed experts} }

Potential issue:

\text{knowledge hybridity}

and:

\text{redundancy}.
DeepSeek-style
\boxed{ \text{many small routed experts} + \text{few shared dense experts} }

This gives:

\boxed{ \text{narrow specialists} + \text{common foundation} }.

5.40.28 Now combine it with Step 5.39

Remember our loss-free balancing:

L'=L+b.

Now the routed path becomes:

L' \rightarrow TopK \rightarrow softmax \rightarrow specialized experts.

Thus all three DeepSeek innovations now fit together:

\boxed{ \text{Fine-grained experts} }

give specialization.

\boxed{ \text{Shared experts} }

give common knowledge.

\boxed{ \text{Dynamic bias} }

keeps routing balanced.

This is why these innovations are much more meaningful together than individually.

5.40.29 Complete DeepSeek-MoE conceptual equation

A source-style simplified expression is:

\boxed{ y_t = x_t + \sum_{j=1}^{N_s}S_j(x_t) + \sum_{i\in TopK_t}g_{t,i}E_i(x_t) }

where:

  • x_t: original token representation,
  • S_j: shared expert j,
  • E_i: routed expert i,
  • TopK_t: selected routed experts for token t,
  • g_{t,i}: routing weight.

And before selecting routed experts:

\boxed{ L_t'=L_t+b }

where b is the dynamically adjusted expert bias.

The source's implementation follows precisely this three-path structure.

5.40.30 Tensor shapes

Suppose:

X\in\mathbb R^{B\times S\times D}.

Flatten:

X_f\in\mathbb R^{BS\times D}.

Suppose:

N_r

routed experts.

Router matrix:

W_R\in\mathbb R^{D\times N_r}.

Therefore:

L=X_fW_R

has:

\boxed{ BS\times N_r }.

After Top-K:

\boxed{ BS\times k }

indices and gating weights.

Routed result:

\boxed{ BS\times D }.

Shared path:

\boxed{ B\times S\times D }.

Final:

\boxed{ B\times S\times D }.

Thus the MoE layer still fits neatly into the Transformer residual stream.

5.40.31 Exam numerical — tensor routing

Suppose:

B=8,
S=1024,
D=4096,
N_r=128,
k=8.

Total tokens:

8\times1024 = \boxed{8192}.

Router logits:

\boxed{ 8192\times128 }.

Top-K indices:

\boxed{ 8192\times8 }.

Total routed expert assignments:

8192\times8 = \boxed{65,536}.

Ideal average assignments per routed expert:

\frac{65,536}{128} = \boxed{512}.

Excellent exam question because it combines:

\text{batch shape} + \text{router} + \text{Top-K} + \text{load balancing}.

5.40.32 Exam numerical — fine-grained preservation

Conventional:

N=16,\quad H=4096.

Fine-grained:

N'=64,\quad H'=1024.

Check:

16\times4096 = 65,536

and:

64\times1024 = 65,536.

Thus:

\boxed{ \text{same aggregate expert hidden capacity} }.

The expert count increased:

64/16 = \boxed{4\times}.

The individual expert size decreased:

1024/4096 = \boxed{1/4}.

So:

\boxed{ 4\times\text{ more experts} ,\quad 1/4\text{ size per expert} }.

5.40.33 Exam numerical — specialization reasoning

Suppose a conventional MoE has:

8

experts.

The dataset effectively contains 8 broad domains.

In a simplified idealization:

1\text{ expert/domain}.

Now split into:

64

experts.

The router has:

64/8 = \boxed{8\times}

more expert choices.

The source's argument is not that there will literally be exactly one expert per semantic category. The point is that the larger pool provides finer routing granularity and therefore more opportunity for specialization. (Source: Build a DeepSeek Model (From Scratch))

5.40.34 One subtle but important correction to your mental model

Do not memorize:

\boxed{\text{one expert = one topic}}

That is too simplistic.

A trained expert's function is learned from optimization.

It may respond to:

\text{linguistic patterns} + \text{domain patterns} + \text{syntactic structures} + \text{other learned features}.

The source uses “Python specialist,” “legal terminology,” etc. as intuition for specialization, not as a strict partition of the knowledge space. (Source: Build a DeepSeek Model (From Scratch))

The correct mental model is:

\boxed{ \text{experts tend toward differentiated specialization} }

rather than:

\boxed{ \text{each expert owns exactly one human-defined subject}. }

5.40.36 Final architecture

For each token x_t:

Shared path
\boxed{ x_t\rightarrow S_1,S_2,\ldots,S_{N_s} }

Every token.

Routed path
x_t \rightarrow L_t \rightarrow L_t+b \rightarrow TopK \rightarrow \text{selected }E_i

Only selected specialists.

Combine
\boxed{ y_t= x_t+ \sum_jS_j(x_t) + \sum_{i\in TopK_t}g_{t,i}E_i(x_t) }

This is the most important equation from the entire MoE section so far. (Source: Build a DeepSeek Model (From Scratch))

5.40.37 The four questions you should be able to answer in an exam

Q1. Why does DeepSeek increase the number of experts?

Because few large experts create:

\boxed{\text{knowledge hybridity}}

and many smaller experts provide finer specialization. (Source: Build a DeepSeek Model (From Scratch))

Q2. Why reduce expert size when increasing expert count?

To preserve approximately the same total expert parameter capacity:

\boxed{ N'H'\approx NH }

in the source's illustrative construction. (Source: Build a DeepSeek Model (From Scratch))

Q3. Why add shared experts?

To provide common foundational knowledge so routed experts don't redundantly relearn it. (Source: Build a DeepSeek Model (From Scratch))

Q4. Are shared experts sparse?

No.

\boxed{ \text{shared experts are dense} }

Every token uses them.

The routed experts are the sparse part. (Source: Build a DeepSeek Model (From Scratch))

5.40.38 Final memory trick

Remember:

\boxed{ \text{MORE} }
M — Many

Many small experts.

O — One common path

Shared experts handle common knowledge.

R — Route sparsely

Only a few routed experts per token.

E — Equalize load

Dynamic bias keeps expert utilization balanced.

So:

\boxed{ \text{Many specialists + One shared foundation + Sparse routing + Equalized load} }

That is the DeepSeek-MoE story we have built so far.
