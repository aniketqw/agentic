The adapter can be algebraically absorbed into the frozen weight for compatible inference.

Prerequisites: LoRA orientation and the complete slide numerical

Notation and assumptions

Wmerged=W+(alpha/r)BA; same arithmetic precision and no active adapter dropout. One factor zero, the other nonzero initializes an unchanged base.

Derivation and mechanism

  1. At zero update, verify outputs equal the pretrained base.
  2. After training, form the scaled matrix update once.
  3. Replace the effective inference weight; compare separate and merged outputs.

Worked example

For the P01 example, merged W=[[4,5],[2,5],[1,2]]. X=[1,1,1] yields[7,12], equal to the separate branch. At one zero factor the update is zero; both zero factors would also kill their initial bilinear gradients.

Limitations

  • Finite-precision merging can differ numerically.
  • Changing adapters, unmerged dropout and quantized-base merging need separate contracts.

Connections to later concepts

  • Q08 keeps a quantized base; merging then requires a precision/requantization contract beyond exact real-number algebra.

Step 3.4 — LoRA Initialization, Training, Scaling, and Merge

Plan node: I3 · chat order #29

We now know what LoRA is and where it is inserted into the Transformer. The next important question is:

How does LoRA actually learn anything if the original LLM is frozen?

This step follows the LoRA implementation in Build a Large Language Model From Scratch, while also connecting it to the PEFT slides. The book initializes one LoRA factor randomly and the other to zero, freezes the original model parameters, trains only the LoRA parameters, and keeps the LoRA weights separate from the pretrained weights during use. (Source: Build a Large Language Model (From Scratch))

1. Start from ordinary fine-tuning

Suppose a pretrained linear layer has

W_0\in\mathbb{R}^{d\times d_{\text{out}}}

and input

X\in\mathbb{R}^{m\times d}.

Normally, during fine-tuning:

W'=W_0+\Delta W

and the output is

Y=XW'.

Therefore,

Y=X(W_0+\Delta W)

so

\boxed{Y=XW_0+X\Delta W}

The problem is that \Delta W has exactly the same size as W_0.

For a 4096\times4096 matrix,

4096\times4096=16,777,216

parameters must potentially be trained.

LoRA says:

Rather than learning the entire \Delta W, learn a low-rank approximation.

The book describes LoRA as learning smaller matrices A and B whose product approximates the weight update. (Source: Build a Large Language Model (From Scratch))

2. LoRA forward computation

There are two notational conventions in the materials, so this is an important exam point.

Book convention

The Raschka implementation uses

A\in\mathbb{R}^{d\times r}

and

B\in\mathbb{R}^{r\times d_{\text{out}}}.

Thus

AB\in\mathbb{R}^{d\times d_{\text{out}}},

which is exactly the shape of W_0.

The LoRA layer computes:

\boxed{ Y=XW_0+\alpha XAB }

in the book's implementation. (Source: Build a Large Language Model (From Scratch))

Equivalently,

Y=X(W_0+\alpha AB).

So the effective weight is

\boxed{W_{\text{eff}}=W_0+\alpha AB}

for the book's notation.

PEFT-slide convention

The slides use the other ordering:

B\in\mathbb{R}^{d\times r},\qquad A\in\mathbb{R}^{r\times d_{\text{out}}},

so their update is written as something like

W'=W_0+\frac{\alpha}{r}BA.

The mathematics is the same idea; only the names/order and scaling convention differ.

Do not blindly memorize whether the smaller matrix is called A or B. For an exam, follow the notation given in the question.

3. Why initialize one matrix to zero?

This is one of the most important ideas in the entire LoRA topic.

The book initializes:

A=\text{random}

and

\boxed{B=0}.

Its implementation uses Kaiming-uniform initialization for A and zeros for B. (Source: Build a Large Language Model (From Scratch))

Therefore initially,

AB=A0=0.

So

W_{\text{eff}} = W_0+\alpha AB = W_0.

Hence:

\boxed{Y_{\text{initial}}=XW_0}

The LoRA branch contributes nothing initially.

The book explicitly notes that this leaves the pretrained model's behavior unchanged at initialization. (Source: Build a Large Language Model (From Scratch))

4. Why is this useful?

Imagine your pretrained model already works reasonably well.

You do not want LoRA to suddenly inject a random perturbation into every projection.

If A and B were randomly initialized, then

AB\neq0

and therefore

W_{\text{eff}}\neq W_0.

You would immediately change the pretrained model's behavior before training.

Instead:

\boxed{B=0\Rightarrow AB=0\Rightarrow W_{\text{eff}}=W_0}

So training begins from the original model.

5. A subtle but VERY important gradient idea

Now comes a beautiful part of LoRA.

Suppose

Y=XW_0+\alpha XAB

and let

G=\frac{\partial L}{\partial Y}.

The base weight W_0 is frozen.

The trainable variables are A and B.

For the book's notation:

A:d\times r,\qquad B:r\times d_{\text{out}}.

The gradients are

\boxed{ \frac{\partial L}{\partial B} = \alpha (XA)^T G }

and

\boxed{ \frac{\partial L}{\partial A} = \alpha X^T G B^T }

These equations are a mathematical derivation from the LoRA forward equation.

6. What happens on the very first training step?

Initially:

B=0.

Therefore:

\frac{\partial L}{\partial A} = \alpha X^TGB^T = 0.

But:

\frac{\partial L}{\partial B} = \alpha(XA)^TG

can be nonzero because A is randomly initialized.

So initially:

\boxed{\nabla_A L=0}

while usually

\boxed{\nabla_B L\neq0}.

Therefore B can start moving.

After B becomes nonzero, gradients can flow into A as well.

Conceptual picture
\boxed{ \text{Initialize } A\text{ randomly}, B=0 }

↓

\boxed{ \text{first step: }B\text{ learns} }

↓

\boxed{ B\neq0 }

↓

\boxed{ A\text{ also starts receiving gradients} }

This is an excellent exam/interview question.

7. Why not initialize BOTH A and B to zero?

Because then:

A=0,\qquad B=0.

The gradients become:

\frac{\partial L}{\partial B} = \alpha(XA)^TG = 0

and

\frac{\partial L}{\partial A} = \alpha X^TGB^T = 0.

So both matrices remain stuck at zero.

Thus:

\boxed{\text{both-zero initialization is a bad idea}}

The useful initialization is asymmetric:

\boxed{A\text{ random},\quad B=0}

for the book's convention. (Source: Build a Large Language Model (From Scratch))

8. Numerical Example — first LoRA gradient

Let's make this completely concrete.

Suppose

X= \begin{bmatrix} 1&2 \end{bmatrix}

and

A= \begin{bmatrix} 0.5\\ 1 \end{bmatrix}.

Let

B= \begin{bmatrix} 0 \end{bmatrix}

and

\alpha=2.

Suppose the pretrained layer produces

XW_0=3

and target is

t=5.

Use

L=\frac12(Y-t)^2.

Because B=0,

Y=3.

Therefore

\frac{\partial L}{\partial Y} = Y-t = 3-5=-2.

So

G=-2.

First compute

XA = [1\quad2] \begin{bmatrix} 0.5\\ 1 \end{bmatrix} = 2.5.

Then

\frac{\partial L}{\partial B} = \alpha(XA)^TG.

Therefore:

\frac{\partial L}{\partial B} = 2(2.5)(-2) = \boxed{-10}.

And because B=0,

\frac{\partial L}{\partial A}=0.

So:

\boxed{ \nabla_B L=-10,\qquad \nabla_A L=0 }

This is exactly the initialization behavior we just derived.

9. One SGD update

Suppose the learning rate is

\eta=0.02.

SGD:

B_{\text{new}} = B-\eta\nabla_B L.

Thus:

B_{\text{new}} = 0-0.02(-10) = \boxed{0.2}.

Now the LoRA branch is no longer zero.

10. What happens on the next step?

Now:

B=0.2.

Suppose again

Y=XW_0+\alpha(XA)B.

We have

XW_0=3

and

\alpha(XA)B = 2(2.5)(0.2) = 1.

Therefore:

Y=4.

Target is 5, so

G=4-5=-1.

Now:

\frac{\partial L}{\partial A} = \alpha X^TGB^T.

Hence:

\frac{\partial L}{\partial A} = 2 \begin{bmatrix} 1\\2 \end{bmatrix} (-1)(0.2)

giving

\boxed{ \nabla_A L= \begin{bmatrix} -0.4\\ -0.8 \end{bmatrix} }

Now A also learns.

This gives us the complete learning mechanism:

\boxed{ B=0 \rightarrow B\text{ starts learning} \rightarrow B\neq0 \rightarrow A\text{ also learns} }

11. Freeze the original model

LoRA's second fundamental idea is:

\boxed{\text{do not update }W_0}

The original pretrained parameters are frozen.

The book explicitly does:

for param in model.parameters():
    param.requires_grad = False

before inserting LoRA layers. (Source: Build a Large Language Model (From Scratch))

In the book's GPT-2 example:

124,441,346

parameters are initially present, but after freezing:

\boxed{0}

parameters are trainable. Then LoRA parameters are introduced. (Source: Build a Large Language Model (From Scratch))

12. Which parameters actually learn?

Suppose the layer is

W_0

plus LoRA parameters

A,B.

During training:

W_0=\text{fixed}

while

A,B=\text{trainable}.

Therefore the optimizer conceptually performs:

A\leftarrow A-\eta\nabla_A L
B\leftarrow B-\eta\nabla_B L.

But:

W_0\not\leftarrow W_0-\eta\nabla_{W_0}L.

Its gradient is unnecessary for updating the model because it is frozen.

13. Why does this save memory?

For a normal 4096\times4096 matrix:

N_{\text{full}}=4096^2 =16,777,216.

With rank

r=8,

LoRA stores:

4096(8)+(8)(4096)

so

N_{\text{LoRA}} = 65,536.

Thus:

\frac{16,777,216}{65,536} = \boxed{256}.

So the trainable parameter count for that matrix is reduced by

\boxed{256\times}.

This exact example appears in the PEFT slides. (Source: peft-slides)

14. What exactly does rank control?

Remember:

AB

has rank at most r:

\boxed{\operatorname{rank}(AB)\le r}.

So r controls the maximum complexity/capacity of the learned update.

Small r

Fewer parameters:

r\downarrow \Rightarrow \text{cheaper}

but the update has a smaller low-rank subspace.

Large r

More parameters:

r\uparrow \Rightarrow \text{more trainable capacity}

but more memory/computation.

The book explicitly describes rank as the setting controlling the number of additional trainable parameters. (Source: Build a Large Language Model (From Scratch))

15. What does alpha do?

The book defines \alpha as a scaling factor controlling the influence of the LoRA adaptation on the original layer output. (Source: Build a Large Language Model (From Scratch))

In the book notation:

Y=XW_0+\alpha XAB.

Think of:

XAB

as the direction/content of the adaptation, while

\alpha

controls how strongly it contributes.

For example, if

XAB=0.5

then:

\alpha=1
\text{LoRA contribution}=0.5
\alpha=4
\text{LoRA contribution}=2

So increasing \alpha strengthens the adapter's effect.

16. The PEFT-slide convention: \alpha/r

The PEFT slides use the more common scaled form:

\boxed{ W'=W_0+\frac{\alpha}{r}BA }

rather than the book's simplified implementation

W'=W_0+\alpha AB.

This is why you may encounter:

\frac{\alpha}{r}

in papers/libraries and simply

\alpha

in the Raschka implementation.

Example

Suppose:

r=8,\qquad\alpha=16.

Then:

\frac{\alpha}{r} = \frac{16}{8} = \boxed{2}.

So the low-rank update is scaled by 2.

The slides also note that values such as \alpha equal to, half of, or double the rank are common choices in their example. (Source: Build a Large Language Model (From Scratch))

17. Full training flow

Now we can finally see the complete LoRA training loop.

Step 1 — Start with pretrained model

W_0

contains all the knowledge acquired during pretraining.

Step 2 — Freeze W_0

\boxed{W_0\text{ does not change}}

Step 3 — Insert LoRA matrices

A,\ B

are added to selected linear layers.

Step 4 — Initialize

A=\text{random}
B=0.

Therefore:

W_{\text{eff}}=W_0.

Step 5 — Forward pass

Y=XW_0+\alpha XAB.

Step 6 — Compute loss

For a classification task, for example:

L=-\log p(y_{\text{correct}}).

Step 7 — Backpropagation

Compute:

\nabla_A L, \qquad \nabla_B L.

Step 8 — Update only LoRA parameters

A\leftarrow A-\eta\nabla_A L
B\leftarrow B-\eta\nabla_B L.

Step 9 — Repeat

After many batches:

A,B

encode the task-specific adaptation.

The book uses its ordinary PyTorch training function with an optimizer on the modified model. (Source: Build a Large Language Model (From Scratch))

18. What happened in the book's actual experiment?

The book uses a GPT-2-small-sized model with:

124\text{M}

parameters.

It freezes the complete model and then adds LoRA.

With

r=16,\qquad \alpha=16,

the reported trainable LoRA parameters are:

\boxed{2,666,528}.

So instead of training roughly 124 million parameters, it trains about 2.7 million. (Source: Build a Large Language Model (From Scratch))

The book reports that the initial accuracy was unchanged after adding LoRA because B=0, so the LoRA branch initially produced no modification. (Source: Build a Large Language Model (From Scratch))

After training, the example achieved very high performance, with the book reporting approximately:

100\%\text{ training accuracy}

and

96.64\%\text{ validation accuracy}.

The book notes that this involved only around 2.7 million LoRA parameters rather than the original 124 million model parameters. (Source: Build a Large Language Model (From Scratch))

19. Why can LoRA still train if most parameters are frozen?

This is the key conceptual insight.

The base model already provides:

W_0

which defines a powerful pretrained function.

We don't need to completely relearn that function.

We only need to learn a relatively small modification:

\Delta W\approx AB.

Thus:

\boxed{ \text{Pretrained knowledge} + \text{small task-specific correction} }

becomes the adaptation strategy.

20. Separate LoRA during deployment

After training, we have:

W_0,\ A,\ B.

We can keep them separate:

Y=XW_0+\alpha XAB.

The book emphasizes that keeping LoRA parameters separate lets the pretrained weights remain unchanged and allows different LoRA adapters to be associated with the same base model, reducing storage requirements when customizing a model for different applications. (Source: Build a Large Language Model (From Scratch))

Conceptually:

                    ┌─────────────┐
X ─────────────────►│ Base W0     │────┐
                    └─────────────┘    │
                                       ├──► Y
X ─► A ─► B ─► scale(α) ───────────────┘

21. Merge LoRA into the base model

Eventually we can combine the matrices.

For the book notation:

\boxed{ W_{\text{merged}} = W_0+\alpha AB }

Then inference becomes simply:

\boxed{ Y=XW_{\text{merged}} }

instead of computing two branches.

Why is this mathematically identical?

Start with:

Y=XW_0+\alpha XAB.

Factor out X:

Y=X(W_0+\alpha AB).

Define:

W_{\text{merged}}=W_0+\alpha AB.

Therefore:

\boxed{Y=XW_{\text{merged}}}.

Nothing about the function changes mathematically.

22. Numerical merge example

Take

W_0= \begin{bmatrix} 1&0\\ 0&1 \end{bmatrix}

and

A= \begin{bmatrix} 1\\ 2 \end{bmatrix}, \qquad B= \begin{bmatrix} 0.2&0.1 \end{bmatrix}, \qquad \alpha=2.

First:

AB= \begin{bmatrix} 1\\2 \end{bmatrix} \begin{bmatrix} 0.2&0.1 \end{bmatrix}

so

AB= \begin{bmatrix} 0.2&0.1\\ 0.4&0.2 \end{bmatrix}.

Scale:

\alpha AB = \begin{bmatrix} 0.4&0.2\\ 0.8&0.4 \end{bmatrix}.

Merge:

W_{\text{merged}} = \begin{bmatrix} 1&0\\ 0&1 \end{bmatrix} + \begin{bmatrix} 0.4&0.2\\ 0.8&0.4 \end{bmatrix}

giving

\boxed{ W_{\text{merged}} = \begin{bmatrix} 1.4&0.2\\ 0.8&1.4 \end{bmatrix} }

Now take

X=[1\quad2].
Separate computation

Base:

XW_0=[1\quad2].

LoRA:

XA=1(1)+2(2)=5.

Therefore:

\alpha(XA)B = 2(5) \begin{bmatrix} 0.2&0.1 \end{bmatrix} = [2\quad1].

Total:

Y=[1\quad2]+[2\quad1] = \boxed{[3\quad3]}.
Merged computation
XW_{\text{merged}} = [1\quad2] \begin{bmatrix} 1.4&0.2\\ 0.8&1.4 \end{bmatrix}

so

= [1.4+1.6,\ 0.2+2.8]
= \boxed{[3\quad3]}.

Exactly the same.

23. Why merge?

During training, keeping them separate is useful because:

A,B

are the only trainable components.

After training, merging gives:

W_{\text{merged}}

so inference can use the ordinary linear layer.

This is conceptually:

During training
\boxed{ W_0 + \text{LoRA branch} }
After merge
\boxed{ W_{\text{merged}} }

Same function, different representation.

The book's emphasis is that keeping adapters separate is particularly useful for customization and storage; merging is the natural algebraic equivalent when a standalone adapted model is desired. (Source: Build a Large Language Model (From Scratch))

24. Very important distinction: trainable parameters vs total model parameters

Suppose:

W_0 = 124\text{M parameters}

and LoRA introduces:

2.7\text{M}.

It does not mean the model suddenly becomes a 2.7M-parameter model.

It is still a 124M-parameter base model plus the adapter.

The important reduction is:

\boxed{ \text{trainable parameters} \downarrow }

not necessarily:

\boxed{ \text{total model parameters} \downarrow }

This distinction leads directly to the motivation for quantization and QLoRA, which we will encounter next.

Numerical 1 — parameter count

A square matrix has

d=4096,\quad r=8.

Calculate LoRA trainable parameters.

N=r(d+d)
=8(4096+4096)
=8(8192)
\boxed{65,536}

Numerical 2 — reduction factor

Full matrix:

4096^2=16,777,216.

LoRA:

65,536.

Therefore:

\frac{16,777,216}{65,536} = \boxed{256\times}.

Numerical 3 — rank constraint

If

A\in\mathbb{R}^{4096\times8}

and

B\in\mathbb{R}^{8\times4096},

then:

AB\in\mathbb{R}^{4096\times4096}

and

\boxed{\operatorname{rank}(AB)\le8}.

Numerical 4 — first-step gradient trap

Given

B=0,

what is

\frac{\partial L}{\partial A} = \alpha X^TGB^T?

Answer:

\boxed{0}.

But \partial L/\partial B can be nonzero because A\neq0.

Numerical 5 — both-zero initialization

If

A=0,\quad B=0,

then:

\boxed{ \nabla_A L=0,\qquad\nabla_B L=0 }

and the LoRA adapter cannot start learning.

Numerical 6 — scaling

Given

\alpha=16,\qquad r=8,

using the PEFT-slide convention:

\frac{\alpha}{r} = \boxed{2}.

Numerical 7 — parameter count across layers

Suppose:

L=32

layers,

four attention projections per layer,

d=4096,\quad r=8.

One projection:

65,536.

All four per layer:

4(65,536)=262,144.

Across 32 layers:

32(262,144) = \boxed{8,388,608}.

26. The whole LoRA story in one chain

Memorize the logic, not just the formula:

\boxed{ W'=W_0+\Delta W }

Full fine-tuning:

\Delta W\text{ is huge}.

LoRA:

\boxed{ \Delta W\approx AB }

with small rank r.

Therefore:

\boxed{ W'=W_0+\alpha AB }

Freeze:

\boxed{W_0\text{ frozen}}

Initialize:

\boxed{A\text{ random},\ B=0}

so initially:

\boxed{W'=W_0}.

Train:

\boxed{A,B\text{ only}}

After training:

\boxed{ W_{\text{merged}} = W_0+\alpha AB }

and inference can use the merged matrix.

27. What you should be able to answer after this step

A strong exam/interview answer to “Explain how LoRA actually learns” should sound like this:

LoRA freezes the pretrained matrix W_0 and learns a low-rank update represented by two smaller matrices. The forward computation becomes XW_0+\alpha XAB. One LoRA factor is initialized randomly and the other to zero, so the initial model behavior is unchanged. During the first backward pass, the zero factor can receive gradients while the other factor's gradient is initially zero; subsequent updates allow both factors to learn. Because only A and B are optimized, the number of trainable parameters is much smaller than full fine-tuning. After training, the low-rank update can be merged into W_0 algebraically.

That is the conceptual core of LoRA initialization → gradient flow → training → merge.
