R102.4 — DeepSeek-R1: Why the Final Pipeline Is More Than “Just GRPO”

Plan node: B2 · chat order #121

↩ Back to main text: Step 5.7 — The Full GRPO Training Algorithm · Step 5.12 — DeepSeek-R1 From Scratch: R1-Zero → R1 → Distill

We have now reached the point where the separate ideas finally assemble into the DeepSeek-R1 post-training pipeline.

A very common oversimplification is:

\boxed{\text{DeepSeek-R1}=\text{GRPO + RLVR}}

That describes an important ingredient, but not the complete pipeline.

The source makes the distinction very clearly:

\boxed{ \text{R1-Zero} = \text{pure RL experiment} }

while:

\boxed{ \text{R1} = \text{staged post-training pipeline} }

containing supervised learning, reasoning RL, rejection sampling, another supervised stage, and final RL. (Source: Build a DeepSeek Model (From Scratch))

1. Start from the problem R1 is trying to solve

R1-Zero showed something extremely interesting:

\text{Base model} + \text{GRPO} + \text{verifiable reward}

can produce reasoning-like behavior.

But R1-Zero also had practical problems.

The source highlights:

\boxed{\text{poor readability}}

and:

\boxed{\text{language mixing}}

among the issues motivating a more engineered pipeline. (Source: Build a DeepSeek Model (From Scratch))

So the objective changes from:

“Can RL make the model reason?”

to:

“Can we make the reasoning capability usable as a general assistant?”

That is why the pipeline becomes multi-stage.

2. The complete R1 pipeline

The source gives the following conceptual sequence:

\boxed{ \text{Cold-start SFT} \rightarrow \text{Reasoning RL} \rightarrow \text{Rejection Sampling} \rightarrow \text{Mixed-data SFT} \rightarrow \text{Final RL} }

(Source: Build a DeepSeek Model (From Scratch))

Let's understand why every arrow exists.

3. Stage 1 — Cold-start supervised fine-tuning

Start with:

\boxed{\text{DeepSeek-V3 base}}

Then create a relatively small set of curated reasoning examples.

The source describes these as long chain-of-thought examples with a more readable style.

The base model is fine-tuned on them before the heavy reasoning RL stage. (Source: Build a DeepSeek Model (From Scratch))

So:

DeepSeek-V3 Base
       │
       ▼
small curated reasoning dataset
       │
       ▼
      SFT
       │
       ▼
better initial reasoning behavior

4. Why is this called “cold-start”?

Because this is the model's initial starting point for the later reasoning-RL stage.

The important idea is:

\boxed{ \text{Don't force RL to discover everything from scratch} }

The model is first given a small amount of useful structure.

The source says this gives the model a better initial response style and reasoning format before heavy RL. (Source: Build a DeepSeek Model (From Scratch))

5. What exactly is SFT contributing?

Supervised fine-tuning is especially good at teaching:

\boxed{\text{format}}
\boxed{\text{style}}

and:

\boxed{\text{imitation of known examples}}.

RL is better suited to optimizing outcomes when we can score them.

The source explicitly says SFT and RL are not competing tools; they solve different parts of the problem. (Source: Build a DeepSeek Model (From Scratch))

So the division of labor is:

SFT → "Here is what a useful response should look like."

RL  → "Now improve the behavior according to reward."

6. Why cold-start data can improve RL itself

This is a subtle but important point from the source.

Suppose the model already knows to produce:

reasoning...
Final answer: ...

Then the verifier can more reliably extract the final answer.

Without that structure, the model may generate:

multiple candidate answers
mixed formatting
unclear conclusion

The verifier may struggle to determine what should be scored.

So cold-start SFT can improve the quality of the RL signal itself.

The source explicitly says that structured initial behavior can reduce wasted exploration and make verification cleaner. (Source: Build a DeepSeek Model (From Scratch))

7. Stage 2 — Reasoning-oriented RL

Now we take the better-formatted model and apply RL.

Conceptually:

\boxed{ \text{Cold-start model} \rightarrow \text{GRPO/RL} }

The source says this stage resembles the R1-Zero experiment but begins from a better-formatted model. (Source: Build a DeepSeek Model (From Scratch))

8. What reward is used here?

The source describes rule-based reasoning rewards.

So for verifiable tasks:

\text{response} \rightarrow \text{verifier} \rightarrow \text{reward}.

The pipeline can therefore continue to exploit:

\boxed{\text{RLVR}}

for tasks such as mathematical reasoning.

The source also mentions a language-consistency reward in this stage, motivated by the language-mixing problem observed in R1-Zero. (Source: Build a DeepSeek Model (From Scratch))

So the reasoning-RL stage is not simply “reward correctness and ignore everything else.”

9. Conceptually, this stage does the hard capability optimization

Think of Stage 1 as setting the initial behavior distribution:

\pi_{\text{cold}}.

Then Stage 2 applies reward pressure:

\pi_{\text{cold}} \rightarrow \pi_{\text{reasoning}}.

The desired behavior becomes more likely because successful reasoning trajectories receive better learning signals.

This is where the RL machinery we've already derived—GRPO, group advantages, clipping, and reference control—becomes operational.

10. Stage 3 — Rejection sampling

Now something interesting happens.

We don't immediately keep training with RL forever.

Instead, we use the improved model as a data generator.

The source describes the process:

\boxed{ \text{sample many responses} \rightarrow \text{filter} \rightarrow \text{keep good responses} }

(Source: Build a DeepSeek Model (From Scratch))

This is called:

\boxed{\text{Rejection Sampling}}

11. Why reject responses?

Suppose the RL-trained model produces:

Response A → correct + readable
Response B → wrong
Response C → correct + messy
Response D → correct + readable
Response E → wrong

We don't want all of them in our next supervised dataset.

We keep high-quality responses and reject poor ones.

Conceptually:

\boxed{ \text{generated distribution} \rightarrow \text{quality-filtered distribution} }

12. This is NOT another RL algorithm

The source explicitly emphasizes this.

Rejection sampling is:

\boxed{\text{data generation + filtering}}

not RL itself. (Source: Build a DeepSeek Model (From Scratch))

This distinction is very important.

RL changes model parameters through a reward-based objective.

Rejection sampling creates a cleaner training dataset.

So:

RL:
parameters ← reward signal

Rejection sampling:
responses → filtering → dataset

13. Why does rejection sampling happen after RL?

Because the RL-trained model is now a stronger generator.

If we started rejection sampling from the original base model, we would have fewer high-quality reasoning trajectories available.

The source explicitly describes the logic as:

\boxed{ \text{RL improves generator} \rightarrow \text{filter generator's best outputs} }

(Source: Build a DeepSeek Model (From Scratch))

This is the data-flow bridge from R1-Zero-style discovery to R1-style refinement.

14. What does the filtering check?

For reasoning tasks, the source says correctness can be checked with a rule-based verifier.

For broader quality, filtering can involve:

  • heuristics,
  • model-based judgments,
  • preference data.

(Source: Build a DeepSeek Model (From Scratch))

So "correct" isn't the only criterion.

We also care about:

\boxed{\text{readability}}

and:

\boxed{\text{consistency / quality}}

15. Stage 4 — Mixed-data supervised fine-tuning

Now we have a valuable dataset of strong reasoning examples.

We use it for SFT again.

But this time something changes.

We mix reasoning data with broader non-reasoning instruction data.

The source explicitly describes this as a way to restore general assistant behavior. (Source: Build a DeepSeek Model (From Scratch))

16. Why do we need non-reasoning data?

Imagine we train almost exclusively on:

Math problem
Math problem
Code problem
Math problem
Code problem
...

What is the model being optimized to become?

A very strong reasoning solver.

But perhaps not a well-balanced general assistant.

It may:

  • overuse long reasoning,
  • behave awkwardly on simple requests,
  • become excessively optimized for benchmark-style answer formats.

The source explicitly warns about this specialization effect. (Source: Build a DeepSeek Model (From Scratch))

17. What is in the broader data?

The source gives examples such as:

\boxed{\text{writing}}
\boxed{\text{editing}}
\boxed{\text{factual QA}}
\boxed{\text{role play}}

and other general assistant tasks. (Source: Build a DeepSeek Model (From Scratch))

So now the training distribution looks more like:

Reasoning examples
       +
General instruction examples
       ↓
      SFT
       ↓
balanced model

18. This stage is restoring breadth

A useful conceptual interpretation is:

\boxed{ \text{Reasoning RL increases depth} }

while:

\boxed{ \text{mixed-data SFT preserves breadth} }

This phrasing is a conceptual summary of the source's stated roles for the stages.

The important source point is that a narrow reward creates narrow improvement unless combined with broader data and alignment signals. (Source: Build a DeepSeek Model (From Scratch))

19. Stage 5 — Final RL

Now we have a model that is:

  • better at reasoning,
  • better formatted,
  • trained on broader assistant data.

The source then describes a final RL stage with a hybrid reward design. (Source: Build a DeepSeek Model (From Scratch))

This is crucial.

The reward is no longer exclusively:

\text{rule-based correctness}.

Instead:

Verifiable tasks

Use:

\boxed{\text{rule-based rewards}}
Open-ended helpfulness / harmlessness

Use:

\boxed{\text{learned reward models}}

(Source: Build a DeepSeek Model (From Scratch))

20. Why a hybrid reward?

Because by this point the goal isn't merely:

“Solve math correctly.”

The goal is closer to:

“Be a strong reasoning model and a useful assistant.”

Some properties are mechanically checkable.

Others are preference-based.

Therefore:

\boxed{ R_{\text{final}} = \text{verifiable rewards where possible} + \text{learned preference rewards where necessary} }

The exact weighting isn't established by the excerpt we are using, so we should not invent one.

21. This explains a common misconception

Don't summarize DeepSeek-R1 as:

“DeepSeek removed reward models.”

That is incorrect according to the source.

A better statement is:

\boxed{ \text{Use deterministic verifiers when correctness is objectively checkable;} }
\boxed{ \text{use learned reward models when the desired behavior is subjective.} }

The source makes this distinction explicitly. (Source: Build a DeepSeek Model (From Scratch))

22. Why R1-Zero and R1 are different

Now the difference becomes very intuitive.

R1-Zero asks:
\boxed{ \text{Can RL discover reasoning?} }

Pipeline:

DeepSeek-V3-Base
      ↓
GRPO + verifiable rewards
      ↓
R1-Zero
R1 asks:
\boxed{ \text{Can we turn that reasoning capability into a usable assistant?} }

Pipeline:

V3 Base
   ↓
Cold-start SFT
   ↓
Reasoning RL
   ↓
Rejection sampling
   ↓
Mixed-data SFT
   ↓
Final hybrid RL
   ↓
R1

(Source: Build a DeepSeek Model (From Scratch))

23. The arrows have different meanings

This is worth slowing down for.

SFT arrow
\text{dataset} \rightarrow \text{parameter update}
RL arrow
\text{reward} \rightarrow \text{policy update}
Rejection-sampling arrow
\text{model outputs} \rightarrow \text{filtered dataset}.

Therefore the pipeline isn't one single training algorithm.

It is a system of different learning/data-construction mechanisms.

25. Why not just keep running GRPO?

This is the deeper engineering lesson.

Because each optimization method has a target.

Pure reasoning RL strongly rewards:

\text{task success}.

But the model also needs:

\text{readability} + \text{general instruction following} + \text{language consistency} + \text{preference-sensitive behavior}.

The source's R1 pipeline therefore uses different stages rather than expecting one objective to solve everything. (Source: Build a DeepSeek Model (From Scratch))

26. This is the bigger post-training principle

The source's broader lesson can be summarized as:

\boxed{ \text{One objective rarely captures the entire behavior you want.} }

Therefore:

\boxed{ \text{stage the training process} }

so each stage solves a different problem.

For R1:

SFT
→ initialize useful behavior

RL
→ optimize reasoning outcome

Rejection sampling
→ manufacture high-quality training data

Mixed SFT
→ restore/generalize assistant behavior

Final RL
→ optimize the final mixture of goals

27. R1 → Distill

Now notice what we have accidentally created.

After all this RL and filtering, R1 can generate high-quality reasoning traces.

Those traces themselves are valuable data.

So the natural next question becomes:

Can we train a much smaller model to imitate those reasoning behaviors?

That is the transition to:

\boxed{\text{DeepSeek-R1-Distill}}

The source describes R1-Distill as smaller student models trained using data generated by R1. (Source: Build a DeepSeek Model (From Scratch))

29. Exam/interview version

If someone asks:

“Explain DeepSeek-R1 training.”

A strong structured answer is:

\boxed{ \text{V3 Base} \rightarrow \text{cold-start SFT} \rightarrow \text{reasoning RL} \rightarrow \text{rejection sampling} \rightarrow \text{mixed-data SFT} \rightarrow \text{final hybrid RL} }

Then explain each:

Cold-start SFT: establish readable structured reasoning behavior.

Reasoning RL: use reward pressure to strengthen reasoning, with rule-based rewards for suitable verifiable tasks.

Rejection sampling: generate many responses and retain high-quality ones.

Mixed-data SFT: train on curated reasoning data plus broader assistant data to restore general capabilities.

Final RL: combine rule-based rewards for verifiable tasks with learned preference rewards for open-ended behavior. (Source: Build a DeepSeek Model (From Scratch))

\boxed{ \text{R1-Distill: Can we transfer that capability to smaller models?} }

This is the cleanest way to keep the three names separate. (Source: Build a DeepSeek Model (From Scratch))
