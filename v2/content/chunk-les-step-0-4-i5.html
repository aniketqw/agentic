Why this matters

Training needs the effect of a parameter change on loss even when several intermediate calculations separate them.

Prerequisites: Matrix multiplication and shape contracts

Symbols, shapes and assumptions

Use a differentiable scalar computation L=(2w-1)². The derivative refers to this particular computation, not every neural-network loss.

Derivation or mechanism

  1. Set u=2w-1.
  2. Differentiate the outer loss: dL/du=2u.
  3. Multiply by du/dw=2 to obtain dL/dw=4(2w-1).
\frac{dL}{dw}=\frac{dL}{du}\frac{du}{dw}=4(2w-1)

Worked numerical

At w=3, u=5, L=25 and dL/dw=20. Increasing w by a very small amount increases L at approximately 20 units of loss per unit w. The central-difference check evaluates the loss at w±10⁻⁵ and recovers 20.

Edge cases and limits

  • At a nondifferentiable point, finite differences need not reproduce a chosen subgradient.
  • A gradient is local sensitivity, not a guarantee about a large parameter change.

Connections

  • F08 extends this reasoning to every matrix entry.
  • F09 uses a gradient to make a controlled parameter update.

Batch 1 · checked example F09 — A gradient-descent step and its limits

New teaching capsule and stated examples only; inherited prose/formulas/code remain pending

← Previous audit card · Next audit card →

Why this matters

The derivative becomes a learning rule only after we specify an update and a step size.

Prerequisites: Chain rule and scalar gradients, Matrix gradients from a scalar loss

Symbols, shapes and assumptions

Use Wnew=W-η∇W with η=0.01 on the F08 squared-error fixture. The sign minimizes this loss. A maximization objective uses the opposite sign.

Derivation or mechanism

  1. Evaluate the current loss and gradient at the current parameters.
  2. Subtract η times that gradient from every parameter.
  3. Recompute the loss at the new parameters instead of assuming it fell.
W_{new}=W-\eta\nabla_W L

Worked numerical

The loss starts at 31.5. Updating with η=0.01 gives Wnew=[[0.83,-1.18],[0.26,1.74]], Ynew=[[1.35,2.3],[3.53,3.42]], and loss 15.6349. The checker evaluates the forward calculation after the update.

Edge cases and limits

  • A large step can increase loss even with a correct gradient.
  • This one-step decrease is not evidence that a model will generalize or that a training run converges.

Connections

  • T01 changes the loss to token CE.
  • Later PPO/GRPO objectives require a separately verified sign and reduction.

STEP 0.4 — CALCULUS FOR DEEP LEARNING

Plan node: I0 · chat order #5

Derivative → Partial Derivative → Gradient → Chain Rule → Backpropagation → Gradient Descent

Now we reach the part that answers one of the most fundamental questions in machine learning:

How does the Transformer actually learn its parameters?

You already know the forward direction:

X \rightarrow Q,K,V \rightarrow Attention \rightarrow Transformer \rightarrow Logits \rightarrow Softmax \rightarrow Loss

But during training, we need to go backward:

\boxed{ Loss \rightarrow \text{which parameters caused it?} \rightarrow \text{how should parameters change?} }

That is where calculus enters.

Raschka explicitly describes backpropagation as an implementation of the chain rule for neural networks, where gradients are propagated backward from the loss to the parameters. (Source: Build a Large Language Model (From Scratch))

0.4.1 The whole idea before the mathematics

Imagine a single parameter:

w

and suppose the model's loss is:

L(w)

You want to make L smaller.

So the central question is:

If I increase w slightly, does the loss go up or down, and by how much?

That is exactly what a derivative tells us.

0.4.2 Derivative: the slope

For a function:

y=f(x)

the derivative is:

\boxed{ \frac{dy}{dx} }

It measures the instantaneous rate at which y changes when x changes.

A rough interpretation is:

\boxed{ \text{derivative} = \frac{\text{change in output}}{\text{change in input}} }

Simple example

Let:

f(x)=x^2

Then:

\frac{df}{dx}=2x

At:

x=3

we have:

\frac{df}{dx}=6

Interpretation:

Around x=3, increasing x slightly increases f(x) at a rate of about 6 units of output per unit of input.

0.4.3 Why slope matters for optimization

Suppose:

L(w)=w^2

Then:

\frac{dL}{dw}=2w

Consider:

w=5

Then:

\frac{dL}{dw}=10

The slope is positive.

That means:

Increasing w increases the loss.

So to reduce the loss, we should move w in the negative direction.

Now suppose:

w=-5

Then:

\frac{dL}{dw}=-10

The slope is negative.

That means:

Increasing w decreases the loss.

So we should move w in the positive direction.

This gives us the fundamental rule:

\boxed{ \text{move opposite to the gradient} }

0.4.4 Partial derivative

A neural network doesn't have just one parameter.

Suppose:

L(w_1,w_2,w_3)

Now we may ask:

\frac{\partial L}{\partial w_1}

while treating the other parameters as fixed.

That is a partial derivative.

Similarly:

\frac{\partial L}{\partial w_2}

and:

\frac{\partial L}{\partial w_3}

Raschka and the supplied Hands-On ML material use this idea explicitly: a partial derivative measures how the cost changes with respect to one parameter while considering the others. (Source: Hands-On Machine Learning with Scikit-Lear - Aurelien Geron; Build a Large Language Model (From Scratch))

0.4.5 Why not just use one derivative?

Because the model has millions or billions of parameters.

Suppose:

\theta= [w_1,w_2,w_3,w_4]

We need:

\frac{\partial L}{\partial w_1}, \frac{\partial L}{\partial w_2}, \frac{\partial L}{\partial w_3}, \frac{\partial L}{\partial w_4}

all at once.

We package them into a vector.

0.4.6 Gradient

The gradient is:

\boxed{ \nabla_\theta L = \begin{bmatrix} \frac{\partial L}{\partial\theta_1}\\ \frac{\partial L}{\partial\theta_2}\\ \vdots\\ \frac{\partial L}{\partial\theta_n} \end{bmatrix} }

So:

\boxed{ \text{Gradient}=\text{all partial derivatives collected together} }

This is exactly how the supplied sources describe it. (Source: Hands-On Machine Learning with Scikit-Lear - Aurelien Geron; Build a Large Language Model (From Scratch))

0.4.7 Geometric meaning of the gradient

Remember the mountain analogy.

Suppose you are standing somewhere on a mountain.

The gradient tells you:

\boxed{ \text{the direction of steepest increase} }

Therefore:

-\nabla L

points toward the steepest local decrease.

This is why optimization uses:

\boxed{ \theta_{\text{new}} = \theta-\eta\nabla_\theta L }

The supplied Hands-On ML source gives this exact gradient-descent update. (Source: Hands-On Machine Learning with Scikit-Lear - Aurelien Geron)

0.4.8 What is the learning rate?

\eta

is the learning rate.

It determines how large a step we take.

So:

\theta_{\text{new}} = \theta-\eta\nabla_\theta L

has two pieces:

Direction
-\nabla_\theta L
Step size
\eta

Think:

Gradient tells us where to go.

Learning rate tells us how far to go.

0.4.9 Numerical gradient-descent example

Take:

L(w)=w^2

Then:

\frac{dL}{dw}=2w

Start with:

w=5

and:

\eta=0.1

Gradient:

\frac{dL}{dw}=10

Update:

w_{\text{new}} = 5-0.1(10)
\boxed{w_{\text{new}}=4}

Loss changed from:

L(5)=25

to:

L(4)=16

Good—we moved downhill.

0.4.10 Another iteration

Now:

w=4

Gradient:

8

Update:

w=4-0.1(8)
=3.2

Then:

L(3.2)=10.24

Again smaller.

Eventually:

w\rightarrow0

because:

L(w)=w^2

has its minimum at zero.

0.4.11 Why this becomes difficult in neural networks

In a Transformer:

L = L(\text{softmax}( \text{Transformer}( X,\theta )))

A parameter such as W_Q affects:

Q

which affects:

QK^T

which affects:

A

which affects:

O

which affects later layers,

which affects:

z

which affects:

p

which affects:

L

So there is a long chain of dependencies.

We therefore need the chain rule.

0.4.12 Chain rule

Suppose:

y=f(u)

and:

u=g(x)

Therefore:

y=f(g(x))

The chain rule says:

\boxed{ \frac{dy}{dx} = \frac{dy}{du} \frac{du}{dx} }

This looks simple, but it is the mathematical engine behind backpropagation.

Raschka explicitly describes backpropagation as applying the chain rule backward through the computation graph. (Source: Build a Large Language Model (From Scratch))

0.4.13 Tiny numerical example of chain rule

Let:

u=x^2

and:

y=3u

Then:

\frac{du}{dx}=2x

and:

\frac{dy}{du}=3

Therefore:

\frac{dy}{dx} = \frac{dy}{du} \frac{du}{dx} = 3(2x) = 6x

If:

x=2

then:

\boxed{ \frac{dy}{dx}=12 }

Instead of directly differentiating the full expression, we propagated derivatives through intermediate variables.

That is exactly what a neural network does.

0.4.14 Computational graph

Let's represent the previous example as a graph:

x
│
▼
u = x²
│
▼
y = 3u

Forward:

x\rightarrow u\rightarrow y

Backward:

\frac{\partial y}{\partial y} \rightarrow \frac{\partial y}{\partial u} \rightarrow \frac{\partial y}{\partial x}

This is the basic shape of backpropagation.

0.4.15 A neural-network example

Suppose:

z=wx+b

Then:

a=\sigma(z)

and loss:

L=\ell(a,y)

The dependency graph is:

x, w, b
   ↓
   z
   ↓
   a
   ↓
   L

To find:

\frac{\partial L}{\partial w}

we walk backward.

By the chain rule:

\boxed{ \frac{\partial L}{\partial w} = \frac{\partial L}{\partial a} \frac{\partial a}{\partial z} \frac{\partial z}{\partial w} }

Every factor represents one local derivative.

0.4.16 Why this is so powerful

Imagine a model with:

10^9

parameters.

We don't want to symbolically re-derive the entire loss function for every parameter from scratch.

Instead, the computation graph contains local operations.

Backpropagation reuses intermediate derivatives efficiently.

This is why modern deep-learning frameworks rely on automatic differentiation.

Raschka explains that PyTorch tracks operations in a computational graph and can then compute the gradients required for training. (Source: Build a Large Language Model (From Scratch))

0.4.17 Forward pass vs backward pass

This distinction is essential.

Forward pass

We compute:

X \rightarrow Q,K,V \rightarrow Attention \rightarrow Transformer \rightarrow logits \rightarrow probabilities \rightarrow loss

Purpose:

\boxed{ \text{compute prediction and loss} }

Backward pass

We start with the loss and move backward:

L \rightarrow logits \rightarrow Transformer \rightarrow Attention \rightarrow Q,K,V \rightarrow parameters

Purpose:

\boxed{ \text{compute gradients} }

0.4.18 Backpropagation

So now we can define it properly:

\boxed{ \text{Backpropagation} = \text{efficient backward application of the chain rule} }

It calculates:

\frac{\partial L}{\partial\theta_i}

for the model parameters.

The supplied Raschka source makes exactly this connection and describes reverse-mode automatic differentiation as computing loss gradients by working backward from the output toward the parameters. (Source: Build a Large Language Model (From Scratch))

0.4.19 Why "reverse mode"?

Suppose we have:

\text{many parameters} \rightarrow \text{one loss}

A Transformer has an enormous number of inputs/parameters, but typically the training objective produces a relatively small number of scalar losses.

Reverse-mode differentiation is efficient for this structure.

Conceptually:

Many parameters
      ↓
     ...
      ↓
   Scalar loss

Then propagate backward:

Scalar loss
      ↓
 intermediate nodes
      ↓
 many parameters

This is the mathematical reason reverse-mode autodiff is so useful for neural-network training.

0.4.20 A complete small example

Let's create:

z=wx

with:

w=2,\quad x=3

Then:

z=6

Suppose loss is:

L=(z-10)^2

Therefore:

L=(6-10)^2=16

Now calculate:

\frac{\partial L}{\partial w}

Break the graph:

w \rightarrow z \rightarrow L

We have:

z=wx

so:

\frac{\partial z}{\partial w}=x=3

And:

L=(z-10)^2

so:

\frac{\partial L}{\partial z}=2(z-10)

At z=6:

\frac{\partial L}{\partial z} = 2(6-10) = -8

Chain rule:

\frac{\partial L}{\partial w} = \frac{\partial L}{\partial z} \frac{\partial z}{\partial w}
=(-8)(3)
\boxed{ \frac{\partial L}{\partial w}=-24 }

0.4.21 What does -24 mean?

It means locally:

Increasing w tends to decrease the loss.

So gradient descent does:

w_{\text{new}} = w-\eta(-24)

If:

\eta=0.1

then:

w_{\text{new}} = 2+2.4
\boxed{w_{\text{new}}=4.4}

The gradient was negative, so subtracting it moves w upward.

That is exactly why we always say:

\boxed{ \text{gradient points uphill} }

and:

\boxed{ -\text{gradient points downhill} }

0.4.22 Connect this to the Transformer

Now replace our simple w with:

W_Q

A simplified dependency chain is:

W_Q \rightarrow Q \rightarrow QK^T \rightarrow S \rightarrow A \rightarrow O \rightarrow \text{Transformer output} \rightarrow z \rightarrow p \rightarrow L

Therefore we want:

\frac{\partial L}{\partial W_Q}

The chain rule conceptually gives:

\frac{\partial L}{\partial W_Q} = \frac{\partial L}{\partial z} \frac{\partial z}{\partial O} \frac{\partial O}{\partial A} \frac{\partial A}{\partial S} \frac{\partial S}{\partial Q} \frac{\partial Q}{\partial W_Q}

The actual implementation uses tensor operations and automatic differentiation, but this is the conceptual mathematical structure.

0.4.23 Even more concretely

We previously had:

Q=XW_Q

Suppose:

L=L(Q)

Then:

\frac{\partial L}{\partial W_Q}

comes from:

W_Q \rightarrow Q \rightarrow L

The local derivative of:

Q=XW_Q

is essentially governed by X.

For the complete matrix calculus, autodiff handles the tensor-shaped derivative bookkeeping for us.

This is why learning matrix dimensions earlier was essential.

0.4.24 Why gradients can explode or vanish

Now we encounter another crucial deep-learning issue.

Suppose chain rule gives:

\frac{\partial L}{\partial x} = a_1a_2a_3a_4\cdots a_n

If the factors are mostly less than 1:

0.5^{20}

becomes extremely small.

The gradient can effectively disappear.

This produces the:

\boxed{\text{vanishing-gradient problem}}

If the factors are mostly greater than 1:

2^{20}

becomes enormous.

That gives:

\boxed{\text{exploding gradients}}

Hands-On ML explicitly discusses these problems as part of deep-network optimization. (Source: Hands-On Machine Learning with Scikit-Lear - Aurelien Geron)

This will later motivate:

  • initialization
  • normalization
  • residual connections
  • activation choices
  • careful optimization

which we will encounter when studying the Transformer block.

0.4.25 Gradient descent in vector form

Suppose:

\theta= \begin{bmatrix} \theta_1\\ \theta_2\\ \theta_3 \end{bmatrix}

and:

\nabla_\theta L= \begin{bmatrix} 2\\ -4\\ 1 \end{bmatrix}

Let:

\eta=0.1

Then:

\theta_{\text{new}} = \theta - 0.1 \begin{bmatrix} 2\\ -4\\ 1 \end{bmatrix}

Thus:

\theta_{\text{new}} = \begin{bmatrix} \theta_1-0.2\\ \theta_2+0.4\\ \theta_3-0.1 \end{bmatrix}

Each parameter moves independently according to its own derivative.

0.4.26 Batch Gradient Descent

The supplied Hands-On ML source derives:

\nabla_\theta \mathrm{MSE} = \frac{2}{m}X^T(X\theta-y)

and then:

\boxed{ \theta_{\text{next}} = \theta-\eta\nabla_\theta \mathrm{MSE} }

It describes this as batch gradient descent because the full training set is used at every update. (Source: Hands-On Machine Learning with Scikit-Lear - Aurelien Geron)

For a modern Transformer, we generally use stochastic/minibatch variants rather than computing the gradient over the entire training corpus at every step.

The fundamental mathematical update remains the same.

0.4.27 The training loop

Now we can finally write the conceptual training loop:

Initialize parameters θ
        ↓
Take a batch of training data
        ↓
Forward pass
        ↓
Compute logits
        ↓
Softmax / loss
        ↓
Compute loss L
        ↓
Backpropagation
        ↓
Compute ∇θL
        ↓
Optimizer update
        ↓
New parameters θ
        ↓
Repeat

Mathematically:

\boxed{ \theta \rightarrow L(\theta) \rightarrow \nabla_\theta L \rightarrow \theta-\eta\nabla_\theta L }

This is the fundamental learning loop.

0.4.28 PyTorch example

Let's see automatic differentiation perform the calculation.

import torch

# Parameter
w = torch.tensor(2.0, requires_grad=True)

# Input
x = torch.tensor(3.0)

# Forward pass
z = w * x

# Loss
loss = (z - 10) ** 2

print("z =", z.item())
print("loss =", loss.item())

# Backward pass
loss.backward()

print("gradient =", w.grad.item())

# Gradient descent update
learning_rate = 0.1

with torch.no_grad():
    w -= learning_rate * w.grad

print("updated w =", w.item())

Expected reasoning:

w=2
z=6
L=16
\frac{\partial L}{\partial w}=-24

So:

w_{\text{new}}=4.4

0.4.29 What requires_grad=True means

When we write:

w = torch.tensor(2.0, requires_grad=True)

we are telling PyTorch:

Track operations involving w so its gradient can be computed.

Raschka explains that PyTorch builds a computational graph by tracking operations on tensors whose gradients are being tracked. (Source: Build a Large Language Model (From Scratch))

0.4.30 What loss.backward() means

This:

loss.backward()

means conceptually:

Start at the loss and propagate derivatives backward through the computation graph.

So:

\boxed{ \texttt{backward()} \approx \text{reverse-mode automatic differentiation} }

Afterward:

w.grad

contains:

\frac{\partial L}{\partial w}

0.4.31 Why do we use torch.no_grad() for the update?

We do:

with torch.no_grad():
    w -= learning_rate * w.grad

because the parameter update itself should not become another differentiable operation in the training graph.

Otherwise we would start tracking the optimizer's bookkeeping as part of the computation graph.

For now, the important mental model is:

forward operations → tracked
backward → calculate gradients
parameter update → outside the gradient graph

0.4.32 Gradient vs parameter

Never confuse:

w

with:

\frac{\partial L}{\partial w}

The first is:

the parameter itself.

The second is:

how the loss changes when the parameter changes.

Example:

w=2

but:

\frac{\partial L}{\partial w}=-24

These are completely different quantities.

0.4.33 Gradient vs learning rate

Also don't confuse:

\nabla_\theta L

with:

\eta

The gradient determines:

\boxed{\text{direction and local sensitivity}}

The learning rate determines:

\boxed{\text{update magnitude}}

0.4.34 Why the chain rule becomes the Transformer learning mechanism

Let's now connect everything we've learned.

Forward:
X \rightarrow Q,K,V
QK^T \rightarrow \text{softmax} \rightarrow AV
\text{Transformer blocks} \rightarrow z \rightarrow \text{softmax} \rightarrow p
p \rightarrow -\log p_{\text{correct}} \rightarrow L
Backward:
L \rightarrow p \rightarrow z \rightarrow \text{Transformer} \rightarrow A \rightarrow Q,K,V \rightarrow W_Q,W_K,W_V

and simultaneously toward:

  • embeddings
  • FFN weights
  • normalization parameters
  • output projection
  • positional parameters where applicable

Then:

\nabla_\theta L

is computed.

Finally:

\boxed{ \theta\leftarrow\theta-\eta\nabla_\theta L }

The model has learned a little.

Then we repeat this billions of times.

0.4.35 The four equations you now need to own

Derivative
\boxed{ \frac{df}{dx} }

“How does f change with x?”

Gradient
\boxed{ \nabla_\theta L = \left[ \frac{\partial L}{\partial\theta_1}, \ldots, \frac{\partial L}{\partial\theta_n} \right]^T }

“How does loss change with every parameter?”

Chain rule
\boxed{ \frac{dy}{dx} = \frac{dy}{du} \frac{du}{dx} }

“How do local changes combine through a chain of operations?”

Gradient descent
\boxed{ \theta_{\text{new}} = \theta-\eta\nabla_\theta L }

“How do we actually change the parameters?”

0.4.37 One important correction to a common mental model

Backpropagation does not mean:

"The model runs backward and generates the sentence backward."

It has nothing to do with reversing language.

It means:

The model's mathematical computation graph is traversed backward to calculate derivatives of the loss with respect to earlier quantities and parameters.

0.4.38 Another common mistake

Don't think:

\boxed{\text{backpropagation}=\text{gradient descent}}

They are related, but different.

Backpropagation

Computes:

\nabla_\theta L
Gradient descent

Uses that gradient:

\theta\leftarrow\theta-\eta\nabla_\theta L

So:

\boxed{ \text{backpropagation} \rightarrow \text{gradient} }
\boxed{ \text{optimizer} \rightarrow \text{parameter update} }

0.4.39 Connection to Adam

In modern Transformers, the optimizer is commonly more sophisticated than plain gradient descent.

Instead of simply:

\theta\leftarrow\theta-\eta\nabla_\theta L

optimizers such as Adam maintain statistics of gradients and adapt updates.

But the fundamental input to the optimizer is still:

\boxed{\nabla_\theta L}

So even when we later study Adam/AdamW, this lesson remains the foundation.

0.4.40 What comes next?

We've now completed the core calculus needed to understand training mechanics.

The remaining mathematical foundation we should add before starting the Transformer itself is:

\boxed{\text{Expectation and weighted averages}}

This is deceptively important because the exact concept will reappear in:

\text{attention} \rightarrow \text{probabilistic modeling} \rightarrow \text{reinforcement learning} \rightarrow \text{policy objectives}

In particular, an expression such as:

E_{x\sim P}[f(x)]

is the mathematical language for:

"Take an average, weighted according to a probability distribution."

That will make the later RL formulas much less mysterious.
