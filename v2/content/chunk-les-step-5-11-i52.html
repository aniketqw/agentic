Step 5.11 — What DeepSeekMath's RL Actually Changes

Plan node: I7 · chat order #52

We now have the full GRPO equation. The next question is deeper:

What does GRPO actually improve in the model?

Does RL teach the model completely new mathematical abilities?

Or does it mainly make already-available good solutions more likely to be produced?

The supplied DeepSeekMath slides address this directly using Pass@K vs Maj@K. They also compare Online RFT vs GRPO and outcome supervision vs process supervision. (Source: deepseekmath-slides)

5.11.1 First reconstruct the DeepSeekMath pipeline

The whole experiment should be viewed as:

\boxed{ \text{DeepSeek-Coder-Base-v1.5} }
\downarrow
\boxed{ \text{math-focused pretraining} }

using the large DeepSeekMath Corpus:

\boxed{120B\text{ math tokens}}
\downarrow
\boxed{ \text{DeepSeekMath-Base 7B} }
\downarrow
\boxed{ \text{instruction tuning} }
\downarrow
\boxed{ \text{DeepSeekMath-Instruct} }
\downarrow
\boxed{ \text{GRPO + verifiable rewards} }
\downarrow
\boxed{ \text{DeepSeekMath-RL} }

The supplied slides describe DeepSeekMath-Base 7B as starting from DeepSeek-Coder-Base-v1.5, and the RL stage as applying GRPO to DeepSeekMath-Instruct. (Source: deepseekmath-slides)

5.11.2 What reward is available?

For many mathematical problems, we know the correct answer.

So after the model generates:

o_i

we can verify it.

For a simplified binary reward:

R_i= \begin{cases} 1 & \text{correct}\\ 0 & \text{incorrect} \end{cases}

This is:

\boxed{\text{outcome supervision}}

because the reward concerns the final outcome.

The key advantage is that we do not need a human to manually score every generated reasoning trace.

5.11.3 Why can math use RLVR?

Because the answer can often be checked mechanically.

Suppose the model answers:

2x+3=11

with:

x=4.

A verifier can simply calculate:

2(4)+3=11.

Therefore:

R=1.

For:

x=3,

we get:

2(3)+3=9\neq11

so:

R=0.

Thus:

\boxed{\text{problem}+\text{verifier}\rightarrow\text{scalable reward}}

This is the basis of RL with verifiable rewards.

5.11.4 The key experimental question

Suppose the pretrained/instruction-tuned model already has a chance of solving a problem.

Example:

Model samples 8 answers:

Correct
Wrong
Wrong
Correct
Wrong
Wrong
Wrong
Wrong

The model already knew how to produce a correct solution sometimes.

GRPO can increase the probability of the successful trajectories.

That motivates the question:

\boxed{ \text{Does RL create new capability, or sharpen existing capability?} }

5.11.5 Pass@K

Define:

\boxed{\text{Pass@K}}

as:

Is there at least one correct answer among K sampled responses?

For example, with:

K=5

suppose:

[W,W,C,W,W].

There is one correct answer.

Therefore:

\boxed{\text{Pass@5}=1}.

If:

[W,W,W,W,W],

then:

\boxed{\text{Pass@5}=0}.

5.11.6 Why is Pass@K important?

Pass@K measures something close to:

\boxed{ \text{Can the model produce a correct solution at all?} }

Suppose the model has:

\text{Pass@8}=80\%.

That means that across eight attempts, a correct answer appears for many problems.

But that does not mean the first/default answer will be correct.

The correct response might be buried among several wrong ones.

5.11.7 Majority@K / Maj@K

Now consider:

\boxed{\text{Maj@K}}

The question becomes:

Among the K sampled answers, is the most common answer correct?

Example:

[83,83,38,83,38].

The majority answer is:

83.

If the correct answer is 83:

\boxed{\text{Maj@5}=1}.

5.11.8 Compare the two

Consider:

Samples:
83
83
38
41
17

Assume 83 is correct.

Then:

\text{Pass@5}=1

because at least one response is correct.

And:

\text{Maj@5}=1

because the correct answer is also the majority.

Now consider:

83
38
38
41
17

Again 83 is correct.

Then:

\text{Pass@5}=1

but:

\text{Maj@5}=0

because 38 is the majority.

This distinction is crucial.

5.11.9 What happens after RL?

The supplied DeepSeekMath slides report an important observation:

\boxed{\text{Maj@K improves}}

while:

\boxed{\text{Pass@K changes little}}

under the discussed RL analysis. (Source: deepseekmath-slides)

That means the model may already have been capable of producing correct solutions.

RL makes the correct solution more dominant in the output distribution.

5.11.10 Visualize the distribution

Before RL:

Correct solution      20%
Wrong strategy A      25%
Wrong strategy B      20%
Wrong strategy C      20%
Other                 15%

There is a correct solution, but it isn't dominant.

After RL:

Correct solution      55%
Wrong strategy A      15%
Wrong strategy B      12%
Wrong strategy C      10%
Other                  8%

The model's probability mass has been reshaped.

So:

\boxed{ \text{capability already present} \rightarrow \text{probability mass shifted toward successful behavior} }

This is the interpretation emphasized by the supplied deck. (Source: deepseekmath-slides)

5.11.11 This is the paper's interpretation, not a universal theorem

The slides phrase this as the paper's own interpretation:

RL is sharpening the probability distribution so that correct answers become more likely to dominate top-of-distribution decoding. (Source: deepseekmath-slides)

So we should be careful.

This does not prove:

\boxed{\text{RL can never create new reasoning capabilities}}

It means that, for this particular DeepSeekMath analysis, the Pass@K/Maj@K behavior suggests that a significant part of the gain can be explained as making successful existing behaviors more likely.

That distinction is important.

5.11.12 Why does this make intuitive sense?

Suppose the model already generates:

A=\text{correct solution}

with probability:

P(A)=0.2.

There are many competing incorrect solutions.

RL rewards sampled trajectories that succeed.

Repeatedly reinforcing successful trajectories pushes:

P(A)

upward.

For example:

0.2 \rightarrow 0.35 \rightarrow 0.50 \rightarrow 0.65.

Eventually the correct solution becomes dominant.

Thus greedy or ordinary top-of-distribution decoding becomes much more likely to return the correct answer.

5.11.13 A simple probability numerical

Suppose:

P(\text{correct})=0.2.

Assuming independent samples, the probability of getting at least one correct response in K samples is:

\boxed{ \text{Pass@K} = 1-(1-p)^K }

for this simplified setting.

For:

K=5,

we get:

1-(0.8)^5.
0.8^5=0.32768.

Therefore:

\text{Pass@5} = 1-0.32768 = \boxed{0.67232}.

So:

\boxed{67.2\%}.

This formula is a useful mathematical interpretation of Pass@K, though the supplied slide's primary point is the empirical Pass@K vs Maj@K behavior rather than a derivation of this formula.

5.11.14 Suppose RL increases p

Now suppose RL changes:

p=0.2 \rightarrow p=0.6.

Then:

\text{Pass@5} = 1-(1-0.6)^5
=1-0.4^5
=1-0.01024
=\boxed{98.976\%}.

So increasing the probability of successful reasoning dramatically increases the chance of seeing at least one correct answer.

But in the slide's interpretation, the particularly important gain is that correct answers become more likely to be the dominant/selected answer, not merely somewhere in the sample set. (Source: deepseekmath-slides)

5.11.15 Now connect this directly to GRPO

Remember:

A_i= \frac{R_i-\mu_R}{\sigma_R+\epsilon}.

Suppose:

R=[1,0,0,0].

Then the one successful response receives:

A>0.

The incorrect responses receive:

A<0.

Therefore the policy update approximately says:

\boxed{ \text{increase probability of successful trajectory} }

and:

\boxed{ \text{decrease probability of unsuccessful trajectories} }

Repeated across many problems, that reshapes the distribution.

That is exactly the bridge:

\boxed{ \text{GRPO mathematics} \rightarrow \text{distribution sharpening} }

5.11.16 Why GRPO beats Online RFT

Now compare two approaches.

Online RFT

Correct:

R=1

Wrong:

R=0.

The correct rollouts receive a binary reinforcement signal.

GRPO

Use:

A_i= \frac{R_i-\mu}{\sigma+\epsilon}.

So the signal is relative.

The supplied deck says that Online RFT and GRPO use the same online data source; their key difference is the gradient coefficient. GRPO provides a richer continuous signal that reinforces above-average responses more strongly and penalizes below-average ones. (Source: deepseekmath-slides)

5.11.17 Numerical comparison

Suppose:

R=[1,1,0,0].

Mean:

\mu=0.5.

Unnormalized deviations:

[+0.5,+0.5,-0.5,-0.5].

Online RFT essentially gives:

[1,1,0,0].

GRPO instead gives positive/negative relative signals.

Therefore:

\boxed{ \text{GRPO has directional suppression as well as reinforcement} }

rather than merely:

\boxed{ \text{rewarded = reinforce} }

5.11.18 Why actively penalizing bad responses matters

Imagine all four responses:

R=[1,1,0,0].

You want to increase:

P(o_1),P(o_2)

and decrease:

P(o_3),P(o_4).

GRPO naturally supplies:

A_{1},A_{2}>0

and:

A_{3},A_{4}<0.

This gives the policy a much richer update direction.

That richer gradient coefficient is exactly what the supplied deck highlights. (Source: deepseekmath-slides)

5.11.19 Outcome supervision vs Process supervision

Now we reach another important experiment.

Outcome supervision

Reward only the final result.

For example:

\boxed{ R= 1\quad\text{if final answer is correct} }
0\quad\text{otherwise}.

This is:

\boxed{\text{GRPO+OS}}

in the supplied slide terminology.

5.11.20 Process supervision

Instead of only evaluating the final answer, provide reward signals at intermediate reasoning steps.

For example:

Step 1 → correct setup      +1
Step 2 → correct algebra    +1
Step 3 → correct substitution +1
Step 4 → correct answer     +1

The slide describes process supervision as giving one reward per reasoning step, rather than only a final-answer reward. (Source: deepseekmath-slides)

This produces:

\boxed{\text{GRPO+PS}}.

5.11.21 Why should process supervision help?

Consider this reasoning chain:

S_1\rightarrow S_2\rightarrow S_3\rightarrow S_4

where only the final answer is checked.

Suppose the final answer is wrong.

With outcome supervision:

R=0.

But maybe:

S_1

and:

S_2

were perfectly correct, and the mistake happened at:

S_3.

Outcome supervision doesn't tell us exactly where the reasoning went wrong.

This creates a credit-assignment problem.

5.11.22 Process supervision provides finer credit assignment

Instead of:

[0]

we might have:

[1,1,0,0].

Now the learning system receives more localized information.

Conceptually:

\boxed{ \text{final reward} \rightarrow \text{coarse credit} }

while:

\boxed{ \text{step rewards} \rightarrow \text{fine-grained credit} }

The supplied slides report that:

\boxed{\text{GRPO+PS}}

edges out:

\boxed{\text{GRPO+OS}}

in the cited comparison, suggesting the finer credit assignment is useful. (Source: deepseekmath-slides)

5.11.23 Why doesn't DeepSeekMath simply use process supervision everywhere?

Because it is more expensive and difficult.

For outcome supervision:

\text{one final verification}.

For process supervision:

\text{verify many intermediate steps}.

That raises the requirements for:

  • step-level correctness checking,
  • reward-model or verifier quality,
  • data construction,
  • computational cost.

The supplied material identifies the empirical benefit but does not provide a complete cost analysis in the cited slide, so we should not attach a specific cost number here.

5.11.24 Iterative RL — another important idea

The deck also introduces Iterative GRPO.

Suppose we have a reward model trained using behavior from:

\pi_0.

After substantial RL:

\pi_t

may generate responses that look very different.

The old reward model may now be operating out of distribution.

Therefore its judgments can become less trustworthy.

The supplied slides describe iterative GRPO as periodically:

  1. retraining the reward model on fresh rollouts,
  2. retaining 10% older data as replay,
  3. resetting the reference policy,
  4. continuing training. (Source: deepseekmath-slides)

5.11.25 Why does this make sense?

We have a moving policy:

\pi_0 \rightarrow \pi_1 \rightarrow \pi_2 \rightarrow \pi_3.

If the reward model was trained on:

\pi_0\text{'s outputs},

then eventually:

\pi_3

may produce very different outputs.

Thus:

\boxed{ \text{policy distribution shifts} \rightarrow \text{reward model distribution shift} }

This is another form of instability in RL training.

5.11.26 Why keep old data?

The supplied slide says the iterative procedure retains about:

\boxed{10\%}

older data as replay.

Conceptually, this prevents the new reward model from completely forgetting the earlier distribution while adapting to the current one. (Source: deepseekmath-slides)

So:

\boxed{ \text{fresh data} + \text{some historical data} }

helps maintain continuity.

5.11.27 Put all DeepSeekMath experiments into one hierarchy

We can now see the evolution:

\boxed{\text{SFT}}

teaches the model from demonstrations.

Then:

\boxed{\text{Offline RFT}}

uses fixed sampled responses.

Then:

\boxed{\text{Online RFT}}

continually samples from the updated policy.

Then:

\boxed{\text{GRPO}}

adds richer group-relative gradient coefficients.

Then:

\boxed{\text{GRPO+PS}}

adds finer-grained process supervision.

Then:

\boxed{\text{Iterative GRPO}}

refreshes reward modeling as the policy changes.

This is the experimental progression presented across the supplied DeepSeekMath slides. (Source: deepseekmath-slides)

5.11.28 The most important conceptual axis

The slide's unifying lens is:

\boxed{ \text{What data do we train on?} }

and:

\boxed{ \text{What gradient coefficient do we apply?} }

So:

                 TRAINING METHOD
                       │
             ┌─────────┴─────────┐
             │                   │
        DATA SOURCE         GRADIENT SIGNAL
             │                   │
      offline / online      binary / relative /
                           token / process ...

This makes the algorithms much easier to compare. (Source: deepseekmath-slides)

5.11.29 DeepSeekMath result — the headline number

After applying GRPO to DeepSeekMath-Instruct:

\text{MATH} : 46.8\%\rightarrow51.7\%.

Therefore:

\boxed{+4.9\text{ percentage points}}.

GSM8K:

82.9\%\rightarrow88.2\%
\boxed{+5.3\text{ points}}.

CMATH:

84.6\%\rightarrow88.8\%
\boxed{+4.2\text{ points}}.

(Source: deepseekmath-slides)

5.11.30 Why the CMATH result matters

The RL training data came from:

\boxed{\text{GSM8K + MATH}}

yet CMATH also improved.

So the result is not simply:

\text{memorize training benchmark}.

It suggests some transfer of the improved reasoning behavior to a related out-of-domain benchmark. (Source: deepseekmath-slides)

5.11.31 One subtle but important conclusion

DeepSeekMath teaches us that RL can be extremely effective without necessarily requiring the model to learn an entirely new algorithmic capability from scratch.

The evidence in the deck suggests:

\boxed{ \text{successful behaviors already present} }

can be:

\boxed{ \text{amplified and made more likely} }

through reinforcement.

This is why:

\text{Pass@K}\approx\text{stable}

while:

\text{Maj@K}\uparrow

is so informative. (Source: deepseekmath-slides)

5.11.32 Numerical — Pass@K

A model has:

p=0.3

chance of producing a correct answer in any individual sample.

For:

K=4,

under the simplified independent-sampling assumption:

\text{Pass@4} = 1-(1-0.3)^4
= 1-(0.7)^4
= 1-0.2401 = \boxed{0.7599}.

So:

\boxed{75.99\%}.

5.11.33 Numerical — probability sharpening

Suppose before RL:

P(\text{correct})=0.25.

After RL:

P(\text{correct})=0.55.

Probability increase:

0.55-0.25 = \boxed{0.30}.

So the correct behavior gained:

\boxed{30\text{ percentage points}}

of probability mass in this toy example.

This illustrates the deck's “sharpening” interpretation.

5.11.34 Numerical — outcome vs process supervision

Suppose four reasoning steps receive:

[1,1,0,1].

Under process supervision, total step reward might be:

1+1+0+1 = \boxed{3}

depending on the reward design.

Under binary outcome supervision, if the final answer is wrong:

\boxed{R_{\text{outcome}}=0}.

The process signal therefore contains substantially more information about where the successful/unsuccessful trajectory differed, although the exact aggregation depends on the particular training setup.

5.11.35 Interview question

Question: Why does GRPO need multiple responses for the same prompt?

Correct reasoning:

\boxed{ \text{because its advantage is relative to the group's reward distribution} }

For:

G=1,

the only reward is also the group mean, so:

R_1-\mu=0.

There is no meaningful relative signal.

5.11.36 Interview question

Question: Why can GRPO improve Maj@K without greatly improving Pass@K?

Answer:

Because RL may primarily change the probability distribution over already-available behaviors.

The model may already be able to generate a correct solution occasionally, so Pass@K remains similar.

But GRPO increases the probability of successful trajectories, making the correct answer more likely to dominate the sampled set:

\boxed{ \text{correct behavior becomes more probable} }

which increases Maj@K. This is the interpretation highlighted in the supplied deck. (Source: deepseekmath-slides)

5.11.37 Interview question

Question: What is the difference between Online RFT and GRPO if both sample from the current policy?

Answer:

\boxed{\text{data source is similar}}

but:

\boxed{\text{gradient coefficient is different}}.

Online RFT uses a simpler binary reinforcement signal, while GRPO uses group-relative advantages that both reward above-average responses and penalize below-average responses. (Source: deepseekmath-slides)

5.11.38 Interview question

Question: What is the difference between outcome supervision and process supervision?

\boxed{\text{Outcome supervision}}

judges the final result.

\boxed{\text{Process supervision}}

provides feedback on intermediate reasoning steps.

Therefore:

\boxed{ \text{OS = coarse credit assignment} }
\boxed{ \text{PS = fine-grained credit assignment} }

The supplied slide reports GRPO+PS slightly outperforming GRPO+OS in its cited comparison. (Source: deepseekmath-slides)

5.11.40 The bridge to DeepSeek-R1

This is the point where the story becomes very interesting.

DeepSeekMath established:

\boxed{\text{GRPO + verifiable rewards}}

as a practical reasoning-training recipe.

DeepSeek-R1 then takes the same broad RL idea much further, including a much larger model, stronger reasoning behavior, staged training, and eventually distillation into small students.

The supplied book explicitly describes GRPO as originating in DeepSeekMath and later being used for DeepSeek-R1. (Source: Build a Reasoning Model (From Scratch))

So:

\boxed{ \text{DeepSeekMath} = \text{proof of the training mechanism} }

while:

\boxed{ \text{DeepSeek-R1} = \text{large-scale reasoning system built around it} }

Final mental model for Step 5.11

The most important chain to memorize is:

\boxed{ \text{GRPO does not simply ask “is the answer good?”} }

It effectively asks:

\boxed{ \text{“Among several ways the model tried to solve this problem, which behaviors were better than the others?”} }

Then:

\boxed{ \text{better trajectories} \rightarrow A>0 \rightarrow \text{probability increased} }

and:

\boxed{ \text{worse trajectories} \rightarrow A<0 \rightarrow \text{probability decreased} }

Repeated over many problems:

\boxed{ \text{distribution sharpens toward successful reasoning}. }

That is the central empirical lesson the DeepSeekMath slides draw from the Pass@K/Maj@K analysis. (Source: deepseekmath-slides)
