Step 5.48.1B — Complete DeepSeek Causal MTP Training Pass

Plan node: A3 · chat order #91

↩ Back to main text: Step 1.1 — What Exactly Is a Language Model? · Step 2.5 — Putting the Decoding Strategies Together

Now we will take a real toy sequence and trace it from beginning to end.

This is the step where the earlier equations stop looking abstract.

We will answer four things:

\boxed{ \text{Which hidden state predicts which token?} }
\boxed{ \text{Why does the sequence length shrink?} }
\boxed{ \text{How are the MTP losses aligned?} }
\boxed{ \text{How do they combine with the main next-token loss?} }

The source implementation uses exactly this overall flow: main Transformer → h_{\text{main}} → sequential MTP modules → logits at each depth → combined loss. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.1 Start with a tiny sequence

Take:

X= [t_1,t_2,t_3,t_4,t_5,t_6].

Think of:

t1      t2      t3      t4      t5      t6
 │       │       │       │       │       │
 ▼       ▼       ▼       ▼       ▼       ▼
hidden representations from main Transformer

After the main Transformer:

H^0= [h_1^0,h_2^0,h_3^0,h_4^0,h_5^0,h_6^0].

So:

\boxed{ H^0\in\mathbb R^{6\times d} }

for one example.

This is the initial hidden-state sequence that enters the MTP chain. The source explicitly describes the hidden states from the main Transformer as the starting h^0 representations for MTP. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.2 Ordinary next-token training first

Before MTP, the normal LM head sees:

H^0

and produces:

Z_{\text{main}} = H^0W_{out}.

Hence:

Z_{\text{main}} \in\mathbb R^{6\times V}.

The conceptual targets are:

h1^0 → t2
h2^0 → t3
h3^0 → t4
h4^0 → t5
h5^0 → t6

The final position h_6^0 has no next token inside this finite example.

So ordinary next-token prediction gives a one-step learning signal.

5.48.1B.3 Now turn on MTP with D=3

Suppose:

D=3.

That means we want a three-step future horizon.

The source's toy verification also uses:

D=3.

(Source: Build a DeepSeek Model (From Scratch))

Now we run:

\boxed{ MTP_1\rightarrow MTP_2\rightarrow MTP_3. }

5.48.1B.4 MTP depth 1

At depth 1, we need one future token.

So the valid positions are:

t_1,t_2,t_3,t_4,t_5.

Why not t_6?

Because there is no:

t_7.

Therefore:

L_1=6-1=5.

This is exactly the source implementation's:

L = S - depth_k

for the first depth. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.5 What happens position by position?

The first MTP stage receives:

[h_1^0,h_2^0,h_3^0,h_4^0,h_5^0]

and future-token embeddings corresponding to the shifted sequence:

[E(t_2),E(t_3),E(t_4),E(t_5),E(t_6)].

So conceptually:

h1^0 + E(t2) → MTP1 → h1^1 → predict t2
h2^0 + E(t3) → MTP1 → h2^1 → predict t3
h3^0 + E(t4) → MTP1 → h3^1 → predict t4
h4^0 + E(t5) → MTP1 → h4^1 → predict t5
h5^0 + E(t6) → MTP1 → h5^1 → predict t6

This is the easiest way to understand the first stage.

So:

\boxed{ MTP_1:\quad h_i^0\rightarrow t_{i+1} }

with the future-token embedding incorporated inside the module.

5.48.1B.6 Important subtlety

At first this might look strange:

“Why are we giving the model E(t_{i+1}) while asking it to predict t_{i+1}?”

Exactly.

This is one reason MTP must be understood primarily as a training architecture, not as simply “the normal inference model predicts three tokens.”

The source's training implementation explicitly uses the ground-truth future-token embedding for the MTP module. (Source: Build a DeepSeek Model (From Scratch))

The point is to construct a richer intermediate representation and train the model through that representation.

5.48.1B.7 MTP 1 output

After MTP 1:

H^1= [h_1^1,h_2^1,h_3^1,h_4^1,h_5^1]

so:

\boxed{ H^1\in\mathbb R^{5\times d}. }

Then shared unembedding produces:

Z^1=H^1W_{out}

with:

\boxed{ Z^1\in\mathbb R^{5\times V}. }

These logits correspond to the first future-token prediction depth. The source explicitly says the new hidden state is sent to the shared unembedding matrix to produce the logits for the relevant future token. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.8 Now MTP depth 2

This is where the architecture becomes interesting.

We do not go back to:

H^0.

Instead:

\boxed{ H^1\rightarrow MTP_2. }

This is the causal chain.

But we also need a second future position.

Now:

L_2=6-2=4.

So only the first four positions have enough future tokens for depth 2.

We take:

[h_1^1,h_2^1,h_3^1,h_4^1].

And the corresponding future-token embeddings:

[E(t_3),E(t_4),E(t_5),E(t_6)].

Thus:

h1^1 + E(t3) → MTP2 → h1^2 → predict t3
h2^1 + E(t4) → MTP2 → h2^2 → predict t4
h3^1 + E(t5) → MTP2 → h3^2 → predict t5
h4^1 + E(t6) → MTP2 → h4^2 → predict t6

Therefore:

\boxed{ MTP_2:\quad h_i^1\rightarrow t_{i+2}. }

5.48.1B.9 Why is h_i^1 important?

Remember:

h_i^1

is not the original hidden representation.

It has already passed through:

  1. the original Transformer,
  2. RMSNorm + future embedding merge,
  3. the MTP-1 Transformer block.

So h_i^1 is a refined hidden state.

Therefore MTP 2 is making its prediction from a representation that has already been transformed by the previous prediction stage.

That is precisely the causal refinement property highlighted by the source. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.10 MTP 2 output

We obtain:

H^2= [h_1^2,h_2^2,h_3^2,h_4^2]

and:

\boxed{ H^2\in\mathbb R^{4\times d}. }

Shared output projection:

Z^2=H^2W_{out}

gives:

\boxed{ Z^2\in\mathbb R^{4\times V}. }

5.48.1B.11 MTP depth 3

Now:

L_3=6-3=3.

So we use:

[h_1^2,h_2^2,h_3^2].

And future embeddings:

[E(t_4),E(t_5),E(t_6)].

Thus:

h1^2 + E(t4) → MTP3 → h1^3 → predict t4
h2^2 + E(t5) → MTP3 → h2^3 → predict t5
h3^2 + E(t6) → MTP3 → h3^3 → predict t6

Hence:

\boxed{ MTP_3:\quad h_i^2\rightarrow t_{i+3}. }

And:

\boxed{ H^3\in\mathbb R^{3\times d}. }

while:

\boxed{ Z^3\in\mathbb R^{3\times V}. }

5.48.1B.12 Put the whole thing in one table

For:

S=6,\qquad D=3,

we get:

Depth Previous state Future embedding Valid length Target
Main H^0 — 6 next token
MTP 1 H^0 E(t_{i+1}) 5 t_{i+1}
MTP 2 H^1 E(t_{i+2}) 4 t_{i+2}
MTP 3 H^2 E(t_{i+3}) 3 t_{i+3}

The source's implementation follows the same shrinking-length pattern. Its concrete S=20,D=3 example produces lengths 20,19,18,17. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.13 The prediction grid

Here is the same idea in the most exam-friendly form:

                         FUTURE TARGETS

Current
position       +1       +2       +3
────────────────────────────────────────
t1              t2       t3       t4
t2              t3       t4       t5
t3              t4       t5       t6
t4              t5       t6        -
t5              t6        -        -
t6               -        -        -

So for K=3:

  • position t_1 has 3 targets,
  • t_2 has 3,
  • t_3 has 3,
  • t_4 has 2,
  • t_5 has 1,
  • t_6 has 0.

This is why the usable sequence lengths are:

5,\;4,\;3

for the three explicit MTP stages.

5.48.1B.14 But where does the loss compare against?

Take MTP 1.

Its predictions are aligned with:

[t_2,t_3,t_4,t_5,t_6].

So its loss is conceptually:

L_1 = -\sum_{i=1}^{5} \log P_1(t_{i+1}).

For MTP 2:

L_2 = -\sum_{i=1}^{4} \log P_2(t_{i+2}).

For MTP 3:

L_3 = -\sum_{i=1}^{3} \log P_3(t_{i+3}).

This is the essence of the multi-horizon loss.

The source describes the final MTP loss as the sum of the individual cross-entropy losses for the different prediction depths. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.15 Now see the repeated supervision

Look at token t_4.

It appears as a target in:

L_1

from position t_3,

and:

L_2

from position t_2,

and:

L_3

from position t_1.

Therefore:

\boxed{ t_4\text{ receives supervision at multiple prediction depths}. }

Likewise t_5 and t_6 can appear at multiple depths.

This is the mechanism behind the source's idea of densified training signals and the repeated influence of important future tokens. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.16 Why does this matter for “choice points”?

Recall the source's example:

1\rightarrow2\rightarrow3\rightarrow4\rightarrow5\rightarrow A\rightarrow B.

Suppose A is the important pattern-changing token.

Then:

starting point 3 → 4, 5, A
starting point 4 → 5, A, B
starting point 5 → A, B, C

So the loss associated with predicting A appears repeatedly.

Thus:

\boxed{ A \text{ influences multiple training terms}. }

The source interprets this as implicitly giving greater importance to such critical pattern shifts. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.17 Now combine with the main loss

The complete source implementation does not replace ordinary next-token prediction.

It keeps:

\boxed{ L_{\text{main}} }

and adds MTP losses:

\boxed{ L = L_{\text{main}} + \frac{\lambda}{D} \sum_{k=1}^{D} L_k. }

The source's implementation explicitly uses this weighted-average form. (Source: Build a DeepSeek Model (From Scratch))

So MTP is an additional training signal, not a replacement for the main language-model objective in this implementation.

5.48.1B.18 Numerical loss example with our sequence

Suppose the computed average losses are:

L_{\text{main}}=0.60
L_1=0.40
L_2=0.80
L_3=1.00.

Then:

\sum_{k=1}^{3}L_k = 0.40+0.80+1.00 = 2.20.

Average MTP loss:

\frac{2.20}{3} = 0.7333.

Suppose:

\lambda=0.1.

Then:

L_{\text{MTP contribution}} = 0.1(0.7333) = 0.07333.

Therefore:

\boxed{ L_{\text{total}} = 0.60+0.07333 = 0.67333. }

5.48.1B.19 Important distinction: “sum” vs “weighted average”

The source explains conceptually that the loss for one input token is the sum of the depth-specific losses. (Source: Build a DeepSeek Model (From Scratch))

The source's complete implementation then scales the aggregate MTP losses using:

\frac{\lambda}{D}.

So both statements fit together:

Inside MTP
\boxed{ \sum_kL_k }
Contribution to complete model objective
\boxed{ \frac{\lambda}{D}\sum_kL_k. }

This is an important exam distinction.

5.48.1B.20 Code ↔ mathematics

The source's code:

h_prev = h_main

for depth_k in range(1, self.num_mtp_heads + 1):

    L = S - depth_k

    h_prev_sliced = h_prev[:, :L, :]

    future_token_ids = input_ids[:, depth_k:depth_k + L]

    future_token_embeds = self.get_embedding(
        future_token_ids
    )

    h_curr = self.mtp_modules[depth_k - 1](
        h_prev_sliced,
        future_token_embeds
    )

    logits_k = self.get_output_logits(h_curr)

    all_logits.append(logits_k)

    h_prev = h_curr

(Source: Build a DeepSeek Model (From Scratch))

Maps directly to:

h^{k-1}

↓

\text{slice valid positions}

↓

E(t_{i+k})

↓

M_k[\operatorname{RMSNorm}(h^{k-1}); \operatorname{RMSNorm}(E(t_{i+k}))]

↓

TRM_k

↓

h^k

↓

W_{out}

↓

z^k.

Then:

h^k\rightarrow h^{k+1}.

5.48.1B.21 Why does h_prev = h_curr matter so much?

Consider removing:

h_prev = h_curr

Then every MTP module would keep using:

h^0.

You would effectively get:

h^0\rightarrow MTP_1
h^0\rightarrow MTP_2
h^0\rightarrow MTP_3.

That is much closer to an independent-head architecture.

But with:

h_prev = h_curr

we get:

h^0\rightarrow h^1\rightarrow h^2\rightarrow h^3.

So that one assignment is responsible for the recursive causal dependency in the implementation. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.22 Why does the code slice h_prev?

At depth k:

h_prev_sliced = h_prev[:, :L, :]

Suppose:

S=20.

At:

k=2:
L=18.

We therefore use:

h_{1}^{1},h_{2}^{1},...,h_{18}^{1}

and discard the final two positions for this particular prediction depth because they do not have two future targets available.

So:

\boxed{ \text{deeper horizon} \Rightarrow \text{fewer valid positions}. }

5.48.1B.23 The sequence-length formula

For MTP depth k:

\boxed{ L_k=S-k. }

Therefore:

L_1=S-1
L_2=S-2
L_3=S-3

and generally:

\boxed{ L_k=S-k. }

This is one of the best formulas to memorize.

5.48.1B.24 Total number of MTP prediction positions

For sequence length S and depth D, the total number of MTP positions is:

\boxed{ \sum_{k=1}^{D}(S-k) }

which simplifies to:

\boxed{ DS-\frac{D(D+1)}{2}. }
Numerical

Let:

S=100,\quad D=3.

Then:

L_1=99
L_2=98
L_3=97.

Total MTP position-depth predictions:

99+98+97 = 294.

So:

\boxed{294}

MTP prediction positions exist across the whole sequence.

5.48.1B.25 Compare that with standard NTP

For the same sequence:

S=100,

standard next-token prediction gives:

99

valid next-token targets.

MTP with D=3 gives:

294

depth-position prediction terms.

Thus the raw number of supervised prediction positions is approximately:

\frac{294}{99} \approx2.97.

So almost three times as many prediction terms are created.

This illustrates the source's notion of denser training signals. (Source: Build a DeepSeek Model (From Scratch))

Be careful, though: this does not mean exactly 3× total training compute or exactly 3× useful learning. Each MTP module contains additional computation.

5.48.1B.26 Tensor-shape exam problem

Given:

B=8,\quad S=128,\quad d=512,\quad V=32,000,\quad D=4.

Find the logits shape at MTP depth 3.

We first calculate:

L_3=128-3=125.

Therefore:

H^3:
[8,125,512].

Shared unembedding:

[8,125,512] \times [512,32000].

Therefore:

\boxed{ Z^3=[8,125,32000]. }

5.48.1B.27 Parameter-count exam problem

Suppose:

d=1024.

Each MTP projection:

M_k\in\mathbb R^{d\times2d}.

Therefore:

1024\times2048 = \boxed{2,097,152}.

So one projection has:

\boxed{2.097M}

weights.

For:

D=4

MTP modules, the projections alone require:

4\times2,097,152 = \boxed{8,388,608}.

That is:

\boxed{8.39M}

parameters, before counting the Transformer blocks inside those MTP modules.

5.48.1B.28 The source's two implementations: an important note

The DeepSeek book presents both:

  1. a conceptual/self-contained DeepSeekMTPModule, and
  2. a more integrated MiniDeepSeek training-path implementation.

The first explicitly shows:

\operatorname{RMSNorm} \rightarrow \operatorname{concat} \rightarrow \text{projection} \rightarrow \text{Transformer}.

(Source: Build a DeepSeek Model (From Scratch))

The second integrates that chain with the full model and MTP loss. Its training-path example shows the slicing and embedding alignment explicitly. (Source: Build a DeepSeek Model (From Scratch))

The source also uses slightly different indexing conventions between the explanatory diagrams and code listings. For exams, the safest conceptual rule is:

\boxed{ \text{Depth }k \text{ predicts a future token }k\text{ steps ahead} }

while the exact tensor slicing follows the implementation shown in the relevant listing.

5.48.1B.29 Training-time teacher forcing intuition

There is another important idea hiding here.

During training, the future embedding is taken from the ground truth.

So suppose:

t1  t2  t3  t4  t5  t6

At MTP 2, the module can receive the ground-truth embedding associated with t_3, rather than having to rely on a sampled t_3.

This avoids making the training path depend on a discrete sampled prediction at every MTP stage.

So the training computation remains differentiable through the hidden-state transformations.

The source explicitly states that future-token embeddings used by the MTP module are ground-truth embeddings during training. (Source: Build a DeepSeek Model (From Scratch))

5.48.1B.30 Then what happens during inference?

This is extremely important:

\boxed{ \text{MTP training path} \neq \text{ordinary inference path}. }

The source's integrated model has a separate inference branch.

When:

targets=None,

it goes into the inference path, uses KV caching, processes the newly arriving token(s), and computes the final logits from the last hidden position. (Source: Build a DeepSeek Model (From Scratch))

The source later explains that although the public release uses standard single-token prediction for inference, MTP modules can potentially be repurposed for speculative decoding. (Source: Build a DeepSeek Model (From Scratch))

So don't make the exam mistake:

\boxed{ D=3\text{ during training} \not\Rightarrow \text{normal generation always emits 3 tokens per forward pass}. }

5.48.1B.32 What exactly should you remember for the exam?

Memorize these five equations:

1. Valid sequence length
\boxed{ L_k=S-k }
2. Merged MTP input
\boxed{ u_i^k = [RMSNorm(h_i^{k-1});RMSNorm(E(t_{i+k}))] }
3. Projection
\boxed{ h_i^{\prime k}=M_ku_i^k }
4. Causal refinement
\boxed{ h_i^k=TRM_k(h_i^{\prime k}), \qquad h^k\rightarrow MTP_{k+1} }
5. Complete loss
\boxed{ L = L_{\text{main}} + \frac{\lambda}{D} \sum_{k=1}^{D}L_k }

5.48.1B.33 One final check

Suppose:

S=10,\qquad D=3.

Then:

L_1=9, \quad L_2=8, \quad L_3=7.

Total:

9+8+7=\boxed{24}.

Now suppose:

B=4,\quad V=20,000.

Then:

\boxed{ Z^1=[4,9,20000] }
\boxed{ Z^2=[4,8,20000] }
\boxed{ Z^3=[4,7,20000]. }

And the hidden-state chain is:

\boxed{ H^0 \rightarrow H^1 \rightarrow H^2 \rightarrow H^3. }

That is the complete causal MTP training pass.

The deepest idea from this step

The entire architecture can now be summarized as:

\boxed{ \text{Main Transformer learns context} }

then:

\boxed{ \text{MTP 1 learns one-step future representation} }

then:

\boxed{ \text{MTP 2 refines that representation for a deeper future} }

then:

\boxed{ \text{MTP 3 refines it again}. }

Therefore:

\boxed{ \text{MTP is not merely “predict more tokens.”} }

It is:

\boxed{ \textbf{repeated latent refinement across future prediction depth}. }

That is the key idea behind the source's description of DeepSeek's causal MTP architecture. (Source: Build a DeepSeek Model (From Scratch))
