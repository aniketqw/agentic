Continuation · checked fixture T18 — SwiGLU gate, up and down projections

Checked continuation mechanism and declared fixture; this is not certification of every inherited claim.

Use one learned feature stream to modulate another before projecting back to model width.

Prerequisites: Positionwise MLP and GELU variants

Notation and assumptions

Row input X:T×d; gate/up:d×f; down:f×d. SiLU(a)=a·sigmoid(a). No biases in this fixture.

Derivation and mechanism

  1. Compute G=XWgate and U=XWup.
  2. Apply SiLU to G, multiply elementwise by U.
  3. Project the f features with Wdown.
Y=(\mathrm{SiLU}(XW_g)\odot XW_u)W_d

Worked example

X=[1,2], gate=identity, up=[[2,1],[0,1]], down=identity gives G=[1,2], U=[2,3], output=[2/(1+e^-1),6/(1+e^-2)]≈[1.462117,5.284782].

Limitations

  • A gated FFN has three weight matrices rather than two.
  • An empirical advantage of a variant is specific to a training/evaluation setting.

Connections to later concepts

  • T19 counts the third gated projection. A02 substitutes selected expert FFNs for a single dense FFN.

New teaching capsule and stated examples only; inherited prose/formulas/code remain pending

← Previous audit card · Next audit card →

Why this matters

Normalize a token across its feature dimensions while keeping token positions separate.

Prerequisites: Expectation and population variance

Symbols, shapes and assumptions

μ and variance use the feature population denominator d. The normalized variance is σ²/(σ²+ε). Learned gamma/beta can change the final mean and variance.

Derivation or mechanism

  1. Compute μ and σ² over one token feature row.
  2. Divide centered features by √(σ²+ε).
  3. Apply per-feature gamma and beta.
y_j=\gamma_j\frac{x_j-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_j

Worked numerical

For [1,3], μ=2 and σ²=1. With ε=0, gamma=1, beta=0, the output is [-1,1]. With ε=1 it becomes [-1/√2,1/√2], whose variance is 1/2. With ε=0, gamma=[2,3] and beta=[1,-1], the output is [-1,2]. For [4,4], positive epsilon gives [0,0].

Edge cases and limits

  • Unit variance is an approximation when epsilon is positive, before an unrestricted affine step.
  • Sample variance with denominator d-1 changes the operation.
  • RMSNorm is a separate method and is not certified by these LayerNorm checks.

Connections

Step 1.10 — Position-Wise Feed-Forward Network (FFN / MLP)

Plan node: I1 · chat order #17

We have now built the attention part:

X \rightarrow Q,K,V \rightarrow \text{attention} \rightarrow \text{MHA}

But a Transformer block does not consist only of attention.

There is another major computation:

\boxed{\text{Feed-Forward Network / MLP}}

The Transformer slides make an important division:

\boxed{ \text{Attention = information mixing across positions} }
\boxed{ \text{MLP = nonlinear processing within each position} }

(Source: transformers-slides)

This distinction is fundamental.

1.10.1 Why Do We Need an MLP After Attention?

Let's first understand the problem.

Suppose we have:

The cat is sleeping

Attention allows the representation of "is" to gather information from:

The
cat
is

So attention answers:

What information should this token gather from other positions?

But after gathering the information, the model still needs to process and transform the resulting vector.

That is the job of the MLP.

So conceptually:

\boxed{ \text{Attention: gather information} }

then:

\boxed{ \text{MLP: process that information} }

The slides phrase this as attention deciding what information to gather while the MLP performs nonlinear processing of that information. (Source: transformers-slides)

1.10.2 The Most Important Difference From Attention

Attention mixes information between tokens.

For example:

x_3

can receive information from:

x_1,x_2,x_3.

Therefore attention involves interactions like:

x_i \leftrightarrow x_j.

The MLP does not do that.

For each token separately:

x_i\rightarrow \operatorname{FFN}(x_i).

There is no:

x_i\leftrightarrow x_j

inside that MLP operation.

So if:

X= \begin{bmatrix} x_1\\ x_2\\ x_3 \end{bmatrix},

the FFN conceptually does:

\begin{bmatrix} x_1\\ x_2\\ x_3 \end{bmatrix} \rightarrow \begin{bmatrix} FFN(x_1)\\ FFN(x_2)\\ FFN(x_3) \end{bmatrix}.

Each token is processed independently using the same learned weights.

That is why it is called:

\boxed{\text{position-wise FFN}}

The slides explicitly state that it is applied identically and independently to every token position. (Source: transformers-slides)

1.10.3 The FFN Formula

The basic equation is:

\boxed{ FFN(x) = W_2\phi(W_1x+b_1)+b_2 }

where:

  • x = input token representation
  • W_1 = first linear transformation
  • b_1 = first bias
  • \phi = nonlinear activation
  • W_2 = second linear transformation
  • b_2 = second bias.

The Transformer slides give this exact structure. (Source: transformers-slides)

1.10.4 Why Two Linear Layers?

Look carefully:

x \rightarrow W_1x+b_1 \rightarrow \phi \rightarrow W_2(\cdot)+b_2.

The first layer expands the representation.

The activation introduces nonlinearity.

The second layer compresses it back.

So:

\boxed{ d \rightarrow d_{ff} \rightarrow d }

The source describes this as:

expansion → GELU → contraction.

For the GPT-style example in Raschka:

768\rightarrow3072\rightarrow768.

(Source: Build a Large Language Model (From Scratch))

1.10.5 Why Expand First?

This is a very important conceptual question.

Suppose:

x\in\mathbb{R}^{768}.

If we only applied another 768\rightarrow768 linear transformation, we would have a much more limited computational bottleneck.

Instead, the first transformation creates a richer hidden representation:

768\rightarrow3072.

Then GELU introduces nonlinear processing in this larger space.

Then:

3072\rightarrow768.

This gives the MLP a larger intermediate computational space.

Raschka explicitly describes the expansion as allowing the model to explore a richer representation space. (Source: Build a Large Language Model (From Scratch))

1.10.6 Tensor Shapes

Let:

x\in\mathbb{R}^{d}.

Then:

W_1\in\mathbb{R}^{d_{ff}\times d}.

Therefore:

W_1x

has shape:

d_{ff}.

After activation:

a=\phi(W_1x+b_1)

still has shape:

d_{ff}.

Then:

W_2\in\mathbb{R}^{d\times d_{ff}}.

So:

W_2a

has shape:

d.

Therefore:

\boxed{ d \rightarrow d_{ff} \rightarrow d }

1.10.7 Matrix Version

For the entire sequence:

X\in\mathbb{R}^{n\times d}.

Then:

Z=XW_1+b_1.

The shape is:

(n\times d)(d\times d_{ff}) = n\times d_{ff}.

Then:

A=\phi(Z)

still:

n\times d_{ff}.

Then:

Y=AW_2+b_2

gives:

(n\times d_{ff})(d_{ff}\times d) = n\times d.

Thus:

\boxed{ X:n\times d \rightarrow Z:n\times d_{ff} \rightarrow A:n\times d_{ff} \rightarrow Y:n\times d }

The output and input width match, which is necessary for the later residual addition.

The mathematical cheatsheet explicitly records these shapes. (Source: Step1_Transformers_Mathematical_Cheatsheet)

1.10.8 The Batch Version

In a real Transformer:

X\in\mathbb{R}^{B\times n\times d}.

Then:

XW_1

produces:

\boxed{ B\times n\times d_{ff} }

and the final output is:

\boxed{ B\times n\times d. }

For example:

B=2,\quad n=3,\quad d=8,\quad d_{ff}=32.

Then:

X: 2\times3\times8

becomes:

2\times3\times32

and finally:

2\times3\times8.

Raschka's implementation likewise demonstrates that the FFN input/output tensor shape remains unchanged, e.g. [2, 3, 768] → [2, 3, 768]. (Source: Build a Large Language Model (From Scratch))

1.10.9 Why Is d_{ff} Usually Larger Than d?

The slides use the common GPT-style relationship:

\boxed{ d_{ff}=4d }

(Source: transformers-slides)

So if:

d=768,

then:

d_{ff}=4(768)=3072.

Hence:

768\rightarrow3072\rightarrow768.

This is one of the easiest things to turn into an exam numerical.

Numerical 1 — Direct Calculation

Suppose:

d=512

and:

d_{ff}=4d.

Then:

d_{ff}=4(512)=2048.

Therefore:

\boxed{ 512\rightarrow2048\rightarrow512 }

So each token's representation temporarily expands from 512 dimensions to 2048 dimensions.

1.10.10 Now the Most Important Part: GELU

The activation is typically:

\boxed{\phi=\operatorname{GELU}}

in the slide formulation.

The slide gives:

\boxed{ GELU(x)=x\Phi(x) }

where:

\Phi(x)

is the standard normal cumulative distribution function. (Source: transformers-slides)

So:

FFN(x) = W_2\,GELU(W_1x+b_1)+b_2.

1.10.11 What Does GELU Actually Do?

A common first intuition is:

"It is basically ReLU."

Not exactly.

ReLU:

ReLU(x)=\max(0,x).

So:

ReLU(-2)=0
ReLU(2)=2.

GELU behaves more smoothly.

It does not sharply set all negative values to zero.

The Transformer slides explicitly distinguish it from ReLU by noting that GELU smoothly damps negative values instead of sharply zeroing them. (Source: transformers-slides)

1.10.12 Exact GELU Formula

\boxed{ GELU(x)=x\Phi(x) }

For a standard Gaussian:

\Phi(x) = \int_{-\infty}^{x} \frac{1}{\sqrt{2\pi}} e^{-u^2/2}\,du.

Thus:

GELU(x) = x \int_{-\infty}^{x} \frac{1}{\sqrt{2\pi}} e^{-u^2/2}\,du.

The cheatsheet you generated includes both the exact formula and the common approximation. (Source: Step1_Transformers_Mathematical_Cheatsheet)

Numerical 2 — GELU at x=1

We know:

\Phi(1)\approx0.8413.

Therefore:

GELU(1) = 1(0.8413)
\boxed{ GELU(1)\approx0.8413 }

Compare:

ReLU(1)=1.

So GELU does not simply copy the positive value unchanged.

Numerical 3 — GELU at x=-1

We know:

\Phi(-1)\approx0.1587.

Therefore:

GELU(-1) = (-1)(0.1587)
\boxed{ GELU(-1)\approx-0.1587 }

Compare:

ReLU(-1)=0.

So GELU keeps a small negative contribution.

This is one reason the activation is smoother.

1.10.13 Now Do an Entire FFN Numerically

Let's choose a tiny example.

Let:

d=2

and:

d_{ff}=3.

Take:

x= \begin{bmatrix} 1\\ -1 \end{bmatrix}.

Choose:

W_1= \begin{bmatrix} 1&0\\ 0&1\\ 1&1 \end{bmatrix}

and:

b_1= \begin{bmatrix} 0\\ 0\\ 0 \end{bmatrix}.

1.10.14 First Linear Layer

Calculate:

z=W_1x+b_1.

So:

z= \begin{bmatrix} 1&0\\ 0&1\\ 1&1 \end{bmatrix} \begin{bmatrix} 1\\ -1 \end{bmatrix}.

Therefore:

z= \begin{bmatrix} 1\\ -1\\ 0 \end{bmatrix}.

So:

\boxed{ z=[1,-1,0]^T }

1.10.15 Apply GELU

We know approximately:

GELU(1)=0.8413
GELU(-1)=-0.1587

and:

GELU(0)=0.

Therefore:

a= \begin{bmatrix} 0.8413\\ -0.1587\\ 0 \end{bmatrix}.

So:

\boxed{ a= GELU(z) }

1.10.16 Second Linear Layer

Now choose:

W_2= \begin{bmatrix} 1&1&0\\ 0&1&1 \end{bmatrix}

and:

b_2= \begin{bmatrix} 0\\ 0 \end{bmatrix}.

Then:

y=W_2a+b_2.

First component:

y_1 = 1(0.8413)+1(-0.1587)+0(0)
=0.6826.

Second component:

y_2 = 0(0.8413)+1(-0.1587)+1(0)
=-0.1587.

So:

\boxed{ FFN(x)\approx \begin{bmatrix} 0.6826\\ -0.1587 \end{bmatrix} }

Notice what happened:

\boxed{ 2\rightarrow3\rightarrow2 }

The FFN temporarily expanded the representation, performed nonlinear processing, and returned to the original dimension.

1.10.17 Why Is the Nonlinearity Essential?

Imagine removing GELU.

Then:

FFN(x)=W_2(W_1x+b_1)+b_2.

Ignoring biases for intuition:

FFN(x)=W_2W_1x.

That is still fundamentally a linear transformation.

Stacking multiple linear transformations without nonlinear activations can collapse into another linear transformation.

The nonlinear activation prevents the entire FFN from behaving like just one giant linear transformation.

So:

\boxed{ W_1 + GELU + W_2 }

is much more expressive than:

\boxed{ W_2W_1 }

alone.

This is why the nonlinear function is a key part of the MLP.

1.10.18 Why Doesn't the FFN Need a Mask?

Because the FFN does not compare different positions.

Suppose:

X= \begin{bmatrix} x_1\\ x_2\\ x_3 \end{bmatrix}.

Then:

FFN(X) = \begin{bmatrix} FFN(x_1)\\ FFN(x_2)\\ FFN(x_3) \end{bmatrix}.

There is no:

x_1x_2^T

or:

x_2x_3^T.

Therefore:

\boxed{ \text{No token-token communication} }

and hence no causal mask is needed inside the basic FFN.

1.10.19 Attention vs MLP

This distinction is extremely exam-worthy.

Attention MLP / FFN
Mixes information across positions Processes each position independently
Uses Q/K/V Uses linear layers + activation
Produces attention weights No attention weights
Uses token-to-token interactions No token-to-token interaction inside FFN
Needs causal mask in decoder No causal mask inside FFN
Main operation is AV Main operation is W_2\phi(W_1x+b_1)+b_2

The slides explicitly summarize this division of labor. (Source: transformers-slides)

1.10.20 Numerical Track — Parameter Count

Now we enter the kind of numerical question that can easily appear in an exam.

For:

W_1\in\mathbb{R}^{d_{ff}\times d}

the number of weights is:

d_{ff}d.

For:

W_2\in\mathbb{R}^{d\times d_{ff}}

the number is:

dd_{ff}.

Therefore the two weight matrices together contain:

\boxed{ 2dd_{ff} }

parameters.

The cheatsheet explicitly gives:

FFN\approx2dd_{ff}.

(Source: Step1_Transformers_Mathematical_Cheatsheet)

Numerical 4 — FFN Parameter Count

Suppose:

d=768

and:

d_{ff}=3072.

Then:

W_1: 3072\times768

so:

3072(768)=2,359,296.

Similarly:

W_2: 768\times3072

also:

2,359,296.

Therefore total weights:

2,359,296+2,359,296
\boxed{ 4,718,592 }

If biases are included:

b_1:3072

and:

b_2:768.

Total biases:

3072+768=3840.

Hence:

4,718,592+3,840 = \boxed{ 4,722,432 }

FFN parameters.

1.10.21 Important Complexity Numerical

For one token:

W_1x

costs roughly:

O(dd_{ff})

and:

W_2a

also costs:

O(dd_{ff}).

So:

\boxed{ FFN\text{ compute}\approx O(2dd_{ff}) }

per token up to constant/convention details.

With:

d_{ff}=4d,

we get:

2d(4d) = 8d^2.

The cheatsheet explicitly records:

\boxed{ FFN\approx8d^2 \quad\text{when }d_{ff}=4d. }

(Source: Step1_Transformers_Mathematical_Cheatsheet)

Numerical 5 — Compare FFN and Attention Projection Parameters

Suppose:

d=768.

The four major attention projections are approximately:

W_Q,W_K,W_V,W_O

each around:

768\times768.

So:

4d^2

parameters.

Calculate:

d^2=768^2=589,824.

Thus:

4d^2 = 2,359,296.

The FFN has approximately:

8d^2

weights under:

d_{ff}=4d.

Therefore:

8(589,824) = \boxed{ 4,718,592. }

So in this simplified comparison:

\boxed{ FFN\text{ weights}\approx2\times\text{attention projection weights}. }

This is an important architectural numerical insight captured in the cheatsheet. (Source: Step1_Transformers_Mathematical_Cheatsheet)

1.10.22 Why Is This Important?

You may initially think:

"Attention must dominate the model because it is the complicated part."

But parameter-count-wise, the FFN can be extremely large.

For the common:

d_{ff}=4d

configuration:

FFN\approx8d^2

while:

Q/K/V/O\approx4d^2.

So the FFN has roughly twice as many projection parameters.

This will matter later when we study:

  • model size,
  • computational cost,
  • MoE architectures,
  • inference optimization,
  • quantization,
  • parameter-efficient fine-tuning.

1.10.23 A Very Important Conceptual Boundary

Attention operates across positions:

\boxed{ [n\times d] \rightarrow [n\times n] \rightarrow [n\times d_v]. }

The n\times n matrix is the key clue.

The FFN does not construct an:

n\times n

interaction matrix.

Instead:

\boxed{ [n\times d] \rightarrow [n\times d_{ff}] \rightarrow [n\times d]. }

This is a fantastic exam trick.

If a question asks:

Which component allows token-to-token information interaction?

Answer:

\boxed{\text{Attention}}

If it asks:

Which component independently transforms each position through a nonlinear function?

Answer:

\boxed{\text{FFN/MLP}}

1.10.24 Position-Wise Does Not Mean Sequential

Another common misunderstanding:

"Position-wise" does not mean the MLP processes token 1, then token 2, then token 3 sequentially.

It means the same function is independently applied to every position.

So mathematically:

FFN(x_1),FFN(x_2),\ldots,FFN(x_n)

can all be computed in parallel as one tensor operation.

That is:

\boxed{ \text{independent across positions} \neq \text{sequential across positions} }

1.10.25 Now Insert FFN Into the Transformer Block

We previously had the MHA sublayer:

h= x+\operatorname{MHA}(\operatorname{Norm}(x)).

Now the FFN follows:

\boxed{ y= h+\operatorname{FFN}(\operatorname{Norm}(h)). }

So the complete pre-normalization block is:

\boxed{ h=x+\operatorname{MHA}(\operatorname{LN}(x)) }
\boxed{ y=h+\operatorname{FFN}(\operatorname{LN}(h)). }

The Transformer cheatsheet you generated contains exactly this block formulation. (Source: Step1_Transformers_Mathematical_Cheatsheet)

1.10.26 The Entire Decoder Block Is Now Visible

We started with:

X

then:

Normalize
LN(X)
Multi-head causal attention
MHA(LN(X))
Residual
H= X+MHA(LN(X)).

Then:

Normalize again
LN(H)
Feed-forward
FFN(LN(H))
Residual
Y= H+FFN(LN(H)).

Therefore:

\boxed{ Y= H+FFN(LN(H)) }

where:

\boxed{ H=X+MHA(LN(X)). }

This is the fundamental Transformer block architecture we have been building piece by piece.
