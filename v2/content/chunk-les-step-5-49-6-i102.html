We have now completed all five FP8 pillars individually. This response is deliberately a synthesis, not a sixth FP8 concept.

The purpose is to make one thing completely clear:

\boxed{ \text{How do all five ideas cooperate inside one actual matrix multiplication during training?} }

The source explicitly presents the five pillars as one multi-part framework rather than five unrelated tricks. (Source: Build a DeepSeek Model (From Scratch))

5.49.6.1 The five pillars again — but now as one machine

We have:

\boxed{\text{Pillar 1: Mixed Precision}}

Use different precisions for different jobs.

\boxed{\text{Pillar 2: Fine-Grained Quantization}}

Scale small groups/blocks independently.

\boxed{\text{Pillar 3: Increasing Accumulation Precision}}

Periodically promote partial results to FP32 accumulation.

\boxed{\text{Pillar 4: Mantissa over Exponents}}

Use E4M3 because fine-grained scaling helps control dynamic range.

\boxed{\text{Pillar 5: Online Quantization}}

Calculate the scale from the tensor being processed now rather than stale historical statistics.

The source explicitly summarizes these five in exactly this spirit. (Source: Build a DeepSeek Model (From Scratch))

5.49.6.2 Start with the ordinary linear layer

Everything happens around:

\boxed{ Y=WX }

For one output element:

\boxed{ Y_{ij} = \sum_{k=1}^{K}W_{ik}X_{kj}. }

The source uses this equation as the starting point for both its mixed-precision and accumulation discussions.

5.49.6.3 Before computation: what representation do we have?

According to the source:

Activations

Typically stored as:

\boxed{BF16}.
Master weights

Stored in:

\boxed{FP32}.
Optimizer state

Stored in:

\boxed{FP32}.

The source explicitly identifies these as the higher-precision persistent quantities.

5.49.6.4 Now Pillar 5 enters first

We need to quantize the current tensor.

Instead of using an old scale:

s_{t-1},

the source says to inspect the current tensor:

X_t.

Compute:

\boxed{ \alpha_t=\max|X_t|. }

Then derive the scale.

So the first conceptual operation is:

\boxed{ X_t \rightarrow \alpha_t \rightarrow s_t. }

This is Online Quantization. (Source: Build a DeepSeek Model (From Scratch))

5.49.6.5 But Pillar 2 says: don't use one scale for everything

Suppose:

X_t

is a long activation vector.

DeepSeek does not necessarily use one global:

\alpha_t.

Instead, the source says the activation vector is broken into:

\boxed{ N_C=128 }

element groups.

Each group gets its own scale.

Therefore, more precisely:

\boxed{ \alpha_{t,g} = \max_{i\in g}|X_{t,i}| }

and:

\boxed{ s_{t,g} }

is derived separately for every group g.

That is the combination:

\boxed{ \text{Pillar 2 + Pillar 5} = \text{local + current}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.6.6 Weight quantization works similarly

The source says the weight matrix is divided into:

\boxed{ 128\times128 }

blocks.

So for weight block b:

\alpha_{t,b} = \max_{i\in b}|W_{t,i}|.

Then:

s_{t,b}

is calculated for that block.

Therefore:

\boxed{ \text{activation group} \rightarrow \text{local current scale} }

and:

\boxed{ \text{weight block} \rightarrow \text{local current scale}. }

5.49.6.7 Now where does E4M3 enter?

Once the local dynamic ranges are controlled, DeepSeek can use:

\boxed{E4M3}

for its FP8 computations.

Why?

Because:

E4M3 = 1\text{ sign}+4\text{ exponent}+3\text{ mantissa}.

Compared with:

E5M2 = 1+5+2,

E4M3 has:

\boxed{\text{more mantissa precision}}

but:

\boxed{\text{less dynamic range}}.

The source's argument is that fine-grained quantization has already mitigated the dynamic-range problem sufficiently to let DeepSeek favor the extra mantissa bit.

So:

\boxed{ \text{Pillar 2 enables Pillar 4}. }

5.49.6.8 Quantized tensors enter the GEMM

Now we have:

X_{FP8}

and:

W_{FP8}.

The source says the three major GEMMs use FP8:

\boxed{ Fprop,\quad Dgrad,\quad Wgrad. }

So the forward calculation becomes conceptually:

\boxed{ Y\leftarrow W_{FP8}X_{FP8}. }

5.49.6.9 But now Pillar 3 takes over

The Tensor Core performs fast low-precision matrix multiplication.

The source describes WGMMA as the low-level instruction performing chunks of this matrix multiplication.

So the calculation isn't thought of as one giant operation:

4096

products appearing magically at once.

Instead, it can be understood as chunks:

\boxed{ WGMMA_1 \rightarrow WGMMA_2 \rightarrow WGMMA_3 \rightarrow\cdots }

with each contributing to the running sum.

5.49.6.10 The low-precision accumulator

The Tensor Core maintains:

\boxed{ \text{Low Prec Acc} }

while processing those chunks.

The source's problem is:

\boxed{ \text{this accumulator has limited precision}. }

For large inner dimensions, repeatedly adding many products can cause numerical error.

5.49.6.11 DeepSeek doesn't wait until the end

The source specifies a promotion interval:

\boxed{ N_C=128. }

After the relevant chunk of work, the low-precision partial sum is moved to a general-purpose CUDA Core.

So:

\boxed{ \text{Low Prec Acc} \xrightarrow{N_C} \text{FP32 Register}. }

5.49.6.12 Why FP32 register?

Suppose:

P_1,P_2,P_3,\ldots

are promoted partial sums.

The FP32 register maintains:

\boxed{ A= P_1+P_2+P_3+\cdots }

in higher precision.

So the long-running reduction is protected from the narrower low-precision accumulator.

This is the essence of:

\boxed{\text{Pillar 3}}.

5.49.6.13 Now Pillar 2 comes back again

Remember:

X\approx s_XQ_X

and:

W\approx s_WQ_W.

So the low-precision multiplication gives a quantity proportional to:

Q_XQ_W.

The source explains that the CUDA Core stage uses the corresponding scaling factors to restore the magnitude of the result.

Conceptually:

\boxed{ Y \approx s_Xs_W(Q_XQ_W). }

This equation is a derived mathematical abstraction of the source's scale-restoration diagram, not a literal hardware-level equation printed as such.

5.49.6.14 The output is then stored in BF16

After high-precision accumulation/dequantization, the source says the result is ready to be stored in:

\boxed{BF16}.

So the complete forward path is:

\boxed{ BF16 \rightarrow \text{online local scaling} \rightarrow FP8 \rightarrow \text{Tensor Core GEMM} \rightarrow \text{FP32 accumulation} \rightarrow \text{dequantization} \rightarrow BF16. }

5.49.6.15 Now complete the backward pass

Suppose the layer is:

Y=WX.

There are two important gradients.

Dgrad
\boxed{ \frac{\partial L}{\partial X} = \frac{\partial L}{\partial Y}W^T. }

The source says:

dL/dY

is typically stored in BF16, converted to FP8 for computation, and the result uses FP32 accumulation before being stored as BF16.

So:

\boxed{ BF16 \rightarrow FP8 \times FP8 \rightarrow FP32\text{ accumulate} \rightarrow BF16. }

5.49.6.16 Wgrad

The source gives:

\boxed{ \frac{\partial L}{\partial W} = X^T\frac{\partial L}{\partial Y}. }

Again, the GEMM uses FP8 inputs.

But now there is an important difference:

\boxed{ dW\text{ is stored in FP32}. }

The source explicitly identifies Wgrad as the critical gradient because it directly drives the weight update.

So:

\boxed{ FP8\times FP8 \rightarrow FP32\ dW. }

5.49.6.17 Then the optimizer operates in FP32

The source gives:

\boxed{ W_{\text{master,new}} = W_{\text{master,old}} - \text{learning rate} \cdot dW. }

And all of the important update state remains in:

\boxed{FP32}.

That includes:

  • master weights,
  • weight gradients,
  • optimizer states such as momentum/variance,
  • the update itself.

5.49.6.19 Now identify exactly what each pillar is doing inside this diagram

Pillar 1

Controls the precision map:

\boxed{ FP8/BF16/FP32 }

across the computation.

Pillar 2

Controls the spatial granularity of scaling:

\boxed{ 128\text{-element activation groups} }

and:

\boxed{ 128\times128\text{ weight blocks}. }
Pillar 3

Controls the accumulation path:

\boxed{ \text{low precision} \rightarrow \text{FP32 promotion}. }
Pillar 4

Controls the FP8 bit allocation:

\boxed{ E4M3. }
Pillar 5

Controls the time at which scales are calculated:

\boxed{ \text{current tensor}. }

5.49.6.20 This reveals something important

The five pillars operate on different axes.

Pillar Axis
Mixed precision Which numerical format?
Fine-grained scaling Which region gets the scale?
Accumulation precision Where does the running sum live?
E4M3 choice How are the 8 bits allocated?
Online quantization When is the scale measured?

This is why they are complementary rather than redundant.

5.49.6.21 A complete numerical example

Suppose a single local activation group is:

X=[1.0,\;2.0,\;-4.0].

Assume a simplified target maximum:

q_{\max}=127.
Online scaling

Current maximum:

\alpha_X=4.

Therefore:

s_X=\frac{127}{4}=31.75.

Quantized values:

1(31.75)\rightarrow32
2(31.75)\rightarrow64
-4(31.75)\rightarrow-127.

Thus:

\boxed{ Q_X=[32,64,-127]. }

This is a simplified INT8-style illustration of the source's scaling concept; the actual DeepSeek computation uses FP8 rather than this integer example.

5.49.6.22 Suppose the local weight values have:

W=[0.5,-1,2].

Then:

\alpha_W=2.

Therefore:

s_W=\frac{127}{2}=63.5.

The important point is not the exact resulting FP8 code, but:

\boxed{ s_W \neq s_X. }

Because:

\boxed{ \text{weights and activations have independent local scales}. }

That follows directly from the source's fine-grained design.

5.49.6.23 If an outlier appears next batch

Suppose current activation group becomes:

[1,2,100].

Online scaling immediately computes:

\alpha_X=100.

So the scale changes.

The previous batch's scale is not blindly reused.

Therefore:

\boxed{ \text{scale follows the current data distribution}. }

That is Pillar 5.

5.49.6.24 If the outlier appears in a different group

Suppose:

Group A → [1,2,3]
Group B → [1,2,100]

Fine-grained quantization means:

s_A

is determined by:

3,

while:

s_B

is determined by:

100.

So:

\boxed{ 100\text{ does not force Group A to use Group B's scale}. }

That is Pillar 2.

5.49.6.25 Why E4M3 is then attractive

Because Group A has a locally controlled range.

Thus it doesn't need the huge exponent range that a single global tensor scale might have required.

So DeepSeek can prioritize:

\boxed{ 3\text{ mantissa bits} }

over:

\boxed{ 5\text{ exponent bits}. }

That is Pillar 4.

5.49.6.26 Why FP32 accumulation is still necessary

Even after local scaling:

Q_XQ_W

can produce many partial products.

Suppose:

K=4096.

Then one output involves:

4096

products.

Fine-grained scaling doesn't automatically make the running sum numerically safe.

Therefore:

\boxed{ Pillar 2\text{ solves scale range} }

but:

\boxed{ Pillar 3\text{ solves accumulation precision}. }

This is a very important distinction.

5.49.6.27 Why online scaling also doesn't solve accumulation

Similarly:

\boxed{ Pillar 5 }

ensures:

\text{good current scale}.

But it doesn't change how thousands of products are added.

So:

\boxed{ \text{good scale} \neq \text{good accumulator}. }

Hence Pillars 2, 3, and 5 solve different problems.

5.49.6.28 The architecture as a chain of safeguards

You can think of it this way:

\boxed{ \text{FP8 is aggressive} }

so:

\boxed{ \text{Mixed Precision} }

prevents us from applying it indiscriminately.

Then:

\boxed{ \text{Fine-Grained Scaling} }

prevents outliers from destroying local precision.

Then:

\boxed{ \text{Online Scaling} }

prevents yesterday's statistics from being applied to today's tensor.

Then:

\boxed{ \text{FP32 Accumulation} }

protects long matrix reductions.

Finally:

\boxed{ \text{E4M3} }

uses the available 8-bit budget in favor of precision once the range problem is controlled.

5.49.6.29 One exam question that combines all five

Question

Why can DeepSeek use E4M3 uniformly rather than using E5M2 for the backward pass?

Reasoning

Normally:

\text{backward} \rightarrow \text{large gradient outliers} \rightarrow \text{need more exponent range}

which motivates E5M2.

But DeepSeek:

\boxed{ \text{fine-grained scaling} }

reduces the influence of outliers at the local level.

Then:

\boxed{ \text{online scaling} }

keeps the scales matched to the current tensor.

Therefore the need for huge global dynamic range is reduced.

So DeepSeek can use:

\boxed{ E4M3 }

and gain:

\boxed{ \text{one extra mantissa bit}. }

This is exactly the synergistic argument made in the source. (Source: Build a DeepSeek Model (From Scratch))

5.49.6.30 One exam question on the complete system

Question

A model uses:

128

activation elements per group and:

128\times128

weight blocks.

What are these numbers doing?

Answer

They determine:

\boxed{ \text{where independent scaling factors are applied}. }

They are not:

\boxed{ \text{the FP8 bit width} }

and not:

\boxed{ \text{the Tensor Core accumulation precision}. }

The activation grouping and weight blocking belong to Pillar 2.

5.49.6.31 One exam question on N_C

This is a classic confusion.

We saw:

N_C=128

in more than one place.

But ask:

“What does N_C=128 mean here?”

For the activation quantization discussion:

\boxed{ 128\text{ activation channels per group}. }

For accumulation promotion:

\boxed{ 128\text{ element-wise operations per promotion interval}. }

Same numerical value in the source, but different roles.

Do not conflate them.
