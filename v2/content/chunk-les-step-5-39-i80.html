Concentrating every token on a single expert can waste the available expert capacity.

Prerequisites: MoE top-k routing and selected normalization, Expectation and population variance

Notation and assumptions

Switch-style top1 illustration: f_i assigned-token fraction, P_i mean router probability, E experts, coefficient a. Not a universal DeepSeek balancing formula.

Derivation and mechanism

  1. Count realized top1 assignments to obtain f.
  2. Average soft router probabilities to obtain P.
  3. Compute aEΣf_iP_i and distinguish this differentiable surrogate from a hard load guarantee.
L_{balance}=aE\sum_i f_iP_i

E2,a1: assignments[0,1],all probabilities[.5,.5]→loss1. Assignments[0,0],all probabilities[1,0]→loss2. Loss1 is a reference value for this uniform fixture, not zero.

Step 5.39 — MoE Load Balancing: Why Routing Must Be Controlled

Plan node: A2 · chat order #80

↩ Back to main text: Step 1.10 — Position-Wise Feed-Forward Network (FFN / MLP)

We have now built the basic sparse MoE:

\boxed{ y_t= \sum_{i\in TopK(t)}g_{t,i}E_i(x_t) }

But this immediately creates the most important training problem in MoE:

\boxed{\text{imbalanced routing}}

The source presents three successive approaches:

\boxed{ \text{Auxiliary Loss} \rightarrow \text{Load-Balancing Loss} \rightarrow \text{Auxiliary-Loss-Free Bias} }

We will derive them in exactly that order. (Source: Build a DeepSeek Model (From Scratch))

5.39.1 First understand what “balance” actually means

Imagine:

N=4

experts and:

T=100

tokens.

Suppose:

k=2.

Every token chooses two experts, so there are:

100\times2 = \boxed{200}

total expert assignments.

Perfectly balanced routing would give:

\frac{200}{4} = \boxed{50}

assignments to each expert.

So the ideal routing is:

[50,50,50,50].

Suppose instead we get:

[90,70,30,10].

Still:

90+70+30+10=200,

but the distribution is terrible.

Expert 1 is a hotspot.

Expert 4 is barely used.

5.39.2 Why not simply force equal routing?

Because routing is supposed to be learned.

Suppose every token is mathematically forced to go equally to every expert.

Then we lose the point of specialization.

We want:

\boxed{\text{specialization}}

while simultaneously preventing:

\boxed{\text{collapse onto a few experts}}.

So load balancing is a soft preference, not “make every expert process exactly the same token.”

That tension is the heart of MoE routing.

5.39.3 Three different quantities you must not confuse

This is extremely important for the exam.

For expert i, we can discuss:

1. Router probability / importance

How much probability the router assigns to expert i.

2. Actual load

How many tokens are actually dispatched to expert i after Top-K.

3. Capacity

The maximum number of tokens expert i is allowed to process in a batch.

These are different.

The source explicitly highlights the distinction between importance and actual load. (Source: Build a DeepSeek Model (From Scratch))

5.39.4 Attempt #1 — Auxiliary Loss

The traditional idea is simple:

Add another term to the training objective that encourages the router to distribute importance more uniformly.

So instead of only optimizing:

L_{\text{main}}

we optimize:

\boxed{ L_{\text{total}} = L_{\text{main}} + \lambda L_{\text{aux}} }

where:

  • L_{\text{main}}: normal language-model loss,
  • L_{\text{aux}}: routing-balancing penalty,
  • \lambda: controls how strongly balancing matters.

The source explicitly describes the auxiliary loss as an additional penalty designed to be high for imbalanced expert importance and low for balanced importance. (Source: Build a DeepSeek Model (From Scratch))

5.39.5 What is “expert importance”?

Suppose the router gives probabilities:

P= \begin{bmatrix} 0.7 & 0.2 & 0.1\\ 0.4 & 0.5 & 0.1\\ 0.3 & 0.3 & 0.4\\ 0.0 & 0.2 & 0.8 \end{bmatrix}.

Each row is one token.

Each column is one expert.

So:

P_{t,i}

means:

the router's probability for expert i on token t.

The source measures an expert's importance by aggregating these probabilities across the batch. (Source: Build a DeepSeek Model (From Scratch))

For expert i:

\boxed{ I_i=\sum_{t=1}^{T}P_{t,i} }

in the source's conceptual treatment.

5.39.6 Example: calculate importance

Using the matrix above:

Expert 1
I_1= 0.7+0.4+0.3+0 = \boxed{1.4}
Expert 2
I_2= 0.2+0.5+0.3+0.2 = \boxed{1.2}
Expert 3
I_3= 0.1+0.1+0.4+0.8 = \boxed{1.4}

So:

\boxed{ I=[1.4,1.2,1.4] }

The ideal total importance is:

4

because every token contributes total probability 1:

\sum_iI_i=T.

Ideal equal importance:

4/3=1.3333.

Our values are reasonably close.

5.39.7 Convert importance to probability

The source later calls the normalized version:

p_i

and computes it by dividing expert importance by the number of tokens. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ p_i=\frac{I_i}{T} }

For the example:

p_1=\frac{1.4}{4}=0.35
p_2=\frac{1.2}{4}=0.30
p_3=\frac{1.4}{4}=0.35.

And:

0.35+0.30+0.35=1.

So p_i tells us:

On average, how much router probability mass does expert i receive?

5.39.8 Why does auxiliary loss help?

Because the model is encouraged to make:

p_1,p_2,\ldots,p_N

closer to:

\frac1N.

For:

N=4,

the ideal is:

[0.25,0.25,0.25,0.25].

So the auxiliary objective pushes the routing distribution toward that point.

5.39.9 But here comes the subtle flaw

Balancing probability does not necessarily balance actual token count.

This distinction is explicitly emphasized by the source. (Source: Build a DeepSeek Model (From Scratch))

Consider the source's illustrative example.

There are:

\boxed{2\text{ experts}}

and:

Expert 1

One token gives it probability:

1.0.

Importance:

1.0.
Expert 2

Four tokens each give it probability:

0.25.

Importance:

0.25+0.25+0.25+0.25 = 1.0.

Therefore:

I_1=I_2=1.

So an importance-based auxiliary objective sees:

\boxed{\text{perfect balance}}.

But actual token routing is:

E_1:1\text{ token}
E_2:4\text{ tokens}.

That is a:

\boxed{4\times}

difference in workload.

(Source: Build a DeepSeek Model (From Scratch))

5.39.10 This is the key distinction

Think of it this way:

\boxed{ \text{Importance} = \text{how much probability I receive} }

while:

\boxed{ \text{Load} = \text{how many tokens I actually process} }

Those can disagree.

This gives us the motivation for:

5.39.11 Attempt #2 — Load-Balancing Loss

The source therefore introduces a more sophisticated objective that considers both:

\boxed{f_i}

and:

\boxed{p_i}.

where:

  • f_i = fraction of tokens actually dispatched to expert i,
  • p_i = average router probability assigned to expert i. (Source: Build a DeepSeek Model (From Scratch))

The source describes the objective as proportional to:

\boxed{ \sum_i f_i p_i }

scaled by:

N\lambda.

Thus the source-style load balancing objective is:

\boxed{ L_{\text{load}} = \lambda N\sum_{i=1}^{N}f_i p_i }

with the goal of minimizing it. (Source: Build a DeepSeek Model (From Scratch))

5.39.12 What exactly is f_i?

Suppose:

T

tokens are in the batch.

For expert i, count how many tokens were actually dispatched to it.

Call that:

C_i.

Then:

\boxed{ f_i=\frac{C_i}{T} }

in the source's fraction-of-tokens interpretation. (Source: Build a DeepSeek Model (From Scratch))

Important:

With top-k, one token can appear in multiple expert assignments.

So depending on the precise convention, “fraction” can be defined over routed assignments or tokens. For the chapter's illustrative development, follow the source's stated definition and examples rather than silently substituting another MoE paper's convention.

5.39.13 Numerical example for f_i

Suppose:

T=100

tokens.

After Top-2 routing:

C=[60,50,40,50].

Then:

f_1=0.60
f_2=0.50
f_3=0.40
f_4=0.50.

Again, the exact normalization convention matters in production implementations; here we are following the chapter's conceptual treatment.

5.39.14 Why multiply f_i and p_i?

This is the clever part.

Suppose an expert has:

f_i\gg \frac1N

meaning it receives many tokens,

and also:

p_i\gg \frac1N

meaning the router strongly favors it.

Then:

f_ip_i

becomes large.

Thus minimizing:

\sum_i f_ip_i

discourages an expert from simultaneously being:

\boxed{\text{highly selected}}

and:

\boxed{\text{highly weighted}}.

5.39.15 Perfectly balanced example

Suppose:

N=4

and ideal routing is:

f_i=0.25

and:

p_i=0.25

for all experts.

Then:

\sum_i f_ip_i = 4(0.25\times0.25)
= 4(0.0625) = \boxed{0.25}.

Therefore:

L_{\text{load}} = \lambda N(0.25) = \lambda.

So the balanced case gives a neat baseline.

5.39.16 Why the factor N?

The factor:

N

normalizes/scales the objective with the number of experts.

The source explicitly states that the expression is scaled by the number of experts and the hyperparameter \lambda. (Source: Build a DeepSeek Model (From Scratch))

Don't think of N as creating the balance by itself.

The important part is:

\boxed{f_i p_i}

The N and \lambda control scaling/strength.

5.39.17 Exam numerical: compute a load loss

Suppose:

N=4,\qquad \lambda=0.01

and:

f=[0.4,0.3,0.2,0.1]

while:

p=[0.25,0.25,0.25,0.25].

Then:

\sum_i f_ip_i = 0.4(0.25)+0.3(0.25)+0.2(0.25)+0.1(0.25)
= 0.25(1.0) = 0.25.

Therefore:

L_{\text{load}} = 0.01\times4\times0.25
= \boxed{0.01}.

Notice something interesting:

Even though f is highly uneven, uniform p makes the simple product sum unchanged.

This is one reason it is important to understand the exact normalization and balancing objective rather than assuming one metric guarantees another.

The source itself motivates load loss precisely because importance balancing alone does not guarantee token-load balancing. (Source: Build a DeepSeek Model (From Scratch))

5.39.18 Now let's use the source's four-token example

The source gives:

p_1=0.35
p_2=0.25
p_3=0.40.

These came from:

I=[1.4,1.0,1.6]

divided by:

T=4.

(Source: Build a DeepSeek Model (From Scratch))

Suppose the actual dispatch fractions are:

f=[0.25,0.50,0.25].

Then:

\sum_i f_ip_i

is:

0.25(0.35)+0.50(0.25)+0.25(0.40)
= 0.0875+0.125+0.100
= \boxed{0.3125}.

For:

N=3

and:

\lambda=0.01,

the scaled loss is:

0.01\times3\times0.3125 = \boxed{0.009375}.

This numerical calculation is based on the source's f_i,p_i definitions and an explicit illustrative f choice; the source snippet does not specify this exact f vector in text.

5.39.19 Now the deeper problem with auxiliary/load losses

We have changed the objective to:

\boxed{ L_{\text{total}} = L_{\text{LM}} + L_{\text{balance}} }

This sounds reasonable.

But now the router is being asked to satisfy two objectives:

\boxed{ \text{1. choose the best experts} }

and:

\boxed{ \text{2. distribute work evenly} }

These objectives can conflict.

Suppose Expert 7 is genuinely much better for mathematics.

The language-model objective might want:

\boxed{\text{send math tokens to Expert 7}}

while the balancing loss might say:

\boxed{\text{stop sending so many tokens to Expert 7}}.

So we introduce a competition between:

\boxed{\text{model quality}}

and:

\boxed{\text{load balance}}.

The source identifies this interference as the fundamental drawback of traditional auxiliary-loss-based balancing. (Source: Build a DeepSeek Model (From Scratch))

5.39.20 DeepSeek asks a different question

Instead of changing the training loss:

L_{\text{main}} \rightarrow L_{\text{main}}+\lambda L_{\text{balance}},

why not leave the primary learning objective alone?

That means:

\boxed{ L=L_{\text{next-token}} }

and control routing by modifying the router itself.

This leads to:

5.39.21 Attempt #3 — Auxiliary-Loss-Free Load Balancing

DeepSeek introduces a persistent bias:

\boxed{b_i}

for each expert.

Instead of:

\text{router logits}

we use:

\boxed{ \text{adjusted logits} = \text{router logits}+b }

before Top-K selection.

The source explicitly states that the dynamic bias is added to raw router logits before top-k selection and softmax normalization. (Source: Build a DeepSeek Model (From Scratch))

5.39.22 Why does adding a bias help?

Suppose original logits are:

[1.7,\;1.5,\;2.3].

Expert 3 is being selected too often.

Suppose bias is:

b=[0.2,\;0.1,\;-0.3].

Then:

L+b = [1.9,\;1.6,\;2.0].

Now Expert 3 becomes less dominant.

Conversely, underused experts receive positive bias.

So the bias changes the probability of future selection without becoming part of the learned neural network weights.

5.39.23 Source's feedback rule

The source uses:

\boxed{ \text{underloaded expert} \rightarrow \text{increase bias} }

and:

\boxed{ \text{overloaded expert} \rightarrow \text{decrease bias} }.

(Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{underused} \Rightarrow b_i\uparrow \Rightarrow L_i\uparrow \Rightarrow \text{more likely selected} }

and:

\boxed{ \text{overused} \Rightarrow b_i\downarrow \Rightarrow L_i\downarrow \Rightarrow \text{less likely selected}. }

This is a classic negative-feedback control loop.

5.39.24 The source's load-violation example

We already had:

[2,2,4]

tokens assigned to:

[E_1,E_2,E_3].

Total:

8.

Average:

\frac83 = 2.67.

Therefore:

v_1=2.67-2=+0.67
v_2=2.67-2=+0.67
v_3=2.67-4=-1.33.

(Source: Build a DeepSeek Model (From Scratch))

Interpretation:

\boxed{ v>0\Rightarrow \text{underloaded} }
\boxed{ v<0\Rightarrow \text{overloaded} }

5.39.25 Why the sign matters

The source describes a simple update based on the sign of the violation.

Conceptually:

\boxed{ b_i \leftarrow b_i+u\,\operatorname{sign}(v_i) }

where u is a small adjustment constant. (Source: Build a DeepSeek Model (From Scratch))

Therefore:

Expert 1
b_1\leftarrow b_1+u
Expert 2
b_2\leftarrow b_2+u
Expert 3
b_3\leftarrow b_3-u.

5.39.26 Modernized source implementation

The source's concrete implementation uses a smoother bounded update:

\boxed{ b_i \leftarrow b_i+ \eta\tanh(v_i) }

where:

\eta = \text{bias learning rate}.

The code is:

violation = (avg - counts) / (avg + 1e-6)
self.bias.add_(self.bias_lr * torch.tanh(violation))

The \tanh makes the update bounded and smoother than a raw sign-based jump.

5.39.27 Numerical bias update

Suppose:

\text{avg}=10.

Expert 1 has:

C_1=8.

Then:

v_1= \frac{10-8}{10} = 0.2.

Suppose:

\eta=0.01.

Then:

\tanh(0.2)\approx0.1974.

So:

\Delta b_1 = 0.01(0.1974)
\approx \boxed{0.001974}.

Thus:

b_1

increases slightly.

5.39.28 Overloaded expert

Suppose:

C_3=15.

Then:

v_3= \frac{10-15}{10} = -0.5.
\tanh(-0.5)\approx-0.4621.

Therefore:

\Delta b_3 = 0.01(-0.4621)
= \boxed{-0.004621}.

Thus:

b_3

decreases.

Exactly the desired direction.

5.39.29 Why call it “loss-free”?

Because we do not add:

L_{\text{balance}}

to the next-token loss.

Instead:

\boxed{ L_{\text{training}} = L_{\text{language}} }

and the balancing mechanism operates through:

\boxed{ b_i }

as a separate control mechanism.

The source emphasizes that this decouples the primary language-learning objective from the balancing objective. (Source: Build a DeepSeek Model (From Scratch))

5.39.30 Very important distinction

The bias:

b_i

is not trained through ordinary backpropagation as a normal model parameter.

In the source implementation it is a buffer and is updated under:

\boxed{\texttt{torch.no\_grad()}}

so the adjustment does not contribute gradients to the main model.

That is why the architecture separates:

\boxed{ \text{gradient-based learning} }

from:

\boxed{ \text{load-control adjustment}. }

5.39.31 Full DeepSeek-style routing sequence

Now we can write the complete pipeline:

X
\downarrow
Router
L=XW_R
\downarrow
Add dynamic bias
\boxed{ L'=L+b }
\downarrow
Top-K
I=TopK(L',k)
\downarrow
Softmax
g_i= \frac{e^{L'_i}} {\sum_{j\in I}e^{L'_j}}
\downarrow
Sparse dispatch
E_i(x),\qquad i\in I
\downarrow
Weighted sum
y= \sum_{i\in I}g_iE_i(x)
\downarrow
Measure load
C_i
\downarrow
Compute violation
v_i= \frac{\bar C-C_i}{\bar C}
\downarrow
Update bias
b_i\leftarrow b_i+\eta\tanh(v_i)
\downarrow

next training step.

This creates:

\boxed{\text{self-correcting routing}}.

5.39.32 Why update for the next step?

This is an important subtlety.

Suppose the current batch routed too many tokens to Expert 3.

We don't magically change the computation that already happened.

Instead:

\boxed{ \text{current batch} \rightarrow \text{measure imbalance} }

then:

\boxed{ \text{update bias} }

then:

\boxed{ \text{next batch uses corrected logits} }.

The source explicitly describes this as a feedback loop carried across training steps. (Source: Build a DeepSeek Model (From Scratch))

5.39.33 Control-theory interpretation

This is a very useful way to remember it.

Let:

\text{target load}=\bar C.

Measure:

\text{error} = \bar C-C_i.

Then:

\text{controller} \rightarrow b_i.

If error is positive:

\text{increase bias}.

If error is negative:

\text{decrease bias}.

So:

\boxed{ \text{MoE balancing} \approx \text{feedback control over router preferences} }

This is an interpretation of the source mechanism rather than a terminology claim made by the source.

5.39.34 Traditional vs DeepSeek balancing

Mechanism What it changes
Auxiliary loss Training objective
Load-balancing loss Training objective using probability + load
DeepSeek loss-free bias Router scores

So:

\boxed{ \text{Traditional} : L_{\text{LM}}+\lambda L_{\text{balance}} }

versus:

\boxed{ \text{DeepSeek} : L_{\text{LM}}, \quad L_{\text{router}}\leftarrow L_{\text{router}}+b }

with b separately updated.

The source's central claim is that this separation avoids making the balancing objective compete directly with language learning. (Source: Build a DeepSeek Model (From Scratch))

5.39.35 But there is still one more problem

Even with load balancing, standard MoE experts can still be too broad.

Suppose:

16

experts.

Each expert has to absorb many domains.

One expert might still learn:

\text{Python} + \text{math} + \text{legal} + \text{grammar}.

That creates:

\boxed{\text{knowledge hybridity}}.

The source identifies this as one of the two fundamental obstacles to ultimate specialization. (Source: Build a DeepSeek Model (From Scratch))

So balancing alone is not enough.

DeepSeek's next architectural idea is:

\boxed{\text{Fine-Grained Expert Segmentation}}.

5.39.36 Exam numerical — full balancing question

Suppose:

T=120

tokens,

N=6

experts,

k=2.
Step 1 — total assignments
120\times2 = \boxed{240}.
Step 2 — ideal average
240/6 = \boxed{40}.

Suppose actual loads:

[30,40,55,25,45,45].
Step 3 — violations

Using:

v_i=\frac{40-C_i}{40}.

We get:

v_1=\frac{40-30}{40} = \boxed{0.25}
v_2=0
v_3=\frac{40-55}{40} = \boxed{-0.375}
v_4=\frac{40-25}{40} = \boxed{0.375}
v_5=-0.125
v_6=-0.125.

Therefore:

\boxed{ E_1,E_4\text{ underloaded} }

and:

\boxed{ E_3,E_5,E_6\text{ overloaded}. }

That means the next update should:

b_1\uparrow,\quad b_4\uparrow

and:

b_3\downarrow,\quad b_5\downarrow,\quad b_6\downarrow.

5.39.37 Exam numerical — capacity

Suppose:

T=4096,\quad k=2,\quad N=32,\quad CF=1.25.

Ideal load:

\frac{4096\times2}{32} = \boxed{256}.

Capacity:

256\times1.25 = \boxed{320}.

So, under the source's simplified capacity discussion:

\boxed{320\text{ tokens/expert}}

is the nominal hard ceiling.

5.39.38 The deepest concept from this step

There are three different goals:

Goal 1 — specialization

Each token should reach useful experts.

Goal 2 — utilization

Experts should not become dead or overloaded.

Goal 3 — learning freedom

Balancing should not damage the language-model objective.

Basic MoE addresses:

\boxed{\text{specialization + sparsity}}

Traditional load balancing addresses:

\boxed{\text{utilization}}

DeepSeek's auxiliary-loss-free balancing tries to obtain:

\boxed{ \text{utilization without directly modifying the main loss} }.
