Control feature magnitude with a root mean square rather than mean centering.

Prerequisites: LayerNorm: variance, epsilon, and affine parameters, Expectation and population variance

Notation and assumptions

Final feature axis, population mean-square; gain matches feature width. Epsilon is inside the square root. This fixture uses no additive bias.

Derivation and mechanism

  1. Square features and average.
  2. Add epsilon and take a square root.
  3. Divide original features and apply gain. Compare against LayerNorm, which subtracts the mean.
y_i=g_i x_i/\sqrt{d^{-1}\sum_jx_j^2+\epsilon}

Worked example

[1,3] has mean-square5. At epsilon0 and gain1, output=[1/√5,3/√5]≈[.447214,1.341641], not [-1,1]. Scaling input positively preserves this output at epsilon0; adding1 does not. Zero input with epsilon>0 yields zero.

Limitations

  • Exact scale invariance is qualified by epsilon.
  • RMSNorm and LayerNorm coincide on zero-mean data with matching epsilon/gain/bias conventions.

Connections to later concepts

  • RMSNorm gain contributes to T19 parameter counts; its epsilon convention also affects every normalized decoder/MTP input.

Step 1.11 — Layer Normalization and RMSNorm

Plan node: I1 · chat order #18

We now have both major computational parts of the Transformer block:

\boxed{\text{Multi-Head Attention}}

and

\boxed{\text{FFN / MLP}}

But there is still a component surrounding them:

\boxed{\text{Normalization}}

Your cheatsheet identifies two forms we need to understand:

\boxed{\text{LayerNorm}}

and

\boxed{\text{RMSNorm}}

The important idea is that normalization keeps activation scales in a useful range and supports stable optimization. Your reasoning-model source explicitly explains that both LayerNorm and RMSNorm serve this core purpose, while RMSNorm removes the mean-centering step. (Source: Build a Reasoning Model (From Scratch))

And because you specifically said the exam will include numericals, this step will be calculation-heavy.

1.11.1 First: Why Do We Need Normalization?

Imagine that a token representation is:

x= [10,\;20,\;30,\;40].

Later in the network it could become:

[100,\;200,\;300,\;400]

or:

[0.001,\;0.002,\;0.003,\;0.004].

The network is repeatedly performing:

\text{linear transformation} \rightarrow \text{nonlinearity} \rightarrow \text{residual addition}.

The scale of the activations can therefore matter greatly for optimization.

Normalization transforms the representation into a more controlled scale.

Conceptually:

\boxed{ \text{raw activation} \rightarrow \text{normalize scale} \rightarrow \text{more stable computation} }

The source describes LayerNorm as subtracting the mean and dividing by the standard deviation, giving zero mean and unit variance. RMSNorm instead scales by the root mean square without explicitly centering at zero. (Source: Build a Reasoning Model (From Scratch))

1.11.2 Very Important: What Dimension Do We Normalize?

Suppose a token has representation:

x= [x_1,x_2,\ldots,x_d].

LayerNorm computes statistics across the features of that token.

So if:

x\in\mathbb{R}^{d},

we calculate one:

\mu

and one:

\sigma^2

for that token.

We are not calculating the mean across all tokens in the sequence.

This matters enormously in numerical questions.

For:

X\in\mathbb{R}^{B\times n\times d},

LayerNorm is typically applied across the final dimension:

\boxed{d}

for each token independently.

1.11.3 LayerNorm — Step 1: Calculate the Mean

Given:

x=[x_1,x_2,\ldots,x_d],

the mean is:

\boxed{ \mu=\frac1d\sum_{i=1}^{d}x_i }

This is the average feature value of that token representation.

Numerical Example

Take:

x=[1,2,3,4].

Then:

d=4.

Therefore:

\mu= \frac{1+2+3+4}{4}
=\frac{10}{4}
\boxed{\mu=2.5}

1.11.4 LayerNorm — Step 2: Center the Values

Subtract the mean:

x_i-\mu.

So:

[1,2,3,4]-2.5

gives:

\boxed{ [-1.5,-0.5,0.5,1.5] }

This is the mean-centering step.

Notice:

-1.5-0.5+0.5+1.5=0.

Therefore the centered vector has mean:

\boxed{0}.

1.11.5 LayerNorm — Step 3: Calculate Variance

The variance is:

\boxed{ \sigma^2 = \frac1d \sum_{i=1}^{d}(x_i-\mu)^2 }

For our example:

[-1.5,-0.5,0.5,1.5].

Square each value:

[2.25,0.25,0.25,2.25].

Add:

2.25+0.25+0.25+2.25=5.

Divide by 4:

\sigma^2=\frac54.

Therefore:

\boxed{ \sigma^2=1.25 }

1.11.6 LayerNorm — Step 4: Standard Deviation

We need:

\sigma=\sqrt{\sigma^2}.

Therefore:

\sigma=\sqrt{1.25}.
\boxed{ \sigma\approx1.1180 }

But in actual numerical implementations, we normally use:

\sqrt{\sigma^2+\epsilon}

rather than simply:

\sqrt{\sigma^2}.

1.11.7 Why Do We Need \epsilon?

The normalization formula uses:

\boxed{ \sqrt{\sigma^2+\epsilon} }

where:

\epsilon

is a small numerical stabilizer.

Suppose all values were identical:

x=[5,5,5,5].

Then:

\mu=5

and:

\sigma^2=0.

Without \epsilon, we would divide by:

\sqrt0=0.

That's problematic.

Adding a tiny:

\epsilon>0

prevents division by zero.

Your cheatsheet lists \epsilon as the small numerical stabilizer in the notation. (Source: Step1_Transformers_Mathematical_Cheatsheet)

1.11.8 LayerNorm — Step 5: Normalize

The normalized value is:

\boxed{ \hat{x}_i = \frac{x_i-\mu} {\sqrt{\sigma^2+\epsilon}} }

Ignoring the tiny effect of \epsilon for our hand calculation:

\hat{x} = \frac{[-1.5,-0.5,0.5,1.5]}{\sqrt{1.25}}.

Since:

\sqrt{1.25}\approx1.1180,

we get:

\boxed{ \hat{x} \approx [-1.3416,-0.4472,0.4472,1.3416] }

1.11.9 Check the Result

Let's calculate the mean:

\frac{-1.3416-0.4472+0.4472+1.3416}{4}=0.

So:

\boxed{\text{mean}=0}

And the variance becomes approximately:

\boxed{\text{variance}=1}.

That is exactly the point of the normalization.

Your reasoning-model source explicitly shows LayerNorm producing approximately zero mean and unit variance. (Source: Build a Reasoning Model (From Scratch))

1.11.10 But There Is One More Stage: \gamma and \beta

The complete LayerNorm formula is:

\boxed{ LN(x)= \gamma\odot \frac{x-\mu}{\sqrt{\sigma^2+\epsilon}} +\beta }

where:

  • \mu = mean
  • \sigma^2 = variance
  • \epsilon = numerical stabilizer
  • \gamma = learned scale
  • \beta = learned shift
  • \odot = element-wise multiplication.

This is exactly the formulation on your mathematical cheatsheet. (Source: Step1_Transformers_Mathematical_Cheatsheet)

1.11.11 Why Learn \gamma and \beta?

This is a subtle but very important idea.

Suppose normalization forces everything into:

\text{mean}=0,\qquad \text{variance}=1.

What if the network actually wants a different scale or offset?

The learned parameters provide that flexibility.

For example:

\gamma=[2,1,1,0.5]

and:

\beta=[1,0,-1,2].

Then:

y_i=\gamma_i\hat{x}_i+\beta_i.

So normalization gives a controlled baseline, while the model can learn how to rescale and shift the normalized representation.

1.11.12 Numerical Example With \gamma,\beta

We had:

\hat{x} = [-1.3416,-0.4472,0.4472,1.3416].

Suppose:

\gamma=[2,1,1,0.5]

and:

\beta=[1,0,-1,2].

Then:

First component
y_1=2(-1.3416)+1
=-2.6832+1
\boxed{y_1=-1.6832}
Second
y_2=1(-0.4472)+0
\boxed{y_2=-0.4472}
Third
y_3=1(0.4472)-1
\boxed{y_3=-0.5528}
Fourth
y_4=0.5(1.3416)+2
=0.6708+2
\boxed{y_4=2.6708}

Therefore:

\boxed{ LN(x) \approx [-1.6832,-0.4472,-0.5528,2.6708] }

Notice something important:

After applying \gamma,\beta, the final output does not necessarily have zero mean and unit variance anymore.

The normalized intermediate \hat{x} has those properties; the learned affine transformation can change them.

1.11.13 Now RMSNorm

Now we move to the second normalization method.

RMSNorm stands for:

\boxed{\text{Root Mean Square Normalization}}

The key conceptual difference:

LayerNorm

First subtract the mean.

RMSNorm

Does not subtract the mean.

Your reasoning-model source explicitly describes RMSNorm as removing the mean-centering step. (Source: Build a Reasoning Model (From Scratch))

1.11.14 RMSNorm Formula

The root mean square is:

\boxed{ RMS(x) = \sqrt{ \frac1d\sum_{i=1}^{d}x_i^2+\epsilon } }

Then:

\boxed{ RMSNorm(x) = \gamma\odot\frac{x}{RMS(x)} }

This is the formulation on your cheatsheet. (Source: Step1_Transformers_Mathematical_Cheatsheet)

Compare:

LayerNorm
\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}
RMSNorm
\frac{x}{\sqrt{\frac1d\sum_i x_i^2+\epsilon}}

The easiest memory trick is:

\boxed{ LN:\text{ subtract mean + divide by std} }
\boxed{ RMSNorm:\text{ divide by RMS only} }

1.11.15 RMSNorm Numerical Example

Use the same:

x=[1,2,3,4].

First square each value:

[1,4,9,16].

Sum:

1+4+9+16=30.

Average:

\frac{30}{4}=7.5.

Square root:

RMS(x)=\sqrt{7.5}.

Therefore:

\boxed{ RMS(x)\approx2.7386 }

1.11.16 Divide the Original Values by the RMS

RMSNorm(x) = \frac{[1,2,3,4]}{2.7386}.

So:

\boxed{ RMSNorm(x) \approx [0.3651,0.7303,1.0954,1.4606] }

assuming:

\gamma=[1,1,1,1].

1.11.17 Notice the Biggest Difference

For LayerNorm:

\boxed{ \text{mean}\approx0 }

after normalization.

For RMSNorm:

\boxed{ \text{mean}\neq0 }

in general.

Our RMSNorm output has mean:

\frac{0.3651+0.7303+1.0954+1.4606}{4}
\approx0.9129.

So:

\boxed{ \mu_{\text{RMSNorm}}\approx0.913 }

It is not centered around zero.

This is exactly the distinction emphasized in your source: RMSNorm keeps the activation magnitude controlled but does not enforce zero mean or unit variance. (Source: Build a Reasoning Model (From Scratch))

1.11.18 Why Is It Called "Root Mean Square"?

Because we literally:

1. Square
x_i^2
2. Mean
\frac1d\sum_i x_i^2
3. Root
\sqrt{ \frac1d\sum_i x_i^2 }

Therefore:

\boxed{ RMS=\sqrt{\text{mean of squares}} }

1.11.19 LayerNorm vs RMSNorm Side-by-Side

Property LayerNorm RMSNorm
Compute mean? Yes No
Subtract mean? Yes No
Compute variance? Yes No explicit variance
Divide by Standard deviation RMS
Center output? Yes No
Learned scale \gamma \gamma
Learned shift \beta Not in the basic formulation
Main goal Control activation scale Control activation scale with simpler computation

The source explicitly describes RMSNorm as computationally simpler because it removes mean-centering. (Source: Build a Reasoning Model (From Scratch))

1.11.20 Parameter-Count Numerical

This can also become an exam numerical.

For a hidden dimension:

d.
LayerNorm

The standard formulation has:

\gamma\in\mathbb{R}^{d}

and:

\beta\in\mathbb{R}^{d}.

Therefore:

\boxed{ 2d }

learned affine parameters.

RMSNorm

The basic formulation has:

\gamma\in\mathbb{R}^{d}.

1.11.21 Numerical: Compare the Computation

Suppose:

x=[2,4,6,8].

LayerNorm

Mean:

\mu=\frac{2+4+6+8}{4} =5.

Centered:

[-3,-1,1,3].

Variance:

\frac{9+1+1+9}{4} = \frac{20}{4} =5.

Standard deviation:

\sqrt5\approx2.236.

Normalized:

\boxed{ [-1.3416,-0.4472,0.4472,1.3416] }

RMSNorm

Squares:

[4,16,36,64].

Mean square:

\frac{4+16+36+64}{4} = \frac{120}{4} =30.

RMS:

\sqrt{30}\approx5.477.

Normalized:

\boxed{ [0.3651,0.7303,1.0954,1.4606] }

Notice something interesting.

The LayerNorm normalized vector is the same as we got for [1,2,3,4].

Why?

Because multiplying every input by 2 does not change the LayerNorm normalized pattern.

For RMSNorm, the same is also true after proportional scaling.

This illustrates that both methods normalize scale, though they do it differently.

1.11.22 Exam Numerical: Can the Answer Be Negative?

Yes.

LayerNorm:

\boxed{\text{definitely can produce negative values}}

because it subtracts the mean.

RMSNorm can also produce negative values if the input value itself is negative.

For:

x=[-2,1,3,4],

the RMS is positive, but:

\frac{-2}{RMS}<0.

So don't associate "RMSNorm" with "all positive values."

The normalization denominator is positive; it does not change the sign of the original input.

1.11.23 Numerical: What Happens to a Constant Vector?

This is a useful exam edge case.

Take:

x=[5,5,5,5].

LayerNorm

Mean:

\mu=5.

Centered:

[0,0,0,0].

Variance:

0.

With \epsilon:

LN(x) = \gamma\odot \frac{[0,0,0,0]}{\sqrt{\epsilon}} +\beta.

If:

\beta=0,

then:

\boxed{ LN(x)=[0,0,0,0]. }

RMSNorm

RMS(x) = \sqrt{ \frac{25+25+25+25}{4} } = 5.

Therefore:

RMSNorm(x) = [1,1,1,1]

for:

\gamma=1.

So:

\boxed{ LN([5,5,5,5])=[0,0,0,0] }

while:

\boxed{ RMSNorm([5,5,5,5])=[1,1,1,1]. }

This is a very nice numerical demonstration of the fundamental difference:

\boxed{ \text{LayerNorm removes common offset} }

while:

\boxed{ \text{RMSNorm preserves the offset information and only rescales magnitude}. }

1.11.24 Why Is RMSNorm Sometimes Preferred in Modern LLMs?

Your source states that RMSNorm is often preferred in large-scale LLMs because it is computationally more efficient. (Source: Build a Reasoning Model (From Scratch))

The reason follows directly from the formulas.

LayerNorm needs:

\mu

and:

\sigma^2.

RMSNorm does not explicitly compute the mean-centering step.

Conceptually:

\boxed{ LN=\text{mean + variance + normalization} }

whereas:

\boxed{ RMSNorm=\text{mean-square + square-root + scaling}. }

The exact performance advantage in a real implementation depends on the kernel and hardware, but mathematically RMSNorm removes the mean-centering computation.

1.11.25 Pre-LN vs Post-LN

Now we connect normalization to the Transformer block.

There are two important structural choices.

Post-LN

Historically associated with the original Transformer:

\boxed{ x \rightarrow \text{Attention} \rightarrow \text{Residual} \rightarrow LN }

and similarly for FFN.

Pre-LN

Used in GPT-style and many later architectures:

\boxed{ x \rightarrow LN \rightarrow \text{Attention} \rightarrow \text{Residual} }

Your Raschka source explicitly distinguishes Post-LayerNorm, used in the original Transformer, from Pre-LayerNorm, adopted in GPT-2 and newer LLMs, and discusses the different training dynamics. (Source: Build a Large Language Model (From Scratch))

For the architecture we are currently deriving, our cheatsheet uses the Pre-LN formulation:

\boxed{ h=x+MHA(LN(x)) }
\boxed{ y=h+FFN(LN(h)). }

(Source: Step1_Transformers_Mathematical_Cheatsheet)

1.11.26 Why Does Normalization Appear Before the Sub-layer?

In Pre-LN:

LN(x)

is fed into attention.

Then:

MHA(LN(x))

is computed.

Then:

x+MHA(LN(x)).

Likewise for the FFN.

So normalization controls the scale of what enters the sub-layer, while the residual path preserves the original stream.

This gives us:

\boxed{ \text{Normalize} \rightarrow \text{Transform} \rightarrow \text{Residual addition} }

as our basic pattern.

1.11.27 Important Numerical Shape Question

Suppose:

X\in\mathbb{R}^{B\times n\times d}.

What is the output shape of LayerNorm?

\boxed{ B\times n\times d }

It does not change tensor shape.

For example:

X: 16\times128\times768

becomes:

\boxed{ 16\times128\times768 }

after LayerNorm.

Likewise RMSNorm preserves:

\boxed{ B\times n\times d. }

1.11.28 Why Does Normalization Not Change Dimensions?

Because normalization is performed element-wise after computing statistics over the feature dimension.

For one token:

d\rightarrow d.

It changes:

\text{values}

but not:

\text{number of features}.

Therefore:

\boxed{ \text{Normalization changes scale/distribution, not representation width.} }

1.11.29 LayerNorm Numerical Checklist

When you see a numerical question, do these steps in exactly this order:

\boxed{1.\;\mu}
\boxed{2.\;x-\mu}
\boxed{3.\;\sigma^2}

1.11.40 One Final Conceptual Connection

We can now explain why the Transformer block has this order:

\boxed{ Norm \rightarrow Attention \rightarrow Residual \rightarrow Norm \rightarrow FFN \rightarrow Residual }

because the two major computations have fundamentally different jobs:

\boxed{ Attention: \text{mix information between positions} }
\boxed{ FFN: \text{nonlinearly transform each position} }

and normalization controls the activation scale entering these operations.

So the Transformer block is essentially:

\boxed{ \text{normalize} \rightarrow \text{communicate} \rightarrow \text{preserve residual} \rightarrow \text{normalize} \rightarrow \text{compute} \rightarrow \text{preserve residual}. }
