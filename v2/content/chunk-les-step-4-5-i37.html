Step 4.5 — DeepSeek-R1 Distillation: Turning a Teacher Reasoning Trace into the Student’s Training Signal

Plan node: I5 · chat order #37

Now we move from the idea of R1 hard distillation to the actual mechanics.

The central question is:

Once the teacher has generated a reasoning trace, exactly how does that text become tensors, targets, loss, and finally a gradient update?

The supplied Build a Reasoning Model (From Scratch) chapter gives this pipeline explicitly: tokenize the teacher-generated example, split prompt from answer, shift input/target sequences by one token, compute cross-entropy only on the answer tokens, and train the smaller pretrained model with that loss. (Source: Build a Reasoning Model (From Scratch))

1. Start with one teacher-generated example

Imagine the teacher produces:

Prompt:
Compute -49/7.

Teacher response:
The answer is \boxed{-7}

The important point is that the student does not receive:

P_T(v)

for every vocabulary token.

Instead, it receives the sequence itself.

So conceptually:

\boxed{ (x,\;y_T) }

where:

  • x = prompt
  • y_T = teacher-generated reasoning/answer

The student is then trained exactly like an autoregressive language model on that synthetic supervised example. (Source: Build a Reasoning Model (From Scratch))

2. Tokenize the complete sequence

Suppose, purely for illustration, tokenization gives:

[\texttt{P1},\texttt{P2},\texttt{P3}, \texttt{A1},\texttt{A2},\texttt{A3}]

where:

[\texttt{P1},\texttt{P2},\texttt{P3}]

are prompt tokens and:

[\texttt{A1},\texttt{A2},\texttt{A3}]

are teacher-answer tokens.

Let the total sequence be:

T=6.

Let:

\boxed{\text{prompt\_len}=3}.

The chapter stores both the token IDs and the prompt length so it can later determine which positions belong to the teacher answer. (Source: Build a DeepSeek Model (From Scratch))

3. Why do we shift the sequence?

This is fundamental to autoregressive language modeling.

The model sees:

P1 P2 P3 A1 A2

and should predict:

P2 P3 A1 A2 A3

So:

\boxed{ \text{input} = \text{all tokens except last} }

and:

\boxed{ \text{target} = \text{all tokens except first} }

Mathematically:

\text{input\_ids} = [t_1,t_2,\ldots,t_{N-1}]
\text{target\_ids} = [t_2,t_3,\ldots,t_N].

The chapter's actual code is:

input_ids = tok[:-1].unsqueeze(0)
target_ids = tok[1:]

(Source: Build a Reasoning Model (From Scratch))

4. Why is this shift necessary?

Suppose:

[t_1,t_2,t_3,t_4]

is:

The capital of Germany

The model should learn:

P(t_2|t_1)
P(t_3|t_1,t_2)
P(t_4|t_1,t_2,t_3).

Therefore:

INPUT              TARGET
The       →         capital
The capital →      of
The capital of →   Germany

This is precisely the ordinary next-token objective you studied earlier.

So R1 hard distillation does not invent a new autoregressive loss.

It reuses:

\boxed{ \text{next-token cross-entropy} }

but with teacher-generated sequences as the reference data. (Source: Build a Reasoning Model (From Scratch))

5. Tensor shapes

Suppose:

N=100

tokens in the combined prompt + teacher response.

Then:

Input
\boxed{ [1,99] }

because the final token is removed.

Target
\boxed{ [99] }

The model produces:

\boxed{ [1,99,V] }

where V is vocabulary size.

For example, if:

V=151{,}000,

then:

[1,99,151000].

The chapter's example similarly discusses logits over a vocabulary of roughly 151K tokens. (Source: Build a Reasoning Model (From Scratch))

6. The model is predicting a distribution at every position

For every position t:

z_t = [z_{t,1},z_{t,2},...,z_{t,V}]

is the student’s vocabulary logit vector.

Then:

P_S(y_t|context) = \operatorname{softmax}(z_t).

Cross-entropy asks:

How much probability did the student assign to the teacher's actual next token?

Therefore:

\boxed{ L_t=-\log P_S(y_t|context) }

7. Sequence-level loss

For a sequence with N target tokens:

\boxed{ L = -\frac{1}{N} \sum_{t=1}^{N} \log P_S(y_t|y_{<t},x) }

This is the negative average token log probability.

The chapter explicitly connects cross-entropy to the negative average log probability and explains that lower cross-entropy corresponds to greater confidence in the reference tokens. (Source: Build a Reasoning Model (From Scratch))

8. BUT there is a crucial problem

Suppose the full sequence is:

Prompt:
What is 2 + 2?

Answer:
4

Should the model be penalized because it is not good at predicting the prompt tokens?

No.

The prompt is provided to the model.

We are not asking the student to learn:

\text{“reproduce the prompt.”}

We are asking it to learn:

\boxed{ \text{“produce the teacher's response given the prompt.”} }

Therefore the chapter uses an answer-only loss. (Source: Build a Reasoning Model (From Scratch))

9. Prompt masking

This is one of the most important implementation details.

Suppose:

Prompt tokens:
[P1 P2 P3]

Answer tokens:
[A1 A2 A3]

The shifted training structure is:

Input:   P1  P2  P3  A1  A2
Target:  P2  P3  A1  A2  A3

But we only calculate loss on:

Target positions:
             A1  A2  A3

The prompt target positions:

P2  P3

are ignored.

10. Why does the answer start at prompt_len - 1?

This often looks strange in code.

Suppose:

\text{prompt\_len}=3.

The original tokens are:

[t_0,t_1,t_2,t_3,t_4,t_5].

Prompt:

[t_0,t_1,t_2].

Answer begins at:

t_3.

After shifting:

input:
t0 t1 t2 t3 t4

target:
t1 t2 t3 t4 t5

The target corresponding to the first answer token t_3 comes from input position:

t_2.

That is index:

\boxed{\text{prompt\_len}-1}.

So the chapter uses:

answer_start = max(prompt_len - 1, 0)

and then selects:

answer_logits = logits[answer_start:]
answer_targets = target_ids[answer_start:]

(Source: Build a Reasoning Model (From Scratch))

11. Concrete example of the indexing

Suppose:

\text{prompt\_len}=4.

Original:

[t_0,t_1,t_2,t_3,t_4,t_5,t_6]

Prompt:

t_0,t_1,t_2,t_3

Answer:

t_4,t_5,t_6.

Shift:

input=[t_0,t_1,t_2,t_3,t_4,t_5]
target=[t_1,t_2,t_3,t_4,t_5,t_6].

Now the first target answer token is:

t_4.

It occurs at target index:

3.

And:

\text{prompt\_len}-1=4-1=3.

Exactly.

This is the reason the code slices at:

\boxed{\text{prompt\_len}-1}.

12. Numerical next-token loss

Suppose for one teacher token:

P_S(y_t)=0.8.

Then:

L_t=-\log(0.8).

Using natural logarithm:

L_t\approx0.223.

If:

P_S(y_t)=0.2,

then:

L_t=-\log(0.2) \approx1.609.

Therefore:

\boxed{ \text{higher probability on teacher token} \Rightarrow \text{lower loss} }

13. Numerical sequence loss

Suppose the teacher answer contains three target tokens with probabilities:

[0.8,0.5,0.25].

Then:

L = -\frac13 [ \log(0.8) + \log(0.5) + \log(0.25) ].

Compute:

-\log(0.8)\approx0.223
-\log(0.5)\approx0.693
-\log(0.25)\approx1.386.

Therefore:

L = \frac{0.223+0.693+1.386}{3}
= \frac{2.302}{3}
\boxed{L\approx0.767}.

This is the teacher-response training loss for that example.

14. The student is learning the entire reasoning sequence

Suppose the teacher generated:

First isolate x.
Subtract 2x.
Add 9.
Therefore x = 83.

Then each token becomes a training target.

The student learns:

P_S(y_1|x)

then:

P_S(y_2|x,y_1)

then:

P_S(y_3|x,y_1,y_2)

and so forth.

So the sequence of reasoning acts as a sequence of supervised targets.

That is why the chapter describes hard distillation as teaching the student to reproduce teacher-generated reasoning traces. (Source: Build a Reasoning Model (From Scratch))

15. Complete single-example loss implementation

The source gives:

def compute_example_loss(model, example, device):
    token_ids = example["token_ids"]
    prompt_len = example["prompt_len"]

    input_ids = torch.tensor(
        token_ids[:-1],
        dtype=torch.long,
        device=device
    ).unsqueeze(0)

    target_ids = torch.tensor(
        token_ids[1:],
        dtype=torch.long,
        device=device
    )

    logits = model(input_ids).squeeze(0)

    answer_start = max(prompt_len - 1, 0)

    answer_logits = logits[answer_start:]
    answer_targets = target_ids[answer_start:]

    loss = torch.nn.functional.cross_entropy(
        answer_logits,
        answer_targets
    )

    return loss

This is the source's Listing 8.11. (Source: Build a Reasoning Model (From Scratch))

16. Understand every line

Line 1
token_ids = example["token_ids"]

Retrieve the complete:

[\text{prompt}+\text{teacher answer}]

sequence.

Line 2
prompt_len = example["prompt_len"]

Remember where the teacher answer starts.

Lines 3–7

Create shifted:

\boxed{input}

and:

\boxed{target}.
Line 8
logits = model(input_ids)

Student predicts the next token at every position.

Line 9
answer_start = prompt_len - 1

Locate the first prediction whose target is a teacher-answer token.

Lines 10–11

Keep only:

\boxed{\text{answer logits}}

and:

\boxed{\text{answer target tokens}}.
Final line
cross_entropy(answer_logits, answer_targets)

Calculate:

\boxed{ -\frac1N\sum_t\log P_S(y_t|context) }

over the teacher answer only.

17. Why cross_entropy can handle this directly

You do not need to manually calculate:

\operatorname{softmax}

followed by:

\log

followed by:

-\log p.

PyTorch's:

F.cross_entropy(logits, targets)

implements the required computation efficiently.

The chapter explicitly notes that this produces the same core quantity as the earlier negative-average-log-probability calculation and is the preferred implementation for training. (Source: Build a Reasoning Model (From Scratch))

18. Source numerical example

The chapter reports that for one example, the negative average log probability is:

\boxed{1.68}

and the directly computed cross-entropy also gives approximately:

\boxed{1.68}.

This demonstrates that the custom probability calculation and PyTorch cross-entropy are representing the same training objective. (Source: Build a Reasoning Model (From Scratch))

19. Why answer-only loss matters mathematically

Suppose the prompt contains 100 tokens and the answer contains 20.

If we calculated loss over all 120:

L_{\text{all}} = -\frac1{120} \sum_{t=1}^{120}\log p_t.

The prompt tokens would consume:

\frac{100}{120}=83.3\%

of the loss positions.

The actual teacher response would contribute only:

\frac{20}{120}=16.7\%.

That is the opposite of what we want.

We care about:

\boxed{\text{learning the teacher response}}

not:

\boxed{\text{learning to reproduce the supplied prompt}}.

This explains the chapter's explicit prompt masking. (Source: Build a Reasoning Model (From Scratch))

20. Numerical question — effect of prompt masking

Suppose:

\text{prompt}=80\text{ tokens}

and:

\text{answer}=20\text{ tokens}.

Without masking, answer tokens account for:

\frac{20}{100}=20\%.

With answer-only loss:

\boxed{100\%}

of the optimization signal comes from the response.

This is a very useful interview explanation.

21. The training example becomes

Conceptually:

                    Complete sequence
                           |
             +-------------+-------------+
             |                           |
          Prompt                       Answer
             |                           |
         context only                TRAIN HERE
             |                           |
             +-------------+-------------+
                           |
                      Student logits
                           |
                    Cross-entropy
                           |
                        backward
                           |
                    update student

The prompt is not discarded from the model input.

This is crucial.

We use the prompt as context, but do not use its positions as the optimization targets.

22. This distinction is extremely important

Do not say:

“We remove the prompt.”

That is wrong.

We:

\boxed{\text{keep prompt in the input}}

but:

\boxed{\text{mask prompt positions in the loss}}.

The student therefore learns:

\boxed{ P(\text{answer}\mid\text{prompt}) }

which is exactly what we need.

23. Validation loss

The source then wraps the single-example calculation inside an evaluation function.

Conceptually:

L_{\text{val}} = \frac1M \sum_{i=1}^{M} L_i.

This lets us measure how well the student predicts held-out teacher-generated responses.

The chapter emphasizes that validation loss is generally a cleaner indicator of generalization because it is computed on held-out examples without updating weights. (Source: Build a Reasoning Model (From Scratch))

24. Training loss vs validation loss

Training loss

Computed on examples being used for optimization.

It can fluctuate.

Validation loss

Computed on held-out examples.

It is more useful for judging whether improvement generalizes.

The chapter's example gives:

\text{Train loss}\approx0.98

and:

\text{Validation loss}\approx1.02

on a small subset during evaluation. (Source: Build a Reasoning Model (From Scratch))

25. Full training loop

Once the loss function exists, training becomes conventional deep learning.

The chapter's structure is essentially:

Initialize model + optimizer
        ↓
for each epoch
        ↓
shuffle training examples
        ↓
for each example
        ↓
zero gradients
        ↓
compute answer-only CE loss
        ↓
loss.backward()
        ↓
(optional) clip gradients
        ↓
optimizer.step()
        ↓
periodically evaluate validation loss
        ↓
save checkpoint

(Source: Build a Reasoning Model (From Scratch))

26. Why gradient clipping appears

The supplied implementation uses:

\boxed{\text{gradient clipping}}

with:

\text{grad\_clip\_norm}=1.0

in its example training run. (Source: Build a Reasoning Model (From Scratch))

Conceptually:

\|\nabla\|>c \Rightarrow \text{rescale gradient to norm }c.

This helps prevent unusually large updates from destabilizing training.

The chapter connects this specifically to occasional examples producing unusually large gradients. (Source: Build a Reasoning Model (From Scratch))

27. Important: there is no teacher forward pass during each student update here

Compare this with classical soft KD.

Classical:
prompt
  ├──> teacher logits
  └──> student logits
              ↓
             KL
R1 hard distillation:
teacher generated dataset
            ↓
        saved text
            ↓
        student SFT

Once the dataset has already been generated, the teacher is not needed in the student's training loop.

This is one of the core practical differences emphasized by the source. (Source: Build a Reasoning Model (From Scratch))

28. Data-generation stage vs training stage

This gives us two separate computational phases.

Phase A — expensive teacher stage

\text{prompt} \rightarrow \text{teacher generation} \rightarrow \text{verification} \rightarrow \text{filtering}

Phase B — student training

\text{curated examples} \rightarrow \text{student} \rightarrow CE \rightarrow \text{gradient update}.

This separation makes the architecture much easier to scale and reason about.

29. Sequence-length filtering

There is another engineering issue.

The chapter reports:

\text{average total length}=2946\text{ tokens}

for the initial examples, with an extreme maximum of:

42005

tokens. (Source: Build a Reasoning Model (From Scratch))

Training on extremely long examples can be expensive.

So the example filters sequences to:

\boxed{\text{maximum length}=2048}.

(Source: Build a Reasoning Model (From Scratch))

30. Why sequence length matters

Transformer computation has strong dependence on sequence length.

For a self-attention layer, the attention matrix has shape:

N\times N.

So increasing:

N

increases attention-related work roughly quadratically.

Therefore filtering:

42005 \rightarrow 2048

is not a small engineering tweak.

It can drastically reduce computational cost.

The source specifically presents maximum sequence length as one of the practical constraints that makes this example feasible on smaller hardware. (Source: Build a Reasoning Model (From Scratch))

31. Numerical question — sequence-length scaling

Suppose attention-related work is approximated by:

O(N^2).

Compare:

N_1=1024

and:

N_2=2048.

Then:

\frac{N_2^2}{N_1^2} = \left(\frac{2048}{1024}\right)^2 = 2^2 = \boxed4.

So doubling sequence length approximately quadruples the quadratic attention component.

This is a classic exam numerical.

34. The student's actual objective

Now we can write the final DeepSeek-R1 hard-distillation objective much more precisely:

For a teacher-generated response:

y_1,y_2,\dots,y_N

conditioned on prompt x,

\boxed{ L_{\text{R1-distill}} = -\frac1N \sum_{t=1}^{N} \log P_S(y_t\mid x,y_{<t}) }

where N refers to the target response positions being trained.

And importantly:

\boxed{ \text{prompt tokens are context, not loss targets} }

according to the supplied implementation. (Source: Build a Reasoning Model (From Scratch))

35. Compare the equations one final time

Classical soft KD

\boxed{ L= \alpha CE(z_S,y) + (1-\alpha)T^2 KL(P_T^T\|P_S^T) }

Teacher logits required.

DeepSeek-R1 hard distillation

\boxed{ L= -\frac1N \sum_t \log P_S(y_t|x,y_{<t}) }

Teacher-generated tokens required.

Not teacher logits.

Not temperature.

Not KL.

This distinction is the mathematical heart of the two methods. (Source: Build a Reasoning Model (From Scratch))

36. One subtle point about <think>

The source's practical setup uses explicit reasoning markers:

<think>
...
</think>

and the chapter includes an exercise comparing training with and without these tokens. (Source: Build a Reasoning Model (From Scratch))

So these tokens can become part of the sequence representation and therefore part of what the student learns to reproduce.

The important conceptual point is:

\boxed{ \text{reasoning format can itself become part of the learned behavior} }

The source tests this explicitly through its exercise. (Source: Build a Reasoning Model (From Scratch))

37. Exam trap: hard distillation does NOT mean one-token classification

Hard distillation in this context still means:

\boxed{\text{autoregressive token prediction}}

not:

\boxed{\text{one classification decision}}.

At each position:

\text{student} \rightarrow V\text{-dimensional logits} \rightarrow \text{one teacher token target}.

Repeated over the entire reasoning sequence.

38. Exam trap: teacher-generated text is not necessarily the prompt

The prompt is:

x.

Teacher response is:

y_T.

Student training is:

\boxed{ P_S(y_T|x) }

not:

P_S(x|x).

That is why prompt masking exists.

39. Exam trap: prompt_len - 1

Suppose:

\text{prompt\_len}=50.

Then first answer prediction occurs at:

\boxed{49}

in the shifted logits/target indexing convention.

Not 50.

Because prediction at position 49 corresponds to target token 50 in the original sequence.

40. Exam numerical: shifted positions

Suppose the original sequence contains:

10

prompt tokens and:

6

answer tokens.

Total:

16.

After shifting:

15

predictions.

The number of answer targets is:

\boxed6.

The answer begins at:

\text{prompt\_len}-1 = 10-1 = \boxed{9}.

So answer targets occupy shifted target positions:

9,10,11,12,13,14.

\boxed{ y_t=\text{next token after the current context} }

\boxed{ L_t=-\log P_S(y_t|context) }

44. One final conceptual distinction

There are actually three different things we have now learned:

\boxed{\text{SFT}}

Train on reference text.

\boxed{\text{Classical soft KD}}

Train on reference text plus teacher probability distributions.

\boxed{\text{DeepSeek-R1 hard distillation}}

Use teacher-generated reasoning traces as synthetic SFT data, after verification/filtering.

So DeepSeek-R1 distillation is best thought of as:

\boxed{ \text{high-quality synthetic reasoning SFT} }

rather than as:

\boxed{ \text{classical temperature/KL knowledge distillation} }

The source explicitly makes this distinction. (Source: Build a Reasoning Model (From Scratch))
