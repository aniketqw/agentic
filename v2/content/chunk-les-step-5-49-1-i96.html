Step 5.49.1 — DeepSeek Mixed-Precision Training: Fprop → Dgrad → Wgrad → Weight Update

Plan node: A4 · chat order #96

↩ Back to main text: Step 3.5 — Quantization → QLoRA · Step 3.6B — GGUF, K-Quants, QAT, BitNet, and 1.58-bit LLMs

Now we will open the entire Mixed Precision Framework.

The most important thing to understand is that DeepSeek does not choose one precision and use it everywhere.

Instead, for a linear layer

\boxed{y=Wx}

different versions of x, W, y, and the gradients exist at different points in the computation.

The source's four-stage flow is:

\boxed{ \text{Fprop} \rightarrow \text{Dgrad} \rightarrow \text{Wgrad} \rightarrow \text{Weight Update} }

with FP8 used for the expensive GEMM operations and higher precision retained where numerical sensitivity is greater. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.1 First establish the mathematical layer

Consider:

\boxed{ y=Wx }

where:

x\in\mathbb R^{d_{in}}
W\in\mathbb R^{d_{out}\times d_{in}}

and therefore:

y\in\mathbb R^{d_{out}}.

For a batch:

X\in\mathbb R^{B\times d_{in}}

and:

W\in\mathbb R^{d_{out}\times d_{in}}.

Then:

Y=XW^T

under the batch-row convention.

The source explains its formulas using the equivalent conceptual linear-layer relation y=Wx. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.2 What are the three major matrix operations?

There are three large GEMMs in the training pass.

Forward
\boxed{ Y=WX }

conceptually.

Gradient with respect to input
\boxed{ \frac{\partial L}{\partial X} = \frac{\partial L}{\partial Y}W^T }
Gradient with respect to weight
\boxed{ \frac{\partial L}{\partial W} = X^T\frac{\partial L}{\partial Y} }

The source explicitly gives the latter two formulas. (Source: Build a DeepSeek Model (From Scratch))

These are often abbreviated as:

\boxed{ \text{Fprop},\quad \text{Dgrad},\quad \text{Wgrad}. }

5.49.1.3 Why is this important for FP8?

Because each one is a huge matrix multiplication.

DeepSeek wants:

\boxed{ FP8 }

for these expensive operations.

But it does not want:

\boxed{ FP8 }

for everything surrounding them.

So the design is:

\boxed{ \text{FP8 GEMM} + \text{higher-precision accumulation/storage}. }

The source calls this a mixed-precision framework. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.4 Stage A — Forward propagation

Start with an input activation:

x.

The source says activations are typically stored in:

\boxed{BF16}.

But for the actual multiplication, they are converted on the fly to:

\boxed{FP8}.

(Source: Build a DeepSeek Model (From Scratch))

So:

x_{BF16} \longrightarrow x_{FP8}.

5.49.1.5 What happens to the weights?

The model maintains a higher-precision "master" weight copy:

\boxed{ W_{\text{master}} }

in:

\boxed{FP32}

or, as the source allows in its description of the forward path, high precision such as BF16 for the main stored copy. (Source: Build a DeepSeek Model (From Scratch))

For the multiplication, the weights are converted on the fly to:

\boxed{FP8}.

Thus:

W_{\text{master}} \rightarrow W_{FP8}.

5.49.1.6 Why not store only FP8 weights?

Because training needs accurate updates.

Suppose the true weight is:

W=0.12345678.

An 8-bit representation cannot preserve as much information as FP32.

If we repeatedly:

  1. quantize the weight,
  2. perform computation,
  3. update the quantized value,
  4. quantize again,

small errors can accumulate.

DeepSeek therefore maintains a higher-precision master copy for the actual optimizer update.

The source explicitly describes the master weights as high precision and updated in FP32. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.7 The forward GEMM

Now perform:

\boxed{ Y_{FP8\times FP8} }

using the FP8 versions.

Conceptually:

Y = W_{FP8}X_{FP8}.

But here comes the key detail:

\boxed{ \text{the multiplication is FP8, but accumulation is FP32}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.1.8 What does accumulation mean?

Consider a single output:

y_i = \sum_{j=1}^{d}W_{ij}x_j.

Suppose there are:

4096

terms.

The GPU performs many products:

W_{i1}x_1, W_{i2}x_2, \ldots

and then sums them.

If every partial sum were kept in FP8, numerical error could compound.

Instead:

\boxed{ \text{FP8 products} \rightarrow \text{FP32 partial sums}. }

This is the first place where you should distinguish:

\boxed{\text{multiplication precision}}

from:

\boxed{\text{accumulation precision}}.

5.49.1.9 A tiny numerical example

Suppose:

a=[1.2,\,1.3,\,1.4]

and:

b=[2.1,\,2.2,\,2.3].

The dot product is:

1.2(2.1)+1.3(2.2)+1.4(2.3).

Calculate:

1.2(2.1)=2.52
1.3(2.2)=2.86
1.4(2.3)=3.22.

Therefore:

y=2.52+2.86+3.22 = \boxed{8.60}.

Real large matrix multiplications may involve thousands of such terms.

That is why the source places importance on using FP32 accumulation even though the products are computed in FP8. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.10 What happens to the output?

After FP32 accumulation:

Y_{FP32}

is converted to:

\boxed{ Y_{BF16}. }

The source explicitly describes this conversion for storage in memory/inter-layer communication. (Source: Build a DeepSeek Model (From Scratch))

So the entire forward path is:

\boxed{ x_{BF16} \rightarrow x_{FP8} }
\boxed{ W_{\text{master}} \rightarrow W_{FP8} }
\boxed{ FP8\times FP8 \rightarrow FP32\text{ accumulation} }
\boxed{ Y_{FP32} \rightarrow Y_{BF16}. }

5.49.1.11 Why this combination?

Because the source wants three things simultaneously:

\boxed{ \text{FP8} \rightarrow \text{fast computation} }
\boxed{ \text{FP32 accumulation} \rightarrow \text{numerical stability} }
\boxed{ \text{BF16 storage} \rightarrow \text{reasonable memory usage}. }

That is the essence of mixed precision in the forward path. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.12 Stage B — Dgrad

Now the forward computation has produced a loss.

During backpropagation, suppose the incoming gradient is:

\boxed{ \frac{\partial L}{\partial Y}. }

We want:

\boxed{ \frac{\partial L}{\partial X}. }

For:

Y=WX,

the source gives:

\boxed{ \frac{\partial L}{\partial X} = \frac{\partial L}{\partial Y}W^T. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.1.13 Why do we need Dgrad?

Because backpropagation must continue into the previous layer.

Suppose:

Layer 1
   │
   ▼
Layer 2
   │
   ▼
Layer 3
   │
   ▼
Loss

When Layer 3 computes:

\frac{\partial L}{\partial X_3},

that becomes the incoming gradient used by the previous layer.

Therefore Dgrad is how error information travels backward through the network.

The source explicitly notes that dL/dx is needed to continue backpropagation to the previous layer. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.14 Precision in Dgrad

The source says the incoming gradient is typically stored in:

\boxed{BF16}.

For computation, it is converted to:

\boxed{FP8}.

The weight matrix is likewise converted to:

\boxed{FP8}

for the GEMM.

Then:

\boxed{ FP8\times FP8 \rightarrow FP32\text{ accumulation}. }

Finally:

\boxed{ dL/dX_{FP32} \rightarrow dL/dX_{BF16}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.1.15 Dgrad pipeline

Write this exactly:

\boxed{ \frac{\partial L}{\partial Y}_{BF16} \rightarrow FP8 }
\boxed{ W_{\text{high precision}} \rightarrow FP8 }

then:

\boxed{ \frac{\partial L}{\partial Y}_{FP8} W_{FP8}^{T} \rightarrow FP32\text{ accumulation} }

then:

\boxed{ \frac{\partial L}{\partial X} \rightarrow BF16. }

The source describes this as a symmetry with the forward computation. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.16 Stage C — Wgrad

Now we need the gradient of the weights.

Again:

Y=WX.

The source gives:

\boxed{ \frac{\partial L}{\partial W} = X^T \frac{\partial L}{\partial Y}. }

(Source: Build a DeepSeek Model (From Scratch))

This gradient is especially important because:

\boxed{ \frac{\partial L}{\partial W} }

is what tells the optimizer how to change the model's learned weights.

5.49.1.17 Why does Wgrad need extra care?

Because this gradient directly determines the parameter update.

Suppose:

W_{\text{new}} = W_{\text{old}} - \eta \frac{\partial L}{\partial W}.

If:

\frac{\partial L}{\partial W}

is noisy or inaccurate, the parameter update becomes inaccurate.

The source therefore emphasizes preserving this gradient at high precision. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.18 Precision in Wgrad

The source says:

  • the input activation is available from the forward computation,
  • the incoming gradient is converted from BF16 to FP8,
  • the Wgrad computation uses FP8 operands,
  • the resulting weight gradient is stored in FP32.

(Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ X_{FP8} }

and:

\boxed{ \frac{\partial L}{\partial Y}_{FP8} }

are used in the GEMM.

But:

\boxed{ \frac{\partial L}{\partial W}_{FP32} }

is retained at high precision.

5.49.1.19 Wgrad pipeline

Conceptually:

X_{FP8}

times:

\left(\frac{\partial L}{\partial Y}\right)_{FP8}

gives:

\boxed{ \frac{\partial L}{\partial W}_{FP32}. }

This is the key precision distinction:

\boxed{ \text{Wgrad computation may use FP8, but the resulting weight gradient is preserved in FP32}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.1.20 Stage D — Weight update

Now we finally change the actual model parameters.

The source gives:

\boxed{ W_{\text{master,new}} = W_{\text{master,old}} - \text{learning rate} \cdot \frac{\partial L}{\partial W}. }

(Source: Build a DeepSeek Model (From Scratch))

Let's denote:

\eta=\text{learning rate}.

Then:

\boxed{ W_{\text{new}} = W_{\text{old}} - \eta \frac{\partial L}{\partial W}. }

5.49.1.21 Why is everything FP32 here?

Because this is the point where the model's parameters permanently change.

The source states that:

  • master weights are FP32,
  • weight gradients are FP32,
  • optimizer states are FP32,
  • update occurs entirely in FP32.

(Source: Build a DeepSeek Model (From Scratch))

Thus:

\boxed{ \text{FP32 master weights} + \text{FP32 Wgrad} + \text{FP32 optimizer state} \rightarrow \text{FP32 update}. }

5.49.1.22 What happens after the update?

Suppose:

W_{\text{master,new}}

is now updated in FP32.

For the next iteration, the source says these master weights are converted to the lower-precision form required for computation:

\boxed{ W_{\text{master,new}} \rightarrow W_{BF16}/W_{FP8}. }

Then the cycle repeats.

So:

\boxed{ \text{FP32 master} \rightarrow \text{FP8 compute} \rightarrow \text{FP32 gradient} \rightarrow \text{FP32 update} \rightarrow \text{FP8 next iteration}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.1.23 The complete lifecycle

Here is the entire thing:

                 FP32 Master Weight
                        │
                        ▼
                   convert to FP8
                        │
                        ▼
BF16 Input ──► FP8 Input + FP8 Weight
                        │
                        ▼
                 FP8 × FP8 GEMM
                        │
                        ▼
                  FP32 Accumulation
                        │
                        ▼
                     BF16 Output
                        │
                        ▼
                       Loss
                        │

                    Backprop
                   /        \
                  /          \
               Dgrad        Wgrad
                 │             │

                 │             │

                 │             │
               BF16        FP32 dW
                                │

                                ▼
                      FP32 Master Update

That is the mixed-precision training framework presented in the source. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.24 Now let's use actual numbers

Take a tiny linear layer:

W= \begin{bmatrix} 2&1\\ 3&4 \end{bmatrix}

and:

x= \begin{bmatrix} 5\\ 6 \end{bmatrix}.

Then:

y=Wx.

Calculate:

y_1=2(5)+1(6)=16
y_2=3(5)+4(6)=39.

Therefore:

\boxed{ y= \begin{bmatrix} 16\\ 39 \end{bmatrix}. }

This numerical example itself is ordinary linear algebra; the point is now to map its operations onto the mixed-precision pipeline.

5.49.1.25 Suppose the incoming loss gradient is

\frac{\partial L}{\partial y} = \begin{bmatrix} 0.1\\ 0.2 \end{bmatrix}.

Then Dgrad:

\frac{\partial L}{\partial x} = \frac{\partial L}{\partial y}W^T.

We have:

W^T= \begin{bmatrix} 2&3\\ 1&4 \end{bmatrix}.

So:

\begin{bmatrix} 0.1&0.2 \end{bmatrix} \begin{bmatrix} 2&3\\ 1&4 \end{bmatrix}

gives:

\boxed{ \begin{bmatrix} 0.4&1.1 \end{bmatrix}. }

Thus:

\boxed{ \frac{\partial L}{\partial x} = [0.4,1.1]. }

5.49.1.26 Wgrad numerical

For one column-vector example, the gradient is conceptually:

\frac{\partial L}{\partial W} = \frac{\partial L}{\partial y}x^T.

Therefore:

\begin{bmatrix} 0.1\\ 0.2 \end{bmatrix} \begin{bmatrix} 5&6 \end{bmatrix}.

This gives:

\boxed{ \frac{\partial L}{\partial W} = \begin{bmatrix} 0.5&0.6\\ 1.0&1.2 \end{bmatrix}. }

This corresponds to the source's Wgrad formula in equivalent column-vector notation. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.27 Weight update numerical

Suppose:

\eta=0.01.

Then:

W_{\text{new}} = W_{\text{old}} - 0.01 \begin{bmatrix} 0.5&0.6\\ 1.0&1.2 \end{bmatrix}.

Therefore:

W_{\text{new}} = \begin{bmatrix} 2&1\\ 3&4 \end{bmatrix} - \begin{bmatrix} 0.005&0.006\\ 0.010&0.012 \end{bmatrix}.

So:

\boxed{ W_{\text{new}} = \begin{bmatrix} 1.995&0.994\\ 2.990&3.988 \end{bmatrix}. }

In DeepSeek's mixed-precision framework, this update is performed on the high-precision master weights, not on an FP8-only copy. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.28 Why not update the FP8 weight directly?

Suppose the current master weight is:

W_{\text{master}}=1.234567.

After FP8 conversion you may get an approximation:

W_{FP8}\approx1.23

for illustration.

Suppose the gradient is:

dW=0.0017.

The desired update is:

1.234567-\eta(0.0017).

If you repeatedly modify only the coarse FP8 representation, tiny updates can be lost.

The master FP32 copy preserves these small changes.

This is the conceptual reason behind master-weight storage, and the source explicitly ties the use of FP32 to stable learning and accurate updates. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.29 Source-specific precision map

The source's mixed-precision diagram can be summarized like this:

Quantity / operation Precision described by source
Stored input activations BF16
Fprop input during GEMM FP8
Stored/master weights FP32 or high precision
Weight used by GEMM FP8
Fprop accumulation FP32
Output stored/inter-layer BF16
Incoming gradient BF16
Dgrad computation FP8 operands
Dgrad accumulation FP32
Dgrad result passed backward BF16
Wgrad computation FP8 operands
Wgrad storage FP32
Master weights FP32
Optimizer states FP32
Weight update FP32

(Source: Build a DeepSeek Model (From Scratch))

5.49.1.30 Why are optimizer states also FP32?

The source explicitly names optimizer states such as:

\boxed{\text{momentum and variance in AdamW}}

as being kept in FP32. (Source: Build a DeepSeek Model (From Scratch))

Why?

Because these states accumulate information across many optimization steps.

For an Adam-like optimizer, simplified state variables include:

m_t

and:

v_t.

They contain running statistics of gradients.

If these were aggressively quantized, accumulated numerical errors could affect future updates.

So the source's strategy is:

\boxed{ \text{persistent optimizer state} \rightarrow \text{FP32}. }

5.49.1.31 Why not store all activations in FP32?

Because activations are enormous.

Suppose:

B=32,\quad S=4096,\quad d=4096.

Then the number of activation values is:

32\times4096\times4096.

Calculate:

4096\times4096 = 16,777,216.

Then:

16,777,216\times32 = 536,870,912.

So over:

\boxed{536\text{ million values}}.

At 4 bytes each:

\approx2.147\text{ GB}

for just one such activation tensor.

Therefore using FP32 everywhere can be extremely expensive.

This explains the motivation for BF16/FP8 storage and computation, although the numerical example is our derived illustration.

5.49.1.32 The deeper design principle

The mixed-precision architecture answers:

Where is precision actually worth paying for?

DeepSeek's answer is roughly:

\boxed{ \text{massive repeated GEMMs} \rightarrow \text{FP8} }

while:

\boxed{ \text{accumulation} \rightarrow \text{FP32} }

and:

\boxed{ \text{persistent learning state} \rightarrow \text{FP32} }

and:

\boxed{ \text{inter-layer activation/gradient storage} \rightarrow \text{BF16}. }

That is much more intelligent than simply saying “use FP8.”

5.49.1.33 Sensitive components that remain higher precision

The source goes one step further.

It says certain Transformer components bypass FP8 and remain in higher precision such as BF16.

The source specifically lists:

\boxed{\text{Embedding modules}}
\boxed{\text{Final output head}}
\boxed{\text{MoE gating modules}}
\boxed{\text{Normalization layers}}
\boxed{\text{attention softmax/context-vector calculations}}.

(Source: Build a DeepSeek Model (From Scratch))

This is extremely important.

5.49.1.34 Why keep the MoE gate higher precision?

Recall our MoE routing:

L=XW_R.

Then:

TopK(L)

selects experts.

A small numerical change around a ranking boundary could change which experts are selected.

For example:

L=[2.01,2.00,1.2].

Top-1:

E_1.

But an error could turn:

2.01\rightarrow1.99

and:

2.00\rightarrow2.00.

Now:

E_2

could be selected.

So router calculations are sensitive to numerical perturbations.

The source therefore lists MoE gating among components kept at higher precision. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.35 Why keep softmax higher precision?

Attention uses:

softmax(z_i) = \frac{e^{z_i}} {\sum_j e^{z_j}}.

Exponentials can be numerically sensitive.

Suppose logits are:

[10,9,1].

Small numerical errors in the logits can change the resulting probabilities.

Therefore the source keeps attention's softmax and context-vector calculation out of the FP8 path. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.36 Why keep normalization higher precision?

Consider RMSNorm:

\frac{x} {\sqrt{\operatorname{mean}(x^2)+\epsilon}}.

The normalization depends on aggregate statistics.

Numerical errors in the denominator can affect every component of the normalized vector.

So the source lists normalization layers among the higher-precision components. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.37 The precision hierarchy

A useful mental model is:

\boxed{ FP8 = \text{fast arithmetic} }
\boxed{ BF16 = \text{robust inter-layer representation} }
\boxed{ FP32 = \text{high-fidelity accumulation and learning state} }

This isn't saying these are mathematically interchangeable; they serve different roles.

5.49.1.38 Exam numerical — memory savings

A tensor contains:

1,000,000,000

values.

FP32
1\times10^9\times4 = 4\times10^9

bytes:

\boxed{4\text{ GB}}.
BF16
1\times10^9\times2 = 2\text{ GB}.
FP8
1\times10^9\times1 = 1\text{ GB}.

Therefore:

\boxed{ FP32:4GB \rightarrow BF16:2GB \rightarrow FP8:1GB. }

This is the raw storage effect of changing bit width.

5.49.1.39 Exam numerical — gradient update

Given:

W= \begin{bmatrix} 1.5&2.0\\ 3.0&4.5 \end{bmatrix}

and:

dW= \begin{bmatrix} 0.2&-0.1\\ 0.3&0.4 \end{bmatrix}

with:

\eta=0.05.

Then:

W_{\text{new}} = W-0.05dW.

So:

0.05dW= \begin{bmatrix} 0.01&-0.005\\ 0.015&0.02 \end{bmatrix}.

Therefore:

\boxed{ W_{\text{new}} = \begin{bmatrix} 1.49&2.005\\ 2.985&4.48 \end{bmatrix}. }

Again, conceptually this update happens on the high-precision master weights in the source's framework. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.40 One very important exam distinction

Do not say:

\boxed{ \text{“DeepSeek stores everything in FP8.”} }

The source explicitly contradicts that.

Instead:

\boxed{ \text{FP8 for bulk GEMM computation} }
\boxed{ \text{BF16 for many activations/gradients and sensitive components} }
\boxed{ \text{FP32 for accumulation, master weights, Wgrad, optimizer state, and updates}. }

(Source: Build a DeepSeek Model (From Scratch))

5.49.1.41 Another important distinction: computation vs storage

These two questions are different:

“What precision is this tensor stored in?”

versus:

“What precision is used to compute with it?”

For example:

\boxed{ x\text{ stored in BF16} }

but:

\boxed{ x\text{ converted to FP8 for GEMM}. }

Similarly:

\boxed{ W_{\text{master}}\text{ stored in FP32} }

but:

\boxed{ W\text{ converted to FP8 for GEMM}. }

This distinction is one of the most important things to understand about mixed precision.

5.49.1.42 Full lifecycle in equations

Forward
x_{BF16} \xrightarrow{\text{quantize}} x_{FP8}
W_{FP32} \xrightarrow{\text{quantize}} W_{FP8}
Y_{FP32} = W_{FP8}X_{FP8} \quad \text{with FP32 accumulation}
Y_{FP32} \rightarrow Y_{BF16}.
Backward — Dgrad
G_{BF16} \rightarrow G_{FP8}
W \rightarrow W_{FP8}
dX_{FP32} = G_{FP8}W_{FP8}^{T}

then:

dX_{FP32}\rightarrow dX_{BF16}.
Backward — Wgrad
X\rightarrow X_{FP8}
G\rightarrow G_{FP8}
dW_{FP32} = X_{FP8}^{T}G_{FP8}.
Update
\boxed{ W_{\text{master,new}} = W_{\text{master,old}} - \eta dW_{FP32}. }

This is the full precision choreography described in the source. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.43 The exam-level “why” for every precision choice

Choice Why
FP8 multiplication Speed + lower memory/data movement
FP32 accumulation Reduce accumulation error
BF16 activations More robust than FP8 for stored intermediate values
FP32 master weights Preserve small parameter updates
FP32 Wgrad Accurate parameter-learning signal
FP32 optimizer states Stable accumulated optimization statistics
Higher precision sensitive modules Prevent quantization-induced instability

This summarizes the source's mixed-precision reasoning. (Source: Build a DeepSeek Model (From Scratch))

5.49.1.44 Source-reported performance

The source states that using FP8 for the three major GEMMs:

\boxed{ Fprop,\quad Dgrad,\quad Wgrad }

can provide up to a 2× speed improvement over BF16 operations in its described framework. (Source: Build a DeepSeek Model (From Scratch))

This is a source-reported performance figure, not a universal guarantee.
