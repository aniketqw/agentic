Compensate one fixed quantization error using correlations in calibration activations.

Prerequisites: Matrix multiplication and shape contracts, Matrix gradients from a scalar loss, Quantization scale units and rounding

Notation and assumptions

Current free-coordinate positive-definite curvature proxy H; error e=wq-wqhat. Minimize δ^T H δ subject δq=e. Actual loss Hessian can include an overall factor2 that cancels in the ratio.

Derivation and mechanism

  1. Use a Lagrange multiplier for the fixed-coordinate constraint.
  2. The optimum displacement is proportional to H^-1[:,q].
  3. Set its q component to e; update w←w-δ. Repeat with the remaining-coordinate inverse, not an unchanged full inverse.
\delta={e\over(H^{-1})_{qq}}(H^{-1})_{:,q}

Worked example

w=[.42,.30],H=[[1,-1],[-1,2]],H^-1=[[2,1],[1,1]],fix w0=3/7≈.428571. e≈-.008571; δ=[e,e/2]. New w≈[.428571,.304286]. Constrained loss=e²/2, versus e² for naive independent fixing.

Limitations

  • This is one compensation step, not a full blocked GPTQ implementation.
  • Calibration representativeness, damping and singular curvature matter.

Connections to later concepts

  • F08 supplies matrix-gradient/curvature intuition, while calibration inputs determine which output directions quantization must preserve.

Step 3.6 — Advanced Quantization: Clipping, Calibration, Dynamic/Static Quantization, and GPTQ

Plan node: I4 · chat order #31

We now move from the basic idea of quantization to the question that actually matters in practice:

How do we choose the quantization range and the quantized values so that model output changes as little as possible?

The supplied quantization deck develops this progression:

\boxed{ \text{basic quantization} \rightarrow \text{outliers} \rightarrow \text{clipping} \rightarrow \text{calibration} \rightarrow \text{dynamic/static quantization} \rightarrow \text{GPTQ} }

I’ll take it in exactly that order.

1. The fundamental problem with a quantization grid

Recall symmetric quantization:

s=\frac{127}{\alpha}

for INT8, where

\alpha=\max |x|.

Then:

x_q=\operatorname{round}(sx).

This looks perfect until an outlier appears.

Suppose:

X=[-1.0,-0.8,-0.6,-0.4,0,0.5,0.7,256].

Then:

\alpha=256.

Therefore:

s=\frac{127}{256} \approx0.496.

Now look at x=1.0:

1(0.496)=0.496.

So:

x_q=\operatorname{round}(0.496)=0.

And for:

x=0.5:
0.5(0.496)=0.248

so again:

x_q=0.

Thus:

0.5\rightarrow0

even though 0.5 is a perfectly meaningful value.

The supplied deck explicitly demonstrates this “one outlier ruins the whole grid” problem. (Source: quantization-slides)

2. Why does one outlier cause such a big problem?

Because a single global scale must represent the entire interval.

With:

\alpha=256,

the integer interval

[-127,127]

must represent:

[-256,256].

Therefore, one integer step corresponds to approximately:

\frac{256}{127} \approx2.016.

So the grid is extremely coarse.

That means:

Real values:

-3 -2 -1  0  1  2  3
 |  |  |  |  |  |  |

Quantized grid:

...     0     ...

Several distinct small values can collapse to the same integer.

3. First solution: clipping

Instead of allowing the outlier to determine the range, we deliberately clip the tensor.

Suppose:

X=[-1,-0.8,-0.5,0,0.4,0.9,256].

Instead of:

[-256,256],

we choose:

\boxed{[-5,5]}.

Any value outside this range is clipped.

So:

256\rightarrow5.

Yes, we intentionally destroy the outlier.

Why?

Because we may gain much better precision for the huge number of ordinary values.

The supplied deck explicitly presents clipping as trading accuracy on extreme values for better precision on the rest of the distribution. (Source: quantization-slides)

4. Numerical comparison

Suppose:

x=1.
Without clipping
\alpha=256.

Thus:

s=\frac{127}{256} \approx0.496.

Then:

x_q=\operatorname{round}(1\times0.496) = 0.

Dequantize:

x_{\text{deq}}=\frac0{0.496}=0.

Error:

|1-0|=\boxed1.

Very bad.

With clipping to 5

Now:

\alpha=5.

Scale:

s=\frac{127}{5} = 25.4.

Then:

1(25.4)=25.4

so:

x_q=25.

Dequantize:

x_{\text{deq}} = \frac{25}{25.4} \approx0.984.

Error:

|1-0.984| \approx \boxed{0.016}.

Huge improvement for the normal value.

But the outlier:

256\rightarrow5

has enormous error.

This is the central quantization tradeoff:

\boxed{ \text{protect the tails} \quad\text{vs}\quad \text{protect the bulk} }

5. So how do we choose the clipping threshold?

This is the calibration problem.

We need to find a good range:

[\beta,\alpha]

or, for symmetric quantization,

[-\alpha,\alpha].

The supplied slides explain that calibration determines the quantization range before computing the scale. (Source: quantization-slides)

There are several possibilities.

6. Calibration method 1 — literal min/max

Simplest:

\alpha=\max|X|.

No calibration dataset is needed.

But a single extreme outlier can make the grid terrible.

So:

\boxed{\text{simple but potentially wasteful}}

7. Calibration method 2 — percentile clipping

Instead of using the absolute maximum, choose a high percentile.

For example:

P_{99.9}.

Then values above that threshold are clipped.

Conceptually:

\boxed{ 99.9\%\text{ of values are preserved normally} }

while the extreme 0.1\% can be clipped.

The supplied deck uses percentile-based range selection as one calibration strategy. (Source: quantization-slides)

8. Why might percentile be better?

Imagine:

9999

values lie between:

[-1,1]

but one value is:

100.

Using max:

\alpha=100.

Using approximately the 99th percentile:

\alpha\approx1.

Then the quantization grid becomes much finer around the region where almost all data lies.

So the objective is not necessarily:

\boxed{\text{minimize every individual weight error}}

but often:

\boxed{\text{minimize the useful error over the distribution}}

9. Calibration method 3 — choose the clip by minimizing MSE

This is more principled.

For every candidate clipping value c:

  1. Clip values to [-c,c].
  2. Quantize.
  3. Dequantize.
  4. Compare reconstructed values with the originals.
  5. Compute MSE.

The mean squared error is:

\boxed{ \operatorname{MSE} = \frac1n\sum_{i=1}^{n}(x_i-\hat{x}_i)^2 }

where:

x_i=\text{original}

and

\hat{x}_i=\text{quantized/dequantized}.

Then choose the c producing the smallest MSE.

The supplied deck gives an explicit INT4 calibration experiment with candidate clip values of 30%, 40%, 50%, 60%, and 100% of the true maximum. (Source: quantization-slides)

10. The slide's numerical example

The deck reports:

Candidate clipping MSE
30% 0.127
40% 0.068
50% 0.055
60% 0.063
100% 0.156

Therefore:

\boxed{50\%\text{ is optimal in this example}}

because:

0.055

is the smallest MSE.

The deck reports that this MSE-selected clipping produced about 65% lower MSE than naive full-range clipping for that INT4 heavy-tailed example. (Source: quantization-slides)

11. Why doesn't the best clipping always equal 100%?

Because the objective has two competing errors.

Error A — quantization resolution

Larger range:

c\uparrow

means the quantization interval becomes larger.

Therefore ordinary values are represented less precisely.

Error B — clipping distortion

Smaller range:

c\downarrow

means more values are clipped.

Therefore tails are distorted more heavily.

So MSE is approximately balancing:

\boxed{ \text{rounding error} + \text{clipping error} }

The optimal c sits somewhere between the extremes.

12. Why is this more important for INT4 than INT8?

INT8 has:

256

possible codes.

INT4 has:

2^4=16

codes.

So INT4 has vastly fewer available quantization levels.

Therefore every level matters more.

The supplied calibration experiment reports that clipping selection mattered strongly for INT4 but had much less benefit for INT8 in the same setup. (Source: quantization-slides)

This gives an important general principle:

\boxed{ \text{lower bit-width} \Rightarrow \text{greater need for careful calibration} }

13. Calibration method 4 — KL divergence

MSE isn't the only objective.

Suppose the original activation/weight distribution is:

P.

After quantization, we obtain:

Q.

We can choose the clipping range that minimizes:

\boxed{ D_{KL}(P\|Q) }

where:

D_{KL}(P\|Q) = \sum_x P(x)\log\frac{P(x)}{Q(x)}.

The supplied deck describes KL-divergence calibration as another search-based calibration method, using histograms of original and quantized distributions. (Source: quantization-slides)

The distinction is:

\boxed{ \text{MSE compares numerical values} }

whereas:

\boxed{ \text{KL compares distributions} }

14. Very important: weights vs activations

Now we encounter another practical distinction.

Weights

After training, weights are fixed.

Therefore their range can be measured ahead of time:

W\rightarrow\text{measure range once}.
Activations

Activations depend on the input.

For one input:

X_1\rightarrow A_1

and for another:

X_2\rightarrow A_2.

Usually:

A_1\neq A_2.

Therefore activation ranges can change from one inference to another.

The supplied slides explicitly distinguish fixed weight ranges from input-dependent activation ranges. (Source: quantization-slides)

15. Dynamic quantization

Dynamic quantization handles changing activation ranges by measuring them during inference.

For each new input:

\boxed{ \text{measure activation range} \rightarrow \text{compute scale/zero-point} \rightarrow \text{quantize} }

The range is freshly computed for the current activation values.

The supplied slides describe exactly this behavior. (Source: quantization-slides)

16. Dynamic quantization flow

Suppose layer 1 produces:

A_1=[-2,3,5].

Find:

\alpha=5.

Build quantization parameters.

Then a different input produces:

A_2=[-0.2,0.4,0.7].

Now:

\alpha=0.7.

The scale is recomputed.

Thus:

\boxed{ \text{same layer} \neq \text{same activation scale for every input} }

under dynamic quantization.

17. Advantage of dynamic quantization

No large calibration dataset is required beforehand for the activation range.

Because:

\boxed{ \text{the current input provides the range} }

The supplied deck states that dynamic quantization needs no calibration data ahead of time. (Source: quantization-slides)

18. Disadvantage of dynamic quantization

The price is runtime work.

For every inference:

\text{measure} \rightarrow \text{calculate scale} \rightarrow \text{quantize}.

Therefore:

\boxed{ \text{less offline preparation} \quad\text{but more runtime overhead} }

19. Static quantization

Static quantization does the opposite.

We run representative calibration data before deployment.

Suppose:

D_{\text{calibration}} = \{x_1,x_2,\ldots,x_N\}.

Run the model on these.

Observe the activation ranges.

Choose fixed:

s,z.

Then deployment uses those fixed parameters.

The supplied deck describes exactly this: a small calibration dataset is run offline, activation distributions are recorded, and the resulting s,z are fixed before real inference. (Source: quantization-slides)

20. Dynamic vs static

Property Dynamic Static
Activation range computed at runtime determined offline
Calibration dataset not required required
Runtime overhead higher lower
Sensitivity to calibration data low important

The static method is only as good as the representativeness of its calibration dataset. (Source: quantization-slides)

21. Numerical static-vs-dynamic example

Suppose calibration data gives:

A\in[-4,4].

Static quantization chooses:

\alpha=4.

For INT8:

s=\frac{127}{4}=31.75.

Now suppose an actual deployment input produces:

A=[-8,1,2].

The fixed scale was designed for:

[-4,4].

The new value:

8

is outside the calibrated range.

So it must be clipped.

Dynamic quantization instead sees:

\max|A|=8

and computes:

s=\frac{127}{8}=15.875.

Thus dynamic adapts to the new input.

This illustrates the fundamental tradeoff.

22. Now the question becomes more interesting

So far our objective was:

\text{minimize weight/activation reconstruction error}.

But is that actually what we care about?

Suppose:

w=0.42

becomes:

\hat{w}=0.4286.

That's a weight error of:

0.0086.

But does that necessarily mean the model output is badly affected?

No.

A small change in one weight might barely affect the final output.

Conversely, a tiny change in a highly sensitive weight could matter enormously.

This leads to:

\boxed{\text{GPTQ}}

23. GPTQ — the key idea

GPTQ is post-training quantization designed specifically to minimize the damage quantization does to a layer's outputs.

The quantization deck describes GPTQ as processing a pretrained model one layer at a time, asking:

Which quantized weights best reconstruct the original layer outputs on calibration data? (Source: quantization-slides)

This is a much more intelligent objective than:

\min\|W-\hat W\|^2.

Instead, conceptually:

\boxed{ \min_{\hat W} \|WX-\hat WX\|^2 }

where:

  • W = original layer weights,
  • \hat W = quantized weights,
  • X = calibration activations.

The slides explicitly formulate this output-reconstruction objective. (Source: quantization-slides)

24. Why does GPTQ use calibration activations?

Suppose a layer computes:

Y=WX.

A particular weight matters according to the input dimensions that actually pass through that layer.

If calibration activations tell us that feature 7 varies strongly and feature 12 barely varies, then perturbing a weight connected to feature 7 may have a much larger effect.

Therefore:

\boxed{ \text{importance depends on the data flowing through the layer} }

not simply on the numerical size of the weight itself.

25. Deriving the quadratic objective

For one output row w:

y=wX.

After quantization:

\hat y=\hat wX.

The output error is:

\|wX-\hat wX\|^2.

Define:

\delta=w-\hat w.

Then:

wX-\hat wX = (w-\hat w)X = \delta X.

Therefore:

\|\delta X\|^2.

Using matrix algebra:

\boxed{ \|\delta X\|^2 = \delta XX^T\delta^T }

So define:

\boxed{ H=XX^T }

or with regularization:

\boxed{ H=XX^T+\lambda I. }

The supplied slides identify this H as the Hessian-like matrix arising from calibration activations. (Source: quantization-slides)

26. Why call H a Hessian?

Consider the quadratic objective:

L(\delta) = \delta H\delta^T.

The curvature of this quadratic depends on:

H.

So H tells us how sensitive output reconstruction is to movement in different directions of weight space.

This is why GPTQ can make data-aware corrections.

27. The most important GPTQ insight

Suppose one weight is quantized.

The quantization error is:

e=w_q-w.

Naive quantization says:

“Too bad. That error is fixed.”

GPTQ says:

“Can I redistribute the damage across weights that are less sensitive?”

The supplied slides explicitly describe this compensation idea. (Source: quantization-slides)

Therefore:

\boxed{ \text{one weight's quantization error} \rightarrow \text{compensating changes elsewhere} }

while respecting the quantization constraint.

28. Worked GPTQ example from the slides

Consider:

w= [0.42,\ 0.30,\ 0.50].

Suppose INT4 quantization uses a grid such that:

\hat w = \frac{\operatorname{round}(14w)}{14}.

For the first element:

0.42\times14=5.88.

Round:

6.

Thus:

\hat w_1=\frac6{14} = 0.4286.

Error:

e=w_1-\hat w_1
=0.42-0.4286 = \boxed{-0.0086}.

These are the values shown in the supplied GPTQ slides. (Source: quantization-slides)

29. Naive quantization vs GPTQ

Naive:

[0.42,0.30,0.50]

might become:

[0.4286,0.2857,0.5000].

GPTQ instead first quantizes the first weight and then modifies other still-unquantized weights to compensate for the induced output error.

The slides give the sequence:

[0.4200,0.3000,0.5000]

↓

[0.4286,0.2966,0.4999]

↓

[0.4286,0.2857,0.5010]

↓

[0.4286,0.2857,0.5000].

(Source: quantization-slides)

Notice something fascinating:

The intermediate weights are deliberately moved away from their original values.

That sounds wrong until we remember the objective.

30. GPTQ does NOT minimize raw weight error

This is an extremely important exam/interview point.

A student might assume:

\boxed{ \text{best quantization} = \min\|W-\hat W\|^2 }

GPTQ says:

\boxed{ \text{best quantization} = \text{minimize output damage} }

The supplied deck gives a striking result:

  • naive independent rounding has larger output error;
  • GPTQ produces 52.6% lower output error in its reported experiment;
  • yet GPTQ can have higher raw weight error.

(Source: quantization-slides)

That sounds paradoxical only until you realize the objective is different.

31. Intuition using a road analogy

Imagine two roads.

Direction A

Changing the road by 1 cm causes almost no traffic problem.

Direction B

Changing the road by 1 cm causes traffic to collapse.

If you only minimize physical distance moved, you treat both directions equally.

GPTQ instead asks:

\boxed{\text{“Which direction can absorb the quantization error with least output damage?”}}

So it may deliberately move some weights more if those dimensions are less sensitive.

32. GPTQ's compensation equation

The slides give the compensation update in terms of the inverse Hessian.

For the weight being quantized, the quantization error is incorporated into a correction:

\boxed{ \delta_q = \frac{e} {[H^{-1}]_{qq}} }

and the remaining weights are adjusted using the corresponding column of H^{-1}.

The exact form shown in the deck is:

\boxed{ w_j \leftarrow w_j-\delta_q \,[H^{-1}]_{j,q} }

with normalization by the corresponding diagonal term in the definition of \delta_q. (Source: quantization-slides)

The important conceptual meaning is more important than memorizing every subscript:

\boxed{ H^{-1} = \text{how quantization error should be redistributed} }

33. Numerical GPTQ compensation from the slide

The slide gives:

e=-0.0086

and:

[H^{-1}]_{qq}=0.1268

with another relevant element:

[H^{-1}]_{2,1}=-0.0504.

The correction produces:

w_2 \leftarrow 0.30 - \frac{0.126?}{?}

and the supplied result is:

\boxed{w_2=0.2966}.

The exact displayed algebra is less important for the intuition than the conclusion:

0.30\rightarrow0.2966

before w_2 itself is quantized.

That means GPTQ prepares future weights for the error created by earlier quantization. (Source: quantization-slides)

34. Why does GPTQ process weights sequentially?

Suppose we have:

w_1,w_2,w_3,\ldots,w_d.

GPTQ:

  1. quantizes one coordinate/column;
  2. measures its error;
  3. compensates remaining coordinates;
  4. moves to the next coordinate;
  5. repeats.

Therefore:

\boxed{ \text{quantize} \rightarrow \text{compensate} \rightarrow \text{quantize} \rightarrow \text{compensate} \rightarrow\cdots }

The supplied deck explicitly describes this sequential process. (Source: quantization-slides)

35. Why “one column across all rows”?

An important implementation detail.

Suppose a weight matrix:

W\in\mathbb{R}^{d_{\text{out}}\times d_{\text{in}}}.

The calibration Hessian:

H=XX^T

depends only on the input activations X.

Every output row sees the same input features.

Therefore every row can reuse:

H,\quad H^{-1}.

The slides say GPTQ processes one column across all rows simultaneously and reuses the same decomposition, rather than solving a completely independent problem for every row. (Source: quantization-slides)

This is an important computational optimization.

36. Why is GPTQ computationally practical?

If we solved a separate optimization problem independently for every row, that would be expensive.

Instead:

H=XX^T

is computed once for the layer.

Its factorization is then reused.

The slide describes a Cholesky decomposition being computed once and reused column-by-column across the weight matrix. (Source: quantization-slides)

The dominant matrix factorization is approximately:

\boxed{O(d^3)}

for the relevant input dimension, which the deck highlights. (Source: quantization-slides)

37. The complete advanced quantization picture

We can now see why all these techniques exist:

\boxed{ \text{Global min/max} }

is simple but vulnerable to outliers.

Therefore:

\boxed{ \text{clipping} }

can trade tail accuracy for better bulk precision.

But how should clipping be selected?

\boxed{ \text{calibration} }

using:

\text{percentiles}

or:

\text{MSE}

or:

\text{KL divergence}.

Then activations introduce another issue:

\boxed{ \text{dynamic vs static quantization} }

because activation ranges depend on the input.

Finally, instead of minimizing raw tensor reconstruction:

\boxed{ \text{GPTQ minimizes layer-output damage} }

using calibration activations and curvature information.

39. Exam numerical — MSE calibration

Suppose candidate clipping thresholds yield:

\{0.12,\ 0.08,\ 0.05,\ 0.07,\ 0.15\}

for MSE.

Minimum is:

\boxed{0.05}.

Therefore choose the corresponding clipping threshold.

Very simple exam question, but conceptually important:

\boxed{ \text{choose the range producing minimum calibration loss} }

40. Exam numerical — quantization resolution

INT8 symmetric range:

[-127,127].

Total number of usable positive/negative code steps is roughly 254 apart from the centered zero convention.

If:

[-5,5]

is mapped to this grid, approximate step size is:

\frac{10}{254} \approx \boxed{0.0394}.

If instead:

[-256,256],

step size becomes:

\frac{512}{254} \approx \boxed{2.016}.

This immediately shows why clipping can dramatically improve precision for ordinary values.

41. Exam numerical — dynamic quantization

An activation tensor is:

X=[-2,1,4].

INT8 symmetric.

\alpha=4.

Therefore:

s=\frac{127}{4} = \boxed{31.75}.

Now another inference produces:

X'=[-1,2,8].

Dynamic quantization recalculates:

\alpha'=8.

Thus:

s'=\frac{127}{8} = \boxed{15.875}.

The scale changes.

Static quantization would retain the previously calibrated scale.

42. Exam numerical — GPTQ conceptual question

Suppose two quantization methods produce:

Method Weight MSE Output MSE
Naive 0.010 0.020
GPTQ 0.015 0.009

Which method is better according to GPTQ's objective?

Answer:

\boxed{\text{GPTQ}}

because:

0.009<0.020.

Even though:

0.015>0.010

for raw weight MSE.

This is one of the most important conceptual exam questions in this section.

43. Do not confuse these objectives

Ordinary quantization

Often focuses on:

\boxed{ \|W-\hat W\| }
GPTQ

Focuses on:

\boxed{ \|WX-\hat WX\| }

That one change in objective is the conceptual leap.
