Step 5.34 — Transfer Languages, Few-Shot Prompting, and the Failure of Single-Language Specialization

Plan node: I11 · chat order #75

We now connect three experiments that look separate but actually answer one large question:

\boxed{ \text{How should an Indic-capable model obtain useful knowledge for a target language?} }

The deck studies three possibilities:

\boxed{\text{English demonstrations}}
\boxed{\text{Hindi demonstrations}}
\boxed{\text{target-language demonstrations}}

and then asks whether simply fine-tuning a model heavily for one Indic language causes that ability to transfer to the others.

The answer to the first question is encouraging:

\boxed{ \text{linguistically related demonstrations help} }

The answer to the second is much more cautionary:

\boxed{ \text{specializing in one Indic language does not automatically transfer to the rest} }

Both are explicitly reported in the supplied IndicGenBench deck. (Source: indicgenbench-slides)

5.34.1 First: what is an “exemplar”?

An in-context exemplar is simply a worked example placed inside the prompt.

Suppose the task is translation.

Without an example:

Translate:
English sentence

With one example:

Example:
English sentence A
→
Hindi sentence A

Now translate:
English sentence B

The model can infer:

\boxed{ \text{what the task expects} }

from the demonstrated input-output relationship.

5.34.2 Three possible languages for the exemplar

Suppose the target test language is:

\boxed{\text{Punjabi}}.

We could give demonstrations in:

English
\boxed{\text{English exemplars}}
Hindi
\boxed{\text{Hindi exemplars}}
Punjabi
\boxed{\text{test-language exemplars}}

The benchmark compares these.

5.34.3 The reported ordering

The deck says the prompting order is consistent:

\boxed{ \text{test language} > \text{Hindi} > \text{English} }

and explicitly connects this with linguistic relatedness to the test language. (Source: indicgenbench-slides)

So if Punjabi is the target:

\boxed{ \text{Punjabi demonstrations} > \text{Hindi demonstrations} > \text{English demonstrations} }

in the reported setup.

5.34.4 Why would Hindi beat English?

The benchmark's empirical interpretation is:

\boxed{ \text{closer linguistic relationship} \rightarrow \text{more useful demonstrations} }

Hindi is itself an Indic language and can therefore provide a more relevant demonstration distribution than English for many Indic targets.

This is a source-supported interpretation of the reported ordering. (Source: indicgenbench-slides)

We should not turn it into:

Hindi is equally close to every Indic language.

That is not what the source establishes.

5.34.5 Why is this surprising?

You might initially assume:

\boxed{ \text{English is best} }

because English is the dominant training/evaluation language for many multilingual benchmarks.

But the experiment suggests:

\boxed{ \text{related-language examples can be more useful than English examples} }

for Indic generation.

This is an important shift in how we think about multilingual prompting.

5.34.6 Small-model effect

The deck gives an especially interesting observation:

\boxed{ \text{for smaller models, Hindi exemplars can come very close to, and sometimes exceed, target-language exemplars} }

(Source: indicgenbench-slides)

That suggests that a strong bridge language can be particularly valuable when the model has less capacity.

Conceptually:

\boxed{ \text{small model} + \text{related-language demonstrations} \rightarrow \text{stronger task induction} }

in the reported experiments.

5.34.7 Think of the exemplar as a compressed task description

An exemplar communicates several things at once:

\boxed{ \text{input structure} + \text{output structure} + \text{expected linguistic style} + \text{task mapping} }

Suppose the task is QA.

A Hindi example can simultaneously teach:

\text{how the question is phrased in an Indic language}

and:

\text{what the answer format looks like}.

An English example may communicate the task just fine, but it may be less useful for target-language generation.

This latter explanation is a model-level interpretation rather than a separately quantified claim in the source.

5.34.8 Numerical example

Suppose a model obtains:

\boxed{45}

with English exemplars,

\boxed{55}

with Hindi exemplars,

and:

\boxed{60}

with target-language exemplars.

Then the ordering is:

60>55>45.

English → Hindi improvement:

55-45 = \boxed{10\text{ points}}.

Hindi → target-language improvement:

60-55 = \boxed{5\text{ points}}.

These numbers are illustrative; the source provides the qualitative ordering rather than these hypothetical values.

5.34.9 Now ask: is prompting always better than fine-tuning?

No.

The deck directly compares:

\boxed{\text{fine-tuning}}

with:

\boxed{\text{few-shot prompting}}.

The interesting result is task dependent. (Source: indicgenbench-slides)

5.34.10 QA behaves differently from long-form generation

The deck says:

\boxed{ \text{mT5 beats PaLM-2 on QA tasks even when fine-tuned} }

while:

\boxed{ \text{PaLM-2 wins on longer-form CrossSum-IN} }.

(Source: indicgenbench-slides)

So model architecture and task type matter.

5.34.11 Few-shot vs fine-tuning on QA

For QA, the deck reports that:

\boxed{ \text{few-shot prompting on PaLM-2-XS can match or beat fine-tuning it} }

(Source: indicgenbench-slides)

This is an important result.

It means:

\boxed{ \text{training the model further is not always necessary for strong task performance} }

at least for the reported QA settings.

5.34.12 But long-form generation is different

For:

\boxed{\text{CrossSum-IN}}

the deck says:

\boxed{ \text{fine-tuning still wins outright} }

and calls long-form generation the setting where extra training data clearly pays off. (Source: indicgenbench-slides)

So we now have:

\boxed{ \text{short-span QA} \rightarrow \text{few-shot can be highly competitive} }

versus:

\boxed{ \text{long-form generation} \rightarrow \text{fine-tuning remains very valuable} }.

5.34.13 Why is this plausible?

QA usually requires a relatively short output:

\boxed{ \text{one span / short answer} }

while summarization requires:

\boxed{ \text{long, coherent generation} }.

A few examples can strongly specify a short-answer format.

Long-form generation requires learning more extensive target-language generation behavior.

This is a natural explanation, but the source itself reports the empirical distinction rather than proving this causal mechanism.

5.34.14 Numerical example

Suppose:

QA

Fine-tuned model:

70

Few-shot model:

72.

Then few-shot wins by:

\boxed{2\text{ points}}.
Summarization

Fine-tuned:

60

Few-shot:

48.

Then:

\boxed{12\text{-point advantage for fine-tuning}}.

These are illustrative examples capturing the source's reported pattern, not its exact table values.

5.34.15 Now we reach the biggest specialization experiment

The next question is:

What if we simply train a model mostly on Hindi?

Maybe Hindi is a useful bridge language, so perhaps a Hindi-specialized model will generalize extremely well across Indic languages.

To test this, the deck examines:

\boxed{\text{Airavata}}.

5.34.16 What is Airavata in this experiment?

The deck says Airavata is fine-tuned almost exclusively on:

\boxed{\text{Hindi + English}}

(Source: indicgenbench-slides)

So its training emphasis is highly concentrated compared with broad multilingual systems such as BLOOMZ.

5.34.17 First result: Hindi improves

The deck says Airavata:

\boxed{ \text{clearly beats LLaMA on Hindi} }

(Source: indicgenbench-slides)

This is exactly what we might expect.

If we specialize the model toward Hindi:

\text{Hindi performance} \uparrow.

So specialization can work very well for the language it was trained on.

5.34.18 The surprising part: other Indic languages

Now test Airavata on:

\boxed{\text{Bengali}}
\boxed{\text{Punjabi}}
\boxed{\text{Assamese}}
\boxed{\text{Manipuri}}
\boxed{\text{Santali}}.

The deck says Airavata performs much worse than BLOOMZ on these other Indic languages. (Source: indicgenbench-slides)

Therefore:

\boxed{ \text{Hindi specialization} \not\Rightarrow \text{broad Indic transfer} }

5.34.19 This is an extremely important distinction

Earlier we learned:

\boxed{ \text{Hindi exemplars can be useful} }

Now we learn:

\boxed{ \text{Hindi-only specialization can fail to transfer broadly} }

These are not contradictory.

Why?

Because prompting and training are fundamentally different interventions.

5.34.20 Prompting with Hindi

The model remains broadly multilingual.

You are adding:

\boxed{ \text{Hindi examples at inference time} }

to help guide behavior.

So the underlying model may retain broad language representations.

5.34.21 Fine-tuning heavily on Hindi

Now the model parameters are changed toward:

\boxed{ P_\theta(\text{Hindi behavior}) }

and the training distribution is concentrated.

This can improve Hindi while failing to preserve or develop equally strong behavior for other languages.

The source's Airavata result demonstrates this experimentally. (Source: indicgenbench-slides)

5.34.22 Think of the difference as “bridge” vs “destination”

Hindi prompting can function as a:

\boxed{\text{bridge}}

between a general model and another Indic language.

But Hindi-only model training can create:

\boxed{\text{specialization}}

rather than universal Indic competence.

So:

\boxed{ \text{bridge language} \neq \text{universal replacement language} }

This is an important conceptual lesson.

5.34.23 Numerical specialization example

Suppose:

Airavata

Hindi:

85

Bengali:

50

Punjabi:

48
BLOOMZ

Hindi:

80

Bengali:

Punjabi:

Airavata wins Hindi:

This is an illustrative representation of the qualitative pattern in the deck, not the source's exact numbers.

5.34.24 Why does broad multilingual training help here?

The deck's comparison suggests that:

\boxed{ \text{broad language coverage} }

can be more useful for cross-Indic transfer than:

\boxed{ \text{extreme specialization in one Indic language} }.

The model still needs some specialization to perform well, but narrowing the training distribution too aggressively can hurt transfer.

This conclusion is an interpretation grounded in the Airavata/BLOOMZ comparison. (Source: indicgenbench-slides)

5.34.25 Connect this to the earlier “Hindi exemplar” result

Now we can build a very useful framework.

Strategy A — English exemplars
\text{general multilingual model} + \text{English examples}
Strategy B — Hindi exemplars
\text{general multilingual model} + \text{Hindi examples}
Strategy C — Hindi-specialized model
\text{Hindi-heavy fine-tuning}

The source results indicate:

\boxed{ B>A }

for the reported few-shot prompting comparison, but:

\boxed{ C\text{ does not generalize broadly to other Indic languages} }.

That is an extremely useful conceptual distinction.

5.34.26 The mathematical intuition

Prompting modifies the conditioning context:

P_\theta(y\mid x)

becomes:

\boxed{ P_\theta(y\mid x,E) }

where E is the set of exemplars.

The model parameters:

\theta

stay fixed.

Fine-tuning instead changes:

\boxed{ \theta \rightarrow \theta' }

by optimizing a training objective over a particular distribution.

So:

\boxed{ \text{prompting changes context} }

while:

\boxed{ \text{fine-tuning changes parameters} }.

This is standard ML notation used here to clarify the source's experimental distinction.

5.34.27 Why specialization can hurt transfer

Imagine a model has learned representations shared across:

L_1,L_2,L_3,\ldots,L_{29}.

Now training overwhelmingly on L_1 changes the optimization pressure.

The model is pushed toward:

\boxed{ \text{perform extremely well on }L_1 }

rather than:

\boxed{ \text{maintain broad multilingual generalization} }.

This can lead to specialization without broad transfer.

The source gives empirical evidence of exactly this pattern with Airavata. (Source: indicgenbench-slides)

5.34.28 An important connection to catastrophic forgetting

We should be careful here.

The supplied deck does not explicitly analyze Airavata in terms of catastrophic forgetting, so we should not claim that this experiment proves catastrophic forgetting.

A reasonable interpretation is that highly concentrated fine-tuning can reduce transfer to other languages, but the source's supported conclusion is simply:

\boxed{ \text{single-language specialization does not transfer effectively to the rest} }.

(Source: indicgenbench-slides)

5.34.29 Resource-tier connection

Now connect this to everything from Steps 5.29 and 5.33.

We already found:

\boxed{ \text{High resource} > \text{Medium} > \text{Low} }

in generation performance. (Source: indicgenbench-slides)

And now:

\boxed{ \text{Hindi specialization} \not\Rightarrow \text{all Indic languages} }.

Therefore, solving the low-resource problem is not as simple as:

“Choose one major Indic language and train heavily on it.”

We need:

\boxed{ \text{broad language coverage} }

and:

\boxed{ \text{transfer mechanisms} }

that preserve performance across many languages.

5.34.30 The role of Hindi is therefore nuanced

Hindi appears in two different ways.

As an inference-time exemplar
\boxed{ \text{useful bridge} }

because Hindi demonstrations are often better than English demonstrations.

As a dominant training language
\boxed{ \text{insufficient as a universal substitute} }

because a Hindi-heavy model does not generalize well to every other Indic language.

These two findings together are more informative than either one alone.

5.34.31 Exam-style question

Question:

Does the result “Hindi exemplars outperform English exemplars” imply that a Hindi-specialized LLM should outperform a broad multilingual LLM on all Indic languages?

\boxed{\text{No.}}

The first result concerns in-context prompting, while the second experiment concerns parameter specialization through Hindi/English fine-tuning. The deck reports that Airavata performs better on Hindi but substantially worse than BLOOMZ on several other Indic languages. (Source: indicgenbench-slides)

Suppose:

\boxed{ 52>47>40 }

\boxed{ \text{test language}>\text{Hindi}>\text{English}. }

5.34.33 Exam-style numerical question — transfer failure

Suppose a Hindi-specialized model gets:

90

on Hindi but:

45

on Bengali.

A broad multilingual model gets:

82

on Hindi and:

65

on Bengali.

Hindi specialization gain:

90-82 = \boxed{+8}

but Bengali loss:

45-65 = \boxed{-20}.

This illustrates the concept:

\boxed{ \text{specialization gain on one language} \not\Rightarrow \text{cross-language gain} }.

5.34.34 Master decision framework

Suppose the deployment target is an Indic language.

Scenario 1 — No task-specific training possible

Use:

\boxed{\text{few-shot prompting}}

and prefer demonstrations in:

\boxed{ \text{target language} \rightarrow \text{Hindi} \rightarrow \text{English} }

according to the reported ordering. (Source: indicgenbench-slides)

Scenario 2 — Short QA task

Few-shot prompting may be highly competitive with fine-tuning. (Source: indicgenbench-slides)

Scenario 3 — Long-form summarization

Fine-tuning is more valuable in the reported experiments. (Source: indicgenbench-slides)

Scenario 4 — Build a model for all Indic languages

Do not simply specialize on Hindi.

The Airavata result shows that broad Indic transfer can suffer. (Source: indicgenbench-slides)

5.34.35 Connect to tokenizer fertility

There is one more important interaction.

Suppose target-language demonstrations are best.

But the target language has very high fertility.

Then:

\boxed{ \text{best exemplar language} }

may still be constrained by:

\boxed{ \text{how many examples fit in the context window} }.

So the practical hierarchy becomes:

\boxed{ \text{choose useful language for exemplars} }

then:

\boxed{ \text{fit as many useful examples as the tokenizer allows} }.

That connects Step 5.34 directly to Step 5.33.

5.34.36 Full conceptual chain

We can now put everything together:

\boxed{ \text{Target-language exemplars} > \text{Hindi exemplars} > \text{English exemplars} }

but:

\boxed{ \text{Hindi-heavy specialization} \not\Rightarrow \text{strong all-Indic transfer} }

and:

\boxed{ \text{few-shot} \approx/\!> \text{fine-tuning for some QA settings} }

but:

\boxed{ \text{fine-tuning} > \text{few-shot for long-form generation} }

in the reported experiments. (Source: indicgenbench-slides)

5.34.37 The deeper lesson

There are three different notions of “transfer”:

In-context transfer
\boxed{ \text{examples in another language help the model perform the task} }
Cross-lingual model transfer
\boxed{ \text{multilingual pretraining enables one language's knowledge to support another} }
Parameter specialization
\boxed{ \text{fine-tuning one language changes the model itself} }

These should not be conflated.

Hindi can be an excellent:

\boxed{\text{prompting bridge}}

without being an adequate:

\boxed{\text{universal training substitute}}

for the entire Indic language family.

That distinction is one of the most useful conceptual conclusions from this section. (Source: indicgenbench-slides)

5.34.39 Final mental model

Think of the three strategies as:

\boxed{ \text{Prompt with Hindi} }

= borrow a bridge at inference time

versus:

\boxed{ \text{train mostly on Hindi} }

= specialize the parameters

The first can improve cross-lingual prompting performance.

The second can improve the target training language but does not guarantee broad transfer.

Therefore:

\boxed{ \text{related-language prompting} \neq \text{single-language specialization} }

and that distinction is crucial for understanding multilingual LLM behavior.
