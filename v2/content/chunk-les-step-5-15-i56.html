Step 5.15 — DeepSeek-R1 Distilled Models at Scale

Plan node: I8 · chat order #56

We now move from how one distillation example is trained to the much bigger question:

How was the 800K-example teacher dataset actually turned into six useful small reasoning models, and what do the results tell us about model size, base-model choice, and distillation?

This is where the mathematics we just learned connects directly to the empirical results.

The source describes six distilled models spanning Qwen2.5 and Llama-3 families, all trained with SFT only, with no RL stage for the distilled models. (Source: Build a DeepSeek Model (From Scratch))

5.15.1 First, remember the complete pipeline

We have:

\boxed{ \text{DeepSeek-R1 teacher} }

↓

generates many reasoning responses

↓

\boxed{ \text{rejection sampling / curation} }

↓

\boxed{ \text{800K high-quality training samples} }

↓

choose a smaller pretrained base model

↓

\boxed{ \text{supervised fine-tuning} }

↓

\boxed{ \text{DeepSeek-R1-Distill model} }

The important point is that the student does not repeat the full R1 RL pipeline. The source states that the distilled models receive SFT only. (Source: Build a DeepSeek Model (From Scratch))

5.15.2 Why six models?

DeepSeek did not create just one student.

It tested whether the same teacher-generated knowledge could be transferred into models of different:

  • parameter counts,
  • base-model families,
  • pre-existing capabilities.

The six models are:

\boxed{ \text{Qwen 1.5B,\;7B,\;14B,\;32B} }

and:

\boxed{ \text{Llama 8B,\;70B}. }

(Source: Build a DeepSeek Model (From Scratch))

This lets us ask three different questions:

Question 1

Does a larger student absorb more teacher knowledge?

Question 2

Does the starting base model matter?

Question 3

Is distillation enough, or does the student still need RL?

The experiments address all three.

5.15.3 The starting models matter

This is a very important idea.

The student is not trained from scratch.

It already has pretrained knowledge.

So think of the student's final ability as:

\boxed{ \text{Final ability} \approx \text{base capability} + \text{distilled teacher behavior} }

Not literally an additive equation, but this is the right conceptual model.

The source specifically says the 1.5B and 7B Qwen students use Qwen2.5-Math bases, which are already math-specialized, while the larger Qwen and Llama variants use more general bases. (Source: Build a DeepSeek Model (From Scratch))

According to the source:

5.15.5 Why does a math-specialized base help?

Imagine two students before distillation.

Student A

Already understands:

  • algebraic patterns,
  • mathematical notation,
  • common proof structures,
  • competition-style mathematical language.
Student B

Has broad language knowledge but weaker mathematical specialization.

Now give both the same teacher reasoning traces.

Student A has a better starting representation for those traces.

So even though:

\text{same teacher data}

does not mean:

\text{same final performance}.

That is precisely the point highlighted by the source: base-model pre-existing capabilities interact with distillation quality. (Source: Build a DeepSeek Model (From Scratch))

5.15.6 Training configuration

The source reports that the distilled models were trained for:

\boxed{2\text{–}3\text{ epochs}}

using:

\boxed{\text{batch size}=64}

with:

\boxed{\text{cosine learning-rate decay}}

and maximum context:

\boxed{32,768\text{ tokens}}.

(Source: Build a DeepSeek Model (From Scratch))

The reported initial learning rates were:

Model Initial LR
Qwen 1.5B 1\times10^{-4}
Qwen 7B 8\times10^{-5}
Qwen 14B 7\times10^{-5}
Qwen 32B 6\times10^{-5}
Llama 8B 5\times10^{-5}
Llama 70B 2\times10^{-5}

(Source: Build a DeepSeek Model (From Scratch))

5.15.7 Why are larger models given smaller learning rates?

This is a training-stability idea.

A useful mental model is:

\Delta\theta = -\eta\nabla_\theta L

where:

  • \eta = learning rate,
  • \nabla_\theta L = gradient.

The source uses larger initial learning rates for smaller models and progressively smaller values for larger models. It presents this as a common fine-tuning practice: smaller models can benefit from larger steps, while larger models are more susceptible to instability from overly aggressive updates. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{model size}\uparrow \Rightarrow \text{initial LR}\downarrow }

in this particular training setup.

Do not treat this as a universal law for every LLM training regime. It is the pattern in the supplied source's configuration.

5.15.8 Exam numerical: how many optimizer steps?

Suppose the dataset contains:

800,000

examples and batch size is:

64.

Assuming every example is used once per epoch:

\frac{800,000}{64} = \boxed{12,500}

batches per epoch.

For 2 epochs:

12,500\times2 = \boxed{25,000}

optimizer updates.

For 3 epochs:

12,500\times3 = \boxed{37,500}.

So the rough training range is:

\boxed{25,000\text{–}37,500\text{ optimizer steps}}

under these assumptions.

This is a derived calculation, not a separately reported step count from the source.

5.15.9 What does “cosine decay to one-tenth” mean?

The source says the learning rate gradually decays to:

\boxed{0.1\times \text{initial LR}}

using cosine decay. (Source: Build a DeepSeek Model (From Scratch))

Therefore, for Qwen-1.5B:

\eta_0=10^{-4}

so:

\eta_{\min}=10^{-5}.

For Qwen-32B:

6\times10^{-5}\rightarrow6\times10^{-6}.

For Llama-70B:

2\times10^{-5}\rightarrow2\times10^{-6}.

These endpoint calculations follow directly from the stated one-tenth decay.

5.15.11 First shock: the 1.5B student

The smallest student achieves:

\boxed{28.9\%\text{ AIME}}

while GPT-4o in the supplied table gets:

\boxed{9.3\%}.

So:

28.9-9.3 = \boxed{19.6\text{ percentage points}}.

That is a very large gap.

It also scores:

83.9\%

on MATH-500 versus Claude-3.5-Sonnet's:

78.3\%.

The source uses this as the headline result demonstrating how effectively reasoning behavior can be compressed. (Source: Build a DeepSeek Model (From Scratch))

5.15.12 But don't misinterpret this

It does not mean:

1.5B > 1.8T

in general.

It means:

\boxed{ \text{on these particular benchmarks} }

the distilled 1.5B model scored higher on the reported tasks.

And notice the same 1.5B model is much weaker on coding:

\boxed{16.9\%}

on LiveCodeBench.

So distillation did not make it universally equivalent to the teacher.

5.15.13 Mathematical reasoning compresses differently from coding

For the 1.5B model:

\text{MATH-500}=83.9\%

but:

\text{LiveCodeBench}=16.9\%.

Gap:

83.9-16.9 = \boxed{67.0\text{ percentage points}}.

This is one of the most important results in the source.

It demonstrates a capacity problem:

\boxed{ \text{student can absorb some kinds of teacher behavior much better than others} }

The source specifically points out that coding requires a very large space of syntax, APIs, and programming patterns, which is difficult for a very small model to store. (Source: Build a DeepSeek Model (From Scratch))

5.15.14 Now look at Qwen scaling

AIME performance:

1.5B\rightarrow28.9
7B\rightarrow55.5
14B\rightarrow69.7
32B\rightarrow72.6.

So as model size increases:

\boxed{ 28.9\rightarrow55.5\rightarrow69.7\rightarrow72.6 }

This is called smooth scaling in the source. (Source: Build a DeepSeek Model (From Scratch))

5.15.15 Calculate the increments

From 1.5B to 7B:

55.5-28.9 = \boxed{26.6}

points.

From 7B to 14B:

69.7-55.5 = \boxed{14.2}

points.

From 14B to 32B:

72.6-69.7 = \boxed{2.9}

points.

So the absolute gain from adding parameters gets smaller:

\boxed{ 26.6\rightarrow14.2\rightarrow2.9 }

for these sizes.

This is a useful example of diminishing incremental returns, although the source itself mainly emphasizes the smooth upward scaling rather than fitting a formal scaling law.

5.15.16 Why does performance eventually flatten?

Think about the teacher data.

The student is learning:

\boxed{\text{existing teacher behavior}}

There is only so much information that can be represented by a finite-capacity model.

At small size:

\text{capacity constraint is severe}.

As size grows:

\text{capacity constraint decreases}.

Eventually:

\text{teacher data becomes the limiting factor}.

So conceptually:

\boxed{ \text{performance} = f(\text{data quality},\text{base quality},\text{student capacity}) }

rather than simply:

\text{performance}=f(\text{parameter count}).

5.15.17 Compare Qwen 7B and Llama 8B

This is one of the cleanest demonstrations that size alone is not enough.

Qwen 7B:

\boxed{55.5\%\text{ AIME}}

Llama 8B:

\boxed{50.4\%\text{ AIME}}

Even though:

8B>7B,

the larger model performs worse on AIME.

Difference:

55.5-50.4 = \boxed{5.1\text{ percentage points}}.

(Source: Build a DeepSeek Model (From Scratch))

5.15.18 What explains that difference?

The source attributes an important part of the effect to the starting base models.

The Qwen 7B model uses:

\boxed{\text{Qwen2.5-Math 7B}}

while the Llama 8B model uses:

\boxed{\text{Llama 3.1 8B}}.

The Qwen base therefore begins with stronger mathematical specialization. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{better starting representation} + \text{same teacher supervision} \rightarrow \text{better student} }

5.15.19 The surprising 70B result

Now compare:

\text{Qwen-32B}=72.6\%

against:

\text{Llama-70B}=70.0\%.

The 70B model is more than twice as large but still scores:

72.6-70.0 = \boxed{2.6}

points lower on AIME.

The source uses this as evidence that the base model matters strongly: a larger model does not automatically compensate for weaker prior specialization in the target capability. (Source: Build a DeepSeek Model (From Scratch))

This is a major interview-level lesson:

\boxed{ \text{parameter count is not the only determinant of capability} }

5.15.20 Distillation is not lossless

The teacher has:

79.8\%\text{ AIME}.

Best distilled model in the table:

72.6\%.

Absolute gap:

79.8-72.6 = \boxed{7.2\text{ percentage points}}.

Relative to the teacher:

\frac{79.8-72.6}{79.8}\times100 \approx \boxed{9.0\%}.

This matches the source's statement that roughly 9% of the teacher's mathematical performance is lost in compression to the 32B student. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{distillation}\neq\text{perfect cloning} }

It is compression.

5.15.21 Why does information get lost?

Suppose the teacher implicitly contains:

1000

useful reasoning patterns.

A small student may only have enough representational capacity to encode some of them.

So:

\text{Teacher capability}

↓

\text{compression bottleneck}

↓

\text{Student capability}.

This is the capacity gap discussed by the source. (Source: Build a DeepSeek Model (From Scratch))

5.15.22 This explains the 1.5B coding result

The 1.5B model performs very strongly on:

\text{MATH}=83.9\%.

But poorly on:

\text{coding}=16.9\%.

So the student isn't simply “weak.”

Rather:

\boxed{ \text{different capabilities have different compression difficulty} }

This is much more precise.

This is especially interesting because the training recipe is much simpler:

5.15.24 Now we reach the most important experiment

The key question is:

Suppose I already have a 32B model. Should I train it with RL, or distill a stronger teacher into it?

DeepSeek directly compared these.

The same Qwen2.5-32B architecture was used.

One version:

\boxed{\text{large-scale RL}}

with more than:

\boxed{10,000\text{ policy-gradient updates}}

Another:

\boxed{\text{distillation + 2–3 epochs SFT}}.

(Source: Build a DeepSeek Model (From Scratch))

This is an extremely clean experiment because the architecture is held constant.

5.15.25 Results: RL vs distillation

AIME:

\text{Distill}=72.6\%
\text{RL}=47.0\%.

Difference:

\boxed{25.6\text{ percentage points}}.

MATH-500:

94.3-91.6 = \boxed{2.7}.

GPQA:

62.1-55.0 = \boxed{7.1}.

LiveCodeBench:

57.2-40.2 = \boxed{17.0}.

(Source: Build a DeepSeek Model (From Scratch))

So distillation wins on every benchmark in this comparison.

5.15.26 Why is this result so important?

Because the architecture is basically controlled.

Both are:

\boxed{\text{Qwen2.5-32B}}

So this is not:

“a better architecture beat a worse architecture.”

Instead, it is approximately:

\boxed{ \text{different training strategy} \rightarrow \text{different outcome} }

The source's interpretation is that a 32B model attempting to discover difficult reasoning through RL on its own encounters a capacity/learning bottleneck, whereas distillation gives it successful reasoning patterns directly. (Source: Build a DeepSeek Model (From Scratch))

5.15.27 Think about RL discovery mathematically

During RL, the student is effectively trying to discover useful behaviors:

\boxed{ \text{candidate trajectory} \rightarrow \text{reward} \rightarrow \text{advantage} \rightarrow \text{policy update} }

A difficult reasoning strategy may occupy a tiny region of the model's behavior space.

The model may need many attempts before stumbling upon it.

5.15.28 Distillation changes the search problem

Instead of asking:

“Discover a successful trajectory.”

we ask:

“Imitate this successful trajectory.”

So:

RL
\boxed{ \text{exploration} }
Distillation
\boxed{ \text{supervised imitation} }

This is the core reason the training dynamics are so different.

5.15.29 A useful analogy

Imagine a student learning calculus.

RL-like approach

Give the student:

Solve this problem.

If correct, give reward.

The student has to discover useful methods.

Distillation

Give the student:

Here is an expert solution showing the sequence of reasoning.

Now the student can practice imitating the expert.

That does not guarantee perfect transfer, but it is much more data-efficient when expert demonstrations are high quality.

5.15.30 But distillation has a fundamental limitation

This is extremely important.

Suppose:

\text{Teacher capability}=100.

Distillation may produce:

90,\;80,\;70,\ldots

depending on student size.

But if you keep distilling the same teacher, you do not normally get:

\boxed{120}

from a teacher that never possessed the capability.

Therefore:

\boxed{ \text{distillation transfers} }

while:

\boxed{ \text{RL can potentially discover} }

new behavior when the reward signal supports it.

The source explicitly makes this distinction: distillation is economical and effective, but advancing beyond the teacher's frontier requires stronger base models and/or larger-scale RL. (Source: Build a DeepSeek Model (From Scratch))

5.15.31 The DeepSeek training philosophy becomes clearer

We can now connect the whole pipeline:

\boxed{ \text{Large model + RL} \rightarrow \text{discover/strengthen reasoning} }

then:

\boxed{ \text{large model} \rightarrow \text{generate successful demonstrations} }

then:

\boxed{ \text{small model + SFT} \rightarrow \text{absorb those demonstrations} }

This is why the two techniques are complementary rather than competitors.

5.15.32 One teacher, many students

This gives another major economic advantage.

Suppose generating the teacher dataset costs:

C_T.

You can then train:

N

different students.

The teacher-generation cost is paid once.

Conceptually:

\boxed{ C_{\text{total}} = C_T+\sum_{i=1}^{N}C_{\text{student},i} }

rather than running a large RL process separately for every student.

The source explicitly highlights this amortization property: once the 800K dataset exists, many student models can reuse it. (Source: Build a DeepSeek Model (From Scratch))

5.15.33 Source-reported economics

The source estimates:

\boxed{\$10,000}

for generating the distillation data, corresponding to about:

5,000

H800 GPU hours.

It compares this with approximately:

\$202,000

for R1-Zero RL and:

\$82,000

for the full R1 pipeline, using the source's disclosed hour/rate assumptions. (Source: Build a DeepSeek Model (From Scratch))

These are source-specific estimates, not universal costs for distillation or RL.

5.15.34 A useful amortization numerical

Suppose the teacher-data generation cost is:

\$10,000.

Suppose five student models each cost:

\$3,000

to SFT.

Then:

C_{\text{total}} = 10,000+5(3,000) = \$25,000.

Average cost per model:

\frac{25,000}{5} = \boxed{\$5,000}.

As the number of students grows, the fixed teacher-generation cost is spread across more models.

For N students:

\boxed{ \text{average teacher-generation cost per student} = \frac{10,000}{N} }

plus the individual student-training cost.

5.15.38 What does scaling actually mean here?

Do not think only:

\text{more parameters}\rightarrow\text{more accuracy}.

The more complete picture is:

\boxed{ \text{student size} + \text{base model} + \text{teacher-data quality} + \text{training recipe} }

all influence the final result.

The supplied experiments demonstrate this very clearly:

  • Qwen 7B beats Llama 8B on AIME.
  • Qwen 32B beats Llama 70B on AIME.
  • larger students generally improve over smaller students within a family.
  • the teacher still remains above the students. (Source: Build a DeepSeek Model (From Scratch))

5.15.39 A note about the source's parameter-ratio statements

There is an inconsistency in the supplied material that you should not memorize blindly.

One passage says that a 1.5B student is roughly 12,000× smaller than GPT-4o estimated at 1.8T parameters. (Source: Build a DeepSeek Model (From Scratch))

But:

\frac{1.8\times10^{12}}{1.5\times10^9} = 1200.

So from the numbers actually printed in the table:

\boxed{1200\times}

is the direct ratio, not 12,000×.

Separately, the source summary says approximately 450× compression; that ratio corresponds more closely to:

\frac{671B}{1.5B} \approx447.

(Source: Build a DeepSeek Model (From Scratch))

For exams, when given explicit numbers, calculate from the numbers rather than relying on the prose statement.

Suppose parameters are stored in FP16:

2\text{ bytes/parameter}.

5.15.42 Important distinction: total parameters vs active parameters

The teacher is an MoE model.

Source:

\boxed{671B\text{ total parameters}}

but:

\boxed{37B\text{ active per token}}.

Yet the full weights must remain available in memory. (Source: Build a DeepSeek Model (From Scratch))

So:

\boxed{ \text{active compute} \neq \text{stored model size} }

This connects directly back to our earlier MoE lessons.

5.15.43 What does distillation actually compress?

It is not simply:

671B\rightarrow32B

by deleting parameters.

Instead:

\boxed{ \text{behavior/knowledge expressed by teacher} }

is converted into:

\boxed{ \text{training examples} }

and then re-encoded into:

\boxed{ \text{student parameters} }.

So this is knowledge transfer, not mere parameter pruning.

5.15.44 The deepest conceptual lesson

There are really three resources involved:

1. Exploration capability

Large RL-trained teacher can search for useful reasoning behavior.

2. Data quality

Rejection sampling turns successful behavior into clean demonstrations.

3. Student capacity

The smaller model determines how much of that behavior can actually be absorbed.

So:

\boxed{ \text{Teacher} \rightarrow \text{Data} \rightarrow \text{Student} }

is the complete chain.

A failure at any stage limits the final result.
